## 0. 一页摘要

**问题**：同一角色的货币账本里，同一种钱被记成了很多个名字。真实存档实测（李瑶）：

| 真实类别 | 存档里出现的名字 | 机械档（v3.15.0）能不能合 |
| --- | --- | --- |
| 金 | `黄金`(两) · `天然碎金`(块) · `碎金子`(两) · `碎金`(两) · `赤金条`(贯) · `赤金条子`(贯) · `诺米斯玛金币`(枚) | **一个都合不了**（不在 `CURRENCY_NAME_ALIASES` 里；且有单位冲突） |
| 银 | `碎银`(粒) · `碎银子`(两) · `雪花银`(贯) · `雪花银角子`(贯) · `银角子与碎银饼`(贯) · `官铸雪花大银`(两) | 同上 |
| 票据 | `飞钱`(贯) · `飞钱凭证`(贯) · `东市柜坊飞钱凭证`(贯) · `通兑飞钱凭证`(贯) | 同上 |
| 铜 | `开元通宝`(贯) · `铜钱`(枚/贯) · `拜占庭铜努米亚`(枚，**-6**) | 同上 |

**现状 = 两条通道，缺第三条**：① 机械档「🧹 修正货币」——**零 AI、秒级、可预览**，但只认**写死的别名表** + 结构规则；
② 提取（AI 摘要）——每轮只看当前楼层，**不会回头整理**既有账本。→ 于是「叫法不同」只能靠人工一条条改。

**本稿主张**：加**第三条通道**「🔀 AI 融合货币」——**指定一个角色**，把它名下**全部**货币打包交给 AI，
只做「**语义同义**」的合并（`黄金 + 碎金子 → 黄金`），**不读楼层、不跨角色、不凭空换算**，
**先出方案 → 只读预览 → 确认后落库**，并**复用机械档的应用与墓碑路径**（同一条真相，不造第二套）。

**一句话边界**：**机械档管"结构与写死的别名"，本档管"语义同义"，两者都不新增条目、都不删正文。**

## 1. 目标 / 非目标

### 1.1 目标

| # | 目标 | 判据 |
| --- | --- | --- |
| G1 | 指定**一个角色**，一次点击把它名下全部货币整理规整 | 打包体内**只有**该角色的条目（构造另一角色货币 → 断言不进包） |
| G2 | 只合并「叫法不同、其实是同一种」的货币；**不是同一种的绝不合并** | 金 / 银 / 铜 / 票据 四类不跨类合并；名字仅共用一个字不合并 |
| G3 | **禁凭空换算**：单位不同的不得合组 | 单位集合 > 1 的组**整组拒收**（结构化原因 `unit-conflict`） |
| G4 | **金额不静默丢**：合并后的额度有明确策略，且预览逐条列出成员原额 | 默认**求和**（用户裁决）；设定可切「保留最新不累加」；预览列出每条原额 |
| G5 | **零写入直到确认**；可整轮回退 | 预览阶段构造断言：`state.currencies` 与 `state.links` 逐字节不变；应用前自动落一次快照 |
| G6 | **复用同一套应用与墓碑**，不造第二套真相 | 走 `core/currency-repair.js#runCurrencyRepair({plan})`；被并入条目**留 id 墓碑** |
| G7 | **不读楼层**（不变成提取的旁路） | 打包体不含任何楼层正文片段（构造唯一标记 → 断言不含） |

### 1.2 非目标（明确不做）

| # | 不做 | 理由 |
| --- | --- | --- |
| N1 | **跨单位换算**（两 ↔ 贯 ↔ 枚） | 无汇率依据；凭空换算 = 编造金额（`G3`） |
| N2 | 新增 / 删除与合并无关的条目；改正文 / 日期 / 归属 | 本档只做「合并 + 改名 + 额度策略」 |
| N3 | 跨角色合并（把 A 的钱并到 B） | 归属是事实，不是可整理项 |
| N4 | 逐组勾选 | 沿用既有「先出方案 → 全量应用 / 取消」形态（`docs/D9`）；逐组勾选属新需求 |
| N5 | 自动/定时触发 | 花一次 AI 请求，必须由人点击 |
| N6 | 进调试桥 | 本档是**写入口**，按 `docs/D31` §1.1 只读纪律不得进桥 |

## 2. 现状核对（只读，逐条带证据）

| # | 结论 | 证据 |
| --- | --- | --- |
| ① | 机械档的「合并」按 `归属 + 规范名` 分组，**单位冲突时只报告不合并** | `core/currency-repair.js#currencyRepairPlan` 的 `unit-conflict` 分支 |
| ② | 机械档的别名表是**写死的少数项** | `core/currency-repair.js#CURRENCY_NAME_ALIASES` / `#CURRENCY_UNIT_ALIASES` |
| ③ | 机械档的应用会**留 id 墓碑 + 内容哈希墓碑**，并对被并入条目做**备注/标签/流水/用量/楼层区间并集** | `core/currency-repair.js#runCurrencyRepair` · `core/merge.js#tombMany` / `#tombEntries` |
| ④ | 货币**没有内容哈希口径** → 内容墓碑恒空，实际生效的是 id 墓碑；而货币 id 由「归属 + 币种」派生 → 跨端同一条同 id | `core/model/hash.js#atomIdentityHash`（currencies 返回空）· `core/currency-repair.js` 头部注释 |
| ⑤ | 真实存档里存在**复合名 / 负额度 / 名字即单位词**三类噪声 | 只读核对：`飞钱凭证及赤金条`(贯) · `拜占庭铜努米亚`(-6) · 名字为「贯」一类的条目 |
| ⑥ | 货币页已有两个入口：`👥 指定角色`（**跟踪**标定）与 `🧹 修正货币`（机械档） | `ui/panel.js#currencyTrackButtons` · `#currencyRepairPanelHtml` |

> 结论：**「跟踪标定」不是「本次要整理哪个角色」** —— 本档需要一个**每次运行独立选择**的角色入口（不改变既有标定语义）。

## 3. 方案

### 3.1 三层与"第三条通道"的位置

| 通道 | 读楼层 | 新增条目 | 改字段 | 删 / 合并 | 花 AI |
| --- | --- | --- | --- | --- | --- |
| 提取（AI 摘要） | ✅ | ✅ | ✅ | ❌ | ✅ |
| 机械档（🧹 修正货币） | ❌ | ❌ | ✅（单位归一 / 额度补齐） | ✅（剔除 / 合并） | ❌ |
| **本档（🔀 AI 融合货币）** | **❌** | **❌** | **✅（仅合并组内的名字与额度）** | **✅（仅"并入"，等价于删除 + 并集）** | **✅（1 次）** |

### 3.2 打包（三段）

| 段 | 内容 |
| --- | --- |
| ① 逐条清单 | `id \| 名字 \| 单位 \| 额度 \| 日期 \| 用 N 次 \| 流水净额 \| 备注摘要`（**同角色**；超上限按名字序截断并**如实计数**） |
| ② 名字清单 | **按单位分组**列出该角色所有名字（`[两] 黄金 / 碎金子 / 碎银子 …`）—— 同义合并的判据来源 |
| ③ 无 | **不含**角色档案正文 / 楼层正文 / 其它维度（`G7`） |

### 3.3 窄契约（AI 只提方案，结构由机械兜底）

```json
{"groups":[{"canonical":{"name":"黄金","unit":"两"},
            "members":[{"id":"cur_a","name":"黄金"},{"id":"cur_b","name":"碎金子"}],
            "why":"同为金、单位同为两"}],
 "keep":[{"id":"cur_c","why":"单位是贯，不可换算"}],
 "notes":""}
```

**七条机械判据**（逐条配反向探针）：① 成员必须在本次打包集内；② 每组 ≥2 条；③ **同一 id 不得进两组**；
④ **单位必须相同**（禁凭空换算）；⑤ 规范名非空、≤24 字、**不得含「及/和/、/与」**；⑥ 复合名成员 / 负额度成员 / 名字即单位词的成员**不得进组**；⑦ 组数 ≤30。

### 3.4 应用（复用机械档）

① 合成一份**同形 plan**（机械档的 drop/fix/report + AI 组，AI 组优先占用 id）→ ② `runCurrencyRepair({plan})`
→ ③ 保留条目 = 组内**最新**那条（同日取用量高者），**改名成规范名**，**额度按策略**（默认**求和**）→
④ 被并入条目**留 id 墓碑** + 备注 / 标签 / 流水 / 用量 / 楼层区间**并集** → ⑤ 提示行 + `dbgLog('摘要', …)` + `state.currencyMergeLog`（末 5 条、runtime、不跨端）。

### 3.5 幂等与终止

`currencyMergeSig = hash(打包指纹 + 规范化分组)`；同签名重复提交 → 跳过并提示「本轮方案与上次完全相同（已应用过，不叠加）」。
五种终止：`disabled`（开关关）/ `no-owner`（没选角色）/ `no-data`（该角色没有货币）/ `no-ai`（AI 未返回）/ `invalid`（没有任何可合并的组）。

## 5. 风险与对策

| # | 风险 | 对策 |
| --- | --- | --- |
| R1 | **金额被算错**（求和 vs 不累加语义相反） | 用户已裁决默认**求和**；设定保留开关；预览**逐条列出原额**并写明策略；应用前自动落快照可整轮回退 |
| R2 | AI 把不同货币合并（黄金 vs 黄铜） | 提示词第 4 条（跨类不得合并）+ 机械判据不允许跨单位；`keep` 要求写明理由 |
| R3 | AI 编造不存在的 id | 判据①（成员必须在打包集内）+ 判据③（不得重复消费） |
| R4 | 合并后"跨端复活" | 走机械档同一墓碑路径（id 墓碑）；货币 id 由归属+币种派生 → 同一条同 id（既有实现保证） |
| R5 | 改名后与既有 id 不再一致（保留条目 id 来自旧名） | 如实登记：这是**既有机械档同款**行为（保留条目保留自己的 id，其余 id 进墓碑）；改 id 属另一件事（未做） |
| R6 | 大账本一次请求过大 | `cfg.currencyMergeMaxItems`（默认 120）+ 截断如实计数；必要时用户自行调小/分批 |

## 附录 · 版本变更史（`开发守则.md` §2.7）

### v1.1（2026-10-13，随 **v3.46.5**，`docs/D22` §4.14 **W13** 收口 `应-32`）

**用户报告**（原话）：「其次修复货币融合机制，例如金子、赤条金、黄金，明明都可以融合却被忽略了。」

**实测复现**（本稿 §3.3 的窄契约在真实语料下的行为）：以 `金子(两) + 赤条金(条) + 黄金(两)` 提成一组 →
旧实现 `currencyMergeValidate` 判 `unit-conflict` → **整组被拒**（`groups.length === 0`、`reasons = {unit-conflict: 1}`），
于是**金子与黄金（同为「两」）也没被合并** —— 用户看到的正是「明明可以融合却被忽略」。

**口径修正（§3.3 第 ④ 条的细化，不是推翻）**：
· **「禁凭空换算」不变** —— 不同单位**仍不合并**（不臆造「1 条 = ? 两」的换算）；
· 但**不再整组丢弃**：按单位**拆成同单位子组**，≥2 条的子组照常合并，单条子组**只报告不合并**（进 `keep` 并写明原因）；
· 「发生过拆分」进 `reasons['unit-split']`，单条子组进 `reasons['unit-split-singleton']` —— **预览里看得见**，不再无声忽略。

**影响面**：仅 `core/currency-merge.js#currencyMergeValidate`（AI 档）；机械档「🧹 修正货币」不受影响。

### v1.2（2026-10-13，随 **v3.47.1**，`docs/D22` §4.14 **W13** 修复）

**用户报告**（原话）：「货币通过AI融合后，**记录是分散的，没有合并**。请修复。」

**根因（沿革看）**：本稿 §3.3 第 ④ 条经两次演进仍未满足用户预期 ——
· v3.46.2：遇单位冲突**整组拒** → 同单位的别名也一起被忽略；
· v3.46.5（附录 v1.1）：改为**按单位拆成同单位子组** → 同单位的合并了，但**同一货币的不同单位仍是 2–3 条**。
真实语料里单位写法本就不统一（实测：`黄金/两` · `碎金子/两` · `赤金条子/贯` · `赤金条/贯` · `赤条金/条` 同属「金」）
→ 用户看到的仍然是「记录分散」。**两次修的都是"别丢"，没解决"要合"。**

**口径修正（§3.3 第 ④ 条第二次细化，「禁凭空换算」仍不变）**：

| 面 | v3.46.5（旧） | **v3.47.1（新）** |
| --- | --- | --- |
| 一个 AI 组产出 | 按单位拆成 **1–N** 条 | **恒为 1 条** |
| 主单位 | 每个子组各自一个单位 | 组内**成员最多的单位**（并列 → AI 的 `canonical.unit`；都不匹配 → 第一个成员的单位） |
| 额度 | 各子组分别求和 | **主单位成员**求和（`currencyMergeSumAmount` 关时取其中最新那条的额度）；**分量纲一律不相加** |
| 其它单位的成员 | 单条子组 → `keep`（只报告）；多条子组 → 另起一条 | **不参与算术**：进 `otherAmounts`，落库时写进该条**备注**（`并入：赤金条(贯) 23200、赤条金(条) 5`），预览逐条列出 |
| 透明计数 | `unit-split` / `unit-split-singleton` | `unit-mixed`（跨单位并成一条的成员数，进 `plan.counts.unitMerged`） |

**一句话**：**记录合成一条，金额一分不丢，汇率一分不造。**

**影响面**：`core/currency-merge.js#currencyMergeValidate` / `#currencyMergePlan` · `core/currency-repair.js`（合并落库时把其它单位原额追加进备注）· `core/currency-merge-prompt.js`（口径改写：**单位不同不是不合的理由**，但仍不得跨「金/银/铜/票据」四类混）· `ui/currency-merge.js`（预览列出其它单位）。
机械档「🧹 修正货币」**不受影响**（它仍是「同规范名 + 同单位才合并」）。

**测试**：`tests/unit/currency-merge.test.js` 更新 B1 的跨单位断言 + I 组三条（I1/I2/I4）按新口径改写，另新增 **E 组 4 项**（E1 一组一条 / E2 五条→一条且备注留痕 / E3 主单位选择与「不跨单位相加」/ E4 计数与 `detail` 文案）—— 全档 **23 项**全绿。
