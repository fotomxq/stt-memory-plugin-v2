## 2. 有意修正的偏差：1970 年之前的剧情日期不再被当成「无时间信息」

V1 的 `calcTimeDecay` 第一行是 `if (!Number.isFinite(item) || item <= 0) return 0;  // 无时间信息视为新`。
但剧情日期以 2000-01-01 为基准换算毫秒（`storyDateMs`），**1970 年之前的剧情日期得到负值** —— 于是
状态记录衰退 / 记忆遗忘 / 通用衰退（平行事件）对 **19~20 世纪的剧情整体失效**（最常见的 1919 一类设定恰好落在这里）。
V1 注释写的是「无时间信息视为新」，故 V2 **按注释语义**修正为只判 `!Number.isFinite(item)`；
负值（公元前 ~ 1969）是合法时间，正常参与衰减。

- 黄金样本中同批数据在 V1 下 `memoryForgetScore` 全为 0、`runMemoryForget` 移除 0 条（已记录在 fixture 的 `v1Pre1970` / `v1Pre1970Forget` / `v1DecayGuard`），
  V2 断言同批数据**确实会遗忘**（`H8` / `H8b` 两条测试）。
- 该修正同时让「状态记录衰退」「平行事件衰退」对早期剧情生效（同一函数）。

## 3. 与 V1 的其它差异（逐条明示）

1. **触发方式**：与 V1 一致 —— 状态衰退由剧情日期推进调度（B8-2 时钟自动提取已接线）、记忆遗忘由记忆写入调度（本批接线）、
   通用清扫在「自动修复」管线内执行（B8-6 接线）。V1 该页**没有手动按钮**，V2 保持同样口径；
   另提供 `FTT.forgetRunAll()`（一次跑齐三类 + 库存裁剪）作为**诊断/测试入口**（V2 附加，不进入界面）。
2. **页面诊断行**：V1 遗忘页只有开关与说明；V2 追加一行只读诊断（当前条数 / 上限 / 保底 / 清扫冷却），便于自查「为什么没清」。
3. **定时器**：V1 用 `setTimeout`；V2 经内核 `timerHooks`（宿主注入真实定时器），卸载时 `cancelForgetTimers()` 清理。
