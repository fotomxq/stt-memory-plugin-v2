## 0. 一页摘要

**现状**：角色修复的**入列口径**是「**抽取字数偏少**」（`cfg.repairCharacterMinSize`：档案有效字数 < 门限者入列）+
「出生日期异常优先档」（倒挂 / 未来 / 超常…无视门限一律入列）。而**已去世**的判定只有一条通道：
`snapshotDeathVerdict` 的**文字证据**（本人 + 死亡措辞；长生者另需终局措辞）——**与年龄无关**。

**问题**：一个普通角色按剧情日期算已经**明显高寿**（却没有一句"他死了"的正文），
今天既不会被标去世、也不会被任何规则处置 —— 它会一直留在角色池里，年龄继续涨，AI 每轮都可能重新分析。

**用户要求**：**年龄异常也要处理** —— 当该角色**没有**长生者标记，且年龄**明显达到平均高寿**时，**主动标记去世**。

**主张**：在**角色修复的机械段**（零 AI）里，与文字证据**并列**加一条**年龄规则**；判据**保守**、拒绝一切"猜出来的年龄"；
标记**只增不减**（取消请在编辑器取消勾选），并**如实分列回报**（文字证据 / 年龄各标了几名）。

## 1. 目标 / 非目标

### 1.1 目标

| # | 目标 | 判据 |
| --- | --- | --- |
| G1 | 年龄 ≥ 阈值且**未标记长生者** → **主动写 `身份.已去世 = true`** | `markDeceasedByEvidence()` 返回 `markedByAge ≥ 1`；档案 `identity.deceased === true` |
| G2 | 阈值**可配置**且**默认可解释** | `cfg.repairDeceasedAge` 默认 **75 岁**（中文「高寿」常见门槛 70–80 的中值）；`0` = 关闭规则 |
| G3 | **没有长生者标记**是硬门槛（含档案里的长生类措辞） | 长生者开关 / `长生·不死·精灵·修真…` → `blocked: 'immortal'` / `'long-life-words'`，**绝不标记** |
| G4 | 年龄必须**来自真实出生日期**（不拿猜的值判生死） | `basis` 仅接受 `story` / `timeline`；`stored`（沿用存档值）/ 无出生日期 → 不动 |
| G5 | 「**明显**达到」留余量 | 出生日期只精确到「年」时，阈值 **+1 岁**（±1 岁误差不误伤） |
| G6 | 荒谬年龄**只报告不标记** | `overage` 异常码或 ≥ 200 岁 → `verdict: 'report'`（多半是长生者没标 / 出生日期错） |
| G7 | **幂等 + 只增不减** | 连跑两次第二次 `marked === 0`；已标记者短路（`already-marked`） |
| G8 | 与既有链路**自动联动** | 标后自动被「出生日期校正 / 标签 / 年龄刷新 / 待修复名单」跳过（既有 `snapshotRepairSkip` 口径） |
| G9 | **如实回报** | 机械段返回 `ageMarked` / `ageReported` / `ageThreshold` / `deceasedByEvidence`；通知与调试日志分列 |

### 1.2 非目标（明确不做）

| # | 不做 | 理由 |
| --- | --- | --- |
| N1 | 取消已去世标记 / 反向复活 | 与既有纪律一致（「只标记、从不取消」）；取消请到编辑器 |
| N2 | 依据**推测**年龄（`guessAgeFromCues` / 存档值）判去世 | 拿猜的数字判人生死不可接受（`G4`） |
| N3 | 跨维度写死亡（状态记录清除等） | 由既有固定规则接管（`state-repair` 等），本稿只写这一个布尔 |
| N4 | 给 AI 加"判年龄"的要求 | 这是**机械可判定**的事（出生日期 + 剧情日期），不该花 AI；AI 仍负责文字证据与补全 |
| N5 | 按寿命分布 / 时代自动调阈值 | 时代差异大且无法可靠推断；改用**一个可配置阈值**（`G2`）+ 文档写明 |

## 2. 现状核对（只读，逐条带证据）

| # | 结论 | 证据 |
| --- | --- | --- |
| ① | 入列口径 = 字数门限 + 出生日期异常优先档 | `core/character-repair.js#buildCharacterRepairQueue` |
| ② | 已去世判定**只有文字证据**一条路 | `#snapshotDeathVerdict`（`deathSentenceJudge` 逐句判：本人在场 + 死亡措辞 + 非否定/非第三方） |
| ③ | 年龄是**派生字段**，且带**来源说明** | `core/model/snapshot.js#snapshotAgeInfo` → `basis`：`story`（按剧情日期）/ `timeline`（按最近记录日期）/ `stored`（无锚点、沿用存档值）/ `none` |
| ④ | 出生日期异常已有分级 | `#snapshotBirthAnomaly`：`future` / `after-record` / `overage` / `bad-format`；`overage` = 年龄超常 |
| ⑤ | 长生者与已去世都有既有跳过判据 | `#snapshotRepairSkip`（`deceased` / `immortal`）· `#snapshotImmortal` |
| ⑥ | 机械段的执行顺序：**先**去世研判，再出生/标签/年龄/履历 | `#runCharacterMechanicalPass`（标记后后续步骤与 AI 名单自动跳过） |

## 3. 方案

### 3.1 规则（`snapshotLongevityVerdict`，机械 / 只读 / 零 AI）

按顺序判，任一不满足即**不标记**：

| 序 | 判据 | 不满足时 `blocked` / `reason` |
| --- | --- | --- |
| 1 | 有名字 | `no-name` |
| 2 | **未标记已去世**（短路，避免反复处理） | `already-marked` |
| 3 | **无长生者开关** | `immortal` |
| 4 | 档案字段里**无长生类措辞**（`LONG_LIFE_WORDS`：长生 / 不死 / 精灵 / 妖族 / 修真 / 神明 / 转世 …） | `long-life-words` |
| 5 | 出生日期异常**不是** `future` / `bad-format` / `after-record`（方向或格式本身不可信） | `birth-untrusted` |
| 6 | 出生日期非空、精度可解析，且 `basis ∈ {story, timeline}`（**不拿 `stored` 的存档值判生死**） | `no-birth-date` / `age-not-derived` |
| 7 | **年龄 ≥ 有效阈值**（阈值 = `cfg.repairDeceasedAge`，默认 75；出生日期只到「年」→ **+1**） | `below-threshold` |
| 8 | 年龄**不荒谬**（异常码非 `overage` 且 < 200 岁） | → `verdict: 'report'`（`implausible-age`，**只报告不标记**） |
| ✅ | 全过 | → `verdict: 'dead'`（`age-longevity`），证据写明「按剧情日期 X 计，年龄 N 岁 ≥ 阈值 T 岁（精度 day/month/year），且未标记长生者」 |

### 3.2 落点与联动

| 面 | 做法 |
| --- | --- |
| 研判 | 新增 `snapshotLongevityVerdict(s, {threshold})` + `SNAP_LONGEVITY_DEFAULT_YEARS = 75`（`core/character-repair.js`） |
| 标记 | `markDeceasedByEvidence(opts)` 在**文字证据之外**追加年龄规则；`opts.ageRule === false` 或 `cfg.repairDeceasedAge = 0` 可关；计数**分列** `markedByEvidence` / `markedByAge` / `ageReported` |
| 联动 | 标后由既有 `snapshotRepairSkip` 自动跳过（出生日期校正 / 标签 / 年龄刷新 / 待修复名单 / AI）；年龄锁定由既有机制接管 |
| 回报 | 机械段返回四读数；通知文案加「年龄规则（≥ N 岁且未标长生者）标记去世 M 名」；调试日志 kind `修复` 记明细 |
| 干跑 | `characterAgeScan()` 每行加 `longevity` 读数（界面/调试可先看「谁会被年龄规则标记」，**只读不写**） |
| 配置 | `cfg.repairDeceasedAge`（默认 75；`0` = 关闭）+ 设定页「🧑 角色修复」组控件（同批） |

### 3.3 与文字证据的关系

**两条通道并列，互不替代**：文字证据（有人写了"他死了"）继续按原口径判；年龄规则补的是「无人写、但按剧情日期已经高寿」这一类。
两者都走同一个落笔点（`身份.已去世 = true`）与同一条后续联动（跳过 / 年龄锁定）。

## 5. 风险与对策

| # | 风险 | 对策 |
| --- | --- | --- |
| R1 | **误标活人为死**（最严重） | 判据保守（`G3`–`G6`）· 只增不减但可在编辑器取消 · 通知与日志逐名列出（可追溯）· 单测覆盖 7 类反例 |
