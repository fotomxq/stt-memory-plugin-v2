## 2. 分层与依赖方向

```text
ui/  ──►  host/  ──►  adapters/  ──►  core/
ui/  ──────────────────────────────►  core/          （只读内核）
core/  ◄── 禁止 import host/ adapters/ ui/            （门禁强制）
```

| 层 | 职责 | 代表文件 |
| --- | --- | --- |
| `core/` | 纯逻辑：常量 / 工具 / 数据模型 / 算法 / 提示词（**无 DOM、无宿主、无全局定时器**） | `constants.js` `config.js`(221 键) `model/*` `recall.js` `ingest.js` `migrate.js` `merge.js` `cross-sync.js` `clock*.js` `*-repair.js` |
| `host/` | 宿主适配：能力探测 / 事件 / 注入 / 生成前拦截 / AI 调用 | `st-api.js` `events.js` `inject.js` `interceptor.js` `extract.js` `embeddings.js` `vector-recall.js` `update.js` `paths.js` |
| `adapters/` | 存储与传输：配置 / 本机缓冲 / 文件通道 / 宿主原生存储 / 同步 / 导入 | `store.js` `file-transport.js` `tt-store.js` `user-file.js` `sync.js` `import-v1.js` `gzip.js` |
| `ui/` | 界面：浮层面板 / 分页 / 编辑器 / 设定 / 调试 / 命令 | `panel.js` `settings-pages.js` `constraint-page.js` `rel-table.js` `debug.js` `commands.js` |
| 入口 | 装配 / 事件接线 / 生命周期钩子 / 调试导出 | `index.js`、`devtools.js` |

**为什么强制方向**：`core/` 是跨端（浏览器 / 宿主原生 / Node 测试）共用的事实源；一旦它碰 DOM 或宿主，黄金样本与单元测试就不可复现。

## 3. 运行时装配

| 环节 | 做法 | 落点 |
| --- | --- | --- |
| 触发 | **多触发 + 有限轮询**：不依赖单一 `APP_READY`（不同宿主时机不一致） | `index.js#init`（`init()` 幂等）、`index.js#probeTick`（可见性探针）、`index.js#startReadyProbe`（轮询） |
| 幂等 | 事件 / 轮询 / 命令三处触发都只跑一次；新一轮调度替代旧一轮 | `index.js#ensureReady` |
| 诊断前置 | 命令与调试入口**模块加载期即注册**，即使初始化未触发也能自查 | `index.js#bootstrapDiagnostics` |
| 兜底入口 | 连续若干次仍无可见入口 → 显示悬浮「FTT」按钮并停止轮询（不无限重试） | `index.js#ensureVisibleEntry`、`index.js#probeTick` |
| 生成前 | `generate_interceptor`：**只读**、永不 abort、不改 chat、失败静默 | `host/interceptor.js` |
| 生成后 | 消息事件 → 自动提取 / 自动修复 / 时钟同步（受开关与忙位互斥约束） | `host/extract.js`、`index.js` |
| 卸载 | `onDelete` / `onDisable` / `onClean` → `teardown()`（解绑事件、清注入、移除面板、清调试导出） | `index.js#teardown` |

## 4. 宿主适配与降级

| 能力 | 探测方式 | 降级行为 |
| --- | --- | --- |
| 上下文（`SillyTavern.getContext()`） | 加载期探针 | 无宿主（Node）时导入不抛异常，且全部能力标记缺失 |
| 事件总线 | `eventSource` 存在性 | 缺失则仅靠轮询 + 命令 |
| 注入通道 | `setExtensionPrompt` | 不可用则注入自查如实报「通道不可用」 |
| 存储 | 宿主原生存储（TauriTavern）→ 用户目录文件 → 本机缓冲 | 逐级回退，任一层失败不阻塞 |
| AI 通道 | 三种：`direct` 直连 / `profile` 经酒馆连接配置 / `host` 经宿主覆盖 | 未配置时按用途回落「跟随酒馆当前连接」 |
| 文件下载 / 选择 | Blob + `<a download>` / `<input type=file>` | 不可用时提供文本框粘贴路径 |

## 5. AI 调用与向量层

| 用途 | 说明 | 落点 |
| --- | --- | --- |
| 提取分析（`mem`） | 记忆分析发送 / 增量 JSON | `host/ai-recall.js`、`host/extract.js` |
| 关键词提取（`kw`） | 生成查询词，供召回使用 | `host/ai-recall.js` |

**三层提取**（三键均在 `core/config.js#defaultCfg`）：第一层向量检索（`useVector`）→ 第二层浏览器 JS 抽取（`jsExtractEnabled`）→ 第三层 AI 分析（`memApi`）；逐层失败自动降级。

### 9.3 目标口径（`D11` 已提裁决）

- **配置** → ST `extensionSettings`（保持）；
- **记忆数据** → **`chatMetadata`** 为主载体（随聊天文件同步/备份），**消息 `extra`** 为叶子级兜底；
- **自研文件 / 快照链 / gzip / 瘦身 / 世界书镜像** → 降级为**导出、迁移与灾备**；
- **TauriTavern 原生 KV/blob** → 作为 `chatMetadata` 的**等价替代后端**（同一协议），不另立协议；
- **时序**：引入「载入完成前禁止落盘」的 ready 守门（对齐参考实现 R2）。

## 10. 版本治理

| 对象 | 规则 |
| --- | --- |
| 代码版本 | **`3.XX.XX`**：新增能力 / 行为变更 → `3.<minor+1>.0`；纯修复 → `3.<minor>.<patch+1>`；**只在 3 上追加、主版本固定 3、`minor`/`patch` 位数不限**；四处一致，tag 同名（规则见 `开发守则.md` §3.1，门禁 `scripts/check-version-sync.js`） |
| 数据模型版本 | `DATA_VERSION`，与代码版本**解耦**，仅迁移时递增 |
| 版本史 | `CHANGELOG.md` 只增不改（唯一版本史档） |
| 机器可读清单 | `FTT-memory-changelog.json` 由脚本生成，禁止手改 |
| 发布动作 | 全门禁 → CHANGELOG → tag → 推送代码 + 标签（`开发守则.md` §3） |
