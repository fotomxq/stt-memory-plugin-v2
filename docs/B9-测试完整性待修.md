## 1. 缺陷与真实范围

`tests/smoke-test.js` 的断言助手是**同步**的；套件把 **async IIFE 的 Promise** 当条件传入且未 `await` → Promise 恒真 → 小节永远 ✅，断言从未求值（假绿）。

实测口径（v1.0 文档写「43 处」，实测偏少 1 处，且漏计 1 处嵌套写法）：

| 形式 | 实测数量 |
| --- | --- |
| `assert('<名>', (async () => { … })())`（同一行开始，未 await） | **44 处** |
| `assert('<名>', (() => { … return (async () => { … })(); })())`（**J5**：同步包装内返回 Promise） | 1 处 |
| 合计假绿断言 | **45 处** |
| 已在用的 `await (async () => { … })()`（非断言，是 X/AA 段的辅助计算） | 4 处 |

## 2. 修复内容

### 2.1 断言器：可 await + **永久防呆**（`tests/smoke-test.js` 顶部）

- 同步条件：立即计数 —— 既有同步调用点**行为与时序零影响**。
- thenable 条件：内部 `await` 后再计数，**调用点必须写 `await assert(...)`**。
- 永久防呆（写法对齐 `tests/harness/st-mock.js#makeReporter` 的 thenable 防呆）：thenable 条件若在**两个微任务**内没有被 `await` 消费（返回值未被 `.then()` 接管），**直接判失败**并提示
  `断言条件是一个 Promise 而调用点没有 await：请改为 await assert(...)`；若其后台结果已计入「通过」，会先撤销该次计数再记失败（不重复计数）。

**防呆自检（本批实测）**：把 M1 的 `await assert(` 临时改回 `assert(` 跑一次 →

```text
❌ M1 … 断言条件是一个 Promise 而调用点没有 `await`：请改为 `await assert(...)`
========== V2 冒烟：107 通过, 2 失败 ==========
```

计数精确（109 = 107 + 2，仅 1 项由通过转为失败，无重复计数），证明防呆**真实生效**、缺陷不可回归。

### 2.2 45 处调用点转正

- 44 处 `assert('<名>', (async () => {` → `await assert('<名>', (async () => {`；
- J5 由「同步包装内返回 Promise」改为标准 `await assert('<名>', (async () => { … })())`。

核对命令（修完应为 `0` / `45`）：

```bash
grep -c "^assert('.*(async () => {" tests/smoke-test.js          # → 0
grep -c "^await assert('.*(async () => {" tests/smoke-test.js     # → 44
```

### 3.3 实现缺陷（1 处 —— 本批不改实现，如实保留 ❌）

> **F4 `/ftt-import` 命令：`apply` 参数被吞掉，永远只能干跑**
>
> - 现象：`impCmd.callback({}, '')` 与 `impCmd.callback({}, 'apply')` 返回**完全相同**的干跑文本（`【干跑】… 确认写入请用 /ftt-import apply`）。
> - 期望：`/ftt-import apply` 才真正写入并回报 `【已写入】`（命令自身 `helpString` 与 `docs/P2-宿主与存储.md:150` 都如此定义；同一能力经 `FTT.importV1({apply:true})`（F2/F3 小节）已证明可用）。
> - 依据（根因）：`ui/commands.js:71` 传 `hooks.importV1({ dryRun: !apply })`，而 `index.js#runV1Import` 只认 **`o.apply === true`**（`dryRun` 被忽略）→ `apply` 标志丢失，永远 `dryRun:true`。
> - 建议归属批次：**下批 UI 一行小修**（`ui/commands.js` 改为 `{ apply }`，或让 `runV1Import` 兼容 `dryRun`）；本批纪律禁止改 `ui/` 与 `index.js`，故未修。
> - 影响面：仅 F4 一节；不阻塞其它小节（故未触发「先停手回报」的条件）。

## 6. 方法论沉淀（下次写异步小节时的硬要求）

1. 冒烟断言器**只保证「同步条件立即计数」**；任何 `async` 小节必须写 `await assert(...)`（漏写会被防呆直接判失败并提示）。
2. 断言**数据来源**先确认真实语义：面板提示一律读 `state.note`（`r.note` 只对「动作自身返回 note」的分支成立）。
3. 依赖「排序 / 编号」的 AI 桩，**按真实扫描结果定位编号**，不要硬编码 1/2/3。
4. 依赖服务端文件通道的小节，必须确保 `globalThis.fetch` 桩在场；「无对端」要真的清空对端文件。
5. 依赖延迟排程（清单 1.2s / 快照 2.5s / 保存镜像 3s）的断言，要等窗口而不是立即读结果。
