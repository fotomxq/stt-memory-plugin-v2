# 测试完整性待修 · 冒烟套件「未 await 的异步断言」专项

> 文档版本：v1.0 ｜ 日期：2026-09-26 ｜ 状态：**待修（高优先级）** ｜ 发现者：B8-6c-3 子代理（物品域交付时顺带发现），队长复核确认并扩大范围

---

## 1. 缺陷（已复核确认）

`tests/smoke-test.js` 的断言助手是**同步**的：

```js
function assert(name, cond, extra) {
    if (cond) { pass++; ... } else { fail++; ... }
}
```

而套件里大量小节把 **async IIFE 的 Promise** 当作断言条件传入，且**没有 `await`**，例如：

```js
assert('W3 …（async 小节）', (async () => {
    const r = await entry.popupAction('memoryRepair', {});
    return r.ok === true && …;          // ← 这个布尔从未被求值
})(), '');
```

Promise 对象恒为真 → 这些小节**永远显示 ✅**，其内部断言**完全不生效**（假绿）。

## 2. 影响范围（量化）

| 口径 | 数量 |
| --- | --- |
| `assert('<名>', (async () => {` 形式（未 await） | **43 处** |
| 已正确 `await (async () => {` | 5 处（B8-6c-1 起的新批次） |

因此当前「冒烟 109 通过」中，**约 43 项是未真正校验的**——它们的副作用确实执行了（fire-and-forget），
但断言结果被丢弃；副作用还会与后续小节**并发交错**（实测：W3 的 `popupAction('memoryRepair')` 期间
`generateRaw` 被并发调用 6 次，且其记忆条目被其它在途小节删除）。

## 3. 复核证据（队长实测）

1. 把 W3 改为 `await (async () => { … })()` 后，W3 **立即变为 ❌**（此前一直 ✅）——证明其断言从未生效。
2. W3 的诊断值显示并发交错：`calls:[0,6]`、`ids:[]`（3 条记忆全被删除）、`note:"记忆修复：无需 AI 梳理（机械去重 0 条）"`
   —— 与「未 await → 与后续小节并发」一致。
3. 同时发现 W3 取提示的来源写错：面板提示在 `r.state.note`，而它读的是 `r.note`（恒 `undefined`）。
   **该处已修**（`String((r.state || {}).note || '')`，并加注释）；但因未 await 仍未生效，随本专项一并转正。

## 4. 修复方案（专项批次）

1. 断言器改为**可 await**（对 thenable 条件 `await` 后再计数），保持既有同步调用不受影响：

   ```js
   async function assert(name, cond, extra) {
       const c = (cond && typeof cond.then === 'function') ? await cond : cond;
       if (c) { pass++; … } else { fail++; … }
   }
   ```

2. 把 43 处 `assert('<名>', (async () => {` 改为 `await assert('<名>', (async () => {`（顶层 await 已在本文件使用）。
3. **逐一修好由此暴露的真实失败**——不得为了变绿而放宽断言；若某节暴露的是**实现缺陷**，单独记录并按其归属批次修复；
   若暴露的是**断言/场景写错**（如 W3 的 `r.note`），按实现真实语义修正并说明依据。
4. 修完后：`node tests/smoke-test.js` 必须真实全绿；把最终「冒烟 N 项」写入 CHANGELOG 与相关文档。
5. 同类问题自检：单元套件已内置 thenable 防呆（`tests/harness/st-mock.js#makeReporter` 会对 Promise 条件直接判失败），
   故本次缺陷仅限 `tests/smoke-test.js`；修复后建议在冒烟断言器里也**永久保留**该防呆（Promise 条件直接判失败 + 提示「请 await」）。
