## 0. 一页摘要

在**场景页**（现有双子标签「场景树 \| 地图网图」）的**右侧新增常驻侧栏**「🏙 城镇发展」，并新建**一个原子容器 `towns`** 承载数据；城镇状态以
**三向度**（向好 / 平衡 / 向坏）与**发展指数**表达，同时标记**归属版图**与**规模**；数据在**场景入选时随 `[场景地点]` 从属注入**，让模型据此理解城镇局势、勾勒剧情。

| 要素 | 设计结论 |
| --- | --- |
| **载体** | **新原子容器 `towns`**（不是往 `scenes` / `maps` 里塞字段，理由见 §3.2） |
| **三向度** | `trend: 'up'`（向好）/ `'steady'`（平衡）/ `'down'`（向坏）—— **三值闭集**，非法值退化为 `steady` |
| **发展指数** | `index`：**0–100 整数**；变更**必须留痕**（`devHistory`），不允许静默改 |
| **归属版图** | `owner`（势力/领主/国）+ `ownerSince`（自何剧情日期）；**易主**进留痕并在侧栏高亮 |
| **规模** | `scale`：`village` 村 / `town` 镇 / `city` 城 / `metropolis` 大城 / `capital` 都城 —— 五档闭集 |
| **侧面呈现** | 场景页**右侧栏**，跨「场景树 / 地图」两个子页**常驻**；窄屏折叠为**顶部摘要条** |
| **注入** | **从属注入**：仅当本次入选的场景属于该城镇时，在 `[场景地点]` 小节追加一行；**不新增注入小节**（与 `maps` 同款，`docs/D27` §3.5） |
| **成本** | 新原子容器 → **六处接线** + **`DATA_VERSION` 3 → 4** + 维度 **17 → 18** / 原子层 **16 → 17**（`docs/README.md` §3 由门禁 C1 逐行实测） |

**三条硬口径**

1. **三向度与指数必须自洽**：`trend` 是标注值，`index` 的变化是事实；两者冲突时**只报不改**（体检提示「方向与指数不符」），不擅自改标注。
2. **归属/规模/指数的每一次变化都要留痕**（`devHistory`）—— 否则"发展"这件事就无从追溯，也无法支撑剧情回溯。
3. **不新造视觉语言**：侧栏卡片严格复用 `docs/D55` 的三段式卡片层级与设计令牌（首行主标题 + 语义徽标 / 中段关键信息 / 尾段操作），只新增**城镇专属徽标**（归属·规模·方向）。

**待裁决 6 项**（§6）：侧栏 vs 第三个子标签 · 是否常驻"当前城镇"注入行 · `scale` 是否含人口数 · 城镇与 `scenes` 的关联口径 · 指数刻度是否 0–100 · 归属是否允许"无主/未知"。

## 3. 方案

### 3.1 定位：为什么是"城镇"这一层

- `scenes` 的 `pathArr` 把地点串成层级（如 `唐 > 关中 > 长安城 > 西市 > 醉仙楼`）；**"城镇"是这条路径上的一个前缀层**（`长安城`）。
- 但它**不是** `scenes` 的某一条记录：同一城镇会对应**多条**场景记录（王宫 / 酒楼 / 城门…）—— 因此"城镇"需要**独立身份**，用它的**名与归属**寻址，再与场景按**前缀**关联（§3.3）。
- 同理，`maps.place` 的 `sceneRef` 指向具体场景，也不适合承载"全国层面的城镇发展"。

> 一句话：`scenes` 回答"**这是哪**"，`maps` 回答"**怎么走**"，`towns` 回答"**这里在变好还是变坏**"。

### 3.2 数据模型 `towns`（新原子容器）

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `id` | 是 | `town_<hash(name\|owner)>`；`owner` 变更时**沿用旧 id**（易主不换身份），由 `devHistory` 记录版本 |
| `name` | **是** | 城镇名（如「长安城」） |
| `pathStr` | 否 | 对应场景路径前缀（供**与 `scenes` 关联**与侧栏跳转）；缺省时按 `name` 前缀匹配 |
| `owner` | 否 | **归属版图**（国 / 势力 / 领主）；空 = **未知/无主**（见 §6 Q6） |
| `ownerSince` | 否 | 归属自（剧情日期字符串，`clockDateValid` 校验） |
| `scale` | 否 | **规模**五档：`village` 村 · `town` 镇 · `city` 城 · `metropolis` 大城 · `capital` 都城 |
| `index` | **是** | **发展指数**：**0–100 整数**（越大越繁荣） |
| `trend` | **是** | **三向度闭集**：`up`（向好）/ `steady`（平衡）/ `down`（向坏） |
| `desc` | 否 | 概述（现状一段话，≤ 300 字） |
| `devHistory` | 否 | **变化留痕**（见 §3.4）：`[{ date, index?, trend?, owner?, scale?, note?, floor? }]` |
| `floorSeen` | 否 | 最近一次被观察的楼层 |
| 通用元字段 | 否 | `nsfw` 等沿用 `02` §1.3 |

**归一硬规则（`02` I2「归一即夹取」）**

| 输入异常 | 处置 |
| --- | --- |
| `name` 空 | **丢弃该条**（无身份就没有意义） |
| `index` 缺失 / 非数 | 取 **50**（中性基准）并**记一条 `devHistory` 说明"初值补全"**（不静默） |
| `index` 越界 | 夹取到 0–100（取整） |
| `trend` 非法 | 退化为 **`steady`**，并在 `devHistory` 记"非法值纠正" |
| `scale` 非法 | 退化为 **`town`**（镇——最常见单位） |
| `owner` 空 | 允许（= 未知/无主），但侧栏显示「归属未知」并要求补全（§6 Q6） |

### 3.3 与场景 / 地图的关联

| 关联 | 口径 |
| --- | --- |
| **与 `scenes`** | 优先用 `pathStr` **前缀匹配**（`scenes.pathStr` 以 `towns.pathStr` 开头即视为属于该城镇）；无 `pathStr` 时用 `name` 在 `pathArr` 中**全词命中** |
| **与 `maps`** | 不直接引用 `maps`；侧栏点击某城镇时，按"该城镇下所有场景 → 这些场景的 `place` 节点"**间接高亮**（地图子页） |
| **多城镇同名** | 以 `owner` 区分身份；`owner` 都空时以 `pathStr` 区分；仍冲突则**保留首条**并在体检提示"同名歧义" |
| **删除** | 仅用户显式删除；**不随场景删除**（城镇比场景活得久） |

### 3.4 发展留痕（`devHistory`）

**必须留痕的四类变化**（任一发生即追加一条节点）：

1. `index` 变更（含初值补全）
2. `trend` 变更
3. `owner` 变更（**易主**）
4. `scale` 变更（升级/降级）

**节点形态**：`{ date, index?, trend?, owner?, scale?, note?, floor? }` —— 只记**发生变化的字段**，未变的不写（避免噪声）。

**派生（不另存）**：

- `ownerHistory` = 从 `devHistory` 中取 `owner` 非空的节点**折叠**得出（不单独存字段 —— 避免两套真相）
- 侧栏「⚑ 易主」徽标 = `devHistory` 最近一条含 `owner` 的节点距今（剧情时间）较近（阈值可配，建议 ≤ 30 天）

**幂等**：同一 `date + 变化字段值` 不重复追加（重复提交得到同一节点）。

### 3.5 侧面 UI（场景页右侧栏）

| 项 | 口径 |
| --- | --- |
| **位置** | 场景页**右侧栏**，跨「场景树 / 地图」两个子页**常驻**（不因切换子标签而消失） |
| **卡片内容**（复用 `D55` 三段式） | **首行**：城镇名 + 三枚语义徽标（`⚑ 归属` · `▣ 规模` · 方向 `↗ 向好 / → 平衡 / ↘ 向坏`）；**中段**：发展指数**进度条**（0–100，数值 + 条形）+ 归属自日期 + 最近变化一句；**尾段**：查看详情 / 在地图定位 |
| **排序** | 默认按「最近变化（剧情日期）倒序」；可切换「指数高→低」（沿用列表页排序口径） |
| **联动** | 点卡片 → ① 场景树子页：过滤到该城镇下场景；② 地图子页：高亮其对应 `place` 节点 |
| **空态** | "还没有城镇数据。城镇由「AI 摘要」从正文识别，也可在侧栏手动新建。" |
| **窄屏** | 宽度不足时侧栏折叠为**顶部一行摘要**（当前/最高指数城镇 + 方向），点开为抽屉 |
| **视觉约束** | 严格复用 `docs/D55` 的设计令牌与卡片层级；**新增徽标须沿用既有徽标形态**（不新造组件） |
| **不新增分页** | 侧栏属于场景页内部布局，`PANEL_TABS` 不变（N6） |

### 3.6 注入（从属，不新增小节）

| 项 | 口径 |
| --- | --- |
| **落点** | `core/recall.js` 的 `[场景地点]` 小节（K5）——与 `maps` 的 `mapRows` **并列追加** `townRows` |
| **触发条件** | **仅当**本次入选的场景属于某城镇（§3.3 前缀匹配）时，才为该城镇追加**一行** |
| **行形态** | `- 〔城镇〕长安城 · 归属：唐 · 规模：都城 · 发展指数：72（向好）`（可选附一句最近变化） |
| **每小节上限** | 最多 **3 行**（按指数或最近变化取前 3），防挤占场景正文 |
| **预算优先级** | **场景正文 > 地图子块 > 城镇行**：超预算时**先裁城镇行**（明确写死，便于测试） |
| **不新增小节** | **禁止**出现独立的「[城镇]」小节（N5）；场景未入选 → 城镇行**完全不出现** |
| **常驻通道（待裁决 Q2）** | 若采纳：额外一行 `〔所在城镇〕…`，仅在"主角当前所在城镇已确定"时输出，且**仍并入 `[场景地点]`** |

### 3.8 与 `D28`（不删数据）的衔接

- `towns` 只增不减；`devHistory` 长期累积**不设条数上限**（只限单条 `note` 字数）。
- 超量时按 `D28` 的**冷热分层**：热集 = 最近变化的 N 个城镇（侧栏首屏与注入只看热集），冷存可搜索、可翻页，**不删除**。
- **无级联删除**：城镇**不随**场景/地图删除（§3.3 末条）—— 与 `D53` 的"货币消失→流水级联删"不同，因为城镇是**独立语义主体**，不是派生数据。
