### 1.2 「同步后情节丢失」的可疑路径（按可能性排序，均可验证）

| # | 路径 | 机制 | 证据 |
| --- | --- | --- | --- |
| **R1** | **内容墓碑 + 墙钟未知 → 静默删除** | `applyDeletedToArray`：`deadByHash = !!th && (wall === 0 \|\| th >= wall)`。条目若**没有 `updatedAt` 毫秒墙钟**（跨端同步进来 / 旧存档 / 对端写入），只要其**身份指纹**与任一内容墓碑相同即被删除；而 v2.86.0 起身份指纹收窄为 7 槽（**不含 `time`/`entities`/`owner`**）→ 同一天、同题、同正文而仅时段/在场角色不同的两条情节会被判为「同一条」 | `core/sweep.js:133-155`（原口径）；`core/model/hashfields.js#IDENTITY_FIELDS`；**v2.91.0 已修正为「只删有明确墙钟且不晚于墓碑者」** |
| **R2** | **快照链按 `atomsHashes` 去重** | `mergeSnapshotStores` 把双方快照按 `JSON.stringify(atomsHashes)` 去重；v2.86.0 起快照哈希取自**变更指纹**（口径未变，但与更早版本写入的快照不同）→ 旧快照与新快照**不被识别为同一份**，链变长；若随后触发 `trimSnapshots()` 上限（30）+ 根快照合并，**覆盖面缩小**，回滚时看不到早期情节 | `core/cross-sync.js#mergeSnapshotStores`、`core/snapshots.js`（`SNAP_CAP=30` / `SNAP_BATCH=15`） |
| **R3** | **合并后触发上限裁剪** | 合并进来的远端情节若使 `atoms` 超过 `storeCapFor('atoms')`（默认 3000×23%≈690），下一次保存即裁剪（重要度→调用次数→新者优先）。若一端配置仍是**旧的逐维上限**（`storeTotalMax` 缺省 → 兼容口径），上限口径不同 → 一端裁得更狠 | `core/ingest.js#enforceDimCaps` / `capAtomsKeepingHidden` / `storeCapFor` |
| **R4** | **id 墓碑误伤** | id 由 `atom_<hash(text+floorStart+floorEnd)>` 派生；两端楼层不同 → 同内容异 id。删除动作在 A 端留下 id 墓碑；B 端若**恰好**生成了同 id（同正文 + 同楼层档），会被删 | `core/model/atom.js`（id 派生）、`core/sweep.js`（`deadById`） |
| **R5** | **原生通道与文件通道并存** | TauriTavern 下若同时启用「原生 KV」与「镜像到文件」，两条通道的**时间戳与写入顺序**可能交错；`stateFileReadCandidates()` 的选择顺序决定读哪一份，读错即「像丢数据」 | `adapters/tt-store.js:157-159`（`ttNativeActive` / `ttMirrorToFiles`）、`adapters/sync.js#stateFileReadCandidates` |

> v2.91.0 已修 **R1**（保守判据：墙钟未知的条目**只**由 id 墓碑删除；代价是极少数「同内容换 id 复活且无墙钟」会漏挡）。
> **R2–R5 未修**，需按下节取证后处理。

## 4. 存储简化（用户要求 ②）

### 4.1 现状复杂度来源（V1 遗产）

V1 是**酒馆助手脚本注入**：没有插件级存储 API，只能自己拼「文件 + 世界书 + 浏览器缓存」三套并用，因此衍生出：
瘦身/同义收敛、gzip、快照链（增量 + 根合并）、世界书镜像（借用世界书当存储）、墓碑双账本（防跨端复活）、
processedFloors 台账、缓冲清理页……**多数机制的存在理由是「宿主不给存储」**。

### 4.2 目标架构（简化后）

```text
配置        → ST 扩展设置（extensionSettings.cfg）          ← 既有，不动
记忆数据    → **宿主原生存储**：
              · TauriTavern：原生 KV（单键）+ blob（大对象/备份）
              · 其它宿主：ST 扩展存储（若有）→ 否则状态文件
备份/迁移   → 状态文件（明文 JSON）+ 可选 gzip          ← 只在「导出/迁移/兜底」时写，不再每次保存都写
快照        → 保留「手动快照 + 一个自动根」即可；**增量链降级为可选**（默认关）
世界书镜像  → 降级为「只读派生视图」（默认关；需要时手动开启）
墓碑账本    → 保留（必要的防复活机制），但加**上限与过期回收**
```

**判据**：一条通道只有在「宿主确实不提供」时才保留默认开启。原生可用 → 其余默认关闭（不再双写）。

### 4.3 迁移与兼容

| 项 | 口径 |
| --- | --- |
| 已有数据 | 首次启动：按「原生 → 文件 → 缓冲」顺序**读最优**，成功后**写回原生**（一次性迁移，保留原文件不删） |
| V1 存档 | 既有导入链不变（`adapters/import-v1.js`） |
| 回滚 | 每次迁移前导出一次明文状态文件（保留 3 份轮转） |
| `DATA_VERSION` | 简化只改**通道**不改**结构** → 保持 1；若引入新容器再递增 |
| 兼容开关 | `cfg.storage.nativeOnly`（默认：原生可用时 true）、`snapshotIncrEnabled`（默认 false）、`worldbookMirror`（默认 false）、`tauriMirror`（默认 false） |

## 8. 后续版本复核：宿主能力面与「本机目录模式」的裁决（v0.4，只增不改）

> v0.4 变更（v3.26.0/v3.26.1 落地后复核）：把**真实宿主能力面**与**由此产生的设计约束**登记下来 ——
> 这几条属 `docs/D15` §3 **类别②（可偏离：宿主差异）**：V1 无宿主原生存储概念，V2 只能按宿主实际 ACL 设计。

| # | 事实（实测 / 代码证据） | 由此确定的设计口径 |
| --- | --- | --- |
| **H1** | 宿主 store 的命名空间 / 表 / 键**只允许 `[A-Za-z0-9_.-]`**（`adapters/tt-store.js#ttKeyOf`；本地目录映射见 `adapters/local-file.js#localFileNs`） | 「选择目录」只能是**宿主数据目录内的相对目录名**（盘符 / 前导斜杠 / `..` 一律剥掉）；**非 ASCII 目录名带路径短哈希**，避免 `记忆缓冲` 与 `剧情缓冲` 双双变成 `____` 而互相覆盖（v3.26.0 修复） |
| **H2** | 宿主**没有可用的通用文件对话框 API**：Tauri ACL 直接拒绝（真机取证 `Command plugin:dialog|confirm not allowed by ACL`：见 `docs/history/P10g-设定按钮审计与调试包导出.md`，本仓侧兜底见 `ui/panel.js#confirmDialog` 与 `index.js` 里的确认弹窗兜底（`ctx.callGenericPopup` 优先）） | 目录选择器**不依赖原生对话框**：候选目录 + 「新建并使用（写探针 → 回读校验）」为主路径；「从系统选择文件夹」只作便利入口，**只取文件夹名**并在提示里写明「宿主限制 → 实际写到数据目录内」 |
| **H3** | 宿主是否提供**目录枚举**（`listNamespaces` / `listDirs`）**不在官方 Public Contract 内**，只能**能力探测**（`adapters/tt-store.js#ttDirListCapability`） | 界面**按能力渲染**：有能力 → 渲染「🔍 扫描宿主已有目录」并列出；无能力 → 如实写「宿主未提供目录枚举（可手动输入）」，**不假装**能浏览 |
