# D37 · 管道请求守门（开工弹窗提示 · 同动作排重 · 在途按钮禁用）

> 文档版本：v1.0 ｜ 日期：2026-10-13 ｜ 类型：**设计稿（不发版）** ｜ 状态：**已裁决并落地（v3.46.4）**
> 关联台账：`docs/D17-未落实事项台账.md` §1.30（**U229**）· 执行视图 `docs/D22` §4.15（**W14**）· 本稿实施规格 **1 条**（`应-31`）。
> **来源（用户原话）**：「新版本v3.46.4 / 上一个版本修复的内容，如果发起管道请求操作，应该有弹窗提示。
>   核对相关按钮是否存在排重点击的机制，避免用户反复点击触发。」
> **用户裁决（本轮）**：① 弹窗形式 = **开工弹窗提示**（沿用仓内既有 `panelNotify('info', '…开始…')` 惯例，**不加二次确认**）；
>   ② 覆盖面 = **全部管道请求类动作**统一纳入。

## 0. 一页摘要

**问题（用户报告）**：v3.46.3 修好「动作结果提示看不见」之后，用户提出两件事 ——
（1）**发起管道请求时应当有弹窗提示**；（2）**核对按钮有没有排重点击机制**，别让用户反复点触发多次。

**核对结论（本轮实测，不是推测）**：

| # | 核对项 | 结论 |
| --- | --- | --- |
| 1 | 货币融合 / 履历补全 / 联动构建 有没有**自己的**在途闸？ | **没有** —— 只调用共享的 `aiBusy()` |
| 2 | `aiBusy()` 管什么？ | 「**摘要 / 提取 / 同步在途**」的忙位（`core/ai-hooks.js` 的 `busy` 钩子 → `host/extract.js#extractBusy`）—— **不含自己这次 AI 请求** |
| 3 | 所以连点两下会怎样？ | 两次 `aiBusy()` 检查**都为假** → **真的发两次 AI 请求**（重复烧 token、重复占管道） |
| 4 | `runResumeRepair`（📜 补全 / 修复履历） | 此前**连 `aiBusy()` 都没有** —— 三个动作里最裸的一个 |
| 5 | 在途期间按钮状态 | **不 `disabled`** —— 用户看不出「已经点过了」，视觉上还在鼓励继续点 |
| 6 | 有没有通用闸？ | 没有。`panelAction` 只有「载入未完成」一道闸（`loadBlocked()`），与重复点击无关 |

**结论**：**排重机制此前不存在**（不是"有但不灵"），故本稿从零建立；
**弹窗口径**沿用仓内既有惯例（AI 类动作开工时本就弹一条 `panelNotify('info', '…开始…')`，
如 `'AI 摘要：开始分析…'`、`'自定义推演：开始推演…'`），不新增「二次确认」这一交互。

**一句话方案**：新模块 `ui/pipe-guard.js` 用一张 **24 项的动作登记表**（`PIPE_ACTIONS`，唯一事实源）承载三件事 ——
**开工必弹窗提示** · **同动作在途排重**（挡下并明说）· **在途按钮禁用**；释放点复用 `panelAction` 已有的统一收尾，
另加 5 分钟安全阀。

## 1. 目标 / 非目标

### 1.1 目标

1. **开工告知**：登记过的管道请求类动作**真正开工时**弹一次提示，让用户知道「一次 AI 请求已经发出、正在等返回」；
2. **防重复触发**：同一动作上一次未结束前，再点**一律挡下**（并且**明说**为什么没反应，不静默忽略）；
3. **看得见**：在途期间该按钮渲染为 `disabled`，让用户**看得见**"现在点不动"；
4. **不会锁死**：无论动作成功 / 失败 / 抛异常 / 早退，守门**一定释放**；另有安全阀兜底；
5. **清单可维护**：登记表是唯一事实源，且有**自维护哨兵**保证登记的名字真实可调度。

### 1.2 非目标（明确不做）

1. **不做二次确认**（用户已裁决：要的是「提示」不是「确认」）—— 不加确认点击，不并入 `docs/D9` §10 **U4** 的危险动作清单；
2. **不做全局串行**：排重**按动作名**，**不同动作仍可并行** —— 不改动既有的「摘要 + 推演可并行」能力（那是 `aiBusy()` 的分工）；
3. **不做中断入口**：那是 `docs/D9` §10 **U6**（长耗时动作的忙状态与中断入口）的范围，本稿只补「开工告知 + 排重 + 禁用」；
4. **不接管非动作路径**：命令（`/ftt-*`）、启动期自动管线、宿主事件驱动的提取**不走** `panelAction`，因而不受本守门约束
   （它们的互斥仍由 `aiBusy()` / 管线自身表达）。

## 2. 现状核对（只读，逐条带证据）

| # | 事实 | 证据 |
| --- | --- | --- |
| 1 | 三个动作只检查共享忙位 | `ui/currency-merge.js#currencyMergeRun`、`ui/tri-link.js#triLinkRun` 均有 `if (aiBusy()) return {…reason:'busy'}`；`aiBusy()` = `core/ai-hooks.js` 的 `busy` 钩子（注释写明「摘要/提取/同步在途」） |
| 2 | 履历补全没有忙位检查 | `core/character-repair.js#runResumeRepair` 内无 `aiBusy()`（v3.46.3 的 H 组用例跑通该路径时也未触发 busy 分支） |
| 3 | 调度层没有排重 | `ui/panel.js#panelAction` 开头的闸只有 `loadBlocked()`（载入闸门），无「同动作在途」判定 |
| 4 | 按钮不随在途禁用 | 三个入口的按钮（`ui/currency-merge.js#currencyMergeButton`、`ui/tri-link.js`、`ui/list-rows.js` 的 `resumeRepair`）渲染时不读任何「在途」状态 |
| 5 | 仓内已有「开工提示」惯例 | `ui/panel.js` 内 `panelNotify('info', 'AI 摘要：开始分析…')` / `'自定义推演：开始推演…'` / `'第 N 楼：开始分析…'` |
| 6 | 统一收尾已存在（可复用） | `ui/panel.js#finalizePanelAction`（v2.96.0 为「早退也要重绘」而抽出）—— **所有**返回路径都过它 |

## 3. 方案

### 3.1 三层位置

```text
点击 → panelAction(action)
        ├─ 载入闸门（原有：loadBlocked）── 未读完 → 拒绝
        ├─ 【新】pipeEnter(action)
        │     ├─ 未登记 → 完全不介入（零开销）
        │     ├─ 已登记 + 在途 → 挡下整条动作（提示行 + ⚠️ warning）
        │     └─ 已登记 + 空闲 → 登记 + 返回开工提示（若该动作自带提示则不返回）
        ├─ …（原有分支照旧执行）…
        └─ finalizePanelAction(...) ── 【新】pipeLeave(action)   ← 成功/失败/异常/早退都过
渲染 → panelModalInnerHtml(...) ── 【新】pipeDisableInFlightHtml(html)  ← 在途按钮注入 disabled
```

### 3.2 登记表（唯一事实源）

`ui/pipe-guard.js#PIPE_ACTIONS`：`action → { label, selfNotice? }`，共 **24 项**。

| 类别 | 动作 |
| --- | --- |
| 写库（提取 / 摘要） | `summary`\* · `summaryFloor`\* · `plotSegmentSummarySel` |
| 自动修复族 | `repair` · `characterRepair` · `resumeRepair` · `stateRepair` · `memoryRepair` · `conceptRepair` · `sceneRepair` · `itemRepair` · `planSuspRepair` |
| 压缩 / 合并 | `atomCompactNow` · `atomMergeSummary` |
| 平行事件 / 推演 | `parallelAdvance` · `parallelAdvanceAll` · `parallelCustomRun` · `parallelWeaveNow` |
| 三域联动 / 货币融合 | `triLinkBuild` · `currencyMergePick` |
| NSFW / 时钟 | `nsfwSoften` · `nsfwAnalyze` · `clockRepair` |
| 通道 / 向量测试（**真实网络请求**） | `apiTest` · `apiModels` · `testLayer` |

\* `selfNotice`：`summary` / `summaryFloor` **自己**已弹开工提示 → 本模块**只做排重与禁用、不再补弹**（同一次点击绝不弹两条）。

### 3.3 三条口径

| # | 口径 | 文案 / 行为 |
| --- | --- | --- |
| ① | 开工弹窗 | `🔄 <label>：已发起 AI 请求（管道请求），等待返回…`（`docs/D9` §7 **U7** 进行中图标口径） |
| ② | 在途排重 | 提示行 = `<label>：上一次请求还在进行中（已挡下本次重复点击）`；弹窗 = `⚠️ …已挡下本次重复点击`；动作返回 `{ok:false, reason:'in-flight'}` |
| ③ | 在途禁用 | 渲染期给在途动作的 `<button>` 注入 `disabled`；`<a>` 形态**不注入**（原生 `disabled` 对 `<a>` 无效），点击仍由 ② 兜底 |

### 3.4 释放与安全阀

* **释放点**：`finalizePanelAction`（唯一收尾）—— 覆盖成功 / 失败 / **异常** / 早退；
* **安全阀** `PIPE_MAX_MS = 300000`（5 分钟）：占用超时 → **自动放行本次**并 `timeouts += 1`（如实计数），
  提示写明「上一次请求已超时 Ns（已放行本次）」。
  取舍：**宁可放行，也不把按钮永久锁死** —— 与 `docs/D22` `技-1` 落盘守门同一套哲学（失败要可见，不要静默卡死）。

### 3.6 **不在册的两个动作**：`summary` / `summaryFloor`（v3.46.4 实测后修正）

首版把这两个也登记进 `PIPE_ACTIONS`（共 26 项），结果 **smoke 立刻变红两项**（BA3、BJ1）。查明确切原因后**改为不并入**：

| 事实 | 说明 |
| --- | --- |
| 它们**本来就有自己的在途闸** | `summaryFloor` 用 `ui/panel.js#singleFloorBusyState()`，是**按楼层**判重；`summary` 走批量管线的忙位 |
| 粒度**更细** | 统一守门按**动作名**判重 → 对 `summaryFloor` 而言，「3 楼正在分析」会把「5 楼」也一起挡下 |
| **开工提示它们本就自己弹** | `AI 摘要：开始分析…` / `第 N 楼：开始分析…` —— 用户要的「弹窗提示」对它们**已经成立** |
| 并入的后果（实测） | 第二次点击的**拒因文案被本表改写**（原本由更细的机制给出更准的原因）→ BJ1 断言失败 |

**处置**：`summary` / `summaryFloor` **不进登记表**；登记表 **24 项**。
**「全部管道请求类动作」的准确含义**（对 Q2 裁决的补注）：**全部「没有自己的在途闸」的管道请求类动作** ——
已有更细闸的动作**不并粗闸**，这才是同一类风险同一口径的正确读法（否则是「统一」压掉「更准」）。

### 3.5 与既有件的关系

* **`aiBusy()`**：管「跨管线的忙位」（摘要 / 提取 / 同步在途）；本守门管「同一动作的重复点击」→ **互补，不替代**；
* **`docs/D9` §10 U6**：管「长耗时动作的忙状态与中断入口」；本稿是 U6 的**补集**（开工告知 + 排重），随后登记为 **U15**；
* **`docs/D9` §10 U4**：危险动作二次确认清单 —— 本稿**不并入**（不是危险动作，用户也明确不要确认）；
* **`docs/D10` 的 ready 守门 / `技-1` 落盘守门**：同为「时序守门」家族，安全阀哲学一致。

## 5. 风险与对策

| # | 风险 | 对策 |
| --- | --- | --- |
| R1 | 守门**误杀正常连点**（用户确实想点两次不同操作） | 排重**按动作名** —— 不同动作不互相阻塞；同一动作的第二次点击**明说**被挡（不是静默），用户能理解 |
| R2 | 释放点被绕过 / 宿主不回调 → 按钮**永久点不动** | 释放点放在**唯一收尾**（异常也过）+ `PIPE_MAX_MS` 安全阀（超时放行并计数） |
| R3 | 登记表**漏登记**新 AI 动作 → 新按钮没有守门（**例外**：若该动作已有更细的在途闸，按 §3.6 **不并入**） | E1 哨兵：登记表里每个动作必须**真实可调度**；D22/W14 行 + `docs/D9` C13 固定检查口径；新增 AI 动作时同批登记（写进 `docs/05` 与批次档的口径） |
| R4 | 登记表**写错名字** → 守门永不生效（静默失效） | E1 哨兵（扫 `ui/panel.js` 的 `a === 'x'` + 各 `*_ACTIONS` 组）**直接失败**；E2 用**恰好 24 项**的快照防误删 |
| R5 | 在途禁用误伤（把不该禁的按钮禁了） | 只对**登记动作**且是 `<button>` 注入；`<a>` 与其它动作不动（C 组用例锁定） |
| R6 | 开工提示与动作自带提示**重复弹两条** | `selfNotice` 标记（`summary` / `summaryFloor`）+ B5 用例锁定「不补弹」 |
