| --- | --- | --- |
| **现状架构层**（`01`–`05`） | 「**现在**是什么样、为什么这样」 | **随版本更新**（改了行为就改这里） |

> 「下一步打算怎么做」→ `D*`。冲突时以 **`01`–`05` + 代码** 为准，并把 `history/` 里的过时结论登记到 `勘误-历史档过时条目.md`。

## 4. 命名规则

| 前缀 / 形态 | 归属 | 例 |
| --- | --- | --- |
| `README.md` | 索引（本文件） | —— |
| `0<数字>-<主题>.md` | **现状架构层**（排序稳定，`01`–`05`） | `02-数据架构.md` |
| `D<数字>-<主题>.md` | **设计稿层**（Draft） | `D2-关系约束层设计稿.md` |
| `P<阶段><字母?>-<主题>.md` | **历史批次层**（`history/` 内；`P` = 批次/阶段） | `history/P8r-B8-6c-1记忆聚类修复.md` |
| `B9-<主题>.md` | 历史批次层中的**专项批次**（`history/` 内） | `history/B9-测试完整性待修.md` |
| `<主题>.md`（排障 / 机制说明） | **专项层** | `排障-面板不显示.md` |
| `勘误-<主题>.md` | 过时登记的**只增**台账 | `勘误-历史档过时条目.md` |

**简称约定**：现状层与设计稿里出现的 `P6`、`P10ar`、`B9` 等简称，一律指 **`docs/history/` 下的同名文档**。

## 5. 维护约定

1. 新功能落地：更新**对应的架构篇**（改了什么行为）+ 在 `history/` 新增一份 `P*` 批次档（证据、门禁、关联文档）。
2. 设计讨论：只加 `D*` 设计稿，**不改代码、不动版本**（`开发守则.md` §1）。
3. `history/` 与 `CHANGELOG.md` **只增不改**；结论被推翻时在原档追加「结论变更」段落，并在勘误表登记。
4. 新增文档必须带**头部元信息**（文档版本 / 日期 / 类型 / 状态），由 `scripts/check-docs.js` 强制。
5. 改了会变数字的东西（维度 / 控件 / 测试规模）→ **同步更新本文件 §3**。
