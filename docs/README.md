## 1. 四层文档，各司其职

| 层 | 回答什么问题 | 更新时机 | 文档 |
| --- | --- | --- | --- |
| **现状架构层**（事实源） | 「**现在**是什么样、为什么这样」 | **随版本更新**（改了行为就改这里） | `01-业务架构` `02-数据架构` `03-技术架构` `04-应用架构` `05-开发指南` |
| **设计稿层** | 「打算做什么、待定什么」 | 设计轮次追加 / 修订 | `D1-约束机制现状梳理` `D2-关系约束层设计稿` `D3-文档架构设计稿` |
| **历史批次层**（只读留痕） | 「**当时**怎么做的、证据在哪」 | **只增不改**（新批次写新档） | `P0`–`P9x`、`P10a`–`P10ar`、`B9-测试完整性待修` |
| **专项 / 运维层** | 特定问题的处置手册 | 问题复现时更新 | `排障-面板不显示`、`更新检查机制` |

> **一句话口径**：想知道「现在怎么跑」→ 看 `01`–`05`；想知道「某次改动为什么这么做」→ 看对应的 `P*`；
> 想知道「下一步打算怎么做」→ 看 `D*`。三者冲突时，以 **`01`–`05` + 代码** 为准，并把 `P*` 里过时的结论登记到 `D3`。

## 4. 维护约定（摘要）

1. 新功能落地：更新**对应的架构篇**（改了什么行为）+ 新增一份 `P*` 批次档（证据、门禁、关联文档）。
2. 设计讨论：只加 `D*` 设计稿，**不改代码、不动版本**（`开发守则.md` §1）。
3. `P*` 与 `CHANGELOG.md` **只增不改**；结论被推翻时在原档追加「结论变更」段落。
4. 新增文档必须带**头部元信息**（文档版本 / 日期 / 类型 / 状态），由 `scripts/check-docs.js` 强制。
5. 文件名前缀：`01`–`05` 现状架构 · `D<n>` 设计稿 · `P*`/`B9` 历史批次 · 其它专项。
