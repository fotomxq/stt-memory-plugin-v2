# D50 · 货币无法自动变更（注入机制 / 提示词变更机制 / 提示词设计）

> 文档版本：v1.0 ｜ 日期：2026-10-20 ｜ 类型：**设计稿（不发版）** ｜ 状态：生效（已按本稿落地 v3.50.30）｜ **维度归属：数据（优先级 1）**
> 触发（用户原话）：「剧情明明提到了资金变化，且关键词也有，但货币完全没反应。请核对注入机制、提示词设计缺陷等问题。」
>   补充：「货币可以手动添加，这个没异常。只是注入机制、提示词变更机制存在缺陷，AI无法正常自动变更货币。」
> 前置：`docs/D22` §4.29（**W29 `数-40`**）· `docs/D17`（U261）· 相关往事：`D17` U231（货币注入曾整份变空）、`D22` `应-32`（货币融合）
> 事实基准：程序 **v3.50.30**（`core/constants.js#VERSION`）。本稿按**设计轮次**格式成稿并同轮落地。

---

## 0. 一页摘要

用户的现象很具体：**手动能加货币**（面板写入正常），但**剧情里出现资金变化时 AI 不会自动改**。
三处缺陷叠在一起，任一处都足以让「自动变更」完全失效：

| # | 缺陷 | 位置 | 后果 |
| --- | --- | --- | --- |
| ① | **注入匹配方向写反** | `core/recall.js#buildMemoryBodyForInject` 非主角货币分支：`hay.includes(q)` 拿**整段正文**去比「归属+币种+备注」 | 永远不命中 → 该货币**从不注入** → AI 没有账本参照，改不动 |
| ② | **模板为空/缺失时整维静默消失** | `core/prompt.js#buildSummaryPrompt`：`else if (pt[d])` | 旧存档 / 误清空 / 迁移缺键 → 【货币】整段不进提示词 → AI 收不到指令（其它维度同理） |
| ③ | **提示词缺「资金变化」触发规则** | `core/prompts-v2.js` 的【货币】块 | AI 遇到「说不清具体数字」就**整条不记**（负例「约一千多」放大了这个倾向） |

---

## 1. 目标 / 非目标

### 1.1 目标

1. **注入**：正文提到「币种名 / 单位 / 归属名 / 标签 / 备注」任一 → 该货币进入注入（不再要求整段正文等于字段拼接）；
2. **提示词变更机制**：任何维度的模板为空 / 缺失 → **回落默认模板**并留痕（`提示词` kind 调试日志），不再静默丢整维；
3. **提示词设计**：给【货币】块加**强制触发规则**（资金变化必须输出；没有精确总额也要记，额度按净额推算）；
4. 落库口径保持：`更新` 按「归属 + 币种」命中并覆盖额度、收支追加；只给收支时按「旧额度 + 净额」推算。

### 1.2 非目标（明确不做）

* **N1 不改货币的融合/拆分口径**（`应-32` / `currency-merge` 另案）；
* **N2 不加「自动换算汇率」**（既有边界：原文怎么写就怎么记）；
* **N3 不改 `DATA_VERSION`**：无字段形态变更（只改匹配规则与提示词文案）。

## 2. 现状核对（只读，逐条带证据）

| # | 结论 | 证据 |
| --- | --- | --- |
| K1 | 非主角货币的匹配是 `hay.includes(q)`：`hay` = 归属+币种+备注，`q` = **整段正文** → 恒为假 | `core/recall.js#buildMemoryBodyForInject` 货币分支 |
| K2 | 主角货币恒定注入（`isMine` 含 `owner === '主角'`、`defaultCurrencyOwner()`、标定跟踪），故「主角那条其实会注入」——**用户看到的"没反应"多发生在**: 账本归属是角色名 / 正文提到的是币种而非归属 | 同上 |
| K3 | `buildSummaryPrompt` 取模板缺兜底：`cfg.promptTemplates.<d>` 空串或缺失 → `else if (pt[d])` 直接跳过 | `core/prompt.js` |
| K4 | 【货币】块没有触发规则；三条负例（约数 / 未到手 / 非主角）会让 AI 更倾向于**不输出** | `core/prompts-v2.js` currencies 块 |
| K5 | `mergeDelta` 的货币更新路径本身正常（覆盖额度 + 收支追加 + 净额推算）——**故障不在落库** | `core/ingest.js` 货币段 |

## 3. 方案

### 3.1 ① 注入匹配方向（`core/recall.js`）

非主角分支改为「**正文是否提到该货币**」：

```text
hitKw = nameMatch(owner, q)                       // 正文提到归属名
      || q.includes(币种名)                        // 正文提到币种（如「银元」）
      || q.includes(备注)                          // 备注被提到（≥2 字）
      || tagMatch(tags, q)                         // 正文提到标签（既有口径）
      || (单位 && 资金变化词 && q.includes(单位))   // 如「三枚银币」：单位 枚 + 钱相关词
```

「单位 + 资金变化词」这条是为「**币种写法与账本不一致**」准备的（账本 `银元`、正文 `银币`），
但要求同时出现**单位**与**钱相关词**，避免「一枚戒指」这类误伤（单测 A2 锁「没提就不注入」）。

### 3.2 ② 维度模板兜底（`core/prompt.js`）

新增 `tplOf(key)`：取 `cfg.promptTemplates[key]`；为空串 / 缺失 → 回落 `PROMPT_TEMPLATES_V2[key]`，并 `dbgLog('提示词', …)` 留痕。
**用户自定义内容一律优先**（不被默认覆盖）——「清空某维模板」不再是「禁用该维」的隐式手段（禁用请用 `dimensionEnabled`）。

### 3.3 ③ 提示词触发规则（`core/prompts-v2.js`）

在【货币】块第一行后新增（**V1 黄金偏离，按 `开发守则.md` §2.4 三件套登记**）：

```text
触发（**强制**）：正文出现**资金的收 / 支 / 转移 / 找零 / 报数 / 余额变化**（买、卖、付、收、花、赚、亏、借、还、赏、罚、薪、盘缠、积蓄、欠款、余额…）时，**必须**输出【货币】条目；**没有精确总额也要记** —— 给出本次收支即可（额度按净额推算），不要因为「说不清具体数字 / 原文只说资金见底」就整条不记。
```

### 3.4 落点与体量

| 文件 | 改动 |
| --- | --- |
| `core/recall.js` | 非主角货币匹配改写（约 10 行） |
| `core/prompt.js` | `tplOf()` 兜底 + `提示词` kind 留痕 |
| `core/prompts-v2.js` | 【货币】块 +1 行（触发规则） |
| `core/debug-catalog.js` | `DEBUG_KINDS` 登记 `提示词` |
| 测试 | 新增 `tests/unit/currency-auto.test.js`（9 项）· `extract-prompt-flow` P1 偏离归一 + P1b · `separate-dim-golden` G2 偏离归一 |

### 3.5 回退

三处改动都是独立小改：注入匹配还原一条表达式、`tplOf` 去掉兜底、提示词删那一行即可回到 v3.50.29 行为。

## 4. 风险与对策

| # | 风险 | 对策 |
| --- | --- | --- |
| R1 | 「单位 + 钱词」误注入无关货币 | 要求**同时**命中单位与钱相关词；单测 A2 锁「没提就不注入」 |
| R2 | 模板兜底让「用户清空=禁用」失效 | 明确口径：禁用维度请用 `dimensionEnabled`；兜底只防「静默整维消失」，且有调试留痕 |
| R3 | 提示词加行改变 V1 逐字黄金 | 按 §2.4 登记：黄金样本**一字不改**，测试内**显式剔除该行**再比对 + 新增正面断言 |
| R4 | 触发规则过度诱导（编造额度） | 规则要求「归属与币种能判断」，且明确「没有精确总额也要记**收支**」而非编造总额；负例仍保留 |
| R5 | 体量棘轮 | 三处均为函数体内小改，无新文件逻辑膨胀 |
