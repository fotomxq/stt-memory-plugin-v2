## 0. 一页摘要

**现象**：出生日期与剧情日期都把年份**卡在 4 位 / ±9999**（`\d{1,4}` + `-9999..9999` 判断，且校验依赖 `new Date(ms)` —— Date 只到 ±273,790 年）。
于是：`-9999-01-01` 之外的公元前（如 `-12000`）与玄幻纪元的百万年 / 亿年**一律判非法** → 出生日期算不出年龄、剧情日期存不进去 → 「卡死」。

**主张**：把「日期」从**字符串正则 + Date 运算**换成**整数日历**（年份只受安全整数护栏约束），
并把年龄的展示做**单位简化**（岁 / 万岁 / 亿岁 / 万亿岁）。

| 决策点 | 结论 | 理由 |
| --- | --- | --- |
| 年份范围 | **不设业务上限**，只受溢出护栏 `BIG_YEAR_MAX = 1e13` | 用户原话「不应限制死范围，确保计算不溢出即可」；1e13 年 × 365.2425 ≈ 3.65e15 日仍在安全整数内 |
| 纪年约定 | **历史纪年（无 0 年）**：`-9999` = 公元前 9999 年 | 用户原话明确；日序算法内部用天文纪年（有 0 年），进出各偏移 1 年 |
| 结构 | `[正负]年-月-日`（另接受年-月 / 年两种低精度；`-` `/` `.` 等价） | 用户原话「结构必然是正负年份-月份-月份」 |
| 计算 | 全部**整数**（日序 = `days_from_civil`），不经 `Date` | 不经 Date 就没有 ±273,790 年的天花板，也不会溢出 |
| 年龄展示 | `<1万` 岁 · `≥1万` 万岁 · `≥1亿` 亿岁 · `≥1万亿` 万亿岁（最多 1 位小数） | 用户举例「102万岁、300亿岁」 |
| 神话尺度 | 年龄 ≥ 1 万岁**不再**报「超长年龄（疑长期未出场）」 | 那是**凡人**长期未出场的启发式；玄幻百万年是设定本身 |

## 1. 目标 / 非目标

### 1.1 目标

1. **出生日期**：支持 `-9999-01-01`、`-12000-01-01`、`3000000-05-01`、`9999999999-01-01`（千亿年）等写法，结构固定为「正负年份-月-日」；
2. **剧情日期**（年龄的另一个输入）同样放开位数，使玄幻纪元能够**存进去**；
3. **年龄**：跨大年份相减正确（含精度规则与跨纪元修正），且**不溢出**；
4. **展示**：按量级自动换单位（`42岁` / `102万岁` / `3亿岁` / `1.5万亿岁`）；
5. **不误报**：万岁级以上的年龄不再触发「疑长期未出场」的待研判信号；
6. 解析 / 计算 / 展示的**唯一事实源** = 新模块 `core/model/bigdate.js`。

### 1.2 非目标（明确不做）

* **N1 不改提示词逐字文本**：角色档案 / 角色修复两支模板与 V1 **逐字**锁定（`v1-golden-character-repair.json` / 配置黄金样本）→
  本轮只放开**解析层**；AI 按剧情照录大年份即可（提示词措辞另立条目并走黄金归一）。
* **N2 不改毫秒域语义**：`storyDateMs` 仍按 `Date` 实现（用于按天衰减 / 老化）；
  |年| > 275,760 时它返回 `NaN`，调用方按「无日期」降级（**不崩、不误判**）—— 大跨度的**排序与相差**用整数日序（`bigDayNumber`）。
* **N3 不改 `DATA_VERSION`**：出生日期与剧情日期本来就是**字符串字段**，本轮只改解析/校验/展示 → 无数据契约变更、无迁移。
* **N4 不改年龄的存储语义**：`identity.age` 仍是**数字字符串**（`bigAgeText` 只在展示层用）。

## 3. 方案

### 3.1 新模块 `core/model/bigdate.js`（唯一事实源）

| 导出 | 作用 |
| --- | --- |
| `BIG_YEAR_MAX` / `BIG_YEAR_DIGITS` | 溢出护栏（1e13 / 13 位） |
| `bigDateParse(v)` | 解析为 `{y,m,d,precision}`：ISO（正负 / 大年份 / 时间后缀）· 年-月 · 年 · BC 文本（`公元前9999年1月2日` / `前9999年` / `9999 BC`） |
| `bigDateStr` / `bigYearStr` / `bigDateValid` | 规范化输出（负年份带 `-`；不足 4 位补零、更长不截断） |
| `bigDayNumber` / `bigDateFromDayNumber` | **整数日序**（`days_from_civil`；历史纪年 ↔ 天文纪年偏移 1 年）；1970-01-01 = 0 |
| `bigAgeYears(birth, now)` | 整年数（day/month/year 三种精度 + **跨纪元 -1** 修正） |
| `bigAgeParts` / `bigAgeText` | 单位简化（岁 / 万岁 / 亿岁 / 万亿岁，最多 1 位小数；空值 ≠ 0 岁） |
| `bigIsLeap` / `bigDaysInMonth` | proleptic Gregorian 闰年与月天数（负数年份同样成立） |

### 3.2 接线（三处）

| 位置 | 改动 |
| --- | --- |
| `core/model/snapshot.js` | `parseBirthDateParts` → `bigDateParse`（保留 BC 文本归一与精度语义）；`calcAge` → `bigAgeYears`（返回数字串，契约不变）；`age-extreme` 增加**神话尺度豁免**（≥1 万岁） |
| `core/clock.js` | `CLOCK_YEAR_MIN/MAX` → ±`BIG_YEAR_MAX`；`clockDateTrim` / `clockDateValid` / `clockDateParts` / `storyDateMsFromStr` 位数放宽；`clockDateParts` 改**整数校验**（不经 Date）；`clockYearStr` → `bigYearStr` |
| 全仓 14 文件 30 处 `\d{1,4}` → `\d{1,13}` | 只作用于「年份形态」的正则（日期门 / 年份提取 / BC 归一 / 未来来客判定） |
| `ui/list-rows.js` | 年龄展示 → `bigAgeText`（单位简化） |

### 3.3 纪年约定（本稿的**核心决定**，务必一致）

* **对外（用户 / 存储 / 展示）**：历史纪年，**没有 0 年** —— `-9999-01-01` = 公元前 9999 年（用户原话）；
* **日序算法内部**：天文纪年（有 0 年）→ 负年份**输入 +1**、**输出 -1**；
* 由此推导：公元前 1 年 12 月 31 日 → 公元 1 年 1 月 1 日 **相隔 1 天**；跨纪元年龄 = 年份差 **-1**（V1 朴素相减多算 1 年，本轮修正）。

### 3.4 单位简化阶梯

| 量级 | 单位 | 例 |
| --- | --- | --- |
| `< 1e4` | 岁 | `42岁` |
| `1e4 ~ 1e8` | 万岁 | `102万岁`（1020000 ÷ 1e4 = 102） |
| `1e8 ~ 1e12` | 亿岁 | `3亿岁` |
| `≥ 1e12` | 万亿岁 | `1.5万亿岁` |

最多保留 1 位小数并去掉尾随 `.0`；`< 1e4` 一律取整（年龄是整年）。空值 → 空串（**不允许「空 → 0岁」的假事实**）。

### 3.5 落点与体量

| 文件 | 改动 |
| --- | --- |
| `core/model/bigdate.js`（新） | 全部解析 / 日历 / 年龄格式化 |
| `core/model/snapshot.js` | 两函数改委托 + 神话尺度豁免 |
| `core/clock.js` | 范围与位数 + 整数校验 |
| 其余 13 个 core 文件 | 仅正则位数（`\d{1,4}` → `\d{1,13}`） |
| `ui/list-rows.js` | 展示层单位简化（1 行级接线） |
| 测试 | 新增 `tests/unit/big-date.test.js`（24 项）；`clock-patrol-golden` / `config-clock-golden` / `model-golden2` 三处**偏离归一** |

### 3.6 回退

`parseBirthDateParts` / `calcAge` 换回旧实现、`ui/list-rows.js` 改回 `+ '岁'` 即可回到 v3.50.25 行为（新模块留着不接线也不生效）。

## 4. 风险与对策

| # | 风险 | 对策 |
| --- | --- | --- |
| R1 | 超大年份让**日序**溢出 | 日序本身有 `8.64e15` 上限检查（超限 → `ok:false`，绝不返回错数）；毫米域（ms）另有 Date 上限并按「无日期」降级 |
| R2 | 纪年约定与既有数据错位 1 年 | 只影响**跨纪元**的年龄（±1 年）与极少数公元前日期；其余日期行为逐字不变（黄金样本锁住） |
| R3 | 放宽位数让「脏日期」被当成合法 | 仍强制：`0 年` 非法、月/日范围、2 月 30 日等按**按月天数**判非法、超护栏非法 —— 单测 B3 覆盖 |
| R4 | 展示单位让人误读精度 | 单位只在**量级**上简化（1 位小数）；原始数字串仍在 `identity.age` 与调试读数里可查 |
| R5 | 神话尺度豁免掩盖真正的数据错 | 只豁免 **≥1 万岁**；200–9999 岁仍按原判据（`overage` / `age-extreme`）—— 单测 F4 用 628 岁样本证明既有口径未被吃掉 |
| R6 | 体量棘轮 | 逻辑整体落新模块；`snapshot.js` / `clock.js` 只改函数体（不在 5 个受监控文件内） |
