## 1. 目标 / 非目标

**目标**

1. 把用户当轮裁决写成**可执行的边界口径**：V1 是**参考实现**，不是 V2 的契约；V2 以 `docs/D*` 设计稿 + `docs/01`–`05` 现状层为准。
2. 给出**三类处置**（数据契约 / 可偏离 / 仅作参考）的判定标准与**偏离登记三件套**，让「要不要跟 V1 一致」不再靠记忆与习惯。
3. 修正本轮实测出的**文档不一致**（失效行号引用、层级口径过时、设计稿与代码漂移）并登记。

**非目标（明确不做）**

- 不改插件行为（`core/` `host/` `adapters/` `ui/` `index.js` `style.css` `settings.html` 一律未改）；
- 不动版本号、不打 tag、不跑发布终检（本轮是**设计轮次**，见 `开发守则.md` §1）；
- **不批量重写存量绝对行号引用**（211 处，见 §6）：改用「口径 + 棘轮」约束，只减不增，触及即改；
- 不因为「V1 这么写的」去回退任何 V2 已裁决的改进；也不因为「V1 没这么写」去否定 V2 的新能力。

## 2. V1 的定位（一句话口径）

> **V1 = 参考实现与 oracle，不是契约。**
> · **参考**：它是 V2 的直系前任，绝大多数数据口径由它移植而来 —— 读它有助于理解「为什么是这样」；
> · **oracle**：`tests/fixtures/v1-golden-*.json` 是**真实 V1 跑出来的输出**，用作**行为回归的对照物**，不是「必须永远相等」的目标；
> · **不是契约**：V2 已独立演进数十版（存储通道、同步口径、UI 结构、重要度、传言演化…），这些地方的**权威是 V2 自己的设计稿与现状层**。

## 3. 三类处置（判定标准）

| 类别 | 判定 | 处置 | 例（证据） |
| --- | --- | --- | --- |
| **① 数据契约：不得偏离** | 改了就**读不动老存档**、**破坏跨端一致性**或**让哈希/墓碑失效** | 与 V1 **逐值一致**；确需改必须带迁移 + `DATA_VERSION` 递增 + 双端兼容 | `hashText`（djb2 → base36，id 与指纹的根）· 信封形状与 `storageHash`（`core/envelope.js`）· 维度 id 派生与内容指纹（`core/model/hash.js`）· 墓碑双账本（`state.deleted` / `state.deletedH`）· 合并口径（`core/cross-sync.js` + 墓碑生效）· 作用域键 `char:<hashText(id)>` 与存档文件名 slug（`adapters/user-file.js#slugify`）· 归一化语义 `normText`（保换行 / 截断）· 瘦身键映射的**可读旧键**（`core/slim.js`） |
| **② 可偏离：需登记** | 属于**实现缺陷修复**、**宿主差异**、**成本 / 体验取舍**、**用户明确要求** | 允许与 V1 不同；必须按 §4 登记，并给出**回归判据** | 传言掷骰 `NaN` 修复（`docs/history/P10c47`）· 文本卫生（`normText` 清坏占位 token，同档）· `processedDropped` / `lastChatFloor`（`docs/02` §3）· `state.chatKey` 聊天归属（同）· 宿主原生存储通道（`docs/D10`）· 本机目录模式（`docs/D13` §3.3）· 自动合并替代人工待选（`docs/D11` §3.1）· 删楼一次批量截断（`docs/history/P10c33`）· 重要度改窗口占比（`docs/D7`）· 内容哈希 R1=B 两指纹（`docs/D8`）· NSFW 等级留档 / 长生者 / 已去世判定（`docs/03`）· 通知出口统一（`docs/D9` §10）· 分页渲染（`docs/D13` §5）· **本机缓冲压缩留存**（v3.26.2：超预算不再丢本机层，属成本取舍；见 `docs/history/P10c48`） |
| **③ 仅作参考：无需对齐** | 文案措辞、内部函数命名与结构、V1 的历史怪癖（未被数据依赖） | **不需要**照搬；碰到就按 V2 设计稿重写；老怪癖可择机清理（清理属类别②，需登记） | V1 的 `notify(...)` 弹窗形态（V2 统一走 `ui/notify.js`）· V1 里靠 `getStoryNow()` 取日期的恒 `undefined` 怪癖（`docs/D6` §2 记为「逐字保留」，属可清理项）· V1 的逐页 HTML 拼接结构（V2 分页渲染重写） |

**判据的优先级**：类别① > 用户当轮明确要求 > 类别②（需登记） > 类别③。

## 4. 偏离登记三件套（缺一不可）

| # | 登记物 | 位置 | 要求 |
| --- | --- | --- | --- |
| 1 | **设计稿 / 现状层** | 相关 `docs/D*` 或 `docs/01`–`05` 的对应小节 | 写清「V1 口径 → V2 口径 → 为什么改」，并在表格里标 **「有意偏离 V1」**（沿用既有做法） |
| 2 | **历史档冲突 → 勘误表** | `docs/勘误-历史档过时条目.md` | 历史档**只增不改**：凡历史档里「与 V1 逐字一致」的结论被推翻，必须在勘误表追加一行（位置 / 原文口径 / 现行口径 / 证据 / 处置） |
| 3 | **回归判据** | 单元 / 冒烟测试 | 二选一：**(a) 显式归一** —— 测试里把「有意偏离」的字段归一后再与 V1 oracle 比对；**(b) V2 自基线** —— 新增一份明确标注「自基线（非 V1 oracle）」的 fixture 锁定 V2 行为，并在测试头写明「为什么这一段不与 V1 逐字比对」 |

**永不手改**：`tests/fixtures/v1-golden-*.json`（真实 V1 输出）。确需新的对照物时，**新增**文件（如 `tests/fixtures/rumor-evolve-v2-baseline.json`），不与 oracle 混放、不覆盖。

## 7. 风险与对策

| 风险 | 对策 |
| --- | --- |
| 「可偏离」被当成「随便改」→ 老存档读不动 | 类别①的清单是**硬边界**：涉及 id / 哈希 / 信封 / 墓碑 / 合并 / 文件名的一律先做迁移与双端兼容，再谈偏离 |
| 偏离只写在代码里、文档没跟 → 下一个人又「修回去」 | 登记三件套（§4）缺一不可；勘误表是兜底入口 |
| 行号引用继续增长，文档再次大面积失真 | C9 棘轮（只减不增）+ C8 符号级阻断 + 设计稿只写「可核对的符号」 |
| 一次设计轮次改太多文档 → 评审成本高 | 本轮只动「实测不一致」与「缺失的叶子细节」；大改留给专门批次（见 §8 Q1） |
