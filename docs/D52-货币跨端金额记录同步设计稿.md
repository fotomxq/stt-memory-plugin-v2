## 0. 一页摘要

用户的现象只有一句：**货币在另一台设备上看到的金额与收支记录不对**（一边已经改了，另一边还是旧的，
甚至"改回来了"）。这不是"货币没被合并"——v3.45.6 起货币已按「归属 + 币种」逐条并集（`docs/history/P10c86`）。
真正的问题是**合并发生在错误的时点、读到错误的副本、并且用错误的时钟仲裁**：

| # | 缺陷 | 位置 | 后果 |
| --- | --- | --- | --- |
| ① | **保存先写后拉** | `adapters/store.js#saveStateNowInner`（每次保存**先**整份写回服务端）→ `adapters/sync.js#scheduleStorageSync`（3 秒后才拉取合并） | 等它去拉时远端已被本端刚写的**旧内存**覆盖 → 另一端刚记的**货币额度/流水**在服务端消失；两端从此各说各话 |
| ② | **会话内读缓存无 TTL** | `adapters/sync.js#filesReadContentCached`（同名远端文件整个会话只读一次） | 自动路径又不绕开缓存（只有手动「刷新状态 / 立即同步」与首屏载入会 `fileCacheDropAll`）→ 即使拉了也读到本会话早先那份 |
| ③ | **货币没有条目级时间戳** | `core/model/money.js#normalizeCurrency`（从不写 `updatedAt`）· `core/ingest.js#mergeDelta` · `core/entries.js#upsertEntry` · `core/currency-repair.js#runCurrencyRepair` | 冲突仲裁的顺序是「条目 `updatedAt` → 信封时间」，缺前者就永远退化为「**谁后保存谁赢**」→ 只是保存了别的内容的一端，会把另一端较新的额度盖回去 |

另有两条「同源现象」在③之下被放大：
* `core/cross-sync.js#mergeCurrencyEntry` 合并流水时把**本端固定放前面**，而 `mergeMoneyHistory` 只保留最近 12 笔 →
  两端各 12 笔时被裁掉的是「本端较新的那几笔」（用户看到的"记录少了"）；
* 设置里 `storage.crossPullOnVisible` / `storage.crossPullOnActivity` 两个开关**从未被读取**（死键）——
  用户以为"回到页面就会自动对账"，实际不会。

## 1. 目标 / 非目标

### 1.1 目标

1. **不再用旧内存覆盖对端**：主文件是提交点，写它**之前**先做一次「读远端 → **把货币逐条并集**」（`pullRemoteBeforeWrite`）；
2. **自动路径能读到真值**：写前拉取与回到前台拉取都**先绕开会话读缓存**，再用清单(meta)预判远端是否变化（未变不下载大文件）；
3. **回到前台自动对账**：页面从隐藏变可见时拉一次并**只并集货币**（`storage.crossPullOnVisible`，默认开）；有变化才落盘、才重绘面板；
4. **货币有账本时间戳**：AI 落库 / 面板编辑 / 快速记账 / 修正与融合四条写入路径都写条目级 `updatedAt`；
   合并仲裁按「账本何时被改」取新，而不是「哪个设备后保存」；
5. **记录按较新账本保留**：同一条货币的流水并集后，12 笔上限保留**胜出方（较新账本）**的最近记录；
6. 保持既有安全口径：清空 / 导入 / 退出前落盘**不写前拉取**（否则清不掉、导不进、退出被网络拖住）。

### 1.2 非目标（明确不做）

* **N1 不改「非原子容器整侧取新」的裁决**（`summaries` / `npcs` / `protagonist` / `vars` / `varTemplates` / `state`，`docs/D20` `数-4` 方案 A 保持）；
* **N2 不改 `dataAggHash` / `atomEntryCount` / `diffAtomData`** 三个 V1 锁定口径（货币仍不在 `ATOM_DIM_KEYS`）；
* **N3 不改 `DATA_VERSION`**：`updatedAt` 是**可选**字段（缺省不写），老存档与 V1 黄金样本逐字可读；
* **N4 不引入"实时双向推送"**：不新增长连接、不做多端在线互斥；
* **N5 不改货币融合 / 拆分口径**（`应-30` / `应-32` 另案）；
* **N6 不把"整份合并"提前到写前**：自动对账**只并集货币**，其余维度仍走「保存后镜像 / 载入并集 / 手动同步」——除货币外的条目合并时钟只有 AI 写入路径在维护，整份提前会让**手动编辑**被对端旧副本盖回去（属独立议题，见 §6 Q7）。

## 3. 方案

### 3.1 ① 写前拉取（`adapters/sync.js#pullRemoteBeforeWrite`）

保存流水线在**组装信封之前**调用一次：

```text
if (不是 skipFile 保存 && pullRemote !== false) {
    await pullRemoteBeforeWrite(reason)      // 失败一律静默，保存照旧
}
```

内部顺序（全部只读 + 内存合并，不写任何文件）：

1. 开关 `storage.crossPullOnActivity`（默认开）关闭 → 跳过；载入未完成 / 长任务在途 → 跳过；
2. **绕开会话读缓存**（主文件 / 备份 / 清单三个名字）→ 读清单；
3. 清单哈希 == 本端上次已合入的远端哈希 → **不下载主文件**（流量保护口径不变）；
4. 读远端最新信封 → `mergeRemoteCurrencies`（**只并集货币**；同口径：归属+币种一条 / 账本时间取新 / 流水并集 / 双墓碑）→ 本次保存把它一起写下去；
5. 15 秒内不重复探测（同一波连续保存不反复打网络）。

### 3.2 ② 回到前台自动对账（`host/events.js#bindAutoPullVisible`）

`visibilitychange → visible`（开关 `storage.crossPullOnVisible`，默认开）→ `crossAutoPull('visible')`：
同一个「缓存绕过 + 清单预判 + **只并集货币**」实现；**有变化才 `saveState()`**，并通过注入的 `onMerged` 回调
让界面层重绘已打开的面板（宿主层不依赖 `ui/`）。15 秒内不重复拉取。

### 3.3 ③ 账本时间戳（货币条目 `updatedAt`）

| 写入路径 | 打标 |
| --- | --- |
| AI 落库（新增 / 更新） | `core/ingest.js#mergeDelta` 货币段 `n.updatedAt = Date.now()` |
| 面板编辑 / 快速记账 | `core/entries.js#upsertEntry`（`kind === 'currencies'`） |
| 机械修正 / AI 融合应用 | `core/currency-repair.js#runCurrencyRepair`（受影响条目与合并保留条目） |
| 归一 | `core/model/money.js#normalizeCurrency` **只保留**入参带来的值；没有就不写该键（V1 黄金逐字不变） |

合并仲裁因此变成「**账本何时被改**」优先、「信封时间」只在双方都没有时间戳（老存档）时兜底。

### 3.4 ④ 记录取较新账本（`core/cross-sync.js#mergeCurrencyEntry`）

流水并集改为 `mergeMoneyHistory(落败方, 胜出方)` → 12 笔上限保留**胜出方（较新账本）**的最近记录；
两端都没收支时仍逐字段取自胜出方（`cross-sync-golden` 同形口径不变）。

### 3.5 落点与体量

| 文件 | 改动 |
| --- | --- |
| `adapters/sync.js` | 新增 `crossAutoPull` / `pullRemoteBeforeWrite` / `autoPullInfo` / `autoPullSwitchOn` + 缓存绕过 + 节流单飞；`resetSyncState` 复位；`storageStatusInfo` 加只读 `autoPull` 读数 |
| `adapters/store.js` | 保存流水线**写前**调用 `pullRemoteBeforeWrite`（4 行以内；`skipFile` / `pullRemote:false` 跳过） |
| `host/events.js` | `bindAutoPullVisible` / `unbindAutoPullVisible` / `autoPullBindState`（页面可见性绑定 + `onMerged` 注入） |
| `index.js` | 接线：init 绑定（一行）、teardown 解绑、清空 / 导入 / 退出前落盘加 `pullRemote:false`（均在既有行内） |
| `core/model/money.js` · `core/ingest.js` · `core/entries.js` · `core/currency-repair.js` | 条目级 `updatedAt`（保留 + 四条写入路径打标） |
| `core/cross-sync.js` | 流水并集「落败方在前、胜出方在后」 |
| 测试 | 新增 `tests/unit/currency-cross-ledger.test.js`（16 项）；`ingest-golden` M2 显式归一 + 新增 M2c 正面断言；`storage-loss-3402` GZ-1 与 `exit-flush` E0 的口径同步 |

### 3.6 回退

关 `storage.crossPullOnActivity` / `storage.crossPullOnVisible` 即回到「只有手动同步才拉」；
去掉保存流水线的写前调用即回到 v3.50.31 时序；条目 `updatedAt` 是可选字段，删掉打标即回到「按信封时间仲裁」。
三处互不依赖，可分别回退。

## 4. 风险与对策

| # | 风险 | 对策 |
| --- | --- | --- |
| R1 | 写前拉取把网络带进保存路径，网络挂住会拖慢落盘 | 只做「清单预判 + 一次货币并集」，**失败一律静默**；载入未完成 / 长任务在途跳过；15 秒节流；退出前落盘与清空 / 导入显式跳过 |
| R2 | 每次保存多一轮清单请求（流量） | 清单命中即不下载主文件（既有口径）；同一波连续保存 15 秒内只探一次；`syncOnSave=false` 时整体不动作（沿用镜像开关） |
| R3 | 自动拉取误伤其它维度 | **只并集货币**（其余维度时序不变）；「非原子容器整侧取新」的既有裁决也不动（`数-4` 方案 A） |
| R4 | 清空记忆后对端旧数据被并回来 | 清空（`resetState`）/ 导入（V1 / JSON）/ 退出前落盘三处保存**显式 `pullRemote:false`**，单测 D2 锁死 |
| R5 | 条目时间戳让老条目与新条目仲裁口径不同 | 只写不猜：老条目没有 `updatedAt` 时与 v3.50.31 行为一致（退回信封时间）；下一次真实写入即打标 |
| R6 | V1 黄金样本被改 | `v1-golden-ingest.json` **一字未改**；`normalizeCurrency` 缺省不写该键；`ingest-golden` M2 显式归一 + M2c 正面断言（按 `开发守则.md` §2.4 类别②登记） |
| R7 | 体量棘轮（`index.js` / `adapters/store.js` 已贴上限） | 新逻辑全部落 `adapters/sync.js` / `host/events.js`；`index.js` 与 `store.js` 只留**必要接线**，两文件均未超过「基线 + 40 行」 |

## 6. 决策记录（2026-10-24）

| # | 问题 | 结论 |
| --- | --- | --- |
| Q1 | 根因是"货币没被合并"吗？ | **不是**：v3.45.6 起货币已逐条并集。根因是**合并时点 / 读到的副本 / 仲裁时钟**三处（见 §0） |
| Q2 | 写前拉取放哪一层？ | `adapters/sync.js`（同步能力），保存流水线只留一行调用；`index.js` / `store.js` 不涨体量 |
| Q3 | 自动拉取要不要整体替换？ | **不要**：只做货币逐条并集（并集 + 双墓碑），把"谁覆盖谁"留给既有合并口径 |
| Q4 | 三个开关的语义？ | `crossPullOnActivity` = 写前拉取（聊天活动引发的保存先拉）；`crossPullOnVisible` = 回到前台拉取；两者默认开、都可关 |
| Q5 | 清空 / 导入要不要也先拉？ | **不要**：它们是"用户显式替换"，先拉会让对端旧数据被并回来（清不掉 / 导不进） |
| Q6 | 12 笔上限保留谁的记录？ | **较新账本（胜出方）**的最近 12 笔——两端各满 12 笔时不再把较新的记录裁掉 |
| Q7 | 自动对账为何只并集货币？ | 其它维度的条目合并时钟只有 AI 写入路径在维护（手动编辑不涨 `updatedAt`）；把整份合并提前到写前会让手动编辑被对端旧副本盖回去 —— 本轮只解决用户报告的货币，其余维度维持原时序（独立议题） |
