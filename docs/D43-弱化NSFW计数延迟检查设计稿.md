## 0. 一页摘要

**现象核对（先分清「事实」与「用户推断」）**：总览那个「🌶 弱化NSFW（N）」的 N **不是定时器**算的 ——
它来自 `core/nsfw.js#nsfwSoftenState()` → `nsfwScan()`，而 `nsfwSoftenState()` 被写在**总览每次渲染**里（`ui/panel.js#overviewBody`）。
也就是说：**没有轮询定时器，但比轮询更糟** —— 面板每点一下都重绘一次，重绘就全库扫一遍。

**实测代价（本机 4000 条目：3000 记忆 + 1000 情节，文本贴近真实长度）**：

| 调用 | 单次耗时 | 改造前的调用频率 |
| --- | --- | --- |
| `nsfwSoftenState()`（内含 `nsfwScan()` 全库全字段扫描） | **≈ 243 ms** | **每次总览渲染**（点一下按钮、切一次页、每个动作完成后…） |
| `nsfwLabelStats()`（留档等级分布） | 0.3 ms | 同上（可忽略） |

→ 用户在总览连点几下，就是**上千毫秒**白烧在主线程上；而这个数字**不会因为「看它一眼」而变化**。

**主张**：把「每次渲染都算」改成「**事件触发 + 延迟 10 秒 + 窗口内合并**」，并且**只在用户看得见时才真的算**。

## 1. 目标 / 非目标

### 1.1 目标

1. **管道完成**（`core/pipeline.js#endPipeline`）→ 向界面层**广播一次「某事完成了」**（带标签）；
2. **排除 `弱化NSFW` 自身**：那一条管道完成**不发**延迟检查信号（用户明确要求）；
3. **延迟 10 秒**才真正检查一次；**延迟窗口内多余信号一律忽略**（合并不重排）→ 避免频繁更新；
4. **渲染层不再全库扫描**：改为读缓存；缓存缺失 / 过期（> 10s）时才就地算一次；
5. **看不见就不算**：面板关闭 / 不在总览页 → 执行时跳过扫描；
6. **就地更新 DOM**：命中时只重写那一个按钮的文案与 title，**不整页重绘**（不打断输入与滚动）。

### 1.2 非目标（明确不做）

* **N1 不改 `nsfwScan()` 的判定口径**（关键词、规则、字段范围、上限一律不动）——本轮只改**何时**算；
* **N2 不改按钮的动作语义**（`nsfwSoften` 做什么、确认与回报一字不动）；
* **N3 不引入轮询定时器**（用户要的正是**摆脱**被动刷新；新机制只在信号到来时排一次延迟）；
* **N4 不适配到其它计数**（如 `nsfwLabelStats` 已经在同一份缓存里顺带受益，但本轮不推广到别处）。

## 3. 方案

### 3.1 内核侧：只广播「一件事完成了」

`core/pipeline.js` 的 `hooks` 增加 **`onRunEnd(info)`**（默认 no-op —— 内核保持零宿主依赖），
在 `endPipeline` 的真实收尾处调用（合流引用计数未归零时**不算完成**，因此不广播）：

```js
try { hooks.onRunEnd({ label: String(r.label || ''), ms, ok: ok !== false, at: Date.now() }); } catch (e) { /* 忽略 */ }
```

**分层**：内核只如实说「标签 / 耗时 / 成功与否 / 时刻」；**要不要扫库、延迟多久、合并多少信号**完全由界面层决定。

### 3.2 界面侧：延迟检查器（新模块 `ui/nsfw-count-tick.js`）

| 状态 | 含义 |
| --- | --- |
| `timer` / `pending` | 已排一次延迟检查（窗口内**只排一次**） |
| `cache = {candidates, labels, at}` | 最近一次算得的读数（渲染层读它） |
| `stats` | `signals` / `dropped`（合并掉的） / `excluded`（弱化NSFW） / `skipped`（看不见） / `runs` / `inline` |

| API | 作用 |
| --- | --- |
| `signalNsfwCountRefresh(label)` | 管道完成信号：`弱化NSFW` → `excluded`（不排）；窗口内 → `coalesced`（**不重排**）；否则排一次 10s 检查 |
| `nsfwCountSnapshot()` | 渲染层取值：有缓存用缓存；缺失 / 过期就**就地算一次**（并续上窗口） |
| `refreshNsfwCount(opts)` | 唯一扫描入口（算一次 + 写缓存 + 就地更新 DOM） |
| `invalidateNsfwCount()` | 作废缓存（弱化动作结束时调用 → 紧接着那次重绘**就地算一次**） |
| `updateNsfwCountDom()` | 就地更新 `#ftt-nsfw-btn` 文案与 title（文本未变不写 DOM） |
| `nsfwCountVisible()` | 面板是否看得见那个按钮（看不见就不扫） |

### 3.3 时序（用户口径的逐条落实）

```text
管道完成(提取记忆) ──signal──► 排一次 10s 检查 ──┐
管道完成(自动修复) ──signal──► 忽略(dropped)      │  ← 窗口内多余信号一律忽略，且**不重排**
管道完成(推演)     ──signal──► 忽略(dropped)      │
管道完成(弱化NSFW) ──signal──► 排除(excluded)     │  ← 连排都不排
                                    … 10s 到 ────┘
                                     ├─ 看得见 → 扫一次 + 就地更新按钮
                                     └─ 看不见 → 跳过（skipped），算力留给用户在看时
```

### 3.4 弱化动作自己的即时性（为什么不算「违反排除」）

「排除 `弱化NSFW`」= 不让**它**去排那个延迟检查（用户口径）。
但弱化跑完，用户**就在看着那个数字**，给旧的数会显得「点了没反应」——
故该动作在结束时调 `invalidateNsfwCount()` **作废缓存**：紧接着的那次重绘**就地算一次**（**只算这一次**），
点完立刻看到新数。两条口径不冲突：**一个管「谁触发延迟检查」，一个管「用户主动动作后立刻给对的数」**。

### 3.5 落点与体量

| 文件 | 改动 |
| --- | --- |
| `ui/nsfw-count-tick.js`（新） | 全部机制（缓存 / 延迟 / 合并 / 排除 / 可见性 / 就地更新） |
| `ui/panel.js` | 3 行：import、总览两处读数改读缓存、弱化动作后作废缓存（并移除两个已收口的全库扫描调用） |
| `core/pipeline.js` | 2 行：`onRunEnd` 钩子 + 收尾处广播 |
| `index.js` | 2 行：把 `onRunEnd` 接到界面层信号函数 |
| 测试 | 新增 `tests/unit/nsfw-count-tick.test.js`（18 项，含 4 条反向探针）+ 冒烟 `CN1`（真实 `beginPipeline/endPipeline` 走一遍） |

### 3.6 回退

把总览两处读数改回直接调用 `nsfwSoftenState()` / `nsfwLabelStats()` 即可回到 v3.48.x 行为
（新模块留着不接线也不生效）。

## 4. 风险与对策

| # | 风险 | 对策 |
| --- | --- | --- |
| R1 | 数字变「旧」（最多滞后一个 10s 窗口） | 这正是用户要的延迟口径；**用户主动动作**（弱化）后作废缓存立刻给新数；渲染层过期即**就地算一次**，不会长期陈旧 |
| R2 | 窗口内信号不重排 → 检查时间点「偏早」而非「偏晚」 | 刻意如此（用户要「避免频繁更新」）；不重排可保证「第一信号 + 10s」稳定可预期 |
| R3 | 忙时每 10s 扫一次仍有成本 | 只在**看得见**时扫；看不见直接跳过；一次扫描 243ms 是既有口径成本（本轮不改判定范围，另立条目可优化扫描本身） |
| R4 | 内核被界面污染 | 内核只加一个默认 no-op 钩子（`onRunEnd`），报文里不带任何 UI 概念 |
| R5 | 桩环境无 `setTimeout` / DOM | 全部 try/catch；无定时器时降级为「渲染时就地算一次」（等于旧行为，不报错） |

## 6. 决策记录（2026-10-14 · 用户当轮要求，逐条按原话落实）

| # | 问题 | 结论 |
| --- | --- | --- |
| Q1 | 触发源是什么？ | **管道完成**（`endPipeline` 广播）—— 不再由「渲染」或任何轮询驱动 |
| Q2 | 延迟多久？ | **10 秒**（`NSFW_COUNT_DELAY_MS = 10000`，用户指定，写死为常量并在单测里锁死） |
| Q3 | 窗口内多余信号怎么办？ | **忽略（合并不重排）**，并计入 `dropped` —— 用户原话「自动忽略多余信号，以避免频繁更新」 |
| Q4 | 弱化NSFW 自己算不算触发源？ | **不算**（`excluded`）；但该动作结束后**作废缓存**保证用户看到新数（见 §3.4） |
| Q5 | 看不见时算不算？ | **不算**（`skipped`）—— 算力留给用户真的在看的时候 |
| Q6 | 要不要顺手优化 `nsfwScan()` 本身？ | **本轮不做**（超范围）：先把「何时算」改对；扫描本身的优化另立条目 |
