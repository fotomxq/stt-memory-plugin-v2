## 1. 环境与命令

无需安装依赖（源码即发布物）。仅需 Node（用于跑门禁与测试）与 git。

```bash
npm run gate    # 全部门禁（发布前必跑）
npm test        # 单元测试（tests/unit/run.js）
npm run smoke   # 冒烟测试（真实宿主桩全链路）
node scripts/check-docs.js          # 文档规范
node scripts/check-version-sync.js  # 版本一致性（--strict：HEAD 必须落在同名 tag 上）
node scripts/gen-changelog-json.js  # 由 CHANGELOG.md 重新生成版本清单 JSON
```

## 3. 测试体系

| 层级 | 命令 | 规模 | 特点 |
| --- | --- | --- | --- |
| 单元 | `npm test` | 102 文件 / 1565 断言 | 无宿主也可跑；`tests/harness/st-mock.js` 提供 DOM / 宿主桩 |
| 冒烟 | `npm run smoke` | 167 项 | 全链路（装配 → 注入 → 提取 → 修复 → 导出/导入 → teardown） |
| 黄金样本 | 随单元跑 | 54 份 | oracle = **真实 V1 v1.206** 直跑产出；逐字节/逐项比对 |
| 归档级 | 手工 | — | `git archive` 导出 tag → **改名目录**复跑全门禁（证明自足性） |

**黄金样本规则**：

- `tests/fixtures/v1-golden*.json` 是 **oracle，禁止手改**；
- 生成器在 `tests/fixtures/gen-*.cjs`（可复现）；
- 确需偏离 V1：在**测试里显式归一**（如 `list-rows-golden` 对 state 行去冒号的归一），并在文档登记「有意偏离」。

**异步断言防呆**：断言里的 Promise 必须 `await`（`tests/harness/st-mock.js` 有防呆；写成 `assert(name, Promise)` 会假绿）。

## 4. 发布流程

见 `开发守则.md` §3（版本号规则 · 发布前四步 · 推送策略 · CHANGELOG 与文档同步）。要点：

1. `npm run gate` 全绿；
2. `node scripts/gen-changelog-json.js`（CHANGELOG 是唯一事实源）；
3. `git archive` 到**改名**的干净目录复跑门禁；
4. 提交 → 推送 `main` → **新版本必须推送同名 tag**。

CHANGELOG 条目格式（沿用既有风格）：`## vX.Y.Z（日期）· 标题` → `**用户要求**：原话` → `**① …**：改动与理由` → `**门禁**：测试与回归`。

## 5. 编码约定

| # | 约定 | 理由 |
| --- | --- | --- |
| C1 | `core/` 只写纯函数与数据；不 import 上层、不碰 DOM / `window` / `setInterval` | 跨端共用 + 黄金样本可复现（门禁强制） |
| C2 | 归一化必须**幂等**：同一输入重复归一结果不变 | 跨端各自归一时才能收敛 |
| C3 | 一切「可能抛错」的归一入口用 try/catch 兜底并返回 `null`/默认值，**但不得吞掉数据丢失**（门禁查未定义标识符就是为此） | 防静默丢数据 |
| C4 | 新增引用类字段：显式决策**是否进内容哈希**（现状是「不进」） | 影响快照与跨端是否触发更新 |
| C5 | 删除一律走**双墓碑**（id + 内容哈希） | 跨端不复活 |
| C6 | 参照 V1 的行为要在注释里写清「V1 出处（函数 + 行号）」；偏离 V1 要写「有意偏离 + 原因 + 登记文档」 | 保真度可审计 |
| C7 | 用户可见文案与 V1 **逐字一致**，除非用户明确要求改；改文案要同步测试断言 | 界面口径稳定 |
| C8 | 面板动作/控件要能被 `panel-audit` 审计到（动作有处理分支、属性型控件有前置分支） | 防「点了没反应」 |
| C9 | 新增文档必须有头部元信息（文档版本 / 日期 / 类型 / 状态） | 文档门禁强制 |
| C10 | 提交信息格式：`vX.Y.Z: 标题（要点）` —— 与 `CHANGELOG.md` 条目标题同源 | 版本史可追溯 |

## 7. 排查入口

| 现象 | 先看 |
| --- | --- |
| 面板不显示 | `docs/排障-面板不显示.md` → `/ftt-panel` → `/ftt` 的入口诊断 → 悬浮兜底 |
| 注入不对 / 少了条目 | 设定 → 约束「🧷 约束自查」（本轮注入了什么、为什么别的没进去）；总览「查看注入内容」 |
| 提取没生效 | `/ftt` 的能力探测与拦截器统计 → 设定 → 调试「调试日志」→ 总览「管线状态」 |
| 某个按钮点了没反应 | 设定 → 调试「🧭 交互与宿主调用时间线」（点击 → 动作 → 宿主调用 → 结果 → 代码位置） |
| 时钟不对 | 设定 → 调试「🕒 时钟取值追踪」；口径见 `docs/history/P10c`/`P10e`/`P10o` |
| 更新检查失败 | `docs/更新检查机制.md`（失败一律静默，不影响主流程） |
| 同步不一致 | 设定 → 存储「同步日志」；机制见 `02-数据架构` §6 |

控制台调试入口（只读）：`FTT.snapshot()` / `FTT.probe()` / `FTT.interceptor()` / `FTT.injectLength()` / `FTT.traceTimeline()` / `FTT.debugLogExport()`。

## 8. 需要知道的三个「坑」

1. **`currencies` 不在原子层**（唯一例外）：不参与逐条合并，跨端是**整侧取较新**。
2. **引用字段不进哈希**：改了引用不会触发快照/同步判定为「更新」，需要显式考虑。
3. **`cfg` 与适配层设置分离**：更新检查、面板宽度等存 `extensionSettings`，写到 `cfg` 里会「改了不生效」。
