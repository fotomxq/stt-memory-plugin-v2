# D47 · 日期字段保存不被截断（负年份 / 大年份）

> 文档版本：v1.0 ｜ 日期：2026-10-19 ｜ 类型：**设计稿（不发版）** ｜ 状态：生效（已按本稿落地 v3.50.27）｜ **维度归属：数据（优先级 1）**
> 触发（用户原话）：「经过测试还是有问题，出生年月无法保存'-9999-01-01'，以此类推，负数年份超出999及'-999'
>   就会将日期挤出，造成保存后被截断。请修复该错误。」
> 前置：`docs/D46`（v3.50.26 大年份出生日期与年龄 —— 本轮修的是它的**保存链路**）· `docs/D22` §4.27（**W27 `数-39`**）· `docs/D17`（**U256**）
> 事实基准：程序 **v3.50.27**（`core/constants.js#VERSION`）。本稿按**设计轮次**格式成稿并同轮落地。
> 关联：实施规格 **1 条**（`数-39`）· 批次档 `docs/history/P10c136-日期字段保存截断修复.md`

## 0. 一页摘要（用户的判断完全正确）

v3.50.26 放开了**解析**（年份不再卡 4 位），但**保存链路**还留着一层 `normText(x, 10)` ——
那个 `10` 是按 `YYYY-MM-DD`（10 字符）写的。于是：

| 输入 | 字符数 | `normText(x, 10)` 后 | 结果 |
| --- | --- | --- | --- |
| `1919-11-29` | 10 | `1919-11-29` | 正常 |
| `-999-01-01` | 10 | `-999-01-01` | 正常（所以用户说「999 及以内没事」） |
| **`-9999-01-01`** | **11** | **`-9999-01-0`** | **截断 → 解析失败 → 「存不进去」** |
| `3000000-05-01` | 13 | `3000000-05` | 截断 |

**主张**：把日期字段的长度上限从「按 `YYYY-MM-DD` 写死的 10」改为**统一常量** `BIG_DATE_FIELD_MAX = 32`，
并把所有「按 10 字符硬切」的取日期写法换成 `bigDatePrefix`（只剥离时间后缀、不再切坏年份）。

---

## 1. 目标 / 非目标

### 1.1 目标

1. **保存往返**：`-9999-01-01` / `-12000-01-01` / `-9999999999-01-01` / `3000000-05-01` 经归一化与落库后**逐字不变**；
2. **覆盖全部容器**：角色档案（出生日期 / 最后见面 / 最后更新）· 情节 / 记忆 / 物品 / 计划 / 悬念 / 传言 / 概念 / 平行事件 / 货币的日期字段；
3. **取日期部分**：`slice(0, 10)` 一类写法不再切坏负年份（改用 `bigDatePrefix`）；
4. **单点定义**：长度上限只在新模块 `core/model/bigdate.js` 定义一次（`BIG_DATE_FIELD_MAX`）。

### 1.2 非目标（明确不做）

* **N1 不改任何字段的语义**：日期字段仍是「原文日期字符串」，本轮只**不切**它；
* **N2 不做日期规范化**：不补零、不换分隔符、不改精度（`628-04-28` 仍写作 `628-04-28`，不变成 `0628-04-28`）——
  这一条在实现中曾踩到（`bigDatePrefix` 初版做了规范化 → 把 `628-04-28` 改成 `0628-04-28`，被 `clock-latest-plot` 当场抓住，已改回「原文保留」）；
* **N3 不放宽其它文本上限**：只动**日期语义**的字段（标题 / 正文 / 备注等上限不变）；
* **N4 不改 `DATA_VERSION`**：不涉契约，无迁移。

## 3. 方案

### 3.1 单点常量 + 取日期部分

| 件 | 位置 | 作用 |
| --- | --- | --- |
| `BIG_DATE_FIELD_MAX = 32` | `core/model/bigdate.js` | 日期字段存储上限（覆盖 `-9999999999-01-01`(17) 与带时刻最长形态(26)） |
| `bigDatePrefix(v)` | 同上 | 取日期部分：**原文保留**（不补零 / 不换分隔符），仅剥离时间后缀；不可解析 → 原串 |

### 3.2 替换清单（本次共 21 处）

| 类别 | 文件 | 处数 |
| --- | --- | --- |
| `normText(x, 10)` → `normText(x, BIG_DATE_FIELD_MAX)` | `snapshot.js`(3) · `dims.js`(8) · `money.js`(4) · `atom.js`(1) · `parallel.js`(1) · `field-names.js`(1) | 18 |
| `slice(0, 10)` 取日期 → `bigDatePrefix` | `recall.js`(4) · `clock.js`(1) · `clock-extract.js`(2) · `rel-maint.js`(1) | 8（其中 `recall.js` 一处合并） |

> 数量说明：§2 K1 记 17 处 `normText`（含 1 处 `field-names.js`）；替换后实测共 18 处写入点（`dims.js` 的多字段被逐一覆盖）。

### 3.3 V1 偏离登记（`开发守则.md` §2.4 三件套，黄金样本**一字未改**）

| 偏离 | V1（= 有 bug） | 本轮 | 归一 + 单独断言 |
| --- | --- | --- | --- |
| 公元前出生日期 | 被截成 `-0221-01-0` → `bad-format`、算不出年龄 | 完整保留 → 合法、年龄 **2140**（历史纪年） | `model-golden2#N2`/`N4` 显式归一（第 4 条）+ 新增 **N2b** / **N4b** |

### 3.4 落点与体量

| 文件 | 改动 |
| --- | --- |
| `core/model/bigdate.js` | 新增 `BIG_DATE_FIELD_MAX` + `bigDatePrefix` |
| `core/model/snapshot.js` · `dims.js` · `atom.js` · `money.js` · `parallel.js` · `field-names.js` | 日期上限改用常量（仅 18 处字面量） |
| `core/recall.js` · `clock.js` · `clock-extract.js` · `rel-maint.js` | 取日期部分改用 `bigDatePrefix` |
| 测试 | 新增 `tests/unit/big-date-save.test.js`（13 项）；`model-golden2` 两处偏离归一 |

### 3.5 回退

把 `BIG_DATE_FIELD_MAX` 换回字面量 `10`、`bigDatePrefix` 换回 `slice(0, 10)` 即回到 v3.50.26 行为（会重新截断负年份）。
