## 0. 一页摘要

**现象（改造前）**：每个维度列表页的行右侧按钮（✏️ 编辑 / 🗑 删除 / 🔍 速览 / 🚀 推进 / ⬆ 转正…）**始终平铺在行内**。
窄屏下靠 `flex-wrap` 折行 → **行高翻倍**、正文可用宽度被按钮吃掉；按钮越多越严重（平行页早在 v2.71.0 就因此改成竖排，
其余维度未处理）。而按钮是**低频动作**：列表浏览（读标题 / 正文 / 日期 / 楼层）是高频动作。

**主张**：把按钮改成**按需出现** —— 触屏**左滑**、PC**鼠标悬停**、键盘**聚焦**，三条入口展开**同一组按钮**；
展开时行内容左移**恰好等于按钮组实测宽度**；按钮太多则**折行成网格**而不是吃掉整行。

| 决策点 | 结论 | 理由 |
| --- | --- | --- |
| 展开触发方式 | 触屏滑动 + PC 悬停 + 键盘聚焦，**三合一**（共用 `.ftt-open`） | 一份状态机三端一致；**刻意不做 `:hover` 的 CSS 旁路**，避免两套观感 |
| 滑动方向 | **左滑展开**（按钮在右），右滑收起 | 与移动端「右滑返回 / 左滑露出操作」的通行手势一致 |
| 是否自动收起 | **不自动**（无计时器） | 避免「手指还没点到按钮，它就自己收回去」 |
| 展开宽度 | **实测** `ops.scrollWidth` → `--ftt-swipe-w` | 按钮 3 个与 5 个、中文短标签与长标签的左移量本就不同，估算必然错位 |
| 过宽怎么办 | 宽 > 行宽 × 72% → `.ftt-swipe-wide` **折行网格**并夹宽 | 按钮再多也不吃掉整行（这是「布局适配」的核心） |
| 失败怎么办 | 拿不到 DOM / 量不到宽度 → 跳过动画与左移，**按钮照旧可点** | 宁可退化为「按钮常显」，绝不出现「按钮没了也点不了」 |

## 1. 目标 / 非目标

### 1.1 目标

1. 列表行右侧按钮**默认不占行宽**：触屏左滑 / PC 悬停 / 键盘聚焦才展开；
2. **布局适配**：左移量按按钮组实测宽度；按钮过多时折行网格；窄屏与桌面各有断点细则；
3. **互斥清晰**：同一时刻只展开一行；点行外空白收起；**点行内按钮不收起**；
4. **失败可见而不致命**：所有 DOM 操作容错，最差退化为「按钮常显」；
5. 把口径写进 `docs/D9`（**§3.2 + §3.2.1**），实现落新模块 `ui/swipe-rows.js`。

### 1.2 非目标（明确不做）

* **N1 不改任何动作语义**：动作名、二次确认、`disabled` 条件、`data-ftt-action` 一律不动；
* **N2 不改数据**：纯界面层，点击不写任何记忆数据（与 `应-21` 的「点击不写数据」同款纪律）；
* **N3 不做自动收起计时器**（理由见 §0 决策点）；
* **N4 不统一全部列表形态**：只改**维度列表行与状态列表行**（用户所指的条目操作列）；
  场景树、各类「选择器」面板（选角色 / 货币选角色 / 履历批量勾选）、同步日志等的行**本期不动**（形态不同，见 §5 R4）；
* **N5 不引入依赖 / 构建步骤**（仓库约束：源码即发布物）。

## 3. 方案

### 3.1 结构（标记层，单一事实源）

```html
<div class="ftt-item ftt-inline ftt-swipe" data-ftt-swipe="1" data-ftt-swipe-n="3" [行属性…]>
  <div class="ftt-swipe-body">…勾选框 + <span class="ftt-grow">行内容</span>…</div>
  <div class="ftt-swipe-ops ftt-item-ops[ ftt-ops-col]">…按钮组…</div>
</div>
```

* 由 `ui/swipe-rows.js#swipeRowHtml(bodyHtml, opsHtml, opts)` **统一产出**（调用方不再自己拼外壳）；
* `opts.attrs` 承载行级属性（如「🆕 本次新增」的定位锚点）；`opts.opsCol` 供平行页竖排；
  `opts.count` 写 `data-ftt-swipe-n`（只读读数）；
* `data-ftt-swipe` 的**读者**是字面选择器 `SWIPE_ROW_SELECTOR = '.ftt-swipe[data-ftt-swipe]'`（K8 要求可查）。

### 3.2 行为（一份状态机）

| 入口 | 事件 | 行为 |
| --- | --- | --- |
| 触屏 | `touchstart` / `touchmove` / `touchend` / `touchcancel` | 横向意图判定（> `SWIPE_INTENT_PX`=10px 且横 > 纵）→ 位移 ≤ `SWIPE_OPEN_THRESHOLD`(-26px) 展开；≥ `SWIPE_CLOSE_THRESHOLD`(+22px) 收起；拖动期间 `.ftt-drag`（关过渡） |
| PC | `mouseenter` / `mouseleave` | 悬停展开、移开收起（`hasFocusInside` 为真则不收） |
| 键盘 | `focusin` / `focusout` | 聚焦展开；`focusout` 延后一拍再判 `hasFocusInside`，避免 Tab 在行内移动时闪收 |
| 全局 | 根上 `click`（**只挂一次**） | 点击位置不在任一展开行内 → 收起全部；点在行内按钮上 → **不收起** |

### 3.3 布局适配（三层）

| 层 | 规则 |
| --- | --- |
| 左移量 | `--ftt-swipe-w` = `ops.scrollWidth`（实测）；`.ftt-swipe.ftt-open > .ftt-swipe-body { transform: translateX(calc(-1 * var(--ftt-swipe-w, 0px))) }` |
| 过宽折行 | 宽 > 行宽 × `SWIPE_MAX_RATIO`(0.72) → `.ftt-swipe-wide`：`flex-wrap: wrap` + `max-width: 72%`，`--ftt-swipe-w` 夹到 72% 上限 |
| 断点 | ≤760px：行内容可折行、折行网格上限放宽到 78%；`prefers-reduced-motion: reduce`：无过渡 |

### 3.4 落点与体量

| 文件 | 改动 |
| --- | --- |
| `ui/swipe-rows.js`（新） | 标记（`swipeRowHtml`）· 状态机（`openSwipeRow` / `closeSwipeRow` / `closeAllSwipeRows`）· 实测（`measureSwipeRow`）· 绑定（`bindSwipeRow` / `applySwipeRows`）· 常量与选择器 |
| `ui/panel.js` | **三处接线**：两处渲染助手（`dimBodyList` / `statesBody` 行）+ 渲染后一次绑定（`renderPanel#finish`，三条渲染路径共用） |
| `style.css` | `.ftt-swipe*` 规则（5 个新类名） |
| 测试 | 新增 `tests/unit/swipe-rows.test.js`；同步 `panel` / `parallels-layout` / `list-pager` 三处既有断言 |

### 3.5 回退

删掉绑定调用 + 把 `swipeRowHtml` 换回原来的行拼接即可回到 v3.47.x 行为（CSS 规则留着也不生效）。

## 4. 风险与对策

| # | 风险 | 对策 |
| --- | --- | --- |
| R1 | 悬停展开在**触屏**上误触发（某些设备会同时报 `mouseenter`） | 展开态唯一 + 只在 `mouseenter` 时展开；触屏设备的滑动仍走 touch 分支，二者不冲突（都只是打同一个类） |
| R2 | 滑动与**纵向滚动**打架 | 横向意图判定（横 > 纵且 > 10px）才进入手势；未成手势的 `touchmove` 立即退出，交给滚动 |
| R3 | 面板重绘后绑定丢失 / 重复绑定 | 绑定放在 `finish()`（三条渲染路径共用）；`WeakSet` + `__fttSwipe` 双保险幂等 |
| R4 | 其它列表形态（选择器 / 场景树）观感不统一 | 登记为**非目标 N4**（形态不同：那是勾选与挑选，不是条目操作列）；如需统一另立条目 |
| R5 | 体量棘轮被顶破 | 实现整体落新模块；面板只留 3 处接线（实测 +20 行，基线 +40 以内） |
| R6 | 键盘用户被「收起」打断 | `focusout` 前先问 `hasFocusInside(row)`；行内按钮获得焦点时绝不收 |
