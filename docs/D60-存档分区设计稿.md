## 1. 目标 / 非目标

### 1.1 目标

1. 同一角色的**不同聊天存档**互不混淆：换聊天 = 换视图（列表 / 计数 / 注入都只覆盖本档）；
2. 自动清理（上限裁剪 / 低使用遗忘）**绝不误删别档数据**；
3. 升级前的历史数据（无 `chatKey`）**保留可见并打标**，一键归入本档（幂等、需确认）。

### 1.2 非目标

- **N1** 不改物理存储骨架：仍是「每个角色一份」（`scope: char:xxxx`），**不改 `DATA_VERSION`**、不动服务端文件命名；
- **N2** 不按楼层范围 / AI 推断历史数据归属（`docs/D29` 既定纪律：猜错比不打标更危险）；
- **N3** 不删除任何其它存档的条目（只隐藏）；
- **N4** 不改 `chatKey` 内容哈希口径（不在 `HASH_FIELDS`，归档不引发跨端计条）。

## 3. 方案

### 3.1 分区模型（`数-51`）

* 分区键 = `entry.chatKey`（兼容短键 `ck`）；当前档 = `state.chatKey`；
* 档位：`current`（属于本档）/ `legacy`（无归属 = 升级前历史数据）/ `other`（别的存档）/ `all`（当前档未知时的 fail-open）；
* **可见** = `current` + `legacy`；`other` **隐藏**且不参与注入、不参与裁剪与遗忘。

### 3.2 业务口径（`业-17`）

* 本档视图 = 当前档 + 历史遗留（打「旧存档」标，显式而非静默）；
* 换聊天 → 视图自动切换（`state.chatKey` 变，无需重载）；
* 「把旧存档归入当前」= **只补空归属**（已有归属不动），幂等、二次确认；
* 自动清理只在本档范围内进行（`capVisibleKeepingOthers` / `forget` 分区守卫）。

### 3.3 界面（`应-56`）

* 面板外壳横幅 `data-ftt-archive-bar`：`📂 当前存档 <短键> ｜ 本档 N 条 ｜ 旧存档遗留 L 条（可见·打标） ｜ 其它存档 M 条（已隐藏…）` + `↪ 把旧存档归入当前`；
* 列表行：`legacy` 条目加 `旧存档` 徽标（`data-ftt-archive-legacy`）；
* 当前档未知 → 横幅不渲染（fail-open）。

## 5. 风险与边界（如实登记）

| # | 风险 | 处置 |
| --- | --- | --- |
| R1 | 物理仍是一份文件：导出/备份会含所有存档数据 | 明确登记；导入到别的存档时条目的 `chatKey` 使它们仍归原档（不串档） |
| R2 | 历史数据无归属 → 归入本档后就被"认领"了 | 归档**需二次确认**、可先导出备份；不自动执行 |
| R3 | 别的存档条目仍占物理空间（不自动清理） | 属"不删数据"纪律（`docs/D28`）；用户可切换存档后自行清理 |
| R4 | `chatKey` 读不到时不分档（fail-open） | 宁可显式回到旧行为，也不误藏数据 |
