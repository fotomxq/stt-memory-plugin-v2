## 4. 筛选条语义（V2 按 V1 口径实现）

- **字段范围**：`全部字段 / 标题 / 描述 / 标签 / 名称` → `fieldHayOf()` 与 V1 `fieldHay` 逐条等价；
- **检索**：`fieldHay.includes(q) || subject.includes(q)`（V1 语义：命中**角色名**也保留整组）；
- **额外条件**：`全部状态` / `仅已失效`（V1 `pageExtraOptions('states')`）；
- **排序**：`默认`（保持原序，V1 同）/ `最新在前` / `最早在前`（`sortRecentByStoryDate`，V1 `sortRecent` 同源）/
  `重要度`（`importancePct` 降序）/ `调用次数`（`uses` 降序）；
- **✕ 清除**：同时清空搜索词、多选与筛选态（V1 `searchClear` 同义）。

## 5. 与 V1 的既有/新增偏离（逐条登记）

1. **多选控件形态**：V1 在筛选条里用 `<select>单选模式/多选模式`，V2 全站统一用「☐/☑ 多选模式」按钮
   （v2.47 起既定形态）；本批保持 V2 形态，避免同一面板两套交互。
2. **状态删除墓碑维度键**：V1 写 `deleted.states`，而它的维度表只认 `currentStates`（V1 的墓碑自己读不到）；
   V2 统一写规范键 `currentStates` —— 既有偏离（docs/P8c-B2），本批未变。
3. **筛选条覆盖范围**：本批只为**状态页**补了筛选条（用户点名状态大类）；其它大类仍是 V2 的简化工具栏。

## 7. 未验证 / 风险

1. V1 的「原地显隐筛选」（`pageFilterRowsInPlace`，为中文输入法安全不重建 DOM）V2 未移植：V2 走重绘路径，
   功能等价但输入法体验未在真实浏览器验证。
2. 排序「重要度」用 V2 `importancePct`（与 V1 `importancePct` 同源）；若用户自定义 `importanceBase/PerUse`，
   排序结果随配置变化 —— 与 V1 一致。
3. 其它大类（情节/记忆/…）的筛选条仍缺，若需要可按本批同一套 `listFilter*` 助手逐页补齐。
