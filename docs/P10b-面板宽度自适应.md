# P10b · 面板宽度自适应（v2.36.0）

> 文档版本：v1.0 ｜ 日期：2026-09-26 ｜ 状态：生效（v2.36.0）
> 触发（用户原话）：「**宽度不足，插件自适应宽度。手机端可铺满、PC 可自适应，但需注意较宽。**」
> 涉及：`style.css` · `adapters/settings.js` · `ui/panel.js` · `tests/unit/panel-width.test.js` · `tests/harness/st-mock.js` · `tests/smoke-test.js`

---

## 1. 问题（与 V1 的关系）

面板宽度原本是**逐字照搬 V1** 的固定上限：

```css
/* 改前（= V1 v1.206:22389 逐字） */
#ftt-panel .ftt-modal { width: min(940px, 94vw); ... }
```

V1 是**酒馆助手 iframe 内**的浮层，940px 是为 iframe 场景选的保守值；V2 是**原生扩展**，浮层挂在
`document.body` 上、`position: fixed; inset: 0`（`ui/panel.js#ensureOverlay`），可用空间是**整个视口**。
于是在宽屏 PC 上 940px 只占约半数宽度 → 用户看到「宽度不足」。

**处置**：本项属 **V2 对 V1 的有意偏离**（同 §3 的其它 UI 偏离一样单独登记），不再逐字照搬固定像素。

## 2. 新口径：一档变量 + 三档媒体查询

```css
#ftt-panel { --ftt-panel-max-w: 1280px; }                    /* 上限（可配置，见 §3） */
#ftt-panel .ftt-modal { width: min(var(--ftt-panel-max-w), calc(100vw - 32px)); ... }

@media (min-width: 701px) and (max-width: 1024px) {          /* 平板 */
  #ftt-panel .ftt-modal { width: min(var(--ftt-panel-max-w), 96vw); ... }
}
@media (max-width: 700px) {                                  /* 手机：整屏铺满 */
  #ftt-panel .ftt-modal { width: 100vw; width: 100dvw; height: 100dvh; border-radius: 0; border: none; ... }
}
```

| 场景 | 宽度 | 说明 |
| --- | --- | --- |
| 手机（≤700px） | `100dvw × 100dvh` | **铺满**（`dvh` 动态视口，避开地址栏/键盘；去圆角/边框/阴影）—— 与用户要求与既有实现一致 |
| 平板（701~1024px） | `min(上限, 96vw)` | 既有的 96vw 档保留 |
| 桌面（≥1025px） | `min(上限, 100vw - 32px)` | **随窗口自适应**，两侧恒留 16px，到上限收住 |
| 超宽屏（例：2560px） | 上限值（默认 1280px） | 「**注意较宽**」：默认不收满，长行阅读与鼠标移动距离都更舒服；需要更宽由用户显式选择（§3） |

同一套变量在需要时也能整体调窄：默认档 1280px，比改前的 940px 宽 **+36%**；1024px 窗口下实际为 992px
（96.9% 屏宽），1366px 下为 1280px（93.7%）。

## 3. 可调上限：「V2 附加设定 → 面板最大宽度」

档位（**适配层设置** `extensionSettings[ftt_memory_v2].panelMaxWidth`，**不进内核 cfg** —— 与更新检查/入口开关同类）：

| 档位 | 值 | 说明 |
| --- | --- | --- |
| 960px（紧凑） | `960` | 接近 V1 原值，适合小屏笔记本 |
| 1120px | `1120` | |
| **1280px（默认 · 推荐）** | `1280` | 默认档；桌面自适应到 1280 收住 |
| 1440px（大屏） | `1440` | |
| 1600px（超宽） | `1600` | |
| 铺满（只留 32px 边距） | `0` | CSS 变量置 `100vw` → 实际 `100vw - 32px` |

- 归一（`adapters/settings.js#setSetting`）：有限数且 ≥0 → 取整并夹在 `[0, 4000]`；非法值回落默认 1280；
  `0` 是**合法档**（铺满），故用 `Number.isFinite` 判定而不是 `||`。
- 下发：`ui/panel.js#applyPanelWidth()` 把 `panelWidthCssValue(px)`（`'1280px'` / `'100vw'`）写入浮层的
  `style.setProperty('--ftt-panel-max-w', …)`；在**新建浮层**（`ensureOverlay`）与**每次重绘**（`renderPanel`）都下发，
  切换档位即时生效；无 `style` 的宿主（测试桩、受限环境）静默跳过且不抛错。
- 手机档**不受该设置影响**（媒体查询优先级更高，恒铺满）—— 与用户要求一致。

## 4. 「注意较宽」的落地（加宽后的溢出保护）

加宽后最容易出问题的是**长内容撑破容器**，故补了三条约束（不改列数，保持 V1 的单列口径）：

```css
#ftt-panel .ftt-body, #ftt-panel .ftt-section, #ftt-panel .ftt-settings-page { min-width: 0; max-width: 100%; }
#ftt-panel .ftt-dbg-data, #ftt-panel .ftt-wb-entries, #ftt-panel .ftt-editor, #ftt-panel .ftt-pre-box { max-width: 100%; overflow-x: auto; }
#ftt-panel .ftt-item-main { min-width: 0; }
```

另：抽屉卡片（v2.0 形态的 `#ftt_v2_settings` 内联卡片，宽度由酒馆抽屉决定）在 ≤700px 下
`flex-wrap: wrap` + 文本输入占满整行，避免撑破卡片。

> 说明：`.ftt-pop*`（`min-width: 78vw; max-width: 1100px`）是 v2.0 弹窗时代的**死 CSS**（全仓 JS 零引用），
> 本批**不动**它（既不影响渲染，也不值得为清理而扩大改动面）。
