## 1. 结论（两处真缺陷 + 一处契约遗漏）

| # | 缺陷 | 影响 | 引入批次 |
| --- | --- | --- | --- |
| ① | **过滤与去标签的顺序颠倒了** | 白名单「按标签名提取 `<content>…</content>`」与黑名单「按行匹配标签」**永远匹配不到** → 点「＋白 / ＋黑」后投喂文本与不过滤**一模一样**（「不联动生效」的直接原因） | **v2.44.0（本插件自身回归）** |
| ② | **委托读错属性名**：`kind` 只读 `data-kind`，而按钮用的是 V1 同款 `data-ftt-kind` | 点「＋黑」被 `feedScanAction` 归一为 `white` → **标签实际加进了白名单**；调试页时间线「类别筛选」按钮恒为「全部」（点了没反应） | v2.41.0 之前（与 v2.41.0 的「入参透传」修复同源但漏了这一项） |
| ③ | 契约未写清 | 「取文保留标签、过滤后再去标签」这条顺序约束此前没有测试锁死，也没有文档说明，于是 v2.44.0 顺手把它改错了 | v2.44.0 |

面板 change 委托对两个文本域做整表排重并以**数组**写回。问题全部在「委托属性映射」与「取文顺序」两处。

## 2. 修复 ①：顺序必须是「取文（含标签）→ 标签过滤 → 去标签 → 交 AI」

```text
ctx.chat[i].mes（富文本，含 <content>/<br>）
   └─ host/floors.js#collectFloorLinesInRange   ← **保留 HTML**（过滤需要标签）
        ├─ host/floors.js#buildFeedFloorText      → applyFeedRegex(原始行) → cleanText() → AI 提示词
        ├─ host/floors.js#buildFeedFloorTextRange → 同上
        ├─ host/floors.js#floorAnalyzableText     → 同上（单楼分析）
        └─ host/extract.js（分段摘要）            → 同上
```

- `core/prompt.js#applyFeedRegex` **未改动**（V1 逐字）：白名单提取 `<tag>…</tag>` 内部内容、
  黑名单按行丢弃、白名单零命中则回退原文。它是「必须看到标签」的那一步，因此**只能在它之后去标签**。
- 时钟/在场解析不需要标签 → 仍由 `core/clock-extract.js` 在**取值前**自行清洗（v2.44.0 行为不变）。
- **楼层哈希口径不变**（`floorStableText` 仍取原始正文）→ 既有「已处理楼层」台账不失效。

## 3. 修复 ②：`kind` 必须兼容 `data-ftt-kind`

```js
// ui/panel.js（点击委托）
const kind = ds.kind || ds.fttKind || '';   // v2.45.0：补 data-ftt-kind 回退
```

- 投喂标签「＋白 / ＋黑」与调试页时间线「类别筛选」按钮都沿用 **V1 同款 `data-ftt-kind`**；
  V1 的 `rxAddTag` 分支正是直接读 `ds.fttKind`（v1.206 27095）—— 即修复后回到 V1 口径。
- 同一行同时修复了调试页：`dbgTraceFilter` 的 `payload.kind` 此前恒为空串 → 类别筛选恒为「全部」。

## 5. 已知 V1 怪癖（**原样保留**，未顺手修正 —— 需要时另批申请）

1. **白名单对非成对标签无效**：`<br>` 这类自闭合标签不会命中 `<br>…</br>`，于是回退到「行内包含 `br`」语义
   （可能误伤含 `br` 字母的正文）。V1 同此。
2. **标签名必须无属性**：提取正则为 `<tag>…</tag>` 字面匹配，`<content type="x">…</content>` 不会被提取，
   同样回退到「行内包含」。V1 同此。
3. 以上两条都只在「白名单」路径上；黑名单是逐行包含匹配，不受影响。分析与「＋白 / ＋黑」按钮的候选名仍按标签名给出（大小写归一）。

## 6. 影响面与兼容性

- 只影响**投喂文本/分析文本**的构造顺序与点击委托的 `kind` 取值；配置键、文案、按钮标记与 V1 一致。
- 「＋黑」修复后，此前被误写进**白名单**的标签需要用户手工清理（升级不会自动搬迁，避免擅自改动用户配置）——
  可在「投喂白名单标签」文本域删掉对应行；名单为空即「不过滤」。
