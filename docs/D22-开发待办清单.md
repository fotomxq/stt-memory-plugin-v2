## 0. 怎么用这份清单（与 `D17` 的分工）

| | `docs/D17-未落实事项台账.md` | **本稿 `docs/D22-开发待办清单.md`** |
| --- | --- | --- |
| 回答 | 「**还有什么没做**」 | 「**轮到做哪个**」 |
| 组织 | 按**来源文档**（`D*` / `01`–`05`） | 按**维度序 + 批次**（业务 → 应用 → 数据 → 技术） |
| 粒度 | `U<n>` = 事实条目（**281 条**，含文档治理类） | 只收**开发项**（各设计稿「实施规格」行），文档治理类不入本清单 |
| 完成标记 | 状态改 `✅`（**行不删、不搬家**） | 具备「版本 + 呼应」后**移出本表**；编号永久保留、禁止改号 / 复用 / 重排 |
| **销账去向** | 状态改 `✅ 已落地（vX.Y.Z）`，仍在原节 | **移出本表**（不设归档区；git 历史即归档），同时改 `D17` 的对应 `U<n>` |

> **判据**：一行只有**同时**具备「版本号」与「呼应」两项，才能销账并从本表移除；缺任一项 → 先在 `D17` 记 `🟡 部分` 或补留痕，**不得**只写「已完成」（§6 Q1 / Q2）。
> **不复述设计**：事项的落点 / 前置 / 步骤 / 验收 / 回退一律**指向来源稿的对应行**，避免与设计稿二次漂移（同 `D17` §5.4 口径）。
> **两态承接（C12）**：设计稿的每条实施规格，要么在本表有行（待办），要么其台账 `U<n>` 已在 `D17` 标已落地（已交付并移出）；两者都不满足即判为真遗漏。

| **编号冻结** | `业-n` / `应-n` / `数-n` / `技-n` 与 `U<n>` **只增不复用**；已移出的编号禁止改号 / 复用 / 重排 |
