## 1. 目标 / 非目标

**目标**

1. 把「版本号只在 `3.XX.XX` 上追加」这条**用户裁决**写成可执行规则（谁改、怎么改、越界怎么办）。
2. 把「docs 内容一致性」从**人工校对**变成**可机械核对的判据**，并修掉本轮实测出的全部不一致。

**非目标（明确不做）**

- 不改插件行为（`core/` `host/` `adapters/` `ui/` `index.js` `style.css` `settings.html` **一律未改**）；
- 不动版本号、不打 tag、不跑发布/归档终检（本轮是**设计轮次**，见 `开发守则.md` §1）；
- 不重写历史层（`CHANGELOG.md`、`docs/history/**` 是**只增不改的快照**，其内部旧路径**不算不一致**）；
- 不追求「文档与代码 100% 自动对齐」——只覆盖**可机械判定**的部分（数字、版本、引用存在性、目录树集合）。

## 4. 版本号追加规则（用户裁决 → 制度化）

| 规则 | 口径 |
| --- | --- |
| 只在 `3.XX.XX` 上追加 | 新增能力 / 行为变更 → `3.<minor+1>.0`；纯修复 → `3.<minor>.<patch+1>` |

| tag 同名 | `v<版本>`；`--strict` 要求 HEAD 落在同名 tag 上 |

## 6. 风险与对策

| 风险 | 对策 |
| --- | --- |
| 门禁把**历史层**的旧路径判为错误 → 永远修不完 | C7 历史层豁免（只增不改的快照） |
| 误报（仓库外路径 / 裸文件名）导致门禁被绕过 | 白名单**显式登记 + 写明理由**；裸文件名按固定落点解析；不放宽用户名/主机名等隐私规则 |
| 断言数等**动态计数**让门禁抖动 | 计数只由唯一实测方（runner）核对；若日后出现同一代码两次跑出不同数，视为测试**不确定性缺陷**去修测试，而不是放宽门禁 |
| 文档持续漂移 | 每次「改了会变数字的东西」→ 同一提交内更新 §3，否则 `npm run gate` 失败（见 `开发守则.md` §3.2.1） |
| **行号引用漂移**（v1.1 实测：D6 §1 整表 +44、D8 §2.1 整表 +8、D7 §3 全节、D9 §2.2、D12 §1…共约 74 处） | ① **C8**：`文件#符号` 符号级阻断（改名/删除立刻失败）；② **C9**：行号棘轮只减不增 + 「新引用一律写符号」的口径；③ 本轮把已核实失效的那些改成符号/真实行（见 `docs/D15` §5 与本稿 §8.1） |
| **想「自动核对行号指向的语义」**（本轮明确**不做**） | 行号引用的「语义对应」无法机械判定：同一行可能被合理引用于不同结论，且任何自动阈值都会产生大量误报。替代方案就是 C8：**让引用写成符号**（符号存在性可判定），行号只留给冻结坐标 |
