### 2.2 四个结构性失衡

| # | 失衡 | 表现 |
| --- | --- | --- |
| S1 | **只有历史，没有现状** | 想回答「现在注入怎么写」必须翻 `P3`+`P10al`+`P10am`+`P10aq` 多份批次档 |
| S2 | **数字无单一来源** | 黄金样本 13/54、配置键 217/216、模板 33/32、控件 105/173 分散在各文档 |
| S3 | **过时内容无登记处** | `P8:222` 的「进行中（未完成）」与 `:224`「批次收官」**自相矛盾**；8 份文档状态停在「待发版」 |
| S4 | **引用关系未被利用** | 代码 / 测试里有 **49 + 11 处** `docs/*.md` 路径引用，但没有任何索引把它们与现状文档关联起来 |

### 2.3 引用关系（决定「能不能搬」）

| 引用来源 | 处数 | 影响 |
| --- | --- | --- |
| 代码注释（`core/` `host/` `ui/` 等） | 49 | 搬移会留下死链（仅注释，门禁不检查） |
| 测试注释 | 11 | 同上 |

结论：**物理归档必须与「批量改引用」同批执行**，否则文档可读性下降（§6 P2）。

### 4.1 四篇架构文档的**职责边界**（防互相抄）

| 文档 | 只回答 | 不该出现的内容 |
| --- | --- | --- |
| 01 业务架构 | 用户价值、能力全景、用户旅程、**业务规则与口径**、已知边界 | 代码路径细节、门禁、存储实现 |
| 02 数据架构 | 容器与字段、id 与哈希、生命周期、迁移、存储分层、跨端、一致性清单 | 界面、流水线、宿主装配 |
| 03 技术架构 | 分层与依赖、装配、宿主适配与降级、AI 通道、横切能力、质量体系、版本治理 | 具体页面清单、业务流程叙述 |
| 04 应用架构 | 界面外壳、分页 / 子页职责、主流水线、动作分发、命令与事件、扩展点清单 | 数据结构、门禁、发布流程 |
| 05 开发指南 | 环境命令、目录地图、测试体系、发布流程（引守则）、编码约定、常见任务、排查入口 | 与四篇重复的架构叙述（只给链接） |

**交叉引用规则**：业务动机 → 01；数据形状 → 02；落地机制 → 03；界面与流程 → 04；怎么干活 → 05；历史与证据 → `P*`；未来方案 → `D*`。
