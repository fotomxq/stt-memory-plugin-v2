## 2. 安全口径（V1 的四条，逐条落地）

1. **锚点不可信 → 只统计不修改**：手工、当前时钟、多数派、一致性四条都不满足时 `usable=false`，`blocked=no-anchor`（库内日期分歧过大 → `ambiguous-anchor`）；
2. **任何写回都过唯一闸门**：`clockPatrolSafeDate` 要求「格式合法」且「不触发年份异常（与锚点相差不超阈值）」；
3. **格式合法但年份漂移、又无法可靠修正 → 保留原值**（只有「格式非法/日期不存在」才允许清空）；
4. **写回前自动留全量快照**（`snapshotCreateFull()`），报告里给出快照 id，可到数据管理页还原。

## 3. 与 V1 的偏差（逐条明示）

1. **定位差异**：V1 的锚点/手工值直接读写全局 `state`/`cfg`；V2 走注入视图（`state`/`cfg`/`saveState`/`notifyHooks`），因此 `runClockPatrolRepair` 的提示经 `notifyHooks.toast` 输出、面板重绘由 UI 层负责（V1 在函数内 `renderPanel()`）。
2. **未移植的两条 AI 管线（属 B8-2）**：`clockRegexGen`（AI 捕捉正文 → 生成日期/时间/地点正则）与 `clockRepair`（AI 结合正文修复日期时间）。
   基础页对这两项以「属后续批次（B8-2）」明示标注，**不提供假按钮**；本批交付的是**零 AI** 的机械巡检与手工锚点。
3. **「显示界面开关（buttonLocation*）」**：V1 在基础页提供底部/顶栏/悬浮/菜单四处按钮开关；V2 的入口形态由「V2 附加设定」的悬浮/菜单开关承担（配置键 `buttonLocations` 为对象，未拆成四个顶层键），故基础页该节仅作说明，不重复渲染。
