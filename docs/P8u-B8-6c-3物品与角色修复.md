## 2. 与 V1 的差异（逐条明示）

1. **AI 通道**：V1 自建 OpenAI 兼容请求（`callChatCompletion`）；V2 统一走注入钩子 `core/ai-hooks.js#aiCallText`（酒馆 `generateRaw`），采样参数由酒馆预设控制。
2. **正文投喂**：V1 `buildFeedFloorText(n)` → V2 `core/ai-hooks.js#aiFeedText(n)`（宿主 `host/floors.js`），长度口径与 `slice(-8000)` / `slice(-10000)` 逐字保留。
3. **任务管线 UI 未移植**：V1 的 `pipeStart`/`pipeUpdate`/`pipeEnd`/`abortTick`/`abortQuiet`/`abortRequested`/`newTaskStart`/`renderPanel` 在 V2 不存在；互斥改为 `aiBusy()`（等价 V1 `busy.repair` + 摘要/压缩/推演/推进/同步占用），重绘由 UI 层负责，AI 不可用时如实回报。
4. **`opts.aiText` 注入点**：两个管道的 `run*` 均增设可选 `opts.aiText`（与 `runRepair`/`runMemoryRepair`/`runConceptRepair` 同约定），供测试显式提供 AI 返回；缺省仍走 `aiCallText`。
5. **通知形态**：`notify(kind, title, text)` 统一经 `notifyHooks.toast`；V1 `notify('repair', …)` 的 toastr 类型是 `warning`，V2 取等价 `'warning'`（黄金样本比对时做 kind 映射，**文本逐字符一致**）。`dbgLog` 类别沿用 V1 的 `'摘要'`。
6. **复用而非复制**：
   - 物品域复用 `core/group-repair.js`（`GROUP_REPAIR_SPECS.items` / `groupPick` / `itemBaseNameKey`）、`core/forget.js#lowUseSweepGate·lowUseSweepMark`、`core/ingest.js#storeMinFor`；
   - 角色域复用 `core/model/snapshot.js` 的剧情时间采样 / 年龄锚点 / 出生日期兜底 / 已去世锁定 / 倒挂判定 / 标签归一，以及 `core/entries.js#sweepStatesForRemovedSnapshots`；
   - 为此两处**新增导出**：`core/model/snapshot.js#guessAgeFromCues`（V1 私有，`snapshotFallbackTags` 需要）与 `core/entries.js#sweepStatesForRemovedSnapshots`（V1 私有，删除角色时状态联动清除需要）；实现未改动。
7. **V1 `isCurrencyItemName` 为私有函数**，V2 在 `core/item-repair.js` 导出以便 `FTT.*` 自证与单测覆盖（真值表与 V1 一致）。
8. **V1 中 `SNAP_REPAIR_FIELD_MAP` 未导出**，V2 导出（`FTT.snapRepairFieldMap`）供调试与测试自证。
9. **面板 note 的 `groupsTotal` 兜底**：V1 `runItemRepair` 成功分支的返回结构**不含 `groupsTotal`**（黄金样本已固化 key 集，V2 不加键改形）；因此物品页 note 用 `groups` 兜底展示「高相关组 N/M 组」，不引入 V1 没有的字段。
10. **按钮 class 差异**：V1 用 `ftt-btn`，V2 工具栏约定为 `ftt-btn ftt-sm`；位置在 V2 维度工具栏内（V1 在分类统计行 / 页面顶部）。**文案、`title` 与显隐条件逐字对齐 V1**；角色页的「（⚠️N 优先）」角标计数口径与 V1 相同（对**全部**档案调 `snapshotBirthAnomaly`，含已去世角色）。
11. **`h` 内容哈希不参与黄金样本比对**：V1 的 `saveState` 会为原子补 `h`；V2 测试把 `saveState` 注入为桩，故 fixture 的档案投影只含字段内容而不含 `h`。
12. **未验证项**：真实宿主（酒馆 `generateRaw` 超时/中断）下的行为未单独验证 —— V2 无 `abortRequested` 语义，`runCharacterRepair` 的「中断静默收尾」分支未移植（V1 的 `abortQuiet` 依赖任务管线）。
