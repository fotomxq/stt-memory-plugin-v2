## 3. 主流水线

| 流水线 | 触发 | 步骤 | 落点 |
| --- | --- | --- | --- |
| **注入** | 生成前（拦截器）/ 手动「立即注入」 | 读库 → 候选打分（含词法/向量/关键词三层）→ 预算内择优 → 结构头 + 正文 + 说明 + `记忆结束。` → 写入扩展提示词 | `host/inject.js`、`core/recall.js` |
| **注入体结构（v2.88.0）** | —— | 注入体为 **Markdown**：外框 `# FTT 记忆注入` + 引用行，正文为 `## 小节`（`> 说明：…`）+ `- ` 条目，约束段 `## 注入约束`；**预算按内容计**（`mdCostOf`，Markdown 标记不挤占）→ 注入条目集合与 V1 逐条一致 | `host/inject.js#wrapInjectText`、`core/recall.js#buildMemoryBodyForInject` / `#buildInjectConstraints` |
| **提取** | 生成后自动 / 手动 / 命令 | 取未分析楼层 → 提取前校对基本信息 → 三层提取（向量 → JS → AI）→ 增量 JSON → 逐维归一 → 落库 → **分析后按最新情节同步日期/时间/地点/在场角色**（情节有变化才执行，v2.81.0）→ 台账记账 → 落盘 | `host/extract-flow.js`、`host/extract.js`、`core/ingest.js`、`host/preflight.js` |
| **修复** | 各页按钮 / 「🛠 自动修复」/ 合并失败自动 | 机械清理 → 聚类选组 → 窄契约 AI → 按编号精确应用（**AI 不删原件，除显式路径**） | `core/repair.js` 与 `*-repair.js` 族 |
| **演化** | 传言「立即演化」（每 N 楼被动触发）/ 平行推演 | 机械演化（零 AI、种子确定）→ 变化先入 `pending`，N 轮后提交（留传导链路） | `core/rumor-evolve.js`、`core/parallel.js` |
| **遗忘** | 修复管道 / 载入 | 按**剧情时间**多级衰退 → 达阈值移除（留双墓碑） | `core/forget.js`、`core/recall.js#calcTimeDecay` |
| **时钟** | 消息后自动 / 手动巡检 | 只取最新情节 → 日期异常判据 → 写时钟 | `core/clock*.js` |
| **提升** | 用户点击各维度条目的「⬆ 提升为情节」（现仅平行页有「⬆ 转正为情节」） | 前置校验 → 生成情节草稿预览 → 确认写入 `atoms` → 写 `derived-from` 边与留痕 → 触发联动传播 | `core/parallel.js:498-548`（现有）· 设计稿 `D6` |
| **被动调度** | 合并成功后 | 推演 / 情节总结按延迟排程一次（防重复） | `index.js` 调度 + `docs/history/P9d` |

## 4. 交互与动作分发

| 机制 | 说明 |
| --- | --- |
| 动作分发 | 统一 `data-ftt-action` + 面板事件委托；未知动作如实报错（审计动作完整性） |
| 属性型控件 | 无 action 的控件（设定子标签 `data-ftt-subtab`、约束页维度 `data-ftt-cdim`、情节子标签 `data-ftt-asub`）在 `!act` 分支前置处理 |
| 入参透传 | 动作参数（kind / id / idx / tag / mode / name / editor…）逐一映射，避免「点了没反应」 |
| 按钮安全 | 面板内按钮一律带 `type="button"`（防 form 内 submit 跳顶） |
| **异常提示（v2.87.0）** | 内核 `warn(...)` 一次调用做三件事：宿主 warn 钩子 → 调试日志（kind=`异常`）→ **用户可见 ⚠️ 提示**（节流：同文案 60s 一次、每会话上限 5 条）；面板动作**异常**强制提示、**被拒绝**（`ok:false`）走节流提示；此前 `adapters/store.js` 把 `warn` 接成 `() => undefined`，等于所有内核告警被静默丢弃（用户报告「什么都没反应」） |
| **范围型控件** | 相似度 / 阈值 / 比例 / 概率 / 占比等**百分比语义**统一渲染为**滚动条**（`RANGE_SPECS` 28 项 + `rangeControlHtml`，v2.84.0 起；v2.86.0：下线 `importanceBase/PerUse` 两项、加入「清扫保护阈值」）：轨道上有一道**默认值刻度**（内联 `--ftt-range-def`）、右侧「默认 X」文字、拖动中 `output` 实时读数；`input` = 只刷读数，**`change`（松手）= 写配置 + 落盘 + 重绘**。**计数类（条数 / 年限 / 楼层）刻意保留数字输入** |
| **占比联动（v2.85.0）** | 「各大类占比」这 10 条滚动条之间存在 **=100% 约束**，故拖动时**当场联动**：本次拖动首次 `input` 快照**基准占比**，此后每帧走纯函数 `allotStoreShares`（被拖动项权威、其余按基准比例缩放、四舍五入、余数给最大项），同一帧内重写其余滚动条 + 读数 + 行尾保底文字 + 合计行 + 上方保底输入框；**拖动中不写配置**，松手才提交。拖「存储总上限」时占比不变，但各维条数与保底文字当场跟着变 |
| **保底被动下移（v2.85.0）** | 有效上限**只由**总上限 × 占比决定；配置的 `storeMin*` 高于该值时被 `clampStoreFloors` **只降不升**地写回上限之下（提交占比 / 改总上限 / 手填保底 / 启动自愈），note 如实回报「保底已下移：情节 5000→90」，行尾标注「（已随上限下移）」。兼容口径（`storeTotalMax` 为 0 / 缺键）下**不碰**保底 |
| 重渲染 | 复用既有 `.ftt-modal` 节点、只替换其内部 —— **入场动画不重放**（v2.80.1 修复「点击闪一下」）；首次打开 / 关闭后重开才播放入场动画 | `ui/panel.js#renderPanel` · `#existingModalNode` |
| 滚动保持 | 整页重渲染后恢复**活动标签内容区**滚动位置（点击不跳顶） |
| 隔离 | 单页渲染异常被捕获并降级为错误卡片，不拖垮整页 |
