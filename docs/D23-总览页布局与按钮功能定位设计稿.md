## 0. 一页摘要

用户指出的"提取功能与立即 AI 摘要冲突"，核对后**成立**，但真实形态比"重名"更硬 —— 是**三重问题叠加**：

| # | 问题 | 证据（只读核对） |
| --- | --- | --- |
| **① 功能完全重复** | 总览的「📤 提取记忆」与「📤 立即注入」**调用同一个函数、同样传空查询词**，功能等价 | 「📤 提取记忆」→ `hooks.recall` → `index.js#runRecallNow` → `host/inject.js#pushMemoryInject({})`；「📤 立即注入」→ `hooks.inject` → `index.js#injectNow` → `pushMemoryInject({ queryText: '' })` |
| **② 命名与功能相反** | 这个按钮叫「提取记忆」，做的却是**召回 + 刷新注入**（读库送出），与真正做提取的「⚡ 立即 AI 摘要」（写库落库）**名字撞车、方向相反** | 按钮 `title` 自述：「按向量 / JS 抽取**召回相关记忆并刷新注入**（零 AI 为主，不占用分析管道…）」；`ui/panel.js` 该分支注释自述：「**「提取记忆」= 发送前召回**」 |
| **③ 回退歧义** | 该按钮在 `hooks.recall` 未接线时**回落到 `hooks.extract`（＝AI 摘要）** → 同一按钮在两种宿主形态下做**两件不同的事** | `ui/panel.js` 的 `extractNow` 分支注释：「`hooks.recall` 未接线时回落到旧的 AI 摘要入口（`hooks.extract`）」 |

**用户裁决**：**总览只保留「⚡ 立即 AI 摘要」作为提取入口**，删除「📤 提取记忆」。

**本稿据此明确三件事**：① 每个按钮的**功能定位**（§3.1）；② 总览的**布局分区**（§3.2，仅分组与文案，**不做视觉改版**）；③ 删除后的**能力补偿**（§3.3）——
其中**召回方式提示必须迁移到「📤 立即注入」**，否则删按钮会丢掉「用什么方式召回」这项可观测性（v3.26.3 的成果）。

> 与 `D22` 的呼应：本稿产生 **`应-14`**（删按钮 + 提示迁移）· **`应-15`**（布局与按钮定位回写 `04` §2.1 与 `D9`）· **`技-20`**（命名口径统一，与 `D21` 侧的术语错位同源）。

## 1. 目标 / 非目标

### 1.1 目标

1. 明确总览**每个按钮的功能定位**，消除「提取记忆」这一名实不符的入口（§3.1）；
2. 明确总览的**布局分区**（状态区 / 写库区 / 读库区 / 维护区 / 存取区），使按钮归属唯一（§3.2）；
3. 给出**删除后的补偿清单**，保证能力不下降（§3.3）；
4. 统一「提取 / 召回 / 注入」三个词的口径，使文档、注释、按钮文案一致（§3.4）。

### 1.2 非目标（明确不做）

- N1 **不改任何代码 / 不动版本号 / 不打 tag**（设计轮次，`开发守则.md` §1）；
- N2 **不做视觉改版**、不引入 UI 框架、不改移动端断点（`D9` §1 N1–N5）；
- N3 **不动「⚡ 立即 AI 摘要」与「第 N 楼」的联动语义**（`04` §2.2 已定：同一条分析管线的两个入口）；
- N4 **不删除「📤 立即注入」** —— 它与提取方向相反、不与 AI 摘要冲突，是本稿的**唯一注入入口**（§3.1）；
- N5 **不改「设定 → 提取记忆」页**的结构与三键（`useVector` / `jsExtractEnabled` / `useKeywordFlow`）—— 页面归属问题见 `技-20`，与本次按钮删减分开处置。

## 3. 方案

### 3.1 按钮功能定位（现状 → 目标）

| 按钮 | 动作 | 方向 | 现状 | **目标定位** |
| --- | --- | --- | --- | --- |
| ⚡ **立即 AI 摘要** | `summary` | **写库**（提取） | 批量分段 AI 摘要并落库；与「第 N 楼」同一条管线 | **保留** —— 总览**唯一**的提取 / 落库入口（用户裁决） |
| 📤 提取记忆 | `extractNow` | 读库（召回） | 与「立即注入」同函数；名字与「AI 摘要」撞车；含回退歧义 | **删除**（`应-14`） |
| 📤 **立即注入** | `inject` | **读库**（注入） | 刷新注入，只报"已注入 N 字" | **保留** —— 总览**唯一**的注入入口；**接收迁移来的召回方式提示**（§3.3） |
| 🛠 自动修复 | `repair` | 维护 | 三段式修复 | 保留（维护区） |
| 🌶 弱化 NSFW | —— | 维护 | 文本弱化 | 保留（维护区） |
| 🧭 推演世界 | `parallelWeaveNow` | 维护 | 平行事件推演 | 保留（维护区） |
| 💾 保存（对齐所有存储） | `saveAll` | 存取 | 逐层写盘并回报 | 保留（存取区） |
| ⏳ 未摘要 N 楼（可点击单楼分析） | —— | 写库（提取） | 与「立即 AI 摘要」同管线的单楼入口 | 保留（状态区内，作为**提取**的第二入口，与 `04` §2.2 已定口径一致） |

**一句话口径**：**写库只有「立即 AI 摘要」（+ 单楼），读库只有「立即注入」。** 两者方向相反，不冲突；「提取记忆」这个名字只留给写库路径。

### 3.2 总览布局（分区与归属）

> 仅规定**分组与文案归属**，不改视觉、不改 DOM 结构、不改断点（N2）。分区的意义是：**任何新按钮必须能唯一归入某个区**，否则不允许加入总览。

| 区 | 名称 | 内容 | 该区的按钮 | 约束 |
| --- | --- | --- | --- | --- |
| **A** | 状态区（只读） | 剧情时钟 · 在场角色 · 管线状态 · 已处理与未摘要楼层 · 最后一次提取 | 「⏳ 未摘要 N 楼」按钮组 | 只读展示为主；按钮仅作**下钻**（单楼分析） |
| **B** | 写库区（提取） | ——（动作区，无独立展示） | **⚡ 立即 AI 摘要** | **本区只能有一个入口**（单楼入口归 A 区下钻） |
| **C** | 读库区（注入） | —— | **📤 立即注入** | 本区只能有一个入口；**召回方式提示在本区输出** |
| **D** | 维护区 | 修复 / 弱化 / 推演 | 🛠 自动修复 · 🌶 弱化 NSFW · 🧭 推演世界 | 均为**可能改数据**的动作，须走既有二次确认口径 |
| **E** | 存取区 | 备份与迁移 | 💾 保存（对齐所有存储） · ⬇ 导出 · ⬆ 导入 | 危险动作（导入覆盖）延续二次确认 |

**展示顺序**：`A 状态 → B 写库 → C 读库 → D 维护 → E 存取`（自上而下、由读状态到改状态，最后是备份）。
**按钮行内部顺序**：B / C 各自独立成组（视觉上相邻但语义分离），D、E 各成一行或一段 —— **不把 B/C 与 D/E 平铺在同一行**（现状把 8 个按钮挤在一行，是 K10 那种"挤成一组"的根因）。

### 3.3 删除「提取记忆」的补偿清单（**能力不得下降**）

| # | 丢失的东西 | 补偿动作 | 为什么必须补 |
| --- | --- | --- | --- |
| C1 | **「召回方式」提示**（向量召回 / 本地关键词召回 / AI 分析召回 + 降级原因） | **迁移到「📤 立即注入」分支**：`injectNow` 的返回值补 `method`（复用 `host/inject.js#pushMemoryInject` 已产出的 `method`，词表仍取 `host/extract-flow.js#recallMethodInfo`），并在注入结果提示里输出 | `pushMemoryInject` **本来就返回 `method`**；只是 `inject` 分支没读它。不迁就等于**白丢** v3.26.3 的成果 |
| C2 | `hooks.recall` 未接线时的 `hooks.extract` 回退 | **不保留**：该回退的存在正是"一个按钮做两件事"的来源。未接线时应**如实提示**"召回入口未就绪"，由「⚡ 立即 AI 摘要」承担提取 | 消除 K8 的回退歧义；且「立即 AI 摘要」本就在，不需要第二个回退路径 |
| C3 | 向量 / JS 层的单层测试入口 | **不受影响**：仍在「设定 → 提取记忆」页（`ui/api-page.js` 用 `host/extract-flow.js#testLayer`）与 `/ftt-analyze` | 删的是**总览按钮**，不是能力 |
| C4 | 管线行的名字「提取记忆（召回 + 注入）」 | 改为「**召回 + 注入**（刷新注入）」，并同步 `04` §2.2 的相关表述 | 否则删了按钮、管线里还写着"提取记忆"，名实不符仍在（与 `技-20` 同源） |
| C5 | 手动"不占分析管道"的召回入口 | 由「📤 立即注入」承担（同函数，行为等价）；发送前自动刷新不变（`host/interceptor.js#fttGenerateInterceptor`） | 保住 v2.74.0 的原始诉求："不占分析管道、可与长任务并行" |

### 3.4 命名口径统一（与 `技-20` 同一件事）

| 词 | **只用于** | 不得用于 |
| --- | --- | --- |
| **提取**（extract） | 楼层正文 → AI 摘要 → 增量 JSON → **落库**（`host/extract.js`） | 召回、注入、刷新提示词 |
| **召回**（recall） | 从记忆库**选出**要送出的条目（`core/recall.js` + `host/inject.js` 的三层流程） | 落库、写数据 |
| **注入**（inject） | 把召回结果**写入扩展提示词**（`setExtensionPrompt`） | 落库 |

> 现状已知的错位（**另案**，登记为 `技-20`）：`host/extract-flow.js` 名为提取、实为召回三层；`01` §2.2「提取（三层）」、`03` §5「三层提取」、`04` §3 提取行把召回三层记成提取。

## 5. 风险与对策

| # | 风险 | 对策 |
| --- | --- | --- |
| R1 | 先删按钮后补提示 → 用户暂时失去召回方式可见性 | 阶段顺序固定为 **E1 补偿先行**（§4）；E1 未通过不得进入 E2 |
| R2 | 用户习惯"点提取记忆刷新注入" | 「立即注入」行为**完全等价**（K5 同函数）；且它在同一行相邻位置，迁移成本低 |
| R3 | 删掉 `hooks.recall` 回退后，某些宿主形态失去唯一入口 | C2 明确"如实提示未就绪"；提取路径由「立即 AI 摘要」承担；`/ftt` 的能力探测会如实报出（`04` §6） |
| R4 | 布局分区被理解为"视觉改版" | N2 明确：只改**分组与顺序**，不改类名/DOM 结构/断点；`D9` §1 N2 是硬约束 |
| R5 | 面板审计（`panel-audit`）因删动作误报 | `应-14` 的验收含"动作完整性审计通过"（`docs/05-开发指南.md` 约定 C8） |
| R6 | 与 `D19` 的 U1（列表分页）等改动叠加造成界面抖动 | 本稿只动总览工具行；与列表类改动无交集，可独立发布 |
