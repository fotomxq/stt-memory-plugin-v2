## 2. 与 V1 的差异（逐条明示）

1. **楼层取文改经注入钩子**：V1 直接调宿主 `collectFloorLinesInRange(start, end, {})`；V2 由 `setParallelTextHooks({ floorLinesInRange })` 注入（`index.js` 接线到 `host/floors.js`），内核不读宿主聊天 —— 与 `core/clock-extract.js#setClockTextHooks` 同款。未接线时返回空数组（推演正文为空、推进背景为空）。
2. **`pipelineOccupied()` → `aiBusy() || weaveBusy || advanceBusy`**：V1 的 `longTaskBusy() || syncOcc()` 含「存储同步在途」；V2 无同步占用概念，宿主互斥钩子（`aiBusy()`）表达「摘要/提取在途」，再叠加本模块自身的推演/推进在途位，保持「推演进行中再次推演 → busy」的 V1 语义。
3. **`resolveParallelApiOverride()` 未移植**：V1 支持「平行事件（推演/推进）专用分析渠道预设」并可按域切换 API 连接；V2 的 AI 通道由宿主统一接线（`aiCallText` → 酒馆 `generateRaw`），无自建连接 → **不设假控件**（`cfg.parallelApiPreset` 在 V2 配置里存在但无引用，与 §6.1「按用途 API 预设」判定一致）。V1 的调用标签原样透传（`'[平行事件·交织]'` / `'平行事件推进'`）。
4. **任务管线 / 中断未移植**：`newTaskStart` / `abortTick` / `abortQuiet` / `pipeStart` / `pipeUpdate` / `pipeEnd` / `renderPanel` 在 V2 不存在；因此 V1 `catch` 里「用户中断 → 静默收尾」的分支退化为「一律按异常告警」，且本批**未新增任何后台队列**（重绘由 UI 层负责）。
5. **主流程增设 `opts.aiText` 注入点**（`runParallelWeave` / `runParallelAdvance`）：与 `runRepair` / `runPlotSegmentSummary` 同约定，仅供黄金样本与离线测试；缺省仍走 `aiCallText`。
6. **`lastExtractKeywords` → `setParallelLastKeywords / parallelLastKeywords`**：V1 的全局变量由提取管线写入；本批（P9d）已把 `jsExtractKeywords` **逐字移植**到 `core/parallel.js`（V1 11213~11232）并由 `host/extract.js` 在提取合并成功后接线，**手动「推演世界」仍按 V1 用最近一次提取关键词**（V1 该值由 `runExtractAction` 写入，V2 的注入域批次未接线 → 手动入口默认空关键词，与 V1 关键词为空时行为一致：上下文退化为列出既有平行事件）。
7. **自动被动调度**：~~未接线~~ → **✅ P9d 已闭环**：`host/extract.js` 在 V1 的四个检查点接线（单楼 15240 / 分段 15490 / 独立分组 14806·14829）+ `scheduleAtomCompact`（15242 / 15537）；由单测 W1–W6 与冒烟 AI2/AI3（注入定时器驱动）固化。
8. **面板动作提示落点**：V1 用 `toast(...)` 汇报分支结果；V2 统一写面板 `note`（`r.state.note`），文案取自 V1 toast 正文（保留前导图标）。`parallelAdvanceAll` 另加「无目标」提示（V1 该分支静默）—— V2 的可见反馈补充。
9. **确认闸门实现**：V1 `D.confirm(...)`；V2 `hooks.confirm(text,title)` → 否则 `globalThis.confirm`；**都没有则取消**（与 V1「`D.confirm` 非函数 → `ok=false` 直接 break」同口径），故 `cfg.parallelPromoteConfirm` 开启时在无对话框环境不会静默转正。取消时 V2 写 `note='已取消转正（未生成情节）'`（V1 静默）。
10. **备注行少了「🔗 关联」跳转**：V1 的 `relJump` 动作（条目行 ↔ 关系表双向定位）在 V2 尚未移植（§6「B9 待做」），本批**不渲染空跳转**；其余文案逐字一致。
11. **toast 前导图标剥离**：V1 的 `toast(msg,type)` 兼容入口会剥离前导图标（`LEGACY_STRIP_ICONS`）；V2 逐字移植该剥离，保证核心通知文本与 V1 一致；`notify(kind,{title,text})` 仍按 V2 约定合并为「标题 + 空格 + 正文」经 `notifyHooks.toast` 发出。

## 3. V1 原生缺陷 / 怪癖（如实保留，不擅自修正）

1. **后到调度被静默丢弃**：`scheduleParallelWeave` 的 `if (!weaveEnabled() || weaveBusy || weaveTimer) return;` 不排队、不替换 pending —— 先到请求生效，后到请求无任何提示（黄金样本 `schedule.double` 已固化：二次调度后仅 1 次 AI 调用）。
2. **去重跳过时楼层已先被计数**：`runParallelWeave` 先写 `state.weaveLastFloor`，再判输入签名 → `skipped:'dedup'` 也会推进「被动触发间隔」计数（V1 顺序原样）。
3. **推进忙位返回 `ok:true`**：`{ ok:true, skipped:'busy' }`，与推演的 `{ ok:false, error:'busy' }` 口径不一致（V1 原样）。
4. **转正注释与实现不符**：注释称「id + 内容哈希双墓碑」，实际走 `deleteEntry('parallels', id)` **只写 id 墓碑**；`tombEntry(dim, p)` 的兜底分支在真实路径上**不可达**（`deleteEntry` 恒为函数）。内容哈希墓碑由存储层「删除留痕」（`tombstoneSweep` / `applyDeletedToArray` 的 `learnH`）在保存时补记 —— 黄金样本里 V1 的 `deletedH.parallels` 有一条 `storageHash` 键，V2 侧由同一移植件（`core/sweep.js`）复现。
5. **`promotedAt` 的取日期表达式**：`(getStoryNow() || {}).date || state.state.date` —— `getStoryNow()` 返回**字符串**，其 `.date` 恒为 `undefined` → 实际总是回落 `state.state.date`（空则空串）。V2 逐字保留（黄金样本 `titlePad/success/...` 的 `promotedAt` 已固化）。
6. **`演化目标可能性` 只认中文键 `目标`、`: likelihood` 缺省 0**：`{目标:'', …}` 空目标项被丢弃；`可能性:'abc'` → 0；越界值夹取 [0,100]（黄金样本 `advance.single` 固化 130→100、-20→0、'abc'→0）。
7. **被动推演的关键词只截前 10 个**、`matchParallelsByKeywords` 忽略长度 <2 的关键词（V1 原样）。
