## 1. 目标 / 非目标

**目标**

1. 让「新加一个页面 / 一个控件 / 一个列表」有**唯一模板**可抄，且模板本身可被检查；
2. 把**既有约定**（点击不闪、滚动保持、提示言简意赅、范围型控件、异常提示、Markdown 注入体）固化为**规范条目**，避免后续版本反复回归；
3. 明确**组件边界**：哪些类名是公共组件（改动需评估全站），哪些是页面私有（可自由改）；
4. 明确**交互契约**：`input`（预览）vs `change`（提交）、拖动联动、危险操作确认、失败提示分级；
5. 给出**可机械化的检查清单**（§9），并建议新增门禁脚本（Q13）。

**非目标（明确不做）**

| # | 不做 | 原因 |
| --- | --- | --- |
| N1 | 不引入 UI 框架 / 构建步骤 | 仓库是**无构建**扩展（源码即发布物，`开发守则.md` §4） |
| N2 | 不做视觉改版（配色 / 字号 / 间距的重新设计） | 本次只**统一**既有形态；视觉调整属另一个议题（若要做，需另立设计稿） |
| N3 | 不改移动端断点数值 | 现状已有三档媒体查询（`style.css:108-134`），本稿只把它们写入规范 |
| N4 | 不重构 `ui/panel.js`（2647 行）的文件拆分 | 属实现层重构，风险大且与「规范」无关；本稿只约束**对外契约** |
| N5 | 不引入 i18n 扩充（仍为 zh-CN / en 双语词条） | 现状 54 条 × 2 语言（`i18n/`），本稿只要求**新增界面文案口径统一** |

| 机制 | 事实 | 证据 |
| --- | --- | --- |
| 动作分发 | 统一 `data-ftt-action` + 事件委托；未知动作如实失败（`ok:false`） | `ui/panel.js#panelAction` / 委托分支 |

## 3. 页面规范（三类骨架）

### 3.1 通用骨架（所有页面）

```text
[分页/子页标题]               ← .ftt-sec-title（可带 .ftt-muted 补充）
[一句话短提示]                ← shortHintHtml（≤ 40 字，v2.57.0 口径）
[主体：控件 / 列表 / 卡片]
[ⓘ 说明（可选，默认折叠）]      ← hintDetailsHtml + paramListHtml
```

**必备要素**（缺一即视为不规范，§9 可查）：

| # | 要素 | 口径 |
| --- | --- | --- |
| E1 | **空态** | 列表/容器为空时给 `.ftt-empty` 文案（写清「为什么空 + 下一步做什么」，如「点「🔧 修复物品」可自动补齐」） |
| E2 | **数量口径** | 列表页顶部或统计行给出「共 N 条 / 已处理 N / 待处理 N」，与内核同源 |
| E3 | **短提示** | 每节 ≤ 1 句；详细解释进 ⓘ 折叠区（不挤占界面） |
| E4 | **危险确认** | 删除 / 清空 / 覆盖类动作必须二次确认（弹窗 confirm 或按钮二段式） |
| E5 | **失败可见** | 动作失败必须有可读反馈（面板备注 + toast；见 §5.4） |
| E6 | **忙碌态** | 长耗时动作（AI / 向量 / 批量）显示进度与可中断入口 |

### 3.2 列表页（13 分页中的 11 个维度页）

| 区块 | 结构 | 现状来源 |
| --- | --- | --- |
| 工具行 | 搜索框 + 筛选条（字段 / 排序 / 额外条件）+ 批量操作按钮 | `data-ftt-search` / `data-ftt-filter`（`ui/panel.js`） |
| 统计行 | `📚 共 N 条` + 各维度徽标 | 总览胶囊（`PANEL_TABS` + 类目统计） |
| 列表 | 每行 `.ftt-item`：标题行（`.ftt-title-row`）→ 正文/描述（`.ftt-desc`）→ 标签行（`.ftt-tags`）→ 元信息（`.ftt-meta`：日期 · 楼层 · 调用次数 · 重要度）→ 操作（`.ftt-item-ops`） | `ui/list-rows.js`（逐维行装配） |
| 分页/裁剪 | 列表按内核顺序与筛选条件；超长列表给「显示更多」或滚动容器 | 现状各页自定（**Q1**：是否统一分页步长） |
| 空态 | `.ftt-empty` + 引导动作 | 各页现有文案 |

**行内元素顺序固定**（V1 对齐）：标题 → 正文 → 标签 → 元信息 → 操作；元信息顺序 = `日期 · 类型 · 楼层 · 调用次数 · 重要度 · 位置`（`ui/list-rows.js`）。

## 4. 组件规范（结构 / 变体 / 状态 / 文案）

| 组件 | 结构（必须） | 变体 | 状态 | 文案口径 |
| --- | --- | --- | --- | --- |
| **分节标题** | `.ftt-section > .ftt-sec-title` | 带 `.ftt-muted` 补充 | —— | 标题 ≤ 12 字；补充 ≤ 20 字 |
| **短提示** | `.ftt-hint` | 警告态（含 `⚠️`） | —— | **≤ 40 字**，一句话；不写「请…注意…」套话 |
| **折叠说明** | `<details><summary>ⓘ 说明</summary>…` | 带参数清单 | 默认折叠 | 正文说明参数含义与边界；参数清单由控件 `hint` 生成 |
| **表单行** | `.ftt-field`（`label` + 控件 + `.ftt-muted`） | 范围型 / 开关 / 下拉 / 多行 | 禁用（`disabled`）灰化 | `label` 写「名称（默认 X）」；补充说明 ≤ 30 字 |
| **范围型控件** | `.ftt-field-range`（range + `output[data-ftt-*-out]` + `--ftt-range-def` + `默认 X`） | 百分比 / 比例 / 阈值 | 拖动中（只刷读数）/ 提交（`change`） | 读数带单位（`%` 或小数）；**默认值刻度必须可见** |
| **开关** | `.ftt-switch`（`input[type=checkbox]`） | —— | 开/关 | `label` 描述「开启后发生什么」 |
| **列表行** | `.ftt-item`（标题行 / 描述 / 标签 / 元信息 / 操作） | 维度行、状态行、场景树行、快照行 | 隐藏（已总结）、失效、待清理 | 元信息用 `·` 分隔；**不用中文冒号**（v2.80.0 取消「：」） |
| **按钮** | `<button type="button">` | 主操作 / 次操作 / 危险操作 | 禁用、忙碌 | 动词开头 ≤ 10 字；危险操作含明确对象（如「🗑 删除」+ 确认） |
| **徽标** | `.ftt-badge` | `--abandoned` / `--blocked` / `--immortal` | —— | 用符号 + 短词（`🪦 已去世` / `🧬 长生者` / `⚠️ 出生日期异常` / `⚠️ 超长年龄（疑长期未出场）`）；**不同语义不共用一个变体色**（已去世=红、长生者=紫、异常=黄） |
| **空态** | `.ftt-empty` | 列表空 / 搜索无结果 | —— | 「为什么空 + 下一步」两段式，≤ 40 字 |
| **确认框** | `ui/popup.js` 桥接 confirm | 删除 / 清空 / 覆盖 | 取消不产生副作用 | 标题写动作对象；正文写不可逆后果 |
| **异常提示** | `notifyHooks.toast(text, 'error')`，文案前缀 `⚠️ ` | 节流（同文案 60s）/ 强制（用户动作） | —— | 说清「哪里失败 + 怎么办」，≤ 200 字 |

**组件归属**（改动影响面，供评审用）：

| 归属 | 组件 | 改动要求 |
| --- | --- | --- |
| **公共件**（全站） | 分节标题 / 短提示 / 折叠说明 / 表单行 / 范围型 / 开关 / 按钮 / 空态 / 徽标 / 确认框 / 异常提示 | 需**全站回归**（冒烟 + 面板审计） |
| **页私有件** | 场景树行、注入自查区块、关联层面板、快照链明细、调试日志区块、货币流水行 | 改本页即可，但要遵守 §3 骨架 |

## 5. 交互契约

### 5.1 事件与提交时机

| 事件 | 允许做什么 | 禁止 |
| --- | --- | --- |
| `input`（拖动/键入中） | 只刷**读数**、做**联动预览**（如占比滚动条）；不写配置、不重绘 | 落盘、重绘、发网络请求 |
| `change`（松手/失焦） | 写配置（含夹取）→ 落盘 → 重绘 → 必要时给短备注 | 静默失败（必须给反馈） |
| `click`（`data-ftt-action`） | 交给 `panelAction` 统一分发；返回 `{ok, reason, note}` | 在委托里直接改状态（绕过 action） |
| 危险操作 `click` | 先 `confirm` → 确认后才执行；取消**不得**产生任何副作用 | 直接执行后「无法撤销」 |
| 键盘 | 输入框 `Enter` 视为 `change`；`Esc` 关闭弹窗 | 拦截浏览器默认行为（除已确认的场景） |

### 5.2 重渲染纪律（v2.80.1 起）

1. **复用同一 `.ftt-modal` 节点**，只替换内部 → 入场动画不重放（不「闪一下」）；
2. 重渲染后**恢复滚动位置**（面板 / 模态 / 内容区三处，`ui/panel.js:1222-1246`）；
3. 瞬时输入（分组名等）**不重绘**（`applySettingsControl` 的 `transient` 分支）；
4. 纯 DOM 交互（如场景树折叠）**不触发重绘**。

### 5.3 提示三级

| 级别 | 通道 | 用途 | 节流 |
| --- | --- | --- | --- |
| 行内备注 | 面板 `setNote`（顶部一行） | 动作结果摘要（「已调整占比…」） | 不节流（每次动作覆盖） |
| 短提示 | `.ftt-hint`（页面内） | 解释当前区块怎么用 | 静态 |
| 异常提示 | `⚠️` toast（`notifyError`） | 失败/异常（必须可见） | 同文案 60s；每会话 5 条；用户动作 `force` |

### 5.4 失败与错误

| 场景 | 必须 |
| --- | --- |
| 面板动作异常 | 调试日志（`kind=异常`）+ 面板备注 + **强制** `⚠️` toast |
| 动作被拒绝（`ok:false`） | 面板备注 + 节流 `⚠️` toast（如「操作未完成：未知维度」） |
| 内核 `warn(...)` | 调试日志 + 节流 `⚠️` toast（v2.87.0：此前被静默丢弃） |
| AI / 网络失败 | 如实回报原因（不吞异常）；不阻塞聊天（B1） |

### 5.5 忙碌与取消

长耗时动作（批量摘要 / 修复 / 推演 / 向量测试）必须：① 头部忙状态 + 进度文案；② 提供**中断**入口；③ 结束后恢复原状态并给结果摘要。

## 6. 文案规范

| 类型 | 口径 | 例 |
| --- | --- | --- |
| 短提示 | ≤ 40 字，一句话，说明「做什么 / 什么时候用」 | 「按剧情日期老化；没有剧情时钟就不会衰退。」 |
| 控件 `label` | 「名称（默认 X）」；计数类写单位 | 「窗口半径 R（前后各 R 条，含自身 → 窗口 2R+1 条；默认 10）」 |
| 备注（`setNote`） | 「已+动词+对象（结果）」 | 「已调整「情节」占比为 3%，其余按比例联动（合计 100%）；保底已下移：情节 5000→90」 |
| 空态 | 「为什么空 + 下一步」 | 「（无标签 · 点「🔧 修复物品」可自动补齐 3-5 个）」 |
| 错误 | 「哪里失败 + 怎么办」 | 「聊天尚未就绪，已处理楼层台账暂未刷新（不影响已分析记录）」 |
| 危险确认 | 「动作 + 对象 + 不可逆后果」 | 「删除该条目？删除后不会自动恢复（跨端也不会复活）。」 |
| **状态说明**（v3.20.1 新增） | **写成模式、不写成进度**：`已开启 / 已关闭 / 已停用`（必要时给「怎么改」），**禁用「…中」**；且**必须与开关联动**（关掉后不得仍写「自动同步」） | 「⚙️ 自动同步：**已开启**（日期/时间/地点只取本聊天的最新情节…）」 |

**禁用**：中文全角冒号充当字段分隔（v2.80.0 已取消）；裸 `**加粗**` 出现在 HTML（用 `<b>`，`ui-wording` 门禁）；未说明的英文缩写；
**「…中」这类进度腔描述常驻状态**（v3.20.1 实证：`自动同步中` 被读成「正在同步（卡住）」，且不看开关就说「同步中」—— 状态标签必须能被开关证伪）。

## 结论变更（v3.1.0）

**C1 的判据随渲染架构更新**（依据 `docs/D13` S1 / `docs/history/P10c9`）：面板渲染自 v3.1.0 起是
**单一构建路径**（一次渲染只构建当前分页一遍，动作返回值复用同一次结果），原先「面板 HTML + 模态 HTML 各调一次
`ensureButtonTypes`」的两条路径已合并。因此 `scripts/check-ui-spec.js` 的 C1 判据改为：
机制存在 + **≥1 处实际应用且覆盖模态内部构建**（`panelModalInnerHtml()` / `panelHtml(`）+ DOM 层兜底 `hardenButtonTypes` 存在。
规范**语义不变**：所有渲染产物仍必须经集中机制补 `type="button"`，只是不再要求两条重复路径。
