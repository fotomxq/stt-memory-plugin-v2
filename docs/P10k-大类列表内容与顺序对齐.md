## 1. 问题定性

V2 此前**所有维度共用一句摘要**：`entrySummary()`（`title → name → content → text → subject`，截 90 字）+ 一行
`date · 调用N次 · 归属`，排序也用「容器倒序」（`consoleList().reverse()`）。于是：

| 缺口 | 具体表现 |
| --- | --- |
| **各维度自有字段全部缺失** | 情节：类型 / `N-M楼` / 有效性（🔒已失效 ⚠️不确定）/ 标签组 / 重要度 / 涉及地点；记忆：知情徽标（公开事实/事实/共同/私密）/ 分类 / 概念引用 / 关联摘要与差异行；角色：档案正文（性别/出生/年龄/种族/…/承诺）与「已知记忆·参与计划·在查悬念」下钻；物品：`×数量`/所在地/携带中/无标签提示；货币：额度单位 / 归属徽标 / ⭐已标定 / 收支流水（最近 4 笔）；传言：阶段 / 客观性 / 发酵度 / 传播者 / 载体 / 谱系 / 进行中 / 传导链路；计划与悬念：阶段角标 / 时间·角色·目标·揭晓 / 进度与步骤 / 线索与揭晓条件；概念：来源 / 被记忆引用；平行：卦象 / 📅📍角色 / 源起 / 目标概率 / 新鲜度 / 相关角色 / 来源·预演·约束 |
| **顺序不是 V1 的** | V1 各页用 `sortRecent`（剧情日期倒序 → 无日期靠后 → `floorEnd` 倒序）；状态页组内按 `floorEnd` 倒序；计划/悬念**只列 `status==='open'`**；情节默认**隐藏已总结**项 |
| **场景页少了整棵树** | V1 是「按全部 `pathArr` 聚合的树」（父级缺记录→灰色虚节点、`▾` 折叠、**当前位置高亮**、叶子才挂操作）；V2 是平铺列表 |

## 2. 做法

- **行渲染**：新增 `ui/list-rows.js`，按 V1 各维度行渲染器**逐条对齐字段与先后顺序**（源码行号写在该文件头注：
  atoms 23932 / memories 24114 / snapshots 24040 / items 24151 / currencies 24197 / rumors 24235 /
  plans 24300 / suspense 24336 / concepts 24529 / parallels 24489 / states 24008）。
  行序规则（V1 原样）：情节 `标题 → 正文 → 标签 → 时间行`（无独立标题时 `正文 → 标签 → 时间行`）；
  记忆 `徽标+归属 → 标题 → 描述 → 标签 → 关联摘要 → 差异 → 时间行`；平行**九行**结构（标题+卦象 → 时间/地点/角色 →
  描述 → 源起 → 目标概率 → 统计 → 标签 → 相关角色 → 来源/预演/约束）。
- **排序与可见范围**：`core/clock.js` 新增 `sortRecentByStoryDate()`（V1 `sortRecent` 逐字）；
  `ui/panel.js#listOf()` 改为「先按 V1 规则筛可见（情节隐藏已总结、计划/悬念只留 open）→ 排序 → 搜索 → 截断」。
- **下钻与引用**：`ui/list-rows.js` 实现 V1 `relCharacterDrillHtml`（角色页「🧠 已知 / 📋 参与计划 / 🔍 在查悬念」）
  与 `relConceptRefHtml`（概念页「← 被记忆引用 N 条」）；`relHowLabelOf` 由 `core/model/rel.js` 导出。
- **重要度**：`core/recall.js` 补 `calcImportance` / `importancePct`（V1 `clamp(base + uses × per, 0, 1)`）。
- **场景树**：新增 `ui/scene-tree.js`，移植 V1 `scenesHtml()`（同路径去重、虚节点、路径化 `data-ftt-scene-node`、
  `data-ftt-scene-children` + `data-ftt-scene-caret-for` 折叠、当前位置连续子序列匹配高亮、叶子操作 `➕子/✏️/🗑`）；
  面板点击委托新增**折叠分支**（点 `▾` 纯 DOM 切显隐，**不触发重绘** —— V1 v1.206 26185 同款）。
- **关系入口去重**：记忆/平行/计划/悬念的 `🔗 关联` 由行内按 V1 位置输出，面板不再追加第二个。

## 3. 验证（oracle 逐条比对）

- `tests/fixtures/v1-golden-list-rows.json`：生成器 `gen-v1-golden-list-rows.cjs`（真实 V1 v1.206，固定样本 15 行 × 11 维度）
  取每行的**正文文本序列**（平衡切片取整行 → 去掉全部按钮 → 去标签 → 分词；现实墙钟归一 `<WALL>`），
  **两次运行逐字节一致**。
- `tests/unit/list-rows-golden.test.js`（14 断言）：
  - **V 组**逐维度逐条目比对「字段集合 + 先后顺序」——两端用**同一取法**，任何字段增删或换序都会红；
  - **O 组**排序（日期倒序 / 无日期靠后 / `floorEnd` 倒序）；**S 组**可见范围（计划悬念只列 open、情节隐藏已总结）；
  - **T 组**场景树（聚合虚节点、📍 当前位置高亮、折叠标记成对、搜索保留祖先路径）。
- 冒烟 **AW1**：真实面板 + 真实点击 —— 情节行含 `· 主线 ·`/`3-5楼`/`重要度24%`/`#码头`/涉及地点；场景页为聚合树且
  点 `▾` 后子树 `display:none`、三角变 `▸`（`tests/harness/st-mock.js` 因此补了**最小 `querySelector`**：
  仅支持 `[attr="value"]`，按解码值或实体转义值匹配）。

**修掉的自身缺陷**：① 情节时间行漏了 V1 的 `📅` 前缀；② 计划/悬念的阶段角标未按 V1 走 `normPhase` 判空
（无阶段时多出一个「进行中」角标）；③ 场景页早期实现在 `dimBodyList` 里**提前 return**，把「新增/编辑子场景」的
编辑器挤掉了（`panel.test.js` B2-2 抓到）。

## 4. 与 V1 的差异（仅 DOM 口径，内容一致）

1. 操作按钮用 V2 的 `data-ftt-action` + `data-id`（V1 用 `data-ftt-kind/-id`）；多选复选框沿用 V2 的 `data-ftt-select`。
2. 行容器仍为 V2 的 `.ftt-item.ftt-inline`（主体 `.ftt-grow` + 右侧操作），V1 用 `.ftt-item-main` + `.ftt-item-ops`。
3. 计划与悬念在 V2 是**同页两段**（`📌 计划` 段 + `<h4>悬念</h4>` 段），V1 是同页两个子标签 —— 行内容与顺序一致。

## 5. 未纳入本批（如实登记）

- 计划/悬念「标记已完成（✅，原文删除留统计）」按钮 V2 仍缺（V1 `closeEntry`）；本批只对齐**列表内容与顺序**。
- 排序下拉（最新/最早/重要度/调用次数）与逐页筛选器（V1 `pageSortItems` / `pageExtraMatch`）V2 未实现。
