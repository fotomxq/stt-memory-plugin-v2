## 0. 一页摘要

用户报告「不同存档的内容出现了交叉」。本地端只读核对（`ftt.*` 调试桥同源口径 + 只读扫描 extension-store）：

| 取证 | 读数 | 含义 |
| --- | --- | --- |
| 当前聊天 | 「书籍 - 2026-11-16@18h10m54s」= **全新 1 楼**，`chatKey=8048378324082269` | 用户在看的是**空白新存档** |
| 同角色状态 | `atoms` 229 = 本档 0 / **旧版遗留 26** / **别档 203**；`ledger` 912 = 别档 623 / 无归属 289；`deals` 5 = **全部别档**；`snapshots` 89 = 无归属 71 | 一次打开新档，**539 条无归属旧数据可见**，货币页还列出 **912 笔流水** |
| 楼层位置 | **773 条**条目的 `floorNowHash` 被写成当前聊天**第 0 楼**的哈希（各档开场白相同 → 哈希必然相同），部分被写 `originGone` | 别档条目的位置/「原文已移除」被本档收缩**洗白** |
| 台账 | `processedFloors` 在收缩时**整批重建**（含别档标记） | 切回别档时「已分析楼层」成片复现 |

结论：v3.52.7 的「读侧分区」只覆盖了**列表/计数/注入/裁剪**，且把 `legacy`（无归属）**保留可见**；
真实数据里 `legacy` 恰恰是**别条聊天**的旧数据 → 在每条聊天里都可见 = 「内容交叉」。
另有两条**未分档的读写路径**：货币流水/长期收支的读接口、以及楼层收缩（把别档条目当本档重算）。

## 1. 目标 / 非目标

### 1.1 目标

1. `legacy`（无 `chatKey` 的升级前历史数据）**默认隐藏**（与 `other` 同档不可见：不进列表、不进注入、不参与上限裁剪与低使用遗忘）；横幅**如实计数**并给「👁 显示旧存档数据」**显式开关**（仅本次会话，不落盘）+「↪ 归入当前」（二次确认）；
2. **货币流水 / 长期收支按存档过滤**：`ledgerVisible()` / `dealVisible()` 作为唯一读口径（列表、汇总、对账、触发器、修复候选、删除守卫）；
3. **楼层收缩只维护本档**：`handleFloorShrink` 只重建/裁剪**本档**台账标记，别档标记原样保留；条目只处理**本档**（`chatKey === 当前档`），别档与无归属一律不动；`0/0` 区间不参与哈希定位；
4. **归属证据②加固**：`floorFingerprintHit` 不再用「第 0 楼 / 位置未知」作证据（各档共享开场白，无法辨位）。

### 1.2 非目标

* **N1 不删任何数据**（`docs/D28` 纪律）：旧存档遗留只是**默认隐藏**，可显示、可归入；别档条目不删不改；
* **N2 不改物理存储骨架**：仍「每个角色一份」（`scope: char:xxxx`），不迁移服务端文件、不改 `DATA_VERSION`（零迁移）；
* **N3 不自动归档**：`legacy` 归入当前存档仍是**显式确认**动作（`archiveAdoptAuto` 语义不变）；
* **N4 不改 V1 取文/哈希口径**：`floorStableText` / `hashFloorText` / `chatKey` 不在内容哈希内。

## 3. 方案

### 3.1 读侧：旧存档遗留默认隐藏（`core/archive-scope.js`）

```text
archiveVisible(x):
  tier = archiveTierOf(x)          # current / legacy / other / all
  other  → false
  legacy → legacyVisible           # 新增：会话级开关，默认 false
  else   → true                    # current / all（fail-open）
toggleLegacyVisible(): 翻转开关，返回 {on, note}（面板动作 `archiveReveal` 与横幅共用）
```

横幅（`ui/archive-banner.js`）：
`📂 当前存档 <短键> ｜ 本档 N 条 ｜ 旧存档遗留 L 条（默认隐藏）｜ 其它存档 M 条（已隐藏…）` + `👁 显示旧存档数据`；显示后改文案为「已显示·打标」并出现 `↪ 把旧存档归入当前`。

### 3.2 货币流水 / 长期收支分档

| 模块 | 改动 |
| --- | --- |
| `core/model/ledger.js` | 新增 `ledgerVisible()`（= `filterArchiveVisible(ledgerList())`，只读副本）；`ledgerOf` / `ledgerSum` / `reconcileLedger`（只对可见货币对账）/ `orphanLedgerEntries` 改用之；`deleteLedgerEntry` 增加「别档/隐藏流水不可删」守卫 |
| `core/model/deal.js` | 新增 `dealVisible()`；`findDeal` 只在可见范围查找 |
| `core/deal-triggers.js` / `core/deal-repair.js` | 候选/触发只对 `dealVisible()`（别档标的物不触发、不被修复） |
| `ui/money-tabs.js` | 三个子页的计数与列表改用 `ledgerVisible()` / `dealVisible()` |

写路径仍用 `ledgerList()` / `dealList()`（身份语义：`deleteLedgerEntry` / 级联删除依赖 `state.ledger` 引用）。

### 3.3 楼层收缩只维护本档（`host/floors.js#handleFloorShrink`）

1. `curKey = currentChatMarkKey()`；
2. 台账重建：`keep = 别档标记（原样保留，含 at/ck） + 重建出的本档标记`；`hist`（归位哈希集）与 `metaByHash2`（继承归属/时刻）只收**本档**标记；留痕只针对**本档**被丢弃的标记；
3. `preLedger` / `oldHashAt`（台账代理）只取**本档**标记 —— 别档标记的「楼层→哈希」绝不能当本档代理；
4. 条目处理：`curKey` 已知时**只处理 `chatKey === curKey` 的条目**；别档与无归属（`legacy`）一律不动（判不出来就不改行为）；
5. `originFloorRange` 返回 `0/0` 视为「区间未知」→ 不参与哈希定位；分支 ④ 亦不写 `0/0` 位置的指纹。

### 3.4 归属证据②加固（`core/chat-scope.js#floorFingerprintHit`）

要求 `plotPositionOf(entry) > 0`（第 0 楼是各档共享开场白，哈希必然相同）且 `floorNowHash` 非空；
真实位置（>0 楼）且指纹一致时**仍然认**（不收紧正常路径）。

### 3.6 回退

* 旧档隐藏：`archiveVisible` 的 `legacy` 分支改回 `true` 即回到「可见+打标」；或只把 banner 的开关默认打开。
* 流水/标的物分档：把 `ledgerOf`/`ledgerSum`/`money-tabs` 改回 `ledgerList`/`dealList`。
* 收缩隔离：去掉 `mapEntry` 的档位判断与 `0/0` 跳过、台账重建恢复整批。
数据零迁移，回退不影响存量。

## 4. 风险与对策

| # | 风险 | 对策 |
| --- | --- | --- |
| R1 | 隐藏 `legacy` 让「整库都是旧版数据」的用户看着像空档 | 横幅**如实计数** + 一键显示（会话级）；`archiveStats` 计数不归零；归入仍是显式动作 |
| R2 | 隐藏后注入少了一批旧记忆 | 这正是隔离目标（旧档内容不应进新档注入）；显示开关只影响查看，不静默改数据 |
| R3 | `deleteLedgerEntry` 拒绝别档流水 → 用户觉得「删不掉」 | 报错文案明确「属于别的存档（已隐藏）」；切到那条存档即可删 |
| R4 | 触发器只跑本档标的物 → 别档标的物不执行 | 与「一条聊天存档一份视图」一致（别档运行状态在它自己的聊天里推进） |
| R5 | 收缩不再判无归属条目的 `originGone` → 旧档「原文已移除」不再更新 | 无归属本来就判不出所属聊天（`docs/D29` 纪律：宁可少判不误判）；本档条目的判据不受影响 |

## 5. 分阶段

单阶段（同轮）：旧档隐藏 + 横幅开关 → 流水/标的物分档 → 收缩隔离 → 证据加固 → 单测 → 文档与版本。
