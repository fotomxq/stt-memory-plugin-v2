## 1. 闭环总览（V1 `runSummaryFloor` 的 V2 版）

```text
GENERATION_ENDED / 手动命令 / FTT.analyze
   ↓ host/floors.js      取「可分析正文」：ctx.chat[i] → 稳定刷正文 → 投喂正则(applyFeedRegex) → 去占位楼
   ↓ core/prompt.js      buildSummaryPrompt(正文, dims) → [{role:'system'},{role:'user'}]（**与 V1 逐字符一致**）
   ↓ host/generation.js  ST generateRaw（systemPrompt + prompt）
   ↓ core/util.js        extractJsonObject(回复) → 归一化增量 delta
   ↓ core/ingest.js      mergeDelta(delta, {start:楼, end:楼})  → 13 类维度按 V1 口径落库
   ↓ host/floors.js      recordProcessedFloors(楼, 楼)  → state.processedFloors 台账 + 版本签名
   ↓ 内核 saveState()    经 adapters/store.js 写 localStorage / IndexedDB / 服务端文件
```

## 2. 楼层取文与判据（`host/floors.js`，V1 逐字对齐）

| 能力 | 口径 |
| --- | --- |
| `floorStableText(msg)` | 楼层内容哈希用**原始首刷** `swipes[0]`，不随选中刷/可视文本被改写而变化 |
| `assistantTextOf(msg)` | 实际分析的正文用**当前刷** `swipes[swipe_id]`，回退 `message/mes/content` |
| `collectFloorLinesInRange` | 生成 `[第N楼 用户/AI] 正文` 行，跳过隐藏楼；`aiOnly` 只取 AI 楼 |
| `floorAnalyzableText(i)` | 经 `applyFeedRegex`（黑白名单投喂正则）过滤后，**排除占位楼**（`...`/`……`/`—`/`-`/`·`）与空楼 |
| `hashFloorText(i)` | `hashText(稳定正文)`；空楼 → `''` |
| `listUnprocessedFloors` | 跳过用户楼 / 隐藏楼 / 占位楼 / **已分析且内容未变**的楼 |

### 已分析楼层台账（与 V1 存档兼容）

`state.processedFloors = [{f, h}]`（楼层 + 内容哈希，上限 5000）+ `state.processedVer = "v1.174:11n8nlu"` + `state.lastKnownFloor`。
签名 `PROCESSED_SIG = hashText('【FTT 已处理楼层哈希自检样本 v1.174】')`，与 V1 的 `hashText` 同实现故**同值**；
签名不符时按当前算法重算台账（V1 v1.170/v1.174 口径），**不会**把历史楼层判成「未分析」。
内容被改写 → 该楼重新变为「未分析」（防「改判」漏分析）。

## 4. 编排（`host/extract.js`）

| 入口 | 说明 |
| --- | --- |
| `analyzeFloor(id, opts)` | 单楼：取文 → 提示词 → AI → JSON → `mergeDelta` → 台账；返回 `{ok, added, total, chars, ms, deltaKeys}` |
| `analyzeFloors(opts)` | 批量：默认「未分析清单」，可用 `ids` / `onlyLatest` / `limit` / `dims`；**忙碌互斥**（并发调用返回 `busy`） |
| `autoExtractLatest()` | `GENERATION_ENDED` 自动路径：受 `cfg.autoExtract` 保护，取**最后一个**未分析楼层 |
| `extractStats()` / `extractSummary()` | 运行/成功/失败计数、最近原因、台账、待分析数（`/ftt`、`FTT.extractStatus()`、设置面板共用） |
| `promptToGenerateArgs(msgs)` | V1 的 messages 数组 → ST `{systemPrompt, prompt}` |
| `enabledDims()` | `cfg.dimensionEnabled`（未配置 = 全 14 维） |

**失败姿态**：`empty-floor`（无正文） / `no-generate`（宿主无 AI 能力） / `ai-error` / `no-json` / `merge-fail` / `error`
—— 一律只回报原因并计数，**不抛出、不 abort、不改 chat、不写台账**（失败楼层下次仍会出现在待分析清单）。

## 5. 入口接线

| 入口 | 用法 |
| --- | --- |
| `GENERATION_ENDED` | 生成结束 → 刷新视图 → 防抖落盘 → `runAutoExtract()`（`cfg.autoExtract` 关闭即零 AI 调用） |
| `/ftt-analyze` | 无参 = 分析未分析清单；`/ftt-analyze 12` = 指定楼层；`/ftt-analyze list` = 列出待分析 |
| `FTT.analyze({floor})` / `FTT.pendingFloors()` / `FTT.extractStatus()` | 控制台调试入口 |
| `/ftt` 状态行 | `提取：运行 N · 成功 M · 失败 K（最近原因） · 待分析 P` |
