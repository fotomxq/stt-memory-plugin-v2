## 2. 仍未对齐的那一处（本批修正 = **V1 缺陷 #4**）

`core/model/snapshot.js#stampNowForState()`（V1 v1.206 `stampNowForState`，V1 8102~8108）**在无剧情日期时回退现实墙钟**：

```js
// 改前（V1 与修正前的 V2 完全一致）
function stampNowForState() {
    const d = getStoryNow();
    if (d) return { date: clockDateTrim(d), time: state.state?.time || '' };
    const n = new Date();                       // ← 现实墙钟
    return { date: `${n.getFullYear()}-…`, time: `${…}:${…}` };
}
```

它的产物被写进**剧情时间字段**（不是记账字段）：

| 写入点 | 字段 | 语义（V1 定义） |
| --- | --- | --- |
| `core/ingest.js`（memories add） | `memories[].date` | 记忆的发生日期 → 参与**注入行**、相对时间折算、遗忘时间轴 |
| `core/ingest.js`（states add/update） | `currentStates[].updatedAt` / `.updatedAtTime` | 「状态记录的最后更新时刻」→ 参与 `recallDateNum` 与状态衰退 |
| `core/ingest.js`（state 变更史） | `history[].updatedAt` | 变更史时间 |

**实测后果（V1 oracle，本批样本 `v1-golden-clock-story-only.json` A 组）**：无剧情日期时写入一条无日期记忆 →
V1 落库 `date = <TODAY>`（现实日期）→ **注入体出现 `- [2026-09-25]记忆甲：甲在码头清点铜箱`**；
更糟的是这枚现实日期会**反向污染**「手工录入缺年份」的可用年份来源（原子数据多数派），
于是 `parseClockManualInput({date:'11月29日'})` 变成 `2026-11-29`（样本 A 组 `manualYearless` / `majorityYear` 有证据）——
即「现实年份被钉成剧情锚点」的老问题从另一条路复发。

V2 与 V1 在这一点上**逐字相同**（同一份代码），因此同样踩坑。

## 3. V2 修正（story-only）

```js
/** 无剧情日期 → 返回空（调用方据此不写）—— 现实时间只允许出现在带「现实更新」标注的 UI 与 epoch 记账字段里 */
function stampNowForState() {
    const d = getStoryNow();
    if (!d) return { date: '', time: '' };
    return { date: clockDateTrim(d), time: String((state.state && state.state.time) || '') };
}
```

配套守卫（`core/ingest.js`）——`st.date` 为空时**不写**（不写空串、也不覆盖 AI 自带值）：

```js
const st = stampNowForState(); if (st.date) { n.updatedAt = n.updatedAt || st.date; n.updatedAtTime = n.updatedAtTime || st.time; }   // states.add
const st = stampNowForState(); if (st.date) { n.updatedAt = st.date; n.updatedAtTime = st.time; }                                     // states.update
if (!n.date) { const st = stampNowForState(); if (st.date) n.date = st.date; }                                                        // memories.add（v1.63 的「补剧情日期」本意）
```

**UI 侧同时补齐 V1 v1.170 的标注口径**（V1 24508）：平行事件行渲染现实墙钟时，**必须**带「现实更新」前缀与
`📅 剧情日期` 并列区分（`ui/panel.js` 的行 meta：仅当 `updatedAt` 是 epoch 毫秒时追加 ` · 现实更新 <本地时间>`）：

```text
分支甲  1919-11-20 · 调用 2 次 · 现实更新 9/25/2026, 10:28:36 AM      ← 剧情日期与墙钟并列且已标注
分支乙  1919-11-21 · 调用 0 次                                        ← 无墙钟 → 无标注
```

## 4. 保留项（**不**属于剧情时间字段，无需修正）

| 字段 | 性质 | 说明 |
| --- | --- | --- |
| `parallels[].updatedAt` | **epoch 毫秒** | 平行事件衰退窗口（V1 明确：按**现实**更新近度做 30 天窗口；只用于排序/衰退，UI 现已标注「现实更新」） |
| `nsfw` 命中后刷新的 `updatedAt` | epoch 毫秒 | 跨端合并取较新用 |
| `state.updatedAt`（容器信封）/ `snapStore[].ts` / `clockManual.at` / 时钟追踪 `at` | epoch 毫秒 | 存档与排障记账，不参与剧情时间线 |
| 时钟日志里的 `at` / `ms` | epoch 毫秒 | 日志时间戳 |

> 已知并列事实（V1 同款、本批不动）：`recallDateNum()` 对**没有 `date` 的状态记录**会读 `updatedAt`；
> 若某条状态的 `updatedAt` 曾被写入 epoch 毫秒（v1 的若干路径如此），该条在召回评分里会被当作「极新」。
> 该现象与「剧情时钟取真实日期」无关（不写进注入正文），已在此登记备查。
