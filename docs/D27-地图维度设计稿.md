## 0. 一页摘要

**新增第 15 个维度 `maps`（地图）**，在既有**场所数据（`scenes`）**之上做**空间结构化**：把"场所 → 房间 → 陈设"三级**分层**表达为同一维度的**空间单元**，并把"地点之间怎么走"表达为同维度的**路径条目**。可视化只做**分层关联网图**，**不做坐标地图**。

| # | 用户要求 | 本稿结论 |
| --- | --- | --- |
| ① | 不建可视化地图，建**分层关联网图** | **非目标：不引入坐标 / 瓦片 / 寻路几何**。网图 = 空间单元为点、路径为边，按 `level` **分层展开** |
| ② | 路径的**距离 / 所需时间**，**剧情走过**才分析 | `route` 条目在 `traversed: true` 时**才**由剧情文本自动抽取 `distance` / `timeCost`，并带 `evidence`（楼层 / 情节）；未走过**默认不建**（手填须标 `inferred`） |
| ③ | **数据使用场所数据** | `place` 一律带 `sceneRef`（指向 `scenes` 条目）；**场所层级仍以 `scenes.pathArr` 为准**，地图**不重复**它的层级与非空描述 |
| ④ | 点击 → **用户输入框尾部插入套话** | 点击节点 → 尾部追加「前往〈地点〉、〈房间〉」；**能力探测 + 降级**（探不到输入框 → 复制到剪贴板 + 面板内可复制文本）。宿主输入框写入**无既有先例**，列为本稿**最高优先级前置验证**（`技-26`） |
| ⑤ | 需**穿透到房间、陈设** | `place.level = scene / room / fixture` 三级 + `parentId` 分层；UI 由场所逐层下钻 |
| ⑥ | 与场所**捆绑注入**，**禁止单独注入**；**场景注入不受约束** | 注入体小节在 `core/recall.js#buildMemoryBodyForInject` 里是**硬编码**的 → 新维度**不会自动进注入**；`maps` **不进候选池**，只在 `[场景地点]` 小节入选后**挂载**其关联片段。场景小节本身照旧独立入选、独立生效 |

**成本定性（必须先看清）**：这是**新增原子维度** —— 按 `docs/02-数据架构.md` §3.4 需要**六处接线**（常量表 → 归一化 → 内容哈希 → 瘦身白名单 → 迁移/合并 → 跨端）+ **`DATA_VERSION` 递增**，并会改动 `docs/README.md` §3 的**维度数 14 → 15**、**原子层维度数 13 → 14**（由 `scripts/check-docs-facts.js` 的 C1 逐行实测），以及面板/字段表/编辑器/提示词/测试的接入清单（`docs/04-应用架构.md` §9）。**这是本项目迄今为止最重的一条改动。**

## 3. 方案

### 3.1 定位与分层模型

**分层（`level`）四级，但只有三级属于本维度**：

| 层 | 归属 | 说明 |
| --- | --- | --- |
| 场所（场所级） | **`scenes`（既有）** | 城市 > 区域 > 建筑 / 室内 —— 以 `pathArr` 表达，**地图不重复** |
| `scene` 级 `place` | **`maps`（本稿）** | 场所在地图里的**锚点**（1:1 引用某个 `scenes` 条目），供路径挂接 |
| `room` 级 `place` | `maps` | **房间** —— ⑤ 要穿透的第一层 |
| `fixture` 级 `place` | `maps` | **陈设物件** —— ⑤ 要穿透的第二层 |

**分层关联（①）**：`place.level` + `place.parentId` 构成一棵树；`route` 构成同层的横向边。网图 = **纵向树 + 横向边**，按 `level` 分层展开（不是坐标图）。

### 3.2 数据模型（同一维度，两种 `kind`）

**`maps` 条目 A：空间单元 `kind: 'place'`**

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `level` | 是 | `scene` / `room` / `fixture` |
| `name` | 是 | 单元名（`scene` 级与 `scenes.name` 对齐） |
| `aliases` | 否 | 别名（供召回与去重） |
| `desc` | 否 | 描述；**`scene` 级留空**（以 `scenes.desc` 为准，N3） |
| `sceneRef` | 是 | 所属 **`scenes` 条目 id** —— 落实 ③「数据使用场所数据」 |
| `parentId` | 否 | 上层 `place` id（`room` → `scene` 级 place；`fixture` → `room`）；空 = 顶层 |
| 通用元字段 | —— | `floorSeen` / `floorStart` / `nsfw` 等沿用 `docs/02-数据架构.md` §1.3 的通用口径 |

- **稳定 id**：`mp_<hash(level|sceneRef|parentId|name)>` —— 满足 `02` §2 **I1「一切由 id 寻址」**；同名同父同场所 → 两端归一得到同一 id。
- **不重复描述（N3）**：`scene` 级 `place` 只做锚点；文本一律以 `scenes` 为准。

**`maps` 条目 B：路径 `kind: 'route'`**

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `fromId` / `toId` | 是 | 两端 `place` id（同维度内引用） |
| `distance` | 否 | `{ value, unit, raw }` —— **规整值 + 剧情原话** |
| `timeCost` | 否 | `{ value, unit, raw }` —— 同上 |
| `traversed` | 是 | **剧情是否走过**（②的判据） |
| `evidence` | 否 | 走过的那次证据：`{ floor, atomId }` |
| `inferred` | 否 | 未走过而由用户手填 → `true`；自动分析的**恒为 false** |
| `direction` | 否 | `both`（默认，互通）/ `a-to-b` / `b-to-a`（单向：如"只能出不能进"） |

- **稳定 id**：`mr_<hash(from|to)>`（**方向无关**：`A→B` 与 `B→A` 是同一物理路径的两种方向，由 `direction` 表达；避免两条记录互相矛盾）。

### 3.4 路径的自动分析（②）

| 项 | 口径 |
| --- | --- |
| **何时建** | **仅当剧情明确走过**（`traversed: true`）：从该次经过的**正文**里抽取距离与耗时 |
| **抽什么** | `distance`：原话（"三里路""半日脚程"）→ `raw`；可规整为 `{value, unit}` 时一并给出。`timeCost`：同理（"一盏茶""走了两个时辰"） |
| **不猜** | 抽不到就**留空**，**不估算**（`null` 保持 `null`）；不得用现实世界常识替代剧情原话 |
| **护栏** | ① **未走过默认不建 `route`**；② 用户手填必须标 `inferred: true`；③ 每条自动分析**必须带 `evidence`**（楼层 / 情节 id），可回溯 |
| **时间基准** | 若涉及"多久之前走过"，一律用**剧情时间**（与 `docs/D18` §4 / `业-6` 一致），不用现实时间 |
| **重复走过** | 同一对地点**只保留一条** `route`（同 id）；新一次走过**更新** `evidence` 与（若更具体）`distance`/`timeCost`；**不累加** |

### 3.5 捆绑注入（⑥）—— 精确落点

| 项 | 口径 |
| --- | --- |
| **为什么天然满足"禁止单独注入"** | 注入体小节是**硬编码**的（K2）→ 新增 `maps` 维度**不会**自动出现在注入体里 |
| **仍要显式保证** | ① `maps` **不进**召回候选池（不参与 `docs/D25` 之外的任何择优）；② 在 `core/recall.js#buildMemoryBodyForInject` 的 `[场景地点]` 小节构建处（K3）**追加**地图片段；③ **不新增** `[地图]` 小节 |
| **挂载规则** | 场景小节入选 → 取该场景 `sceneRef` 下的 `place` 树（`scene` → `room` → `fixture`，**按层、有上限**）与两端都在该场景内的 `route`，拼成该小节的**子块** |
| **继承场景的命运** | `[场景地点]` 的默认分值 0.3（K4）→ **场景不入选则地图也不注入** —— 这正是"捆绑"的语义 |
| **场景不受约束** | `scenes` 的注入口径（入选、文案、上限）**一律不变**（N4）；地图缺失时场景小节照旧输出 |
| **文本卫生** | 子块走既有 `normText` 与预算口径（`charBudget`）；**不得**因地图撑爆预算而挤掉场景本身 |
| **可观测** | 注入自查里如实列出"本次地图子块 N 条（或：未注入，因场景未入选）" |

### 3.6 交互套话（④）

| 项 | 口径 |
| --- | --- |
| **触发** | 用户在网图/树里**点击**某个 `place`（场所 / 房间 / 陈设） |
| **动作** | 在**用户输入框尾部追加**套话：`前往〈地点〉、〈房间〉`（层级深时展开为「前往〈场所〉的〈房间〉」）；**绝不覆盖或改写**用户已输入的内容 |
| **模板** | 套话文案**可配置**（新增提示词模板或设定项）→ 若新增模板，`README` §3 的「提示词模板数」需同步 |
| **能力探测** | 优先取宿主输入框（同页面 DOM，属 `ui/` 层，`core/` 不得碰）；**无既有先例**（K9）→ 必须先验证 |
| **降级（对齐 `03` §4 的既有姿态）** | 探不到输入框 → ① 复制到剪贴板；② 面板内显示可复制文本并提示"请手动粘贴"；**如实说明原因，不静默失败** |
| **点击不产生数据** | 单纯插入文本**不写**任何记忆数据（避免"点了就落库"）；若要记录"去过"，走正常提取 |

### 3.7 UI 与三级穿透（①⑤）

| 项 | 口径 |
| --- | --- |
| **落点** | **场景分页内**（不新开面板分页，避免动 `README` §3 的「面板分页数 13」）；采用与"情节 / 分段总结"同款的**双子标签**（场景 | 地图） |
| **呈现** | **分层关联网图**：按 `level` 分层展开的节点 + `route` 边；**不做坐标定位**（N2）。带"剧情走过"的边与"未走过"的边**视觉可区分**（`traversed` / `inferred`） |

## 5. 风险与对策

| # | 风险 | 对策 |
