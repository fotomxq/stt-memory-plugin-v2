## 0. 一页摘要

**用户看到的**：点一次「🧩 生成分段总结」，插件向 AI 提交了**远超预期**的数据 —— 用户认为「要统计的 30 个情节不可能这么大」。

**核对结论（只读，真实代码路径，非复刻）**：

| 面 | 实测 |
| --- | --- |
| 单条情节正文 | 均值 ~236 字符 · 最长 306 · >1KB **0 条** → **上限 300 的截断生效，单条没问题** |
| 批（旧口径） | 30 条/批 → **28 批**；最重一批 **11,275 字符**；全部批次合计 **266,323 字符** |
| **一次点击**（旧默认） | **12 次请求 · 103,747 字符**（= 360 条情节） |

**判断**：锅不在"每条"，在**"批"这一层没有体量上界** —— ① 只按**条数**切批（无字符预算）；② 一次点击最多 **12 批**；
③ `plotSegmentIncremental` **默认关**（每次全量重跑，等于把整库反复提交）。用户口中的「30 个情节」正对应**一批**。

## 1. 目标 / 非目标

### 1.1 目标

| # | 目标 | 判据 |
| --- | --- | --- |
| G1 | **一次点击只提交一批**（用户预期量级） | `cfg.plotSegmentMaxBatches` 默认 **1**；实测一次点击 1 次请求 |
| G2 | 每批有**字符预算**（与条数取先到者） | `cfg.plotSegmentMaxChars` 默认 **8000**；`batch.chars` 记账；预算 0 = 关 |

## 3. 方案

### 3.1 三条上界（可配置）

| 键 | 默认 | 范围 | 语义 |
| --- | --- | --- | --- |
| `plotSegmentMaxBatches` | **1** | 1–40 | 一次点击最多提交几批（余下可再点继续） |
| `plotSegmentMaxChars` | **8000** | 500–60000（0 = 关） | 每批字符预算；与条数**取先到者**；**软上界**：装到超预算为止（至少 1 条） |
| `plotSegmentIncremental` | **true**（默认值偏离 V1，已登记 `DEVIATED_KEYS`） | 布尔 | 只整理尚未被现有段落覆盖的批次 |

### 3.2 口径单源与读数

- `plotSegmentLineText(a)`：一条情节进提示词后的**正文行**（正文 ≤300 + 标题 / 角色 / 地点 / 楼层）；
- `plotSegmentLineCost(a)` = 行文本长度 + 1（换行）→ 切批预算与 `batch.chars` 都用它；
- `plotSegmentPlan()` 增补 `chars`（Σ 行成本）/ `batchAtoms` / `batchChars`；每批带 `chars`；
- **预告是下界**：真实 user 段 = 行成本 + 批头（待整理/时间跨度）+ 【输出要求】固定段（实测差 < 900 字符）。

### 3.3 收敛修复（`applyPlotSegmentResult`）

命中「同时间范围」时：把本批 `ids` **并入**该段 `atomIds`（并集、只增不减），同步 `atomCount` 与楼层区间，刷新 `updatedAt`；
**段的正文与时间范围仍不被改写**（保护手动编辑的口径不变），`out.ids` 仍只记"本次新增段"（返回结构逐字不变）。

### 3.4 界面（C11：新功能落新模块）

`ui/plot-segment-forecast.js#plotSegmentForecastHtml()` —— 分段总结子页顶部的**提交前预告行**；
`ui/panel.js` 只留**一行调用**（体量棘轮：直接内联会 +45 > +40）。

## 5. 风险与对策

| # | 风险 | 对策 |
| --- | --- | --- |
| R1 | 一次一批 → 大库要点很多次 | 预告行写明"共 K 批 / 余下可再点继续"；想快可把 `plotSegmentMaxBatches` 调大（设定页可改） |
| R2 | 字符预算是**软上界**，单批可能超一点 | 界面写「每批 ≤ N 条 / ≤ M 字符」；实测最重一批 9,493（超 ≤1 条成本） |
| R3 | 预告与实际不符（两套口径） | 预告与切批**共用** `plotSegmentLineText()`；Q4 断言两侧同口径（差值 = 固定开销 < 900） |
| R4 | 并入 ids 会不会"吃掉"新内容 | 只并入 **id 列表与楼层区间**，正文/时间范围不改写；段落只增不减的纪律不变 |
| R5 | 默认值改动触碰 V1 平价 | `plotSegmentIncremental` 登记 `DEVIATED_KEYS`；两个新键进 V2 专有白名单；`runAll/runSelected` 投影两侧剥掉被并集改动的 5 字段；`runIncremental` 黄金期望显式改写（其原值恰好编码了本缺陷） |
| R6 | 大文件体量棘轮 | 预告落新模块，`ui/panel.js` 一行接线（实测回到 +40 以内） |
