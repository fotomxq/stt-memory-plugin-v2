## 2. 与 V1 的差异（逐条明示）

1. **AI 通道**：V1 自建 OpenAI 兼容请求（`callChatCompletion`，含 `apiTemperature`/`apiMaxTokens`/`apiTopP`）；V2 统一走注入钩子 `core/ai-hooks.js#aiCallText`（酒馆 `generateRaw`），因此这三个 API 参数**不设设定页控件**（避免做出不生效的假控件），V2 的采样参数由酒馆预设控制。
2. **任务管线 UI 未移植**：V1 的 `pipeStart`/`pipeUpdate`/`pipeEnd`/`abortTick`/`newTaskStart`/`renderPanel` 在 V2 不存在；互斥改为 `aiBusy()`（等价 V1 `busy.repair` + 摘要/压缩/推演/推进/同步占用），重绘由 UI 层负责，AI 不可用时如实回报。
3. **本批只交付记忆域的「应用层」**：概念 / 物品 / 悬念三域的 spec 已完整移植（`groupPick` 的通用输入），但 `conceptMergeExact` / `applyConceptMergeGroups` / `runConceptRepair`、`applyItemMergeGroups` / `runItemRepair`、`applySuspenseMergeGroups` / `runPlanSuspRepair` 及场景/角色/状态修复属**后续批次**（B8-6c-2~4），本批不含其 UI 按钮。
4. **设定页控件补齐为 V2 自查发现**：V1 那 22 个控件是手写 `<div class="ftt-field">…<input data-ftt-cfg="…">`，B4 的自动提取只覆盖 `f(...)`/`switchField(...)`，故此前 V2 漏采；本次按 V1 源码逐键补回（同批交付，属「13 组设定子页」对齐的一部分）。
5. **`cfg.dimensionGrouping`（V1「独立分组/各维度单独选预设并行请求」）暂无实现**：V2 配置已含该键，但全仓无引用；缺的是**功能**而非控件，需单独立项（core 提取管线 + 进度 + 控件），**不设假控件**。
6. **关联重挂的既有怪癖原样保留**：`retargetRelRefs` 只在被重挂行之间比可靠度，目标条目既有行会被顶掉 —— 与 V1 逐字节一致（黄金样本已固化），V2 不做「顺手修正」。

7. **通知/日志的 V2 适配**：`notify` 统一为 `notify(kind, title, text)` 并走 `notifyHooks.toast`（与 `core/repair.js` 同款写法）；V1 `notify('repair', …)` 的 toastr 类型是 `warning`，V2 取等价 `'warning'`（黄金样本比对时做 kind 映射，**文本逐字符一致**）。`dbgLog` 类别沿用 V1 的 `'摘要'`（V2 `core/repair.js` 用 `'修复'`，故记忆修复日志在 V2 内与「数据修复」日志不同分组 —— V1 原样）。
8. **`runMemoryRepair(opts)` 增设可选 `opts.aiText` 注入点**（与 `runRepair` / `runClockRepair` 同约定），供测试显式提供 AI 返回；缺省仍走 `aiCallText`。
9. **按钮样式与位置的非逐像素差异**：记忆页按钮 class 用 `ftt-btn ftt-sm`（V2 工具栏约定）而非 V1 的 `ftt-btn`；位置在 V2 的维度工具栏内（V1 在分类统计行）；**文案与 title 逐字对齐**，显隐条件同 V1（无记忆不显示）。
10. **`state.repairCursor` 不在 V2 `emptyState()` 内**（靠 `migrateState` 的 `OBJ_KEYS` 兜底），`groupPick` 已用 `|| {}` 防御；宿主端到端（真实角色切换）未单独验证。
11. **`newTaskStart`（V1 中断标志复位）未移植** —— 因此「AI 中断后立即再次修复」在 V2 的行为未验证（V2 无任务管线 UI，中断语义不存在）。
12. **黄金样本内的数值只对各自场景有效**：测试用例 H9-B/C 的文本与队长独立 oracle 的样例不同（bigram 相似度 0.778 / 0.125 对 0.818 / 0.1），**语义一致但数值不可互相引用**；fixture 固化的是测试自身 oracle 的取值。
