## 1. 覆盖范围（V1 `src/modules/05-记忆状态与存储抽象.js` 的 `storageProviders.worldbook` + `buildWorldbookKeys` + `scheduleWorldbookSync`）

| V1 能力 | V2 落点 | 语义（V1 原样） |
| --- | --- | --- |
| 词条构建（Markdown 分层） | `core/worldbook.js#buildWorldbookEntries` | 类目常驻词条（`# 类目` + `- 原子标题` 清单，`strategy.type='constant'`、`keys=[]`）在前，该类目原子词条（`## 标题` + 正文，`strategy.type=cfg.storage.worldbookMode`、`keys=原子真实标签`）在后；空类目不建词条；书内顺序即层级顺序；全量重建无冗余 |

| 短标题 | 同上（`shortTitle`） | 空白折叠为单空格；超过上限（词条名/类目名 40、类目 kind 20、atomContent 标题 48）→ 截到 `max-1` 并加 `…`；`max` 下限 8 |

## 2. 本批交付边界（**未接线项明示**）

本批交付**内核 + 宿主通道**；以下项目**未实现/待接线**（共享文件 `ui/panel.js`、`ui/settings-pages.js`、
`index.js`、`devtools.js`、`tests/smoke-test.js` 在本批冻结，由队长在共享文件空闲后安排）：

1. **面板动作 `worldbookRefresh`**：V1 设定页按钮 `<button data-ftt-action="worldbookRefresh">📚 刷新世界书列表</button>` 与动作分发（更新下拉 + `fillWorldbookSelect()`）**未接线**。本批只提供 `host/worldbook.js#refreshWorldbookNames()` / `worldbookNames()` 两个数据出口。
2. **`FTT.*` 入口**：`worldbookEntries` / `worldbookWrite` / `worldbookSync` / `worldbookSyncState` / `refreshWorldbookNames` 等**未挂**到 `index.js` / `devtools.js`。
3. **启动对账后的第二次同步**：V1 在存储启动对账（`storageBootstrap`）收尾也会 `scheduleWorldbookSync()`；V2 本批只接了保存流水线，启动对账路径（`adapters/sync.js`）**未接**。
4. **ST 原生世界书接口转换层未实现**：P0 已确证 ST 原生有 `loadWorldInfo` / `saveWorldInfo` / `getWorldInfoNames`，但 V1 走的是**酒馆助手（TavernHelper）世界书 API**（`getWorldbookNames` / `getWorldbook` / `updateWorldbookWith` / `deleteWorldbookEntries` / `createWorldbookEntries`）。TH 词条格式（`name` / `strategy` / `position` / `extra`）到 ST 原生词条格式的**字段映射层 V1 不存在，本批不臆造**。因此：纯 ST 环境（未安装酒馆助手 / 拿不到 `TavernHelper`）下 `worldbookProvider.test()` 返回 `false`，写入按 V1 原样告警并静默失败 —— 这是**待接线**项，不是已实现能力。
5. **UI 渲染**：`worldbookNamesHtml()` / `fillWorldbookSelect()` / 设定页子区块联动未移植（属 UI 层）。
6. **世界书不进入 V2 的跨端读写体系**：V2 无 V1 的「存储优先级 + 写镜像」抽象，世界书天然是独立单向通道；`storageIsWriteMirror('worldbook')===false` 仅作为元数据口径保留。

## 3. 与 V1 的差异（逐条明示）

1. **ESM 化与注入视图**：`cfg` / `state` 取 `core/model/runtime.js` 注入视图，`scopeId()` 取 `core/state.js`，`activeAtoms()` 取 `core/merge.js`；V1 直接读全局 `cfg` / `state` 与 `getCurrentCharacterId()`。`cfg` 为空时 V2 以 `|| {}` 兜底（V1 会抛错），有效配置下行为逐字节一致。
2. **角色名来源**：`legacyEntryName()` 用 `identityView.characterName`（宿主注入）；V1 调 TH `getCurrentCharacterName()`。V1 的 `catch → 'FTT记忆快照'` 兜底分支在 V2 **不可达**（视图读取不抛错），保留等价语义（未注入 → `'FTT记忆快照·'`）。
3. **关联摘要行独立重写**：V2 `core/model/rel.js#relSummaryLine` **不可复用** —— 文案与行序都不同（计划/悬念输出「公开计划/公开悬念」、平行事件无 `关联：` 前缀、且按可靠度重排行；`relHowLabelOf` 未导出）。`core/worldbook.js` 因此逐字重写 V1 `relWbLine`（含 `REL_LINK_HOW_LABEL` 取值与 `links` **原序**），保证词条内容与 V1 逐字符一致。**这是本批唯一一处「复制而非复用」**，已在文件头注明。
4. **宿主函数解析**：V1 内联 `thApi(name) || getFn(name)`；V2 收敛到 `host/st-api.js#worldbookApi()`，解析口径**逐项对齐**（`test`/`read` 用 thApi→getFn 链，`write`/`remove` **只用 thApi** —— V1 原样，未放宽）。
5. **调度用注入定时器**：`timerHooks.set/clear`（V1 用全局 `setTimeout`）；宿主未注入时默认 no-op（无宿主/测试环境不后台跑）。
6. **V2 新增两个观测出口**：`worldbookSyncState()` / `worldbookResetSync()`（V1 的 `wbSyncTimer` / `wbLastSyncedAt` 是模块私有变量，测试不可观测）。**不改变写入语义**，仅供调试页/面板接线与用例隔离。
7. **`worldbookMemoryTotal()`**：V1 `totalMemoryCount()` 的逐字副本，只用于 `dbgLog('对账', { action:'世界书同步完成', entries })`；V2 同名函数在 `core/ingest.js` 未导出。
8. **数值怪癖原样保留**：`worldbookDepth: null` → `0`（`Number(null) != null` 恒真，V1 同款，不会回落 9999）；`worldbookScanDepth` 非数字 → `NaN`；概率钳制 0-100；这些都不做「顺手修正」（黄金样本已固化）。
9. **`storageEnvelope` 依赖**：同步回调重新组装信封（`core/envelope.js`，`STORAGE_ENV_VERSION` 与 V1 同为 1），因此 `updatedAt` 由 `Date.now()` 决定；测试以固定 `Date.now` 复现 V1 的 `writes` 轨迹。
10. **未接入 V1 的 `storageWriteAll` 存储循环**：V2 的保存流水线（`adapters/store.js`）与 V1 结构不同，挂钩点选在 `saveStateNow` 末尾（等价于「主存储落地后」），未改动 `adapters/sync.js`。
11. **告警可见性（宿主日志策略，未接线）**：世界书写入的告警文案与 V1 逐字一致，但 V2 生产环境的内核 `warn` 目前由 `adapters/store.js#wirePersistHooks` 置为 no-op（`warn: () => undefined`），故这些告警**不会自动出现在 toast/调试日志**中（同 V1 的 `console.warn` 口径需宿主另接）。本批不改宿主日志策略（改动会波及全部内核告警）。
12. **保存流水线的世界书挂钩为逐次调度**：V1 只在 `storageWriteAll`（常规镜像写入）末尾挂钩，V2 在每次 `saveStateNow` 末尾挂钩 —— V1 的 8s 防抖 + `updatedAt` 去重保证「未变不写」，实际写入次数一致；但若宿主关闭 `syncOnSave`，V2 仍会推送世界书（V1 在未触发镜像写入时不会），属**有意差异**（世界书是独立单向通道，不应被跨端镜像开关连坐）。
