## 0. 一页摘要

**调试面的现状 = 六块运行时读面 + 两个外部工具**（逐项测绘见 §2）：

| # | 类别 | 一句话 | 落点 |
| --- | --- | --- | --- |
| 1 | **调试页** | 9 个分节的只读查看器 | `ui/debug.js` |
| 2 | **业务调试日志** | `{at,kind,data}` 环形，最新在前 | `core/debug-log.js` · `adapters/debug-log.js` |
| 3 | **三层事件时间线** | ui / host / cmd / kernel / ai / error，带 opId 与站点 | `core/trace.js` · `adapters/trace-store.js` |
| 4 | **读取台账** | 逐次读取（来源 / 耗时 / 字节 / 命中，不含正文） | `core/read-ledger.js` |
| 5 | **管线状态** | 长任务的阶段 / token 估算 / ETA / 流式块 | `core/pipeline.js` |
| 6 | **缓冲与留痕管理页** | 本机缓冲、压缩留存、各类留痕条数与清理 | `ui/buffer-manage.js` |
| A | **本地调试桥**（外部工具） | 反向 WebSocket，插件拨出，白名单**只读**方法 | `adapters/debug-bridge.js` ↔ `tests/local/bridge.mjs` |
| B | **`window.FTT` 调试导出**（外部工具） | 只读快照 + 少量探针函数 | `devtools.js` · `ui/commands.js` |

**统一设计（§3）**：**四层模型**（采集 → 缓冲 → 出口 → 留痕）+ 五条统一口径（命名 · 开关/级别 · 上限/保留 · 脱敏 · 只读）+ **追溯六字段**（`opId` / `site` / `ver` / `at` / `window` / `cause`）。
一句话原则：**同一个读数只在一处计算，三处出口只做透传**（页面 / 调试桥 / 调试导出）。

**探针并入（§4）**：性能与卡顿探针是调试面的**第 7 类采集**，与既有六类**同层、同出口、同追溯字段**；`D28` §3.10 由此迁移过来（`D28` 只留指针），并展开为：卡顿检测 · 潜在优化清单 · 统一接口（`ftt.perf` / `ftt.perfJank` / `ftt.perfTargets` / `ftt.perfBaseline`）。

**完整性（§5）**：把**插件必要内容 12 类**逐类核对「有采集 / 有出口 / 有保留 / 缺口在哪」，并由 `技-43` 把它做成**门禁**（必要内容无出口即失败）。

## 1. 定义 · 范围 · 目标 / 非目标

### 1.1 定义（调试工具的边界与"可追溯"）

| 项 | 口径 |
| --- | --- |
| **调试工具** | 回答四类问题的**运行时只读面**：① **现在是什么状态**（配置 / 存储 / 宿主 / 数据形状）；② **刚刚发生了什么**（事件、耗时、失败原因）；③ **为什么是这个结果**（台账、取舍、跳过原因）；④ **哪里慢、该优化什么**（性能与卡顿探针）。 |
| **可追溯（本稿的硬定义）** | 一条读数必须能回答三件事，缺一即不算可追溯：**① 谁触发的**（`cause` / `opId` 链）· **② 在哪一行产生的**（`site`，`core/trace.js` 的站点字段：本仓库内第一帧 `file:line`）· **③ 属于哪一版**（`ver`）+ 采样窗口（`window`）。若要挂到待办，再加 `u`（`docs/D17` 的 `U<n>`）。 |
| **只读的判据** | 判定"某入口是只读的"不看文档措辞，看**白名单里有没有它**：调试桥只派发 `ui/debug.js#buildBridgeMethods` 登记的方法，未登记一律拒绝（`adapters/debug-bridge.js#BRIDGE_DENY_PREFIX`）；**清空型动作（`dbgClear` / `traceClear` / …）一律不进桥白名单**、也不进 `FTT.*` 的写面。 |
| **不是调试工具的东西** | **构建期脚本**（`scripts/coverage.js` · `scripts/check-ledger-sync.js` · `scripts/ledger-sync-lib.js` · `scripts/check-*.js` 门禁族）服务的是**开发流程**，不是插件运行时功能；它们出现在本文档只为**划边界**（§2 #10）。 |

### 1.2 范围

| 面 | 覆盖 | 优先级 |
| --- | --- | --- |

| **B. 外部工具** | 本地调试桥（协议 / 白名单 / 只读 / 端口与安全）· `window.FTT` 调试导出 · `/ftt` 命令 | **P0** |
| **C. 性能与卡顿探针** | 卡顿检测 · 潜在优化清单 · 统一接口（**由 `D28` §3.10 迁入并展开**） | **P0** |
| **D. 统一口径** | 命名 · 开关与级别 · 上限与保留 · 脱敏 · 只读 · 追溯六字段 · 去重与收口 | **P0** |
| **E. 完整性门禁** | 12 类必要内容的"有采集 / 有出口"自动核对 | P1 |

**明确不改**：不改数据语义与契约（`docs/D15` §3 类别①）· 不改插件行为（本稿只动"怎么看"，不动"怎么跑"，`D28` A 案口径）· 不引入第三方依赖（自研 WebSocket 服务端的既有选择保持不变）· 不给调试桥加鉴权（保持"只读 + 回环默认 + 每次加载默认关"的既有安全姿态，见 Q3）。

### 1.3 目标

1. **测绘现状**：把每个功能与每个日志的**内容 / 上限 / 保留 / 出口 / 只读性 / 开关 / 缺口**逐项写清（§2）；
2. **统一模型**：四层 + 五条统一口径 + 追溯六字段，并给出"同一读数只算一次"的收口办法（§3）；
3. **探针并入并展开**：把性能/卡顿探针定位为调试面第 7 类采集，承接 `D28` §3.10 的全部结论并展开（§4）；
4. **完整性核对**：插件必要内容 12 类逐一映射到"采集点 / 出口 / 保留"，缺口立项（§5）；
5. 给出分阶段落地（§6）与风险对策（§7），并按 `开发守则.md` §2.8 立项（§10）。

### 1.4 非目标（明确不做）

- N1 **不改任何代码 / 不动版本号 / 不打 tag**（设计轮次，`开发守则.md` §1）；
- N2 **不做可视化性能仪表盘 / 图表**：只要求**如实可读**的结构化读数（延续 `D28` N5）；
- N3 **不给调试桥加写方法或鉴权**（保持只读白名单 + 回环默认；`--host 0.0.0.0` 的风险提示沿用既有权衡）；
- N4 **不合并"业务调试日志"与"事件时间线"** 两类载体（定位不同：前者记**业务动作与结果**，后者记**交互/宿主/命令/错误链路**）；只统一**命名、上限、脱敏、追溯**口径（Q6 若裁决合并再另立条目）；
- N5 **不把构建期脚本纳入运行时调试面**（§2 #10 只划边界）；
- N6 **不做远程/云端上报**（数据不出本机；桥默认回环）。

## 3. 统一设计（方案）

### 3.1 四层模型（数据流）

```text
采集（谁产生）        缓冲（内存，恒定）              出口（三处同源）           留痕（持久 + 基线）
─────────────      ───────────────────────      ──────────────────────    ─────────────────────────
业务动作/结果   →   业务调试日志 300 条       ┐
交互/宿主/命令  →   时间线 分类环形+总量 800  ├→   ① 调试页 9 分节      →   ① localStorage 摘要尾部
读取/字节/耗时  →   读取台账 240 条           ├→   ② 调试桥 白名单 50   →      （DEBUG_KEY / TRACE_KEY）
长任务阶段      →   管线状态（会话内）        ├→   ③ window.FTT / 命令  →   ② 性能与容量基线（门禁）
性能/卡顿       →   探针（只记超阈段）        ┘                               ③ 台账号（U / D22）
```

**一条原则**：**同一读数只在一处计算**；出口层只做**透传 + 格式化**，不得再算一遍（G1 的根治办法）。

### 3.2 统一命名

| 面 | 契约 |
| --- | --- |
| 调试桥方法 | `类别.对象`：`ftt.*` = **插件事实**（本插件的状态 / 数据 / 读数）· `sys.*` = **桥与环境自身**（如 `sys.info` / `sys.methods` / `sys.ping` / `sys.host` / `sys.bridgeState`）· `host.*` = **宿主能力**（经 `api.dev` 特性检测，缺失返回 `available:false`，不抛） |
| 探针方法 | 统一 `ftt.perf` 前缀：`ftt.perf` · `ftt.perfJank` · `ftt.perfTargets` · `ftt.perfBaseline`（§4.4） |
| 页面分节 | 顺序固定为：**桥 → 日志 → 时间线 → 异常 → 台账 → 体检 → 时钟 → 性能（新增）→ 主载体**；标题格式 `图标 + 名称 (+ 只读标注)` |
| 日志 `kind` | 由**枚举表**固定（现状为自由字符串，只冻结既有取值 + 新增需登记），与时间线的 `TRACE_CATS` 互不混用（N4） |
| 命令 | `/ftt` 前缀 + 与桥方法**同名**（同一读数两个入口不得异名） |

### 3.3 统一开关与级别

| 载体 | 开关 / 级别 | 默认 |
| --- | --- | --- |
| 业务调试日志 | `cfg.debugEnabled` | 开（`!== false`） |
| 事件时间线 | `cfg.debugLevel`（`error` < `warn` < `info` < `debug` < `trace`） | `debug` |
| 调试桥 | 面板开关（**不持久化**） | **关**（每次加载回到关闭） |
| 性能 / 卡顿探针 | 独立开关 + **只记超阈段** | 开（Q10 待裁决保留窗） |
| 桥的目标主机 | `bridgeHost`（默认回环） | `127.0.0.1` |

### 3.4 统一上限与保留（唯一的 CAP 汇总表）

| 载体 | 内存上限 | 持久化 | 备注 |
| --- | --- | --- | --- |
| 业务调试日志 | 300 条（`DEBUG_CAP`）· 单条 2000 字符（`DEBUG_DATA_MAX`） | 键 `SPreset_FTTMemoryDebug`（去重后降序截断） | 单条上限由 6000 降到 2000（`docs/D13` R1/Q6：避免挤占本机缓冲配额） |
| 事件时间线 | 分类环形 `TRACE_CAT_CAP`（ui 200 / host 300 / cmd 100 / kernel 100 / ai 100 / error 100）· 总量 `TRACE_TOTAL_CAP` | **摘要尾部** `TRACE_STORE_CAP` 条（键 `SPreset_FTTMemoryTrace`，**不存 detail**） | 去重 `TRACE_DEDUPE_MS`；错误附上下文窗口 `TRACE_CONTEXT_SPAN` |
| 读取台账 | `READ_LEDGER_CAP` 条 | **不落盘**（"内存恒定、不随会话增长"） | 分来源累计计数 |
| 探针 | 环形上限（建议 200，Q10） | 不落盘 | 只记超阈段 |
| 桥 | 不适用（不落盘） | —— | 每次加载重置 |
| 基线 | —— | scripts/perf-baseline.json（待建） | 只增不降棘轮（`D28` 的 `技-39`） |

**纪律**：新增长期留痕必须**同时**给出上限与保留窗；**任何缓冲都不得随会话无限增长**。

### 3.5 统一脱敏

- 沿用时间线既有规则：键名含 `key` / `password` / `secret` / `token` / `authorization` → `***`；`sk-*` 值 → `sk-***`；**长正文（prompt / content / text / messages）只记长度**（除显式 `verbose`）。
- **调试桥**：只回传**结构化读数**，**不回传正文**（既有口径：`cands` 一类只给编号与维度/字段）。
- **导出**：调试导出与调试包同样受上述规则约束。

## 4. 探针并入与展开（性能 · 卡顿 · 优化清单）

> **来源**：本节内容**由 `docs/D28` §3.10 摘出**（`D28` 只留指针），因为探针是**调试工具的一部分**。
> **定位**：探针 = 调试面的**第 7 类采集**，与既有六类（业务日志 / 时间线 / 台账 / 管线 / 体检 / 桥）**同层、同出口、同追溯六字段**。

### 4.1 卡顿检测

**时钟分层（内核保持纯净）**：

| 层 | 时钟 | 依据 |
| --- | --- | --- |
| 内核（`core/`） | **注入时钟**：`core/read-ledger.js#nowMs`（经 `hooks.now()` 取，缺省 `Date.now()`） | 内核不得直用宿主 / DOM / 高精度 API（`scripts/check-core-refs.js` 的不可用标识符口径） |
| 宿主 / UI / 适配（`host/` · `ui/` · `adapters/`） | **高精度** `performance.now()`（无则回退 `Date.now()`） | 既有先例：`ui/panel.js` |

**采集点（"已有载体 + 只加分段"）**：

| # | 采集点 | 采什么 | 载体 |
| --- | --- | --- | --- |
| 1 | 一次动作的阶段拆分 | 保存 8 步 · 修复（闸门 + 第①段 9 步 + 第②段 + 第③段 3 步 + 收尾）· 体检 · 注入装配 · 渲染分页 | 复用 `core/trace.js` 事件流（`kernel` 类）+ opId |
| 2 | 单次同步段耗时 | `adapters/store.js#saveStateNowInner` 8 步 · `core/repair.js#runRepairMech` 9 步 · `core/relations.js#deriveRelations` · `core/ingest.js#enforceDimCaps` · `core/rel-maint.js#relRepairMaint` / `#cleanInvalidRelLinks` · `core/nsfw.js#nsfwScan` · `core/data-health.js#dataHealthReport` | 同上，**只记超阈段** |
| 3 | 队列等待 | `adapters/tt-store.js#ttWriteStats` 的 `pending` / `lastSlow` | 既有出口 |
| 4 | 读取耗时 / 字节 | `core/read-ledger.js` | 既有出口（**不重复采集**：仅引用） |
| 5 | 管线阶段与 ETA | `core/pipeline.js` | 既有出口（仅引用） |
| 6 | 宿主钩子耗时 | 时间线的 `host` 类事件 | 既有载体 |
| 7 | 事件循环 gap / 长任务（能力探测） | `PerformanceObserver('longtask')` 或 rAF gap —— 宿主支持时才采 | 新增；**不支持就如实标注，不伪造** |

**分级与窗口**：`notice ≥ 50ms` · `stall ≥ 200ms` · `freeze ≥ 1000ms`（单段同步耗时）；`jankRate = Σ(超阈段耗时) ÷ 采样窗口时长`。

**采样自限**：只记超阈段 · 同站点同 kind 去重 · 环形上限 · 默认开关见 Q2（探针不得成为卡顿源）。

### 4.2 潜在优化清单（机械判据 → 只读清单）

| # | 现象 | 判据（阈值最终以基线为准） | 归因 | 建议方向 | 对应条目 |
| --- | --- | --- | --- | --- | --- |
| 1 | 单段热点 | 某段 ≥ `stall`，或占该动作 ≥ 40% | 同步全量 / 全量序列化 | 分批 / 索引 / 增量 | `技-38` · `数-26` |
| 2 | 扫描量随总量线性增长 | 扫描数 ÷ 库总数 ≥ 0.8 且随库上升 | 每次全量遍历 | 变更集 + 世代缓存 | `技-38` |
| 3 | 写字节 ≫ 变化量 | 写字节 ÷ 变化字节 > 阈值 | 写放大 | 写入收敛 | `数-31` |
| 4 | 队列等待 > 执行 | `pending` 等待 > 执行耗时 | 写队列拥塞 | 去重 / 降频 / 副本收敛 | `数-31` · `数-32` |
| 5 | 派生与副本膨胀 | (快照链 + 副本) ÷ 语义数据 > 阈值 | 派生无保留窗 | 保留窗 + 合并 + 回收 | `数-32` |
| 6 | 可重复的结构性热点 | 同一 `site` ≥ 3 次采样均超阈 | 结构性热点 | 立项 | 未立项 → 走 §2.8 |
| 7 | 卡顿率恶化 | `jankRate` > 基线 × 容忍系数 | 回归 | 回滚 / 优化 | `技-39` 门禁 |

**清单字段**：`现象 · 判据 · 证据（读数 + window + cause + site）· 归因 · 建议方向 · 已有台账号（`U<n>` / `D22` 条目号，或"未立项"）`。**只输出候选，不自动开单**。

### 4.3 探针与既有载体的接线（本次展开的重点）

| 关系 | 口径 |
| --- | --- |
| 探针 ↔ 时间线 | 探针的**阶段事件写进同一条时间线**（`kernel` 类 + 同一 opId）→ 于是"这次动作慢在哪一段"与"这次动作调了哪些宿主 API"在**同一条链路**上可对照 |
