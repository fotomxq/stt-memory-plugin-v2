## 1. 目标 / 非目标

### 1.1 目标

1. **开篇保护**：叙事开篇的前 10 条情节永远保持「逐条可见」，不被压成概述（分段段落只增不减、不回写情节本体，压掉即不可逆）；
2. **约束一致**：自动计划与手动勾选**同一套**保留窗口（否则用户一次误勾就把开篇压没了）；
3. **审查修复**：修正「已覆盖情节仍被切进批次」导致的重复总结；
4. **如实回报**：被头部保留剔除的条数（`skippedHead`）与读数（`headN` / `headKept`）可查、界面 toast 告知。

### 1.2 非目标（明确不做）

* **N1 不改分段段落的数据结构**（`atomIds` / `header` / 区间 / 只增不减口径不动）；
* **N2 不改尾部保留窗口**（最新 10 条，v3.50.4 已定）；
* **N3 不新增配置键**（头部保留是**产品口径**，不是用户可调参数；内部 `headN` 覆盖仅供测试与 V1 平价校验）；
* **N4 不改 `DATA_VERSION`**。

## 3. 方案

### 3.1 头部保留窗口

```text
list = plotSegmentAtomList()                 // 剧情时间升序（无日期排最前，同切批口径）
headN = PLOT_SEGMENT_HEAD_N = 10
pool = list[ headN : len - reserveN ]        // 头 10 与尾 10 都不进池
```

* 自动计划：`plotSegmentPlan()` → `poolTotal` 读数、`headN`/`headKept` 读数；
* 手动勾选：`plotSegmentPlanForIds(ids)` → 先剔除**排序前 10 条**的 id，`skippedHead` 如实回报；
  运行时 toast 与成功提示都说明「开篇前 N 条不参与」；
* 边界：情节不足 10 条 → 全部保留（池空、0 批），**绝不为了凑批而动开篇**。

### 3.2 审查修复：混合批次不再重算已覆盖情节

```text
batchSrc = includeCovered ? pool : pool.filter(a => !covered.has(a.id))
batches = plotSegmentBatchesFrom(batchSrc, size)
```

* 与 `pending` 的口径一致（`pending` 本来就只数未覆盖）；
* `includeCovered: true` 保留旧行为，仅供 **V1 平价校验 / 测试**；
* 收益：不再重复消耗 AI；不再产生「同内容、不同区间」的重复段落。

### 3.3 落点与体量

| 文件 | 改动 |
| --- | --- |
| `core/plot-segment.js` | 常量 + `plotSegmentHeadReserve()` + plan 的头部/增量修正 + `planForIds` 的头部剔除 + 两处读数与提示 |
| 测试 | 新增 `tests/unit/plot-segment-head-audit.test.js`（12 项）· `plot-segment-golden` 的 V1 平价档补 `headN: 0` / `includeCovered: true`，并新增头尾保留的断言 |

### 3.5 回退

`PLOT_SEGMENT_HEAD_N` 设 0（或 `plan({headN:0})`）即回到旧行为；增量修正可加 `includeCovered: true` 还原。
