# D56 · 投喂白名单与正文格式不匹配 → 新存档楼层「整楼被判无正文 / 无法分析」

> 文档版本：v1.0 ｜ 日期：2026-10-27 ｜ 类型：**设计稿（不发版）** ｜ 状态：生效（已按本稿落地 v3.52.1）｜ **维度归属：数据（优先级 1）**

## 0. 一页摘要

用户现象：换过一次存档、清理过数据、删过一次楼之后，**新存档的楼层再也分析不了**；「最开始只能分析 0 层」。
用**本地调试接口**（`node tests/local/bridge.mjs --call …`，插件「调试 → 🔌 调试桥」）逐项取证，结论是
**投喂白名单与正文格式不匹配**导致「整楼被判无正文」——不是楼层台账、不是聊天归属、也不是 AI 接口：

| 取证（桥方法） | 实测读数 | 含义 |
| --- | --- | --- |
| `ftt.config`（`keys`） | `feedRegexWhitelist: ["content"]` | 白名单是**旧存档**的标签名（旧正文用 `<content>…</content>`） |
| `fft.floors` / `ftt.floorDiag` | 非用户楼层 `stableChars` 1800–2500，但 `analyzableChars: 0`、`wouldBePending: false` | 正文存在，但**可分析正文为空** |
| `ftt.pendingScan` | `skipped.noText: 20`、`pending: 0/1` | 全部非用户楼层被算作「无可分析正文」 → 清单空 → 自动提取 `nothing-pending` |
| `ftt.ledger` | `marks: [0,33,34]`、`droppedMarks: 1`、`lastChatFloor: 42`、`verMatches: true` | 台账/版本签名/聊天归属都**正常**；不是「换存档后台账错乱」 |
| 真实楼层原文（只读） | 新正文是 `<dream_plot>` / `<dream_scene>` / `<q content="…">` 等；`content` 变成**属性名** | 白名单在行内兜底里命中 `content=` 属性行，去标签后为空 |

失效链（代码级）：

```text
cfg.feedRegexWhitelist = ['content']                          // 旧存档留下的标签名
→ core/prompt.js#applyFeedRegex：
    ① 标签内容提取 `<content>…</content>` → 新正文明明没有 → extracted = []
    ② 回退「行内包含」：/content/i 命中 `<q content="…">` 这类**纯标记行** → kept > 0（不再是空）
    ③ 返回这些纯标记行 → host/floors.js#cleanText 去标签后 → ''（整楼「无正文」）
→ host/floors.js#floorAnalyzableText = ''
→ host/floors.js#scanPendingFloors：skipped.noText++ → pending 里没有这些楼层
→ host/extract.js#autoExtractLatest / analyzeFloor：「没有未分析楼层」/「empty-floor」→ 用户看到「无法分析」
```

为什么「最开始只能分析 0 层」：第 0 层是**不带 `content` 子串**的短楼 → 旧实现走「白名单未命中 → 回退原文」→ 可分析；
后续 AI 楼层都带 `<q content="…">` → 被过滤成空 → 再也不进清单。

## 1. 目标 / 非目标

### 1.1 目标

1. **纯标记行不算白名单命中**：命中的行去标签后没有任何文字 → 不计入 kept、不写进投喂文本；
   若最终一行有文字的都不剩 → 沿用既有「回退原文」兜底（并留痕，说明疑似白名单过期）；
2. **分析判定不让「过滤成空」吞掉楼层**：`floorAnalyzableText` / `analyzeSegment` 在「过滤后为空（或只剩楼层前缀）而原文有正文」时**回退原文**并记调试日志；
3. **不再静默「登记为已处理」**：`analyzeSegment` 只有「原文本身也空」才沿用旧语义（记该段已处理、不调 AI）；
4. **诊断可区分**：`scanPendingFloors` 新增 `skipped.filtered`（有正文但被判定不可分析，含被过滤清空），不再混进 `noText`；
5. 既有语义不变：真 `<content>…</content>` 仍**只取内部内容**；真·空正文楼仍计 `noText`；台账 / 聊天归属 / 版本签名逻辑一律不动。

### 1.2 非目标（明确不做）

* **N1 不自动改用户的投喂配置**（`feedRegexWhitelist` / `feedRegexBlacklist` 是用户设定；本轮只做「不因配置错位而整楼失效」+ 留痕，不擅自清空）；
* **N2 不改 V1 取文口径**（`collectFloorLinesInRange` / `floorStableText` / `hashFloorText` 不变；哈希仍用原始稳定正文）；
* **N3 不改聊天归属 / 台账 / 删楼逻辑**（`lastKnownFloor` / `coverReset` / `processedDropped` 均不在本稿范围）；
* **N4 不改 `DATA_VERSION`**（无数据结构变化）；
* **N5 不改提示词模板与维度抽取口径**。

## 3. 方案

### 3.1 ① 投喂过滤（`core/prompt.js#applyFeedRegex`）

* 行内兜底阶段：命中的行若 `stripHtmlTags(line).trim()` 为空 → **不算命中**（`markupOnly++`，不写入结果）；
* 全部行都不构成「有文字的命中」→ 沿用既有**回退原文**，并把调试日志的原因写清：
  `白名单只命中纯标记行已回退原文`（附 `markupOnly` 行数与提示：白名单可能还是旧存档的标签名，新正文把它当了属性名）；
* 「标签内容提取」分支不变：真 `<content>…</content>` 仍只取内部内容。

### 3.2 ② 楼层可分析判定（`host/floors.js#floorAnalyzableText`）

```text
src       = collectFloorLinesInRange(f, f)          // 原始（含标签）
filtered  = cleanText(applyFeedRegex(src))
body      = 去掉楼层前缀后的 filtered
if (!body)                                         // 过滤后为空 或 只剩楼层前缀
    unfiltered = cleanText(src)
    if (去掉前缀后的 unfiltered 非空)
        raw = unfiltered; body = unfiltered 的 body   // 回退原文 + 留痕
if (!raw || !body || body 全是占位符号) return ''
```

### 3.3 ③ 分段分析（`host/extract.js#analyzeSegment`）

同上口径：`segBody(text)` 为空且未过滤原文有正文 → 回退原文并 `filterFallback: true`；
**只有原文也空**才 `recordProcessedFloors` + `empty: true`（旧语义保留）。

### 3.4 ④ 诊断口径（`host/floors.js#scanPendingFloors`）

`skipped` 新增 `filtered`：`floorAnalyzableText` 为空且 `floorTextFilteredOut(i)` 为真 → `filtered++`（否则 `noText++`）。
新增只读导出 `floorTextFilteredOut(i)` 供诊断/单测使用。

### 3.5 影响面（落点）

| 文件 | 改动 |
| --- | --- |
| `core/prompt.js` | 导入 `stripHtmlTags`；纯标记行不算命中 + 留痕（原因区分「未命中」/「只命中纯标记行」） |
| `host/floors.js` | `floorAnalyzableText` 回退（过滤清空 / 只剩前缀）；新增 `floorTextFilteredOut`；`scanPendingFloors` 增 `skipped.filtered` |
| `host/extract.js` | `analyzeSegment` 回退 + `filterFallback` 读数；只有原文也空才记已处理 |
| `tests/unit/feed-filter-stale.test.js`（新） | 10 项：过滤语义 / 楼层可分析 / 清单计数 / 分段回退 |
| 文档 | 本稿 · `docs/D22` §4.34（W34）· `docs/D17` U282 · `docs/04`（投喂子页一句 + 文档树）· `docs/05`（测试计数）· 批次档 `docs/history/P10c154` |

### 3.6 回退

三处都是小改：去掉「纯标记行跳过」即回到旧过滤行为；去掉 `floorAnalyzableText`/`analyzeSegment` 回退即回到「过滤空 → 判无正文」；
`skipped.filtered` 只是新增只读字段。均可独立回退，不影响数据结构。

## 4. 风险与对策

| # | 风险 | 对策 |
| --- | --- | --- |
| R1 | 「纯标记行」判定把用户**真的有意的**标签过滤放松（例如白名单就是 `<q content>` 里的文字？） | 标签内容提取分支走原生 `<tag>…</tag>`（不是属性）；属性行本来就不在「标签内容提取」范围内；本次只是让属性行**不再冒充命中** |
| R2 | 过滤清空后回退原文，违背用户「只喂某段」的意图 | 与既有「白名单未命中 → 回退原文」同口径（v2.44.0 起的既有兜底）；且**只在过滤结果为空时**回退（有内容时严格按白名单） |
| R3 | 回退让 AI 看到未过滤内容（含 HTML 标签） | 回退的仍是 `cleanText` 之后的文本（标签已去、实体已解），不是原始 HTML |
| R4 | 分段「原文也空」仍记已处理 → 真丢分析 | 既有 V1 语义（避免无限重试）；本稿只在「原文有正文」时回退，不扩大该语义 |
| R5 | 台账 `noText` 语义变化导致既有单测/读数漂移 | `noText` 只在真·空正文时计数；新增 `filtered` 为**只读增量字段**，既有断言不受影响（`pending-floors` 全绿） |
