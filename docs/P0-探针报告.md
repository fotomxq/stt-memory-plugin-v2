### 1.1 注入 API（精确签名，实现依据）

```js
// public/script.js
export const extension_prompt_types = { NONE: -1, IN_PROMPT: 0, IN_CHAT: 1, BEFORE_PROMPT: 2 };   // :484
export const extension_prompt_roles = { SYSTEM: 0, USER: 1, ASSISTANT: 2 };                        // :494
export const MAX_INJECTION_DEPTH = 10000;                                                          // :499
export function setExtensionPrompt(key, value, position, depth, scan = false,
                                   role = extension_prompt_roles.SYSTEM, filter = null) { ... }     // :8926
```

实现约定（`host/inject.js`）：注入键唯一（`ftt_memory_v2`），默认 `IN_PROMPT / depth 0 / scan false / role SYSTEM`；
关闭、禁用、无内容时必须显式置空（`clearInject()`），避免旧注入残留。

## 3. 对 V2 设计稿的修正（据本轮源码核对）

| # | 原设计 | 修正后 | 原因 |
| --- | --- | --- | --- |
| 1 | §8.2 L2「扩展内检查更新」= 自行 `fetch` 远端 `manifest.json` / 版本清单 | **L2 改为调用 ST 原生端点**：`POST /api/extensions/version`（拿 `currentCommitHash` / `isUpToDate` / `remoteUrl`）与 `POST /api/extensions/update`（触发 pull），扩展只负责**展示与引导**；远端 `CHANGELOG` 抓取仅用于呈现「更新要点」 | 源码证明 ST 已内建 git 检测与拉取；自建通道既不必要也更容易出错 |
| 2 | 「更新检测依据 = `manifest.version`」 | **依据是 git commit**（`isUpToDate`），`manifest.version` 只用于展示；分支切换走 `/api/extensions/branches` + `/switch`（ST 界面已有） | 同上 |
| 3 | `auto_update` 语义模糊 | 明确：`auto_update: true` = **当 ST 包版本变化时**允许自动 `git pull`（仅 `third-party` 生效）；日常更新仍由用户在「Manage extensions → Update」触发 | `public/scripts/extensions.js:1958/:2008` |
| 4 | 世界书 / 弹窗 / 变量对标「需探针」 | **全部可用**：世界书 `loadWorldInfo`/`saveWorldInfo`；弹窗 `callGenericPopup`；变量 `variables` + `substituteParams`（可替代 TH 的 `getVariables`/`replaceVariables`） | `st-context.js` 返回对象 |
| 5 | 副 API 需自建 fetch | 优先 `ConnectionManagerRequestService`（连接配置），自建 fetch 保留为兜底 | `st-context.js` |
| 6 | 内核纯净度门禁「新增规则」 | 已落地：`scripts/check-core-purity.js`（core 不得引用宿主层 / 浏览器标识符） | 本仓库门禁 |

## 4. 仍需真机验证（需在真实 SillyTavern 上执行，P0 无法离线完成）

| # | 项 | 验证方法 | 失败时的处置 |
| --- | --- | --- | --- |
| L1 | 用户态安装（`data/<user>/extensions`）下相对导入与扩展挂载路径 | 安装本仓库 → 控制台应无 404，`/ftt` 可用 | 改用 all-users 安装路径，或把导入改为相对根路径 URL |
| L2 | `APP_READY` 时序（监听器晚挂是否补发） | 观察初始化日志与 `FTT.snapshot()` | 退回 `APP_INITIALIZED` + 定时重试 |
| L3 | `generate_interceptor` 在各生成类型下的 `type` 取值与多扩展次序 | 打印实参；与其它注入类扩展并用 | 用 `loading_order` 调整次序；必要时改用 `GENERATION_AFTER_COMMANDS` |
| L4 | 注入内容是否进入最终提示词（不与其它注入冲突） | 用 Prompt Inspector 检查 | 调整位置（`IN_CHAT` + depth）或改由 `generateRaw` 自拼 |
| L5 | `extensionSettings` 体积上限与写入频率 | 灌入 1 MB 观察 | 设定只存轻量键，大对象走文件通道 |
| L6 | 多用户下 `/api/extensions/*` 权限（admin / 用户态） | 非 admin 账号执行更新 | 只提示、不自动执行；指引手工更新 |
| L7 | 服务端无 git 或离线环境的降级表现 | 断网触发更新 | 静默失败 + 提示（`autoUpdateCheck` 可关） |
| L8 | i18n 词条生效（`data-i18n` + manifest `i18n`） | 切换语言观察设置面板 | 回退中文内置文案 |
