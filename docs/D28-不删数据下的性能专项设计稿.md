## 0. 一页摘要

「**数据不应被移除**」是一条**保留策略**，但它会与既有的**删除/裁剪/遗忘**族正面冲突（§3.7 共 **7 处**），且会把"全量扫描"从"偶发"变成"**每次都在增长**"。本稿给出的解法是把它从"保留问题"转成**分层问题**：

> **不删数据 ≠ 全都参与查询。** 语义数据**永久保留**，但只有**热集**参与召回与渲染；其余进**冷存**（仍在库、仍参与哈希与跨端同步、可检索、可下钻），**不进高频扫描路径**。

| 机制 | 作用 |
| --- | --- |
| **冷热分层** | 高频路径（每次生成前的注入、列表渲染）只碰热集；冷存按需惰性读 |
| **索引化 + 世代缓存** | 用**已存在**的 `core/model/runtime.js#kernelStateSeq()` 作失效判据，索引不每次重建 |
| **分区（维度 × 区间）** | 按剧情时间 / 楼层区间分区，查询带区间 → 只扫相关分区；与既有 `adapters/shards.js` 的维度分片叠加 |
| **上限改口径** | `storeTotalMax` 等从"**存活上限**"改为"**工作集上限**"；超出**降权移出热集**，不删 |
| **全量操作节流 + 可观测** | 修复 / 体检 / 合并等全量类**只在显式触发或空闲时**跑，且如实报**扫描量与耗时**（复用既有读取台账与管线状态） |

**本轮新发现三条**（其开发项见 §8，均已按 §2.8 登记进 `docs/D17` 与 `docs/D22`）：

| 序号 | 发现 | 证据 | 对应条目 |
| --- | --- | --- | --- |
| **①** | **注入路径存在二维全量交叉**：`core/recall.js` 的候选构建里有 `REL_LINK_DIMS` × `state[dim]` 的双层全量遍历并伴随 `.filter()` 分配；而注入是**每次生成前**都跑的**最高频**路径 → 数据只增不减时，**每次注入的扫描成本线性增长** | `core/recall.js` 的候选构建段 | `数-26` |
| **②** | **`core/relations.js#deriveRelations` 无任何缓存/世代判据**：每次调用重建 `byName` / `byPath` / `byId` 三个 Map → **每次都是全量**，而关系表页与派生视图都会调它 | `core/relations.js#deriveRelations` | `数-26` |
| **③** | **上限族仍在"删"**：`core/forget.js#sweepLowUseForget` / `#forgetState`、`core/ingest.js#enforceDimCaps`、`core/merge.js#capAtomsKeepingHidden`、`core/rel-maint.js#capRelLinks`、`core/snapshots.js#trimSnapshots`、`core/parallel.js#prunePromotedParallels` 全部**移除条目** | 见 §3.2 的全量/删除点清单 | `数-25` |

**与本稿冲突、必须回改的既有约定**：**遗忘与衰退**、**上限裁剪**、**低使用遗忘**，以及 **`docs/D26` 履历的"自动遗弃"**（逐条对账见 §3.7；收口动作见 `技-29`）。

## 3. 方案

### 3.1 「不删数据」的边界（三层）

| 层 | 内容 | 处置 |
| --- | --- | --- |
| **① 语义数据（永久保留）** | 15 个维度的条目正文与结构化字段（情节 / 状态 / 档案 / 记忆 / 物品 / 计划 / 悬念 / 场景 / 概念 / 平行 / 关联 / 分段 / 传言 / 货币 / **地图**） | **永不自动移除**。老化只**降权 + 移出热集** |
| **② 派生与账本（可回收）** | 关系派生视图与索引缓存 · 向量缓存 · 读取台账 · 调试日志 / 时间线 / 时钟追踪 · 版本清单缓存 · **墓碑账本**（`deleted` / `deletedH`） | 可回收，但**墓碑回收需保留复活抑制**（`docs/D16` A8 已列为高风险，按 §6 Q4 处置） |
| **③ 冗余副本（可收敛）** | 单文件 / 逐维分片 / 快照分片 / 日志分片**四套副本** · 主文件与备份 | **收敛为"一个权威 + 其余按需"**（`docs/D16` L10 / A9）—— 收敛副本**不等于**删数据 |

**仍可删除的例外（三条，须显式登记）**：① **垃圾 / 空壳**（无内容、非法值）—— 不是"早期记忆"；② **用户显式删除**（危险动作 + 二次确认，既有口径）；③ **重复条目的合并**（合并的是重复，不是内容）。**这三条之外，一律不自动移除语义数据。**

### 3.2 全量扫描点与删除点清单（逐个改造方向）

| # | 点 | 频度 | 现状 | 改造方向 |
| --- | --- | --- | --- | --- |
| 1 | **召回候选构建**（`core/recall.js`） | **每次生成前**（最高频） | 逐维全量 + `REL_LINK_DIMS` × 全量二维交叉 | **只扫热集**（§3.3）+ 走倒排索引（§3.4）；二维交叉改为**由索引取邻接** |
| 2 | **`deriveRelations`**（`core/relations.js`） | 每次打开关系表 / 派生视图 | 每次重建三个 Map | **世代缓存**（`kernelStateSeq()` 变化才重建，§3.4） |
| 3 | **跨端合并**（`core/cross-sync.js`） | 每次保存对账 / 同步 | 全量建 `L`/`R` map | 先比**聚合指纹**（已有）→ 仅在不等时逐条；逐条走 **id 索引** |
| 4 | **修复机械段 9 步**（`core/repair.js`） | 手动 / 合并失败 | 全量遍历 | 拆为「**热集增量维护**（高频、便宜）」+"**冷存周期全量**（显式触发、可节流）" |
| 5 | **载入自愈**（`core/migrate.js#healthSelfHeal`） | 每次载入一次 | 全量一次 | 接受（载入期一次）；改为**只扫变化分片**（配合 §3.5） |
| 6 | **体检**（`core/data-health.js`） | 按需（面板 / 调试桥） | 全量 | 接受（显式触发）；增加**扫描量上限与截断如实回报**（已有 `cap` / `truncated`） |
| 7 | **上限裁剪族** | 每次修复 / 入库 | **移除条目** | **改为移出热集**（§3.3 / §3.7） |
| 8 | **遗忘 / 衰退** | 每次修复 / 载入 | **移除条目** | 改为**降权 + 移出热集**，保留在库 |
| 9 | **面板列表**（`ui/panel.js#listOf`） | 每次渲染 | 全量排序 + 300 截断 | 走**索引分页**（`docs/D19` 的 `应-1` 分页口径） |

### 3.3 冷热分层（核心机制）

| 项 | 口径 |
| --- | --- |
| **热集定义** | 参与高频路径（注入 / 列表首屏 / 修复的增量段）的条目集合。建议判据（可配置，三条并列取并集）：① **最近 K 楼**内产生或更新；② **最近 M 条**（按剧情时间）；③ **重要度 ≥ 阈值**（复用 `docs/D7` 的口径，但不改其算法） |
| **冷存定义** | 其余语义数据。**仍在库、仍参与内容哈希与跨端逐条合并、仍可被搜索 / 下钻 / 修复读到** |
| **载入时** | 只构建**热集**的索引；**不**为冷存建索引（冷存按需惰性） |
| **访问冷存** | 三条**显式**入口：① 用户在面板**搜索 / 翻页 / 下钻**；② 修复的"冷存周期全量"段；③ 导出 / 同步（这两者本就全量） |
| **冷存的注入** | **不参与召回候选**（§3.2 #1）。**注意**：这不是"不注入"，而是"**不是候选也就不注入**"；用户若要早期记忆进上下文，走**显式入口**（见 §6 Q5） |
| **上限改口径** | `storeTotalMax` 与各维上限从"存活上限"改为"**热集上限**"；超出时**降权移出热集**（写 `coldAt` 与原因），**不移除** |
| **可解释** | 面板与体检须能回答「这条为什么没进上下文」：热集未命中 / 被降权 / 被遗弃（新口径下=移出热集），**如实说明**（延续 `docs/04` 的"召回方式"口径） |

> **与既有 `plotSegments` 先例的关系**：「原子层但不注入」在 `01` B10 已有先例（分段总结只归档不注入）→ 本稿的"冷存不参与召回"是**把该先例从 1 个维度推广为一条通则**。

### 3.4 索引化与世代缓存

| 索引 | 内容 | 失效判据 |
| --- | --- | --- |
| **主索引** | `维度 → id → 条目` | `kernelStateSeq()` 变化（K5，**机制已存在**） |
| **倒排索引** | `标签 / 主体 / 地点 / 角色名 → id 集` | 同上 |
| **时间索引** | `剧情日期 → id 集`（支持区间查询） | 同上 |
| **邻接表** | `id → 出边 / 入边`（替代 §3.2 #1 的二维交叉） | 同上 |
| **热集标记** | `id → 是否热集 + 原因` | 同上 |

- **做法**：索引**惰性构建**（首次查询时建）；`kernelStateSeq()` 不变则**复用**，变了则**增量更新**（新条目入索引、变更条目重算、删除条目出索引）。
- **不落盘**：索引是**派生缓存**，不参与哈希与同步（`02` §2 I3 的引用口径不适用，但**必须**在文档里声明"索引不是数据契约"）。
- **既有先例**：`core/relations.js#deriveRelations` 的 Map 形态 + `adapters/vector-cache.js` 的 LRU 缓存（`D13` §4：2000 条 / 32MB）。

### 3.5 分区（维度 × 区间）

| 层 | 口径 |
| --- | --- |
| **一级：维度** | **已有** —— `adapters/shards.js` 每维一片（K6） |
| **二级：区间** | 新增按**剧情时间或楼层区间**分片（如每 N 楼 / 每 M 剧情月一批） |
| **查询约束** | 一切按区间可表达的查询（未摘要楼层、时间窗、最近 K 楼）**必须带区间**，**禁止**退化为全维扫描 |
| **落盘与同步** | 与既有分片口径一致：**只写变化的片**；载入时**只读变化片**（`docs/D02` §5 的既有纪律） |
| **与冷热的关系** | 热集**优先命中最近的区间片**；冷存天然落在更早的分片 → 两者互补 |

### 3.6 全量操作的节流与可观测

| 项 | 口径 |
| --- | --- |
| **节流** | 全量类操作（修复全量段 / 体检 / 载入自愈 / 跨端逐条合并）① 只在**显式触发**或**空闲**时跑；② 设置**最短间隔**（复用 `docs/D25` 的 `autoRepairEveryOps` / 同楼层上限一类的既有闸门形态）；③ 期间**不得**阻塞注入（`01` B1） |
| **可观测** | 每次全量操作如实记录：**扫描条目数 · 跨维度数 · 耗时 · 命中**（复用 `core/read-ledger.js` 与管线状态，K7；**不含正文**） |
| **预算** | 全量操作设**单次扫描上限**，超限则**分批**并留痕（"本轮扫了 X，余 Y 下轮"），**不静默放弃** |
| **验收基线** | `docs/D13` §8 的未核实清单**必须补齐**（真机载入 / 保存 / 渲染耗时）—— 没有基线就无法判断"是否稳定" |
