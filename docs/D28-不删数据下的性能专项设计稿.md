## 0. 一页摘要

**两条口径**（v1.1 新增，本稿的判据来源）：

> **① 无限容量**：语义数据**只增不减**、容量**不设人为上限**；目标不是"省空间"，而是**「性能不随总规模线性劣化」**。
> **② 功能不变（A 案，默认）**：**结果等价** —— 同一份 state 下，注入体、界面可见内容、落盘后的载入结果、修复与体检的结论**逐字/逐条不变**。
> 允许变的只有：耗时 · 内存 · 体积 · **物理写次数** · **扫描量** · **批次划分（同一结论跨多轮完成）**。

| 机制 | 作用 | 案 |
| --- | --- | --- |
| **写入收敛**（P0） | 一次保存的物理写与字节，**与变化量成正比**（而非与总量成正比）；副本与派生数据收敛 | A 案 |
| **扫描收敛**（P0） | 维护 / 修复 / 体检由「每次全量」改为「**变更集 + 世代缓存 + 游标分批**」，**结论等价** | A 案 |
| **索引化 + 世代缓存** | 用**已存在**的 `core/model/runtime.js#kernelStateSeq()` 作失效判据；**查询结果与全量路径等价** | A 案 |
| **分区（维度 × 区间）** | 按剧情时间 / 楼层区间限定扫描面；**结果等价** | A 案 |
| **全量操作节流 + 可观测** | 全量类只在显式触发或空闲时跑，如实报**扫描量与耗时** | A 案 |
| **卡顿检测 + 潜在优化清单** | 分段耗时按三级阈值判卡顿；按机械判据把"哪里慢"输出成**只读清单**（不自动立项）—— **设计见 `docs/D31` §4.1 / §4.2** | A 案 |
| **统一调试接口** | 探针读数 / 卡顿明细 / 优化清单 / 基线差异**三处同源**暴露（`FTT.*` · 调试桥 · 调试导出），每条带追溯字段 —— **设计见 `docs/D31` §4.4** | A 案 |
| **容量目标：体积增长与语义数据同阶** | 派生 / 账本 / 副本有**保留窗与回收**，不与语义数据同速膨胀 | A 案 |
| 冷热分层（**冷存不参与召回**） | 高频路径只碰热集 —— **会改变可见结果** | **B 案（待裁决，见 Q7）** |
| 上限族改「热集上限」（**不再裁剪**） | 上限从"移除"改"移出热集" —— **会改变可见结果** | **B 案（待裁决，见 Q3）** |

## 1. 定义 · 范围 · 目标 / 非目标

### 1.1 定义（无限容量 · 功能不变 · 判据）

| 项 | 口径 |
| --- | --- |
| **无限容量** | 语义数据**只增不减**、**不设人为容量上限**（不因体积触发自动删除）。三类增长来源必须分别治理：① **语义数据**（对话越长 → 条目越多）；② **派生与账本**（索引 / 台账 / 墓碑 / 日志 / 快照链）；③ **冗余副本**（同一份数据的多处落盘）。目标 = **性能与体积的增长与"变化量"同阶，而不是与"总量"同阶** |
| **功能不变（A 案，硬约束）** | 五条**可测**判据：**① 注入等价** —— 同一 state 下，注入体（`host/inject.js` 的最终文本）**逐字不变**；**② 界面等价** —— 同一 state 下，列表页 / 详情页在**同一分页范围内**的可见条目与顺序不变；**③ 落盘等价** —— 保存后重新载入（含本机层 / 服务端文件 / 分片 / 快照回滚路径），state **逐字段等价**；**④ 维护等价** —— 修复 / 体检 / 清理对同一语料的**最终结论等价**（可跨多轮完成）；**⑤ 数据契约不变** —— 内容哈希 / 信封与 `storageHash` / 墓碑双账本 / 合并口径 / 作用域键 / `normText` 按 `docs/D15` §3 类别①**一律不动**（要动必须带迁移 + `DATA_VERSION` 递增 + 双端兼容） |
| **允许变化（A 案下唯一允许的四类）** | ① **耗时**（更快即可）；② **内存**（驻留更小即可）；③ **体积 / 物理写次数 / 扫描量**（更小即可）；④ **批次划分** —— 同一结论可以**分成多轮跑完**（如"本轮扫 X 条、余 Y 条下轮"），但**最终结论必须一致**，且必须**如实回报余量**（不得静默放弃） |
| **性能判据（可测）** | 四类读数（`技-39` 立基线）：**写入**（每次保存的通道数 / 物理写次数 / 字节 / 耗时）· **读取**（`core/read-ledger.js` 的次数 / 字节 / 耗时）· **扫描**（各全量点的扫描条目数 / 耗时 / 命中）· **体积**（主文件 / 分片 / 快照链 / 副本 / 墓碑）。**判据形态 = "只增不降"棘轮**（回归即失败，改善则收紧基线） |
| **与 v1.0 口径的关系** | v1.0 的两条主结论（**冷热分层 → 冷存不参与召回** 与 **上限族改"移出热集"**）**改变可见结果** → 本版把它们改列为 **B 案**，A 案（功能不变）下**不采用**。v1.0 的其余机制（索引 / 分区 / 节流 / 副本收敛）**与 A 案相容**，全部保留 |
| **不是什么** | 不是"压缩到更小就完事"（编码层只是手段之一）；不是"延迟到空闲再算"（那只是节流，不解决扫描面）；不是"把数据搬走"（不引入外部存储，见 §1.4 N2）；不是"改数据模型换取速度"（数据契约不动） |

## 3. 方案

### 3.1 「无限容量」的边界（三层 + 三条例外）

| 层 | 内容 | 处置 |
| --- | --- | --- |
| **① 语义数据（永久保留）** | 15 个维度的条目正文与结构化字段（情节 / 状态 / 档案 / 记忆 / 物品 / 计划 / 悬念 / 场景 / 概念 / 平行 / 关联 / 分段 / 传言 / 货币 / **地图**） | **永不自动移除**（A 案）；老化只**降权**（B 案才谈"移出热集"） |
| **② 派生与账本（可回收）** | 关系派生视图与索引缓存 · 向量缓存 · 读取台账 · 调试日志 / 时间线 / 时钟追踪 · 版本清单缓存 · **快照链** · **墓碑账本**（`deleted` / `deletedH`） | **有保留窗与回收**（`数-32`）；**墓碑回收必须保留复活抑制**（`docs/D16` A8，按 §6 Q9） |
| **③ 冗余副本（可收敛）** | 单文件（主文件）/ 逐维分片 / 快照分片 / 日志分片**四套副本** · 主文件与备份 · 本机缓冲三层（变量 / 内存库 / 本地目录）· 镜像 | **收敛为「一个权威 + 其余按需」**（`docs/D16` L10 / A9）—— 收敛副本**不等于**删数据 |

**仍可删除的例外（三条，须显式登记）**：① **垃圾 / 空壳**（无内容、非法值）；② **用户显式删除**（危险动作 + 二次确认，既有口径）；③ **重复条目的合并**（合并的是重复，不是内容）。**这三条之外，一律不自动移除语义数据**（A 案）。

### 3.2 A 案与 B 案（**本稿的裁决分界**）

见 §0 的分界表。**A 案 = 默认**（用户当轮明确「功能不变」），**B 案 = 待裁决**（`D28` Q3 / Q7）。三条硬规矩：

1. **A 案下不得使用"会改变结果"的手段** —— 冷存过滤、上限不裁、衰退不删都归 B 案；
2. **同一手段在 A/B 两案下的实现可以共用**（如索引模块、分片、游标分批），差别只在**是否用它去过滤 / 改变候选集**；
3. **任何 B 案的落地都必须先有 Q 裁决**，并在落地时同步 `docs/01` / `docs/02` / `docs/D26` 的口径（`技-29`）。

### 3.3 P0-A · 写入与体积（写放大 · 读放大 · 副本与派生）

#### 3.3.1 一次"有变化的保存"到底写了什么（现状拆解）

| # | 通道 | 现状 | 是否与"变化量"成正比 |
| --- | --- | --- | --- |
| 1 | 本机缓冲（变量 / 本地目录 / 本地文件） | 整份信封；**等值跳过**已在（K5） | ❌ 与总量成正比（有等值跳过兜底） |
| 2 | 内存库（IndexedDB） | 整份信封 | ❌ 同上 |
| 3 | **服务端分片** | **只写变化片**（按内容哈希，K3） | ✅ **已是增量** |
| 4 | **服务端主文件** | **整份信封（提交点）**（K4） | ❌ 与总量成正比（**本路径最大单项**） |
| 5 | 备份（`-bak`） | 随主文件 | ❌ 同上 |
| 6 | 原生通道（KV / Blob） | 经文件通道路由：大载荷 → Blob（真机 7.5MB / 141ms） | ❌ 与总量成正比（走同一份载荷） |
| 7 | 镜像（`syncOnSave`） | 3s 防抖 + 双门控 | ❌（可关，属副本收敛项） |

| 10 | 墓碑账本（派生） | 每维 500 + 90 天；真机墓碑数达存活 **5 倍**（K11） | ❌ 与历史删除量成正比（无保留窗外的回收） |

**结论**：写入侧**已有三层收敛**（分片增量 / 等值跳过 / 无变化短路与合流，K3/K5/K6/K7），**真正的写放大来自"全量主文件 + 备份 + 原生通道 + 镜像"这一串"整份载荷"路径**，以及**派生数据（快照链 / 墓碑）缺少保留窗**。

#### 3.3.2 手段与机理（A 案：全部保持"载入等价"）

| # | 手段 | 机理 | 为什么"功能不变" |
| --- | --- | --- | --- |
| 1 | **读数先行**：给每次保存列出"通道 / 次数 / 字节 / 跳过原因" | 现状只有 `lastSave.via` 与 `ttWriteStats` 的计数（K8）；**没有"这次为什么写了 7.5MB"的口径** | 只加读数 |
| 2 | **主文件降频**（仅在必要时写提交点） | 分片已先写且载入侧会"按比主文件新的分片覆盖"（K3）；主文件是**提交点**语义 → 可在"仅本机层变化"或"窗口内重复"时不写（K6 已部分实现） | 载入结果不变（分片已持有最新内容） |
| 3 | **主文件基准化**（基准 + 变更集，或"分片即权威"） | 把"整份信封"改为"基准 + 差异"→ 写量随变化量 | ⚠️ **触碰数据契约**（信封 / `storageHash` / 载入候选顺序）→ 必须标 **[契约]** + `DATA_VERSION` 递增 + 双端兼容，**本轮只评估不实施** |
| 4 | **编码层**（gzip + 瘦身） | 同一份语义数据的**编码**更小；读路径已兼容多候选（K9） | 读回等价 → 功能不变；但会改**写入名**，须评估旧档与"文件在说谎"类历史缺陷 |
| 5 | **本机层 / 内存库的增量写** | 现状整份；可改为"按作用域 + 变更维度的键"（本机层本就按作用域键存） | 载入等价（读路径按同一键还原） |
| 6 | **镜像与副本"按需"** | 镜像默认关、或在"权威通道已成功"时跳过；四套副本收敛为**一个权威 + 其余按需** | 副本不是语义数据；恢复路径仍完整 |
| 7 | **快照链真增量 + 合并 + 回收窗** | 增量只存与根的差异；按 `atomsHashes` **字面去重**（`docs/D10` R2）；已并入根的增量合并；超窗回收 | 只影响"能回滚到哪些历史点"的**档位数**，不改当前数据（须在 UI 如实说明可回滚范围） |

#### 3.3.3 读放大（先定位，不许猜）

真机读数 **1.27 GB/会话**的本机缓冲读取（K14）**必须先把来源定位清楚**再谈优化：

- 候选来源（**未核实**，逐条只读确认）：① **保存后的回读校验**（若存在）；② 载入期"多候选全读后择优"（`docs/D10` 的候选选取）；③ 诊断 / 探针类读取（`ftt.*` 只读方法）；④ 每次保存的"写 → 回读"对账。
- **纪律**：定位清楚前**不得删除任何校验**（校验是数据安全的最后一道）；确认后只允许"**抽样 / 异步 / 合并多次读为一次**"这类**不改结论**的收敛。

#### 3.4.2 机理（为什么"分批"仍然"功能不变"）

- **世代缓存**：`stateSeq` 不变 → 索引 / 派生结果**必然相同**，复用不改变任何结论；变则**增量更新**（新条目入索引、变更条目重算、删除条目出索引）。
- **变更集驱动**：语义上等价于"只扫上次扫描后变化的条目 + 用它更新结论"，前提是**结论可增量维护**；对**不可增量维护**的判据（如"全库两两相似度"）**必须退回全量**，或按区间分区后**分区内全量**（结果等价）。
- **游标分批**：把一次全量扫描拆成**多轮**，每轮处理预算内的工作量，游标落 `state`（runtime 槽位），**直到覆盖全库**。关键纪律：**"分批 == 一次性"必须被测试锁死**（同一语料两种跑法的结论逐条等价）。
- **预算与可观测**：单次扫描量与耗时**如实回报**；超限**分批并留痕**（"本轮扫 X，余 Y 下轮"），**不得静默放弃**。
- **不阻塞注入**：所有全量 / 分批操作都不得阻塞注入路径（`01` §4 B1）。

### 3.5 冷热分层（**A 案下的重定位**）

| 项 | A 案（默认，功能不变） | B 案（待裁决） |
| --- | --- | --- |
| **热集的作用** | 只用于**加速视图**（先算热集 → 再补齐冷存结果，最终结果与全量等价） | 用于**过滤**（冷存不进候选 → 注入体变化） |
| **冷存** | 仍在库、仍参与哈希与跨端逐条合并、仍可搜索 / 下钻 / 注入 | 同上，但**不参与召回候选** |
| **上限口径** | **保持不变**（上限族仍按既有口径裁剪，`docs/D02` §3.3 语义不动） | 改「**热集上限**」：超出**降权移出热集**、不删 |
| **可解释** | 必须能回答「这条为什么没进上下文」：未命中关键词 / 不在候选 / 开关关闭 | 追加"已移出热集"一类原因 |
| **先例** | —— | `01` B10「分段总结只归档不注入」的推广 |

> **A 案的"热集"只优化**「先算哪一块」**，不改变**「最后算哪些」**——这是它与 B 案唯一的、也是最关键的区别。

### 3.6 索引化与世代缓存（A 案核心加速器）

| 索引 | 内容 | 失效判据 |
| --- | --- | --- |
| **主索引** | `维度 → id → 条目` | `kernelStateSeq()` 变化（K18，**机制已存在**） |
| **倒排索引** | `标签 / 主体 / 地点 / 角色名 → id 集` | 同上 |
| **时间索引** | `剧情日期 → id 集`（支持区间查询） | 同上 |
| **邻接表** | `id → 出边 / 入边`（替代 §3.4.1 #9 的二维交叉） | 同上 |
| **命中缓存**（NSFW / 体检） | `世代 → 命中结果` | 同上 |

- **做法**：惰性构建（首次查询时建）；世代不变则**复用**，变则**增量更新**。
- **等价性**：所有索引查询必须与全量路径**结果等价**（用"同一语料双跑对比"锁死，`技-38` / `数-26` 的验收都含这一条）。
- **不落盘**：索引是派生缓存，**不参与哈希与同步**（`docs/D02` §2 I3 的引用口径不适用，但**必须**在文档声明"索引不是数据契约"）。
- **既有先例**：`core/relations.js#deriveRelations` 的 Map 形态 + `adapters/vector-cache.js` 的 LRU（`docs/D13` §4：2000 条 / 32MB）。

### 3.7 分区（维度 × 区间）

| 层 | 口径 |
| --- | --- |
| **一级：维度** | **已有** —— `adapters/shards.js` 每维一片（K19） |
| **二级：区间** | 新增按**剧情时间或楼层区间**分片（如每 N 楼 / 每 M 剧情月一批） |
| **查询约束** | 一切按区间可表达的查询（未摘要楼层 / 时间窗 / 最近 K 楼）**必须带区间**，**禁止**退化为全维扫描；**且结果与不带区间的全量查询等价** |
| **落盘与同步** | 与既有分片口径一致：**只写变化的片**；载入时**只读变化片** |
| **与冷热的关系** | 热集**优先命中最近的区间片**；冷存天然落在更早的分片 → 两者互补（B 案下才用于过滤） |

### 3.8 全量操作的节流与可观测

| 项 | 口径 |
