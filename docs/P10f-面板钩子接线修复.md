# P10f · 面板钩子接线修复（数据管理「导出/导入」不可用）· v2.40.0

> 文档版本：v1.0 ｜ 日期：2026-09-26 ｜ 状态：生效（v2.40.0）
> 触发（用户原话）：「**数据管理导出导入功能不可用**。」
> 涉及：`index.js` · `tests/unit/panel-hooks.test.js`（新）· `tests/smoke-test.js`

---

## 1. 根因（一行代码，影响面 11 个功能）

V2 的 V1 同构浮层（`ui/panel.js`）通过 `hooks.*` 取得宿主能力；而 index.js 只注入了 `popupHooks()`：

```js
// 改前
function popupHooks() {
    return { extract, pending, extractStatus, clearInject, checkUpdate };   // ← 只有 4~5 个键
}
setPanelHooks2(Object.assign({}, popupHooks(), { inject: injectNow }));     // ← 面板拿到 6 个键
```

但 `ui/panel.js` 实际读取 **15** 个键。缺口 **11** 个：

| 缺失键 | 面板用途（用户可见） | 缺键时的实际表现 |
| --- | --- | --- |
| `exportState` | 数据管理「⬇ 导出 JSON」 | 提示**「导出入口未就绪」**（用户报告的现象） |
| `importState` | 数据管理「⬆ 导入」 | 提示**「导入入口未就绪」** |
| `importV1` | 数据管理「📥 V1 导入（干跑/写入）」 | 提示**「V1 导入入口未就绪」** |
| `autoSummary` | 总览「批量摘要」 | 提示**「批量摘要入口未就绪」** |
| `abort` | 总览「中断」 | 静默失败（`{ok:false}`） |
| `clearFloors` | 数据管理「🧹 清除已处理记录」 | 静默失败 |
| `dimToggle` | V2 附加设定「启用维度」勾选 | **静默无效**（勾了不生效，最难发现的一类） |
| `batchProgress` | 忙位进度「🔄 分析中 x/y 段」 | 只显示「分析中…」 |
| `resetState` | 数据管理「🗑 清空当前角色记忆」 | 有适配层同名函数兜底 → **该按钮一直可用** |
| `confirm` | 破坏性动作的确认框 | 有原生 `confirm` 兜底 → 可用 |
| `inject` | 「注入」按钮 | 已在注入点单独补上 → 可用 |

**时序**：该缺口自 **v2.2.0（B1 批次）** 起就存在（`git log -S "setPanelHooks2(Object.assign"` 指向 `bb5b214`），
即从面板外壳落地那一刻起，数据管理页的动作按钮就没有接上宿主能力。

## 2. 为什么测试没有抓到

面板按钮与 devtools/`popupAction` 走的是**两套不同的钩子**：

- devtools / `FTT` 调试入口：`installDevtools({ …, exportState: exportStateJson, importState: importStateJson, … })` —— **键是齐的**；
- 真实面板：`setPanelHooks2(...)` —— **键不全**。

既有冒烟与单测为了省事都走 `entry.popupAction(...)`（devtools 路径），因此「导出/导入能用」被**假绿**了；
没有任何测试断言「面板读取的 `hooks.X` 集合 ⊆ 注入的钩子集合」。

## 3. 修复

```js
// index.js（v2.40.0）
export function panelRuntimeHooks() {                       // ← 唯一注入来源，键集与面板需求一一对应
    return Object.assign({}, popupHooks(), {
        inject: injectNow,
        exportState: exportStateJson,
        importState: importStateJson,
        importV1: runV1Import,
        autoSummary: runSummaryBatch,        // 总览「批量摘要」
        abort: abortExtraction,              // 总览「中断」
        batchProgress,                       // 忙位进度
        clearFloors: clearProcessedFloors,   // 数据管理「清除已处理记录」
        resetState: () => resetState(),      // 数据管理「清空当前角色记忆」
        dimToggle: (kind, on) => setDimensionEnabled(kind, on),
        confirm: (text, title) => hostConfirm(text, title),
    });
}
setPanelHooks2(panelRuntimeHooks());         // 注入点收敛为这一处
```

两个新实现（此前只是「缺键回落」）：

- **`setDimensionEnabled(kind, on)`**：写内核 `cfg.dimensionEnabled[kind]` 并 `saveKernelCfg()`（V1 同键同语义；
  缺 kind 返回 `{ok:false}`）。此前勾选「启用维度」静默无效。
- **`hostConfirm(text, title)`**：**同步**返回布尔 —— 有宿主 `confirm` 时按 `confirm(text)` 的返回（**文案逐字与 V1 一致：
  只用正文、不带标题**，见下方「与既有断言的冲突」），无对话框能力（测试桩 / 受限 webview）返回 `false`，
  面板按「取消」处理（与 V1「无对话框不执行破坏性动作」同款）。**刻意保持同步**：异步弹窗返回 Promise 会被
  `!!` 误判成「已确认」。

**与既有断言的冲突（已按 V1 口径收口）**：冒烟 AE3 断言确认文案逐字等于
`确认清空当前角色的 FTT 记忆？此操作不可恢复，建议先导出备份。`（无标题）。首版 `hostConfirm` 把 `title` 也拼进了
`confirm()` 文本 → AE3 失败。核对 V1：V1 用**原生 `confirm(text)`（无标题）**，故改为只传正文，`title` 仅保留给
将来的宿主对话框实现；冒烟 AE3 与单测 D1 均按此口径断言。

## 4. 防回归（本批的**核心**交付）

1. **静态交叉校验**（`tests/unit/panel-hooks.test.js#C1`）：从 `ui/panel.js` 源码里提取全部 `hooks.X`，
   断言每一个在 `panelRuntimeHooks()` 中都是函数 —— **缺一个就失败**；并单独断言「曾经缺失的 11 个键全部在册」。
2. **注入点唯一性**（`W1`）：断言 index.js 使用 `setPanelHooks2(panelRuntimeHooks())`，且**不得**退回
   `setPanelHooks2(Object.assign({}, popupHooks(), …))`。
3. **行为断言**（`B1`/`B2`/`D1`）：导出→文本框渲染、导入（**参数路径 + 文本域路径**）真实合并新增 2 条、空文本域如实拒绝、
   维度开关真实落 `cfg`、清台账/中断可用、`confirm` 同步布尔语义。
4. **冒烟走真实入口**：**AQ1** 用 `entry.panelRuntimeHooks()` + 面板动作 + DOM 桩文本域跑完「导出 → 清空 → 粘贴 → 导入」；
   **AQ2** 用**真实 change 委托**驱动「启用维度」勾选框，断言 `cfg.dimensionEnabled.atoms` 随勾选变化。
   （这两条**永远不会**走 devtools 钩子，因此不会再出现同类假绿。）

> 已知并列事实（登记备查）：`setPanelHooks2(next)` 是**合并**语义（`Object.assign`），无法用 `setPanelHooks2({})` 删除
> 已注入的键。冒烟 AE3 注入的抛错版 `importV1` 会一直留在钩子表里 —— 本批的 AQ1 因此不调用 `importV1`（改为只断言其类型）。
