## 1. 目标 / 非目标

### 1.1 目标

1. 让用户能把**重要角色**钉住，自动清理永不误删（`D28` 的人类意志优先）；
2. 让物品页能一次性清理「未关注角色」名下的杂物，但**绝不静默删除**：必须先列清单、再确认；
3. 全部落地在 **新模块**：不改动既有归一契约的可观察输出（V1 黄金样本零漂移）。

### 1.2 非目标

- **N1** 不改 `DATA_VERSION`、不做迁移（`watch` / `owner` 都是**可选字段**；老存档缺省即「未关注 / 未归属」）；
- **N2** 不改「上限裁剪 / 低使用遗忘」的其余口径（只加**豁免**，不减小清理力度）；
- **N3** 不把 `watch` / `owner` 放进内容哈希（V1 黄金样本锁定哈希；两者都是「用户/归属元信息」）；
- **N4** 不在清理里做「按 tags / 描述含角色名」的模糊推断（只认显式 `owner`，无归属一律不动）。

## 3. 方案

### 3.1 数据字段（`数-47`）

* `snapshots[].watch: boolean`：**只在 true 时写**（false 与缺省等价 → 省体积、V1 样本零漂移）；不进内容哈希、不进 `content` 副本。
* `items[].owner: string`：**只在非空时写**；`HASH_FIELDS.items` 含 `owner`（瘦身白名单保留它），但**内容哈希不含**（边界登记于代码注释与 §5）。

### 3.2 业务口径（`业-15`）

* **关注 = 用户意志**：被关注档案在「存档上限裁剪」与「低使用遗忘」里**豁免**（与高重要度同档保护）；主角恒受保护（无需标记）；
* **清理物品 = 两步式**：① 生成**只读计划**（不改任何数据）→ ② 用户确认后才删除；
* **清理范围**：`owner` 非空 且 该 owner **不是关注角色、也不是主角**；
* **不动**：`owner` 为空（未归属）、关注角色/主角名下、以及所有非物品维度。

### 3.3 界面（`应-53` / `应-54`）

* 角色行：`☆ 关注` / `⭐ 已关注` 按钮（`data-ftt-action="watchToggle"`）+ 行首 `⭐ 关注` 徽标；编辑器加「关注」勾选框；
* 物品页：工具行 `🧹 清理未关注角色的物品` → 预览卡（`ui/preview-card.js`：逐条 `剔除` 行 + 数量/位置备注 + 保留/未归属统计 + `✅ 确认清理` / `取消`）；
* 确认走中央危险闸（`DANGER_ACTION_PROMPTS['itemsCleanupApply']`），取消不产生任何副作用。

## 5. 风险与边界（如实登记）

| # | 风险 | 处置 |
| --- | --- | --- |
| R1 | `owner` 不进内容哈希 → 跨端仅改归属可能不触发合并 | 按 `id` + 条目 `updatedAt` 合并；清理判定以本端字段为准（用户可在本端重新编辑） |
| R2 | AI 可能编造归属，误把物品挂到未关注角色 | 清理**只列清单、必须人工确认**；未归属一律不动 |
| R3 | 关注档案仍可能被「角色修复 / 融合」改写内容 | 本版只免**清理**；改写属于内容维护（不删除条目） |
| R4 | 面板体量 | 全部逻辑在新模块；面板仅接线（基线 3716，仍远低于 3985） |
