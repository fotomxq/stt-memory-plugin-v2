## 1. 两个必须解决的接线问题

V1 的归一化内核（逐字移植进 `core/`）按 V1 全局读取 `cfg.*`、`state.*`，而 V2 里：

1. **配置**：内核视图 `core/model/runtime.js#cfg` 只有少量骨架键，真正的 217 键默认配置在 `core/config.js#defaultCfg`，
   用户配置落盘在 ST `extensionSettings['ftt_memory_v2'].cfg`。→ 需要同步器（§2）。
2. **状态**：内核 `state` 由 `host/chat.js` 注入（P2 已完成）。
3. **注入**：`core/recall.js#buildMemoryBodyForInject` 产出正文，但没有宿主写入路径。→ 需要推送器（§3）。

## 2. 配置同步（`adapters/config-store.js`）

```text
loadKernelCfg()  默认(defaultCfg 217 键) ⊕ 已存(store.cfg) → 内核 cfg 视图（原地写入同一对象）
saveKernelCfg()  内核 cfg 视图 → store.cfg → saveSettingsDebounced()
mergeCfg()       对象递归合并：**已存值优先**，对象缺键补默认，数组/标量整体覆盖
stableStringify() 递归排序键的序列化 —— 「是否需要补写默认值」按它判定，避免键序差异造成无意义写盘
```

- `persist:false` 可只同步不写盘（测试用）；
- 未知键**保留**（用户或未来版本写入的键不会被清掉）；
- 内核 `saveCfg()` 钩子已接到 `saveKernelCfg`（`adapters/store.js#wirePersistHooks`），故设置页改值 → 内核视图 → ST 配置一体。
- 启动时 `index.js#init` 在 `getSettings()` 之后调用 `loadKernelCfg()`，摘要进 `runtime.cfg`（`/ftt` 显示「内核配置：217 键」）。

> V1 的 `loadCfg` 里还有「提示词模板签名 / 旧版本提示词迁移」链（`promptMigrateInfo` / `promptSig` / `applyPrompt*`）。
> V2 是全新安装、无历史模板包袱，故本批**不带**该链；若将来需要导入 V1 提示词，按 `docs/14` 的迁移条目单独补（已登记）。

## 3. 注入推送（`host/inject.js`）

逐字复刻 V1 `buildInjectText()` 与 `pushInject()`：

```text
正文   = core/recall.buildMemoryBodyForInject(query, { charBudget, maxAtoms, maxMemories, countUses:true, inject:true })
包装   = 【FTT记忆注入】标题行 + 区块标记说明行 + 剧情日期口径行 + 可配置「使用说明」(cfg.promptTemplates.injectGuide)
         + 空行 + 正文 + 空行 + 「记忆结束。」
写入   = setExtensionPrompt(INJECT_ID, text, POSITION.IN_PROMPT(0), depth 0, scan false, role SYSTEM)
```

行为口径（与 V1 一致，逐条有测试）：

| 口径 | 说明 | 测试 |
| --- | --- | --- |
| 开关 | `及时分析(timelyAnalysis)` 或 `cfg.injectCurrentPrompt` 任一为真才推送；关闭时**不写空串**（不清掉已有注入） | P4 |
| 并发防护 | 序号令牌：构建期间若发生新调用，过期结果直接丢弃（`reason:'stale'`） | P3b |
| 空构建保留 | 构建为空且存在上一次非空注入 → **不覆盖**（V1 v1.149 修复：一次异常不得清掉记忆） | P5 |
| clearInject | 清空注入并**重置**「上一次注入」记忆 → 之后空构建会真正写空 | P5b |
| 失败姿态 | 任何异常只记录 `lastError`，不抛出、不 abort、不改 chat | P7 |

**有意的一处偏离**：V1 调用 `setExtensionPrompt(..., role=null)`，本实现传 `role=SYSTEM(0)`（ST 默认值）。语义等价、行为可预期；已在此登记，避免后续被当成 bug「修回去」。

## 4. 拦截器接线（`host/interceptor.js`）

`fttGenerateInterceptor(chat, contextSize, abort, type)` 现在在记录统计后：

```text
if (cfg.interceptorEnabled !== false && cfg.injectEnabled !== false) → await pushMemoryInject({queryText:''})
injectedLength = readInject().length
```

**永远不调用 `abort`、永远不修改 `chat`**（硬规则；冒烟 G3 与单测 P6/P7 均断言）。

## 5. 事件侧推送

| 事件 | 动作 |
| --- | --- |
| `USER_MESSAGE_RENDERED` / `CHARACTER_MESSAGE_RENDERED` | 刷新聊天视图 → 异步 `pushMemoryInject()` |
| `GENERATION_ENDED` | 刷新视图 → 防抖保存（P3 次批在此接入提取落库） |
| `CHAT_CHANGED` | 清注入 → 刷新视图 → 重载该作用域容器 → 推送 |
