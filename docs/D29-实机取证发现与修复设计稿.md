## 0. 一页摘要

本稿把 v3.40.6 真机「双向一致性核对」中**实测发现**的 9 项问题立成可开发条目。核对本身给出的是**好结论**：
三层落盘同源（本机副本与服务端主文件**原始字节数完全相同**）、信封校验通过、台账 34/34 可读、体检 0 条异常、
30 条同步记录**没有一条** `localN ≠ remoteN ≠ afterN`。因此本稿的 9 项**都不是「数据已经丢了」**，而是
**「一致性无法被证明 / 诊断信号失真 / 存量旧数据未收口」**——它们的共同后果是：**用户报「同步后情节丢失」时，真机上拿不到可判定的读数**。

| 簇 | 条目 | 性质 | 关键判断 |
| --- | --- | --- | --- |
| ① **一致性基准** | 技-30 主文件基准陈旧 · 技-35 条数口径无单一事实源 | 证据力缺口 | 主文件数据体停在 **14 天前**，每次载入靠分片覆盖；「基准」与「增量」的角色在真机上已经反转，**分片一缺即回落旧版** |
| ② **判定口径与取证面** | 技-31 并集自检判据不成立 · 技-32 待确认项桥读不到 · 技-33 本机层废弃路径固定失败 · 技-34 读取台账 miss 口径 | 诊断可信度 | 自检把「去重 / 墓碑 / 上限裁剪」都算成「并集异常」→ **误报**；而真正的丢失又**无法与误报区分**；同一批噪声还污染了读取台账 |
| ③ **存量与状态收口** | 数-28 陈旧快照分片不回收 · 数-29 无聊天归属的存量情节与台账标记 · 应-22 关于页更新状态陈旧 | 工程卫生 | 均为「不影响当前读写、但会让诊断与界面长期说假话」的存量项 |

**本稿新发现九项**（`docs/D17` 原未登记）：主文件数据体长期滞后且每次载入走分片覆盖（技-30）·
跨端合并自检判据不含去重/墓碑/上限三种合法削减（技-31）· 待确认项与记录无只读出口（技-32）·
本机层对已废弃命名空间路径每次载入成对读失败（技-33）· 读取台账 `miss` 与 `fail` 口径不一致（技-34）·
同一份状态存在四个互不相等的「条数」口径（技-35）· 本地快照分片文件数 ≥ 链长（数-28）·
存量无聊天归属情节与台账标记未收口（数-29）· 关于页更新检查状态停在旧版本（应-22）。

## 2. 现状核对（只读，逐条带真机证据）

> 证据出处：`docs/D13` §8.10（本轮真机读数）· `docs/D13` §8.7（前一轮五项回填）· `docs/D13` §8.9（取证通道 BUG）。
> 下列「实测」均为 **v3.40.6 运行态**读数，**不含正文**。

| # | 条目 | 实测证据 | 判定 |
| --- | --- | --- | --- |
| 1 | **技-30** 主文件基准陈旧 | 三次载入（相隔约 50 分钟）的对账记录均为「**主文件滞后 → 用 14 个更新的分片覆盖对应维度**」；`mainAt = 1790434998045`（≈ **14.07 天前**）而 `shardAt` 持续推进（最新 1791650191718）；`解析主文件` 三次的 payload 指纹完全一致（`14e6owc_h5et5s` / 202,674 B），整信封通道字节数却在变（7.39 → 7.48 MB） | **异常**：基准不刷新，分片成为唯一真相；分片缺失/损坏时该维度**静默回落 14 天前版本**（载入只提示「主文件滞后」，不提示「维度退版」） |
| 2 | **技-31** 并集自检判据不成立 | 真机日志：`{"action":"合并自检","atomsBeforeLocal":115,"atomsBeforeRemote":20,"atomsAfter":20,"conflict":0,"unionMin":115}` → 按现判据登记「并集自检异常」；而合并实现本身还会做**内容去重**（`contentDedupeArray`）、**墓碑过滤**（`applyDeletedToArray`）、**上限裁剪**，三者都会合法地让 `after < unionMin` | **判据不成立**：必然误报；且**真丢失与三种合法削减无法区分** —— 用户报的「同步后情节丢失」因此在真机上无法判定 |
| 3 | **技-32** 待确认项桥读不到 | `core/conflicts.js` 有 `listConflicts` / `conflictsSummary` / `pendingConflictCount`，`ui/debug.js` **未登记任何相关只读方法**（桥方法表里没有） | **取证面缺一块**：一致性告警（含上条误报）是否仍挂着、是否被确认过，**真机上读不到** |
| 4 | **技-33** 本机层废弃路径固定失败 | 每次载入/取证都成对出现：`通道读取失败 · fft_v2_store-ftt2-local-<作用域>.json · 原因：miss` 与 `通道读取失败 · fft_v2_store/ftt2-local-<作用域>.json · 原因：miss`；同时 `ftt.localDir` 报的是**这条已废弃路径**（`writes 0 / reads 0 / misses 1 / fileBytes 0`），而真实本机层是浏览器内置目录（`writes 198 / 机制 browser-opfs`） | **诊断误导 + 台账噪声**：固定失败被计入「服务端文件 失败 N」，真失败会被淹没 |
| 5 | **技-34** 读取台账 `miss` 口径不一致 | `ftt.reads.stats = {miss: 1}`，而台账里明确有 **≥ 2 条** `通道读取失败 … reason: "miss"`（这些被计入 `fail`，不计入 `miss`） | **口径不一致**：用 `miss` 判断「本机层是否可用」会得到相反结论 |
| 6 | **技-35** 条数口径无单一事实源 | 同一份状态同时存在四个数字：同步口径 **465** · 体检 `items` **488** · 本机层 `localItems` 与主文件解析 **482** · 读取台账「内存态」**479** | **证据力缺口**：用户与开发者都**无法用一眼读数**判断「两边是否一致」；技-31 的判据分歧正源于此 |
| 7 | **数-28** 陈旧快照分片不回收 | `parts.snapshots = {count 28, files 28}` 而内存链长 `snapshots = 27`；更早时点出现 `files 39 / count 39` 对链长 25、`files 17 / count 16` 对链长 25 | **存量堆积**：本地目录保留不再属于当前链的分片文件（还原口径与体积口径不一致） |
| 8 | **数-29** 无聊天归属的存量数据 | `plotScope`：20 条情节中 **5 条无 `chatKey`**（`legacy 5`）、`overflow 10`、`originGone 15`；台账：**32 / 34 条标记无 `chatKey` 与时间戳**（`marksLegacyNoChat 32`） | **存量风险**：跨聊天时钟残余（与 `docs/D16` 同族），只登记与补归属，**不删** |
| 9 | **应-22** 关于页更新状态陈旧 | `update.state.lastResult = {current: "3.40.0", remote: "3.40.1", status: "newer"}`、`hasUpdate true`，而运行版本是 **3.40.6** | **界面说假话**：关于页在版本已最新时仍显示「有新版本」，直到下一次 24 h 检查 |

**核对中确认「不是缺陷」的两项**（避免误记，`docs/D17` §3 口径）：
① 顶层 `keywords` 全为空是**设计**（模型把 keywords 并入 `tags`，召回同时匹配两者，抽样 60/60 印证）；
② 注入统计里的「无关键词 · 无关键词可用 → 已降级」是**查询侧**无可用关键词时的**如实降级**，且已显示在推送统计里。

## 3. 缺陷逐一完善

### 3.1 一致性基准簇（技-30 / 技-35）

- **技-30**：先**取证定性**（只读）—— 把「主文件候选选取结果」与「载入时实际采用的基准时间」暴露出来（`via` / `mainAt` / `applied` / `reason`），
  据此判定是**候选选取仍有漏**（与 v3.40.2 修过的「陈旧明文主文件」同族）还是**主文件按设计只写基准**；
  定性之后才决定是「刷新基准」还是「明确分片为唯一真相 + 维度退版告警」。**未定性前不得改写入时序**。
- **技-35**：立**单一事实源** —— 给出一个「一致性指纹 + 条数」读数（同一份状态、同一口径），
  并让同步日志、体检、本机层诊断、读取台账**都指向它**；四个口径各自**标注语义**（哪些维度计入、是否含墓碑/货币/名册）。

### 3.2 判定口径与取证面簇（技-31 / 技-32 / 技-33 / 技-34）

- **技-31**：自检下限改为「并集下限 − 墓碑命中 − 内容去重命中 − 上限裁剪命中」，
  并在日志里**分别回报三个削减量**；只有**修正后**仍低于下限才登记待确认项，且待确认项文案给出**该维度的削减明细**。
- **技-32**：调试桥**只读**登记 `ftt.conflicts` / `ftt.conflictLog`（待确认项与记录），并把「待确认数」并进 `sys.info`；
  文档层同步 `docs/04` 调试页区块与 `docs/README.md` §3 的方法数口径（**不写死数字**）。
- **技-33**：本机层**停止对已废弃命名空间路径的读探测**（或在诊断中明确标为「旧路径 · 已停用 · 不参与判定」），
  `ftt.localDir` 改为报**真实生效层**（浏览器内置目录 / 宿主原生通道）并附「已停用路」清单。
- **技-34**：读取台账统一「未命中」与「失败」的计数口径（同一条记录只进一个桶，并在文本台账里写清原因类别），
  补一条反向探针：构造 `reason=miss` 的记录后 `miss` 计数必须 ≥ 1。

### 3.3 存量与状态收口簇（数-28 / 数-29 / 应-22）

- **数-28**：快照分片写入时**回收不属于当前链**的分片文件（按当前链指纹比对，只删本地派生文件，**不动记忆数据**），
  并让 `parts.snapshots.count` 与内存链长在读数上**可解释**（若确有「根 + 增量」差异，就在读数里写明）。
- **数-29**：为无 `chatKey` 的存量情节与台账标记**补归属或登记为「升级前历史数据」**（只读判定 + 幂等补写），
  并在体检里保留一条**可读计数**；`overflow` 类保持现有降级展示口径不变。
- **应-22**：关于页在**本地版本不低于远端**时**不再显示**「有新版本」；陈旧 `lastResult` 按「已过期」显示并注明时间，
  让「本机已是最新」与「远端更新」两种状态不再互相冒充。
