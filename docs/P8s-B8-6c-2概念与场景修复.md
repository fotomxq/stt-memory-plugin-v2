## 2. 与 V1 的差异（逐条明示）

1. **AI 通道**：V1 自建 OpenAI 兼容请求（`callChatCompletion`）；V2 走注入钩子 `core/ai-hooks.js#aiCallText`（酒馆 `generateRaw`），采样与连接由酒馆预设控制。
2. **任务管线 UI 未移植**：V1 的 `pipeStart`/`pipeUpdate`/`pipeEnd`/`abortTick`/`newTaskStart` 在 V2 不存在；互斥改为 `aiBusy()`，重绘由 UI 层负责，AI 不可用时如实回报。
3. **通知与日志**：`notify(kind, title, text)` 经 `notifyHooks.toast`（与 `core/repair.js` 同款写法）；V1 `notify('repair', …)` 的 toastr 类型为 `warning`，V2 取等价 `'warning'`（文本逐字符一致）；`dbgLog` 类别沿用 V1 口径。
4. **`opts.aiText` 注入点**：`runConceptRepair(opts)` / `runSceneRepair(opts)` 支持显式传入 AI 返回（与 `runRepair`/`runMemoryRepair` 同约定），缺省走 `aiCallText`。
5. **场景重建的落盘时机**：V1 在重建后调用 `saveState()` 并 `renderPanel()`；V2 由内核统一 `saveState`，面板重绘交给 `ui/panel.js`。
6. **黄金样本的场景差异**：本批两份 fixture 由各自 oracle 场景生成（与 B8-6c-1 的样例不同），**数值不可跨批次互相引用**，只与各自 oracle 对齐。
