## 1. 目标 / 非目标

### 1.1 目标

1. **① 最短 + 最大间隔**：同一全量操作在 `minMs` 内重复发起 → 拒绝（`too-soon`，用户显式动作可 `force`）；
   距上次成功超过 `maxMs` → `overdue` 与 `scanOverdue()` 如实提示（**只提示不自动跑**）；
2. **② 如实记账**：`items` / `dims` / `ms` / `hits` / `remaining` 逐项落账，**不含正文**（与 `数-31` 的只读读数同口径）；
3. **③ 单次上限 + 分批留痕**：超过 `capItems` → `needMore` + `batches` 计数（不丢计数、不吞「没扫完」）；
4. **④ 不阻塞注入**：本模块只做记账与闸门，不发起扫描、不 `await` 任何 I/O；
5. **`技-29`**：A 案下 10 行删除口径**逐条对账**并留下代码证据。

### 1.2 非目标（明确不做）

* **N1 不做 B 案**（冷热分层 / 上限改热集 / 冷存不参与召回）——`D28` Q3/Q7 未选 B，做了会改变可见结果；
* **N2 不改数据模型**：读数是**运行期内存储账**，不写 `state`、不涉 `DATA_VERSION`；
* **N3 不做 `技-38` 的扫描收敛**（变更集驱动 / 世代缓存 / 游标分批），本稿只做**节流与可观测**；
* **N4 不做 `技-2` 主载体切换**（独立批次，见 §6 Q4）。

## 3. 方案

### 3.1 新模块 `core/scan-throttle.js`（唯一闸门与读数源）

| 导出 | 作用 |
| --- | --- |
| `SCAN_OPS` / `SCAN_DEFAULTS` | 四类操作登记（各自 `minMs` / `maxMs` / `capItems`）；未登记操作按默认并标 `known:false` |
| `scanBegin(op,{force})` | 闸门：`ok` / `too-soon` / `running`；返回 `runId` 与参数 |
| `scanChunk(op,runId,{items,dims,hits})` | 累加；超 `capItems` → `needMore` + `batches` 留痕 |
| `scanEnd(op,runId,{items,dims,ms,hits,remaining})` | 落账（环形保留 ≤ `SCAN_KEEP`，只存计数与时长） |
| `scanStatOf` / `scanStats` / `scanStatsText` / `scanOverdue` | 只读读数（单操作 / 全部 / 一行文本 / 到期列表） |
| `setScanHooks({now})` / `resetScanStats()` | 时间源注入（测试）与清空 |

### 3.2 接线（四类全量操作，各 2–4 行）

| 操作 | 落点 | 记账内容 |
| --- | --- | --- |
| `nsfwScan` | `core/nsfw.js#nsfwScan` | 扫描条目 / 维度 / 耗时 / 命中条目 |
| `dataHealth` | `core/data-health.js#dataHealthReport` | 体检扫描条目 / 维度 / 耗时 / finding 代码数 |
| `repairScan` | `core/repair.js#runRepairMech` | 扫描条目 / 耗时 / 修复命中 |
| `relations` | `core/relations.js#deriveRelations` | 扫描条目 / 耗时 / 派生边数（`truncated` = 余量事实） |

**节流不改变结论**：闸门只拒绝**重跑**；同一份数据「被节流」与「未被节流」的派生结果逐字一致（单测 F3 锁）。

### 3.3 只读出口

* 桥方法 **`ftt.scanStats`**（`ui/debug.js#buildBridgeMethods`）→ 桥方法数 **61 → 62**；
* 同步登记 `core/debug-catalog.js#BRIDGE_FTT`（只读清单）· `tests/unit/debug-bridge.test.js#B6`（快照断言）· `docs/README` §3（62）。

### 3.4 `技-29`：A 案 10 行对账

B 案专有行（#2/#3/#4/#5 的「改移出热集」）**不做**；`docs/D26` §6 Q3「软阈值」口径补记 A 案结论（不改口径）。

`docs/D22` §3 批次表：`技-38` ← `数-26` + `技-28`（**单向**）；`技-28` 的前置改为 `数-31` · `数-32`（去掉 `技-38`），
并在 §4.6 / §4.10 两处注释写明「原为成环，v3.50.28 修正」。

## 4. 风险与对策

| # | 风险 | 对策 |
| --- | --- | --- |
| R1 | 闸门误伤用户显式操作（如手动「体检」） | 面板/命令动作传 `force:true`；后台重复发起才按 `too-soon` 拒 |
| R2 | 读数污染存储或泄露正文 | 纯内存 + 只存计数与时长；单测 B2 断言序列化后无正文相关字样 |
| R3 | 节流改变结果 | 闸门只拒重跑；单测 F3 断言「被节流 vs 未节流」结果逐字一致 |
| R4 | 未登记操作拼错被当合法 | `known:false` 如实标出（单测 E3） |
| R5 | 注入被阻塞 | 模块不发起扫描、不 await；单测 F4 断言注入构建不受影响 |
| R6 | 体量棘轮 | 逻辑落新模块，四处接线合计 ≤ 12 行 |
