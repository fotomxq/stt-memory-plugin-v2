## 2. 与 V1 的偏差（**逐条明示**，不含假实现）

1. **通道收敛**：V1 有「统一存储抽象 + 多后端」（本机 localStorage/IndexedDB、存档变量 settings、服务端文件、世界书、
   插入楼层），V2 为「本机缓冲（localStorage/IndexedDB）+ 服务端记忆文件」两型。因此 V1 的
   「存储治理（分类 → 载体 → 后端 → 策略）」与「TauriTavern 原生存储 `api.extension.store`」两节在 V2 存储页
   **只呈现为说明行 + 同名配置键**（`storage.tauriNative` / `storage.tauriMirror`），不做伪造的多后端视图。
2. **世界书存储**：V1 的「词条镜像（类目常驻 + 原子分层重建、变更后延迟自动同步）」依赖世界书写入能力，
   属 B8；V2 存储页保留全部同名配置键（含触发方式/位置/深度/概率/黏性/冷却/延迟/上限）并明示「属后续批次」，
   世界书选择框暂为空列表（无宿主读取能力时不臆造世界书名）。
3. **文件名与编码**：V1 为 `ftt-state-<slug>-<scope8>.json.gz`（主文件 gzip）；V2 延续既有 `ftt2-` 前缀与
   **明文 `.json`**（主文件仍为 `ftt2-state-<slug>.json`，不改名以免孤立已写出的文件），备份/快照/清单/日志为
   `ftt2-bak|snap|meta|log-<slug>-<scope8>.json`。写入不瘦身（V1 的 `slimEntryForStorage` 属独立优化，未移植 →
   **不丢数据，仅体积更大**）。
4. **楼层哈希门控**：V1 `latestFloorFingerprint()` 取「最新楼层正文」后调用 `hashFloorText(text)`，而该函数只接受
   **楼层号**（内部 `getChatMessages(Number(i))`），实际比对一个与目标楼层无关的哈希 → 门控在真实环境几乎恒为
   「有差异」。V2 按 V1 **注释所述语义**实现为 `{f: 最后楼层号, h: hashFloorText(f)}`（即「楼层号 + 该楼正文稳定哈希」），
   使门控真正生效；此为**有意修正的偏差**，黄金样本仍记录 V1 字面值以便追溯。
5. **同步占用管线**：V1 的「同步中」顶部提示与长任务互斥管线（`syncBusy*`）未移植；V2 的做法是长任务在途时
   **拒绝/推迟**同步（`crossSyncManual` → `blocked`，`refreshFromServer` → `blocked`，自动对账 → 跳过），
   避免并发读写同一份记忆数据。
6. **定时同步**：与 V1 v1.134 一致 —— **无周期心跳、无启动追平、无刷新后延迟全量**；只在「保存后（3s 防抖）」
   与「启动一次对账」触发，另外保留手动「刷新状态 / 立即同步」。

## 3. 同步日志（最近 30 条 · 可追溯「双端不同步」）

- 记录字段：`ts` / `src`（本端源头：设备·浏览器(短码)·平台）/ `action` / `mode` / `changed` / `ms` /
  `localN`+`localBytes` / `remoteN`+`remoteBytes` / `afterN`+`afterBytes` / `localHash`+`remoteHash`+`afterHash` / `note`。
- 持久化：本机 `localStorage` 键 `ftt2_SyncLog_<scope8>`（环形保留 30 条）；开启 `storage.syncLogServer` 时
  1.5s 防抖镜像到服务端 `ftt2-log-<slug>-<scope8>.json`，走「读 → 交叉合并 → 仅在更全时回传」路径
  （**绝不整份覆盖**，避免抹掉对端记录）；清空时本机与服务端镜像同时置空。
- 服务端通道失败（未登录 / 401/403 / 公共部署无权限）→ 本会话停用并只提示一次，功能静默回退纯本机。

## 4. 流量保护（两级门控）

| 门控 | 判据 | 命中后的行为 |
| --- | --- | --- |
| 楼层哈希差异 | 最新楼层「已归档且哈希一致且该指纹已同步过」 | 自动对账**直接跳过**（零网络请求；`why: same`） |
| 镜像推送签名 | 原子聚合哈希 + `vars`/`state`/`protagonist`/`stats`/`deleted` + 摘要数 + 快照数未变 | 不重复写回远端（`mode: 推送(门控)` 记入日志） |
| 清单(meta)预判 | 远端文件级哈希 / 快照链签名 == 本端上次已合入值 | 跳过大文件下载；命中时仅推送本端内容（`mode: 推送(清单命中)`） |

开关：`cfg.syncTrafficGuard`（**顶层键**，与 V1 同名同位置，默认 `true`）、`cfg.storage.syncMetaProbe`（默认 `true`）。
「立即同步」「刷新状态」为手动入口，**不受门控**（保留全量同步能力），且会绕开文件读缓存取真值。
