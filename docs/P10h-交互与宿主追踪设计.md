## 1. 问题定性：为什么「只有异常」等于没有线索

用户报的痛点是三个具体缺失，本批按「先约定、再实现、后门禁」的顺序解决：

| 缺失 | 现象（改造前） | 后果 |
| --- | --- | --- |
| 缺**交互起点** | 只有业务日志（提取/注入/落盘），没有「用户点了哪个按钮」 | 报错时不知道该操作是谁触发的 |
| 缺**跨层链路** | 面板 → 钩子 → 宿主 API → 内核是黑盒 | 「点了没反应」无法定位断在哪一层 |
| 缺**代码位置与上下文** | 异常只有 `message`，无站点、无前序事件 | 只能靠猜，无法追到 `file:line` |

因此本批**不替换** V1 业务日志（`core/debug-log.js` 的「提取/注入/异常」等分类照旧），而是**叠加一层可追溯事件流**：
业务日志回答「业务上发生了什么」，追踪时间线回答「**谁**在**哪一行**调用了**什么**，**结果**如何、**多久**」。

## 2. 约定（三层事件流 + 三条硬要求）

### 2.1 三层事件流（分类固定，不许随意扩张）

`core/trace.js` 导出 `TRACE_CATS = ['ui','host','cmd','kernel','ai','error']`，一行一类，语义如下：

| 类别 | 记录什么 | 典型 `kind` | 关键字段 |
| --- | --- | --- | --- |
| `ui` | **用户交互**：点击 / 控件变更 / 切页 / 面板开关 | `click` · `change:<配置键>` · 动作名（如 `analyze`） · `panel-open` | `detail.target/attrs`（点了什么）· `detail.params`（入参摘要）· `detail.note`（用户可见结果） |
| `host` | **插件 ↔ 宿主**：一切经 `getCtx()` 的宿主 API 调用 | 宿主方法名（如 `generateRaw`） | `detail.args/ret` · `ms` · `ok/reason` |
| `cmd` | **命令与入口**：`/ftt*` 斜杠命令、宏、`FTT.*` 调用 | 命令名 / 入口名 | `detail` 摘要 · 结果 |
| `kernel` | 落盘 / 载入 / 注入等内核动作 | 动作名 | 结果摘要 |
| `ai` | AI 调用（提示词、用途、返回） | 用途名 | 长度/结果（**不落正文**） |
| `error` | 异常（脚本错误 / 未处理拒绝 / 动作失败） | `未处理的 Promise 拒绝` 等 | `reason` · `site` · **上下文窗口** |

> 新增类别需同时改 `TRACE_CATS`、`TRACE_CAT_CAP`、`ui/debug.js` 的筛选按钮与本文档 —— 三处一处不改即视为缺陷。

### 2.2 硬要求 A：`opId` 关联（谁触发的，必须能回溯）

- 交互 / 命令 / `FTT.*` 入口**入口处**调 `traceOpStart(name)` 开一个 op，退出（成功或异常）必须 `traceOpEnd(op, result)`。
- `core/trace.js` 内部维护 **op 栈**：op 执行期间产生的 `host/kernel/ai/error` 事件**自动带上该 opId 与 op 名**，
  调用方无需手工传递；嵌套 op 记录 `parentId`。
- 于是「某条宿主调用/某个报错是**哪个按钮**触发的」= 按 `opId` 反查首条 `ui` 事件即可。
- 代价与约束：op 栈有 32 层上限兜底（异常路径未闭合 op 不会无限增长）；`traceOpEnd` 幂等（重复调用返回 `null`）。

### 2.3 硬要求 B：`site` 代码位置（file:line:fn，且必须是**调用方**）

- 每条事件从 `new Error().stack` 解析出**本仓库内第一帧**。解析必须吃下两种栈形态：
  ① `at fn (file:line:col)`；② 无函数名的裸帧 `at file:///…/a.js:12:5`（V8 常见）。
- 过滤规则：跳过 `core/trace.js` 自身帧、跳过非 `.js/.mjs/.cjs` 帧（`node:internal` 等）；
  **包装层由调用方显式加入跳过表**（如 `host/st-api.js`、`host/events.js`）——否则站点会指向包装层而不是真实调用者。
- 站点文本统一 `file:line[:fn]`，路径只保留末两段（`core/trace.js` / `ui/panel.js`），便于肉眼比对与贴图。
- 反例（本批修掉的真缺陷）：裸帧曾因正则贪婪把 `col` 当 `line`，站点显示成错误的行号 —— 现由单测 B7/B8 锁死。

### 2.4 硬要求 C：错误的**上下文窗口**（不再只有一条孤立异常）

- 任何错误事件在写入时同步计算 `traceContext(id, TRACE_CONTEXT_SPAN=20)`：
  **前后各 20 条事件**（时间正序）+ **同 opId 的全部关联事件**（可超出窗口）。
- 上下文随错误一起进入调试日志条目：`traceId` / `site` / `opId` / `op` / `context.window` / `context.related` / `how`。
- 调试页对错误行**默认展开**并直接渲染上下文文本；导出调试包内含完整时间线，可直接贴给维护者。

## 3. 其它硬约定（体积、隐私、稳定性）

| 约定 | 取值 | 理由 |
| --- | --- | --- |
| 分级 | `error < warn < info < debug < trace`（`traceLevels`） | 低于 `cfg.debugLevel` 的事件**零成本早退**；默认 `debug` |
| 分类上限 | `ui 200 · host 300 · cmd 100 · kernel 100 · ai 100 · error 100` | 单类不会淹没其它类（实测 host 灌 350 条不挤掉 ui） |
| 总量上限 | `TRACE_TOTAL_CAP = 800` | 内存恒定，不随会话增长 |
| 单条上限 | `TRACE_ITEM_MAX = 2000` | 超长 `detail` 截断为 `{note:'[截断]'}` |
| 去重 | 同类同 kind 同摘要，`TRACE_DEDUPE_MS = 800` 内合并为 `×N` | 高频点击/轮询不刷屏；超窗口重新计数 |
| 脱敏 | 键名含 `key/password/secret/token/authorization` → `***`；值以 `sk-`/`Bearer` 开头 → `sk-***` | 导出包可安全外发 |
| 正文 | `prompt/content/text/messages/body/data` 只记**长度**（`debugTraceVerbose` 可放开，默认关） | 追踪不得成为剧情正文的第二份副本 |
| 持久化 | 只把最近 **120 条简报**（id/at/cat/kind/ok/opId/site）交给 `adapters/trace-store.js` 落盘 | 刷新后仍有线索；细节只在内存，避免存储膨胀 |
| 稳定性 | `traceEvent` 永不抛；任何内部失败静默降级 | 追踪绝不能影响主流程（单测 J 组 + smoke AS5） |

## 4. 落点（每一层改了什么）

| 文件 | 改动 |
| --- | --- |
| `core/trace.js` | 引擎：事件写入/列表/统计/上下文/时间线文本/清空/钩子；**纯内核**（仅依赖 `core/model/runtime.js`） |
| `adapters/trace-store.js` | `SPreset_FTTMemoryTrace` 落盘/载入/清空（内核不碰宿主存储） |
| `host/st-api.js` | `getCtx()` 返回**缓存 Proxy**：只包函数属性，调用时再读原函数；记录方法/参数/返回/耗时/失败，站点取真实调用者 |
| `host/events.js` | `errPush` 同时写 `error` 追踪事件，并把 `traceId/site/opId/context/how` 附进异常日志条目 |
| `ui/panel.js` | 点击（含 `data-ftt-*`）、控件变更（含旧值→新值）、面板开合入流；`panelAction` 全程 op（入参摘要 + 结果 + 耗时） |
| `ui/commands.js` | `/ftt*` 命令与宏统一经 `tracedCommand/tracedMacro` 包装（回调改 async，调用方可 await） |
| `ui/debug.js` | 调试页新增「🧭 交互与宿主调用时间线」区块（类别筛选 + 错误行展开上下文 + 清空）；导出包加 `traceStats/trace/timeline` |
| `index.js` | `FTT.trace/traceList/traceTimeline/traceStats/traceContext/traceClear/traceSite` 等入口；`panelRuntimeHooks` 单源接线 |
| `core/config.js` + `ui/settings-pages.js` | 调试页新增 4 个开关：`debugLevel` · `debugTraceUi` · `debugTraceHost` · `debugTraceVerbose`（+ 原 `debugEnabled`） |

## 5. 门禁（防回归）

| 门禁 | 覆盖 |
| --- | --- |
| `tests/unit/trace.test.js`（63 断言，A–J 组） | 结构/级别/统计 · 栈解析（含裸帧与缓存串）· 脱敏与截断 · 去重 · opId 关联（含嵌套与上限）· 三类上限 · 上下文窗口 · 开关 · 时间线 · 永不抛 |
| `tests/smoke-test.js` AS1–AS5 | 真实点击入流（含 `data-ftt-*`）· 宿主调用站点=调用方且同 op 带 opId · 异常带 `traceId`+上下文窗口 · 调试页区块与导出包 · 两个分类开关只拦自己的类别 |
| 既有门禁 | `npm run gate`（内核纯净度 / 标识符 / 词条 / 版本 / 文档 / 单元 / 冒烟）全绿 |

**本批修掉的真缺陷**（非新功能）：

1. **栈解析把列号当行号**：无函数名的裸帧（`at file:///…:12:5`）站点行号错误 → 正则重写为「先按形态分组、再逐字段取名」，单测 B7/B8 锁死。
2. **点击事件级别过高**：原始 `click` 事件此前是 `trace` 级，默认级别下**被丢弃** → 「用户点了什么」这一链条起点消失；改为 `debug` 级，默认可见（smoke AS1 断言）。

## 6. 不做什么（边界）

- **不替代** V1 业务日志：`提取/注入/落盘` 等分类与 V1 口径不变，追踪是叠加层。
- **不落正文**：剧情文本、AI 提示词与返回只记长度/摘要；需要全文请用既有的调试包 `dump` 与业务日志。
- **不做远程上报**：一切留在本地内存 + 120 条简报落盘；导出是**用户主动**动作。
- **不改业务判定**：追踪只观察、不参与分支（`traceEvent` 返回 `null` 时调用方路径完全不变）。
