## 4. 业-6 行为口径（用户当轮裁决：一律剧情时间）

**用户裁决**（2026-10-10）：平行事件与传言的衰退基准**一律改用剧情时间**，与 `01` §2.2 / `02` §3.3 的表述逐字一致。

### 4.1 行为口径

| # | 口径 |
| --- | --- |
| P1 | 所有域的时间衰退**一律以剧情时间为基准**：基准时刻取**剧情时钟当前日期**，条目时刻取**条目自身的剧情日期**（状态记录 / 记忆 / 平行事件 / 传言四域统一） |
| P2 | 剧情日期到毫秒的换算沿用既有约定：以 2000 为基准、公元前日期得负值并照常参与，**不得**把负值当作「无时间信息」丢弃 |
| P3 | **无剧情时钟时不衰退**：基准时刻取不到即**保持条目**（与 `core/forget.js#memoryForgetScore` 既有行为一致，四域统一） |
| P4 | 阈值、比例、开关**一律不变**（`cfg` 的 `parallelDecayCutoff` / `rumorDecayCutoff` / 各 `*Ratio` / 各 `*Enabled`）。本口径只改**基准**，不改**强度** |
| P5 | 计算函数**收敛为单一实现**：以 `core/ingest.js#calcTimeDecay` 为标准件，消除 `core/recall.js#calcTimeDecay` 的私有副本（避免同一算法两处漂移，见 K11） |

### 4.2 副作用与对策（必须与体积治理一起看）

P3 会让「没有剧情时钟的存档」四域**都不衰退**。而 `D13` §4 已记 `plotSegments` / `summaries` / 墓碑 / 本机缓冲压缩留存**仍未封顶**，
`D16` A8 / A9 实测落盘约 **28.5MB/角色**、墓碑数达存活条目的 **5 倍** —— 因此**不能把体积兜底押在时间衰减上**。口径：

| # | 口径 |
| --- | --- |
| S1 | 时间衰减只负责「按剧情推进自然淘汰」；体积的硬兜底一律走**上限 + 收敛触发**（`02` §3.3「条目数 > 上限 × 比例时触发清扫」） |
| S2 | 「无剧情时钟」这一状态应在**数据体检里可见**（新增或复用发现码，报告各域「因缺少剧情时钟而未参与衰退」的条目数），让用户知道数据为何没被清理 |
| S3 | 体积治理的其余部分（副本分层、墓碑回收、快照真增量）归 `D16` P1（`D17` U92–U94）；实施顺序上应**先于或同时于**本口径落地 |

### 4.3 偏离登记（`docs/D15` §3 类别②：实现缺陷修复 → 登记三件套）

| # | 登记项 | 内容 |
