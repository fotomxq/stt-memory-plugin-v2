# P10l · 「剧情第 N 天」不允许注入（仅供插件内校准时间，v2.48.0）

> 文档版本：v1.0 ｜ 日期：2026-09-26 ｜ 状态：生效（v2.48.0）
> 触发（用户原话）：「**剧情第N天，不允许注入，这个设定只是在插件内校准时间用的。**」
> 涉及：`core/recall.js`（注入体 `[当前状态]` 块） · `ui/clock.js`（总览展示标注） ·
> `tests/unit/storyday-no-inject.test.js`（新） · `tests/fixtures/v1-golden-storyday-inject.json`（新，含生成器） ·
> `tests/smoke-test.js`（AX1） · `tests/unit/clock-extract-golden.test.js` · `tests/unit/recall-golden.test.js`

---

## 1. 问题定性（**V1 故障明确修正 #6**）

V1 v1.206（11943）把 `剧情天数:第N天` 拼进注入体的 `[当前状态]` 块：

```text
[当前状态]
日期:1919-11-25
时间:傍晚
剧情天数:第500天      ← 这条不该注入
地点:城市甲·码头
```

「第 N 天」是**插件内部的时间计数**（正文头 `▶第 N 天` 解析而来），不是剧情世界里的说法：
① 它每轮都占注入预算；② AI 可能把它当成可引用的设定写进正文；③ 它不可被故事解释
（角色不会说「今天是第 500 天」）。用户明确要求：**不允许注入**，该值只在插件内用于**时间校准**。

oracle 证据：`tests/fixtures/v1-golden-storyday-inject.json`（生成器 `gen-v1-golden-storyday-inject.cjs`，真实 V1 v1.206）——
`A.bodyHasStoryDay = true`、`A.storyDayLine = "剧情天数:第500天"`，即 V1 确实注入了它。

## 2. 修复范围

| 位置 | 处理 |
| --- | --- |
| `core/recall.js` 注入体 `[当前状态]` | **删除** `剧情天数:第N天` 一行（其余行不动，顺序仍为 日期 → 时间 → 地点 → 在场角色） |
| `state.state.storyDay` | **照常记录**（提取/落盘/巡检都不变）—— 它是校准与诊断用的内部值 |
| `clockStoryDayEpoch`（纪元首日）校准 | **不变**：无其它日期来源时按「纪元首日 + (N-1) 天」换算日期（`source.date = 'storyday'`） |
| 总览（`ui/clock.js`） | 仍展示该值（便于核对锚点），但标签改为 **`📆 校准用：剧情第 N 天（仅用于日期换算，不注入）`** |
| 投喂/世界书/AI 提示词 | 本就不含该值（复核：全仓库 `storyDay` 仅出现在提取与校准路径，唯一注入点即上面那一行） |

**为什么保留总览展示**：该值是「纪元首日 + 天数」校准算式的输入，锚点错时用户需要在总览里核对它；
展示 ≠ 注入 —— 面板是插件自己的界面，不参与提示词。

## 3. 门禁

| 门禁 | 内容 |
| --- | --- |
| `tests/unit/storyday-no-inject.test.js`（10 断言） | **O 组** oracle 自证（V1 注入体含该行；V1 设纪元首日后能把 500 天换算成 `1921-03-14`）· **N 组** V2 注入体不含「剧情天数/第N天」（仅 storyDay / 全字段 / 含约束段三种组合）· **P 组** V1 的其余 `[当前状态]` 行逐条保留（不误删）· **C 组** 内部校准不受影响（`resolveStoryClock` 仍记 storyDay；`clockStoryDayEpoch` 换算与 V1 同值）· **U 组** 总览展示带「校准用 · 不注入」标注 |
| 冒烟 **AX1** | 走**真实注入通道**（`injectNow()` → `ctx.extensionPrompts`）：注入体里没有「第N天」，日期/时间/地点/在场角色齐全，`state.state.storyDay` 仍为 17602 |

既有断言更新：`clock-extract-golden.test.js` U1 与冒烟中总览文案由 `📆 剧情第 N 天` 改为
`📆 校准用：剧情第 N 天（仅用于日期换算，不注入）` —— 值本身仍逐字断言，只是标签更明确。

## 4. 边界（不做的事）

- **不删除** `state.state.storyDay`：校准与巡检仍需要它（删了会让「第 N 天」正文头失去意义）。
- **不改** 正文头解析（`▶第 N 天 08:52->09:05`）：起止时间仍照常提取注入前的**时间**（时间属于剧情信息）。
- **不注入** 该值的任何等价说法（例如「第 X 日」「day N」）：门禁用正则 `第\s*\d+\s*天` 兜住中文写法；
  若将来出现别种写法，按同一约定加入该测试。
