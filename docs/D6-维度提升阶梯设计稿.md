# D6 · 维度提升阶梯设计稿（人工把衍生提升为情节）

> 文档版本：v0.1 ｜ 日期：2026-09-27 ｜ 类型：**设计稿（不发版）** ｜ 状态：草稿（待评审）
> 触发（用户原话）：「人工可以保持提升到情节，例如平行现在就有这个能力，后续给其他也追加层层递进的提升。」
> 前置：`D2`（边与约束）、`D4`（联动传播）、`D5`（优先级与锚定：**情节是唯一事实锚，衍生不得回写**）
> 定位：提升是 `D5` §5.3 中**唯一合法**的「低权威 → 高权威」通道。本文把它从「平行转正」这一个特例，
> 扩展为**通用、逐级、可人工确认**的阶梯能力。

---

## 0. 一页摘要

| 项 | 内容 |
| --- | --- |
| **提升是什么** | 把某维度的「推测 / 意图 / 认知」条目，经**人工确认**，落成一条**情节**（事实锚）—— 产生新事实，而不是修改旧事实 |
| **为什么要人工** | `D5` A2/M1：衍生层**永远不得改写 `atoms` 正文**。若允许自动提升，等于给 AI 开了回写事实的后门 |
| **现状** | 只有一条路径：**平行事件 → 情节**（`core/parallel.js:498-548`，v1.196 起） |
| **要做** | ① 把提升抽成**通用契约**（幂等 / 证据 / 原条处置 / 留痕 / 回退）；② 按**层层递进**开放到更多维度；③ 统一 UI 入口与预览 |

## 1. 现状核实（提升契约的既有雏形）

`core/parallel.js#promoteParallelEvent(id, opts)`（`:498-548`）已经隐含了一整套契约，值得原样继承：

| 环节 | 现有做法 | 行号 |
| --- | --- | --- |
| **前置校验** | 正文 ≥ 8 字（原子层要求）；过短时用标题补足 | `:503-507` |
| **字段映射** | `title / text`、`type`（默认「转折」）、`date / time`、`entities ← characters`、`locations ← location`、`tags`（取前 5）、`importance`（默认 0.6） | `:512-522` |
| **幂等** | 若已提升过（`promotedTo` 指向既有情节）→ **原地更新**该情节，不重复新建 | `:510-511`、`:523` |
| **留痕** | 先写 `promotedTo` / `promotedAt`，再移除原条 | `:527-534` |
| **原条处置** | **移除原平行条 + 走 `deleteEntry` 墓碑**（防跨端合并复活） | `:535-546` |
| **历史兼容** | `prunePromotedParallels()` 载入时清理旧版"软标记"残留 | `:551-553` |
| **入口** | 面板动作 `promoteParallel`（需确认） | `ui/panel.js` |

**已知 V1 怪癖（逐字保留）**：`:530-532` 的 `(getStoryNow() || {}).date` 恒为 `undefined`（`getStoryNow()` 返回字符串）→ 实际总是回落到 `state.state.date`。

**结论**：通用化不必另起一套 —— **把上表的 7 个环节抽成通用入口**，各维度只提供「映射与前置条件」。

## 2. 提升阶梯模型

### 2.1 定义

```text
提升（Promotion）= 人工确认 ① 某条衍生条目所描述的事「已经发生」；
                  ② 以它为来源，写入一条情节（atoms）；
                  ③ 建立 derived-from 边（新情节 ← 来源条目）；
                  ④ 按规则处置来源条目（保留标记 / 移除留墓碑）。
```

### 2.2 三级阶梯（「层层递进」）

| 级 | 名称 | 路径 | 语义 |
| --- | --- | --- | --- |
| **一级** | **直提** | `memories` / `currentStates` / `items` / `plans` / `suspense`（+ 可选 `scenes` / `concepts`） → `atoms` | 这些条目描述的是**已发生或当下**的事，只差"确认为事实"这一步 |
| **二级** | **阶梯** | `rumors` → `parallels` → `atoms` | 传言是**未证实信息**，直接成事实跳跃过大 → 先落成一条**推演候选**（平行事件），再由人确认转事实 |
| **三级** | **合成** | 多条同源条目（如同一事件的若干角色记忆、若干条传言） → **一条**情节 | 避免同一事实在事实层碎裂成多条；`sourceRefs` 汇总全部来源 |

**递进规则**：默认**逐级**（低权威只能升到相邻次高层）；**允许跳级**（如传言直接提到情节）但必须在界面上**明确标注风险**（跳过的确认环节）。

### 2.3 为什么必须人工（设计不变量）

| # | 不变量 | 说明 |
| --- | --- | --- |
| P1 | **不自动提升** | AI / 机械派生**永不**触发提升；只有用户动作（按钮 / 命令）可触发 |
| P2 | **不覆盖** | 提升**只新建**情节，**不修改**任何既有情节正文（幂等情形除外：同一来源重复提升 → 更新自己上次生成的那条） |
| P3 | **不丢源** | 来源条目的信息必须完整进入新情节或被 `derived-from` 边保留；移除来源时先写墓碑与留痕 |
| P4 | **可追溯** | 每条被提升的情节都能回答「从哪来」（`derived-from` 边 + `sourceRefs`）与「何时、被谁提升」 |

## 3. 通用提升契约（7 环节）

| # | 环节 | 通用规则 | 各维度差异 |
| --- | --- | --- | --- |
| 1 | **触发** | 仅人工：条目操作列「⬆ 提升为情节」/ 命令 / 多选批量 | 无 |
| 2 | **前置校验** | 内容长度（原子层 ≥8 字）、必要字段齐备、来源未被提升过（或允许幂等更新） | 各维度字段要求不同 |
| 3 | **证据要求** | 必须携带锚点：来源条目 id + 剧情日期或楼层；**无锚点不允许提升** | 由维度字段推导 |
| 4 | **字段映射** | 生成 `atoms` 草稿（`text` 必填，`title / type / date / time / entities / locations / tags / importance` 尽力填） | 见 §4 规格表 |
| 5 | **写入** | 走 `upsertEntry('atoms', raw)`（复用既有落库与墓碑口径） | 无 |
| 6 | **原条处置** | 三选一，按维度默认：`removed`（移除 + 墓碑，**平行现状**）/ `promoted`（保留 + 标 `promotedTo`，默认不注入）/ `kept`（保留且继续注入） | 见 §4 |
| 7 | **留痕与回退** | 关系层写 `derived-from` 边；来源条写 `promotedTo` / `promotedAt` / `statusNote`；**整轮操作前后可回退**（快照链） | 无 |

**幂等键**：`source: {dim, id}`。同一来源二次提升 → **更新上次生成的那条情节**（沿用现平行转正的幂等口径），不产生重复事实。

## 4. 各维度提升规格表（14 维度）

| 维度 | 开放 | 提升条件（人工确认时展示） | 默认原条处置 | 字段映射要点 |
| --- | --- | --- | --- | --- |
| `atoms` 情节 | **不适用** | 已是事实锚 —— 需要的是**编辑**，不是提升 | —— | —— |
| `snapshots` 角色档案 | **不开放** | 身份是持续状态，不是事件 | —— | —— |
| `currentStates` 状态记录 | ✅ | 状态被事实固定（如「左臂骨折」）且已稳定若干轮 | `promoted` | `field + value` → `text`；`subject` → `entities` |
| `memories` 长期记忆 | ✅ | 记忆已被事实支撑（有日期 / 有来源情节） | `promoted` | `title + content` → `title / text`；`owner` → `entities` |
| `items` 物品 | ✅ | 物品的获得 / 失去 / 转移已发生 | `promoted` | `name + qty + location` → `text`；`owner` → `entities` |
| `currencies` 货币 | **不参与** | 独立账本，不属叙事事实 | —— | —— |
| `plans` 计划 | ✅ | 计划到达终态（完成 / 受阻 / 放弃） | `promoted` | `content + progress + history` → `text`；`participants` → `entities` |
| `suspense` 悬念 | ✅ | 悬念揭晓（`resolveCondition` 满足） | `promoted` | `content + clues` → `text` |
| `scenes` 场景 | ⚠️ 可选 | 场景**确立 / 转移**作为事实 | `promoted` | `name + pathStr + desc` → `text` |
| `concepts` 概念 | ⚠️ 可选 | 概念被确认为设定事实 | `promoted` | `name + content` → `text` |
| `parallels` 平行事件 | ✅ **（现有）** | 人工确认该推演已成事实 | **`removed`**（写入后移除 + 墓碑） | 见 §1 |
| `rumors` 传言 | ✅ **二级** | 传言被证实 | `promoted`（先经平行 → 情节亦可） | `subject + content + chain` → `text`；`carriers` 可入 `entities` |
| `plotSegments` 分段总结 | **不参与** | 归档内容，不注入 | —— | —— |

**开放度小结**：开放 **8 个**（其中 `scenes` / `concepts` 标为可选）、不开放 2 个（`snapshots` / `atoms` 不适用）、不参与 3 个（`currencies` / `plotSegments`）。

## 5. 提升与关系层

| 产出 | 说明 |
| --- | --- |
| **`derived-from` 边** | 新情节 → 来源条目（`D2` §3.2 的 10 类边之一）。反向查询即可回答「这条情节从哪来」 |
| **`sourceRefs`** | 写入新情节的引用字段（`D2`/`D4` 的反向索引来源），使跨端与后续联动都能找到来源 |
| **提升链** | 二级阶梯产生 **多条** `derived-from`（情节 ← 平行 ← 传言），形成可追溯的提升链 |
| **约束校验** | 提升前用 `D5` 的裁决链做一次校验：若新事实与**更高权威**的既有事实互斥（`exclusivity`）→ 提示而非静默写入 |
| **联动** | 提升写入后**触发 `D4` 的传播**（新情节 = `atoms.confirm` 事件）→ 相关的平行 / 传言 / 计划自动迭代（这正是用户要的「归一到情节」） |

## 6. UI 与交互

| 入口 | 说明 |
| --- | --- |
| 条目行操作列「⬆ 提升为情节」 | 各开放维度的条目行统一出现（沿用现平行页「⬆ 转正为情节」的位置与确认弹窗口径） |
| 提升预览 | 弹窗内展示**将生成的情节草稿**（可改标题 / 正文 / 日期 / 类型），再确认写入 |
| 批量提升（三级合成） | 多选模式勾选多条同源条目 → 「⬆ 合并提升为情节（N）」，`sourceRefs` 汇总 |
| 命令 | 例如 `/ftt-promote <dim> <id>`（便于脚本化与排障） |
| 来源可见 | 情节条目的行内展示「来源：传言『…』→ 平行『…』」链路，并可点回原条（若已保留） |
| 撤销 | 提升后的情节可删除（走既有删除 + 墓碑）；快照链可整轮回退 |

## 7. 分阶段落地

| 阶段 | 范围 | 交付 | 回退 |
| --- | --- | --- | --- |
| **P0** | **抽通用契约**：把 `promoteParallelEvent` 的 7 环节抽成 `promoteToAtom(source, opts)` 通用入口，平行路径改为调用它（**行为不变**，纯重构 + 专测锁定现状） | 通用接口 + 回归测试 | 恢复原函数 |
| **P1** | **一级直提**：开放 `currentStates` / `memories` / `items` / `plans` / `suspense` | 5 个维度可提升 + 预览弹窗 | 逐维度开关 |
| **P2** | **二级阶梯**：`rumors → parallels → atoms`（传言先落推演，再转事实）；写 `derived-from` 提升链 | 传言可提升 | 关阶梯 |
| **P3** | **三级合成**：多选批量提升为一条情节（`sourceRefs` 汇总 + 去重） | 批量提升 | 关批量入口 |
| **P4** | **可选维度与联动收口**：`scenes` / `concepts`；提升后自动触发 `D4` 传播 | 全景提升能力 | 逐项开关 |

> **P0 的价值**：先证明「通用化不改变平行转正的现有行为」（黄金样本 + 冒烟），再逐步开放其他维度 —— 避免一次性改动事实层写入路径。

## 8. 风险与待确认

| # | 风险 | 对策 |
| --- | --- | --- |
| R1 | **事实层被污染**（提升出低质量情节） | P1 人工触发 + 预览确认 + 前置校验（长度 / 证据 / 锚点）；无锚点不允许提升 |
| R2 | 同一事实重复落成多条情节 | 幂等键 `{dim, id}` + 三级合成 + `derived-from` 边去重 |
| R3 | 来源被移除后信息丢失 | 移除前先写留痕与墓碑（沿用平行口径）；默认处置 `promoted`（保留）而非 `removed` |
| R4 | 提升与 `D5` 裁决冲突 | 提升前按裁决链校验；互斥时**提示而非静默写入** |
| R5 | 跳级提升（低权威直接 → 事实）质量差 | 允许但需显式标注风险；默认引导逐级 |
| R6 | 改动事实层写入路径影响既有行为 | P0 先纯重构 + 回归锁定；`upsertEntry('atoms', …)` 口径不变 |

### 待确认

| # | 问题 | 建议默认 |
| --- | --- | --- |
| Q1 | `scenes` / `concepts` 是否开放提升？ | 开放但标记为「可选 / 低优先」（P4） |
| Q2 | 默认原条处置：`promoted`（保留不注入）还是 `removed`（如平行）？ | 非平行维度用 `promoted`；平行保持 `removed`（既有行为不动） |
| Q3 | 是否允许**撤销提升**（把情节退回来源层）？ | 不做自动回退；用删除情节 + 快照回退覆盖 |
| Q4 | 批量合成的上限与去重口径？ | 单次 ≤ 12 条（沿用 `planRefsMax` 量级），按内容哈希去重 |
| Q5 | 提升是否需要「反向操作」审计（谁在何时提升了什么）？ | 需要：写 `promotedAt` + 调试日志（无需新容器） |
