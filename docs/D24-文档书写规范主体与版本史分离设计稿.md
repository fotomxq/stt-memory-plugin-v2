## 0. 一页摘要

用户指出的问题**成立且已被量化**：`docs/` 下的现状层与设计稿把**同一功能的多个版本口径并列写在正文里**，读者无法判断哪个是基准。

| 文档 | 正文里的 `vX.Y.Z` 出现次数 |
| --- | --- |
| `04-应用架构.md` | **102** |
| `02-数据架构.md` | **79** |
| `D13-存储层级与界面成本上限核对.md` | **49** |
| `D12-楼层骤减的数据安全与删除操作设计稿.md` | **37** |
| `D9-UI统一规范设计稿.md` | **36** |

**教科书式反面例**（`04-应用架构.md` §2.2「存储」行，**一个表格单元里 13 个版本号**，其中「本机缓冲」被描述四次、两条相互矛盾）：

| 同格内的说法 | 版本标注 |
| --- | --- |
| 本机缓冲按 1.8M 字符预算判定，**超预算如实跳过并留痕** | `（v3.1.0）` |
| 本机缓冲改写宿主的本地目录，变量层与内存库都不写也不读 | `（v3.16.0 / v3.26.0）` |
| 本机缓冲改为「压缩留存」，**超预算不再丢本机层** | `（v3.26.2）` |
| 载入顺序里的「本机缓冲（或本地目录文件）」 | `（v3.16.0 / v3.26.0）` |

> 第 1 条与第 3 条**直接矛盾**（超预算到底"跳过"还是"不丢"）。读者必须按版本号大小自行推断现行口径 —— 这正是用户所说的**致命**处：**文档不再是单一事实源，而是一份需要考古的变更日志。**

**本稿给出四条硬规范**（§3）：**正文＝唯一基准** · **附录＝版本变更史** · **冲突判定顺序** · **禁止写法清单**；
并把它编入 `开发守则.md` §2.2 / §2.3（与设计稿规范同处），配套 `docs/D14` 的新判据 **C11** 使其可机检。

## 1. 目标 / 非目标

### 1.1 目标

1. 确立**正文＝当前生效设计的唯一基准**，使读者/执行者**无需读版本史**即可正确理解与实施（§3.1）；
2. 确立**附录＝版本变更史**的留痕格式，保证改动多次的功能**仍可追溯**（§3.2）；
3. 给出**冲突判定顺序**，消除"到底以哪个为准"的歧义（§3.3）；
4. 给出**禁止写法清单**与**可机检判据 C11**（§3.4 / §3.5）；
5. 给出**存量重排**的分级方案：自相矛盾的优先、单纯堆叠的排期（§4）。

### 1.2 非目标（明确不做）

- N1 **不改任何代码 / 不动版本号 / 不打 tag**（设计轮次，`开发守则.md` §1）；
- N2 **不删除任何历史信息** —— 版本史一律**移入附录**（或已在 `docs/history/` 与 `CHANGELOG.md` 的，改为指向），**不作删除**；
- N3 **不重写 `docs/history/` 与 `CHANGELOG.md`**（只增不改）；
- N4 **不改版本号规则**（`D14` §4 的「只在 `3.XX.XX` 上追加」不变）；
- N5 **不要求一次性重排全部存量文档** —— 按「触及即合规」棘轮，但 §4 的 **P0 级**（正文自相矛盾）除外。

## 3. 方案（规范条文）

> 适用范围：`docs/` 下的**现状架构层**（`01`–`05`）、**设计稿层**（`D1`–`D24`）、**专项层**。
> **不适用**：`docs/history/**`（只增不改的留痕）、`CHANGELOG.md`（本来就是版本史）、**台账类**（`D17` / `D22`，其性质就是逐条状态记录）。

### 3.1 条文 A：正文 = 唯一基准（Current Truth）

| # | 条文 |
| --- | --- |
| A1 | 正文（**附录之前的全部章节**）**只描述当前生效的完整设计与行为**。判据：一个不知道任何版本历史的人读完正文，就能正确理解并实施。 |
| A2 | 正文里出现版本号**只允许一种用法**：标注某项口径**自哪一版起生效**（形如 `（vX.Y.Z 起）`）。**禁止**在正文叙述"旧口径是什么、后来改成了什么"。 |
| A3 | 同一功能在正文里**只允许一处主描述**；其它位置只写引用（`见 §X`），**不得复述**。 |
| A4 | 正文中同一功能**不得出现相互否定的两种说法**；一旦发现，视为**文档缺陷**，登记 `docs/D17` 并限期修正（不得靠读者推断）。 |

### 3.2 条文 B：附录 = 版本变更史（Traceability）

| # | 条文 |
| --- | --- |
| B1 | 凡某项功能在 **≥2 个版本**里改动过，本文档**必须**有 `附录 · 版本变更史` 章节。 |
| B2 | 附录按版本**倒序**逐条记录：`vX.Y.Z（日期）` → **改了什么** → **为什么**（用户原话 / 缺陷）→ **证据**（`CHANGELOG.md` 条目或 `docs/history/P*`）。 |
| B3 | 附录条目**只作追溯**，**不得**与正文冲突。冲突时**以正文为准**，并立即修附录。 |
| B4 | 正文**不得**以"详见附录"代替对当前行为的说明（附录不能当口径依据）。 |
| B5 | 附录的存在**不降低正文要求**：读者不看附录也必须能正确实施。 |

### 3.3 条文 C：基准判定（冲突时以哪个为准）

| # | 场景 | 判定 |
| --- | --- | --- |
| C1 | **同一文档内**：正文 vs 附录 | **正文为准**（B3） |
| C2 | **跨文档**：见 `开发守则.md` §2.4 | 权威顺序：**用户当轮明确要求 → `docs/D*` 设计稿 → `docs/01`–`05` 现状层 → V1 实现** |
| C3 | **跨维度**（同上位阶时） | 见 `开发守则.md` §2.5：**业务 ≻ 应用 ≻ 数据 ≻ 技术** |
| C4 | **正文内部仍"一事两说"** | 不判定为"以某条为准" —— 判为**文档缺陷**：登记 `docs/D17`、按 §4 的 P0 级修正。**不允许读者自行推断** |
| C5 | **代码 vs 文档** | 现状层以**代码实测**为准（`docs/01` 的事实源优先级）；设计稿描述**目标态**，未落地部分标明 |

### 3.4 条文 D：允许并列的三种例外（必须显式标注）

| # | 例外 | 标注要求 |
| --- | --- | --- |
| D1 | **现状 vs 目标** | 显式分节标「现状」/「目标」（如 `03` §9.1 与 §9.3）。**不得**用版本号堆叠代替 |
| D2 | **候选方案** | 标「候选 A / 候选 B」，并写明**尚未裁决**及其裁决入口 |
| D3 | **有意偏离 V1** | 按 `docs/D15` §3 类别②的**登记三件套**（设计稿标注 + 勘误表 + 测试判据）；**不进现状层正文** |

### 3.5 条文 E：禁止写法清单

| # | 禁止 | 例（反例） | 应改为 |
| --- | --- | --- | --- |
| E1 | **链式否定**：同句/同格堆叠 ≥2 个版本号并含「改为 / 不再 / 修正为 / 取代」 | 「按 1.8M 判定，超预算跳过（v3.1.0）… 改为压缩留存，超预算不再丢（v3.26.2）」 | 正文只写现行：**超预算走压缩留存**；两条沿革进附录 |
| E2 | 同一表格单元**重复描述同一功能** | 一格内出现 4 次「本机缓冲…」 | 一处主描述 + 其余引用 |
| E3 | 用「（vX 口径）」当**并列标签** | 「（v3.26.5 口径）」「（v3.26.0 起；v3.26.2 改判）」并列 | 标「现行口径」；沿革进附录 |
| E4 | 版本号写进**标题 / 小节名**当限定语 | 「本地磁盘目录（v3.28.0，语义纠正；v3.34.0…；v3.38.0…）」 | 标题不带版本；沿革进附录 |
| E5 | 同一事实在正文**多处**给出不同口径 | `D13` §1/§3.2/§4 与 §8.5 并存 | 正文统一为最新；旧口径移入附录的版本史 |

### 3.6 条文 F：可机检判据（`docs/D14` **C11**）

| 子判据 | 口径 |
| --- | --- |
| **C11-a 附录存在性** | 文档中出现 ≥2 个版本号**且**含沿革语（「起改为 / 不再 / 修正为 / 取代 / 已改」）→ **必须**存在 `附录 · 版本变更史` 章节 |
| **C11-b 禁止链式否定** | 同一行内 `vX.Y.Z` ≥2 个**且**含沿革语 → 报错（E1） |
| **C11-c 标题不带版本** | 标题行（`#`–`######`）内不得出现 `vX.Y.Z`（E4） |
| **C11-d 主体密度阈值** | 附录之前的正文章节，`vX.Y.Z` 密度 ≤ 阈值（初始按**存量基线**定，见 `docs/D14` §7 Q6），**先 warning** |
| **C11-e 反向探针** | 构造一段"链式否定 + 无附录"的正文 → 必须报错 |

## 4. 分阶段落地

| 阶段 | 内容 | 为什么这个顺序 | 验收 |
| --- | --- | --- | --- |

## 5. 风险与对策

| # | 风险 | 对策 |
| --- | --- | --- |
| R1 | 「移入附录」被误做成「删除历史」 | N2 硬性：**只移动、不删除**；已在 `docs/history/` 或 `CHANGELOG.md` 的改为**指向**，不复制 |

## 6. 待确认问题清单

| # | 问题 | 建议默认 | 采纳 / 不采纳的影响 |
| --- | --- | --- | --- |
| **Q1** | 附录章节的**统一名**用什么？ | `## 附录 · 版本变更史` | 不统一：C11-a 无法机检 |

| **Q3** | 正文允许的版本号用法，是否**限定每处最多一个**？ | **是**（`（vX.Y.Z 起）`，最多一个） | 不限定：E1 的判定会变模糊 |

| **Q6** | C11-d 的密度阈值取多少？ | **按存量基线**（实测最高为 `04` 的 102 处），先设宽松值并登记基线，只减不增；不采用绝对值一刀切 | 一刀切：存量文档全部失败 |

## 7. 维度归属与优先级

| 项 | 内容 |
| --- | --- |
| **本篇维度** | **技术（优先序 4，最低）** —— 书写规范属文档工程 |
