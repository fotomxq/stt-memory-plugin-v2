## 0. 怎么读这份台账

| 字段 | 口径 |
| --- | --- |
| **编号** | `U<数字>`，**只增不复用**。条目完成后把「状态」改成 `✅ 已落地（vX.Y.Z）`，**不删行**（与 `docs/history/` 的只增口径一致） |
| **类型** | `功能未实现` / `设计已定待落地` / `待用户裁决` / `待排期` / `未验证` / `已知缺陷` |
| **优先级** | 照抄原文档标注的 `P0`–`P2` 或高/中/低；原文没标 = `未标` |
| **来源** | 「篇 § 章节」；**设计意图以对应 `D*` 稿为准**，本表只登记「尚未落实」这一事实 |
| **状态** | `⬜ 未落实`（默认）/ `🟡 部分` / `✅ 已落地` |

> **与 `docs/README.md` §6「整理进度」的分工**：那张表只记**文档整理**进度（P0–P4）；本表记**功能 / 设计**的未落实事项。
> **与各 `D*` 稿「分阶段落地」表的分工**：D 稿写「打算怎么做」，本表只回答「**现在还没做的是什么**」。
> **与 `docs/D22-开发待办清单.md` 的分工（v1.4 补）**：本表按**来源文档**登记事实（`U` 编号，含文档治理类）；
> `D22` 按**维度序与批次**给**执行视图**（只收四维修订的开发项，并额外要求「版本号 + 更新内容呼应」两列）。**两者销账时必须同时改**。
> **判据**：一条事项若在某处已写「已完成 / 已落地」，**不登记**；只有文档之间对同一事项**互相矛盾**时才登记（见 §4）。
