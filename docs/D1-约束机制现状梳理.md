## 1. 结论速览

今天的「约束」并不是一个层，而是**五种形态分散在五个地方**：

| 形态 | 载体 | 生效位置 | AI 可写 | 跨端同步 |
| --- | --- | --- | --- | --- |
| A **数据关系型** | `state.links[]`（知情关联层） | 注入段生成 / 关系总览 / 修复维护 | 是（AI 输出「关联 / 知情者」数组） | 是（在 `ATOM_DIM_KEYS` 内） |
| B **机械推导型** | `buildInjectConstraints()` | 只作用于注入体（硬约束段） | 否（零 AI、确定性） | 不落库（每轮现算） |
| C **枚举 / 状态机型** | `validity` / `status` / `phase` / `pending` / `promotedTo` / `deceased` | 维度归一 + 召回过滤 + 各域管线 | 部分（AI 可写 `validity`/`status`） | 是（随条目） |
| D **数值上限型** | `cfg.maxStates` / `dimCharLimits` / `charBudget` / `relLinkMax` … | 入库硬截断 + 注入预算 | 否 | 不落库（配置） |
| E **文本提示型** | 提示词模板「硬性约束」条文 / `constraintNote` / `armorPreset` | AI 提示词（软约束，靠模型自律） | 是 | 部分（`constraintNote` 随条目） |

**一句话**：真正的「关系」只有一层，且只连**角色**（谁知道）；原子与原子之间的关系没有层，只有**散落在各维度私有字段里的引用**；而「约束」目前**没有容器、没有类型、没有生命周期、不能校验**。

## 3. 逐类约束盘点

### 3.1 B 机械推导型：注入约束段（今天唯一的「硬约束」）

- 生成器 `buildInjectConstraints()`：`core/recall.js:305`；导出 `core/recall.js:1459`。
- 开关与参数：`injectConstraintBlock`（默认开）、`injectConstraintMaxChars`（默认 400）、`injectConstraintPosition`（tail/head）、`injectConstraintNameAll`（默认只给聚合计数）—— `core/config.js:971-974`。
- 生成内容（`core/recall.js:313-369`）：① 当前在场角色；② 非公共信息逐条点名「记忆/计划/悬念『标题』知情者 = …」；③ 未召回的非公共信息给**聚合计数**（保证约束不随召回丢失）；④ 平行事件恒计为「仅幕后（角色不知情）」。
- 预算：约束段预留 `min(上限, 预算 × 40%)`（`core/recall.js:797`），超限**整段降级**（切在行边界，不足 40 字则整段丢弃）—— `core/recall.js:1194-1213`。
- 覆盖域：**仅 memories / plans / suspense / parallels 四维**（与 `links` 同域）。

> 这是全仓库**唯一**「机械生成、与召回解耦、优先级最高」的约束机制 —— 也是「用约束规范剧情」今天能做到的全部。

### 3.2 C 枚举 / 状态机型

| 约束 | 取值 | 生效点 | 证据 |
| --- | --- | --- | --- |
| 情节有效性 | `validity`: active / inactive / uncertain | 注入候选过滤（inactive 不注入、不作为「最近现场」） | `core/model/atom.js:30`、`core/recall.js:861/1320/1343/1369` |
| 情节已总结隐藏 | `atomIsHidden()`（`mergedSummary`） | 不参与注入 / 淘汰 / 修复 / 质检 | `core/merge.js`、`ui/panel.js` |
| 计划 / 悬念状态 | `status`: open / closed + `phase`（受阻/放弃）+ `statusNote` | 列表默认只列 open；约束段只列非 closed | `core/model/dims.js:207-208`、`:250-251`；`core/recall.js:333/344` |
| 传言变化延迟 | `pending{kind,need,progress,target,at}`：**变化需 N 轮才提交** | 传言机械演化 | `core/rumor-evolve.js:202-232`、`:266/273`；`core/model/rumor.js:31` |
| 传言阶段 / 发酵度 | `stage` / `ferment` | 注入与演化 | `core/rumor-evolve.js:141`（`rumorFermentDelta`） |
| 平行事件转正 | `promotedTo`（转正后不再注入） | 注入过滤 + 约束段 | `core/recall.js:354` |
| 角色已去世 | `identity.deceased` | 角色修复跳过 | `core/model/dims.js`（`SNAP_GROUP_MAP`）、`core/character-repair.js` |
| 角色长生者（**v3.22.0 补充**） | `identity.immortal`（三态，**可编辑**） | 与「已去世」同款**角色修复跳过**（不进名单、机械阶段不改写出生日期 / 年龄） | `core/model/snapshot.js#snapshotImmortal` / `#snapshotRepairSkip`、`core/character-repair.js`（v3.22.0；见 `docs/history/P10c40`） |

### 3.4 D' 时间衰减型

- 通用机制 `calcTimeDecay(earliest, latest, now, itemAt, count)`：**两份实现**（`core/ingest.js:463`、`core/recall.js:609`）。
- 各域开关 / 触发比例 / 移除阈值：
  平行事件 `parallelDecayEnabled/Ratio/Cutoff`（`core/config.js:715-717`）、
  状态 `stateDecayEnabled/Ratio/Cutoff/SubjectYears/StaleYears`（`:719-724`）、
  记忆 `memoryForgetCutoff`（`:727`）、
  传言 `rumorDecayEnabled/Ratio/Cutoff`（`:837-839`）。
- 语义：**剧情时间**（非现实时间）驱动的老化 → 达阈值自动移除（留墓碑）。

### 3.6 演化引擎现状（「约束规范演化」今天长什么样）

| 引擎 | 触发 | 依据什么做决策 | 证据 |
| --- | --- | --- | --- |
| 传言机械演化（零 AI） | 每 N 楼一次（`rumorEveryRounds`），变化需 `rumorChangeNeedRounds` 轮 | 载体耐久老化、发酵度增量、**与平行事件按标签 Jaccard 关联度联动**、概率由 `hashText` 种子决定（两端确定性一致） | `core/rumor-evolve.js:66-72`（轮次）、`:86`（种子概率）、`:114-141`（载体/发酵）、`:152-195`（标签联动）、`:271`（变化发起） |
| 平行事件推演 / 推进 | 用户按钮或被动排程 | AI 生成 `goalOdds[].likelihood`；`sourceRefs` 只允许已成事实的情节/记忆 | `core/parallel.js:163/172/343/405/498`、`core/model/dims.js:103-131` |
| 时钟提取 / 巡检 | 消息后 / 手动 | 只取最新情节；日期异常判据（跳变 / 倒退 / 非法） | `core/clock*.js` |
| 遗忘 / 衰退 | 修复管道 / 载入 | 时间衰退 + 上限（见 3.4） | `core/forget.js` |

**关键观察**：演化决策**几乎不读关系层**（`links`）—— 传言 ↔ 平行事件的联动只用**标签相似度**，而不是「谁知道 / 谁传给了谁 / 谁在策划」。
