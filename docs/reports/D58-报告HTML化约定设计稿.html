① 为什么不能只留 HTML

仓库的门禁与台账体系只解析 Markdown：

机制依赖若改成纯 HTML
C12 台账双向一致（check-ledger-sync.js）只从 docs/D*.md 的「实施规格」收集条目号失守：设计稿条目无法被承接
C5 引用存在性（check-docs-facts.js）只扫 .md 里的反引号路径失守：引用不再被检查
C6 目录树等式只比对 docs/*.md 顶层失守：目录树与磁盘不再可比
D17/D22 台账U 编号与条目行寄生在 MD失守：销账链断裂
结论：本约定不是用 HTML 替换 MD，而是增加一条阅读轨。

② 双轨分工

契约轨 · docs/*.md

实施规格（业-/应-/数-/技-<n>）必须
U 编号必须
门禁解析（C5/C6/C8/C12）唯一可解析
排版 / 效果模拟有限

阅读轨 · docs/reports/*.html

分层排版 / 锚点导航 / 打印友好主战场
界面效果模拟（mockup）界面类必须
重复定义实施规格禁止
参与门禁不参与
一句话：改契约改 MD，给人看改 HTML；两者同一轮一起动。

③ 硬规则

项规则
目录docs/reports/（唯一报告目录，不散落在 docs/ 顶层）
命名docs/reports/<来源 MD 同名>.html —— 例：docs/D57-城镇发展设计稿.md → docs/reports/D57-城镇发展设计稿.html
首页元信息必须含：来源 MD 路径、MD 版本、本 HTML 版本、日期、状态
自包含样式内联；禁止 <script src> / <link rel="stylesheet" href> / CDN / 外链图片（判据见 ⑥ R-3/R-4，按属性判）
可达性语义标签、lang="zh-CN"、无 JS 也能读全
打印纯 CSS 即可打印（@media print 可选）

④ 效果模拟（界面类报告的最低要求）

必须示意

页面落点哪个分页 / 子标签 / 侧栏
信息层级首行标题+徽标 / 中段信息 / 尾段操作（沿用 D55）
状态差异至少两种（有数据/空态，或 正常/异常徽标）

建议与边界

建议：窄屏折叠形态；边界情况（超上限、缺字段）。

边界：mockup 为静态示意 —— 不承诺像素级一致、不含真实交互、数据为虚构样例并标注"示意数据"。

⑤ 更新与迁移节奏

场景动作
新报告类设计稿同轮产出 MD（契约）+ HTML（阅读）
既有 MD 被更新同一轮更新其 HTML；HTML 首页版本随 MD 递增
既有 MD 无 HTML不追溯批量：在该 MD 下一次更新时补出（触及即合规）
MD 删除 / 更名同步删除 / 更名 HTML，并更新 docs/README.md 的 reports/ 行
例外：docs/history/**、CHANGELOG.md、docs/D17·D22 两个台账不要求 HTML（快照 / 机读 / 逐条记录）。

⑥ 校验口径（可机检）

编号判据强度
R-1docs/reports/*.html 文件名必须对应到一份存在的 docs/*.md可机检 · 阻断
R-2报告首页必须出现其来源 MD 文件名可机检 · 阻断
R-3不得含真正的外链引用：按链接属性判定（href="http…" / src="http…" / url(http…）；正文提到协议字样不算可机检 · 阻断
R-4不得含 <script src= / <link rel="stylesheet"可机检 · 阻断
R-5MD 比 HTML 新时给出提示（不阻断）弱判据 · 提示
落地建议：R-1～R-4 做成拟建脚本 scripts/check-reports.js 并入 npm run gate（阻断）；R-5 只提示。
