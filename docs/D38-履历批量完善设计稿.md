## 0. 一页摘要

**问题**：履历（角色档案第 9 区块）已有**个体档**入口 ——「📜 补全 / 修复履历」（v3.45.5，角色行内）。但它**一次只处理一个角色**：
一本有 8–12 个活跃角色的存档，想"整体完善一遍"要点 8–12 次，每次都发一次 AI 请求 —— 这正是用户点名要解决的「AI 反复请求次数」。

**现状（只读核对）**：

| # | 结论 | 证据 |
| --- | --- | --- |
| ① | 个体档一次 = 一个角色 = 一次 AI 请求 | `core/character-repair.js#runResumeRepair`（`aiCallText(prompt, '履历修复')` 在函数体内） |
| ② | 机械段与护栏都已抽成可复用的纯函数 | `core/character-repair.js#resumeMechanicalPassFor` · `core/resume.js#resumeCanonGuard` / `#resumeNormList` / `#resumeStats` |
| ③ | "相关记忆"的命中口径已有先例（按姓名扫各维度） | `core/character-repair.js#characterEvidencePack`（`owner` 相等或正文命中姓名） |
| ④ | 角色页已有平行按钮的落点 | `ui/panel.js#characterRepairButton`（「🧹 修复角色」）+ 行内「📜 补全 / 修复履历」 |
| ⑤ | 新动作必须进管道登记表（v3.46.4 用户要求「全部管道请求类动作」） | `ui/pipe-guard.js#PIPE_ACTIONS` · `docs/D9` §10 **U15** |

**本稿主张**：加**批量档** —— 一个按钮「📜 批量完善履历」，**与「🧹 修复角色」平行**：
① **按近期更新的记忆抽角色**（近期窗口内命中即候选，按命中数排序）→ ② 勾选一批 → ③ **一次** AI 请求处理**整批** →
④ 逐角色机械复核 → ⑤ **只读预览** → 确认后**逐角色落库（只落盘一次）**。

**一句话边界**：**同一套算法、同一套护栏，只把"N 次请求"合成"1 次请求"。**

## 1. 目标 / 非目标

### 1.1 目标

| # | 目标 | 判据 |
| --- | --- | --- |
| G1 | **一次请求处理一批角色**（默认最多 8 名） | 构造 3 名候选 → 只调 `aiCallText` **一次**（桩计数） |
| G2 | **按近期更新的记忆抽角色** | 窗口内 `owner` 命中或正文命中；**窗口外与无日期的不算**（单测断言） |
| G3 | 与个体档**同算法同护栏**，不造第二套 | 机械段复用 `resumeMechanicalPassFor`；**剧情日期**复用 `resumeClockDate`；护栏复用 `resumeCanonGuard` |
| G4 | **不读楼层正文**（不变成提取的旁路） | 打包体不含楼层正文片段（构造唯一标记 → 断言不含） |
| G5 | **零写入直到确认** + 可整轮回退 | 预览阶段 `state.snapshots` 逐字节不变；应用前自动落一次快照 |
| G6 | 上限与截断**如实计数** | 角色数超 `cfg.resumeBatchMaxRoles` 或总字数超限 → `truncated` 计数并提示 |
| G7 | 新动作进管道登记 | `resumeBatchRun` 在 `PIPE_ACTIONS`；E2 快照 24 → 25 |

### 1.2 非目标（明确不做）

| # | 不做 | 理由 |
| --- | --- | --- |
| N1 | 跨批续跑 / 自动接着跑第二批 | 一次点击 = 一次请求 = 一批（可解释、可控成本） |
| N2 | 读楼层正文 | 会与提取通道职责重叠（`docs/D26` 的依据优先级不变） |
| N3 | 改个体档行为 | 个体档是既有交付，本轮**零变化** |
| N4 | 逐角色勾选应用 | 沿用「方案 → 全量应用 / 取消」（与三域联动 / 货币融合一致） |
| N5 | 新增履历字段或改上限语义 | 字段与上限归 `docs/D26` / `core/resume.js` |

## 3. 方案

### 3.1 三步编排

| 步 | 内容 | 落点 |
| --- | --- | --- |
| ① 抽角色 | 近期窗口（`cfg.resumeBatchDays` 默认 30，按**剧情日期**回看）内扫 `state.memories`：`owner` 相同 **或** 标题/正文含角色名即命中；按命中数降序 | `core/resume-batch.js#resumeBatchCandidates` |
| ② 打包 | 每角色一节：档案摘要（身份 / 出身 / 背景资料.经历概览）+ 现有履历（倒序）+ 该角色近期记忆行；**不含楼层正文** | `#resumeBatchPack` |
| ③ 一次请求 | 提示词（新模块 `core/resume-batch-prompt.js`）输出 `{characters:[{name,履历:{新增,凝练}}]}` | `ui/resume-batch.js#resumeBatchRun` |
| ④ 复核 | 逐角色过窄契约（见 §3.2）与护栏 → 预览 | `#resumeBatchValidate` |
| ⑤ 落库 | 逐角色：先机械段（零 AI）→ 并入新增 → 套用凝练 → **只落盘一次** | `#resumeBatchApply` |

### 3.2 窄契约（机械兜底，AI 只提方案）

```json
{"characters":[{"name":"角色名","履历":{"新增":[{"日期":"YYYY-MM-DD","简述":"…","重要性":0.6,"来源":"剧情"}],
                                       "凝练":[{"日期":"…","原简述":"前 12 字","简述":"更短"}]}}],"notes":""}
```

**七条判据**（逐条配反向探针）：

| # | 判据 | 拒收原因 |
| --- | --- | --- |
| 1 | 角色名必须在**本次打包集合**内（精确匹配） | `role-not-packed` |
| 2 | 条目过 `resumeNormList`（日期 / 简述 / 来源可识别） | 归一后丢弃 |
| 3 | **不得晚于当前剧情日期**（`resumeCanonGuard`，原作人物同样适用） | `canon-after-clock` |
| 4 | 凝练**必须更短**且 ≤ 简述上限 | `condense-not-shorter` / `condense-too-long` |
| 5 | 凝练定位（日期 + 原简述前 12 字）必须命中既有条目 | `condense-no-hit` |
| 6 | 单轮每角色新增 ≤ `min(履历上限, 12)` | `over-role-cap` |
| 7 | 至少有新增或凝练之一，否则该角色无操作 | `no-op` |

> **辨析（本稿写作时纠正的一处口径，如实登记）**：**原作人物允许**写「剧情前生平」（这正是 `snapshotResumeCanonFill` 的用途），
> 真实约束是**不得晚于当前剧情日期**（`resumeCanonGuard` 的判据）。实现轮第一版把这条写反（"原作人物不得补剧情前生平"），
> **被自己的单测抓住**（`B1` 的正例失败）后改正 —— 保留此注以免后人再写反。

### 3.3 上限与落盘

- **上限语义沿用个体档**：校验器只守"单轮每角色 ≤12 条"；"超过履历上限（默认 30 条）"仍由**应用前的机械段**按「重要性 × 剧情时间」清算
  → 满额角色**也能补全**（先清算、再并入；与 `runResumeRepair` 的顺序一致）。
- **仅落盘一次**：`resumeBatchApply` 在所有角色处理完后调一次 `saveState()`（桩计数 = 1 的单测锁死）。
- **留痕**：`state.resumeBatchLog`（末 5 条、runtime、不跨端）+ `dbgLog('摘要', {action:'履历批量完善（一次请求）', …})` + 面板提示行。

### 3.4 与个体档的边界

| 面 | 个体档（行内「📜 补全 / 修复履历」） | 本档（「📜 批量完善履历」） |
| --- | --- | --- |
| 触发范围 | 该角色 | 近期窗口内被记忆命中的一批角色（可勾选） |
| 请求数 | 1 角色 = 1 次 | **1 批 = 1 次** |
| 算法 / 护栏 | `resumeMechanicalPassFor` + `resumeCanonGuard` | **同一套**（复用同一函数） |
| 入口位置 | 角色行内 | 角色页工具行，与「🧹 修复角色」平行 |

## 5. 风险与对策

| # | 风险 | 对策 |
| --- | --- | --- |
| R1 | 一次请求塞太多角色 → 超上下文或质量下降 | `cfg.resumeBatchMaxRoles`（默认 8）+ 总字数上限（超限**如实截断**）；提示词逐角色分节，输出按角色名分键 |
| R2 | AI 编造不存在角色的履历 | 判据 1（角色名必须在打包集内，精确匹配） |
| R3 | 写进"未来"的事 | 判据 3（`resumeCanonGuard` + 剧情日期；日期未知时提示词禁止写"来源：原作"条目） |
| R4 | 凝练把日期 / 重要度改坏 | 凝练只允许改 `summary`，且必须更短（与个体档逐条一致） |
| R5 | 与个体档行为分叉 | 共用函数（机械段 / 时钟 / 归一 / 护栏 / 统计）；单测断言共用同一机械段 |
| R6 | 重复点击烧请求 | 进 `PIPE_ACTIONS`（v3.46.4 守门：开工提示 + 同动作排重 + 在途禁用）；另加幂等签名（同方案跳过） |
