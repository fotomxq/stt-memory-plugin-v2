## 1. 缺口

跨端分歧横幅（`设定 → 存储`）原先只有两个**覆盖型**选择：

| 选项 | 语义 | 代价 |
| --- | --- | --- |
| 保留本地（覆盖对端） | 本端推送覆盖对端 | **对端的差异全部丢弃** |
| 采用对端（整体替换） | 本端替换为对端数据 | **本端的差异全部丢弃** |

两者都会丢数据（故都在 D9-U4 危险动作清单里，需二次确认）。用户要求补上第三项：
**合并差异 —— 将对端下载后合并去重**（两端都不丢）。

## 2. 实现

### 2.1 UI（`ui/sync.js#divergenceBannerHtml`）

```text
⚠️ 跨端同步分歧 · 请选择保留哪个版本
本地 3 条（更新 2026-09-28 12:00:00）／ 对端 2 条（更新 …）· 时间差 1.0s · 仅本端 1 / 仅对端 1 / 冲突 1
[保留本地（3 条）] [采用对端（2 条）] [🔀 合并差异（下载对端后去重合并）]
合并差异 = 下载对端 → 并集去重（同 id 按时间取新，删除墓碑生效）→ 写回服务端；两端数据都不丢。
```

- 前两项**逐字保持 V1 黄金（含无 `title` 属性）**—— 黄金样本比对不破；
- 新增按钮带 `title`「下载对端后并集合并去重 —— 两端数据都不丢（推荐）」+ 一行说明（含 `title` 的按钮不在黄金比对范围内）。

### 2.2 动作（`ui/sync.js` → `adapters/sync.js`）

| 步骤 | 落点 |
| --- | --- |
| ① 取出并**立即清空**待选（V1 同口径：无论成功与否都不重复处置同一份待选） | `crossPendingView()` / `crossPendingGet()` / `crossPendingClear()` |
| ② **下载对端 + 并集去重**：`applyRemoteMergeToState(env)` —— 按 id 对齐、同 id 按时间取新、双墓碑生效、非原子容器整侧取较新 | `adapters/sync.js` |
| ③ 写回服务端（主文件 + 备份 + 快照 + 清单） | `storageWriteAll(storageEnvelope(state))` |
| ④ 留痕 + 提示 | `syncLogPush({action:'分歧选择', mode:'合并差异(下载对端去重合并)'})` + `syncToast('success','已合并差异','两端数据都不丢，合并结果已写回服务端')` |

- **无待选**时与另两个处置动作同口径：留痕 `未找到待选对端`（`changed=false`）+ 警示提示 + **不改动本端**（不拿本端信封自合并假装成功）；
- `changed` 如实：`!!(r && r.mode !== 'same')`（两端本就一致时记 `false`）；
- 动作进 `SYNC_ACTIONS`（**8 → 9 项**），经面板分发与 `panelAction` 可达。

### 2.3 为什么不进危险动作清单（D9 U4 / 检查项 C7）

覆盖型两项会**丢弃**另一方的差异 → 二次确认；「合并差异」是**并集去重**，两端数据都保留（且冲突按更新时间取新），
**没有不可逆后果** → 直接执行，不弹确认框。此口径由 `parallel-design.test.js#B1b` 锁定
（`DANGER_ACTION_PROMPTS` 不含 `'syncPickMerge'`，`DANGER_ACTIONS` 仍为 24 项）。

### 2.4 与 v3.0.3「自动合并」的关系

v3.0.3 起**自动路径**（保存后镜像 / 立即同步）遇分歧已一律自动下载合并，正常使用中不会出现待选；
本项是分歧横幅的**显式选择**能力，用于：① 处置**旧版本遗留**的待选；② 任何人工注入/兜底场景。
两个入口的合并语义**完全同源**（同一个 `applyRemoteMergeToState`），不存在两套合并规则。
