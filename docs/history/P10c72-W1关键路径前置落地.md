## 2. `技-1` ready 守门（细节见 `CHANGELOG.md` v3.40.4 ①）

* **内核守门**（`core/model/runtime.js`）：`setWriteGate` / `writeGateClosed` / `noteWriteBlocked` / `takeWriteGatePending` / `writeGateInfo` / `resetWriteGate`；
* **三条口径**：① 载入开始关、结束（成功**或失败**）开（失败也放行，交既有**异常缩水守卫**兜底）；② **20s 安全阀**（超时自动放行并如实计数，绝不静默卡死写入）；③ **不丢数据**（被挡下的保存记 `pending`，开闸方补跑一次）；
* **覆盖面**：`saveStateNow`（唯一漏斗：状态文件 / 分片 / 快照 / 原生通道）+ 流水线之外的直调入口（`stateFileWrite` / `snapshotFilePushNow`）；
* **验收**：`tests/unit/load-gate-write.test.js` 11 项，含**「载入未完成即保存 → 零写入 + 留痕」**与**「开闸后正常落盘」**两条主判据。

### 2.1 一起被修正的 4 个既有用例（契约变更，不是放宽判据）

`load-align` / `local-copy` / `perf-caps` / `save-all` 都 `await import('../../index.js')` —— 而 `index.js` 有**模块级装配副作用**
（多触发 + 有限轮询 → `init()`），**装配期间守门是关着的**（新行为正确），这些用例却在未等载入结束时就断言保存成功。
现改为：**先等这一次装配落定（`init()` 返回）再复位守门**，并写明「本用例直接注入 state、不复现首屏时序」。
**这正是把「载入窗口不可落盘」这条新契约写进测试** —— 若日后有人把守门去掉，这些用例不会报错，但 `load-gate-write` 会。

### 2.2 与参考实现的一致性（`技-8` 的副产品）

参考实现 `ST-BaiBai-Book` 的 `src/api/settings.ts` **正是**「守门挂在写入路径」的形态：
`let ready = false;` → `watch(apiSettings, () => { if (!ready) return; persist(); })`（注释：「hydrate 前不回写,防止默认值覆盖服务器设置」），
且未就绪时**直接返回、稍后重试**。本版守门与之同构 —— 这条**旁证**是 `技-8`「读参考实现关键路径」的直接产出。
