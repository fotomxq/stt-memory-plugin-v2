## 1. 复核方法

不重新设计，只对着 v3.36.0 的新结构逐条**反推边界**：「老数据会怎样 / 事后能否追溯 / 什么时机接线」，
每条都用**可复现的证据**判定是否成立（能用命令或单测复现 → 才登记为缺陷）。核对范围：

| 面 | 问题 | 结论 |
| --- | --- | --- |
| 老数据 | v3.35 及更早写进 `syncConflicts` 的「删楼 / 楼层收缩 / 跨端分歧」，在新语义下是 `mode:'log'` | **缺陷 S1**（界面出现无动作的行 + 白占徽标） |
| 可追溯 | 「确认」是否留下痕迹 | **缺陷 S2**（清完即无据可查） |
| 接线时机 | 冲突 / 记录钩子何时接上 | **缺陷 S3**（没开过面板 → 通知丢失） |
| 去重键 | `kind + detail` 会不会把不同事实并成一条 | 有意为之（重**保真**轻降噪），不改，见 §4 |
| 记录上限 | 记录只按**条数**封顶（20 类），不按时间淘汰 | 可接受，见 §4 |
| 调试日志 | 记录类写 `kind='同步'` 的自由文本 | 可接受（调试日志本就是自由文本通道） |

## 2. 三处缺陷与修复

### S1 旧数据会变成「无法处理」的行（数据迁移）

`migrateConflicts()`（`core/conflicts.js`）—— 装配时把**语义已变成记录**的类别从待确认区搬到记录区：

- 明细与计数**原样保留**（`noteLog(kind, detail, count)`，与记录区同 id 记录**合并计数**）；
- **幂等**：搬过之后再跑 `moved === 0`；
- 返回值 `{ moved, kept, log }`，搬动时写一条调试日志（可追溯升级动作）。

界面兜底（`ui/sync.js`）：**任何**待确认项，若该类没有登记动作，一律补一个「✅ 知道了」按钮 ——
即使将来又有类别改语义、或老数据没来得及迁移，也**绝不出现「待确认但无法处理」的行**。

复现（迁移前）：`syncConflicts` 里放一条 `{kind:'删楼'}` → 待确认区渲染出该行，但 `contains conflictAct === false`
（无动作按钮），同时 `pendingConflictCount() === 1`（还占着徽标）—— 正是本缺陷。

### S2 「确认」不留痕（确认也写入记录区）

`resolveConflict()` / `clearConflicts()` 处理一条/一批待确认项时，追加一条**合并计数**的记录
`已确认：<类别> ×N`（走与记录区同一条 `noteLog` 通道、同一 20 类上限）：

- 计数**如实带过来**（类别里合并了 3 条 → `已确认：跨端合并冲突 ×3`，不是 ×1）；
- 动作**被拒绝**时不写记录（只有真的确认才留痕）；
- 批量按钮的提示语据此改为「…；最近记录仍有 N 类（无需确认）」，用户能立刻看到痕迹落在哪。

### S3 钩子只在开面板时才接上（丢失通知）

v3.36.0 的接线写在 `index.js#openPanelPopup()` 里 → **没开过面板**的会话里，跨端合并冲突 / 删楼通知
被写进 `core/conflicts.js` 的默认**内存**钩子 → 扩展重载即**丢失**。修：抽出 `wireConflictHooks()`
（幂等：`conflictWired` 标记 + try/catch 不阻塞），在 `init()` 里（`wireDebugLog()` 之后）就接线，
并**顺带跑一次 S1 迁移**；`openPanelPopup()` 改为调它（不再是内联 `setConflictHooks`）。

## 3. 一并修掉的小缺陷

| # | 缺陷 | 修复 |
| --- | --- | --- |
| ① | 总览横幅「去处理」跳「设定 → 存储」时**残留**上一次的编辑态 / 速览态 / 闪烁提示（`ps.editing` / `ps.peek` / `ps.flash`） | `goStorageConflicts` 一并清空这三项后再切页 |
| ② | 单测 A5 的口径随 S2 变化（`keptLog` 不再等于「只有老记录」） | A5 补断言：批量/单条确认**都**在记录区留痕；被拒动作**不**留痕 |

## 4. 复核后**不改**的取舍（登记备查）

- **去重键 `kind|detail`**：同一类别、明细不同的两条**各自成条**（不合并）—— 保真优先于降噪；
  代价是极端情况下待确认区可能有多行同类，这是有意的（漏报比多报危险）。
- **记录只按条数封顶**（20 类，最新在前），不按时间淘汰：记录是「最近发生了什么」的窗口，
  不承担审计台账职责（真正的全量留痕在调试日志 / 交互时间线）。
- **`conflictAct` 的差异动作**（重新同步 / 校验并修复）走的是存储页同名动作：动作若又**新造**一条同类待确认项，
  那是**新事实**，会如实留在清单里（只销掉用户点的那一条 id）。
- 「跨端分歧（已自动合并）」仍是 `log`：自动合并已完成，通知即可，不需要人决策。
