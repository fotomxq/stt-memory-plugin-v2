## 2. 三条通道的记账点（为什么落在这三处）

AI 请求在 V2 有**两条上层管线**（内核 `core/ai-hooks.js#aiCallText`、摘要 `host/extract.js#genTracked`），
但两者都最终汇到 `host/generation.js#rawGenerate`。**真正能拿到 `usage` 的位置在更下面**，故记账落在三个**叶子**上：

| # | 落点 | 通道 | token 来源 | 模型名 |
| --- | --- | --- | --- | --- |
| ① | `host/api-channel.js#sendDirect` | `direct`（自建连接） | **实测 `usage`**（`j.usage` / `j.model`） | 响应回显的 `model`（比配置值可信） |
| ② | `host/api-channel.js#sendViaProfile` | `profile`（酒馆连接配置） | 宿主给了 `data.usage` 就实测，否则估算 | 连接配置里的 `model` |
| ③ | `host/generation.js#rawGenerate`（host 分支） | `host`（跟随酒馆当前连接） | **只能估算**（`generateRaw` 只回文本） | 宿主 best-effort（`getChatCompletionModel()` / `oai_settings`）→ 取不到记 `(未识别)` |

**唯一穿透的标签**：`usageLabel`（可选形参）由 `index.js`（内核管线，传 `opts.label`）与 `host/extract.js#genTracked`（摘要管线，传 `callLabel || label`）透传下来 ——
只用于账本归组，**不改变发送语义**；测试桩忽略未知键，故既有黄金样本零影响。

**为什么不在 `aiCallText` / `genTracked` 记账**：那两处是**上层**，`direct` 通道的真实 `usage` 在那里已经被丢掉；
在两个上层各记一次还会**重复计数**（同一请求）。落在叶子上 = 一次请求恰好一条。

**不计入的**：探针与「🧪 测试」（`probeTarget`）等**诊断请求** —— 它们是 `max_tokens:1` 的连通性检查，不是记忆管线的真实花费。

## 3. 口径与边界（与代码同源）

| # | 口径 |
| --- | --- |
| ① | **估算** = `ceil(字符数 / 4)`（复用 `core/pipeline.js#estTokens`，与管线状态的 token 读数**同一件**） |
| ② | **两种 `usage` 形态归一到「总输入含缓存」**：OpenAI 的 `prompt_tokens` **含**缓存命中；Anthropic 的 `input_tokens` **不含** `cache_read_input_tokens` → 相加后再算。**未命中 = 总输入 − 缓存命中**（缓存部分按 `cachedIn` 单价计，不重复收全价） |
| ③ | **花费** = `(未命中输入 × in + 命中输入 × cachedIn + 输出 × out) ÷ 100 万`；`cur: USD` 按可配置汇率折人民币（默认 **7.2**，可改） |
| ④ | **累计用微元整数**（1 元 = 1e6 微元）累加 → 不出现浮点漂移；明细环保留最近 **200** 条，**累计不受该上限影响** |
| ⑤ | 分维度聚合（按**行为标签** / 按**模型**）键数上限 **40**，超出并入「其它」（账本有界，不随用量无界膨胀） |
| ⑥ | 坏账本（非法值 / 非对象）**归一后不抛异常** —— 账本坏掉绝不能连带 AI 调用出问题 |

## 4. 价格清单的诚实口径（**不编价格**）

- 内置价目表**只收已核实来源**的条目，每条带 `src`（来源）与 `asOf`（采集日期），UI 逐条展示；
  首个版本收 **DeepSeek 官方价目页**（`deepseek-flash` / `deepseek-v4-pro`，**峰时价**——非峰期为半价，预估按峰时**偏保守**）。
- **未覆盖的模型不会假装有价**：照样记 token，花费列显示「未定价」，统计里单独计数 `未定价 N 次`，
  并在设定页提供「🧩 为未定价模型建条目」一键生成 0 价模板（用户按官方账单填数后再保存）。
- 用户覆盖：设定页的 **JSON 文本域**（与内置条目**同名键 → 覆盖**，新键 → 新增条目），另有汇率输入与「↩️ 清空覆盖」。
- 所有价格改动只影响**之后的记账**（历史明细按当时的单价与汇率留痕，不回改）。

| 项 | 说明 |

| **Embedding / Rerank 用量** | 本版只记 **chat 请求**（用户说的是「请求 token」）。向量层调用（`host/embeddings.js`）未纳入；其计价方式与 chat 不同（按输入 token 且通常无输出），需要时另立条目 |

| **实时流式 token 计数** | 流式通道（`profile`）宿主只回累计文本、不回 `usage` → 按字符数估算（改动前就是这样） |
| **跨端合并账本** | 明确**不合并**：各端按自己的用量计费，合并会互相污染（账本随设备/浏览器设置走） |
