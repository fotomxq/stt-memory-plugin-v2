## 1. 错在哪（v3.16.0–v3.27.x）

「本机缓冲目录」被实现成**宿主扩展存储命名空间**：

```text
<数据根目录>/_tauritavern/extension-store/<命名空间>/{kv,blobs}/…
```

而 `_tauritavern/extension-store` 是 **TT-Sync / LAN Sync 的默认数据集**（服务端同步面）。于是：

* 用户以为「我在设本地存储」，实际设的是**服务端存储路径**（还要被剥盘符、折叠成命名空间名）；
* 「本地存储」本该替代的**浏览器变量（localStorage）与内存库（IndexedDB）**，语义上与这个命名空间不是一回事；
* 用户填 `D:\Downloads\stn\fft_v2_store` 时既落不到 D:（命名空间限制），也解释不清「本地存储」到底替代了什么（P10c55 的报错即由此而来）。

## 2. 纠正后的三层语义（v3.28.0）

| 层 | 设置键 | 是什么 | 落点 |
| --- | --- | --- | --- |
| **本地磁盘目录**（本机层） | `storage.localDiskDir` | **替代浏览器变量 / 内存库** 的本地存储 | 用户给的**真磁盘路径**（如 `D:\FTT\store`）：`ftt2-local-<角色>.json` + `aux-*.json` |
| 服务端扩展存储目录 | `storage.localFilePath` | **服务端**数据集（参与官方同步） | `<数据根目录>/_tauritavern/extension-store/<命名空间>/…` |
| 服务端记忆文件 / 分片 / 快照 | 无开关（总是） | 权威大对象与跨端恢复源 | 扩展存储命名空间 + 酒馆 `user/files/` |

**优先级**：设了「本地磁盘目录」→ 本机层 = 该目录（浏览器变量 / 内存库 / 聊天元数据都不读不写）；没设但有「服务端扩展存储目录」→ 按 v3.26.x 口径；两者都没设 → 浏览器变量 + 内存库（旧行为）。

## 3. 真磁盘写入怎么做到（能力探测，绝不假装）

`adapters/local-disk.js` 按优先级探测：

1. `__TAURITAVERN__.api.dev` 下的**文件类命名空间**（名字按 `file|fs|disk|path|io` 关键字发现，方法按 `write|save|put` 与 `read|load|get` 关键字发现）→ `dev-api` 机制；
2. **Tauri 原始桥**的 fs 插件命令（`plugin:fs|write_text_file` / `read_text_file`；是否放行取决于宿主 ACL）；
3. 都没有 → 如实回报「宿主未提供写任意磁盘路径的接口」，UI 不显示成功、也不假装校验通过。

**写入纪律**：`localDiskWrite()` 一律**写 → 回读逐字节校验**；不一致即失败并记账（`failures` / `lastError`）。写盘失败**不回退**浏览器层（浏览器变量 / 内存库保持停用，与「用户要求停用就别偷偷写回」的既有纪律一致）。

## 4. UI / 诊断

* 设定 → 存储：新增「💾 本地磁盘目录（替代浏览器本地存储）」分节 —— 路径输入 + 状态行（目录 / 写·读·校验计数）+「✅ 校验本地磁盘目录」+「🔄 刷新磁盘状态」；能力与失败明细在折叠块；原目录选择器改称**服务端扩展存储目录**（与本地层分开）；
* 数据管理页「辅助数据落点」在磁盘模式下会显示磁盘目录（`auxStoreInfo().mode` 仍为 `dir`，`disk.dir` 给出真路径）；
* 调试桥 `ftt.localDir` 新增 `disk`：`{enabled, dir, kind, capability:{ok,mechanism,ns,writeMethod,readMethod,tauriFs,devKeys,note}, stats}`。

## 6. 纪律（写进本档）

* **术语即契约**：「本地存储」= 替代浏览器本地存储；「服务端存储」= 记忆文件 + 扩展存储命名空间。两者**分开设置、分开呈现**，绝不混用；
* 真实写盘必须**由宿主提供接口**，插件只做探测与如实回报 —— 拿不到就明确说「做不到」，并给出可行替代（服务端扩展存储目录 / 目录联接）；
* 任何「写盘」都要**写→回读校验**，不许「写完就当成功」。
