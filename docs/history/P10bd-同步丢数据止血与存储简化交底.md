## 1. 止血修复（本版已落地）

**问题**：`core/sweep.js#applyDeletedToArray` 的**内容墓碑**（`deletedH`）删除判据与 id 墓碑一致：

```js
const deadByHash = !!th && (wall === 0 || th >= wall);   // 旧口径
```

即：条目只要与任一内容墓碑**同内容**，且**没有毫秒墙钟**（`updatedAt` 缺失／为 0 —— 跨端同步进来、旧存档、
由对端写入或经瘦身往返的条目**经常如此**），就会被**静默删除**。叠加 v2.86.0 把身份指纹收窄为 7 槽
（**不含 `time` / `entities` / `owner`**），「同一天、同题、同正文、仅时段或在场角色不同」的两条情节会被判为同一条 ——
这正是「**跨端同步数据后，情节等数据总是丢失**」的高危路径。

**修复**（v2.91.0）：

```js
// 内容墓碑只删「有明确墙钟且不晚于墓碑」的条目；墙钟未知的条目**只能由 id 墓碑删除**
const deadByHash = !!th && wall > 0 && th >= wall;
```

- **方向是保守的**：宁可多留，不可误删；代价是极少数「同内容换 id 复活且无墙钟」的条目会漏挡（可在下一版用
  「对端已确认 + 到期回收」补齐，见 `D10` Q3）。
- **id 墓碑语义不变**：主动删除仍会生效（无墙钟也删）。
- **保留并作废**：条目墙钟晚于墓碑（删除后重写）→ 保留该条并作废对应内容墓碑（原语义）。

**新增单测** `tests/unit/tombstone-safety.test.js`（4 项）：无墙钟不被内容墓碑删除 / 有墙钟且早于墓碑仍删 /
有墙钟且晚于墓碑保留并作废墓碑 / id 墓碑不受影响。

## 2. 设计交底（`docs/D10`）

| 内容 | 要点 |
| --- | --- |
| **现状核实** | 存储通道**同时存在 5 条**（ST 扩展设置 / localStorage·IndexedDB 缓冲 / 状态文件（明文+gzip+瘦身）/ 快照文件链 / 世界书镜像），TauriTavern 另有原生 KV·blob；同步为自研「文件 + 快照链 + 墓碑账本」三件套 |
| **丢数据候选路径** | **R1** 内容墓碑 + 墙钟未知（**已修**）· **R2** 快照链按 `atomsHashes` 字面去重（口径变更即失配，链触顶 30 后覆盖面缩小）· **R3** 合并后按上限裁剪（两端上限口径可能不同）· **R4** id 墓碑在同正文同楼层档时误伤 · **R5** 原生通道与文件镜像双写交错（读错一份即「像丢数据」） |
| **取证计划** | 5 步、10 分钟内可执行（看 `deletedH.atoms` 键数 / 检查 `updatedAt` 是否缺失 / 对比两端 `storeTotalMax`·`storeShare` / 看快照链长度与键数 / 看是否双通道写入） |
| **修复顺序** | 止血（本版）→ 口径对齐 → 墓碑账本上限与过期回收 → 快照链合并判据升级 → 原生通道唯一化 → 同步自检哨兵 |
| **存储简化（用户 ②）** | 目标架构 **5 条通道 → 2 条**：配置走 ST 扩展设置；记忆数据走**宿主原生存储**（TauriTavern 原生 KV/blob，其它宿主回落状态文件）；**gzip / 瘦身 / 快照链 / 世界书镜像降级为备份与可选**；「一条通道只有在宿主确实不提供时才默认开启」 |
| **迁移策略** | 首次启动按「原生 → 文件 → 缓冲」读最优 → 成功后写回原生（一次性迁移，**不删源文件**，保留 3 份明文轮转）；`DATA_VERSION` 保持 1（只改通道不改结构） |
