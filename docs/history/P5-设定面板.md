## 2. 单一写入口（避免「两套配置」分叉）

面板的内核配置控件**不直接改 ST 配置对象**，而是：

```text
控件 change → applyPanelCfg(id, value) → cfg[key] = value（内核视图）
                                    → saveKernelCfg()（写回 extensionSettings.ftt_memory_v2.cfg + saveSettingsDebounced）
                                    → refreshPanelStatus()（状态块随值刷新）
```

- 绑定表 `PANEL_CFG_BINDINGS`（id → `[cfg 键, 类型]`）是唯一映射，控件、绑定与测试共用，避免 id/键对不上；
- 维度开关走 `applyPanelDim(kind, on)` → `cfg.dimensionEnabled[kind]`（同一持久化路径）；
- 读取侧只读 `cfg.*`（`panelData()` 由内核视图生成），**不存在**「面板显示 settings.charBudget、内核读 cfg.charBudget」这类分叉。

面板钩子由入口注入（避免 `ui/ → host/` 反向依赖与循环引用）：
`mountSettingsPanel({ hooks: { extract, pending, importV1, clearInject }, status: {...} })`。

## 3. 与内核/导入的联动

| 按钮 | 调用 | 结果提示 |
| --- | --- | --- |
| 分析未分析楼层 | `runExtract({})`（host/extract） | `分析完成：成功 N / M` 或 `没有未分析楼层` |
| 待分析清单 | `pendingFloors({})`（host/floors） | `待分析楼层：…` |
| 清空注入 | `clearInject()`（host/inject） | `已清空注入`（并清掉「上次注入」记忆） |
| V1 导入（干跑/写入） | `runV1Import({apply})`（adapters/import-v1） | `【干跑】新增 a · 已存在 b · 冲突 c` / `【已写入】新增 a 条（源数据未删除）` |

## 4. 降级

`renderExtensionTemplateAsync` 不可用 → 使用内置回退 HTML（`fallbackPanelHtml`），**同样包含**内核配置控件、
状态块与动作按钮（仅无 Handlebars 变量替换），并继续绑定事件；两条路径共用 `bindPanelEvents()`。

## 5. 测试

`tests/smoke-test.js` I1–I4（真实宿主桩 + 真实 `settings.html` 渲染）：

1. I1 面板含内核配置控件 / 维度容器 / 状态块 / 动作按钮，状态块文本可刷新；
2. I2 `change` 事件写回内核配置并**持久化到 ST 配置容器**（`extensionSettings.ftt_memory_v2.cfg`）；
3. I3 `applyPanelDim` 写 `cfg.dimensionEnabled` 且状态块随之刷新；
4. I4 动作按钮（清单 / 清空注入 / 分析）调用注入钩子并回填提示，清空后注入通道为空。
