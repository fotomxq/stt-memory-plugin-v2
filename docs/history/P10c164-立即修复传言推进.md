> 关联：`core/repair.js` · `index.js`（钩子接线）· `ui/panel.js` · `core/rumor-evolve.js` · `docs/04` §2.2

## 1. 传言立即推进（并入「立即修复」流程，第 ③-d 步）

* **同一条处理**：复用传言页「🧪 立即演化」的**零 AI 机械推进**（`core/rumor-evolve.js#runRumorEvolveNow`）——
  载体老化 / 发酵消退 / 平行联动 / 裂变；不新增第二套算法（与 `planSuspRepair` 的接线纪律一致）。
* **接线**：`repairHooks.rumorEvolve`（`index.js` 注入，`silent: true, reason: 'repair'`）；
  `core/repair.js#runRepair` 在计划/悬念修复之后执行；**零 AI → 不受 `cfg.repairAutoAi` 约束**。
* **跳过口径**：`opts.rumor === false` → `disabled`；钩子未接线 → `no-hook`（如实回报，不伪装成「无变化」）；
  传言演化开关关闭（`cfg.rumorEnabled === false`）→ 钩子返回 `disabled`，note 写明「已关闭」。

## 2. 统计同步

| 位置 | 变化 |
| --- | --- |
| `repairTotals` | 新增 `rumor`（= 载体停用 + 平行联动 + 酝酿变化 + 完成变化）及分项 `rumorAged/rumorLinks/rumorChanges/rumorCommitted/rumorFissions`；**并入 `total`** |
| `repairTotalsText` | 追加一行「传言推进 N」（合计明细里可见） |
| `stage1.notes` | 「传言立即推进：载体停用 … · 平行联动 … · 酝酿变化 … · 完成变化 …（裂变 …）· 发酵度更新 …」 |
| 修复报告 / 日志 | 合计文案随 `repairReport.extra` 内嵌（含传言推进） |

## 3. 提示同步

* 概览「🛠 自动修复」状态行：合计在前，新增一段
  `传言立即推进：载体停用 N · 联动 N · 酝酿 N · 完成 N（裂变 N）`；未接线时写「跳过（宿主未接线）」；
* 修复完成通知：合计文案自动含「传言推进 N」（与面板同源 `repairTotalsText`）。

## 5. 边界（如实登记）

1. 传言推进是**零 AI 机械演化**，不生成新正文、不改剧情；与传言页手动「立即演化」完全同一套；
2. 统计口径：`载体停用/联动/酝酿/完成` 各算一处；纯「发酵度更新」计入 note 但不进 `total`（避免把数值微调当修复量）；
3. 自动修复的 AI 开关（`cfg.repairAutoAi`）**不影响**本步（本步不调 AI）。
