## 1. 缺陷

| 面 | 旧实现 | 为什么算「不是图」 |
| --- | --- | --- |
| 注入（AI 看到的） | `📍 地图（码头）：` 下两串平铺行 —— `- 房间：货仓（陈设：…）`、`- 路径：码头 → 货仓（…）` | 一维清单，**读不出拓扑**（谁与谁相连、几条通路、是否成环） |
| 面板（人看到的） | `.ftt-item` 逐行罗列（场所 → 房间 → 陈设 → 路径也是行） | 只是**缩进列表**，没有任何连线 / 节点图形 |

设计稿 `docs/D27` §1.1 的目标写的是「**分层关联网图**」（空间单元为点、路径为边），§3.7 也要求「走过 / 未走过视觉可区分」
→ 实现**没画出图** = 与设计稿不符 ✓ 本版补齐。

## 2. 修法

### ① 注入子块 → **网表**（`core/model/map.js#mapInjectLines`）

```text
  🗺 地图（网状图 · 节点 / 连线）·码头：
    节点：N1 码头（场景）｜N2 货仓（属 N1 · 房间）｜N3 暗室（属 N2 · 房间）
    连线：N1 →(距离 三里路（3里）) N2［剧情走过］｜N2 →(正文未给距离 / 耗时) N3［未走过（手填）］
    陈设：N2 货仓：木箱、绳
```

- **稳定编号 `N1…`**：场景 → 房间 → 陈设依次编号，连线用编号引用（`N1 →(…) N2`），AI 能直接读出**有向边**；
- **度量与状态文案复用核心单一事实源**（`mapRouteMeasureText` / `mapRouteStatusText`），与列表行、图标签三处同口径；
- **限额与从属注入不变**：仍挂在 `[场景地点]` 小节下，仍受房间 / 陈设 / 路径上限约束，超限如实写「（还有 N 个…未展开）」。

### ② 面板 → **网状图 SVG 为主视图**（新模块 `ui/scene-map-graph.js`）

- **纯布局函数** `sceneMapGraphLayout(places, routes)`：分层摆放（场景 0 / 房间 1 / 陈设 2），**确定性**（无随机、无物理引擎、无时间依赖）；
- **渲染** `sceneMapGraphSvg()`：`<svg data-ftt-map-graph>` + 每个空间单元一个 `<g data-ftt-map-node="id">`（**可点**，复用既有下钻 / 插入套话分发）+ 每条路径 `<line data-ftt-map-edge="traversed|inferred">`（走过实线 / 未走过虚线）+ 「属 Nx」细虚线 + **图例**；
- **不是坐标地图**（守 N2）：不出现瓦片 / 经纬 / 寻路几何；只有「层级 + 序号」的确定性摆放；
- **悬空边如实标红**（路径指向未知单元 → `⚠ 路径指向未知单元：A → B`），不静默吞掉、不伪造节点；
- 逐行明细**保留**（下钻与「🗺 前往」按钮仍在），排在网图之后 —— 图为主、表为辅。

## 4. 如实登记（未做 / 限制）

1. **布局是分层式**（按层级分列），不是力导向 / 环形等其它网图美学；数据量很小（同场景几到几十个单元），分层式最易读且**确定可测**；
2. **跨场景的路径**在图里按「全图」渲染（根层），二级页只画本场所子树 —— 与列表口径一致；
3. **未做交互增强**（拖拽 / 缩放 / 高亮路径）—— 面板既有动作分发只认点击；
4. **真机未人工试用**：需刷新后在「场景 → 🗺 地图」看网图与图例。
