## 1. 问题：旧提示说不出「靠什么召回」

| 环 | 事实（代码证据） |
| --- | --- |
| 旧文案 | 总览提示行只拼「召回完成：N 条 · 注入 X 字 · Yms」，方式信息最多是 `{vector:'向量层',js:'JS 抽取层',ai:'AI 分析层'}[hitLayer]` |
| 空隙 | `hitLayer` 为空有两种情形：① **三层流程未进入**（`useVector` 与 `useKeywordFlow` 都关）② 由 `host/inject.js` 的**本地兜底**产出正文 —— 两种都不带方式名，用户看到的就是一条「没有方式的完成」 |
| 更看不见的 | 「为什么没用向量」：向量**未启用** / **未配置**（开着但没填 Embedding）/ **无命中** / **请求失败**，旧文案一律不区分 |
| 影响 | 用户无法判断「这次召回是否可信、是否该去开向量」，只能去翻注入账目或调试日志 |

## 2. 口径：方式 + 备注，词表唯一

方式词表 = `host/extract-flow.js#RECALL_METHOD_LABELS`（**唯一事实源**，界面与诊断共用）：

| key | label | 触发 |
| --- | --- | --- |
| `vector` | 向量召回 | `hitLayer = vector`（第①层向量命中） |
| `local` | 本地关键词召回 | `hitLayer = js`（第②层 JS 抽取命中）**或** `usedLocalFallback`（注入侧本地兜底产出正文） |
| `ai` | AI 分析召回 | `hitLayer = ai`（第③层 AI 命中） |
| `''` | （无方式） | 三层都没产出正文 → 只出备注（试过什么、为什么没成） |

备注（`note`）拼装口径：

* 关键词段：`关键词 N 个` / `无关键词`；
* 向量段（仅 `local` 与「无方式」时追加）：`向量未启用`（`vectorEnabled !== true`）· 有向量轨迹且 `ok === false` → 原因人话（`向量未配置` / `无关键词可用` / `向量库为空` / `向量请求失败` / `关键词向量失败`）· 有轨迹但 `count <= 0` → `向量无命中`；
* **「已降级」只在 `vectorEnabled === true && 向量段非空` 时追加** —— 「向量未启用」是如实陈述，不是降级；
* AI 段：`长任务在途 → 跳过 AI 层`（`aiSkippedBusy`）优先于 `AI 层未启用`；
* 无方式时首段固定为 `三层流程均未命中`（`flowEntered === true`）或 `未进入三层流程`。

## 4. 边界与纪律（如实）

* **只加说明，不改决策**：三层顺序、`allowAiDuringBusy`、降级条件、注入预算、`hitLayer` 语义一字未动；
* `recallMethodInfo` 是**纯函数**（`core` 口径之外的 host 纯逻辑，无 DOM / 无宿主调用），因此可被单测直测；
* 方式名是**给人看的一句话**，不是新的持久化字段 —— `lastMethod` 只活在 `injectStats`（运行期快照），不落盘、不入数据契约；
* 词表**唯一**：界面不得自建第二套标签（本次把 `ui/panel.js` 里原有的 `{vector:'向量层',…}` 映射退化为**兜底**，只在 `method` 缺失时用）。

## 6. 结论

「召回完成」从**数量句**升级为**方式句**：一条提示同时回答「召回没有」（数量）、「靠什么召回」（方式）、「为什么没用更好的那层」（备注，含降级/未启用/跳过），且总览提示、注入账目、诊断快照三处措辞同源。
