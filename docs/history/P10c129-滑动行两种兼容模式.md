# P10c129 · 列表行按钮「两种兼容模式」+ 修复表单跟着走（v3.50.20）

> 文档版本：v1.0 ｜ 日期：2026-10-15 ｜ 状态：生效（v3.50.20）
> 用户原话：「列表鼠标放上去滑出按钮的设计存在缺陷，应该是两种兼容模式，第一种是手机端或触屏滑动弹出按钮组；第二种是鼠标拖动后触发。
>   当前设计存在缺陷，造成鼠标放上去编辑货币增减的窗口，会跟随走动，造成无法正常编辑。如果两种兼容无技术解决方案，应改善货币增减设计，即如果点击增减按钮，则滑动应该自动临时失效，以避免该问题。」
> **版本位**：用户指定 **v3.50.20** —— 交互缺陷修复 → 守则 §3.1 的 patch 位，**无偏离登记**。
> 关联：`ui/swipe-rows.js` · `ui/currency-quick.js` · `docs/D22` §4.19（W19 `应-35` 的后续修正）· `CHANGELOG.md` v3.50.20

## 1. 根因

`ui/swipe-rows.js`（v3.48.0）在 PC 上**悬停即展开**按钮组（`mouseenter` → 行内容左移 `--ftt-swipe-w`）。
v3.50.17 的货币「快速记一笔」把**行内小表单**（金额输入框）渲染在行内容里 →
鼠标移到行上 / 移到输入框，行持续位移，**输入框跟着走、点不准**。

## 2. 修法（用户首选方案 + 兜底方案，两条都做）

| 面 | 之前 | 现在 |
| --- | --- | --- |
| 触屏 / 手机 | 左滑展开 | **不变**（`touchstart/move/end`，同一套阈值） |
| PC 鼠标 | **悬停（`mouseenter`）即展开** ✗ | **按住左键向左拖动**超过阈值展开 / 向右拖回收起（`mousedown/mousemove/mouseup`，与触屏**共用阈值与展开态**；横向拖动时 `preventDefault` 防选中文本） |
| 键盘 | 聚焦展开（`focusin`） | **保留**（可达性不退化） |
| 行内小表单（货币快速记账） | 与滑动抢位移 | **打开表单即 `setSwipeSuspended(true)`**（模块级暂停：任何入口都不展开）+ **逐行守卫**（行内有 `.ftt-curquick` 时拖动/聚焦都不展开）；取消 / 记账完成 / 校验失败即恢复 |

**导出**（供其它行内表单复用）：`setSwipeSuspended(on)`（返回旧值）、`swipeSuspended()`。

## 3. 兼容与降级

- 鼠标拖动不可用（无 `mousedown`/`mousemove` 的宿主）→ 仍有「聚焦展开」可点按钮（功能不丢）；
- CSS 侧本无 hover 展开规则（展开态只由 JS 打 `ftt-open`）→ **无需改样式**；
- 触屏路径**完全未动**（`passive` 口径保留）。

## 5. 如实登记（未做 / 限制）

1. 鼠标拖动需要 `mousedown` 系列事件（桌面浏览器 / TauriTavern 均有）；拿不到时只能靠聚焦展开（功能不丢，但不如拖动顺手）；
2. **未加「拖动能力探测 / 提示」** —— 用户不一定会想到要拖动；若要更易发现，可后续加一次性提示条；
3. 触屏手势仍走 `passive`（既有口径），只有鼠标侧做了 `preventDefault`；
4. **真机未人工试用**（需刷新后手试：货币行点 `＋` → 输入框应**稳定不位移**）。
