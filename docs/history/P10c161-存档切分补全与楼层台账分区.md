# P10c161 · 存档切分补全 + 楼层台账分区（v3.52.8）

> 文档版本：v1.0 ｜ 日期：2026-11-03 ｜ 状态：生效（v3.52.8）
> 用户报告（原话）：「有些数据没有同步被切分存档，需修复；额外还有切换存档后，很多分析过的楼层会莫名其妙的出现。」
> 关联：`docs/D60` · `host/floors.js` · `core/entries.js` · `core/model/ledger.js` · `core/plot-segment.js` · `core/archive-scope.js`

## 1. 两个症状的根因

### ① 「有些数据没有同步被切分存档」

v3.52.7 的分区只覆盖了经 `preserveEntryMeta` 漏斗的维度条目（atoms/states/snapshots/memories/items/plans/…），
**不在漏斗里的容器没有 `chatKey`**：

| 容器 | 之前 | 后果 |
| --- | --- | --- |
| **关联层** `links` | 写入时不打标 | 切档后关联行仍整份可见（点开可能指向别档条目） |
| **货币账本** `ledger` | 写入时不打标 | 切档后账本混在一起（金额/流水串档） |
| **分段总结** `plotSegments` | 写入时不打标 | 切档后别的存档的分段仍在列 |

### ② 「切换存档后，很多分析过的楼层会莫名其妙的出现」

已处理楼层台账 `processedFloors` 是**一个角色一本**（标记里虽有 `ck` 归属，但维护逻辑用**整本台账**做判定）：

* `reconcileProcessedFloors`：拿**整本台账**的哈希与**当前聊天正文**比对 → 找不到就丢弃；
  切到存档 B 时，存档 A 的标记哈希全都「找不到」→ **整批被丢弃并留痕**；切回 A → 标记没了 → 楼层全变未摘要；
* `migrateProcessedFloorsV170` / `processedDriftGuard`：按**楼层号**用当前聊天正文**重写全部标记的哈希** → 同样把别档标记改坏；
* `recordProcessedFloors`：用**楼层号当唯一键** → 在 B 档分析第 3 楼会**覆盖 A 档的第 3 楼标记**。

结果就是在两条存档之间来回切 → 每切一次都被另一条存档的维护逻辑「洗」一遍 → 已分析楼层成片复现。

## 2. 修复

### ① 补全切分（写入侧打标）

`core/archive-scope.js` 新增 `stampEntryArchive(obj)`（只补空归属、幂等），在
`upsertRelLinks`（关联行）、`applyLedgerEntry`（货币账本）、分段总结落库处调用；
`archiveStats` 的默认统计维度补上 `links` / `ledger` / `deals` / `plotSegments`（横幅计数覆盖）。

### ② 楼层台账按存档切分（维护侧只动本档）

`host/floors.js` 新增 `markArchiveRelation()`（`current` / `legacy` / `other`）与 `splitMarksByArchive()`：

* **写**：`recordProcessedFloors` 按「本档|楼层」为键写入 —— 同楼层号的不同存档标记**共存**，互不覆盖；
* **判**：`processedMarkOf` 同楼多标记时**优先本档**；`isFloorProcessed` 只认本档标记（别档标记不再冒领）；
* **护**：`reconcileProcessedFloors` / `migrateProcessedFloorsV170` / `processedDriftGuard` 只判定与刷新**本档**标记，
  **别的存档的标记与留痕一律原样保留**（不刷新、不丢弃）；
* **清**：`clearProcessedFloors` 只清本档（别的存档台账保留），回报 `cleared` / `keptOtherArchive`；
* `forgetDroppedMarks` 只清本档留痕。

## 3. 测试

`archive-scope.test.js` 10 → **14 项**：
D1 写入按档打标且同楼层号跨档共存 · D2 `isFloorProcessed` 只认本档 · D3 归位对账不丢别档标记 ·
D4 关联行/账本/分段总结新建即打档。
既有 `ledger-heal` / `pending-floors` / 全部黄金样本保持全绿。

全量单测 **264 文件 / 3917 断言**；冒烟 224 项；`npm run gate` 全绿。

## 4. 边界（如实登记）

1. 物理上仍是一份文件（每角色），分区在**逻辑视图 + 台账**层；
2. **无归属（legacy）**的历史标记/条目仍按 fail-open 参与本档判定（`chatKey` 读不到时整层不分档）；
3. 别的存档的楼层台账**只增不减**（不自动清理）—— 切到对应存档可自行「清除已处理楼层记录」（只清该档）。
