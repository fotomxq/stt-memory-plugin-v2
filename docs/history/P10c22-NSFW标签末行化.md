## 1. 改动前的问题

v3.8.0/v3.9.0 的徽标是「**徽标 + 整行**」拼在最前面（`listRowMainHtml` 里的 `withBadge`）：

```text
[NSFW·强] 两人做爱后相拥……            ← 标题/正文被整体后推
📅 [1919-11-01] · 主线 · 3-4楼 · 调用2次 · 重要度50%
```

于是它读起来像「**整行都是 NSFW 的**」，而实际语义是**元信息**（等级留档，随原文判定、弱化后不变）。
用户要求：**放到底部最后一行，与楼层信息等混在一起展示**。

## 2. 改动后的形态

```text
两人做爱后相拥……
📅 [1919-11-01] · 主线 · 3-4楼 · 调用2次 · 重要度50%
└─ 末行开头即徽标：NSFW·强 · 📅 [1919-11-01] · 主线 · 3-4楼 · 调用2次 · 重要度50%
```

| 位置 | 改动 |
| --- | --- |
| `ui/list-rows.js#appendBadgeToLastLine(html, badge)` | **新增（纯函数）**：取行内**最后一个** `ftt-meta` 开标签；没有就取最后一个 `ftt-desc`；都没有则补 `<div class="ftt-meta">`。注入后补 ` · ` 分隔。**绝不退回行首** |
| `listRowMainHtml` | `withBadge` 由「前缀」改为「注入末行」（情节 / 记忆 / 状态 / 物品 / 货币 / 传言 / 计划 / 悬念 / 概念 / 平行 / 兜底 全部走同一入口） |
| `stateRowMainHtml` | 状态行同样把徽标放进末行（`调用N次 · 更新…`） |
| `nsfwBadgeHtml` | 去掉原来自带的**尾随空格**（分隔符交由注入器统一补） |
| `nsfwLegendHtml` | 文案「标记见每条行首」→「标记见每条**末行**，与楼层等信息同段」 |
| `style.css` | 仅**注释**同步（样式本身不变：行内 chip，随末行继承 `--ftt-font-xs`；弱=warn 色 / 强=danger 色 / 无=不显示） |

**为什么不在 CSS 里做定位**：徽标与「楼层信息」是**同一行内的不同片段**（不是两行叠放），
所以位置由**渲染时注入点**决定，CSS 只负责 chip 外观 —— 这样换行/窄屏折叠时它仍然跟着末行走。

## 3. 顺带修一处 v3.10.4 的耐久性缺口（由间歇性失败暴露）

改完 UI 跑全量单测时，`local-copy` B1 **间歇性**失败（单跑 3 次里红 1 次）。追因：

- v3.10.4 的「等值跳过」用 `localLastSig`（上次写入的信封签名）判断「内容没变 → 不重写 1.1MB」；
- 但 **`removeLocalKeys`（清理本机缓冲）只删了键，没清这个签名**；
- 于是「清理本机缓冲 → 下一次**同内容**保存」被判 `unchanged` → **跳过写入** → **本机缓冲一直空着**，
  直到内容再次变化 —— 这是**真实的耐久性缺口**（不是测试问题）。

→ 修：`invalidateLocalBufferCache()` 语义提升为「**忘记本层已知状态**」：同时清**解析缓存**与
**上次写入签名**；`removeLocalKeys` 已经调用它。回归断言见 `local-buffer-io` **B5**
（清理后即使只是 `markDataTouched()` 也必须重新写回）。修后 `local-copy` 连续 4 次稳定通过。
