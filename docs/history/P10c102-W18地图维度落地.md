## 0. 这一批为什么「一次做齐」

`docs/D27` §0 把本批定性为**本项目迄今为止最重的一条改动**：**新增第 15 个原子维度** → 六处接线 + `DATA_VERSION` 递增 + 两组数字口径。
设计稿自带 **M0–M5 分阶段**（M0 只读派生 → M1 前置验证 → M2 数据模型 → M3 路径 → M4 注入 → M5 交互），
且把 M2 标为「单独立批」。本轮**一次性落齐 M2–M5**（M0 的只读派生被 M5 的真实网图取代，不必先行），
理由：任何一半都会留下**静默缺口** —— 只落容器则界面上「有数据但看不到」；只落界面则网图永远为空。

### 1.1 为什么 `maps` 不进身份哈希（`IDENTITY_FIELDS.maps = {}`）

`docs/D27` §3.3 ③ 只说了「引用类不进**内容**哈希」。身份哈希是另一张表，若把 `fromId`/`toId` 塞进身份槽，
`route` 又**没有 `name`/`desc`** → **两条不同路径会算出同一个身份哈希** → 删除其中一条时，内容墓碑会**误伤另一条**。
故取**与 `currencies` 完全同款**的既有先例：不进身份哈希，**以 id 墓碑为准**（本维度 id 由内容派生，跨端同一条算得同一 id）。
该决定写在 `core/model/hashfields.js` 该行注释与 `docs/02` §1.3。

## 2. `数-23`：路径**只在剧情走过时**自动建立

### 2.2 护栏（`docs/D27` §3.4 逐条）

| # | 护栏 | 落点 |
| --- | --- | --- |
| ① | **只在走过时建**（`traversed !== true` → 不建） | `core/map-ingest.js`（计数 `untraversed`） |
| ② | 每条自动分析**必带 `evidence`**（本次抽取的楼层） | 同上（`evidence = [{floor, atomId:''}]`） |
| ③ | 同对地点**只一条**；重复走过**只更新不累加** | `#upsertRoute`（度量「更具体者胜出」，`evidence` 按楼层去重、最多 3 条） |
| ④ | 抽不到就**留空、不估算** | `#normalizeMeasure`（只做有界规整，见 §2.3） |
| ⑤ | 自动分析的 `inferred` **恒为 `false`**（手填才 `true`） | `core/model/map.js#normalizeRoute` |

### 2.3 度量规整的**边界**（「能规整则附」，但绝不猜）

* **认**：阿拉伯数字 + 白名单单位（`3里`）、**个位汉字数字** + 白名单单位（`三里路` / `半日` / `一盏茶`）、
  一个**无义后缀**（`路` / `路程` / `地` / `远`）。
* **不认**（只留 `raw`）：复合数词（`二十里`）、约数（`约莫五里`）、比喻（`三步并作两步`）、带量词（`两个时辰`）、
  非白名单单位（`3把` → 数值留、单位不认）。
* 理由：复合数词 / 约词的解析规则多、歧义大，属**猜测**；白名单极小是为了不把比喻当度量。

### 2.4 名称 → id 解析（AI 只会给名称）

`所属场所` → `scenes` 条目 id（认名称 / 路径末级 / 完整路径三种写法）· `上层` → 父 `place` · 起点 / 终点 → `place`（先按 id、再按名称 / 别名）。
**解析不到就跳过并计数**（`unknownScene` / `unknownParent` / `noEnds`）—— **绝不凭空造场景**（③「数据使用场所数据」）。
`scene` 级锚点**按需自动生成**（Q2：独立锚点条目，路径两端统一用 `place` id）。

## 3. `数-24`：从属注入（`core/recall.js` 的 `[场景地点]` 小节）

* **`maps` 不进召回候选池**；**不新增 `[地图]` 小节**。
* 地图子块 = `[场景地点]` **同一大类里的追加行**：同类内按 `rows` 顺序取 → **场景整块在前、地图行在后** →
  预算紧张时**先丢地图行、场景整块保留**；场景未入选 → 该大类无行 → **地图完全不出现**（= 「捆绑」的语义）。
* 子块内容：房间（含陈设）+ 两端同场景的路径（距离 / 耗时 + 「剧情走过 / 手填」标记），**按层限量**。
* **注入自查如实列出**：`diagnose` 模式的 `mapInject = {units, routes, blocks, lines, reason}`（未注入带原因）。

### 3.1 为什么三个注入上限**不做成设定项**（差异登记）

`MAP_INJECT_MAX_ROOMS` / `_FIXTURES` / `_ROUTES` 只影响「一次注入挂几行」，属内部排版口径；
做成控件要加 3 个配置键 + 3 个控件，而用户可感知的出口已由 `charBudget`（总字数）统一约束。
与 v3.46.0 的 `SNAP_CAP` / `SNAP_BATCH` **同款处置**（常量 + 此处登记）。
