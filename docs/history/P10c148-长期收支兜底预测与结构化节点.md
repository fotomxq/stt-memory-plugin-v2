# P10c148 · 长期收支兜底预测 + 轮动按周期推测 + 结构性节点编辑（v3.51.7）

> 文档版本：v1.0 ｜ 日期：2026-10-24 ｜ 状态：生效（v3.51.7）
> 用户要求（原话）：「长期收支的下一个预测阶段，增加兜底设计。根据前几论收益的趋势预判，判定预计收益点、预计收益费用等。
>   如果AI明确，则以AI为准；如果制空，则采用该设计。其次如果轮动了1轮，应该根据周期，利用起来推测到下一轮。
>   最后，请优化长期收支编辑的面板，一些多余的提示完全没意义。前景预判② 已发生的变动节点，设计也有问题，
>   应该采用结构性设计，不要用分隔符设计。」
> 关联：`core/model/deal.js#inferForecastFallback` · `core/deal-triggers.js` · `ui/fields.js#nodeTableHtml` · `ui/node-table-dom.js`（新）

## 1. 兜底设计（「AI 明确则以 AI 为准；留空则用兜底」）

新增 `core/model/deal.js#inferForecastFallback(nodes, cycle, startDate)`（纯函数、可复现）：

| 项 | 规则 |
| --- | --- |
| 预计收益费用 `delta` | 取**最近 ≤3 个已发生节点**做**线性趋势**（最小二乘斜率）外推一步；1 个节点 → 沿用该节点金额；无节点 → 0（只给日期） |
| 预计收益点 `nextDate` | 最后变动日期（无则起始日期）`+ cycleDays`；**周期未知 → 留空**（不猜） |
| 来源 `source` | `auto`（界面显示「自动推算」） |

**归一化**（`normalizeDeal`）：AI 给了完整预测 → **原样保留（AI 优先）**；预测日期留空 → 用兜底补上；
连兜底都推不出日期（周期未知且无节点/起始日期）→ 仍拒绝（`D53` 原口径：没有日期就没有意义）。

## 2. 轮动后按周期推测下一轮（用户第 2 条）

触发器（`runDealTriggers`）在兑现后：

* 有下一节点且未越过 `endDate` → 水位写回（AI 给的下一个节点优先）；
* **没有下一节点** → 用「趋势 + 周期」兜底补一个（`source:'auto'`）；
* 预测本来就是 `auto` → 用**新趋势**刷新金额（前几轮收益变化会影响下一轮，如 10→20→30 后预测 40）；
* 越过 `endDate` → 不兜底（水位清空，本条结束）。

## 3. 编辑面板（用户第 3 条）

* `deals` 字段标签**只留字段名**（如「标的物名称」「锚定货币」「已发生节点」「预测下一节点日期」）；
  长解释移入 `placeholder` 或字段下方 hint（节点表脚注一句话）；
* 周期等字段的写法提示放进 placeholder，不再占据 label 文本。

## 4. 已发生节点：**结构性设计**（用户第 4 条）

* 编辑器字段由 `nodesText`（「日期|金额|说明」文本域）改为 `nodes`（`type:'nodeTable'`）：
  **三列行控件**（日期 / 金额 / 说明）+ 行删除 ✕ + 「＋加一行」；
* 行键 `node-<i>-date|delta|note`，`collectEditorFields` 直接收集；`deconstructEntry('deals')` 按行号排序、
  忽略空日期行、金额非法**具体报错**；旧 `nodesText`（行格式 / JSON）仍兼容（程序化调用与历史数据）；
* 行操作（加/删）在 `ui/node-table-dom.js`（纯 DOM，不进动作分发）。

## 5. 测试

新增 `tests/unit/deal-forecast-fallback.test.js`（**16 项**）：趋势外推 / 单节点 / 无节点 / 缺周期；AI 优先与留空兜底、推不出则拒绝；
轮动后按周期推进、auto 用新趋势刷新、截止日期不兜底；结构性行解析（排序 / 空行 / 报错 / 旧格式兼容）；
DOM 行操作（加一行行号、删一行、非节点表返回 false）；面板标签精简与节点不再输出「日期|金额|说明」提示。

## 6. 边界

1. 趋势是**确定性线性外推**，不做概率/置信区间（要更复杂模型请另开设计稿）；
2. 「＋加一行」上限 12 行（编辑器展示上限），超出只读并提示总条数；
3. `source:'auto'` 的预测在界面显示「自动推算」，与 AI/手动可区分（「预测 ≠ 事实」口径不变）。
