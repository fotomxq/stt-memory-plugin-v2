## 1. `应-40` 注入体区块级隔离（应用 · P1）

**缺陷（`docs/D45` §2.2 F1）**：`core/recall.js#buildMemoryBodyForInject` 整个函数**共用一个兜错**，只有 `[货币]` 区块自带隔离
（v3.46.5 用户报告「货币根本没注入成功」时补的）→ 其余任何大类只要有一条坏数据（`null` 元素 / 该维度不是数组），
整个函数抛错 → 返回空串 → **AI 一条记忆都看不到**。脏数据来源现成：导入、早期版本写入、跨端合并。

**修法（`docs/D45` §8 `应-40` 步骤 ①②③④）**：

| 步 | 落地 |
| --- | --- |
| ① | 新增 `stSafe`：注入前**只读清洗** —— 每个容器「非数组 → 空数组；元素里的 `null`/`undefined` → 丢弃」（12 处 `st().X` 读取全改走它） |
| ② | 新增 `pushCat(head, md, rowsThunk)`：**区块级错误边界** —— 任一维度的**行构建**抛错只丢该区块的行（记 `warn`），其余维度照常；**始终 push**（哪怕 0 行）→ `catHeads` 等诊断读数与改动前一致 |
| ③ | 13 处 `cats.push({…})` 全改为 `pushCat(head, md, () => rows)`；**不改任何拼接 / 排序 / 预算逻辑** |
| ④ | 补反向探针（下节） |

**首批实现时踩到的自伤（如实登记）**：批量改写脚本把 `pushCat` **自己内部**的 `cats.push({…})` 也改写成了 `pushCat(...)` → 自递归 →
`Maximum call stack size exceeded` → 整个注入体变空（`recall-golden` R10–R12 立刻变红）。已改为直接 `cats.push` 并就地标注「⚠️ 此处不可写成 pushCat」。

**验收（对应 `docs/D45` §8 的判据）**：
- 正常路径**逐字节不变** —— `recall-golden` R10/R11/R12（含 300 字预算裁剪）全绿；
- 新增 **N 组 15 项**反向探针：逐维构造「数组含 `null`」与「该维度不是数组」两种脏数据 → 正文**非空**且含 `## 情节记忆` 见证条目；实现前该 15 项**全红**；
- 一处既有源码形态断言（`map-model` G4）随 `pushCat` 包裹更新（语义不变）并加注。

## 2. `应-41` 修复应用器与键归一化的口径错配（应用 · P1）

**缺陷（`docs/D45` §2.3 F2）**：AI 的**中文键**指令在生产路径**永不命中** ——

| 处 | 原状 | 后果 |
| --- | --- | --- |
| 计划合并 | `core/plan-repair.js#applyPlanSuspMerge` 只读 `delta[cat].merge`，而合同里的中文键「合并」**不在** `core/config.js#CN_KEY_MAP` → 回包经 `normalizeDeltaKeys` 后落在 `delta.plans['合并']` | AI 说「合并了」，库里**没合** |
| 状态删除 | `core/state-repair.js#applyStateRepair` 只认 `ops['删除']` / `ops.delete`，而归一化已把「删除」→ `remove` | AI 要求删的状态记录**不会被删**，且计数上看不出被跳过 |

**修法（`docs/D45` §8 `应-41` 步骤 ① ② ③）**：
1. `CN_KEY_MAP` 补 `'合并': 'merge'`（归一化后进入 `delta.plans.merge`）；
2. 两处应用器**同时接受中英两键**（`merge` / `'合并'`；`remove` / `'删除'` / `delete`）—— 未过归一化的调用方也能命中；
3. 反向断言：构造**中文键回包** → 归一化 → 应用 → 断言数据**真的改了**（去掉任一键的兼容即红）。

**有意偏离 V1（守则 §2.4 类别②）三件套**：
- 设计稿：`docs/D45` §2.3 / §8 `应-41` 明确「修的是 V1 既有缺陷」；
- 本批次档（本文件）+ `CHANGELOG` v3.50.5 条目登记偏离；
- 测试：黄金样本 `v1-golden-plan-repair.json` / `v1-golden-state-repair.json` **一字未动**，在**测试内显式归一**（plan：`mergedP` 0→1、`closedP` 1→0、`removedDup` 1→2、`plansClosed` 1→0、通知文案按 token 归一；state：`deleted` 0→1、`changed` 5→6、`invalid` 3→4、`unknownRole` 1→2、`after` 7→6、文案按 token 归一）并**另行断言 V2 真实值**；
- `I10`（状态）另加「**剥掉删除段后与黄金样本逐字段相等**」的证伪（证明除删除段外一字未改）。
