## 2. `技-31`：一条「必然误报」的判据，与它的三个合法削减

真机日志（`docs/D29` §2 行 2）：`{"action":"合并自检","atomsBeforeLocal":115,"atomsBeforeRemote":20,"atomsAfter":20,"unionMin":115}`
→ 旧判据（`after < unionMin`）登记「并集自检异常」。问题是**合并实现本身**还会做三件合法的事：

| 削减 | 代码位置 | 为什么合法 |
| --- | --- | --- |
| 内容去重 | `core/migrate.js#contentDedupeArray`（`mergeDataObjects` 内） | 同内容异 id 是**同一剧情**在两端各自生成的（id 由文本+楼层派生）→ 只留较新一条 |
| 墓碑过滤 | `core/sweep.js#applyDeletedToArray` | 跨端删除必须传播，否则「删了又被对端并集复活」 |
| 上限裁剪 | `core/merge.js#capAtomsKeepingHidden`（落库在 `core/ingest.js`） | 存储上限；隐藏条目永不裁剪 |

修正后的判据在 `core/cross-sync.js#unionSelfCheck`（**纯函数、可单测**）：

```text
下限 = max(本端合并前条数, 远端合并前条数) − 墓碑命中 − 内容去重命中 − 上限裁剪命中
异常 ⟺ 合并后条数 < 下限          （三项削减**分别回报**，详情文案附明细）
```

**上限裁剪是「干跑」读数**（`capReductionOf`）：只算「若此刻裁剪会削掉几条」，**不裁剪**入参数组 —— 因为真正的裁剪发生在
`core/ingest.js` 的 ingest 路径，合并路径不该替它做决定。**反向探针**（`docs/D29` §5 R1 的硬要求）：三类合法削减 → 不登记；
真丢失 → 必须登记并给出「无解释消失的条数」（`tests/unit/union-self-check.test.js` A1/A2）。

**V1 偏离三件套**（`开发守则.md` §2.4）：`stat` 新增 `conflict` / `reductions` 两键 → ① **黄金样本一字未动**；
② 测试内**显式归一**（`cross-sync-golden.test.js` S3 只比 V1 四键 + 新增 S3b 断言新键）；③ 文档说明写进 `docs/D29` §3.2/§8.1。
**同步语义零改动**：合并结果的数据指纹仍与 V1 逐项一致。

## 3. `技-35`：一致性读数为什么必须「并入现有出口」

真机同一状态同时有四个数字（同步 **465** / 体检 **488** / 本机层与主文件 **482** / 内存态 **479**）—— 差别**不是 bug**，
而是四个口径**各算各的**：体检 `scanned.items` 把 `links` 关联行与所有被扫容器都算进去；本机层数的是**信封里存了什么**；
读取台账记的是**读取动作**。用户要的是「一眼判断两边是否一致」，所以 Q2 裁决 **并入 `ftt.dataHealth` / `ftt.loadDiag`**
（少增方法、口径集中），且读数由**一个函数**给出（`consistencyReading`）：

- `count` = 原子层各大类条数合计；**不含**墓碑 / `links` / `vars` / 快照链，**含**货币与名册；
- `fingerprint` = `dataAggHash`；`at` = 取值时刻（**四处读数必须同一时点**，故随读数返回）；
- `semantics` 随读数一起返回「含什么 / 不含什么」，四个旧口径的差逐个写在 `docs/D13` §8.10.4。

## 4. `技-33` / `技-34`：把诊断噪声清干净

- **旧路**（`<目录>/ftt2-local-*.json` 与平铺名 `<目录>-ftt2-local-*.json`）在真机每次载入成对失败，把「服务端文件 失败 N」灌满。
  本版：**命中过就永不停止探测**（旧存档照旧能捞回，R2），只有**全部未命中**才在本会话停探；两条旧路读取走新增的
  `noLedger` 出口 —— **不进读取台账**，改由 `localFileStats.legacyProbes` / `legacyHits` 单独计数，并在 `ftt.localDir`
  的 `deprecatedPaths` 里连名字带口径（「旧路径 · 已停用 · 不参与判定」）一起列出来。**不静默**：命中旧路时写调试日志。
- **台账三桶互斥**：旧实现先 `if (ok) ok++ else fail++`，再无条件执行 `if (miss) miss++` → 一条 `reason:'miss'` 的记录**同时**进 `fail` 与 `miss`。
  真机因此读成 `stats.miss = 1` 而台账里 ≥2 条「未命中」——用 `miss` 判断「本机层是否可用」会得到**相反结论**。
  现由 `readLedgerBucket` 统一入桶，文本行与统计**同源**，`avgMs` 分母一并修正（旧分母 `ok+fail` 在互斥后会把均值抬高）。

## 5. `数-28` / `数-29`：存量收口，一条都不删

- **分片回收**：基准 = **当前链**（清单 `order` + 逐条 `parts[].hash`），写盘后逐个比对；四道闸门（命名形态 → 可读 →
  **仍被引用绝不删** → 快照内容形态）+ 两条保守闸门（链为空不删 / 本次写盘不完整不删）。**只删 `snapshots/` 下的派生条目文件**；
  日志类（`parts.logs`）按 Q4 **不碰**。读数侧把 `files ≠ count` 的来源写清楚（写侧 `files` 含 `manifest.json` 索引）。
- **归属补写**：只在「当前聊天键 + 内容指纹」**双命中**时幂等补写（条目用 `atomContentHash`，标记用 `h` ↔ 注入的楼层哈希），
  **只补空值**、判不出不写、**不删一条**；判不出的保留「升级前历史数据」**独立计数**（Q3）。附带修 U202（自愈抹掉 `ck`/`at`）。
