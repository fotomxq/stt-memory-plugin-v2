## 1. 缺陷：货币（`currencies`）跨端**总是没有同步**

**用户报告**：货币总是没有同步。**取证前提**：`currencies` **不在** `core/constants.js#ATOM_DIM_KEYS` 内（该常量 13 项；`docs/D8` R11 裁定「货币暂不纳入（身份）哈希」）。

### 1.1 根因（三条同源；缺任何一条都不会出现「总是」这个观感）

| # | 环节 | 旧行为（代码取证） | 用户可见后果 |
| --- | --- | --- | --- |
| 1 | `core/cross-sync.js#mergeDataObjects` | 货币只出现在「**非原子维度：整体取较新一侧**」名单里（`remTs > baseTs` 才 `copyVal(remoteData[k])`） | 对端信封较新 → **本端独有货币被整维丢掉**；本端信封较新 → **对端货币永不并入**（单向覆盖，永不成对合并） |
| 2 | `adapters/sync.js#crossComputeInfo` | `dataAggHash` **计入**货币原始 JSON（含 `uses` / `floor*` 等易变字段）而 `diffAtomData` 按 `ATOM_DIM_KEYS` 遍历、**看不见货币** → 「两端只差货币」时 `aggSame=false` 且 `diff` 六个计数全零 | 判成 `replace-remote` / `replace-local`（**整体替换**）→ 本端较新的账本被对端旧账本整体盖掉 |
| 3 | `adapters/sync.js#adoptRemoteEnvelope` | 「立即同步 / 采用对端」= 整信封替换（只并快照链与墓碑，**不含任何货币并集**） | 本端货币**整维丢弃**（含尚未推送到对端的条目） |

### 1.2 修复（与其它原子维度同口径）

| 落点 | 改动 |
| --- | --- |
| `core/cross-sync.js#mergeCurrencyArrays`（新增，导出） | **逐条并集**。身份键优先「归属 + 币种」（= `core/ingest.js` 与 `core/model/money.js#normalizeCurrency` 的唯一性口径；兼容 V1 原始字段名 `who` / `kind`），二者不全时退回 `id`，都没有则**原样保留、永不合并**；冲突取「条目 `updatedAt` → 信封时间」较新的一侧；**收支流水并集**（复用 `core/model/money.js#mergeMoneyHistory`：同日期 + 同额 + 同说明去重、最近 12 笔）；NSFW / 溯源标记「只升不降 + 补空」（复用 `nsfwMergeLevel` / `mergeEntryProvenance`）；无收支时**逐字段取自胜出一侧**（与 V1 结果逐字段一致） |
| `core/cross-sync.js#diffCurrencyData`（新增，导出） | 货币差异统计 `same / onlyLocal / onlyRemote / conflict(+胜负)`；「内容」比较用**内容签名**（归属 / 币种 / 单位 / 额度 / 备注 / 日期 / 标签 / 流水）→ **`uses` / `floor*` 不同不算内容冲突**（否则两端永远判冲突） |
| `core/cross-sync.js#mergeDataObjects` | 货币**移出**「非原子容器整侧取较新」名单，改走逐条并集 + `core/sweep.js#applyDeletedToArray('currencies', …)`（**id / 内容双墓碑**，删除不复活；削减量进 `stat.reductions.byDim.currencies`）。其余非原子容器（`summaries` / `npcs` / `protagonist` / `vars` / `varTemplates` / `state`）**行为不变** |
| `adapters/sync.js#crossComputeInfo` | 新增 `curDiff` 并把**货币差异并入「是否超集」判据**；再加一条：**原子层完全一致、差异只落在非原子容器时不整体替换**（替换只会顺带丢掉本端独有非原子数据，却换不来任何原子数据） |
| `adapters/sync.js#adoptRemoteEnvelope` | 整体替换**之前**先 `mergeCurrencyArrays` 并入本端货币（并列冲突取「信封较新的一侧」，与合并路径同规则），再过同一套双墓碑；该段失败**不阻断**整体替换 |

### 1.3 有意**不动**的部分（V1 黄金样本锁定，`开发守则.md` §2.4 类别①/②）

| 不动的东西 | 为什么 |
| --- | --- |
| `dataAggHash` 的算法（含「货币原始 JSON 进指纹」） | `cross-sync-golden` **S1 / S4** 与 V1 oracle **逐字符比对** |
| `atomEntryCount` 的维度集合（仍 13 项，**不含**货币） | 同上 **S14** 与 `logStat.n` |
| `diffAtomData` 的字段集与返回键 | 同上 **S2**（`J()` 全等）与 `sync-pick-golden` **R1** |
| 是否把 `currencies` 并进 `ATOM_DIM_KEYS` | 会同时改上面三项的对外值 → oracle 失效；本版选「**合并语义升到原子口径，指纹 / 条数保持 V1 口径**」 |

> 因此货币差异**单独统计**（`diffCurrencyData`）并**并入** `crossComputeInfo` 的超集判据 —— 这是「不合进 `ATOM_DIM_KEYS` 也能正确决策」的关键一步。

### 1.4 反向探针（守门单测不是恒真）

| 反向改动 | 必须失败的断言 | 实测 |
| --- | --- | --- |
| 把 `currencies` 放回 `mergeDataObjects` 的「非原子容器整侧取较新」名单 | `currency-sync` **C1**（并集保留本端独有货币）/ **C3**（墓碑不复活 + 削减量入账） | ✅ 已实测：14 通过 / 2 失败 |
| 去掉 `crossComputeInfo` 的货币判据（`curDiff` 不参与超集判定） | `currency-sync` **D1**（「只差货币」不再判 `replace-remote` / `replace-local`） | ✅ 已实测：15 通过 / 1 失败 |

## 2. 口径更正：一致性读数的「含 / 不含」（**按代码实测**）

`core/cross-sync.js#consistencyReading` 的 `semantics` 原先写「**不含** `links` 关联行」与「**含**货币与名册（它们在 `ATOM_DIM_KEYS` 里）」，
与 `core/constants.js#ATOM_DIM_KEYS` 的实际内容**正好相反**：`links` / `plotSegments` **在**该常量内（第 11 / 12 项），`currencies` / `npcs` **不在**。

| 项 | 更正后 |
| --- | --- |
| `semantics.includes` | `['links', 'plotSegments']` |
| `semantics.excludes` | `['deleted', 'deletedH', 'vars', 'snapStore', 'currencies', 'npcs']` |
| 守门单测 | `tests/unit/data-health.test.js#C5`（旧断言要求 `excludes` 含 `links`） |
| 文档 | `docs/D13` §8.10.4（含 / 不含两行）· `docs/04`（一致性读数那一行）· `docs/02` §1.2 / §6 |
| **未改** | `count`（`atomEntryCount`）与 `fingerprint`（`dataAggHash`）的**算法**；两处出口（`ftt.dataHealth.consistency` / `ftt.loadDiag.consistency`）**同源同值**不变 |

> **为什么值得同批修**：「货币在 `ATOM_DIM_KEYS` 里」这个错误说法，会让人（与后续实现者）默认「货币已经逐条合并了」——
> 这正是本缺陷长期未被定位的原因之一。更正的是**说明文字**，不是口径数值。

### 3.2 已发现的口径差异与未取得项（如实登记）

1. **两条部署入口的条件判定不同源**：`开发守则.md` §6.4 的触发条件是「本地运行 **且** 调试端口已启动」；
   `npm run local:sync` **会**探端口（CDP `debugPort` 默认 9222，或短听 8791 收到插件拨入），而 `npm run local:deploy` 的五条条件里**没有**这一条
   （见 `tests/local/README.md` §6c）。本版**只登记、不改行为** —— 是否统一由用户裁决。
2. **工具侧短听只绑回环**：`tests/local/sync-host.mjs#probeBridge` 的短听用 `server.listen(port, '127.0.0.1')` →
   若插件侧把「目标主机」填成**本机局域网地址**、而工具侧当时**没有**在监听，则该次探测收不到插件拨入（本地默认回环时不受影响）。
   保留现状的理由：条件探测问的是「本机宿主是否开着调试端口」，默认口径即回环；改成监听全网卡会带来防火墙提示副作用。
3. **未取得真机证据**（本机未跑真机宿主）：
   - 局域网（手机端）向 `192.168.x.x:8791` 拨入成功 —— 只有工具侧自检（回环 + `0.0.0.0` 绑定 + 帧编解码），**无真机端到端**；
   - CDP `9222` 是否真能起来 —— `launch-debug.cmd` 头注已写明「wry 会自行下发 browser arguments，该环境变量**可能被忽略**」，沿用该「待实测」结论；
   - `npm run local` / `local:sync` 的条件探测输出（本机是否装了宿主、端口是否在听）**未在真机跑过**。
