# P10c160 · 存档（聊天）分区：不同存档的数据区分（v3.52.7，W38）

> 文档版本：v1.0 ｜ 日期：2026-11-02 ｜ 状态：生效（v3.52.7）
> 用户要求（原话）：「不同的存档，数据应该加以区分，避免混淆。」
> 澄清选择：**按聊天存档隔离** · **每个聊天存档一份（角色内隔离）**。
> 设计稿 `docs/D60`（实施规格 4 条）｜ 台账 `docs/D17` **U297–U300** ｜ 清单 `docs/D22` §4.38（**W38**）。

## 1. 根因

记忆容器**按角色**存（`scope: char:xxxx`）—— 同一角色的每条聊天共用一份 `atoms/snapshots/memories/items/…`。
v3.20.0 只给**新落库条目**打了 `chatKey`（聊天归属），但**读取侧从未按它分区**：
列表、计数、注入、上限裁剪、低使用遗忘全都用整份数组 → 换一条聊天存档仍会看到/注入/清理别条存档的数据。

## 2. 方案（逻辑分区，物理存储不变）

新增 `core/archive-scope.js`：

| 概念 | 口径 |
| --- | --- |
| 分区键 | 条目 `chatKey`（兼容短键 `ck`）；当前档 = `state.chatKey`（宿主从聊天文件元数据读） |
| 档位 | `current` 本档 / `legacy` 无归属（升级前历史数据）/ `other` 别的存档 / `all` 当前档未知（fail-open） |
| 可见 | `current` + `legacy`（历史数据**保留可见并打「旧存档」标**，不静默藏） |
| 隐藏 | `other` 一律隐藏，**不参与注入、不参与上限裁剪、不参与低使用遗忘** |
| 归档 | 「↪ 把旧存档归入当前」= **只补空归属**（已有归属不动）、幂等、危险动作二次确认 |

接线：
* 读侧：`ui/panel.js#arrOf` / `ui/console.js#arrOf`（列表与统计同口径）、`core/recall.js#stSafe`（注入只取本档）；
* 清理侧：`core/ingest.js` 上限裁剪（`capVisibleKeepingOthers`；snapshots 再叠关注保活）与 `enforceDimCaps`（只裁可见档）；
  `core/forget.js` 低使用遗忘跳过其它存档；
* 界面：面板外壳横幅 `data-ftt-archive-bar`（`ui/archive-banner.js`）+ 行内 `旧存档` 徽标（`data-ftt-archive-legacy`）+ `archiveAdopt` 动作。

**fail-open**：`state.chatKey` 读不到时不分档（行为与旧版一致）—— V1 黄金样本 / 冷启动零漂移。

## 3. 测试

`tests/unit/archive-scope.test.js`（**10 项**）：fail-open · 三档判定（含 `ck`）· 统计 · 列表/计数隔离 · 横幅与入口 ·
归档幂等/未知不写/面板动作落盘 · 上限裁剪不裁别档。

全量单测 **264 文件 / 3913 断言**；冒烟 224 项；`npm run gate` 全绿。

## 4. 边界（如实登记）

1. **物理仍是一份文件**（每角色一份）：导出/备份含所有存档数据；导入后条目仍按 `chatKey` 归原档（不串档）；
2. **不改 `DATA_VERSION`**、不动服务端文件命名、不改跨端哈希（`chatKey` 不在 `HASH_FIELDS`，归档零哈希漂移）；
3. 别的存档条目仍占物理空间（不自动清理，`docs/D28` 不删数据纪律）；可切到对应存档自行清理；
4. 历史数据归入本档 = 一次显式认领（需确认、可先导出备份），**不自动执行**。
