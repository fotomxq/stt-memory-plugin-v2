## 2. 真机暴露的缺陷与修法

`ftt.memoryShape` 在真机上 **`states` 与 `roster` 恒为 `null`**。

- 根因：容器真名是 **`currentStates`**（状态记录）与 **`npcs`**（名册）；`states` 这个名字在容器上
  根本不存在，`roster` 也不存在（`DIMENSIONS` 的 14 项里也没有名册，名册是额外运行时容器）。
- 修法（不止手改两个字符串）：维度列表现为**从 `core/constants.js#DIMENSIONS` 派生**（单一来源），
  再补 `npcs` / `vars` / `deleted` 三个运行时容器 —— 这样今后新增维度会自动出现在探针里，不会再漂移。
- 回归锁定：单测新增 **B9/B10**（断言键集恰为 `DIMENSIONS` + 三个补充项、且**不含** `states`/`roster`；
  注入真实容器后 `currentStates`/`npcs` 返回条数而不再是 `null`）。

> 这个缺陷是「无头浏览器模拟」不可能发现的 —— 它只在真实宿主里读真实 `state` 时才暴露，
> 恰好印证了用户「Edge 调试模拟不出真实情况」的判断。

## 3. 手机端：原实现做不到，本版据此扩了口

### 3.1 为什么原实现不行（三条硬事实）

| 事实 | 证据 |
| --- | --- |
| 插件拨号目标**写死回环** | v3.0.7 `adapters/debug-bridge.js`：`ws://127.0.0.1:<port>` —— 只能连**自己设备** |
| 桥接服务只监听回环 | `tests/local/bridge.mjs`：`HOST = '127.0.0.1'` |
| 两端不在同一台设备 | 调试机 WLAN 与用户给出的手机地址不同网段位置；实测该手机地址**不可达**（可能离线/休眠或 IP 已变） |

结论：手机上的插件拨的是**手机自己的** `127.0.0.1`，与调试机的端口无关 —— 必须让插件能指定**目标主机**，
并让桥接服务监听局域网。

### 3.2 本版改动

1. **插件侧目标主机可配**（`adapters/debug-bridge.js`）：
   `setBridgeHost` / `bridgeTarget` / `isLoopbackHost`，默认仍 `127.0.0.1`（**向后兼容**）；
   只接受主机名 / IPv4 / 方括号 IPv6，拒绝带协议或路径的输入（避免拼出意料之外的 URL）；
   `bridgeState()` 新增 `targetHost` 与 `loopback`。
2. **调试页**：把「仅端口」扩为「**目标主机 + 端口**」；动作 `bridgePortSet` → **`bridgeTargetSet`**
   （旧名保留为别名，避免旧页面残留按钮失效）；目标非回环时显著提示
   「只读调试面将对局域网开放，同网设备可读」。
3. **桥接服务**：`tests/local/bridge.mjs` 新增 `--host`（默认仍只监听回环）；
   非回环时启动即打印安全提示；`--selftest` 在监听 `0.0.0.0` 时自检仍走回环。

### 3.3 安全取舍（用户已明确选择）

用户选择「接受：监听局域网 + 只读」，即 **不加令牌鉴权**。因此：

- 桥接**仍是纯只读**（清空 / 删除 / 修复 / 导出落盘一律不登记）；
- 默认**不**监听局域网（要显式 `--host`）；
- 插件侧默认**不**连非回环目标（要显式改目标主机），且改后页面与工具都给出暴露提示；
- 批次档此处**如实登记**：局域网模式下同网任何设备都能读到这些只读数据（记忆条数与取样、
  调试日志统计、宿主 LLM 请求留档）。**如需长期开放，应先补令牌鉴权。**

## 6. 未验证事项与缺口（如实登记）

1. **手机端未实测**。本机无法访问用户给出的手机地址（不可达），故「手机 → 局域网桥接」这条路
   只完成实现与单测覆盖，**未在真机跑通**。首次使用建议：调试机 `--host 0.0.0.0`，
   插件目标填调试机的局域网地址，先确认 `ls` 能列出方法。
2. **局域网模式无鉴权**（用户已确认接受）。若今后要长期开放或引入写操作，必须先补令牌。
3. **混合内容限制仍在**：若以 HTTPS 提供酒馆原生页面，页面连 `ws://` 会被浏览器拦截
   （TauriTavern 因 `csp: null` 且为 `http://` 源不受影响）。本版未处理。
4. **`--deploy` 仍未在真实宿主上执行过**（沿用 v3.0.6 的登记）。
5. **冒烟 `BI1` 有偶发失败（本批实测，已定位为时序问题，非本版回归）**：归档复跑的第 1 次冒烟为
   **186/187**，失败项即 `BI1`（真实分段摘要「在途期间」的管线状态：标签「批量摘要」+ prompt token +
   预估倒计时 + 阶段 + 结构摘要）。随后在**同一归档目录连跑 3 次均为 187/187**，主仓库 `npm run gate`
   亦连续两次 187/187。故判定为**时序偶发** —— 该断言依赖在途流式状态与倒计时推算，对调度敏感；
   与 v3.0.8 改动无关，也与「改名目录」无关。本批**只登记、未改该断言**（改法属测试健壮性专项，
   应单独一轮处理：例如放宽倒计时断言或注入可控时钟）。
