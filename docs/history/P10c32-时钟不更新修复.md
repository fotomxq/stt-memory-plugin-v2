## 1. 现象与取证

**现象**：调试接口里能看到「情节」已经是最新的，但**时钟（日期/时间/地点）不更新**；点「🛠 自动修复」也没变化。

**取证一（真机落盘状态，离线复算）**：

| 项 | 值 |
| --- | --- |
| 时钟 `state.state` | `{date:"327-03-15", time:"下午", location:"昆仑山>西行三十里深谷>谷底>石洞>地下书斋>地热石洞>外间"}` |
| 真正最新的情节（按**当前位置** `floorNow*`） | 现在 **196 楼** · `628-04-28` · 上午 · 平民集市 |
| 生产选片选中的情节 | 原始 **508 楼** · `originGone:true`（原文已移除）· `327-03-15` · 时间/地点**空** |
| 楼层尺度 | 最大 `floorNowEnd = 160` ｜ 最大 `floorEnd = 508` → **两种尺度混比** |

**取证二（读代码定根因）**：`core/recall.js#trustedPlotList` 是**时钟解析与在场解析共用**的情节顺序，
其排序键写作 `Math.max(floorEnd, floorStart)` —— 即**原始楼层**（v3.7.0 起「原始楼层不可变」的溯源字段），
而拆楼重编号后的**当前位置**记在 `floorNowStart/floorNowEnd`。于是原始 508 楼的旧情节**永远排在**现在 196 楼的最新情节之前
→ 时钟（以及走同一解析的「修复」）始终从那条陈旧情节的 `date/time/location` 取值。

**取证三（读代码定「修复也没用」）**：「🛠 自动修复」第 1 段的剧情时钟步骤 =
`core/repair.js` 的 `repairHooks.clockSync` → `index.js` 接到 `clockAutoExtractOnce({force:true})` ——
**同一条 `resolveStoryClock`**，因此读到同一条陈旧情节、`changed=false`，点几次都不会有变化。

## 2. 修法（`core/recall.js` 三处，同一口径）

| 位置 | 改动 |
| --- | --- |
| `trustedPlotList()`（时钟 + 在场共用顺序） | ①「楼层」改用**当前位置**：`floorNow*` 优先、缺失才回落 `floorStart/floorEnd`（口径同 `core/floor-cover.js#meaningfulFloorRange`）；② 新增 **`originGone === true` 降级**：原文已移除 ≠ 剧情当下（位置也不可信）→ 排到活情节之后；**不排除**（全部无原文时仍能取到，向后兼容） |
| `latestPlotByFloor()`（在场角色的情节来源） | 同上（活情节优先 + 当前位置排序）—— 此前会把陈旧情节当成「最近现场」，把在场角色一起带偏 |
| `atomLatestDated()`（快照参考时钟） | 同上（优先活情节；同日期按**当前位置**比较）—— 旧聊天残留的「未来日期」（真机 `628-12-31` 一类）不再胜出 |

**口径边界（有意保持）**：`storyDay`（内置天数，两边 >0 时优先）**不变**；「无楼层信息」的手动情节仍按日期兜底 **不变**；
排除项（`hidden` / `summarizedBy` / `mergedSummary` / `validity==='inactive'`）**不变**；无 `floorNow*` 的存档行为**逐字不变**。

## 3. 修后真机复算（同一份存档，跑生产函数）

| 验证 | 结果 |
| --- | --- |
| `resolveStoryClock()` | `{date:"628-04-28", time:"上午", location:"罗马城", present:["李瑶"], plotFloor:200, source:{date/time/location:"plot", present:"plot-atom"}}` |
| `clockAutoExtractOnce({force:true})`（=「修复」同一条处理） | **`changed = true`**：`327-03-15 / 下午 / 昆仑山…` → **`628-04-28 / 上午 / 罗马城`**；`clockSrc` 全为 `plot`、`degraded:false`、`jumpYears:0`、`manual:false` |

> 注：两次复算之间最新情节从「196 楼 · 平民集市」变成「200 楼 · 罗马城」——用户正在游玩，数据是实时变化的；
> 关键点是**选中的都是活情节且为当前楼层的现场**。

## 5. 未验证项（如实登记）

- **真机页面仍运行 v3.15.1**（端口握手 `sys.info` = `3.15.1`）：v3.16.0 与本版都还没加载，
  所以本修复的真机表现**待刷新后核对** —— 刷新后建议用 `ftt.clockTraceInfo` / `ftt.clockTraceSummary`
  复核取值链（应显示来源 `plot`、指向当前楼层），以及 `ftt.snapshot` 的 `state.state`；
- 「时钟从 327-03-15 跳到 628-04-28」这类**大幅度日期变更**：`clockDateAnomaly`（跳跃 >50 年判异常）
  只在**巡检**路径使用（`clock-patrol.js#clockPatrolSafeDate`），**不参与** `resolveStoryClock` 的时钟写入 →
  本修复不会被它拦住（真机复算 `jumpYears:0`、`degraded:false` 亦印证）；
- 顺带观察（**未改**）：同一角色的 `atoms` 跨聊天共用，`atomLatestDated` 虽已优先活情节，
  但「跨聊天日期混用」的根因（`atoms` 无聊天作用域标记）仍在 —— 属独立议题，需要时单独评估。
