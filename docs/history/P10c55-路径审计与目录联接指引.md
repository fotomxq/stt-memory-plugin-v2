## 1. 核对结论：**数据在写，只是不在 D:\**

| 项 | 实测（只读取证） |
| --- | --- |
| 配置生效值 | `storage.localFilePath = "fft_v2_store"` —— **不是整条路径**。原因：「📂 从系统选择文件夹…」受宿主限制**只取文件夹名**（早前已在 UI 注明），用户随后采用的就是这个名字 |
| 真实落点 | `<数据根目录>/_tauritavern/extension-store/fft_v2_store/`：**13 个文件 / 2.06MB**，且随保存持续更新 |
| 内容 | 本机缓冲（`blobs/local/fft_v2_store_ftt2-local-char_<角色>.json`，1.23MB）+ 辅助数据（`aux/` 下：调试日志 98KB、交互时间线 11KB、版本清单 111KB、同步与对账标记 6 个、**快照副本 678KB**、**同步日志副本 16KB**） |
| `D:\Downloads\stn\fft_v2_store` | 目录存在、**为空** |

**为什么写不到 D:**：宿主扩展存储只能在**数据目录之内**落地（`data_root/_tauritavern/extension-store/<命名空间>/…`）；命名空间只允许 `[A-Za-z0-9_.-]`，**绝对路径传不进去**。插件的归一规则：剥盘符、剥前导斜杠、丢 `..`、非法字符转 `_`、多级路径折叠成**单个命名空间名**。

## 3. 想真的落到 D:（诚实做法：目录联接）

Windows 不允许扩展写数据目录之外，但可以让**数据目录内的那个命名空间目录**变成指向你目标目录的**联接**：

1. 把 `<数据根目录>\_tauritavern\extension-store\fft_v2_store\` 里的文件**全部移动**到 `D:\Downloads\stn\fft_v2_store\`（目标先清空）；
2. 删除空掉的命名空间目录；
3. 运行：`mklink /J "<数据根目录>\_tauritavern\extension-store\fft_v2_store" "D:\Downloads\stn\fft_v2_store"`；
4. 之后插件照旧写命名空间，实际文件落在 D: 的目标目录（两个路径看到同一份）。

UI 会把上面四步与命令**用真实路径生成**（数据根目录由 v3.27.0 的 `ttDataRoot()` 提供），直接复制即可。

## 5. 纪律（写进本档）

* 「用户填了绝对路径」是**预期会发生**的（用户想在自己的盘上管理数据）→ UI 必须**主动**说清「会被改写成命名空间 + 真实落点在哪 + 想真落过去要怎么做」，而不是让用户去文件管理器里扑空；
* 任何「受宿主限制的改写」都要有**可核对出口**（审计函数 + 诊断字段），不靠猜。
