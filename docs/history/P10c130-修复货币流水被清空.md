# P10c130 · 修复「货币快速记账后流水被清空」（v3.50.21）

> 文档版本：v1.0 ｜ 日期：2026-10-15 ｜ 状态：生效（v3.50.21）
> 用户原话：「货币的增减功能，新增记录，但可能存在问题，导致记录全部被清空了。请核对并修复。」
> **版本位**：用户指定 **v3.50.21** —— 数据丢失级缺陷修复 → 守则 §3.1 的 patch 位，**无偏离登记**。
> 关联：`core/model/money.js#normalizeMoneyHistory` · `core/currency-quick.js` · `ui/console.js#consoleSave` · `CHANGELOG.md` v3.50.21

## 1. 复现（先证实，再修）

用真实链路（快速记账 → `consoleSave`）复现，**一次就中**：

```text
保存前：条数 = 2 | A 额度 = 100 | A 流水 = 1
应用结果：ok = true | 新额度 = 150 | 新流水 = 2 | 说明 = 收入50元 修正
consoleSave = {"ok":true,"id":"cur_a"}
保存后：条数 = 2
保存后：A = {"amount":150,"history":[],…,"extra":[{"name":"history","type":"integer","value":2}]}
                ↑ 额度对了，**流水被清成 []** ×
```

## 2. 根因（形状不匹配）

货币流水的**入参有两种合法形态**：

| 形态 | 谁在写 | 例 |
| --- | --- | --- |
| ① **AI 抽取形态** | `normalizeDelta` / AI 提取 | `{增减:'收入', 数额:50, 说明:'…', 日期:'…'}` |
| ② **已归一形态** | `moneyNet` / `mergeMoneyHistory` / **快速记账** | `{date:'', delta:50, note:'收入50元 修正'}` |

`normalizeMoneyFlow`（V1 逐字移植）**只认 ① 的「数额」**；
而 `normalizeCurrency` 的 `history` 归一又把**每一笔**都塞给它 → ② 的条目 `Number(undefined)` = `NaN` → 判 `null` →
`normalizeMoneyHistory` 拿到**空数组** → **保存即清空**。

**为什么我的单测没抓到**：v3.50.17 的测试只测了 `applyQuickCurrencyFlow`（纯函数）**没有测归一化/落库那一步** —— 边界选错了。本轮补了端到端断言（`B2`）正是为了堵这个洞。

## 3. 修法（两层）

1. **容器级兼容**（`normalizeMoneyHistory`）：先走 `normalizeMoneyFlow`（保持 V1 逐字，**黄金样本不动**），
   认不出时再**按已归一形态**读（`delta` 数值 + `date`/`note`）；
2. **最后一道抢救**：仍一条都没有但输入非空 → 把有 `数额`/`amount` 的条目按最小形态保留（`{date, delta, note}`）——
   **宁可少一条说明，也绝不静默清空**。

> 曾试过直接改 `normalizeMoneyFlow`（让它认 `delta`），但 `tests/unit/model-golden2.test.js#M4` 用 V1 黄金样本锁着
> 「`{at,delta,note}` → `null`」的行为 → 立刻红。**改在容器级**既保住 V1 逐字，又让 round-trip 安全。

## 4. 已验证（修复后同一条链路）

```text
① 应用后：额度 150 | 流水 2 | 末笔 {"date":"1919-11-01","delta":50,"note":"收入50元 修正"}
② 归一化后：额度 150 | 流水 2 | 明细 [{"date":"","delta":20,"note":"收入20元"},{"date":"1919-11-01","delta":50,"note":"收入50元 修正"}]
③ 保存后：ok true | 额度 150 | 流水条数 2   ← 不再被清空 ✓
④ AI 抽取形态：流水 [{"date":"1919-11-02","delta":-3,"note":"买酒"}]   ← 回归未破 ✓
```

## 5. 测试（`tests/unit/money-flow-shape.test.js`，**8 个断言**）

| # | 断言 |
| --- | --- |
| `A1` | **已归一形态**不再被丢弃（正负号/说明/日期原样） |
| `A2` | **AI 抽取形态**仍按原口径（V1 回归保护） |
| `A3` | 两种形态**混在一起**都能留下，`moneyNet` 合计对得上（100 − 40 − 10 = 50） |
| `B1` | 快速记账 → **归一化后**条数不减、末笔正确 |
| `B2` | **端到端**：`consoleSave` 之后额度正确 + 流水条数不变（本轮 bug 的正面断言） |
| `C1` | **抢救**：只有 `amount` 的条目也会被保留（不再返回空） |
| `C2` | 两笔完全相同的记录**不合并**（人工记账 = 两笔） |
| `C3` | 上限仍是最近 **12** 笔；`normalizeCurrency` 字段齐备 |

## 6. 已损坏数据（如实登记）

**v3.50.17–v3.50.20 期间**通过快速记账保存过的条目，其 `history` 已被清空为 `[]`（`extra.history` 只留了**条数**，无明细）——
**这部分无法自动恢复**。但：
- **额度是正确的**（用户可据此知道当前余额）；
- 若需要找回旧流水，可从**快照链**（`设定 → 数据管理 → 🧬 快照链`）挑一个该条目被清空之前的快照恢复；
- 本版之后不会再发生（上述两层保护 + 端到端断言锁死）。

## 7. 限制

1. 抢救出的条目**说明文本可能为空**（原条目只有数值时）；
2. `normalizeMoneyFlow` 仍是 V1 逐字（**故意不改**）：它只服务 AI 抽取形态，容器级兼容已覆盖读回场景；
3. **真机未人工试用**（建议刷新后：货币页点 `＋` → 填金额 → 确定 → 看流水**新增一笔**而不是清空）。
