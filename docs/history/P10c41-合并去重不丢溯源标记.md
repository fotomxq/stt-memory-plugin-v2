## 2. 根因链（确定性，可复现）

1. `originGone` / `hidden` / `summarizedBy` / `floorNow*` **不参与内容哈希**（`docs/D8` 槽位口径，**有意**如此：标记变化不该让跨端把同一内容认成两条）；
2. 合并 / 去重只按 `updatedAt` **整对象取一侧**：
   - `core/cross-sync.js#mergeDataObjects`「**同内容哈希**」分支 `merged.push(L[id])` —— 基底（滞后副本）**没有标记**，标记随整对象替换消失（真机走的正是这条：内容一字未改、哈希相同）；
   - 冲突分支同理（胜出侧无标记 → 败者侧标记被丢）；
   - `core/migrate.js#contentDedupeArray`（同内容异 id 去重）只并 NSFW 与楼层 / uses，同样丢标记；
3. 标记丢失 ⇒ `core/chat-scope.js#plotDemoted` 不再降级那条别条聊天的旧情节；
4. 真机 `lastChatFloor = 71` 这个**滞后末楼**使「位置越界」判据不触发（旧情节在第 25 楼 ≤ 71）⇒ 旧情节仅凭「位置 25 > 本聊天最新 23」取胜；
5. 同时 `state.chatKey` 为空（归属只在**消息渲染 / 切聊天**时记，而刷新首屏路径是「载入 → 合并 → 注入 → 重解析时钟」）⇒ 聊天分层失效 ⇒ 上述后果**必然**发生。

**一句话**：v3.20.0 把「哪条情节算数」交给「聊天归属 + 位置越界 + `originGone`」三重判据，而**第 3 重判据的标记会被合并洗掉**，第 1 重判据在刷新窗口里又还没就位 → 判据同时失效。

## 3. 修复（四处，全部「只保守、不放松」）

| 位置 | 改动 | 口径 |
| --- | --- | --- |
| `core/floor-cover.js` | 新增 `mergeEntryProvenance(target, other)` | **只升不降**：`originGone` / `hidden` / `summarizedBy` / `mergedSummary` 任一侧成立即成立；**补空不覆盖**：`originGoneAt` / `floorNowStart` / `floorNowEnd` / `floorNowHash` / `chatKey` 仅在目标缺失（含 `NaN` / 负数 / 非整数 / 空串）时补齐；返回改动字段名 |
| `core/cross-sync.js#mergeDataObjects` | 同内容哈希分支 + 冲突胜出分支各调用一次 | 合并**从不**清除标记；清除只能由本地已核实路径（`handleFloorShrink.mapEntry` 按内容哈希确认原文仍在 → `clearGone`） |
| `core/migrate.js#contentDedupeArray` | 对存活条目并入 `ex` 与 `it` 两侧标记 | NSFW / 楼层并区间 / uses 累计口径**不变** |
| `host/chat.js#attachKernelState` | 注入状态后立刻 `noteChatKey()` | 刷新首屏不再停在 `chatKey` 为空；读不到标识仍写空串（归属未知，不放宽分层） |
