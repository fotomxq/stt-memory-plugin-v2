## 1. 两处缺口

### ① 两个入口没有联动

「⚡ 立即 AI 摘要」（动作 `summary`）与「第 N 楼」（动作 `summaryFloor`）本来就是**同一条分析管线**的
两个入口（都经 `host/extract.js#genTracked` → `core/pipeline.js`），但按钮态 / 提示 / 通知各自为政：

| 场景 | 修复前 | 修复后 |
| --- | --- | --- |
| 批量在途点「第 N 楼」 | 按钮可点，点了才被拒 | 楼按钮**整体禁用** + title 写明「『⚡ 立即 AI 摘要』正在批量分析未摘要楼层 —— 等本次完成后再单独分析该楼」 |
| 单楼在途点批量 | 按钮可点，点了才被拒 | 批量按钮**禁用** + title「正在分析第 N 楼（会占用同一条 AI 管线）」 |
| 批量在途看按钮 | 文案不变 | `.ftt-loading` 转圈 + 文案「⚡ 分析中…（分段 x/y）」+ 禁用 |
| 批量的提示 / 通知 | 只有一行 `setNote`，无任何通知 | 同帧写提示（含待分析楼层数）+ 立即重绘 + 通知「AI 摘要：开始分析 N 个未摘要楼层…」；完成「AI 摘要完成：M 段 · 新增 X 条」（失败 warning） |
| 程序化重复触发 | 可重复启动 | 忙时如实拒绝（不重复启动） |

实现口径：**渲染驱动**（不靠点击时叠 class —— 紧随的那次重绘会把它换掉，v2.96.0 的教训），
状态源 = `hooks.busy()`（批次）+ `singleFloorBusy`（单楼集合）。

### ② 批次本身不占管线行（这就是「点了没有管线提示」）

v3.0.0 的管线块只渲染 `listPipelineRuns()`（AI 运行）。而一次批量分析里 **AI 调用只占一部分时间**
（还有段切分 / 预检 / 落库 / 快照 / 校正）——**两次调用之间整块消失**，用户看到的正是「点了没有管线提示」。

修复后（批次行带 `data-ftt-pipeline-row="batch"`）：

```text
🧵 管线状态
[AI] AI 摘要（批量） · 分段 3/8 · 第 9-16 楼 · 已用时 12s                       ← 批次整体（非 AI 阶段也在）
[AI] 批量摘要 · ⏱ 2s · 🪙 4.4k tok · 预计剩 18s · 阶段：请求 AI（第 9-16 楼）    ← 当前这一次调用
```

- 批次行的读秒来自 `batchProgress().since`（面板中途打开也显示真实用时）；
- `已请求中断` 挂在**批次行**上（只有批次能被中断）；
- 批次行存在时，AI 调用行不再重复挂批次进度（避免两行说同一件事）。

## 2. 验证（修复后的可见序列）

```text
点击「⚡ 立即 AI 摘要」的同一帧：
  按钮     → class 含 ftt-loading / disabled / 文案「⚡ 分析中…（分段 0/1）」
  楼按钮   → 全部 disabled + title「『⚡ 立即 AI 摘要』正在批量分析未摘要楼层…」
  提示行   → AI 摘要分析中…（3 个未摘要楼层 · 分段批量摘要，与「第 N 楼」同一条分析管线）
  通知     → info AI 摘要：开始分析 3 个未摘要楼层…
  管线块   → [AI] AI 摘要（批量） · 分段 0/1 · 已用时 0s
             [AI] 批量摘要 · ⏱ 0s · 🪙 4.4k tok · 预计剩 20s · 阶段：请求 AI（第 3-5 楼）
段与段之间（非 AI 阶段）：批次行仍在（不再整块消失）
完成后：提示「摘要完成：N 段 · 读取楼层 … · 新增 X 条」+ 通知 success
```

反方向（点「第 N 楼」）：该楼按钮转圈禁用、**批量按钮禁用并写明「正在分析第 4 楼…」**，
此时点批量被如实拒绝（不启动批次）。
