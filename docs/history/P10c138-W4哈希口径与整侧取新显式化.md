## 1. `数-3` 三件

### ① 指纹变化 ≠ 删除（`core/sweep.js`）

删除判定本来就分两层：**id 仍在 → 跳过**；**同内容（任一哈希口径）仍在 → 跳过**。本版把这条约束**显式写进代码注释**并用单测锁死：

* 同 id 改写正文（身份哈希变化）→ **不产生墓碑**；
* 跨口径 `it.h` 被刷新 → **不产生墓碑**；
* id 真的消失 → **+1**（只有这种情况才留痕）。

### ② `validity` 纳入「只升不降 + 补空」（`core/floor-cover.js`）

`VALIDITY_RANK = { active: 0, uncertain: 1, inactive: 2 }` → 取**更保守**的一侧；胜出侧缺字段则补空；两侧同值不制造假变更。
修的是真机风险：**胜出侧是较旧副本时，它的 `active` 会把已失效条目降级复活**，失效旧情节重新参与注入。

### ③ 跨口径指纹读数（`core/merge.js`）

`ensureAtomHashes` 在「已有 `it.h` 且与当前口径不一致」时刷新（幂等）并计数；
`hashGuardReadout()` → `{foreign, lastAt}`（只读）。**绝不因此判删除**。

### Q3：删死键

`calcImportance` 与 `importanceBase` / `importancePerUse` 一并删除（自 v2.86.0 起不参与展示与判定）；
同步 `ui/settings-pages.js` 的夹取分支、`importance-placement` 断言（改为「确实删干净」）、`config-clock-golden` 的 `REMOVED_V1_KEYS`（与 10 个时钟键同款登记）。
