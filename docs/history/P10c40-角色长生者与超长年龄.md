## 2. 为什么「超长年龄」要**另立一个码**（而不是复用 `overage`）

| 维度 | `overage`（v1.172 起） | `age-extreme`（v3.22.0） |
| --- | --- | --- |
| 阈值 | > 120 岁 | > 200 岁 |
| 语义 | 「**数据错误**」（年龄与剧情时间线明显冲突，须**修正出生日期**） | 「**待研判**」（可能是长期未出场而虚增 —— 也可能是真长寿，不得自动改数据） |
| 纪元豁免 | 有（剧情锚点年份 < 1000 视为自设纪元，整条不判） | **无**（真机 628 年剧情里出现数百岁的凡人，正是被这条豁免放过的） |
| 处置 | 允许并**要求**改写 `身份.出生日期` | **不改**出生日期；研判「长生者 / 已去世」两个开关 |

豁免（都不判 `age-extreme`）：**公元前出生**（v1.193 用户明确要求支持的跨公元前长寿写法）· 内容层长寿信号（`snapshotLongLived`：精灵 / 龙裔 / 神明 / 修真 / 不死 …）· 穿越者与未来来客（`SNAP_FUTURE_ORIGIN_RE`）· **已标记「长生者」**。

## 3. 两条硬纪律（单测专门锁定）

1. **长生词表 ≠ 死亡词表**：`snapshotImmortalFlag()` 独立实现。若图省事复用 `snapshotFlag()`（死亡语义词表），`"长生"` 会命中「是」→ 「长生者」与「已去世」语义完全反转（这是不可承受的错判）。`snapshotFlagForField()` 按字段显式分派两套词表。
2. **开关双向、已去世仍单向**：「长生者」必须能取消（误判纠正的唯一出口）；「已去世」保持 v1.164/v1.205 的「只标记、不取消」（撤回请到编辑器取消勾选）—— 两条语义**故意不同**，单测 A3 逐条锁定。

## 4. 默认提示词一字不变（V1 黄金样本纪律）

新增内容全部由 `opts.immortalGuide` 控制（只有 `runCharacterRepair` 的真实路径开启）：

- 守则块 `【长生者判定（保守）】`：仅在 `immortalGuide` 时插入；
- 输出契约里的「⚠️ 超长年龄 → 研判长生者 / 已去世」一句：同开关；
- ⚠️ 点名行：**未开启**守则时只说「年龄异常 …请研判该年龄是否成立」（**不提「长生者」三字**），开启时给完整 ① ② ③；
- 「待修复角色」表头：无超长年龄目标时**逐字保持 V1 原文**（`birthAnoms` 与 `ageExtremes` 分开计数）。

## 6. 未验证项与后续

- **真机待核对**：刷新后角色页应显示 `🧬 长生者` 徽标、编辑器出现「长生者」勾选框；「🔧 修复角色」通知应出现「长生者 N 名跳过」与（有纠正时）「纠正误判长生 N 名 · 标记已去世 M 名」。页面当前仍是 v3.18.0（`sys.info` 读数）；
- **阈值 200 岁**为本轮拍定值：若真机出现「该判没判」（如 190 岁的凡人意图被研判）或「不该判却判了」（如自设纪元里的长寿族），可在 `core/model/snapshot.js#SNAP_AGE_EXTREME_YEARS` 调整；若需要**用户可调**，再补一个配置控件（会改变设定控件计数，另行登记）；
- **AI 误标风险**：守则已写明「年龄超长不是依据」，但模型仍可能误标长生 —— 因此开关**双向可编辑**、误标不自动改数据、且可被下一轮研判纠正；
- **`birthNote` 不进归一化白名单**（身份键集与 V1 一致）：因此「穿越者」豁免只能靠 `background.origin/history`、`tags`、`title`、`species`、`family` 等**会落盘**的字段命中，单测按此口径写（`birthNote` 那条路不可靠，已在测试注释中说明）。
