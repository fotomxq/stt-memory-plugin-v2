## 3. `业-6`：衰退基准改剧情时间（**本版唯一运行时行为变更**）

**根因**（`docs/D18` §2 K10 / K11）：平行事件与传言的 `base` 用现实墙钟 `updatedAt`（只有 `speed` 用了剧情时间），与 `01` §2.2 / `02` §3.3 的「按剧情时间」表述**互相矛盾**；
`calcTimeDecay` 还有两份实现（`core/ingest.js` 与 `core/recall.js` 的私有副本），且**对负数毫秒的判定不同** —— 同一算法两处漂移。

| # | 落点 | 改动 |
| --- | --- | --- |
| ① | 新增 `core/decay.js` | 衰退的**唯一实现**（叶子模块，不 import 任何 core 模块 → 避免 `ingest ↔ recall` 循环）；常量 `DECAY_MS_*` 一并迁入 |
| ② | `core/ingest.js` | 函数体删掉，改 import + **既有导出块再导出** → `core/ingest.js#calcTimeDecay` 的文档引用形态与 `core/forget.js` / `core/rumor-evolve.js` 的 import **全部不变** |
| ③ | `core/recall.js#parallelDecayScore` | 基准 = 剧情时钟当前日期；条目时刻 = `p.date`；类目跨度 = 各条 `date`；**无剧情时钟 → 0** |
| ④ | `core/rumor-evolve.js#rumorDecayBreakdown` | 同③（条目时刻 = 该说法自身的 `r.date`）；`speed` 与阈值 / 比例 / 开关**一律不动**（`D18` §4.1 P4） |
| ⑤ | `core/decay.js#calcTimeDecay` | 删除「`nowAt` 缺失回落现实墙钟」的兜底 → 非有限数值**直接 0**（无时钟不许偷偷用墙钟） |

**为什么条目时刻取「条目自身的剧情日期」而不是「`date` ∪ 载体 `at` 的最早者」**：`docs/D18` §4.1 P1 的原文是「条目时刻取**条目自身的剧情日期**」，
与记忆 `m.date` / 平行 `p.date` 同口径；载体 `at` 属**强度侧**的久远度输入（`rumorAgeSpeed`），本版不动强度。
（实测对照：若改用「最早载体日期」，`G.inputs.evolve` 里的 `rum_c1` 会因载体报刊日期早 152 天而直接达阈值 → `runRumorEvolve` 的衰退移除数由 0 变 2；按自身日期则与既有 V2 自基线一致，见下。）

**判据（`docs/D18` §4.3 ③ 要求「显式判据」，不新建 V2 自基线）** —— 新增 `tests/unit/decay-story-time.test.js`（**5 项**）：

| # | 判据 | 断言 |
| --- | --- | --- |
| ① | 同剧情日期 + **不同现实时刻** → 衰老分**不变** | 墙钟 2001 → 2100（推进 40 年），平行与传言的衰老分**逐位相同** |
| ② | 同现实时刻 + **不同剧情日期** → 衰老分**变化** | 墙钟固定；条目剧情日期由「1 天前」挪到「10 年前」→ 两域衰老分**都升高** |
| ③ | 剧情时钟为空 → 衰老分**恒为 0**（四域统一） | 平行 / 传言 / 记忆均 0；状态 `runStateDecay` 走 `no-story-clock` 短路。对照：同一构造**有**时钟时四域都 > 0 |
| ④ | 单一实现 | `core/ingest.js#calcTimeDecay` **===** `core/decay.js#calcTimeDecay`；源码反向探针：`core/recall.js` / `core/ingest.js` 均无 `function calcTimeDecay(`，`core/decay.js` 不含 `Date.now(` |
| ⑤ | 只吃参数（不改强度） | 同参同值；**负数毫秒（公元前 ~ 1969）照常参与**；条目时刻非有限数值 → 0 |

**既有测试的改动（逐条写明理由）**：| 文件 | 改动 | 理由 |
| --- | --- | --- |
| `tests/unit/rumor-decay-age.test.js` A5 | **改判**：由「无时钟与有时钟差 ≤ 0.01」改为「无时钟 = 0，有时钟 = 剧情时间基准值 > 0」 | 基准换了来源，旧断言测的是「墙钟 base 在有无时钟时几乎相同」，已成过时口径 |
| `tests/unit/parallels-layout.test.js` B3 | 「已达衰退阈值」用例**补剧情时钟**（`boot(..., '1919-12-01')`） | 旧用例靠 400 天前的 `updatedAt` 制造老旧；新口径下**无剧情时钟不衰退**，必须给时钟 |
| `tests/unit/rumor-evolve-golden.test.js` | **零改动** | V1 oracle 的衰退打分（Z23–Z27）与 **V2 自基线**（Z17/Z18/Z20/Z21）**全部零变化通过** —— 未动任何 fixture |

**偏离 V1 的登记三件套（`开发守则.md` §2.4 类别②）**：① 设计稿标注 `docs/D18` §3.6 / §4.3 ①；② **勘误表升 v1.3**（追加两行：`P10e` 的「`parallels[].updatedAt` 用于衰退窗口」与 `P10ah` 的「传言 `base` 按 `updatedAt`」**不再成立**）；
