## 1. 现象与根因

**用户看到的**：点完「🔀 AI 融合货币」，方案也应用了，但货币列表**还是好几种「金」**、好几种「银」——"记录是分散的"。

**根因（两次演进都只解决"别丢"）**：

| 版本 | 遇「同组内单位不一致」怎么做 | 结果 |
| --- | --- | --- |
| v3.46.2 | **整组拒**（`unit-conflict`） | 连**同单位**的别名也一起被忽略 |
| v3.46.5 | **按单位拆成同单位子组**（≥2 合并 / 单条只报告） | 同单位的合了，但**同一货币的不同单位各留一条** |
| **v3.47.1** | **一个 AI 组 = 一条** | 记录合成一条（金额进备注、不换算） |

**为什么单位混乱是常态**（真实存档只读核对，李瑶）：`黄金/两` · `碎金子/两` · `碎金/两` · `赤金条子/贯` · `赤金条/贯` · `赤条金/条` · `诺米斯玛金币/枚` 同属「金」，
单位却有 **两 / 贯 / 条 / 枚** 四种 —— 按单位拆开后每种单位各剩 1–2 条 → 用户看到"没合并"。

## 2. 新口径

| 面 | 规则 |
| --- | --- |
| 产出条数 | 一个 AI 组**恒为 1 条** |
| 主单位 | 组内**成员最多的单位**（并列 → AI 的 `canonical.unit`；都不匹配 → 第一个成员的单位） |
| 额度 | 只对**主单位成员**求和（`currencyMergeSumAmount=false` 时取其中**最新**那条）；**分量纲一律不相加** |
| 其它单位成员 | **不参与算术** → `otherAmounts` → 落库写进该条**备注**（预览逐条列出） |
| 透明计数 | `reasons['unit-mixed']` · `plan.counts.unitMerged` |

**一句话**：**记录合成一条，金额一分不丢，汇率一分不造。**

## 3. 只读演练（五条 → 一条）

```text
输入：黄金/两 120 · 碎金子/两 30 · 金子/两 10 · 赤金条/贯 23200 · 赤条金/条 5
校验：组数 = 1（reasons: unit-mixed ×1）
plan：keep=碎金子（两里最新）· amount=160（=120+30+10，**不含**贯/条）· unitMerged=2 · removedIds=4
落库：列表 5 → 1 条：黄金 / 两 / 160 ｜ 备注「并入：赤金条(贯) 23200、赤条金(条) 5」｜ 被并入 4 条留 id 墓碑
```

## 4. 影响面与边界

- `core/currency-merge.js`（校验 / plan / 计数）· `core/currency-repair.js`（备注追加，≤160 字）· `core/currency-merge-prompt.js`（**单位不同不再是"不合"的理由**，但金/银/铜/票据四类仍不得混）· `ui/currency-merge.js`（预览列出其它单位）；
- **机械档「🧹 修正货币」不受影响**：它没有语义判断能力，仍是「同规范名 + 同单位才合并」；"同义识别"始终只属于 AI 档；
- **仍不做**：跨单位**换算**（无汇率依据）；跨角色合并；逐组勾选应用。
