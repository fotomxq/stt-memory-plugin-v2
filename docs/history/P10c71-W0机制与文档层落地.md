## 2. 门禁四件（`技-12` / `技-13` / `技-15` / `技-19`）

### 2.1 `技-12` 引用与目录树的校验不再有盲区

| 判据 | 旧实现的问题 | 现在 |
| --- | --- | --- |
| **C5** 引用存在性 | 只校验**带扩展名**的反引号 token → `history/P10c46` 这类「批次档前缀」**从未被拦住**（`docs/README.md` §2 自述「最近一次界面变更」的指向就这样悄悄过期） | 反引号里的批次档前缀（`P10c46` / `history/P10c46` / `docs/history/P10c46`）必须**唯一匹配**到 `docs/history/` 下存在的文件 |
| **C6** 目录树集合 | 用 `block.indexOf('history/')` 做**裸子串截断** → 树里**任一描述文字**含该子串，比较范围就被静默截短（本轮实测触发：某树条目描述含该路径 → 三行被吞掉、误报「漏列」） | **只在行首**认树分支符号（`├──` / `└──`），取紧随的**条目名**；以「条目名本身是 `history/`」为终止点 —— 描述文字里出现什么都不影响解析 |

**唯一匹配的口径**：文件名**恰为** `<前缀>.md` 或以 **`<前缀>-`** 开头。
这样 `P10c6` 只认 `P10c6-…`（**不会**把 `P10c60`–`P10c68` 一起吞进来）、`P10c` 只认 `P10c-时钟取值追踪与日志口径.md` —— 实测 **141 处**引用全部唯一匹配，**0 处**不唯一。

**顺带拦住 3 处「举例型」引用**（`D14` 的 `P10c99`/`P10c100` 编号举例、`D3` 的 `P9x` 区间端点举例）：按仓库既有的 `<!-- 失效路径豁免 -->` 机制**在该行加标记**（标记后仍保留"举例"说明文字），不删任何内容。

**过期指向修正**：`docs/README.md` §2「要改界面 / 加设定项」由 `history/P10c46`（v3.25.x 本机缓冲目录选择）改指 **`history/P10c68`**（v3.40.0 数据管理页「无效关联行」统计 + 一键清理 —— 实测**最近一次**界面变更）。

**可探针化**：判据抽成 **`scripts/docs-facts-lib.js`** 的纯函数（`BATCH_REF_RE` / `batchHits` / `parseTopTreeNames`），因此反向探针**不必往 `docs/` 写临时文件**（那会反过来牵动 C6 自己的目录树集合判据）。

### 2.3 `技-15` 配置声明一致性（新脚本）

`scripts/check-config-decl.js` —— 实测 `core/config.js#defaultCfg`（**314** 个叶子）与 `ui/settings-pages.js#SETTINGS_CONTROLS`（**159** 个控件 / 去重 **158**）的一致性，三查：

| 判据 | 定义（两者的分工） | 实测 |
| --- | --- | --- |
| **有控件无键** | 控件路径在 `defaultCfg` 里**连命名空间都不存在**（写错命名空间） | **0** |
| **缺默认值** | 控件路径的**命名空间存在**，但该叶子没有默认值 | **0** |
| **有键无控件** | `defaultCfg` 叶子没有任何控件（内部开关 / 派生值天然如此） | **156** → **基线化** |

第三条按本仓库既有的**「基线只减不增」**处置（`scripts/config-decl-baseline.json`）：基线固化常驻噪声，只报
**新增未覆盖键**（加了配置却没给控件）与**基线该收窄**（某键已有控件却仍留豁免）。`--write-baseline` 在**基线为空时**允许一次 **bootstrap**（否则 150+ 条存量内部键永远建不起基线），之后**只减不增**（新增未覆盖键**不写进**基线）。

**实现说明**：`ui/settings-pages.js` 的导入链很深，本脚本用**就地极简 DOM 桩**（刻意**不引** `tests/harness/` —— 门禁脚本不该依赖测试目录），从而直接加载**同一份**声明源，而不是静态正则近似。
