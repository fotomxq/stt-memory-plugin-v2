# P10c152 · 货币三页同步核对（总览 / 收支记录 / 长期收支）（v3.51.11）

> 文档版本：v1.0 ｜ 日期：2026-10-26 ｜ 状态：生效（v3.51.11）
> 用户要求（原话）：「核对货币的三个分页内容是否正常同步，如存在问题需修复。」
> 关联：`core/model/ledger.js#applyLedgerEntry` / `#mergeHistoryIntoLedger` · `core/cross-sync.js` · `adapters/sync.js` · `ui/money-tabs.js`

## 1. 核对口径（三页各自读什么）

| 分页 | 数据源 | 说明 |
| --- | --- | --- |
| 货币总览 | `state.currencies`（额度 + `history` 摘要） | 原页原样渲染 |
| 收支记录 | `state.ledger`（权威账本） | 合计/笔数按全量、列表渲染最近 200 笔 |
| 长期收支 | `state.deals`（含 `outlook` 三段 + `trigger`） | 列表 + 详情 |

同源检查：三页都在**同一次渲染**里读同一个 `state`，页内切换不需要"刷新"；真正的同步风险在**写入端**与**跨端合并端**。

## 2. 核对出的问题（两处真缺陷）

### 2.1 编辑流水**不生效**（静默被当成重复提交）

`ui/console.js` 保存 `kind=ledger` → `applyLedgerEntry(raw)`，而 `raw.id` 是既有条目的 id。
`normalizeLedgerEntry` 保留传入 id → 与内容无关地命中 `dup` 判定 → **直接返回 `duplicate`**：
余额没动、账本没变、摘要没变、**也没有任何提示**（用户看到的就是「编辑了但没反应」）。

**修复**（`applyLedgerEntry`）：区分三种情形 ——
* 同 id 且内容相同 → `duplicate`（保持原语义，防重复扣款）；
* 同 id 但内容变了 → **原位替换**：`cur.amount - 旧delta + 新delta`、账本条目字段更新（**id 保留**，跨端引用不失效）、
  摘要**撤旧换新**（不会两条并存）、`updatedAt` 刷新；
* 无 id / 新内容 → 追加（原逻辑，幂等 id）。

### 2.2 跨端合并后三页**不同源**

跨端设备若是旧版本（只有 `currencies[].history` 摘要、没有 `ledger` 账本）：
合并后账本只有「较新那一端」的流水，旧端摘要里的几笔**不在账本里** → **总览有、收支记录却没有**。

**修复**（新增纯函数 `mergeHistoryIntoLedger(ledger, currencies, opts)`，幂等）：
* `core/cross-sync.js#mergeDataObjects`：货币逐条并集之后，把 `history` 增量补进 `out.ledger`；
* `adapters/sync.js#adoptRemoteVersion`（整份采用远端）后同样补齐；
* 迁移路径（`core/migrate.js` 的 `history → ledger` 回填）保持不变（同一口径、同 id 生成规则）。

## 3. 测试

新增 `tests/unit/money-three-pages-sync.test.js`（**8 项**）：
* A1 编辑生效（余额按差额、账本 1 条、id 保留）；A2 摘要撤旧换新 + 同内容再提交仍 `duplicate`；
* A3 面板「✏ 编辑」→ 保存后三页同源（额度 60 / 账本 1 条 −40 / 收支页渲染 −40）；
* A4 删除仍是「反向冲正 + 墓碑」；
* B1 纯函数回填幂等；B2 跨端合并后账本补齐（本端有账本 + 对端只有摘要 → 两笔都在、净额 −20）；
* B3 合并后长期收支不丢（两端各一条 → 都在）；B4 三页渲染同源。

全量单测 **260 文件 / 3864 断言**；冒烟 224 项；`npm run gate` 全绿。

## 4. 边界

1. **余额与账本净额可能不一致**（AI 直抽过额度 / 历史数据）→ 仍按 `D53` 口径「对账只报不改」，体检里显示 `ledger-amount-mismatch`；
2. 编辑**不改变幂等 id**（流水身份不变，跨端/跨页引用安全）；金额变动只做「差额冲正」，不再重复扣款；
3. 三页均为**同源只读渲染**，不做"缓存副本"——本轮不改渲染结构，只修写入端与合并端；
4. 跨端合并**只补账本、不重算额度**（额度按原有逐条并集口径，避免把用户手改的额度覆盖）。
