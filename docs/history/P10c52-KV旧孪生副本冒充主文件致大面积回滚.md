## 1. 现象与取证（只读，未改数据）

| 项 | 实测（调试桥 + 文件系统） |
| --- | --- |
| 用户报告 | 存档数据**超大面积回滚**（维度条目成片变少 / 内容退回早期） |
| 载入日志 | `载入：应用更新的分片（主文件滞后）`，其中 **`mainAt = 1790725980433` = 2026-09-29T23:53:00Z** |
| 同一个时间戳出现在哪 | `…/extension-store/ftt2-files/kv/main/ftt2-state-char1xbib3t.json.json` → `payload.updatedAt` 完全一致；该文件 **62,262 字节 / v3.0.18 / 9 条原子 / `lastKnownFloor 17`** |
| 权威副本 | 同键的 `blobs/main/ftt2-state-char1xbib3t.json` = 1.1MB / 当天最新（插件一直在正常写它） |
| 规模变化 | atoms 115 → 69、rumors 22 → 7、links 255 → 193、台账标记 104 → 0 |

## 2. 根因

宿主原生存储有**两个通道**：载荷 < `TT_KV_MAX_BYTES`（96KB）走 **KV JSON**，≥ 阈值走**大文件（blobs）**。

1. 2026-09-29 时状态还小 → 写进 KV；
2. 状态随后长到 1MB → 改写进 blobs，**但 KV 里的旧副本从未删除**（`ttPutBytes` 只写不清）；
3. 新会话 `ttGetBytes` 不知道写入通道（`writeChannel` 是会话内记忆）→ 按 `[tryKv, tryBlob]` **先试 KV** → **命中 09-29 的旧副本**并当成「服务端主文件」返回；
4. 载入于是以这份陈旧状态为基底（`mainAt` 09-29），只靠「分片更新则套用」补一部分 —— 而**分片本身也是双份**（`kv/main/ftt2-shard-char1xbib3t-atoms.json.json` 停在 10-02，`blobs/main/…-atoms.json` 才是当天），套用到的可能是旧分片；
5. 载入结果被保存流水线写回 → **回滚固化**；下次刷新再叠加一次 → 逐次劣化（这正是用户看到的「超大面积回滚」）。

`docs/history/P10c11` 记的「读到旧副本 → 已分析楼层成片变回未摘要」是**同一族缺陷的轻症版**（当时只清理了未命中抑制），本次是它在「双通道 + 大对象」下的重症表现。

## 3. 修复

| # | 落点 | 口径 |
| --- | --- | --- |
| ① | `ttGetBytes`（新会话 / 通道未知时） | **两个通道都读**，按信封 `payload.updatedAt` **取较新的一份**；两侧都解不出时间戳（gzip / 非信封）时取**字节更大**的一份（大文件通道才是权威大对象）。通道已知时保持原快路径 |
| ② | 同上 | 选中后**删除落选的旧副本**（幂等；失败不影响本次读取），并记一条 `对账` 调试日志：`picked/dropped` 的通道、时间戳、字节数 —— 下次真机取证一眼可见 |
| ③ | `ttPutBytes` | 大载荷写入 blobs 成功后**清掉 KV 同名孪生**；通道从 blobs 退回 KV 时清掉旧的大副本 → **结构上不再产生同名两份** |
| ④ | 诊断出口 | 通道详情新增「双通道取新：N 次（其中删除旧副本 M 份）」；`ttChannelInfo` 增 `twinPicks` / `twinDrops`（调试桥 `ftt.fileTransport` 可见） |

**纯函数**：`pickNewerBytes(a, b)`（判据独立可测：信封时间戳优先、否则字节数）。

## 4. 存量数据（如实）

* 被回滚覆盖的那份服务端主文件**已被写回覆盖**，无法从 blobs / KV 追回；
* **旧的本机目录副本仍在**：`ftt2-files/blobs/local/ftt2-files_ftt2-local-char_<角色>.json`（**2026-10-06 16:29 / v3.26.1 / 115 条原子 / 75 条记忆 / 104 条台账标记 / 信封哈希校验通过**）—— 可用「设定 → 数据管理 → 导入（文件）」导回（导入前先导出当前存档留底）；
* 本轮修复保证**不再继续回滚**：旧副本一旦被读到即被删除，写入侧也不再产生新的孪生副本。

## 5. 测试与门禁

* `tests/unit/tt-store.test.js` 新增 **E1–E5**（5 项）：`pickNewerBytes` 纯函数（时间戳优先 / 不可比取更大）/ **新会话读到较新的一份且旧孪生被删** / **反向（blobs 旧、KV 新）** / **大载荷写入后 KV 孪生被清** / 通道详情如实写出「双通道取新 + 删旧副本」次数；
* 全量：**160 文件 / 2486 断言** + 冒烟 **220 项**；静态门禁（含 `docs-facts` 的 C8/C9）全绿。

## 6. 纪律（写进本档，供后续复用）

* **同键双通道**是宿主存储的固有形态，任何「先试某个通道就返回」的实现都必须能处理「两份并存」；
* 通道切换（KV ↔ 大文件）**必须清理另一侧的副本**；
* 「读到旧副本」类缺陷一律**先修读取择优**，再谈其它（读取路径是所有写入的源头）。
