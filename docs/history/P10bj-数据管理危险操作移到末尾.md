## 1. 调整前的顺序问题

```text
📤 导出备份
📥 导入存档（合并）
✂️ 删除聊天楼层（减小聊天体积）      ← 危险（不可逆，但会自动备份）
⚠️ 删除数据（不可恢复）              ← 危险（不可恢复）
🧬 快照链（自动备份）                ← 安全
🗂 本地缓冲                          ← 安全（只动本机缓存）
```

两个会写**不可逆改动**的分块被夹在安全分块之间：往下翻，用户先看到危险块、再看到「快照 / 缓冲」，
既不利于「先看清安全操作再决定是否动危险动作」，也让危险块**不在末尾、不醒目**。

## 2. 调整后

```text
📤 导出备份
📥 导入存档（合并）
🧬 快照链（自动备份）
🗂 本地缓冲
──────────────────────────────────────────────
⚠️ 危险操作（不可恢复）              ← 新增开场横幅（复用既有 `.ftt-item--warn` 公共件，**无新增 CSS**）
  ✂️ 删除聊天楼层（减小聊天体积）     ← 删前自动明文备份（3 槽轮转），可用导出的 JSON 还原
  🗑 删除数据（不可恢复）            ← 页面最后一个动作按钮：🗑 清空当前角色记忆
```

| 口径 | 说明 |
| --- | --- |
| 安全在前、不可逆在后 | 导出 / 导入 / 快照链 / 本地缓冲 全在危险区之前 |
| 危险区内按**可回滚程度**排序 | 删楼（自动备份 + 可还原）在前；「清空当前角色记忆」（不可恢复）**在整页最后** |
| 危险区开场横幅 | 一句话讲清「两块都会写入不可逆的改动；删楼会自动备份、可用导出的 JSON 还原；删数据无法恢复 —— 建议先导出备份」 |
| 复用公共件 | 横幅用既有 `.ftt-item ftt-item--warn`（`docs/D9` §4 归属表内），并带 `data-ftt-danger-zone` 便于测试与后续扩展 |
| 危险区内不夹安全动作 | 导出 / 导入 / 粘贴框 / 临时快照等**不得**出现在危险区中（测试显式断言） |

## 3. 为什么保留「🗂 本地缓冲」在安全区

该分块只有**本机缓存**（版本清单缓存 / 调试日志 / 交互追踪简报）的统计与清理，全部标注「不影响记忆数据」，
且权威数据是服务端记忆文件 —— 清掉只会重新生成，属于**低风险**操作，故留在安全区。
（`docs/D9` U4 的危险动作清单里确有「清空本地缓冲」，其**二次确认**已由 v2.94.0 的 U4 闸门覆盖；
本版只调整**顺序**，不动其归属分块。）

## 4. 与 V1 的一致性

V1 的数据管理块（`FTT记忆组件-v1.205.js:25918`）顺序为：
`⬇ 导出 JSON` → `⬆ 导入 JSON（合并）` → `🗑 清空已处理楼层` → `🗑 清空当前角色记忆` ——
**清空类动作同样排在导出/导入之后**。本版在 V2 的分块结构下延续同一口径，并把「不可恢复」的那一个放到最末。
