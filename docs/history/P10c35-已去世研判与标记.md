## 1. 为什么需要「机械研判」

v1.205 起，`身份.已去世 = true` 已经有完整联动：**修复名单整批跳过**（`buildCharacterRepairQueue`）、
**年龄锁定**（出生日期与年龄不再改写）、**状态记录清除**（`state-repair#removeStatesOfDeceased`）。
但**谁来打这个标记**只有两条路径：① 用户手动在编辑器勾选；② AI 修复时「正文明确写了死亡」才回填该字段。
于是「明显已经死了、但 AI 没回填 / 用户没注意」的角色会**每轮都被重新提取、重新修复**（用户说的「反复调取处理」）。

本版补上**机械（零 AI）研判与标记**：读该角色**档案自身字段**与**相关原子数据**，按严格口径判定「本人已明显去世」即标记。

## 2. 判定口径（保守优先：默认不标记）

```text
证据 = 档案自身字段（背景资料.经历 / 外貌 / 关系列表 / 身份.*…）
      + characterEvidencePack() 收的相关原子数据（情节 / 记忆 / 状态 / 物品 / 概念 / 计划 / 悬念 / 平行 / 关联行）

① 死亡措辞命中，且必须满足「本人」邻接：
     名字出现在死亡词**之前 16 字内**，且这段中间没有亲属 / 同伴主语（父/母/兄/弟/姐/妹/妻/夫/子/女/师父/同伴/属下/家人 …）
     → 才算「本人明确死亡」
② 反向证据：否定 / 幸存 / 假死（未死 · 没死 · 不会死 · 死里逃生 · 九死一生 · 假死 · 诈死 · 尚未/并未/未曾 …）
     → 不标记
③ 长寿命语境（长生 · 不死 · 永生 · 精灵 · 妖族 · 修士 · 修真 · 渡劫 · 神明 · 龙族 · 鬼修 · 转世 · 轮回 …）
     → 必须出现**终局**措辞（形神俱灭 · 神形俱灭 · 魂飞魄散 · 灰飞烟灭 · 催骨扬灰 · 彻底陨落 …）才标记；
       否则只报「**待确认**」，**不标记**（用户口径：实在无法确认的不做标记）
④ 只有他人死亡（「角色丁目睹其父去世」）/ 生死不明 / 无证据 → 不标记
⑤ 已标记 → 短路（`already-marked`），不再重复研判（避免反复调取）
```

标记**只增不减**：一旦标记为已去世，后续正文里出现「复活 / 假死」**不会**取消（取消只能在编辑器取消勾选）——
这正是「永久留档 + 跳过处理」的前提。

## 5. 兼容与风险

- **兼容**：判定只在**有明确死亡证据**时写标记；无证据 / 证据不明确一律不动（含所有 V1 黄金样本场景 —— 其「已故者」本就已标记 → 短路）。
  AI 提示词默认**逐字不变**（守则仅在 `deathGuide:true` 时追加，生产路径开启）。
- **风险方向**：词面判据必然有边界 —— 因此所有不确定情形都落到「不标记」（只多一条「待确认」提示），
  标记又是**只增不减**的长期字段 → 宁可漏标（由用户手动勾选或 AI 回填兜底），也不误标。
- **回退**：取消标记只需在角色编辑器取消「已去世」勾选（年龄自动恢复被动更新）；本版**不新增任何持久化字段**。
