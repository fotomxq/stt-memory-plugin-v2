## 1. 为什么需要一个「全量对齐」按钮

v3.0.21 起数据走**多通道**写入，每个通道都有自己的短路与门控：

| 通道 | 日常口径（省流） | 对齐时需要 |
| --- | --- | --- |
| 状态 → 本机缓冲 / IndexedDB / 服务端文件 | 内容签名无变化 → **整条短路**（v3.0.18） | `force:true` 强制写 |
| 状态 → 分片 | 只上传**内容哈希变过**的片 | 全量重传（`shardsForce`） |
| 快照文件 / 清单文件 | 按开关 + 链非空 | 有则写、无则如实跳过 |
| 世界书镜像 / 跨端镜像 | 按各自的开关与节流 | 有则跑、关则报 `disabled` |

日常「有什么变了写什么」是对的，但用户需要一个**「我说了算，现在全部对齐一次」**的动作：
不看签名、不看门控，把内存里的这份数据逐层落到每一层存储上，并**逐层回报**。
这就是本版新增的总览按钮（既不是「再存一次」的同义词，也不是「导出备份」的替代品）。

## 2. 实现分层

**编排（`index.js#runSaveAll`）** —— 逐层 `try/catch`，任一层失败只进 `failed`，不影响其它层：

| 层 | 调用 | 备注 |
| --- | --- | --- |
| ① 状态 | `flushStateNow('手动保存（对齐所有存储）', {force:true, shardsForce:true})` | 一条流水线内完成：本机缓冲 → IndexedDB → 分片（全量）→ 主文件（提交点）→ 配置同步计划 |
| ② 快照 | `snapshotFilePushNow()` | 快照链为空 → `skipped:'no-snapshots'` |
| ③ 清单 | `metaFilePushNow(storageEnvelope(st), env.hash)` | 对账文件；开关关闭则跳过 |
| ④ 世界书 | `worldbookSyncNow()` | 开关关闭 → `disabled` |
| ⑤ 跨端镜像 | `runStorageSync(true)` | 拉取对端 + 原子合并 + 推回 |
| ⑥ 配置 | `saveSettings()` | ST 扩展设置 |

- 返回值：`{ ok, at, layers:{state,snapshot,meta,worldbook,mirror,settings}, failed:[…], skipped:[…] }`；
  每层记录 `{at, ok, via, bytes, error / skipped}`（`skipped` 与 `failed` 互斥，`skipped` **不**把 `ok` 拉成 `false`）。
- 副作用收口：`debugLogPush('存储', …)`（含各层结论）+ `notifyHooks.toast`（`silent` 可关）。
- **埋的坑**：`kernelState` 是 `import { state as kernelState }` 的**状态对象别名**，不是函数 ——
  首版写成 `kernelState()` 直接 `TypeError`，单测 A1 当场拦下（该断言覆盖 ②③ 两层）。

**界面（`ui/panel.js`）** —— 总览 ⑤ 工具行：

```text
[⚡ 立即 AI 摘要] [🛠 自动修复] [📤 提取记忆] [🧭 推演世界] [🌶 弱化 NSFW] [📤 立即注入] [💾 保存（对齐所有存储）]
```

- 动作 `saveAll`（`data-ftt-action="saveAll"`, `id="ftt-saveall-btn"`）：**同帧**进入忙态 →
  按钮转圈（`ftt-loading`）+ `disabled` + 文案「💾 对齐中…」+ 重绘；提示行写明正在对齐哪几层。
- 完成后按**逐层结果**拼提示行，例如：
  `已对齐所有存储：本机缓冲✓/服务端✓ 7KB · 快照✓ · 清单✓ · 世界书（disabled） · 跨端镜像✓ · 配置✓`；
  有失败层则换成 `部分存储对齐失败（<层名>）：…` 并发 `warning` 通知。
- 忙态期间再点 → 提示「正在对齐所有存储，请稍候…」并返回 `reason:'busy'`（**不重复发起**）；
  无钩子环境 → `保存入口未就绪` + `reason:'no-hook'`。
- 返回值并入面板动作结果（`Object.assign(result, r, {action:'saveAll'})`），供冒烟/命令断言。
- 同源入口：`panelRuntimeHooks().saveAll`（面板）· `popupHooks().saveAll` + `FTT.saveAll()`（命令 / 调试台）。
  `tests/unit/panel-hooks.test.js` 的静态交叉校验因此要求 `saveAll` 必须在册（已加入面板所需键集）。

## 3. 「对齐」的语义边界

1. **不创造数据**：只写内存里**当前这份**数据；不合并、不改写、不动 `updatedAt` 之外的任何字段。
2. **不绕过安全闸**：`force` 只绕「无变化短路」，**不绕**缩水守卫的显式语义 ——
   该守卫本身就对用户显式操作放行（清空 / 导入 / 手动同步走 `force`），本按钮属同一类。
3. **不改常规定时保存**：`writeStateShards` 的 `force` **只**由本按钮的 `shardsForce` 传入；
   普通保存 / 退出前落盘仍是增量（v3.0.21 冒烟 `BA1`、单测 `exit-flush` E4 的口径不变）。
4. **失败只影响该层**：某层不可用（域未配置 / 开关关闭）如实记 `skipped` 或 `failed`，其余层照常完成。
