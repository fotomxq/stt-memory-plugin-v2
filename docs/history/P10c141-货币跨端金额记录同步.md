## 1. 缺陷：为什么「货币总是不同步金额与记录」

v3.45.6 起货币已按「归属 + 币种」**逐条并集**（`docs/history/P10c86`）——所以本轮**不是**"货币没被合并"，
而是三处同源问题让合并**发生在错误的时点、读到错误的副本、用错误的时钟仲裁**：

| # | 缺陷 | 代码取证 | 用户可见后果 |
| --- | --- | --- | --- |
| ① | **保存先写后拉** | `adapters/store.js#saveStateNowInner` 先整份写回主文件；拉取合并由 `adapters/sync.js#scheduleStorageSync` **3 秒后**才跑 | 等它去拉时远端已被本端刚写的旧内存覆盖 → 另一端刚记的额度/流水在服务端消失；两端从此各说各话 |
| ② | **会话读缓存无 TTL** | `adapters/sync.js#filesReadContentCached` 命中即返回（无过期）；自动路径不绕开缓存（只有手动「刷新状态 / 立即同步」与首屏载入会 `fileCacheDropAll`） | 即使自动拉取跑了，读到的也是本会话早先那一份 → 「自动同步」形同虚设 |
| ③ | **货币没有条目级时间戳** | `core/model/money.js#normalizeCurrency` 与三条写入路径都不写 `updatedAt`；仲裁先比条目时间、并列才用信封时间（`core/cross-sync.js#currencyRemoteWins`） | 仲裁退化为「**谁后保存谁赢**」→ 只是保存了别的内容的一端，会把另一端较新的额度盖回去 |
| ④ | **流水并集固定本端在前** | `core/cross-sync.js#mergeCurrencyEntry` 调 `mergeMoneyHistory(本端, 对端)`，再 `slice(-12)` | 两端各 12 笔时被裁掉的是本端较新的那几笔 → 「记录少了」 |
| ⑤ | **两个开关是死键** | `storage.crossPullOnVisible` / `crossPullOnActivity` 只有默认值与设定页控件，**没有读取点** | 用户以为"回到页面会自动对账"，实际不会 |

## 2. 修复（四处）

1. **写前拉取**（`adapters/sync.js#pullRemoteBeforeWrite`，`adapters/store.js#saveStateNowInner` 调用）：
   保存**组装信封之前**先「读远端 → `mergeRemoteCurrencies` **把货币逐条并集**」（不动其它维度）；失败静默、15 秒节流、长任务 / 载入未完成跳过。
   清空（`resetState`）/ V1 导入 / JSON 导入 / 退出前落盘**显式 `pullRemote:false`**（`pullRemoteBeforeWrite` 不再把对端旧数据并回来）。
2. **回到前台自动对账**（`host/events.js#bindAutoPullVisible` + `adapters/sync.js#crossAutoPull('visible')`）：
   `visibilitychange → visible`（开关 `storage.crossPullOnVisible`）→ 缓存绕过 + 清单预判 + **只并集货币**；**有变化才落盘**
   并经注入的 `onMerged` 回调重绘已打开的面板；15 秒内不重复拉取。`crossPullOnActivity` = 写前拉取开关（默认开）。
3. **账本时间戳**：`normalizeCurrency` 只**保留**入参 `updatedAt`（缺省不写该键）；四条写入路径打标 ——
   AI 落库（`core/ingest.js#mergeDelta`）· 面板编辑 / 快速记账（`core/entries.js#upsertEntry`）·
   机械修正 / AI 融合应用（`core/currency-repair.js#runCurrencyRepair`）。
4. **流水上限取较新账本**：`mergeCurrencyEntry` 改为 `mergeMoneyHistory(落败方, 胜出方)` —— 12 笔上限保留**胜出方**的最近记录。

## 4. 边界（如实登记）

1. **不改「非原子容器整侧取新」**（`summaries` / `npcs` / `protagonist` / `vars` / `varTemplates` / `state`；`docs/D20` `数-4` 方案 A 保持不变）；
2. **不改** `dataAggHash` / `atomEntryCount` / `diffAtomData` 三个 V1 锁定口径（货币仍不在 `ATOM_DIM_KEYS`）；
3. **不改 `DATA_VERSION`**：`updatedAt` 是**可选**字段，老存档与 V1 黄金样本逐字可读；
4. 自动拉取**只并集货币**（不整体替换、不写备份、不写快照、不动其它维度），与「立即同步 / 刷新状态」的分工不变；
   其余维度仍走「保存后镜像 / 载入并集 / 手动同步」—— 除货币外的条目合并时钟只有 AI 写入路径在维护，整份提前会让**手动编辑**被对端旧副本盖回去（独立议题）；
5. **未取证**：本机没有双端真机环境，端到端「两台设备」的时序由单测模拟（文件系统桩 + 会话重启）覆盖，真机读数待用户复核。
