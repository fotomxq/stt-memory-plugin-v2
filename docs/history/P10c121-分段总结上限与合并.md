## 1. 缺陷（`docs/D20` §8 `数-9`）

`state.plotSegments`（分段总结归档）与 `state.summaries`（遗留摘要容器）**没有上限** —— 归档只增不减，
落盘体积与派生视图（网表 / 列表 / 跨端签名）成本随之膨胀，且用户**没有任何读数**知道自己有多少段、会不会无限长。

## 2. 修法

### ① 新模块 `core/plot-segment-merge.js`（纯内核）

| 导出 | 作用 |
| --- | --- |
| `PLOT_SEGMENT_MAX = 240` · `LEGACY_SUMMARY_MAX = 120` · `PLOT_SEGMENT_LINE_MAX = 40` | 上限常量（**唯一事实源**：数据页 / 子页 / 收口三处共用） |
| `mergeTwoPlotSegments(a, b, now)` | 合并**相邻两段**：时间范围连续（`start` ~ `end`）· `atomIds` **并集** · `atomCount` 求和 · 剧情线按「标签：正文」**去重** · `merged/mergedFrom/mergedCount` 可追溯 · `createdAt` 取较小 · `updatedAt` = now |
| `mergePlotSegmentsToCap(list, cap)` | 按**剧情时间升序**，反复合并**最早的相邻两段**直到 ≤ 上限；**未超限原样返回**（引用不变、`changed:false`）、**幂等** |
| `trimLegacySummaries(list, cap)` | 遗留摘要容器**只裁不并**（该容器已被 `plotSegments` 取代、无写入点），保留较新的 N 条并如实回报 `removed` |

**「不删除」的口径**：合并只做并集 —— 所有原 `atomIds` 一个不少，原始段 id 全在 `mergedFrom` 里；
剧情线超量时**截断并记** `truncated` / `droppedLines`（可解释，不是静默丢弃）。

### ② 收口接线（`core/ingest.js#applyStateBounds`）

`applyStateBounds()` 是「写入 / 合并后」的统一收口 —— 在其中调用上面两个函数；有改动时返回
`{cut, plotSegments:{before, after, merged, droppedLines}}`，无改动则**不返回**该键（避免无谓改写）。

### ③ 裁剪可见（设计稿验收第 ③ 条）

| 位置 | 显示 |
| --- | --- |
| **数据管理页**（`ui/settings-pages.js`） | 新增「🗂 分段总结上限」分节：`分段总结 N / 240 段（其中 M 段是合并过的）· 遗留摘要 K / 120 条` + 「超上限按**剧情时间**合并最早的相邻两段（保留归档与全部条目 id，**不删除**）；遗留摘要只裁不并」；已超限时额外红字提示 |
| **分段总结子页**（`ui/plot-segment-forecast.js`） | 底部条数行补「（上限 240；超出时按剧情时间合并，不删除归档）」+「其中 M 段是合并过的」 |
