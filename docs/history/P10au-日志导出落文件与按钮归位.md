## 1. 缺陷一：导出**不落文件**（用户报告「无法正常导出 log 文件」）

| 环节 | 修复前 | 证据 |
| --- | --- | --- |
| 导出动作 | `exportDebugBundle()` 只把文本写**剪贴板** + 面板**文本框**（`lastDebugExport`），**从不创建文件** | `ui/debug.js`（修复前 `exportDebugBundle`） |
| 用户视角 | 点「导出调试包」→ 既没有下载、也没有任何「文件」；文本框在页面下方，还要再手动复制 | —— |
| 对照 | 同仓库的「⬇ 导出记忆 JSON」早已是**真下载**（Blob + `<a download>`，`ui/file-io.js#downloadTextFile`，冒烟 AY1 有断言） | `ui/file-io.js:55-82` |

**修复**：调试页的导出全部改走同一条下载实现：

| 动作 | 产物 | 文件名 | mime |
| --- | --- | --- | --- |
| `dbgExportLog`（**新增**） | 人读日志文本：头信息（版本 / 导出时间 / 作用域 / 条数）+ 每条一行 `[时间] [类别] 内容` | `FTT调试日志_<作用域>_<YYYYMMDD-HHmmss>.log` | `text/plain` |
| `dbgExport`（修复） | 结构化调试包 JSON（meta / env / dump / errors / stats / logs / trace） | `FTT调试包_<作用域>_<YYYYMMDD-HHmmss>.json` | `application/json` |

两者都**保留**剪贴板与文本框兜底：下载成功时 note 报出文件名，宿主不支持下载时如实写「**未能下载文件**（原因）」，
并在按钮行下方给出提示条；文本框折叠在按钮行下方的 `<details>` 里（既是兜底，也不把日志列表推下去）。

## 2. 缺陷二：日志按钮分散（用户要求「全部调整到最上面」）

| | 修复前 | 修复后 |
| --- | --- | --- |
| 清空日志 | 「📋 日志」区块顶部（在日志列表之前） | 同一个顶部按钮行 |
| 导出调试包 | **下方独立分节**「📦 导出调试包」（要滚到底才能点到） | 并入日志区块顶部按钮行 |
| 导出日志 | 不存在 | 顶部按钮行（首枚，`ftt-primary`） |
| 统计说明 | 与「清空日志」挤在同一行 | 仍在按钮行右侧（条数 · 占用 · 上限口径 · 展开提示） |

**新结构**：`调试日志（开关）→ 📋 日志［按钮行 → 说明 → 类别统计 → 日志条目］→ ⚠ 异常捕捉 → 🧭 时间线 → 🕒 时钟追踪`。

- 按钮行：`⬇ 导出日志` · `⬇ 导出调试包` · `🗑 清空日志`（无日志时按既有规则隐去清空）；
- **空态也保留按钮行**（导出入口不再需要先有日志才出现）；
- 删除独立的「📦 导出调试包」分节（其按钮与说明已上移）。

## 4. 未做与边界

| 项 | 说明 |
| --- | --- |
| 不改调试包内容 | 仍为「日志 + 运行态诊断」，**不含记忆正文**；`FTT.debugLogExport()` / `FTT.debugLogExportText()` 同源不变 |
| 不改清空口径 | `dbgClear` 仍是「清内存 + 清本机持久层」；无日志时不渲染，避免空操作 |
| 时间线 / 时钟追踪的按钮 | 各自仍在自己区块顶部（本次只调整「日志」区块）——它们本就是该区块的首行 |
| 文件名时间戳 | 用本地时间 `YYYYMMDD-HHmmss`（不用 ISO，避免文件名里的冒号）；作用域取角色名并做安全字符替换 |
