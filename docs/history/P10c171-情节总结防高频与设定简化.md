# P10c171 · 情节总结防高频触发 + 设定简化（v3.52.18）

> 文档版本：v1.0 ｜ 日期：2026-11-18 ｜ 状态：生效（v3.52.18）
> 用户要求（原话）：「经过排查可能是分段总结出问题了，前几次改版升级导致的异常，频繁总结引发。
>   请优化总结的机制，避免高频次触发。其次简化设定，主要是控制token上限和保留N条（默认30）情节外，超出去的部分进行总结。」
> 关联：`core/atom-compact.js` · `core/config.js` · `ui/settings-pages.js`

## 1. 根因（「频繁总结」）

半自动情节总结（`atomCompact`）的**聚合目标**是「当前条数 × `atomCompactTarget`（默认 30%）」：

* 例如 100 条情节 → 目标 30 条；总结后仍有新的情节不断进入 → 条数一涨，目标随之上涨，
  **每多 1 条就可能再次触发**一轮总结（每次都重新算目标）→ 高频反复总结；
* 触发入口在每次提取收尾的 4s 检查点（`scheduleAtomCompact`），没有冷却与最小批量限制。

## 2. 修复

### ① 聚合目标 = **保留最近 N 条**（默认 30）

* `atomCompactPlan` 生产口径：`target = recentN`（`cfg.atomCompactRecent`，默认 **30**）——
  只有**超出保留窗口的部分**才进入总结池；总结后压回 N 条，**新增 1-2 条不再触发**（池未满最小批量）。
* 兼容：内部/测试显式传 `recentN` 覆盖时仍按 V1「比例目标」口径（黄金样本可比，界面不暴露）。

### ② 自动路径两道闸

| 闸 | 常量 | 行为 |
| --- | --- | --- |
| 冷却 | `ATOM_COMPACT_AUTO_COOLDOWN_MS = 120000` | 自动总结完成后 120s 内的自动触发 → `cooldown` 跳过 |
| 最小批量 | `ATOM_COMPACT_MIN_BATCH = 10` | 超出保留窗口不足 10 条 → `below-batch` 跳过（防「多 1-2 条就总结」） |

两闸只作用于**自动路径**（`scheduleAtomCompact` 的 4s 检查点）；手动「🧷 情节总结」/ force 不受影响。

### ③ 设定简化

「设定 → 提示词 → 半自动情节总结」页：

* **明面只留 3 项**：启用开关 · **token / 字符上限**（`atomCompactChars`）· **保留最近 N 条**（`atomCompactRecent`，默认 30）；
* 其余调参（`atomCompactTarget` / `atomCompactRatio` / `atomCompactBatch`）收进「**高级（一般不用改）**」折叠
  —— 控件表不删（旧存档兼容、配置声明门禁不受影响）。

### ④ 文案/默认值

* `cfg.atomCompactRecent` 默认 **20 → 30**；标签改为「保留最近 N 条情节（默认 30）」；
* `atomCompactChars` 标签改为「token / 字符上限（提交给 AI 的正文预算，默认 30000）」。

## 4. 边界（如实登记）

1. 总结仍是「**保留原文并隐藏**」，不删除数据；
2. 冷却/最小批量只拦**自动**路径 —— 手动总结与你显式操作不受影响；
3. `atomCompactTarget` 等旧键保留（高级折叠内），但生产口径已不再使用比例目标。
