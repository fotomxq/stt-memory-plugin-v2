## 1. 缺陷 / 用户诉求

各大类清单的**多选模式**此前每条行前放一个 `<input type="checkbox">`：要选中必须**精确点那个小方框**，
行内其它位置点了没反应（手机上尤其难命中）。用户要求：**不要勾选按钮，点整行即加入选择**。

## 2. 改法（C11：交互整体落新模块）

新增 **`ui/row-select.js`**（`ui/panel.js` 只留最小接线）：

| 导出 | 作用 |
| --- | --- |
| `ROW_SEL_ATTR` / `ROW_ON_CLASS` / `ROW_MARK_CLASS` | 行标记 `data-ftt-selrow` · 选中态 `ftt-sel-on` · 行首记号类 |
| `rowSelectMarkHtml(on)` | 行首**只读**记号 `☑ / ☐`（`aria-hidden`，**不是 `input`** —— 用户点的永远是整行） |
| `rowSelectAttrs(kind,id,on)` | 行属性串：`data-ftt-selrow` + `data-ftt-id` + `tabindex="0"`（+ 选中态类） |
| `rowSelectClick(e, api)` | 命中行 → 切换选择；**点在按钮/链接/输入上不抢**（`ROW_INTERACTIVE`）；就地改行样式 + 记号 + 调 `sync()` 局部同步工具行按钮 |
| `rowSelectKeydown(e, api)` | 行上 `Enter` / `Space` 等价于点选（键盘可达） |
| `bindRowSelect(el, api)` | **一次性接线**：capture 阶段的 click + keydown 委托（先于点选分发消费，幂等） |

**面板改动（3 处，共 +7 行）**：
1. 导入新模块；
2. 两处清单渲染：`<input type="checkbox" …>` → `rowSelectMarkHtml(...)`，并把 `rowSelectAttrs(kind,id,on)` 拼进行的 `attrs`；
3. 一处接线：`bindRowSelect(el, { getSel: selOf, sync: … })`。

**样式**（`style.css`，+26 行）：`[data-ftt-selrow]` 手型光标 / 悬停底色 / `:focus-visible` 描边；`.ftt-sel-on` 选中态（**左侧 3px 色条 + 底色**）；`.ftt-selmark` 记号的颜色随选中态变化。

## 3. 交互口径（四端一致）

| 操作 | 结果 |
| --- | --- |
| 点行**任意空白处** | 加入 / 移出选择（切换），当场看到左侧色条 + ☑ |
| 点行内 **✏️ / 🗑 / 🔍 / 跳转链接** 等控件 | **照旧执行原动作**，不切换选择 |
| 键盘：焦点在行上（`tabindex="0"`）按 `Enter` / `Space` | 等价于点行 |
| 工具行按钮（批量删除 / 全选 / 清空 / 情节总结…） | 每次点选后**局部同步** `disabled` 与「（N）」计数，不整页重绘 |

**为什么用 capture 相位**：面板另有「动作分发」的**冒泡** click 监听；同相位会先跑到动作分发、把行内空白处点击当成未知动作。
capture 保证「点选」优先，命中后 `stopPropagation()` 把该次点击消费掉。

1. **只改了两处主清单**（维度列表 + 状态记录页）；回收站、关系表、场景树等**其它带勾选的清单未动**（用户说的是「各大类清单」，如需一并统一可下一轮做）；

3. 「全选 / 清空选择」按钮**保留**（仍是动作，不是勾选框）；
4. **真机未人工试用**：需刷新后在任一大类点「☐ 单选模式」切到多选，然后点行体验。
