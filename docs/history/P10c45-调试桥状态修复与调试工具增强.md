## 1. 状态显示 BUG（用户报告的那条）

**现象**：调试页显示「未连接（重试中）」，其实桥已经连上了。

**成因（确定性）**：状态文案只在**渲染那一刻**采样 `bridgeState().connected`，而 WebSocket 是**异步**建立的：

```text
点「▶ 开启调试桥」
  ├─ bridgeStart() → open() → new WebSocket(...)         // 此刻 readyState = 0
  ├─ 返回 → 面板重绘 → 状态行 = 「未连接（重试中）」        // 采样点：确实还没连上（这一帧没错）
  └─ 稍后 onopen 到达 → connected = true
        └─ ✗ 没有任何东西再重画那一行 → 界面永远停在「重试中」
```

**修法（三件套）**：

| 层 | 改动 |
| --- | --- |
| `adapters/debug-bridge.js` | 新增**状态跃迁序号** `seq`（启动/停下/连上/断开/出错/改目标都 +1）与 `connectedAt` / `retryAt` / `attempts`；新增 **`bridgeStatusLine()`**（唯一事实源：不支持 / 已关闭 / 已连接（含起连时刻）/ 未连接（重试中 + 倒计时 + 尝试次数）） |
| `ui/debug.js` | 状态行改挂 `<b data-ftt-bridge-status>` 活节点，文本来自 `bridgeStatusLine()`；新增 **`updateBridgeStatusDom()`**（只改这一个节点、文本未变不写 DOM；找不到节点如实返回 `false`） |
| `ui/panel.js` | 新增 **`syncBridgeTick()`**：面板开着且停在「设定 → 调试」时每 **1s** 调一次上面的就地刷新；离开该页 / 关面板 / 节点消失 → 立刻停表（与 `syncPipelineTick` 同款结构，不泄漏定时器） |

> 关键取舍：**文案与判定只留一处**（`bridgeStatusLine()`），页面渲染与心跳刷新共用 —— 否则「页面文案」「真实状态」两套逻辑迟早再次漂移（本次 BUG 就是这么来的）。

## 2. 调试工具增强（可读范围 + 效率）

**新增 10 个只读方法（36 → 46）**：

| 方法 | 参数 | 解决什么 |
| --- | --- | --- |
| `ftt.debugLog` | `{kind?,grep?,limit?≤200,since?,full?}` | 读**日志条目本身**（此前只有 `debugLogStats` 计数） |
| `ftt.trace` | `{cat?,errorsOnly?,grep?,limit?≤300,detail?}` | 读**时间线条目**（此前只有统计） |
| `ftt.errors` | `{limit?≤50}` | **一站式**：异常日志 + 错误时间线 + 初始化期告警暂存 + 体检计数 |
| `ftt.entries` | `{dim,id?,offset?,limit?≤200,values?}` | 条目清单 / 单条详情，可翻页；默认只回元信息 |
| `ftt.search` | `{q,dims?,fields?,limit?≤100}` | 跨维度搜索，回命中字段与片段 |
| `ftt.config` | `{keys?,includePrompts?}` | 生效配置摘要（默认只回类型/长度） |
| `ftt.floors` | `{start?,end?,values?}` | 楼层窗口诊断（AI 到底看到了什么） |
| `ftt.syncLog` | `{limit?≤60}` | 同步日志最近条目 |
| `sys.batch` | `{calls:[{method,params?}]}` ≤20 | **一次往返**拿多个结果 |
| `sys.ping` | — | 连通性探针 |
| `sys.methods` | `{detail?:true}` | 带**说明与参数**的自省清单 |

**统一口径（安全不放松）**：
- 大文本一律截断（`BRIDGE_TEXT_CAP` = 4000 字/字段）；
- 正文 / 配置值**默认不外送**，需 `values:true`（条目）或 `includePrompts:true`（提示词）显式开启；
- 参数一律夹取上限（`limit` / `clampNum`），避免一条请求拉走整库；
- 异常一律收敛成 `{available:false, reason}`（`safe()` 兜底）；
- **白名单不放宽**：`sys.batch` 走 `bridgeDispatch()`（与外部工具同一条派发路径），未登记 / 改动型方法照样被拒。
