## 1. ① 平行世界的「卦象等」为什么会被清掉

**根因（V1 同源缺陷）**：`core/ingest.js` 的平行事件「更新」分支是**整条替换**：

```js
const prev = state.parallels[i];
n.id = prev.id; n.uses = prev.uses || 0; n.updatedAt = Date.now();
if (Array.isArray(prev.goalOdds) && !n.goalOdds.length) n.goalOdds = prev.goalOdds;   // 只有它被保底
state.parallels[i] = n;      // ← 其余字段全部以「AI 这次给了什么」为准
```

而推演 / 推进的提示词里，**卦象 / 因果线 / 涉及角色 / 发生地点 / 来源 / 预演 / 约束** 都是**可选**字段
（原文：「可同步更新 类型/日期/卦象/因果线/涉及角色/发生地点/标签 与 演化目标可能性」）——
于是 AI 一次常规「更新」只带标题+正文时，**卦象与因果线当场被清空**。实测（修复前）：

```text
新增后 = {"gua":"山水蒙——局中待启…","causalLine":"源起：船只被毁→议论→幕后","characters":["甲"],"location":"码头区"}
更新后 = {"gua":"",            "causalLine":"",                    "characters":[],  "location":""}      ← 全被清掉
```

**修法**：逐字段合并（与 atoms / items / currencies 同口径）

| 字段类 | 本次未提供 | 本次提供 |
| --- | --- | --- |
| 标题 / 正文 / 类型 / 日期 / 时刻 / 卦象 / 因果线 / 发生地点 | **保留旧值** | 覆盖 |
| 涉及角色 | **保留旧值** | 覆盖 |
| 演化目标可能性 | 保留旧值 | 覆盖 |
| 标签 | — | **并集合并**（`mergeTags`） |
| 重要度 | 保留旧值（区分「AI 没给」与「默认 0.5」） | 覆盖 |
| 来源 `sourceRefs` / 预演 `previews` / 约束 `constraintNote` / 计划·悬念引用 / 转正标记 | **一律保留**（AI 从不产出这些键） | — |

**展示面同步修复**（用户说的「等设计」）：

| 项 | 修复前 | 修复后 |
| --- | --- | --- |
| 因果线行 | `⚡ 源起：` + 值；而提示词要求 AI 把值写成「源起：…」→ 页面恒显示 **`⚡ 源起：源起：船只被毁→…`**（V1 同源） | 值自带「源起/因果」前缀时不再重复加；否则补前缀 |
| 卦象徽标 | 完整值直接塞进徽标（字段规格 ≤40 字，但 `normalizeParallel` 允许 80 → 长输出把徽标撑成多行） | **限宽 40 字 + 「…」**，完整值挂在 `title` 上悬浮可见 |

> **登记偏差**：`parallel-golden` R2 原本逐字段比对的期望值来自 V1 黄金样本（含被清空的字段）。
> 本版按新口径修正期望并**显式断言保留行为**，**黄金样本本身不改**（偏差在测试里就地登记）。

## 3. ③ 自定义平行世界（输入一段话 → AI 单独推演）

**入口**：平行页顶部「🧪 自定义推演（新增平行世界）」→ 展开输入区 → 「🚀 交由 AI 推演」。

| 维度 | 「🧭 推演世界」（既有） | 「🧪 自定义推演」（本版） |
| --- | --- | --- |
| 输入 | **最近楼层正文**（受投喂过滤） | **用户写下的一段设想** |
| 开关 / 去重 | 受 `parallelWeaveEnabled` 与输入签名去重影响 | **不受**推演开关与去重影响（每次都按当前设想推演） |
| 上下文 | 最近正文 + 各维度近期速览 | **设想关键词命中的既有数据**（情节/记忆/状态/计划/悬念/传言/角色/场景/物品） |
| 落库 | `mergeDelta({平行事件})` | **同一条路径** → 产物**完全同构** |

**关键词取词（两级）**：

1. `jsExtractKeywords()`（V1 逐字移植）—— 只认**已登记的特征词**（条目标签 / 关键词 / 角色名 / 场景名…）；
2. **新增 `ideaCorpusTerms()` / `customKeywords()`** —— 从设想里切出 **2~6 字片段**，只保留**在既有数据里真实出现过**的
   （最长优先、去重、上限 12 个），再并入 1 的结果。
   *为什么必须补这一级*：用户随口写一段设想时，往往一个新标签都没有 → 只靠 1 会拿到空关联。

**客观 / 非主角视角兼容**（用户明确要求，提示词显式声明）：

- 可以完全是**客观事件**（自然 / 社会 / 势力 / 环境层面的客观因果）；
- 也可以是**与主角无关的第三方视角**（其它角色 / 组织 / 地区的内部动向）；**主角可以完全不出场、不知情**；
- **禁止**为了让剧情好看把事件牵引向主角（除非设想里明确写到主角）；
- 纯设定 / 世界线前提也接受，并在因果线里注明「来自用户设想」；
- 日期缺省用**当前剧情日期**；字段口径与常规推演完全一致（卦象仍按「第 1 步定卦、第 2 步推因果」）。

**交互**：沿用 v2.96.0 的长耗时动作口径 —— 点下去**立刻**写提示 + 重绘 + 弹「开始推演」通知；
在途禁用防连点（`parallelCustomState().busy`）；完成弹「新增 N 条」通知；空内容 / 无 JSON / 无推演点都如实提示。

## 6. 边界（有意保留）

| 项 | 口径 |
| --- | --- |
| 手动编辑条目仍以表单为准 | 编辑器里清空某字段 = 有意清空（`upsertEntry` 的 `{...prev, ...n}` 合并保留表单未覆盖的字段） |
