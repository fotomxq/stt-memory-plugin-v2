## 1. 核对原因（为什么「超预算跳过」会造成数据异常）

| 环 | 事实（代码证据） |
| --- | --- |
| 触发条件 | 明文信封 `text.length > LOCAL_BUFFER_MAX_CHARS`（默认 **1,800,000** 字符）→ `adapters/store.js` 保存 ④ 走 `over-budget` 分支：**本次跳过本机缓冲写入**（只记台账 / 调试日志）。用户上报的 `chars:1994370` 即此情形 |
| 为什么会越界 | 浏览器 `localStorage` 单键配额按 UTF-16 计约 **2.6M 字符**（5MB）；1.8M 是给调试日志等留余量的**保守预算**。状态随条目增长（`docs/D13` §3.1 实测极端形状 2.64M 字符） |
| 真实后果 | 本机层是**兜底副本**：超预算后它**停在旧版本**（旧内容不清空，但也不再更新）。于是「换设备 / 服务端文件读取失败 / 清缓存后」本机看到的是**旧副本** → 观感即「数据回退」；「退出前落盘」的本机兜底同样失效 |
| 没有丢什么 | 服务端文件 + 分片 + 备份 + 快照 + IndexedDB **照写**（日志文案本身也这么说）——所以这不是「丢数据」，而是**本机层不再是最近一次的数据** |

## 2. 解决思路：把「跳过」换成「压缩留存」

| 层 | 落点 | 口径 |
| --- | --- | --- |
| 写入 | `adapters/store.js#saveStateNowInner` ④ | 明文的 `text.length >= LOCAL_BUFFER_GZ_MIN_CHARS`（**200K**）**或**超预算 → `gzipToBase64` → 写**压缩记录** `{"ftt2gz":1,"at","chars","b64"}`；`useGz` 仅在「超预算」或「记录确实更短」时成立；明文 < 200K 仍写原文（**小状态零额外开销、与旧版逐字节兼容**） |
| 读取（同步） | `#loadFromLocalStorage` | 明文路径**一字未改**（零额外微任务）；检测到压缩记录时**如实让路**（记账 `gz-record`，不误报「信封损坏」） |
| 读取（异步） | `#loadFromLocalStorageGz`（新） | 解析记录 → `base64ToBytes` → `gunzipFromBytes` → **与明文同一套校验**（信封完整 + `storageHash` 一致）；失败一律回落服务端文件 / IndexedDB |
| 载入接线 | `index.js#loadMemoryState` | **只在记录确实是压缩格式时**才多一次 `await`（`localBufferGzPending()` 同步预判）；普通模式（明文）行为与既往逐字节一致 |
| 校验并修复 | `adapters/sync.js#readLocalEnvelope` | 目录模式读目录文件；普通模式遇压缩记录先 `inflateLocalGzRecord` 再解析 —— 否则「校验并修复」看不到本机层这份候选 |
| 装不下 / 不支持压缩 | 同上 ④ | **仍如实跳过**（绝不清空旧内容）+ **停滞标记** `ftt2_LocalStale`（几百字节）+ **一次性可操作提示**（去设「本机缓冲目录」） |
| 面板如实告知 | `ui/sync.js`（设定 → 存储）· `ui/buffer-manage.js`（设定 → 数据管理） | 「压缩留存（原始 X → 存 Y）」/「已超出浏览器配额 → 本机层停更」/「⚠️ 本机层自 ＜时间＞ 起未更新」 |
| 相邻口径修正 | 同上 ④ | 本机层处于**停滞**状态时**不允许「等值跳过」** —— 否则「上次被跳过 + 内容没变」会让本机层永远补不上（`localStaleMarked` 参与判据） |

## 3. 边界与纪律（如实）

* 压缩记录**只是本机缓存**，**不是数据契约** —— 服务端文件 / 分片 / 备份 / 快照 / IndexedDB 的格式一字未动（属 `docs/D15` §3 **类别②：可偏离（成本取舍）**，已在本档与 `docs/02` 登记）；
* 压缩比取决于内容（重复结构高、随机文本低）；极端不可压内容仍走「如实跳过 + 停滞告知」；
* 读路径的**校验口径完全一致**：压缩记录同样要过「信封完整 + 载荷哈希」，坏记录一律丢弃并回落服务端；
* `localStorage` 里可能出现两类记录（明文 / 压缩），**互不兼容格式变化都向后兼容**：旧版只认明文 → 只会把压缩记录当作「无本机缓冲」（不会崩），新版两种都认。
