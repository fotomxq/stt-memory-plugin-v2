## 3. 黄金样本口径（有意偏离 V1 · 已登记）

词条库与转化库是 **V1 逐字移植**的资产，`tests/fixtures/v1-golden-nsfw.json` 记录了 V1 的库规模（63/63）与头尾词条。
本版**追加**词条 → 库规模必然偏离 V1，因此测试按「加法式归一」口径登记（写在 `tests/unit/nsfw-golden.test.js` 顶部）：

- **H1**：`NSFW_KEYWORDS_V1.length === 63`、头 6 条与第 57–63 条与 V1 **逐字一致**（V1 的 63 条原样在前，顺序不变）；
  库规模 = `63 + NSFW_KEYWORDS_V310.length`；每条词条都有转化词；其余字段（字段表 12 维、单批 12）不变。
- **H5 / H6 / H14**（词条库与转化库的增删改恢复序列、状态摘要）：把「计数」减去追加量后与 V1 黄金样本**逐字比较**
  —— 行为口径完全未变，只有库规模变大。
- **H2 / H3 / H4 / H7–H13 不变**：V1 样本场景的替换/命中/扫描/打包/提示词/AI 应用结果**逐字符一致**
  （新增词条与样本正文无交集，已逐词核验）。
- 新增词条的**正向**行为另由 `tests/unit/nsfw-level.test.js` **G 组**锁死（前缀完整、逐条有转化词、真的能命中并转化、不影响 V1 词条口径）。

## 5. 兼容与风险

- **兼容**：自定义库不受影响 —— `cfg.nsfwKeywords` / `cfg.nsfwRules` 非空时**仍以自定义列表为准**（内置库仅在自定义为空时生效）；
  已自定义过的用户想吃到新词条，可在设定页点「♻ 恢复内置默认」（或按需补几条自己的）。
- **影响面**：识别范围扩大 → **已处理文本不会被回溯替换**（替换只在「立即固定规则替换 / 弱化」动作与下次分析时发生）；
  但 v3.8.0 的**载入补档**会用新词库重新判级 → 更多条目可能被标为「强 / 弱」（只升不降，不会降级）。
- **误伤风险**：中文新词条多为多字词（`腿间` / `春光外泄` / `一丝不挂`），普通叙事命中概率低；
  `抚弄` / `调戏` / `拘束` / `脱衣` 属于「性意味但非露骨」的边界词，当前按**强级**处理（会触发替换）——
  若用户觉得过严，可在设定页删除对应词条（自定义库优先）。
