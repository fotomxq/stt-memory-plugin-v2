## 2. 落点与「为什么这样落」

### 2.1 两个**新模块**（都是 `docs/05` §5 **C11** + `scripts/check-file-size.js` 体量棘轮逼出来的，如实登记）

第一版我把实现直接写进单体文件 → **门禁当场报红**：`ui/panel.js` **+139 行**、`core/config.js` **+59 行**（宽限只有 40）→ 按 C11 拆成：

| 新模块 | 内容 | 单体文件留下的 |
| --- | --- | --- |
| `core/tri-link.js` | 打包 / 规则表 / 七条校验 / 钳制 / 幂等签名 / 应用 / 槽位 | —（新功能不在单体文件里） |

> 这正是 v3.45.9 立的 C11 想要的效果：**同一轮里，我自己的实现被自己的门禁挡了两次**，两次都拆对了。

### 2.2 扩维「四处同批」的第四处是**孤儿口径**（不是第四个常量）

`docs/D32` §3.1 要求四处同批：`core/model/rel.js` · `core/entries.js` · `core/recall.js` 三处**重复常量** + 维护侧 `core/rel-maint.js`（它 import 同一常量，自动跟随）。
真正需要显式处置的是**孤儿统计**：`relOrphanStats()` 的 `rows`（坏行）随扩维，而 **`items`（条目一条关联都没有）必须固定 4 维** ——
新增 `REL_ORPHAN_ITEM_DIMS` 把这两件事分开；否则传言（本来就可能"谁都不知道"）会一夜之间全部变成"孤儿条目"。
