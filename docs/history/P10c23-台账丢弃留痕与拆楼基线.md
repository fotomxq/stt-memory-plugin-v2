| 覆盖集合（离线复算） | 现口径 78 楼 → **新口径（忽略越界）25 楼**，8 段：`[0,13] [20,23] [25,25] [29,30] [32,32] [38,38] [40,40] [42,42]` |
| **覆盖者明细** | 第 30/32/38/40/42 楼**各自被本楼产出的 `rumors` 单楼区间条目覆盖**（`30-30` / `32-32` / …） |

**结论**：30/32/38/40/42 **分析过**（有本楼产出的条目），**但台账里没有标记** —— 它们不是「没分析」，
而是「**分析记录丢了**」。而覆盖兜底把「有数据」当成「已分析」，于是这 5 楼永不回到待办。

## 2. 根因 A：丢弃标记即失忆（本版主修）

两条维护路径都会**按内容哈希丢弃**「对不上的标记」：

| 路径 | 丢弃条件 |
| --- | --- |
| `reconcileProcessedFloors`（归位对账，20s 节流） | 当前聊天里找不到该标记的哈希（正文被改写 / 楼层已删） |
| `handleFloorShrink` 第 ① 步（拆楼归位，绕过 mass-mismatch 守卫） | 同上（收缩时整体失配属预期） |

丢弃后**旧哈希不留痕** ⇒ 下游无法区分：

```text
这楼从没分析过          → 应当进未摘要（正确）
这楼分析过、但正文改写了 → 也应当进未摘要（V1 口径：contentChanged 时覆盖不构成跳过理由）
```

而 `scanPendingFloors` 的 `contentChanged` 只在「**标记还在**但哈希不符」时为真；标记一旦被丢弃，
`!!mark === false` ⇒ `contentChanged === false` ⇒ 覆盖兜底生效 ⇒ **永久跳过**。

### 修法

1. `state.processedDropped`（新字段，有界 **600**、按楼层去重、新值覆盖）。
2. **两处丢弃点丢弃前留痕**（`rememberDroppedMarks`）；`migrateProcessedFloorsV170` 的丢弃路径同样接入。
3. `scanPendingFloors`：

   ```text
   contentChanged = !!mark  ||  (丢弃留痕存在 && 留痕旧哈希 ≠ 当前正文哈希)
   ```

   为真时覆盖兜底不得跳过 → 该楼回到待办。**保守规则**：留痕旧哈希与当前相同（楼层消失又回来、
   内容其实没变）→ 仍按覆盖处理，不重分析（避免无谓重跑）。
4. 重新分析过 → `forgetDroppedMarks(start,end)` 清掉该楼留痕（否则它会被永远当成「内容已改写」）。
5. 诊断：`pendingScan` 增 `changedFromDropped`（因该规则入队的楼层数）与 `droppedMarks`（留痕条数）。

## 3. 根因 B：拆楼检测基线错位

`handleFloorShrink` / `processedDriftGuard` 用 `lastKnownFloor` 当「聊天曾有多长」的基线，
但它**只在记录分析结果时更新**（= 「已分析到哪」）。真机：聊天 49 楼、只分析到 22 楼 → 基线 22；
之后若删到 29 楼，判据 `28 < 22-5` 不成立 ⇒ **真实收缩检测不到** ⇒ 来源楼层不归位
（条目停留在已不存在的楼号上）。

### 修法

| 项 | 说明 |
| --- | --- |
| 新字段 `state.lastChatFloor` | **上次观察到的聊天末楼**；`handleFloorShrink` 每次观察都刷新（`noteChatFloor`），**可回落**（last-seen 语义） |
| `shrinkBaseline()` | **max(上次观察到的末楼, 已分析最大楼)** —— 前者反映「上次看到多长」，后者是「聊天至少曾有这么长」的硬证据（分析过第 N 楼 ⇒ 当时至少有 N+1 层） |
| 消费点 | `handleFloorShrink` 的收缩判据、`processedDriftGuard` 的 `floor-shrunk` 短路 |
| 诊断 | `processedStats()`（→ `ftt.ledger`）增 `lastChatFloor` / `shrinkBaseline` / `droppedMarks` |

> **为什么不是「见过的最大末楼」**：那样切到更短的聊天（同角色多聊天）会**每次都误判收缩**并触发归位。
> 为什么不能只用 `lastChatFloor`：两次观察之间「先涨后删」会漏判（冒烟 `BH13` 正是这种局面）。
> 两者取大值同时满足：`BG2`（20 楼、无收缩 → 不触发）与 `BH13`（20→14 → 必须触发）。
