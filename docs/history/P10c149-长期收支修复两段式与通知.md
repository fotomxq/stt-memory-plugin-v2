# P10c149 · 长期收支修复两段式（内置记账优先 → AI 修订）+ 触发通知（v3.51.8）

> 文档版本：v1.0 ｜ 日期：2026-10-25 ｜ 状态：生效（v3.51.8）
> 用户要求（原话）：「长期收支的修复按钮，增加逻辑。优先全量判定预测日期抵达或超出的，通过内置模块计算记账、轮动到下一轮；
>   然后再走现在的抽取+AI修复行为。修复长期收支按钮触发后没通知的错误。」
> 关联：`core/deal-repair.js` · `core/deal-triggers.js` · `ui/panel.js` · `docs/D53` §3.4/§3.9

## 1. 两段式（需求 1）

`runDealRepair()` 现在分**两段**（同一按钮一次触发）：

| 段 | 做什么 | 谁做 |
| --- | --- | --- |
| ① **内置记账** | **全量**判定所有条目：`forecast.nextDate ≤ 当前剧情日期` → 生成流水 + 轮动到下一轮（含跨多周期叠加、截止日期停止、幂等、上限 `cfg.dealCatchUpMax`） | `core/deal-triggers.js`（确定性、**无 AI**） |
| ② **AI 修订** | 再挑**仍需修订的最多 3 条** → 打包（当前记录 + 正文）→ 一次 AI → 机械校验 → 落库 | `core/deal-repair.js`（窄契约） |

要点：
* 内置段用 `prevDate:''` 调用（**不要求"跳动"**，只要到期就算），因此「修复」按钮不会漏掉"只推进一天就到期"的条目；
* 内置段**先落盘**，AI 段失败也**不回滚**（两段各自幂等：流水按 `dealId+节点日期`、AI 段按字段覆盖）；
* 摘要如实分开报：`内置记账 N 笔（轮动到下一轮）；AI 本批 K 条（共 M 条）→ 已更正 X 条`；
* `skipTriggers` / `skipAi` 供测试与"只想跑一段"的场景使用。

## 2. 修复按钮「触发后没通知」（需求 2）

**两个原因一起修**：

1. **没有即时反馈**：AI 段要等几秒，旧实现点击后界面完全无变化 → 看起来像"按钮坏了"。
   现在点击**立即**落一条「长期收支修复：处理中…（先用内置模块结算到期记账，再把最多 3 条交 AI 修订）」并 `renderPanel()`，
   结束后再落最终摘要（含内置段与 AI 段两段结果）；
2. **失败路径没有 note**：`aiBusy` / 空池 / 无 AI 三条早退路径现在**都带 note**（且 `ok:true` 表示"内置段可能已生效"），
   面板兜底文案为「已完成（无变更）」，不会出现"点了没反应也没提示"。

## 3. 测试

`tests/unit/deal-repair.test.js` 13 → **16 项**：
* F1 内置段先跑（到期条目先记账并轮动，AI 段只处理剩余）→ 摘要含两段；
* F2 `skipAi` 只跑内置段；
* F3 面板点按钮 → 结束后 note 必含结果（不再静默）；
另把 E2/E3 改为 `skipTriggers`（专注 AI 段），并修正 busy/空池的期望为 `ok:true` + 明确 note。

全量单测 **259 文件 / 3848 断言**；冒烟 224 项；`npm run gate` 全绿。

## 4. 边界

1. 内置段**不改** AI 段挑选结果（AI 仍只修 ≤3 条；未修的条目下次再点按钮继续）；
2. 内置段失败静默（不影响 AI 段），但摘要会少掉「内置记账」字样（便于判断）；
3. 两段都幂等，**重复点击**不会重复记账（`dealId+节点日期` 去重）。
