# P10ak · 设定 → 分析记忆：UI 布局分组（v2.73.0）

> 文档版本：v1.0 ｜ 日期：2026-09-26 ｜ 状态：生效（v2.73.0）
> 触发（用户要求）：「新版本，分析记忆的 UI 布局需优化，合理分组，**尤其是最底部的一组设定**。」

---

## 1. 修复前

`analyzePageHtml()` 只产出两节：

| 顺序 | 内容 |
| --- | --- |
| ① 维度分组（总开关） | 独立分组开关 + 两句说明 |
| ② 各维度独立子开关与分组（独立分组时生效） | 14 行维度 → API 分组选择器 |
| —— | **末尾平铺 5 个控件**：分段读取楼层数 + 情节分段总结 4 项（无节标题、无说明） |

用户报告的「最底部的一组设定」就是这 5 个控件：它们与「维度分组」是两件完全不同的事（一个管**分批读取/分段总结**，
一个管**多维度请求分组**），却在同一页里连成一片，没有任何视觉分节。

## 2. 现在的结构（对齐 V1 v1.206 25505~25535）

| 顺序 | 分节标题（与 V1 逐字） | 内容 |
| --- | --- | --- |
| ① | 维度分组（总开关） | `dimensionSeparate` 代理键 + 状态文案 + 两句说明 |
| ② | 各维度独立子开关与分组（独立分组时生效） | 14 行维度 → API 分组选择器（未选 = 跟随主配置） |
| ③ | **分析范围** | `summaryChunkSize` + 短提示「分批处理（默认 10）：按该值把正文分批提取；自动补全覆盖全部未摘要楼层，手动摘要只处理最近楼层（默认 2）。」 |
| ④ | **情节分段总结（情节页「🧩 分段总结」）** | `plotSegmentBatchAtoms` / `plotSegmentProtectManual` / `plotSegmentIncremental` / `plotSegmentTextLimit` + 短提示「把情节按时间从早到晚切成批次，逐批拆成多段归档（不注入、不参与召回与遗忘）。」+ 折叠说明 |

**折叠说明**（点击「ⓘ 说明」展开）保留 V1 的四段口径：打包条数与「### 时间范围」段头、单次最多 12 批、
「保护已存在的时间范围」跳过不覆盖（AI 运行永不删除段落）、增量跳过已覆盖批次（关闭则每次全量重跑）、
字数上限为入库硬截断、该内容只归档供人工查阅与编辑、**不注入给 AI**。

## 3. 完整性

- 渲染的 `data-ftt-cfg` = `dimensionSeparate`（代理键）+ 5 个控件 = **6 个，各出现一次**；
- 「分析范围」节内**只有** `summaryChunkSize`；「情节分段总结」节内**只有** 4 个 `plotSegment*`（用切片断言钉死）；
- 控件表 `SETTINGS_CONTROLS.analyze` 的键、V1 原标签与顺序**未动**（渲染层未改文案）；
- 未登记的键回落末节「其它」（当前分析页没有该节，属兜底分支）。
