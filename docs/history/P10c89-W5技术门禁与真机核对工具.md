## 2. `技-10`：零依赖静态检查（与设计稿的**有意差异**及理由）

设计稿 §8 的写法是「新增 `jsconfig.json` 并启用 `checkJs`，先覆盖 `core/` 与 `adapters/`」。
但 `checkJs` 需要 TypeScript（`node_modules`）→ 与 `docs/D21` §6 **Q5 用户裁决**「**不允许**引入需要 `node_modules` 的工具；只用零依赖或 Node 原生能力」**直接冲突**。
设计稿自己也在 §3.2 注明了这个冲突（「`checkJs` 不产生运行时依赖，优先」），但本仓连 **devDependencies 都为空**（`技-11` 的单测 C9 就是断言这件事）→ 实际只能走零依赖。

于是交付**零依赖等价物**（`scripts/static-lib.js` + `scripts/check-static.js`，进 `gate`）：

| 层 | 判据 | 为什么它能替代 `checkJs` 的一部分 |
| --- | --- | --- |
| **正确性（错误 · 必须 0 · 不进基线）** | **导入名 ↔ 导出名一致性**：`import { a, b as c }` / 默认导入 → 逐个核对目标模块的导出集合（`export function/class/const/let/var`、多行 `export { … }`、`export default`）；目标有 `export *` 或说明符非相对（`node:` / 宿主）→ **跳过**（不可静态判定，不制造假报） | 这正是 `checkJs` 最常抓到的一类错：**导入了不存在的具名导出 → 运行时静默 `undefined`**（JS 不报错，直到你调用它） |
|  | `eval` / `new Function` / `debugger` / `with` | 动态执行与调试残留：无法静态核对 / 会中断宿主页面 |
|  | `node --check` 语法（`--syntax`） | 解析层兜底（默认关，见下） |
| **债务（告警 · 基线只减不增 · 逐规则也不得涨）** | `console.*` / `var`（**仅交付面**）· 空 `catch` 未写明忽略原因 | 交付面的 `console`/`var` 存量 **0** → 等于「不许新增」；空 `catch` 存量 218（多为 `try { dbgLog(...) } catch (e) { }` 的日志容错）→ 记为债务、只减不增 |

**文件面分治**：交付面（`core/ host/ adapters/ ui/` + `index.js` / `devtools.js`）查全部规则；工具面（`scripts/` / `tests/`）**只查正确性** ——
测试 runner 与门禁脚本**本来就该**往 stdout 打印，对它们套「不许 `console`」纯属噪声（首版就是这个错：告警 569 → 分治后 218）。

### 2.1 首版误报 11 条 → 定位到一个**解析缺陷**（已修 + 写成回归判据）

首版把 11 个**合法导入**报成「导入了不存在的具名导出」（`relAnchorGaps` / `repairNormText` / `purgeLinksForGoneEntries` / `rumorDecayScore` / `lastShellDropInfo` / `relLinkIndex`…）。
逐个查证：这些名字**确实被导出**，但导出写法是**多行 `export { … }` 列表**，而列表**中间夹了行注释**：

```js
export { demoteRelLinkOrphans, relRepairMaint, …,
    // v3 注释里有一个 `}` 字符 →
    relAnchorGaps, backfillRelLinkAnchors, REL_ANCHOR_PRESENT_HOWS };
```

朴素正则 `/\bexport\s*\{([^}]*)\}/g` 里的 `[^}]*` **在注释里的那个 `}` 上停住** → 列表被**截断** → 后半段的导出名一个都不认识 → 反过来把合法导入判为错。
修法：`symbolsOf` 先在 **`codeOnly()`**（本仓既有的「剔注释 / 字符串 / 正则」剔除器）上判 —— 顺带把「注释里的 `}`」与「注释里的 `import`」两类假报一起消掉。
**同时把它写成回归判据**：`tests/unit/tech-gates.test.js#A1`（多行导出列表含 `}` 注释）与 `#A2`/`#A3`。

### 2.2 第二个坑：导入扫描**不能**喂 `codeOnly()`

`codeOnly()` 把字符串整体替换成 `""` → `from './util.js'` 变成 `from ""` → 正则的 `['"]([^'"]+)['"]` **一个都匹配不上**（探针文件"一行都没识别出来"）。
修法：`importsOf` 改用「轻量去注释」（块注释 + 整行 `//` 注释），**保留字符串原文** —— 导入行的字符串恰好就是说明符。写进注释防复发。

### 2.3 语法检查为什么默认关

每个 `node --check` 都是一次子进程（Windows 上实测 ~450ms）→ 426 个文件 ≈ **25s**（并发 8 路也没救回来，进程创建本身是瓶颈）。
而**语法错误本来就跑不掉**：`gate` 里的单测 + 冒烟会 `import` 全部交付模块，`scripts/` 与 `tests/` 的文件则被门禁本身直接执行 —— 真正可能漏的只有「既没被 import、也没被执行」的孤立文件。
故：门禁默认 `check-static`（**0.5s**），`npm run static:full`（`--syntax`）在发版前跑一次兜底。**如实写在脚本头部与 `docs/05` §3**，不假装门禁覆盖了它没跑的东西。

## 3. `技-14`：体量棘轮（为什么是「基线 + 宽限」而不是绝对上限）

设计稿验收原文：「新增功能的落点不在三个单体文件内；**`wc -l` 不再增长（或增长仅为必要接线）**」——
后半句就是本方案的依据：这三个文件**仍必须承担接线**（新模块要挂进来就一定得改 `index.js` / `ui/panel.js`），
绝对上限会把「正常接线」与「把功能堆进单体文件」一起挡掉 → 用**宽限 = 接线额度**（`margin: 40` 行/文件），**赚到的行数要还**（`--write` 收紧）。

| 在册文件 | 首建基线（行） | 来源 |
| --- | --- | --- |
| `ui/panel.js` | 3983 | `docs/D21` §3.3 主目标 |
| `index.js` | 2728 | 同上 |
| `adapters/store.js` | 1784 | 同上 |
| `ui/debug.js` | 1827 | `docs/D17` U134 实测清单（与三个主目标同口径纳入） |
| `core/config.js` | 1275 | 同上 |

- 两道护栏（与 `perf-baseline.js` / `line-ref-budget.json` 同款）：`--write` 在**有文件比基线更大**时**拒绝**（首次建基线除外）；确需上调须 `--allow-growth` + `CHANGELOG` 写明理由（属「撤销该约定」级别）。
- 策略侧：`docs/05` §5 编码约定新增 **C11**（新功能一律落新模块；五个单体文件只允许必要接线）。
- **本轮自身即受该约束检验**：`index.js` 因加载自检 +20 行、`ui/debug.js` 因新桥方法 +~20 行 → 都在 40 行宽限内通过（这正是宽限的用途）。

## 4. `技-26`：把「真机核对」从「要开 DevTools」变成「加载即产出读数」

| 落点 | 做了什么 | 为什么这样设计 |
| --- | --- | --- |

## 8. 一次自伤与修复（如实记录，供后来者避坑）

本轮在「用 PowerShell 批量改版本号」时踩了两个坑，**当场发现并已修复**（未进入任何提交）：

1. `(Get-Content x -Raw) | Set-Content -Encoding UTF8` 在这个 harness 的 `pwsh` 下**写入了 BOM**，且 `Get-Content` 的默认解码**不是 UTF-8** → `manifest.json` / `package.json` / `core/constants.js` 三个文件出现 **BOM + 中文乱码**（`FTT记忆组件` → `FTT璁板繂缁勪欢`），直接把 `check-docs-facts.js` 的 `JSON.parse` 打崩；
2. 修法：`git checkout --` 三个文件（它们的唯一改动就是版本号）→ 改用 `edit` 工具逐处改版本号；随后全仓扫了一遍 BOM 与典型乱码标记（760 个文件），**只剩 1 个历史文件带 BOM**（`docs/history/P10c59-本机层结构化分片.md`，HEAD 里本来就有，与本轮无关）。

**结论（写给后来者）**：本仓的**任何文本改写都必须用 `edit` / `write` 工具**（或用 Node 读写），**不要**用 shell 的文本管道 —— 编码与 BOM 会静默走样，而这类损伤只有门禁崩掉时才会暴露。
