# P10c59 · 本机层**结构化分片**：逐维文件 / 逐维键 + 清单（v3.31.0）

> 文档版本：v1.0 ｜ 日期：2026-10-07 ｜ 状态：生效（v3.31.0）
> 用户要求（原话）：「本地文件可以拆碎了保存，这样方便分片处理，呈现结构化、体系化，而不是聚合到单一文件。其他本地存储文件同理。」
> 关联：`adapters/local-shards.js`（新，纯函数）· `adapters/local-disk.js`（`localDiskWriteShards` / `localDiskReadShards`）·
>   `adapters/store.js` 保存 ④ · `index.js#loadFromLocalDisk` · `adapters/shards.js`（服务端分片 —— 本次把本机层做成同构）

## 1. 之前的问题

服务端**早已按维度分片**（每维一个文件 + 清单），而**本机层**一直把整份状态聚合成**一条记录**：
浏览器端是单键（`ftt2_state_<scope>`，撞 1.8M 字符预算、超了只能压缩留存），目录/磁盘端是单个大文件。
后果：一条坏记录 = 整份本机副本不可用；也无法只核对/替换某一维。

## 2. 现在的结构（落点）

```text
<本地存储路径>/
└── char_1xbib3t/
    ├── manifest.json      # {v, at, scope, parts:{atoms:{hash,bytes,n}, …}}
    ├── meta.json          # 非维度字段（state/vars/stats/deleted/台账/归属/快照指纹…）
    ├── atoms.json  memories.json  items.json  plans.json  suspense.json
    ├── scenes.json  concepts.json  parallels.json  rumors.json
    └── currencies.json  currentStates.json  links.json  snapshots.json  plotSegments.json
```

浏览器本机层（localStorage / IndexedDB）同构：`ftt2_ls_<scope>__<维度>` 每维一条键（另有 `__manifest`）。

## 3. 口径（`adapters/local-shards.js`，纯函数）

| 函数 | 作用 |
| --- | --- |
| `splitParts(env)` | 按维度切成 `{meta, atoms, …}`；meta 收拢所有非维度字段 |
| `joinParts(parts)` | 合并回同一份 data（逐字等价；缺的维度按空数组处理） |
| `buildManifest(parts)` | 逐片记 `hash / bytes / n`（版本 `LOCAL_SHARD_V`） |
| `verifyParts(parts, manifest)` | **坏一维只报那一维**（`bad[]`），不整体作废 |
| `shardFileName` / `shardKeyName` / `manifestFileName` / `manifestKeyName` | 目录与浏览器两套命名 |

## 4. 接线与纪律

* 保存 ④：单文件副本成功后再写**结构化分片副本**（`localDiskWriteShards`）—— **best-effort**，失败只记诊断、**不阻塞**保存；结果记入 `localBuffer.shards` 与调试日志；
* 载入：单文件命中即用；**未命中则回退读结构化分片**（清单 + 逐维文件，校验后合并）—— 两条路**互为兜底**；
* 浏览器选中的文件夹（File System Access）会自动建 `<scope>` 子目录再逐文件写；宿主机制的磁盘路径同样逐文件写；
* 与辅助数据（`aux-*.json`）一起，本机层现在是**一组结构化小文件**，而不是一个大文件。
