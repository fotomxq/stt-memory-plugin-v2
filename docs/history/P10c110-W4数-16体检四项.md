## 2. 第二个实质修复：补上 hygiene 的「三处出口」缺口

`docs/D20` 对 `数-16` 的要求含「复用 finding 形态与**三处出口**（面板 / `FTT` 导出 / 调试桥）」。
核对发现：**`hygiene` 此前只在 `dataHealthReport()` 的返回值里** —— 面板只渲染异常面 `dataHealthText`，桥方法 `ftt.dataHealth` 只带 `counts`，
**三处出口都看不到卫生面**（因此四项即便实现也无处可读）。本轮补齐：

| 出口 | 改造后 |
| --- | --- |
| 面板（设定 → 调试 → 数据体检） | 新增 `data-ftt-data-hygiene` 一行 + 折叠「卫生面明细（前 30 条）」 |
| `FTT` 导出 / 桥方法 `ftt.dataHealth` | 新增 `hygiene`（计数 + findings）· `tombstone`（比值读数）· `hygieneText`（一行文案） |
| 调试桥新增只读方法 | **`ftt.dataHealthHygiene`**（一行卫生面文本；无卫生项时为空串）→ 桥方法数 **60 → 61** |

新方法**同步登记**三处（门禁按设计生效，先红后绿）：`core/debug-catalog.js#BRIDGE_FTT`（只读清单）·
`tests/unit/debug-bridge.test.js#B6`（白名单快照断言）· `docs/README` §3「调试桥只读方法数 **61**」。

## 3. 测试（新增 11 项构造数据用例）

| 组 | 内容 |
| --- | --- |
| H（7） | 四项逐条：归属缺失（缺 / 异两段）· 失锚关联（**只有「锚点全空」计入**；有锚点的、非记忆类的都不计）· **两码独立**（悬空 ≠ 失锚）· 空壳 · 墓碑比（比值 + 两端计数）· 阈值点名（≥5× 给出墓碑回收出口）· 四项都是 info 且 `level` 保持 `ok` |
| I（4） | 三处出口同源：`ftt.dataHealth` 带 `hygiene`/`tombstone`/`hygieneText` · 新方法 `ftt.dataHealthHygiene` · 一行摘要含四项计数 · 面板渲染出 `data-ftt-data-hygiene` |

**断言口径的两处纠偏（留档）**：

* 初版 H3 误以为「带 `refId` 的关联行就不算失锚」→ 实际 **`refId`（关联行指向谁）与 `atomRef/conceptRef/planRef`（指回依据条目）是两组字段**；
  「悬空」与「失锚」是两个**独立**判据，一行可以同时命中（已改为用「有锚点 + 引用不存在 → 只报悬空」与「无锚点 + 引用有效 → 只报失锚」两条对照证明两码独立）。
* 初版 H7 的构造数据里夹了一条**无关**的悬空关联（`refId` 指向不存在的情节）→ `level` 被抬成 `warn`，判据失真；
  补上那条情节后，四项成了该样本里**唯一**的发现，H7 才真正在验「卫生面不污染 level」。
