## 2. 核对出的 BUG（本版修复）

| # | 缺陷 | 影响 | 修复 |
| --- | --- | --- | --- |
| ① | **旧版台账迁移会伪造成员**：`migrateState` 里旧 `processedFloors` 的纯数字转换只看「首个元素不是对象」，于是混入的 `null` 被 `Number(null) = 0` 变成 `{f:0,h:''}` —— **凭空多出一条「第 0 楼已处理」**；`{f:'x'}` 一类垃圾被丢一半 | 台账失真：未摘要清单可能少列第 0 楼；导出体积与统计被污染 | 该分支整体交给 `healthSelfHeal`：**逐条严格校验**（只认非负整数 / 十进制数字串）、非法项**丢弃**、裸数字转无哈希在册标记、按 `(楼层, 哈希)` 去重 |
| ② | **调试试探也用 `Number()` 宽松读取**：`ftt.ledger` 把 `null` 读成第 0 楼、把 `{f:'x'}` 读成 `NaN` 却不报 | 「核对」工具自己**掩盖**了它本该发现的异常 | `core/data-health.js#ledgerFloorNum` 与 `ui/debug.js#ftt.ledger` 统一改严格解析；非法项回 `f:null` + `bad:true`，并给出 `badMarks` 计数 |
| ③ | `ftt.memoryShape` 把**容器类型**（如 `"string"`）直接填进**计数表** | 消费方（调试页 / 端口脚本）拿到的不是条数；异常被伪装成正常输出 | 只回数字（数组 = 条数 / 对象 = 键数 / 缺失 = `null`），类型错误单列 `bad`，异常本体由体检报告 |
| ④ | 体检自身两处写法缺陷（开发期发现并当场修） | 会**漏报**：首次出现的下标为 0 时 `if (seen[id])` 为假 → 重复 id 漏报；`currentStates` 未映射到上限表键 `states` → 状态记录超长漏检 | 改 `seen[id] !== undefined`；加 `LIMIT_KEY_ALIAS`；关联层（引用行）不再误报「缺 id」 |

## 3. 载入期自愈（修数据，不只是报数据）

`core/migrate.js#healthSelfHeal`（随 `migrateState` 在载入期执行，幂等）：

| 异常 | 自愈动作 |
| --- | --- |
| 台账标记非法（`null` / 布尔 / 空串 / 非数字） | **丢弃**（不再伪造第 0 楼） |
| 台账标记重复「`(楼层, 哈希)`」 | 去重 |
| `lastKnownFloor` 非整数 | → `-1`（未知；下游一律按有限数判据） |
| 条目 `nsfw` 非规范（`Strong` / `true` / `4`） | 规范化为 `strong` / `weak`；无法识别 → **删除字段**（缺省即「无」） |
| 条目 `uses` 负数 / 非数字 | → `0` |
| 条目 `importance` 越界 | 夹到 `0..1`（非数字 → `0.5`） |
| 来源区间倒置（`floorStart > floorEnd`） | **互换修好**（两端都是真实楼层，只是写反） |
| `floorNow*` 倒置 / 半对 / 已判「原文已移除」却仍带位置 | **整对删除**（派生数据，下次突变识别重算） |

**只报告、绝不擅改**（语义无法从数据本身确定）：缺 `id` · 重复 `id` · 单字段超长 · 墓碑时间戳非法
（`{atoms:{a2:'ts'}}` —— 该墓碑实际不生效、跨端可能被复活，改与不改都可能误事，故只列出让人决断）。
**绝不删条目**：自愈前后各维度条数、`id` 集合（含缺 `id` / 空 `id`）逐条一致。

## 5. 兼容与风险

- **兼容**：自愈只针对「明确非法」的值；合法数据一律不动（V1 黄金样本逐字不变）。合法值包括：裸数字台账标记（V1 兼容）、
  台账里带哈希的越界楼层号（`{f:99,h:'abc'}` 保留，交由归位对账处理）、`floorNow 0/0`（跨越删除线的精确位置）。
- **风险方向**：倒置楼层区间选择「互换」而不是「丢弃」，是因为两端都是真实楼层；若确属脏数据，体检里仍能看到（自愈后即正常）。
  墓碑时间戳非法**不自动改**：改成「现在」会删掉本不该删的条目，改成 0 则等于没删 —— 交用户按体检结果决定。
- **本地调试端口的安全边界不变**：仍**只读、无鉴权、默认只连本机**；体检方法不登记任何写操作
  （自愈只在载入期发生，端口无法触发写）。
