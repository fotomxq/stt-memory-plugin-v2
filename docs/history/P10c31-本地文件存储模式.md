## 1. 落在哪一层、替代了什么

插件的本机层原本只有三条：**内存**（内核 state）、**本机缓冲**（浏览器本地变量 `localStorage`，键 `ftt2_state_<角色>`）、
**本机内存库**（IndexedDB）。其中 localStorage 这一层受浏览器配额限制，插件自己加了 **1.8M 字符预算**
（`LOCAL_BUFFER_MAX_CHARS`）：**超预算就跳过写入**（如实留痕，但用户看到的是「本机缓冲不再更新」）。

新模式把这一层换成**宿主的本地文件**：

| | 旧（变量层） | 新（本地文件模式） |
| --- | --- | --- |
| 载体 | 浏览器 `localStorage` | 宿主的本地文件（TauriTavern 扩展存储 / 酒馆用户目录文件） |
| 限制 | 浏览器配额（插件自设 1.8M 字符预算，超限静默停更） | 无该配额；文件可见、可备份、随宿主官方同步 |
| 开关 | 恒开 | **`cfg.storage.localFilePath` 非空才开**（留空 = 不开启，零行为变化） |
| 载入 | 同步读一层 | 开启时**多读一层**（异步，仅在开启时多一次 `await`） |

> 附注：`cfg.storage.chatVariable`（TH 全局变量 `fttMemoryState:<角色>`）在 V2 里**没有任何消费者**（幽灵开关，已在本档登记），
> 所以本次「替代变量」替代的是**真正在用的** localStorage 本机缓冲层。

## 2. 路径约定（用户唯一开关）

- **留空 = 不开启**：`localFileEnable()` 为假 → 写/读都直接返回 `off`，不碰任何存储；
- **非空 = 开启**：路径经 `localFilePathSanitize()` 归一 —— **只保留宿主数据目录之内的相对目录**：
  - 剥掉盘符（`D:\FTT\data` → `FTT/data`）与前导斜杠、丢掉 `..` 段（`../x` → `x`）；
  - 非法字符（含空格）转 `_`（`我的 数据` → `我的_数据`）；多层路径在原生通道折成单段命名空间（`a/b` → `a.b`）；
  - 全部剥完为空 → 等价于「不开启」。
- **落点（按宿主）**：
  - **TauriTavern**：扩展存储命名空间 → 真实目录 `data_root/_tauritavern/extension-store/<目录>/`（`table='local'`，每角色一个文件）；
  - **网页版酒馆**：`user/files/<目录>/ftt2-local-<角色>.json`；若宿主不接受子目录 → 退化为同级平铺名 `<目录>-ftt2-local-<角色>.json`（写失败时自动重试平铺名）。
- **写不到数据目录之外**：宿主只公开「扩展存储（命名空间）」与「酒馆用户目录文件」两类写接口，因此绝对路径（如 `D:\FTT\`）**做不到**，
  当前做法是剥掉盘符后落到数据目录内（如实登记为限制）。

## 3. 行为细节

| 场景 | 行为 |
| --- | --- |
| 保存（开启时） | 第 ④ 步不再写 localStorage，改写本地文件（`localBuffer.layer='local-file'`）；**变量层一个键都不写** |
| 保存（文件写失败） | **回退变量层**（`layer='localStorage'` + 原因 + `kernelWarn` + 读取台账），本机缓冲不丢 |
| 开启路径（迁移） | `switchLocalLayer()`：读变量层信封 → 写文件 → **回读逐字节校验** → 通过才清变量键（腾出配额）并重置写入签名 |
| 校验不一致 | **不清任何数据**，如实回报错误（变量层原样保留） |
| 关闭路径（迁回） | 按「上次路径」（设定页旧值 → 本次会话内存 → 落盘标记 `ftt2_LastLocalFilePath`）读文件 → 写回变量层；文件保留当备份 |
| 载入 | 路径非空时 `loadFromLocalFile()` 读文件并**按与变量层一致的口径校验**（信封完整 + 载荷哈希）；不过则丢弃并回落变量层 |
| 诊断 | `localFileStatsGet()`（读写/失败/最近字节/路径/后端）→ 设定→存储的「本机缓冲模式」状态行 + `🔁 立即对齐本机层` / `🔄 刷新状态` |

## 4. 界面（设定 → 存储 → 本机缓冲）

- 状态行：`本机缓冲模式：本地文件（<目录>）` 或 `变量（localStorage）`，附后端、最近写入字节、失败计数；
- 目录输入框：`data-ftt-cfg="storage.localFilePath"`（通用控件 → 落盘 `cfg.storage.localFilePath`，改动即触发**自动对齐两层**并 toast 结果）；
- 折叠说明：落点、路径约束、替代关系、「先写后清」纪律；
- 两个动作：`localFileAlign`（按当前路径对齐两层）、`localFileStatusRefresh`（刷新状态），均进 `SYNC_ACTIONS`（9 → 11 项）。

## 6. 未验证项（如实登记）

- **真机未实测**：TauriTavern 扩展存储命名空间的真实落盘、以及网页版酒馆对 `user/files/<目录>/…` 子目录的接受度，
  目前只在单测（宿主桩）与冒烟（酒馆文件桩）里验证；请刷新页面后填目录 → 点「🔁 立即对齐本机层」→ 到宿主数据目录确认文件生成；
- **绝对路径不支持**（宿主接口边界，见 §2）；
- **未做**：把「本地文件」也用于**其它层**（快照 / 分片的自定义目录）—— 本次只按用户要求替代变量层；若需要，后续可在同一路径约定下扩展；
- 迁移期间若用户手动改了 var/文件（极端并发），以「先写后清 + 回读校验」为准：校验不过就**什么都不清**，不会造成数据丢失。
