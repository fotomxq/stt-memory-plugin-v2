| `fft.floors`（`start:0,end:42`） | 非用户楼层 `stableChars` 1800–2500、`analyzableChars: 0`、`analyzable: false` | 正文在，**可分析正文为空** |

| 只读楼层原文 | 新正文用 `<dream_plot>` / `<dream_scene>` / `<q content="…">`；`content` 是**属性名** | 与白名单「标签名」语义错位 |

## 2. 根因

1. `core/prompt.js#applyFeedRegex`：白名单 `content` 先走「提取 `<content>…</content>` 内部内容」——新正文没有该标签 → 回退「行内包含」；
2. 行内兜底把 `<q content="…">` 这类**纯标记行**算作命中（`kept > 0`），返回这些行；
3. `cleanText` 去标签后为空 → `host/floors.js#floorAnalyzableText` = `''` → `scanPendingFloors` 计 `noText` → `pending = []`；
4. `host/extract.js#autoExtractLatest` 返回「没有未分析楼层」、单楼分析返回 `empty-floor` → 用户看到「无法分析」；
5. 附带缺陷：`analyzeSegment` 对「过滤后为空」直接 `recordProcessedFloors` + `empty:true`（**不调 AI**）→ 批次可能逐段静默空转。

「最开始只能分析 0 层」的解释：第 0 层不含 `content` 子串 → 走既有「白名单未命中 → 回退原文」→ 可分析；后续 AI 楼层都带 `<q content="…">` → 被过滤成空 → 再也不进清单。

## 3. 修复

| 落点 | 改动 |
| --- | --- |
| `core/prompt.js#applyFeedRegex` | 行内兜底：命中的行若 `stripHtmlTags(line).trim()` 为空 → **不算命中**；全部只剩纯标记行 → 回退原文，调试日志原因区分「未命中」/「只命中纯标记行」 |
| `host/floors.js#floorAnalyzableText` | 以「去楼层前缀后的 body」为准；过滤后为空或只剩前缀、而原文有正文 → **回退原文** + `摘要` 日志 |
| `host/floors.js#floorTextFilteredOut`（新，只读） | 「有正文但被判不可分析」判定，供诊断/单测 |
| `host/floors.js#scanPendingFloors` | `skipped` 新增 `filtered`（有正文但不可分析），不再与 `noText`（真·空正文）混计 |
| `host/extract.js#analyzeSegment` | 同口径回退并回 `filterFallback`；**只有原文也空**才 `recordProcessedFloors` + `empty:true` |

既有语义保留：真 `<content>…</content>` 仍只取内部内容；真·空正文楼仍计 `noText`；台账 / 聊天归属 / 版本签名 / `DATA_VERSION` 一律未动。

## 4. 测试与门禁

* 新增 `tests/unit/feed-filter-stale.test.js`（**10 项**）：属性名形态回退原文 · 真标签语义不变 · 楼层可分析 · 清单计数（`noText`/`filtered`）· 黑名单极端错位 · 真·空正文两态 · `analyzeSegment` 回退后**真的请求 AI**、真·空正文仍不请求 AI。

* 全量：单元 **261 文件 / 3874 断言** 全绿；冒烟 **224 通过**；`npm run gate` 全绿（含版本四处一致、体量棘轮、文档门禁）。

## 5. V1 偏离登记

* 无新 V1 偏离：本批只改**投喂过滤的兜底判定**（V1 原有「白名单未命中 → 回退原文」口径的延伸），提示词模板、取文口径、台账口径、`DATA_VERSION` 全部未动；V1 黄金样本一字未变。
