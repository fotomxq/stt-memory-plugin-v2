## 1. 现象与核对（**先复现再改文案**）

用户在总览「✏️ 手工改写日期/时间/地点」按钮**右侧**看到常驻的「自动同步中（日期/时间/地点只取最新情节…）」，
认为这条提示是错的（像是一直卡在同步）。

用黄金样本场景 + 面板渲染逐档复现（`ui/clock.js#clockSectionHtml`）：

| 情形 | 旧渲染结果 | 判定 |
| --- | --- | --- |
| 组件与自动同步都开着、无手工锚点 | 「自动同步中（…）」 | **用词误导**：「…中」与「加载中」同构，读起来是**进度态**，而它其实是**常驻模式说明**（没有手工锚点就一直显示） |
| `cfg.clockExtractEnabled=false`（消息后自动同步已关） | 「自动同步中（…）」 | **假话**：此时根本不会自动同步 |
| `cfg.enabled=false`（组件总开关已关） | 「自动同步中（…）」 | **假话**：同上 |
| 保存手工值后 | 「🔒 已手工锁定」+「🔓 解锁并恢复自动同步」 | 正确（本次只补回归锁） |

结论：**不是「卡在同步」，是这条常驻提示的用词与判据都不对** —— 既像进度、又不看开关。

## 2. 修法（`ui/clock.js`，只改渲染文案与判据，不动任何时钟取值逻辑）

| 档位 | 渲染文案 |
| --- | --- |
| 开着（`enabled!==false` 且 `clockExtractEnabled!==false`） | ⚙️ 自动同步：**已开启**（日期/时间/地点只取**本聊天的最新情节**；其它数据类别与正文解析都不参与 —— 想钉住就用手工改写） |
| `clockExtractEnabled=false` | ⚙️ 自动同步：**已关闭**（消息后不再自动更新；可在 设定 → 基础 打开「消息后自动同步时钟」） |
| `enabled=false` | ⚙️ 自动同步：**已停用**（组件总开关已关 → 时钟保持原值；可在「设定」里打开） |
| 有手工锚点（`clockManualState()` 非空） | 🔒 已手工锁定（未锁定时补「仍可被自动提取覆盖」）+ 🔓 解锁并恢复自动同步 |

纪律：**文案必须能被验证** —— 三档互不相同、且都不再出现进度腔的「自动同步中」，由单测逐档锁定。

## 4. 未验证项与后续

- **真机待核对**：刷新后总览该行应显示「⚙️ 自动同步：已开启（…）」；关掉「消息后自动同步时钟」应变为「已关闭」；
- 修复与核对都在开发仓库完成，而**页面当时仍是 v3.18.0**（`sys.info` 读数）—— 需刷新后才是新版本；
- 该提示为**中文硬编码**（`ui/clock.js` 未走 i18n 词条），en 界面同样显示中文：与本次报告无关，另行登记；
- 「🔓 解锁并恢复自动同步」按钮文案在**自动同步开关本身关闭**时略有不精确（解锁后并不会真的恢复自动更新，只是回到自动档位）—— 语义可接受，本轮不改；若要精确，可改为「解除锁定（回到自动档位）」。
