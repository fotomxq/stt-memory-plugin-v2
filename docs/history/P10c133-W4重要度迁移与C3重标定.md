## 1. 问题（为什么这两件事**必须同批**）

| 面 | 事实 |
| --- | --- |
| 存量数据 | 条目 `importance` 是 **V1 语义值**（`base + uses×per` ≈ 0.5） |
| 新语义 | v2.86.0 起 `importance` = **窗口调用占比**（≈1/21 ≈ 0.048） |
| 后果 | 一份数据里**两套尺度混存**；只看数值会把旧条目当成「高重要度」 |
| 为什么权重一直没改 | `core/recall.js` 的注释写着：`0.15 → 1.6` 必须与迁移同批，否则在旧值上把重要度项放大 ~10 倍 → **改变注入择优**、破坏 V1 注入保真 |

## 2. 改法

### ① 新模块 `core/importance-migrate.js`

| 导出 | 作用 |
| --- | --- |
| `IMP_MIGRATE_FLAG` | `'importanceV2'` —— 存在 `state.meta` 里，随存档走 |
| `IMP_LEGACY_SCALE` / `IMP_WEIGHT_LEGACY` / `IMP_WEIGHT_V2` | `0.1` / `0.15` / `1.6` |
| `importanceMigrated(st)` | 是否已迁移（只读） |
| `importanceWeight(st)` | **迁移前 0.15 / 迁移后 1.6**（召回打分用） |
| `migrateLegacyImportance(opts)` | ① **窗内**按新语义重算（复用 `recalcImportanceAfterExtract({force:true})`）；② **窗外**旧值 ×0.1（保留相对次序，`strength` 同步）；③ 打标 `state.meta.importanceV2 = true`；**幂等** |

### ② 召回权重切换（`core/recall.js`）

```js
const imp = recallImportance(e) * importanceWeight();   // 未迁移 0.15 / 已迁移 1.6
```

**均值贡献等价**：旧 `0.5 × 0.15 = 0.075`；新 `0.05 × 1.6 = 0.08`（差 < 0.01）→ **注入择优不因重标定而变**（`数-1` 的发布判据）。

### ③ 迁移触发点（**只挂生产路径**）

- `host/preflight.js` 调 `recalcImportanceAfterExtract({ migrateLegacy: true })` → 内部分支调用迁移；
- **不传该 flag 的调用**（所有单测、黄金样本）**完全不受影响** —— 这是刻意的：`migrateState` 与 `importance` 的重算链都有「V1 逐字符黄金样本」锁着，**不能**在那里改语义。

### ④ `数-2`：假 0% → 不适用

- 新增 `importancePctOrNull(item)`：**没有** `importance`/`strength` 的条目返回 **`null`（不适用）**；
  **补修（本轮内发现并修掉）**：`importance` 为 **`0`** 时也返回 `null` —— 因为 `recalcImportanceAfterExtract` 会给
  「窗口内零调用」的条目写 `0`（`D7` R23），而**场景 / 名册 / 货币**从不被注入 → 恒为 0 → 那正是 `D20` 说的
  「65% / 100% 的**假 0%**」；现在这些维度显示「不适用」，真有信号的低占比（如 2%）照常显示。
- `importancePct(item)` **保持原口径（数值）** —— V1 行正文黄金样本逐字符依赖它；
- 于是场景 / 名册 / 货币这些「不参与重要度」的维度不再被显示成 **0% 的假信号**。

## 3. 测试（`tests/unit/importance-migrate.test.js`，**11 个断言**）

| # | 断言 |
| --- | --- |
| `A1` | 未迁移 → 权重 **0.15** |
| `A2` | 迁移后 → 权重 **1.6** + 标志位落到 `state.meta.importanceV2` |
| `B1` | **窗内**重算成窗口占比（尾部因边界截断约 1/11≈0.09，中部 ≈0.05；都不再是 0.5） |
| `B2` | **窗外**旧值 ×0.1（保留次序、`strength` 同步），迁移后全库无 0.5 这类旧值 |
| `B3` | **幂等**：第二次 `skipped=already` 且不改值 |
| `B4` | `{migrateLegacy:true}` 才触发迁移；不传不触发（黄金样本安全） |
| `C1` | **均值贡献等价**（0.075 vs 0.08，差 < 0.01） |
| `C2` | 同一条目迁移前后**召回分差 < 0.01** |
| `D1` | `importancePctOrNull`：无字段 → `null`；有 → 数值 |
| `D2` | `importancePct` 保持原口径（数值；无字段仍 0） |
| `D3` | 场景 / 名册 / 货币三种真实条目 → `null`（不适用） |

## 4. 如实登记（未做 / 限制）

1. **`数-2` 只做了「不适用」口径**：② `uses` 语义统一为「被注入即 +1」、③ 体检按维输出 `uses=0` 占比 —— **未做**（留待下一轮，`数-2` 保持 🟡）；
2. **迁移只覆盖窗内 + 窗外按 ÷10 缩放**（不是逐条按 uses 分布重算窗外）—— 这是 `D20` Q4「仅窗内」的裁决口径；窗外条目在下次进窗时会被重算；
3. 迁移**只在 preflight 的实际运行路径触发**；如果你只导出/查看而从不跑「分析记忆」，旧值会一直保持旧尺度（`importanceWeight` 也因此保持 0.15 —— **行为一致**，不会算错）；
4. `数-1` 的「逐批」未做分批（一次性完成，`state.meta` 打标）；数据量大的存档首跑会多几百次整数运算；
5. **真机未人工试用**。
