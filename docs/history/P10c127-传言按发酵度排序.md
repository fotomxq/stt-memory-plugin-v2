## 1. 现状与诉求

传言列表此前与其它大类**同一套**排序（`core/clock.js#sortRecentByStoryDate`：剧情日期倒序 → `floorEnd` 倒序），
发酵度只作为行内展示字段。用户要求传言页改成「**发酵度优先**，同度看**发生日期**（最近在前）」。

## 2. 改法

### ① 新模块 `core/rumor-sort.js`（纯函数）

| 导出 | 作用 |
| --- | --- |
| `rumorFermentOf(e)` | 发酵度归一：缺省/非法 → **20**（与 `core/model/rumor.js#normalizeRumor` 同口径）；夹 0–100 取整 |
| `sortRumorsByFerment(list)` | **发酵度降序 → 同度按发生日期降序**（最近在前）；不改入参、返回新数组、稳定 |
| `rumorSortKey(e)` | 诊断用键（发酵度） |

**实现要点：两次稳定排序** —— 先复用 `sortRecentByStoryDate` 得到「最近在前」的基准序（**日期口径不另写**，
避免两处口径分叉），再按发酵度**稳定**排序；同度的相对次序 = 基准序 = 日期倒序，正好满足「发酵度优先、同度看日期」。
日期键沿用既有口径：剧情日期 → **无日期的排在有日期之后** → 再退 `floorEnd` 倒序。

### ② 面板接线（`ui/panel.js`，**只改一行**）

`listOfInfo` 的 `sort` 回调：

```js
sort: (a) => { try { return kind === 'rumors' ? sortRumorsByFerment(a) : sortRecentByStoryDate(a); } catch (e) { return a.slice().reverse(); } },
```

其余大类（情节 / 记忆 / 物品 / 计划 / 悬念 / 概念 / 场景 / 角色 / 状态）**行为逐字不变**。

## 3. 排序口径（示例）

| 条目 | 发酵度 | 发生日期 | 排序位置 |
| --- | --- | --- | --- |
| b | 90 | 1919-11-02 | 1（发酵最高） |
| c | 60 | 1919-11-03 | 2 |
| 五 | 50 | 1919-11-05 | 3 |
| 三 | 50 | 1919-11-03 | 4（同 50，比「五」更早 → 靠后） |
| 一 | 50 | 1919-11-01 | 5 |
| y | 50 | （无日期） | 6（无日期排在有日期之后） |
| a | 10 | 1919-11-01 | 7 |

同度且**都无日期** → 退回 `floorEnd` 倒序；完全同键（同发酵度同日期）→ **保持原相对次序**（稳定）。
