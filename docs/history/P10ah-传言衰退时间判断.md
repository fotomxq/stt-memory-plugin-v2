# P10ah · 传言衰退增加时间判断（v2.70.0）

> 文档版本：v1.0 ｜ 日期：2026-09-26 ｜ 状态：生效（v2.70.0）
> 触发（用户要求）：「传言的**衰退系数增加时间判断**，如果**发生时间越久远，衰退速度越快**。」

---

## 1. 原口径的问题

传言衰退（`core/rumor-evolve.js#rumorDecayScore`，V1 v1.192 原样）只把 `calcTimeDecay()` 用在**现实墙钟**上：

```js
// 修复前
return calcTimeDecay(earliest, latest, Date.now(), Number(r.updatedAt) || 0, list.length);
```

- `calcTimeDecay` = 多级时间尺度（小时/天/月/年，1 年封顶）+ 类目内相对位置 + 条目拥挤度；
- 而 `r.updatedAt` 会在**机械演化 / 平行联动 / 裂变 / AI 更新**时被 `Date.now()` 刷新（`rumor-evolve.js` 188/328/463/522/549/551），
- 于是：**越老的传言只要还在被提及，墙钟系数就被重置 → 永远不会消退**，与「旧闻应当淡去」的直觉相反。

## 2. 本批口径

在原有系数之上叠加**剧情时间久远度**（`core/rumor-evolve.js`）：

| 项 | 取值 |
| --- | --- |
| 发生时间 | 该说法的 `date`（该说法本次变化的剧情日期）与各载体 `media[].at`（载体日期）中**最早**的有效剧情日期 —— 即「这条说法最早是何时出现的」 |
| 久远度 `speed` | `min(1, (剧情当下 − 发生时间) / 365 天)`；**无剧情时钟 / 无发生日期 / 发生时间在未来 → 0** |
| 衰退系数 `score` | `min(1, base × (1 + speed) + 0.5 × speed)` ——**乘法加速**（最多 ×2）+**加法下限**（满额 +0.5） |
| 移除 | 仍是 `score ≥ cfg.rumorDecayCutoff`（默认 0.95）；清扫触发条件不变（超出存储上限比例 或 有达阈值者） |

效果举例（同一份列表、`updatedAt` 都是 1 天前 ⇒ 墙钟系数相同）：

| 传言 | 剧情当下 | 发生时间 | base | speed | score | 是否移除 |
| --- | --- | --- | --- | --- | --- | --- |
| 新说法 | 1919-11-29 | 1919-11-25 | 0.00 | 0.01 | 0.005 | 否 |
| 一年前 | 1919-11-29 | 1918-11-29 | 0.00 | 1.00 | 0.500 | 否（但已推到半程，随墙钟上升很快达阈值） |
| 五年前（且近期被刷新过） | 1919-11-29 | 1914-11-29 | 0.745 | 1.00 | 1.000 | **是** |
| 无发生日期 | 1919-11-29 | — | 0.00 | 0.00 | 0.000 | 否（完全保持原行为） |

设计取舍：**「久远」是加速项而非一票否决** —— 仍在活跃传播（刚被刷新、墙钟系数低）的传言不会被立刻删除，但会以明显更快的速度逼近阈值；
完全无时间信息（无剧情时钟 / 无日期）时行为与修复前逐位一致，不引入新的删除风险。

**未改动**：平行事件的衰退（用户本次只提传言）、`rumorDecayRatio` / `rumorDecayCutoff` / `storeMaxRumors` 等配置语义、清扫触发条件、墓碑写入。

## 3. 可核对

- **调试日志**（设定 → 调试 →「摘要」类）的「传言衰退」条目逐条给出
  `{subject, base, speed, boost, add, score, date, ageDays}`；
- 控制台可直接调 `FTT` 无独立入口，但 `core/rumor-evolve.js` 导出 `rumorAgeSpeed(r)` / `rumorDecayBreakdown(r)` /
  `RUMOR_AGE_HORIZON_DAYS` / `RUMOR_AGE_MAX_BOOST` 供自检与二次开发；
- 设定 → 传言：「启用传言衰退」提示改为「超出存储上限后按保留度淘汰旧传言；**发生越久远消退越快**」，
  「移除阈值」提示改为「默认 0.95：系数 ≥ 该值即移除（**系数含剧情时间久远度**）」，页面短提示补「发生越久远消退越快」。

## 4. 门禁

`tests/unit/rumor-decay-age.test.js`（10 断言）：

- A1 久远度取值（4 天 ≈0.011 / 1 年 = 1 / 无日期 0 / 未来 0 / 无剧情时钟 0）；
- A2 发生时间取「说法日期与载体日期中最早者」；A3 拆解公式 `score = min(1, base×(1+speed)+0.5×speed)`；
- A4 单调性（越久远系数越高，封顶后允许并列）；A5 新传言与「无剧情时钟」相比差 ≤0.01；
- A6 无日期的传言与修复前逐位相同；A7 阈值联动（久远达阈值、新说法不达、把日期挪到「刚刚发生」即不达）；
- A8 端到端清扫只移除久远那条且留删除墓碑；A9 365 天边界；A10 设定页文案同步。

`tests/unit/rumor-evolve-golden.test.js` 的模块契约清单同步为 **37 函数 + 2 常量**（新增 `rumorAgeSpeed`、`rumorDecayBreakdown`、
`RUMOR_AGE_HORIZON_DAYS`、`RUMOR_AGE_MAX_BOOST`），其余 V1 对齐断言不受影响。
