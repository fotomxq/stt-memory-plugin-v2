## 1. 缺陷一：货币子页面**无法点击**（用户报告）

**根因**：子标签按钮发出的是 `data-ftt-action="moneySub" data-sub="ledger"`，而面板的动作入参透传表**没有 `sub`**
→ `panelAction('moneySub', { sub: undefined })` → `setMoneySub(undefined)` 回落 `overview` → **点了没反应**。

**修复**（双通道，任一都生效）：
1. 动作入参补 `sub`（`data-sub` / `data-ftt-sub` / `data-ftt-csub` 三个来源都认）；
2. 子标签同时带 `data-ftt-csub` 标记 → 即使不经动作分发，也在「无 action 的标记分支」里被处理（与 `data-ftt-asub` / `data-ftt-mapsub` 同款）。

**回归锁**：`tests/unit/money-ledger-deals.test.js#H1` —— **真实点击委托**点「📒 收支记录 / 📈 长期收支 / 💰 货币总览」，断言面板内容随之切换。

## 2. W32 未落地问题

| # | 未落地点 | 修复 |
| --- | --- | --- |
| 1 | `currencyId` 是**文本输入**（需复制 id） | 改为**下拉选择**：选项 = 当前现存货币（`归属·币种（额度 单位）`）；无货币时占位提示「请先在货币总览新增」；记账/标的物共用 |
| 2 | 变动节点只有「每行 `日期|金额|说明`」文本域 | 支持 **JSON 数组**（结构化）与逐行两种写法；**解析失败/金额非数字 → 具体报错**，不再静默丢弃 |
| 3 | 保存失败只说「必要字段缺失」 | `deals` 保存前**逐项预检**并回报具体缺项：标的物名称 / 锚定货币 / 下一节点预测日期 / 最初确定日期；节点解析失败同样回报 |
| 4 | 详情**只读**，无编辑入口 | 收支记录行与长期收支详情行新增「✏ 编辑」→ 走既有编辑器（`kind=ledger` / `kind=deals`） |

> 仍**未**落地的两条（如实登记，依赖 `数-25` 冷热分层裁决）：账本/长期收支**不参与按条数裁剪**（上限仅展示）· 两者**占比 0**（不参与「总上限 × 占比」分配）。见 `docs/D54` §2。

## 4. 边界

1. 货币下拉只列**现存货币**；若要「边记账边新建货币」需另加流程（本轮不做）；
2. 节点 JSON 只校验形态，不做拓扑校验（日期可不递增，归一里会排序）；
3. 编辑流水不改变其幂等 id（金额改动会生成新 id 的流水 —— 编辑语义按「改为另一笔」落实，余额差已由记账入口冲正）。
