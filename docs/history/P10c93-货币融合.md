## 1. 数据先行（用户指点的「参考本地的调试接口，调取数据核对」）

新增**只读**工具 `tests/local/currency-audit.mjs`（留存，非临时），直接读宿主原生存储（`extension-store/**`），
按归属汇总「名字|单位」组合 + 合计额度 + 疑似同义粗筛。实测（李瑶）：

| 类别 | 存档里的名字 | 机械档 |
| --- | --- | --- |
| 金 | `黄金`(两) · `天然碎金`(块) · `碎金子`(两) · `碎金`(两) · `赤金条`(贯) · `赤金条子`(贯) · `诺米斯玛金币` | 一个都合不了 |
| 银 | `碎银`(粒) · `碎银子`(两) · `雪花银`(贯) · `雪花银角子`(贯) · `银角子与碎银饼`(贯) · `官铸雪花大银`(两) | 同上 |
| 票据 | `飞钱` / `飞钱凭证` / `东市柜坊飞钱凭证` / `通兑飞钱凭证`（均贯） | 同上 |
| 铜 | `开元通宝`(贯) · `铜钱`(枚/贯) · `拜占庭铜努米亚`(枚，**-6**) | 同上 |

**顺带核出的三类噪声**（都进"只报告不改"）：① **单位写法混乱**（黄金「两」/ 赤金条「贯」/ 铜钱「枚」）；
② **复合名**（「飞钱凭证及赤金条」）；③ **负额度**（-6）。

> 这些数字直接决定了本档的两条硬口径：**单位不同的不得合组**（否则必然要凭空换算）、**复合名/负额度不进组**（否则会算出错误金额）。

## 3. 窄契约七条判据（逐条有反向探针）

| # | 判据 | 反向探针（必须被拒） |
| --- | --- | --- |
| 1 | 成员必须在**本次打包集**内 | `cur_notexist` |
| 2 | 每组 **≥2 条** | 单成员组 |
| 3 | **同一 id 不得进两组** | 两组抢 `cur_coin` |
| 4 | **单位必须相同**（禁凭空换算） | 两(黄金) + 贯(赤金条) |
| 5 | 规范名非空、≤24 字、不得含「及/和/、/与」 | `黄金及赤金` |
| 6 | 复合名 / 负额度 / 名字即单位词的成员**不进组** | `飞钱凭证及赤金条` · `-6` 的条目 |
| 7 | 组数上限 | >30 组 |

## 5. 未做 / 限制 / 差异（如实登记）

1. **跨单位换算不做**（无汇率依据）；
2. **逐组勾选不做**（沿用「先出方案 → 全量应用 / 取消」）；
3. **`currencies` 无内容哈希口径** → 实际生效的是 **id 墓碑**（货币 id 由归属+币种派生 → 跨端同一条同 id，足以拦复活）—— 既有实现，本轮复核仍成立；
4. **改名后保留条目的 id 仍是旧名的派生值**（其余 id 进墓碑）→ 与既有机械档同款行为；"改 id"未做；
5. **真机未人工试用**：需刷新宿主页面后在货币页点一次「🔀 AI 融合货币」；
6. **不做自动/定时触发**（花一次 AI 请求，必须由人点击）。
