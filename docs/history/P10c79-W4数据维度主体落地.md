## 2. `数-10`：字段名规范（**只加不删、只补不覆盖**）

**事实**（`docs/D20` §3.4）：同一语义「最后一次出现」有 4 种字段名 —— `date` / `seenDate` / `floorSeen` / `lastSeenDate`。

**先纠正设计稿的一处不精确**：把 `floorSeen` 与三个日期名并列成「4 种**日期**字段名」是错的 —— 它是**楼层号**。
于是规范名按**形态**分两个：

| 形态 | 规范名 | 旧名（只读兼容） | 维度 |
| --- | --- | --- | --- |
| 剧情日期 | **`lastSeenDate`** | `seenDate` → `date` | `items`（`snapshots` 本来就写的规范名） |
| 楼层号 | **`lastSeenFloor`** | `floorSeen` | `scenes` |

| # | 落点 | 改动 |
| --- | --- | --- |
| ① | `core/field-names.js` | 登记表（`LAST_SEEN_DATE_FIELD` / `LAST_SEEN_FLOOR_FIELD` / `LEGACY_SEEN_DATE` / `LEGACY_SEEN_FLOOR`）+ `seenDateOf` / `seenFloorOf`（读：规范名优先、旧名回退）+ `canonicalizeEntryFields`（写：只补不覆盖）+ `legacyNameGaps` / `attributionMissing`（体检判定，纯函数） |
| ② | `core/migrate.js` | 载入期第 ⑦ 步：逐条双写，计数进 `lastHealInfo().fields` |
| ③ | `core/entry-meta.js#preserveEntryMeta` | **写入期**当场双写（这是所有维度归一化结果的**唯一漏斗**）→ 新条目不必等下次载入 |
| ④ | `core/model/hashfields.js` | 新增 `NON_HASH_CANONICAL_FIELDS`：**登记「刻意不进白名单」**，并写明三条理由（进 `HASH_FIELDS` = 改内容哈希 → 属数据契约；进同义组会违反 R3「keeper 必须在白名单内」；故两个名字都存） |

**为什么哈希零影响**：`lastSeenDate` / `lastSeenFloor` **都不在** `HASH_FIELDS` / `IDENTITY_FIELDS` / `slimWhitelistOf` —— 断言写进 `tests/unit/field-names.test.js` F7。
**为什么「归属缺失（`chatKey`）不回填」**：`core/entry-meta.js#stampChatScope` 的纪律是「**只打不推断，宁可少打**」——
历史条目属于哪条聊天**无法从数据本身判定**，猜错等于把别条聊天的情节提到最高档（比不打标更危险）。故只报告（`attribution-missing`），并在 finding 里写明原因。

## 3. `数-11`：关联行锚点（**只回填能确定的那一种**）

**事实**：记忆类关联行 149/149 缺知情时间、145/149 无告知人、98/149 差异为空。

| # | 落点 | 改动 |
| --- | --- | --- |
| ① | `core/rel-maint.js#REL_ANCHOR_PRESENT_HOWS` | 「**当时在场**」= `participant` / `witness` / `author` / `involved` —— 只有这些人的**知情时间 = 事发时间** |
| ② | `#backfillRelLinkAnchors` | 只给「在场」且**归属条目有剧情日期**、且该行**没有 `at`** 的行回填；**幂等**、**绝不覆盖**已有值 |
| ③ | `#relAnchorGaps` | 只读缺口统计（`at` / `from` / `view` + `atPresent` 子集） |
| ④ | `core/prompt.js` | 提示词补丁（**开关默认关**）：常量 `REL_ANCHOR_RULE_DEFAULT`，与 ① 的判据**同源** |

**为什么 `told` / `inferred` / `rumor` 不回填**：他们的知情时间**晚于**事发时间 —— 拿条目日期顶上就是**编数据**（本仓库的硬纪律）。
**为什么来源标记写 `note` 而不是新字段**：`core/model/rel.js#normalizeRelLink` 是**逐字移植 V1** 的归一化器，只产出规范字段集 —— 新字段会在**每次载入**被丢掉，于是「回填 → 丢标记 → 下次再算」形成**非幂等**的写盘循环（第一版正是这样，被 `rel-anchors` R4 抓出）。
`note` 是既有字段、被归一化保留、且**用户可见**（正好同时满足「可区分来源」与 ④「关系表标注」）。

**为什么 ① 改成默认关的补丁位**（本轮与设计稿的**唯一实质偏离**）：
`buildSummaryPrompt` 的输出与 V1 **逐字符一致**，被 `tests/unit/extract-prompt-flow.test.js` P1（`tests/fixtures/v1-golden-prompt.json`）锁死。
直接加两行 → P1/G2/V3 四个断言当场变红。而那是**最高频路径**（每次分析都走）：
在一个「数据卫生」批次里顺手改它，等于把**未经评测的行为变更**混进修复轮。故：
* 补丁文本做成**常量**（不做可编辑模板 —— 它必须与 `REL_ANCHOR_PRESENT_HOWS` 逐字对齐，开放编辑会造成「AI 按 A 规则写、插件按 B 规则判」的口径分叉）；
* 由 `cfg.relAnchorRuleEnabled`（**默认关**）控制是否追加 → **默认输出与 V1 逐字节相同**（P1 零修改通过）；
* 在「设定 → 分析记忆 → 入库卫生」给出开关与一段说明，用户一键启用。

## 4. `数-12`：计划 / 悬念能开环（**不自动删数据**）

**事实**：计划 / 悬念各 30 条全为 `open`，`stats.plansClosed = 0`、`suspenseResolved = 0` → 永不开环。

| # | 落点 | 改动 |
| --- | --- | --- |
| ① | `core/entries.js#closeEntries` | **写侧**：按**明确的 id 列表**了结（与既有「了结」**同一语义**：移出容器 + `stats` 计数 + **级联删关联行**）；空清单 → `ok:false` 且不写任何东西 |
| ② | `core/plan-aging.js` | **只读分档**（纯函数：`st` + `nowDate` 入参）：`fresh`(≤30 天) / `aging`(≤120) / `stale`(>120) / `unknown`（无剧情时钟） |
| ③ | `ui/panel.js` | 「⌛ 长期未推进」筛选（`listFilter` 的 `extra=stale`）+ 「⌛ 了结长期未推进（N）」按钮（**危险动作**，中央 `confirmDialog`） |
| ④ | `core/data-health.js` | 体检 `plan-long-open`（hygiene 通道，分维计数 + 写明当前剧情日期） |

**为什么按剧情时间而不是 `updatedAt`**：现实墙钟会随「用户什么时候打开插件」变化 —— 同一份存档在不同时间得到不同结论，**不可复现**。（与 v3.41.0 `业-6` 的「衰退基准统一为剧情时间」同口径。）
**为什么「无剧情时钟 → 不老化、不给按钮」**：那时「多久没推进」不可判定 —— **宁可没有按钮，也不给一个按现实墙钟乱算的按钮**。
**为什么不自动了结**：本轮同时采纳了 `docs/D28` Q1「**不删数据**」的边界；自动了结一个仍然 open 的计划就是**替用户判定剧情**。老化只做「分档 + 筛选 + 候选清单」，真正的了结必须用户点击（二次确认）。

## 5. `数-13`：空壳条目（**两个判据刻意分开 + 默认关**）

**事实**：场景 5/40、NPC 快照 6/27 正文 < 12 字（最短 0 字）。

| 判据 | 用在 | 规则 | 为什么不同 |
| --- | --- | --- | --- |
| **宽** `isShellEntry` | 体检 `entry-shell` + 列表筛选 | 正文类合计 < 12 字 | 只报告、只收窄可见范围 —— 报多了无害 |
| **严** `shellVerdict` | 入库拦截（默认关） | 正文 < 12 字 **且 标识类也为空** **且** 无其它有值字段 | 拦错了就是**删数据** |

**第一版错在哪**（已写进 `docs/D20` §6.1 与 `CHANGELOG`）：直接拿体检口径去拦 →
① `items` 里「钥匙」（`name` 2 字、`desc` 空）会被丢 —— 那是**删真数据**（`name` 本身就指认了对象）；
② V1 黄金样本里那条 `{"content":"木箱断口之谜：来源不明"}`（11 字、无标题）会被丢 → `ingest-golden` M1/M2 当场变红。
**结论**：拦截必须**严于**体检，**且默认关**（V1 已接受的入库结果属移植契约，不能被新守卫单方面改掉）。
`数-13` 的默认可见价值由**体检**与**筛选视图**承担 —— 两者零行为变更。

## 6. `数-14` / `数-15`：越界约束与槽位登记

### 6.1 `数-14`：**两套楼层上界必须分开**（本轮实测的第二处设计修正）

| 函数 | 取什么 | 用途 |
| --- | --- | --- |
| `ledgerMaxFloor` | `lastKnownFloor` / `lastChatFloor` / `processedFloors` / `processedDropped` | **基线越界判定**（本聊天已分析到哪的**直接**记录） |
| `observedMaxFloor` | 台账 **+ 条目上的 `floorStart` / `floorEnd`** | 只用于**诊断 / 测试**（「这份存档里出现过最大的楼层号」） |

**为什么不能混用**：第一次实现把条目楼层也算进「本聊天长度」→ 一个越界条目（199）会给越界基线（199）**作证**，两者都判不出来（`tests/unit/reserved-fields.test.js` V1/V2 抓出）。
**`floorStart` 为什么只报告不改写**：它极可能来自**另一条聊天**（跨聊天污染是既知现象）—— 自动夹取会把真实来源改写成本聊天楼层，而**来源可追溯正是 `D12` / `D16` 一系列修复的基础**。故改到**写入期**判（那里才有可信上界：本批楼层 + 基线 + 余量）并如实报告。
**`storyDay` 为什么超界 → 0 而不是夹到上界**：53143 天不是「略大」而是**解析错了** —— 夹到上界等于把错误数据伪装成合理数据（与「不编数据」的纪律相反）；记 0 = 「本次没有可用的天数」。

### 6.2 `数-15`：把「验收」机械化

验收原文是「`state` 里每个保留字段都有明确归属与出口说明」——**靠人记**是记不住的。做法：
* `core/state-slots.js`：四张表（`STATE_SLOTS` 声明层 / `STATE_INNER_SLOTS` 内层 / `RUNTIME_SLOTS` + `STATE_INNER_RUNTIME_SLOTS` 运行期层 / `RESERVED_CFG_READS` 死读配置键），每项给出 `label / semantics / wired / outlets / disposition`；
* **键集来自实测**（`grep 'state\.[A-Za-z_$]+ *='` 全仓 + `state.state.*`），不是凭印象列的 —— 这一步同时抓到「生产代码会写、但 `emptyState()` 不声明」的 14 个运行期槽位（不登记就会天天报噪声）；
* `tests/unit/state-slots.test.js` 断言**双向一致**（新增槽位不登记就红）+ 运行期层**不与声明层重叠**。

**判定取「标注」而非「接线」**：`protagonist`（4 处 best-effort 读、**无写入路径**）/ `varTemplates`（只在跨端容器名单）/ `state.sceneFocus`（全仓零读写）三个 `reserved` 槽位**在界面上从不出现**——「从界面移除」无从做起；而「谁是主角」**无法从数据机械判定**，接线等于新造一个用户可见能力（超出本批「无前置」范围）。
另登记一处**死读配置键** `cfg.protagonistName`（读了但不在 `defaultCfg`、无控件可写 → 恒为 `undefined`）→ U185。

## 9. 踩坑与教训（本轮实证）
