## 0. 问题与目标

改造前：列表行右侧按钮**始终平铺在行内**（`.ftt-item-ops`），窄屏靠 `flex-wrap` 把按钮挤到下一行 ——
结果是**行高翻倍、正文可用宽度被吃掉**；平行页更早（v2.71.0）就因此改成竖排。

用户要求把它换成**按需出现**：滑动（触屏）/ 悬停（PC）才展开，并且**布局要适配**（不同按钮数、不同屏幕）。

**非目标**：不改任何动作语义（编辑 / 删除 / 推进 / 转正…的动作名与二次确认一律不动）；不引入新依赖或构建步骤。

## 1. 结构（标记层）

```html
<div class="ftt-item ftt-inline ftt-swipe" data-ftt-swipe="1" data-ftt-swipe-n="3" [行属性…]>
  <div class="ftt-swipe-body">…多选勾选框 + <span class="ftt-grow">行内容</span>…</div>
  <div class="ftt-swipe-ops ftt-item-ops">…按钮组…</div>
</div>
```

* **行标记一律由 `ui/swipe-rows.js#swipeRowHtml()` 产出**（单一事实源）——`ui/panel.js` 只传「内容块 + 按钮」；
* `data-ftt-swipe` 有**可查的读者**（`SWIPE_ROW_SELECTOR = '.ftt-swipe[data-ftt-swipe]'` 字面写出），
  故 `tests/unit/panel-audit.test.js#L5`（委托属性完整）对它照常生效；
* `data-ftt-swipe-n` = 按钮数（只读读数，供诊断与测试）；
* 平行页的**竖排操作列** `.ftt-ops-col` 不变（V1 口径，`parallels-layout` 测试继续锁）。

## 2. 行为（一份状态机，三条入口）

| 入口 | 事件 | 动作 |
| --- | --- | --- |
| 触屏 | `touchstart` / `touchmove` / `touchend` | 横向意图判定 → 左滑过 `-26px` 展开 / 右滑过 `+22px` 收起；拖动期间 `.ftt-drag`（关过渡，跟手） |
| PC | `mouseenter` / `mouseleave` | 悬停即展开、移开即收起（用户明确要求） |
| 键盘 | `focusin` / `focusout` | 焦点进入展开；离开前先问 `hasFocusInside(row)` —— **绝不把键盘用户正在操作的按钮收走** |

**展开态唯一**：行上 `.ftt-open`。三条入口都只是「调 `openSwipeRow` / `closeSwipeRow`」，
所以**不存在第二套视觉**（这也是本轮刻意避免的复杂度：不再写 `:hover` 的 CSS 旁路）。

**互斥与收起**：

* **同一时刻只展开一行**（`openSwipeRow` 先 `closeSwipeRow(openRow)`）；
* 点行外空白 → 全部收起（根上挂**一次**点击守卫，`applySwipeRows` 幂等 → 重复渲染不重复挂）；
* 点行内按钮 → **不收起**（`closest(SWIPE_ROW_SELECTOR)` 命中即跳过）——否则「点一下按钮面板就跳走」，等于按钮不可用；
* **守卫只在「真的有滑动行」时才挂**（`out.rows > 0`）：无行页面不引入任何点击监听 —— 保持既有点击链路**零污染**。
  这条是冒烟 `AO2`（点击入口 `preventDefault` / `stopPropagation` **计数**）当场逼出来的：首版无条件挂守卫，
  多出的那个监听让 `prevented === n` 不成立 → 按「无行不挂」修正（**门禁按设计生效**，已写入 CHANGELOG §二）；
* 切页 / 重渲后由 `applySwipeRows` 重新绑定（行是新建的）。

## 3. 布局适配（本轮重点）

| 项 | 做法 |
| --- | --- |
| **左移量** | **实测**按钮组宽度（`ops.scrollWidth`）→ 写入行级 `--ftt-swipe-w`；行内容 `translateX(-var(--ftt-swipe-w))`。按钮 3 个与 5 个、中文短标签与长标签的左移量**各不相同** |
| **过宽折行** | 按钮组宽 > 行宽 × `SWIPE_MAX_RATIO`（0.72）→ `.ftt-swipe-wide`：按钮组 `flex-wrap: wrap` **折行成多行网格**、宽度夹到 72% —— 按钮再多也不吃掉整行 |
| **窄屏** | ≤ 760px（与面板紧凑模式同断点）：行内容允许折行；折行网格上限放宽到 78% |
| **回退** | 宽度变小后**去掉** `.ftt-swipe-wide`（不留残留态）——测试 D3 锁 |
| **量不到时** | 面板未挂载 / `display:none` → 返回 0、**不写脏变量**、跳过左移与动画，**按钮照旧可点** |
| **动效** | 0.18s 过渡；`prefers-reduced-motion: reduce` → 无过渡（与仓内既有口径一致） |

## 4. 容错与降级（全部 try/catch 兜底，不静默失败）

* `applySwipeRows(null)` / 无 `querySelectorAll` 的根 / `bindSwipeRow(null)` / `openSwipeRow(null)` → 安全返回；
* `classList` 缺失（受限宿主）→ 绑定与展开都不抛错；
* 行对象被 **freeze**（`__fttSwipe` 写不进去）→ 仍用 `WeakSet` 完成去重并绑定；
* 任何一步失败都**不影响按钮本身**：标记仍是普通行，按钮照旧可点（最差退化为「按钮常显」）。

## 5. 体量棘轮（`docs/05` §5 C11）

* 新功能整体落 **`ui/swipe-rows.js`**；
* `ui/panel.js` 只留三处接线：**两处渲染助手**（维度列表行 / 状态列表行）+ **渲染后一次绑定**（放在 `finish()` 内 ——
  三条渲染路径（复用模态 / 整树替换 / 桩回落）都经它）→ 行数 **+20**（基线 3983 + 宽限 40 以内，**未上调基线**）；
* `style.css` 新增 5 个类名（`ftt-swipe` / `ftt-swipe-body` / `ftt-swipe-ops` / `ftt-swipe-wide` / `ftt-drag`）。

## 7. 边界（如实登记）

1. **只改维度列表行与状态列表行**：场景树、各类「选择器」面板（选角色 / 货币选角色 / 履历批量勾选）、同步日志等行**未改** ——
   它们是「勾选 / 挑选」形态而非条目操作列，且部分已自带布局。若后续要一并统一，另立条目。
2. **不做「展开后自动收起」的计时器**：收起只由用户动作触发（右滑 / 点别处 / 移开鼠标），
   避免「手指还没点到按钮，它就自己收回去」。
3. **不引入依赖 / 构建步骤**（源码即发布物）。
4. **版本位**：**v3.48.0** —— 按 `开发守则.md` §3.1「新增能力 → `3.<minor+1>.0`」（新增一种按钮触发交互）。
