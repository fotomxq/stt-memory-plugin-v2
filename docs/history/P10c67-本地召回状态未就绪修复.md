# P10c67 · 修复「本地召回失败 Cannot read properties of null (reading 'state')」：内核态未就绪时如实空手而归（v3.39.0）

> 文档版本：v1.0 ｜ 日期：2026-10-08 ｜ 状态：生效（v3.39.0）
> 用户报告（原话）：「修复报错：本地召回失败 Cannot read properties of null (reading 'state')」
> 关联：`core/recall.js`（取用口径 / 入口短路）· `host/inject.js`（状态未就绪 → 如实跳过）·
>   `host/chat.js#attachKernelState`（绝不置空）· `index.js#init`（空容器占位）·
>   同类历史修复：`index.js` 记过的「已处理楼层漂移防呆失败 reading 'processedFloors'」（`docs/history/P10c42` 一带）

## 1. 报错从哪里来

`core/recall.js` 里的**本地召回**入口 `buildMemoryBodyForInject()` 末尾有一个兜底：

```js
} catch (e) { warn('本地召回失败', e); return ''; }
```

于是只要函数体里抛错，用户就会看到一条红字「本地召回失败 + 原始消息」。这次的原始消息是
`Cannot read properties of null (reading 'state')` —— 说明**内核态 `state` 是 `null`**，而代码在 `state.state.…` 上取属性。

## 2. 为什么 `state` 会是 null

* 内核态由宿主注入：`core/model/runtime.js` 是 `export let state = null`，
  只有载入链路（`index.js#loadMemoryState` → `attachKernelState(st)`）完成后才有值；
* **生成拦截器是页面级全局钩子**（`manifest.json` 的 `generate_interceptor`），它**不受插件 init 顺序约束**：
  首屏载入 / 切换角色 / 跨端合并的**窗口期**里只要发生一次生成，召回就会带着 `state === null` 进来；
* 另外 `host/chat.js#attachKernelState(next || null)` 会在**传入非对象**时把内核态**置空**，
  之后所有 `state.*` 取用处（不止召回）都会炸。

这与仓库里已经修过的一条真机错误**完全同类**：`index.js` 的注释记着
「已处理楼层漂移防呆失败 Cannot read properties of null (reading 'processedFloors')」——
当时是在 `host/floors.js` 的入口逐个短路（`skipped: 'state-not-ready'`）。本次把同一口径补到**召回链路**。

## 3. 本版口径（四层，逐层都独立成立）

| 层 | 落点 | 口径 |
| --- | --- | --- |
| ① 取用 | `core/recall.js` | 全模块经 `st()`（内核态）与 `stState()`（`state.state` 块）取用；未注入 → **空容器**（各大类读作空数组）→ 召回如实为空，**绝不抛错** |
| ② 入口 | `core/recall.js#buildMemoryBodyForInject` | 进函数先判：未就绪 → 记一条**低噪**诊断（`dbgLog('召回', …)`，不是 `warn`）；`diagnose` 模式回 `{ok:false, reason:'state-not-ready', note:'内核态尚未注入…'}` |
| ③ 注入 | `host/inject.js` | 未就绪 → `{ok:true, reason:'state-not-ready', injected:false}` + 召回方式词条「状态未就绪」；**不覆盖上一次注入**、不计错误；载入完成后自动重算 |
| ④ 源头 | `host/chat.js` + `index.js` | `attachKernelState` 传入非对象时**保留当前态**（绝不置空）；`init()` 在 `loadMemoryState()` **之前**注入**空容器占位**，从根上关掉「`state` 为 null」的窗口 |

**注意（数据安全）**：占位注入**不会**造成「空态覆盖好数据」——载入链路仍以服务端文件为基底做并集，
且写盘侧的**双层防缩水守卫**（`adapters/store.js`：`before >= 1 && after === 0` 一律拦下）不受影响；
载入期的用户动作（导入 / 清空 / 跨端合并）仍按 `kernelStateSeq()` 让位，语义逐字不变。

## 4. 只读核对

* 调试日志 `kind='召回'`：`内核态尚未注入（启动 / 切换中）→ 本轮不召回`（一次性、低噪，不是「异常」）；
* 注入自查（面板「🧭 按本地召回」）在窗口期显示**原因句**：内核态尚未注入（首屏载入 / 切换角色 / 跨端合并的窗口期）；
* 注入统计 `pushStats().lastMethod.key === 'state-not-ready'`。

## 5. 测试与门禁

  ① 根因回归（`state === null` → 返回空串且**不再出现**「本地召回失败」/`reading 'state'` 告警）；
  ② 约束段 / 日期锚点 / 可信情节 / 最新日期条目 / 在场名单 / 重要度在未就绪时**都不抛错**；
