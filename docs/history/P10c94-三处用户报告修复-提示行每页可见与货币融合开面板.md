## 2. 根因 (a)：提示行只渲染在总览页（v3.24.0 起）

**证据（复现，本轮实测）**：写一条 note 后，逐页渲染 `panelBodyHtml(tab)`：

| 分页 | 修复前 | 修复后（外壳） |
| --- | --- | --- |
| overview 总览 | ✅ 有 | ✅ 有（位置移到外壳） |
| currencies / snapshots / rumors / plans … 其余 12 页 | ❌ **无** | ✅ **有** |

```text
修复前：overviewBody() 里 `if (ps.note) lines.push('<div … data-ftt-note>…')` ← 全仓唯一渲染点
修复后：panelModalInnerHtml() 里 `head + noteLine + tabs + bodies` ← 面板级（每页都在页签之上）
        同时**删除** overviewBody() 里那一份 → 渲染位置唯一，不重复
```

**为什么放在外壳**：提示行表达的是「**刚才那步动作的结果**」，属**面板级状态**，与「用户正停在哪一页」无关。
放在头部之下、页签之上 → 无论当前在哪页都第一时间看见，且**不需要每个分页各写一遍**（否则 13 处重复，正是 `开发守则` §2.7 反对的）。

**不变量（都被 G 组用例锁定）**：`role=status` + `aria-live=polite`（读屏播报语义）· 级别配色类 `ftt-note--err/warn/ok` ·
节点形状 `data-ftt-note` + `ftt-note-line` · **每页只出现一次** · 总览正文不再含（不是"两处都渲染"）。

## 3. 根因 (b)：货币融合的开面板动作没置 `open`

```js
// 修复前（ui/currency-merge.js）
if (a === 'currencyMergeOpen') return { ok: true, note: '货币融合：请选择要整理的角色…', action: a };
//                                ↑ 只回文案，open 仍是 false
// 而 currencyMergePanelHtml() 首行是： if (!open) return '';
// → 预览区恒为空串 → 角色列表永不出现 → 无法选角色 → 功能不可用

// 修复后
if (a === 'currencyMergeOpen') return Object.assign({ action: a }, currencyMergeOpen());  // 置 open = true
```

**为什么当时没被发现**：v3.46.2 的 `tests/unit/currency-merge.test.js` **只测内核**（导入 `core/currency-merge.js` 的
打包 / 校验 / 合成 plan / 应用 / 墓碑，10 项），**完全没有导入 `ui/currency-merge.js` 与 `ui/panel.js`** ——
UI 层零覆盖，于是「开面板没生效」这种纯界面缺陷**必然逃过门禁**。

### 5.4 一个必须记下的教训（假绿）

首次写 H/G 组时用了**异步断言却传给了同步 `A()`** —— 本文件里 `const A = (n, c, e) => R.assert(n, !!c, e);`
会先 `!!c`，**把 Promise / 函数变成 `true`**，连 reporter 的「断言条件是 Promise」防呆都被 `!!` 提前吃掉 → **全绿但什么都没验**。
症状：**回退修复后用例依然全绿**。改法：新增 `AX`（传函数、`await` 后再断言，同 `tests/unit/aux-store.test.js` 口径），
之后 H4 立刻暴露出一个真错误（墓碑是**按 id 的映射** `deleted.currencies = {<id>:<at>}`，不是数组，我原先用 `.length` 判空 → 恒假）。
**结论：异步用例一律 `await`，并且必须做一次反向验证** —— 否则「新用例全绿」可能只是假绿。
