> 用户要求（原话）：「本地存储的快照，也需要拆分结构化存储，避免单一文件聚合。日志文件也需要拆开做存储。」

## 1. 之前的问题

v3.31.0 把**状态本体**按维度拆成了逐维文件，但同一目录下还有两处「聚合成单一文件」：

* **快照链**：整条链在信封里是一个 `snapStore` 数组（也随逐维分片落成 `snapshots.json` 一维）——一条坏记录 = 整链不可用；
* **日志**：调试日志 / 交互时间线各自是**一个大数组**（单文件 / 单键，撞配额，也无法按时间取用）。

## 2. 现在的结构（落点）

```text
<本地存储路径>/
└── char_1xbib3t/
    ├── manifest.json  meta.json  atoms.json  …      # v3.31.0 的逐维分片（状态本体）
    ├── snapshots/
    │   ├── manifest.json      # {v, at, count, order, parts:{<id>.json:{hash,bytes,n,kind,ts}}}
    │   ├── root_1.json        # 一条快照一个文件
    │   └── incr_2.json  incr_3.json …
    └── logs/
        ├── manifest.json      # {v, at, kind, count, order, parts:{<片>:{day,n,hash,bytes,from,to}}}
        ├── debug-2026-10-06.json
        └── debug-2026-10-07.json  trace-2026-10-07.json …
```

命名口径：快照 `<id>.json`；日志 `<kind>-<YYYY-MM-DD>.json`，同一天超过 `cap`（默认 500 条）再切 `-2`、`-3`。
文件名一律过 `safePartName`（非法字符转 `_`），非法时间戳归入 `unknown` 天。

## 3. 口径（`adapters/local-parts.js`，纯函数）

| 函数 | 作用 |
| --- | --- |
| `snapshotParts(snapStore)` | 快照链 → **一条一个文件** + 清单（链顺序 `order`、逐条 `hash/bytes/n/kind/ts`） |
| `joinSnapshotParts(manifest, files)` | 逐条文件 → 链（按 `manifest.order` 还原；**坏一条只报那一条**） |
| `logParts(entries, kind, {cap})` | 日志 → **按天分片**（`at`/`ts` 定天）+ 清单（各片 `day/n/hash/bytes/from/to`） |
| `joinLogParts(manifest, files)` | 逐片文件 → 条目（按 `at` 升序；坏片只报坏片） |
| `safePartName` / `snapPartFileName` / `logPartFileName` / `dayKeyOf` | 命名与按天键 |

## 4. 接线与纪律

* **写**：保存 ④ 写完单文件副本后写快照分片（`localBuffer.snapParts`）；辅助数据落盘成功后写日志分片（`auxStoreInfo().parts`）——
  两者都是 **best-effort**：失败只记诊断、**不阻塞**主写入，主记录（`ftt2-local-*.json` / `aux-*.json`）**照旧保留**；
* **读**：载入**只补不覆盖** —— `recoverSnapParts` 只在信封里的快照链**为空/缺失**时用分片复原；链非空**一字不动**，
  分片不可用时如实保留空链（**绝不凭空造数据**，也绝不因分片问题清空既有链）；
* **诊断**：`ftt.diskFiles` 附带快照 / 日志两类分片的条数、文件数、坏片数与目录；数据管理页辅助数据明细新增
  「日志结构化拆分」行（条数 / 按天文件数 / 落点）；
* 浏览器选中的文件夹（File System Access）自动建 `<scope>/snapshots`、`<scope>/logs` 子目录；宿主文件 API 逐文件写。
