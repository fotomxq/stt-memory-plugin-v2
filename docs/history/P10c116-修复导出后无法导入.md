# P10c116 · 修复「导出后的数据无法导入」（v3.50.7）

> 文档版本：v1.0 ｜ 日期：2026-10-15 ｜ 状态：生效（v3.50.7）
> 用户原话：「导出后的数据无法导入，请修复。」
> **版本位**：用户报缺陷 → 守则 §3.1 的 patch 位，**无偏离登记**（导入是 V2 自有功能，与 V1 黄金样本无关）。
> 关联：`docs/D17` **U253** · `CHANGELOG.md` v3.50.7 · 上一轮 `P10c115`（v3.50.6）

## 1. 先复现：导出 → 导入到底丢什么（真实代码路径）

用真实函数做**往返探针**（`exportTextOf` → `importStateJson`），逐容器对比：

| 容器 | 导出侧 | 导入后 | 结论 |
| --- | --- | --- | --- |
| 15 个维度容器（情节 / 状态 / 档案 / 记忆 / 物品 / 计划 / 悬念 / 场景 / 概念 / 平行 / 关联 / 分段 / 传言 / 货币 / 地图） | 各有内容 | **逐条还原** | 正常（`mergeV1IntoCurrent` 只并维度容器） |
| **`processedFloors`（已处理楼层台账）** | `{1:{…},2:{…}}` | **`{}`（归零）** | ✗ **缺陷**：导入备份后旧楼层全部重新变成「待分析」→ 用户看到的就是「导入没生效」 |
| **`vars`（变量）** | `{weather:'阴'}` | **`{}`** | ✗ 缺陷 |
| **`stats`（累计统计）** | `{plansClosed:3}` | `{plansClosed:0}` | ✗ 缺陷 |
| `processedDropped` / `lastKnownFloor` / `processedVer` / `varTemplates` / `plotSegmentLog` | 有值 | 丢失 | ✗ 缺陷 |
| `deleted` / `deletedH`（墓碑） | 有值 | 并入 | 正常 |

**另外两处「导入失败」的真实成因（本轮一并修）**：

1. **信封缺 `state` 时「静默假成功」**：旧实现 `incoming = obj.state || obj` → 文件若只有信封（不完整 / 被编辑器截断），
   就把**信封本身**当状态合并 → `added: 0` 但返回 `ok: true` → 面板提示「新增 0 条」，用户完全看不出「其实一条都没进去」。
2. **带 BOM 的 JSON 直接失败**：Windows 记事本 / 部分宿主「另存为 UTF-8」会写 `\uFEFF`，`JSON.parse` 抛错 →
   面板报「导入失败（JSON 解析失败）」，而文件其实是好的。

## 2. 修法

| # | 面 | 修法 |
| --- | --- | --- |
| ① | **运行时槽并入**（`adapters/import-v1.js#mergeRuntimeSlots`，新函数） | 台账类 `processedFloors` / `processedDropped`（**并集**）· 账本 `plotSegmentLog`（按 `sig` 去重、保留末 10 条）· `varTemplates`（并集）· 计数器 `stats`（逐键取较大值）/ `lastKnownFloor` / `processedVer` / `updatedAt`（取较大值）· 对象 `vars`（**当前优先**，文件补空键）· 单值 `protagonist` / `sceneFocus` / `storyDay` / `clockSrc` / `clockManual`（当前为空才采用文件值）。**不并入**：会话 / 时钟游标与运行日志（`chatKey` / `lastChatFloor` / `present` / `repairCursor` / `snapFp` / `rumorTick` / 各类 `*Log`）—— 它们描述本机本次会话。 |
| ② | **导入主流程**（新模块 `adapters/import-state.js#importStatePayload`，`index.js` 只留一行接线） | 解析前**去 BOM + 去首尾空白**；**信封校验**（带 `format` 却无 `state` → 如实失败并点名）；**逐容器回报** `dims` / `slots` / `tombstones`；**落盘失败不吞结果**（`saved:false` + `saveError`，内存已合并）。 |
| ③ | **提示文案**（`importResultNote`，同模块；`ui/panel.js` 两处调用） | 从「新增 N 条」变为**逐容器明细**：「条目新增 N 条（atoms 3 · memories 2）；台账 / 变量等并入 M 项（vars · stats）；删除墓碑并入 K 条；相同的跳过 / 变更覆盖，未删除本地记忆」＋落盘失败另行如实告警。 |
| ④ | **体量棘轮** | `index.js` 加解析容错后会 +62 超限 → 逻辑外移到 `adapters/import-state.js`（入口一行接线）；`ui/panel.js` 的文案助手同样外移 → 两处都在限内（`index.js` +40 / `panel.js` +27）。 |

**合并语义不变**：append-only —— 同 id 以本机为准（**不覆盖**）、本机独有条目**不删除**（本档 A5 锁定）。

## 4. 如实登记（未做 / 限制）

1. **不并入会话 / 时钟游标**（`chatKey` / `lastChatFloor` / `present` 等）—— 跨端并入会与本机会话互相打架；若你希望「导入后连当前在场角色也照文件恢复」，可以按需求单独提出；
2. **`stats` 取较大值**（单调计数器语义）：同机重复导入不会把计数刷小；
3. **未做导入预览 / 干跑**（V1 数据导入有干跑，本 JSON 导入目前是一步合并）—— 如需要可另立条目；
4. **真机未人工试用**：需刷新后在「设置 → 数据管理 → 📥 导入存档」实测一次（选文件导入 + 粘贴导入各一次）。
