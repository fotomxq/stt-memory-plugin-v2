# P10c57 · 本地磁盘目录写盘失败：回退浏览器层 + 醒目提醒 + 标记路径无效（v3.28.1）

> 文档版本：v1.0 ｜ 日期：2026-10-07 ｜ 状态：生效（v3.28.1）
> 用户要求（原话）：「请修复，如果写盘失败回退浏览器层，但必须明显提醒用户，且标记用户设置的路径无效。」
> 关联：`adapters/local-disk.js`（无效状态）· `adapters/store.js`（保存 ④/⑤ 回退）· `index.js#loadMemoryState`（载入回退）·

## 1. 之前的问题（v3.28.0）

本地磁盘目录写盘失败时**不回退**浏览器层，只记一条警告 —— 结果：用户设了路径但写不进去时，
**这一轮保存的本机副本就不存在**（观感仍是「数据丢了」），而用户可能并不会去看调试日志。

## 2. 现在的口径（v3.28.1）

| 情形 | 行为 |
| --- | --- |
| 磁盘写入成功（写 → 回读逐字节一致） | 正常：本机层 = 本地磁盘目录；并**清除**该路径的无效标记 |
| 磁盘写入失败 / 写后回读不一致 / 探针失败 / 无写盘能力 | ① **回退浏览器层**（同一次保存走明文·压缩 + 预算判定的浏览器分支，`localBufferState().layer = 'localStorage'`，**内存库照写**）；② **弹一次醒目通知**（`notifyHooks.toast(..., 'warning')`，同路径每会话只弹一次，避免刷屏）；③ 调试日志 + 内核警告 + 读取台账如实记账；④ **把该路径标记为「无效」** |
| 载入时磁盘层未命中 / 读盘失败 | 同样**回退浏览器层**（变量 / 内存库 / 聊天元数据），标记路径无效 + 弹一次醒目通知（**数据优先**） |
| 路径无效标记 | 是**运行期状态**（不落盘）；写入成功或「✅ 校验本地磁盘目录」通过即**清除**并恢复正常磁盘层 |

**UI**：设定 → 存储 的「💾 本地磁盘目录」分节在无效时显示红字告警：
「⚠️ 该路径已被标记为「无效」：写入/读取失败，已回退浏览器本地存储 —— 请修正后重新『✅ 校验本地磁盘目录』」；
能力详情里写明「失败会回退并标记无效，修正后重新校验即恢复」。

**边界（如实）**：回退**只影响本机层**；服务端记忆文件 / 分片 / 快照照写、跨端同步语义不变。

## 3. 测试与门禁

* `tests/unit/local-file-mode.test.js` 新增 **E1/E2**：
  * E1：宿主无文件 API（能力缺失 → 必然写失败）→ 断言 `localBufferState().layer === 'localStorage'`、浏览器变量层确有内容、**内存库照写**、`localDiskInfo().invalid.invalid === true`、且收到 `warning` 通知（文案含「本地磁盘目录」）；
  * E2：装上 `api.dev.files` 能力 → 先人为标记无效 → `localDiskProbeDir()` 通过 → 无效标记**清除**；
* 全量：**162 文件 / 2505 断言** + 冒烟 **220 项**；静态门禁（含 `docs-facts` 的 C8/C9）全绿。

## 4. 纪律（写进本档）

* 「用户明确要求停用某层」与「这一层此刻不可用」是两件事：**不可用 → 必须回退并告知**，不能静默丢副本；
* 回退要**口径一致**（变量 + 内存库一起回退），否则会出现「回退只回了一半」的新一轮对账错乱；
* 用户的配置一旦被判定不可用，必须**显式标记 + 显著提醒 + 可恢复**（重新校验即清除），不能只活在日志里。
