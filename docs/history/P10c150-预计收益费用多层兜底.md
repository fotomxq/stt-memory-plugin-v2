# P10c150 · 预计收益费用多层兜底（v3.51.9）

> 文档版本：v1.0 ｜ 日期：2026-10-25 ｜ 状态：生效（v3.51.9）
> 用户要求（原话）：「预计收益费用，如果没有任何记录，则直接采信记录的周期、预测下一个日期、下一个费用来轮动。多层兜底。」
> 关联：`core/model/deal.js#resolveForecastDelta` / `#inferForecastFallback` · `core/deal-triggers.js`

## 1. 问题

v3.51.7 的兜底只覆盖「有节点 → 趋势」。两个洞：
1. **零记录**（新建标的物还没任何已发生节点）→ 兜底一律给 `delta = 0` → 轮动时「只推进水位、不记账」，用户看到的是「有周期有预测日期，却永远不出账」；
2. **`forecast.delta` 为 0 但有历史**（AI 只给了日期没给费用）→ 触发器仍按 0 记账（同样不出账），趋势信息被浪费。

## 2. 多层兜底（确定性，逐层降级）

新增 `core/model/deal.js#resolveForecastDelta(deal)`，按顺序取第一个可用值：

| 层 | 来源 | `basis` |
| --- | --- | --- |
| ① | `forecast.delta`（**AI / 手动明确**给出的费用） | `forecast` |
| ② | 已成节点**趋势外推**（最近 ≤3 节点线性；不足 2 个 → 最后节点金额） | `trend` / `last` |
| ③ | **没有任何记录** → 采信记录里声明的「下一个费用」（`forecast.delta`），按记录的**周期 / 预测日期**轮动 | `forecast-record` |
| ④ | 以上都没有（费用确实未记录）→ `0`：只推进水位、不生成流水（如实留痕，不编造金额） | `none` |

`inferForecastFallback(nodes, cycle, startDate, forecastDelta)` 新增第 4 参：正是第 ③ 层的落地
（无节点时不再一律 0，记录里给了费用就用它）。

## 3. 触发器

`runDealTriggers` 生成流水时的金额改为 `resolveForecastDelta(d).delta`（此前是 `fc.delta`）：
* 零记录 + 有预测费用 → **每轮都按该费用记账**（按周期连续轮动）；
* 有历史但预测费用为 0 → 用**趋势**金额记账（不再空转）；
* 真正没有费用可依 → 仍按 0 只推进水位（不编造）。

## 4. 测试

`tests/unit/deal-forecast-fallback.test.js` 16 → **21 项**（G1–G5）：
G1 零记录采信记录费用（17）· G2 五层顺序 · G3 零记录按费用逐轮记账（3 轮 × 10）· G4 预测费用 0 但有历史 → 趋势 30 记账 · G5「预测留空 + 无节点 + 记录给了费用」归一后带出日期与费用。

全量单测 **259 文件 / 3853 断言**；冒烟 224 项；`npm run gate` 全绿。

## 5. 边界

1. 第 ③ 层仍是**采信记录**（不推算、不编造）：记录里费用为 0 就是 0；
2. 轮动金额在「有历史」时会随趋势变化（10→20 → 下一轮 30），这是 v3.51.7 已定口径；
3. 多层兜底不影响「预测 ≠ 事实」：流水仍标 `source:'deal'`、节点仍进 `outlook.nodes`。
