## 1. 真机只读取证（调试桥 + 文件系统，未改任何数据）

| 项 | 实测 |
| --- | --- |
| 目录配置 | `storage.localFilePath = "ftt2-local"`（候选清单另有 `ftt2-files`）；宿主 = TauriTavern（原生存储通道） |
| 目录**写入** | **正常**：`…/_tauritavern/extension-store/ftt2-local/blobs/local/ftt2-local_ftt2-local-char_<scope>.json` 持续更新，字节数与主文件一致 |
| 变量层 / 内存库 | 按设计已停用：localStorage 无 `ftt2_state_*`；`ftt.localDir` → `idbWrites:0` / `idbSkipped:160` |
| 界面/诊断 | **在说谎**：`localFileStatsGet().backend` 恒 `''`；「真实落盘」只写 `kv/local/`；数据管理页不显示目录层；`ftt.loadDiag` 恒报 `present:false` |
| 对齐 / 换目录 | **真缺陷**：目录更新时被旧变量层内容覆盖（回退风险）；换目录不迁移旧目录内容 |

**结论**：用户「是否没有正常读取和写入」的直觉一半对一半错 —— **写是好的**，但**界面与诊断无法证明它**，且「对齐 / 换目录」两个入口确实有覆盖 / 丢失风险。

## 2. 修复（逐条对应）

| # | 事实（旧行为） | 修法 |
| --- | --- | --- |
| ① | `localFileStatsGet()` 用 `Object.assign(事实, stats)` 合并，而 `stats` 自带 `backend:''` → 真实后端被覆盖 | 统计对象**不再持有** `backend`；后端一律 `localFileBackend()` 现算；新增 `lastReadAt` / `lastWriteAt` / `lastChannel` |
| ② | 「真实落盘」写死 `kv/local/` + 占位文件名 | `localFileRealLocation(path, scope)` 返回**两通道**（`blobs/local/` 大信封 · `kv/local/` 小信封）与**真实键名**（`localFileFileKey` = 目录前缀进文件名）；存储页再补「当前角色真实文件」 |
| ③ | 数据管理页在目录模式下看不到目录层 | 新增「状态副本（本地目录）」行（路径 / 最近写入 / 读·写·未命中 / 失败原因 / 真实键名 / 最近读回）；变量层与内存库两行标注**已停用** |
| ④ | `ftt.loadDiag` 恒查 localStorage | 新增 `localLayerReadProbe()`（**按模式**真读目录文件：命中 / 字节 / 信封哈希一致 / 条数 / 时间戳）；`ftt.loadDiag` 改用它 |
| ⑤ | 对齐会把旧的变量层内容写回更新的目录 | 候选源扩到五类（变量 / 内存库 / **当前目录** / **聊天元数据** / **旧目录**），取 `updatedAt` 最新；**目录已最新 → `verified` 只核对**；其余 → 写 → 回读逐字节校验 → 才清旧层 |
| ⑥ | 换目录不迁移旧目录 | `previousPath` 指向的旧目录里更新的一份**迁进新目录**（写 → 回读校验），旧目录文件保留当备份（`moved-dir`） |
| ⑦ | 目录模式仍读聊天元数据 | 目录模式下**不读**聊天元数据（本机只剩「目录 + 服务端」）；关闭后恢复并集（对齐时它仍是候选源） |

## 3. 纪律与边界（如实）

* 目录模式下**记忆数据**只落两层：**本地目录文件 + 服务端文件**；变量层 / 内存库 / 聊天元数据三层**不读不写**（聊天元数据 V2 本就只读不写）；
* 浏览器本地仍保留**可再生成的辅助缓存**（调试日志 / 交互时间线 / 版本清单 / 同步与对账标记，均带体积硬上限）—— 它们不含记忆数据；存储页「停用范围」逐字写明这一点；
* 对齐纪律不变：**先写 → 回读逐字节校验 → 才清旧层**；任何一步失败都不清数据（`A6` 用例锁定）；
* 「目录文件是新是旧」一律以**信封 `updatedAt`** 为判据，不看文件系统时间（避免「刚写空目录就把旧内容当新」）。

## 4. 测试与门禁

* `tests/unit/local-file-mode.test.js` 新增 **D1–D6**（6 项）：统计后端不再被覆盖 / 按模式真读探针 / 四源择优（两参旧行为不变）/ **目录最新不覆盖 + 变量层更新才迁移并清层** / **换目录迁移旧目录内容** / **目录模式不读聊天元数据（关闭后恢复并集对照）**；
* 新增冒烟 `BZ3`（端到端）：目录模式下存储页写出真实后端 + 真实落盘（两通道 + 真实键名）+「变量层 / 内存库 / 聊天元数据已停用」；数据管理页列出目录副本行并把另两层标注已停用；只读探针真读目录文件（命中 / 哈希一致）；
* 全量：**160 文件 / 2481 断言** + 冒烟 **220 项**；静态门禁（含 `docs-facts` 的 C8/C9）全绿。

## 5. 结论

目录模式现在可以**逐项自证**：「存储页 → 后端 / 真实文件 / 读写计数」「数据管理页 → 目录副本行」「调试桥 `ftt.localDir` / `ftt.loadDiag` → 真实键名 + 读回结果」三处同源，且「对齐 / 换目录」两个入口都遵守「取最新、不覆盖、先写后清」。用户要求的「变量 / 内存 / 传统本地存储全部作废」在本版补齐到**聊天元数据**，只留「本地目录 + 服务端」。
