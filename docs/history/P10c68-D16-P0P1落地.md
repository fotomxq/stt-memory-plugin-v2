## 2. L9：为什么「未命中」不等于「路径坏了」

真机取证（`ftt.errors`）：唯一一条 error 级日志就是

```text
载入：本地磁盘目录读不到本机副本 → 已回退浏览器本地存储（该路径已标记为无效）
```

而同一时刻 `ftt.diskFiles` 显示：写 **67 次全成功**、根目录里**确实有**单文件（5,554,193 字节）、`mechanism = browser-opfs`、
`misses = 3`。结论：**读发生得比宿主文件层就绪更早**，旧实现却按「路径坏掉」处理 —— 标记无效 + error 级日志 + 醒目告警，用户每次刷新都撞上。

现在：

* `loadFromLocalDisk({tries, gapMs})`：默认 **2 次**（间隔 250ms，经内核 `timerHooks` 调度 → 测试可替换）；读到 → `localDiskClearInvalid()`；
* 未命中分支分两路：
  * **已知路径不可用**（本会话写过失败 / 已被标记无效）→ 照 v3.28.1 口径：标记 + 醒目告警（用户要求不变）；
  * **纯未命中** → `载入` 级诊断 + **信息级**提示，**不标记无效**（路径没有被证明有问题），台账记 `disk-load-miss-not-invalid`。

## 3. A1：台账的「归属」是证据的一部分

**问题**：`state.processedFloors` 的元素只有 `{f, h}` —— 「这一楼已分析」从未记录**属于哪条聊天**。换聊天后
（角色相同、聊天不同）旧标记会**冒领**新聊天的同号楼层；真机上表现为 8 个标记全越界、`coverFloors = 0`、丢弃留痕 120 条而 95% 与台账无关。

**现在**：写入即带 `{at, ck}`（`recordProcessedFloors` / `markFloorsProcessed` / `rememberDroppedMarks` /
留痕回填 / `migrateProcessedFloorsV170` / `processedDriftGuard` / `reconcileProcessedFloors` / `handleFloorShrink` 八处）；
读取判据 `isFloorProcessed` 与留痕判定 `droppedContentChanged`、留痕回填 `healLedgerFromDropped` 一律**只认本聊天**。

**保守口径（关键）**：任一侧没有 `ck`（legacy 存档、或当前键读不到）→ **按可用处理**。
绝不因为「老标记没有这个字段」把用户的历史台账判废 —— 那正是历史上「突然冒出大量未分析楼层」的成因。

**只读量表**（`ledgerHealth()` → 调试桥 `ftt.ledger.stats` / 面板）：

| 字段 | 含义 |
| --- | --- |
| `marksCrossChat` | 属于**别的聊天**的标记（不再参与本聊天的可读 / 越界统计） |
| `marksNoTimestamp` | 缺 `at` 的标记（legacy 存档） |
| `marksLegacyNoChat` | 缺 `ck` 的标记（同样按可用处理，但如实计数） |
| `droppedCrossChat` / `droppedNoTimestamp` | 丢弃留痕里的对应两项 |
| `chatKey` | 当前聊天标识（用于人工核对） |

## 4. A2：级联 + 一键清理（两条腿）

* **级联（新）**：`core/sweep.js#tombstoneSweep()` 在把消失条目写墓碑的**同一现场**，调用
  `purgeLinksForGoneEntries([{dim, id}…])`（`core/model/rel.js`，纯函数）删掉指向这些 id 的关联行 ——
  证据与墓碑同源，**不会误删「只是暂时读不到」的关联**；
* **一键清理（既有，本批补入口）**：`core/rel-maint.js#cleanInvalidRelLinks` 清孤儿 / 幽灵角色 / 空行 / 非法维度 / 空指向，
  写删除墓碑、幂等；本批在**数据管理页**新增只读统计行 +「🧹 清理无效关联」按钮（二次确认），
  与关系表页「🧹 清理无效关系」是**同一个动作名 → 同一条代码路径**。

## 5. L11：日志环不该被一句话占满

真机取证：环 `300` 条里「存储」**248（83%）**，最近 200 条只有 3 种 action，其中 **166 条**是同一句
「本地磁盘目录：写入并回读校验通过」→ 摘要 / 异常 / 同步类诊断被挤出（与 v3.10.4 修过的「读取占 69%」同族）。

实现：`core/debug-log.js#debugLogPushCoalesced(kind, key, data, {windowMs})` —— 同一 `key` 在窗口内重复时，
**原地改写那条日志**为 `{…, n: 次数, lastAt: 最近, bytes: 累计}`；`debugLogClear()` 复位合并引用表；
`windowMs: 0` / `force: true` = 不合并。宿主侧经 `runtime.dbgLogCoalesced`（未接线 → 退化为普通 `dbgLog`，不丢日志）。
三处高频成功写盘已改用：本地磁盘写盘（key = `local-disk-write|<机制>`）、本机层分片（`shards|<目录>`）、快照链分片（`snap-parts|<目录>`）。
