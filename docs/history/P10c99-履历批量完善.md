## 3. 本轮抓到的两个真问题（如实登记）

1. **原作人物口径被我写反了**：提示词/校验第一版写「原作人物**不得**补剧情前生平」，但真实口径是**允许**（`snapshotResumeCanonFill` 的用途），
   约束只有「**不得晚于当前剧情日期**」。→ `resume-batch` 单测 `B1` 的**正例**当场失败 → 改正提示词、打包标注、UI 文案与拒收原因名（`canon-after-clock`）。
   **单测是唯一发现途径**（静态门禁与冒烟都不会报）。`docs/D38` §2.2 保留了这条辨析注。
2. **满额角色补不进**：第一版把"单轮条数余量"算成 `max - 现有条数`，于是 30/30 的角色**一条也补不进**；
   而个体档的真实语义是「先机械清算 → 再并入 AI 结果」（下一轮继续收敛）。→ 改为只守"单轮每角色 ≤12 条"，与个体档对齐；单测 `C1` 用 31 条的语料锁死（机械段 31 → 30，再并入 1）。

## 6. 未做 / 限制 / 差异（如实登记）

1. **不做跨批续跑**：候选超过上限时**如实截断**并提示，不自动跑第二批（一次点击 = 一次请求 = 一批）；
2. **不读楼层正文**（不调 `aiFeedText`）：依据只有「近期记忆 + 档案 + 现有履历」；没有命中就**不补**（宁缺毋滥）；
3. **不改个体档**：行内「📜 补全 / 修复履历」与 `runResumeRepair` 零变化（只新增共用导出 `resumeClockDate`）；
4. **预览不支持逐角色勾选应用**（沿用「方案 → 全量应用 / 取消」的既有形态）；
5. **真机未人工试用**：需刷新宿主页面后在角色页点一次「📜 批量完善履历」。
