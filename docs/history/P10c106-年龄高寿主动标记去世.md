## 1. 缺口

角色修复的**入列**只有两条口径：「**抽取字数偏少**」（`cfg.repairCharacterMinSize`）+「出生日期异常优先档」；
而**已去世**判定只有**文字证据**一条路（`snapshotDeathVerdict`：本人在场 + 死亡措辞 + 非否定/非第三方）。
→ 一个按剧情日期已**明显高寿**、却**没有一句"他死了"**的普通角色，既不会被标去世，也不会被任何规则处置：
年龄继续涨、每轮 AI 都可能重新分析。用户要求补上这一条。

## 2. 规则（机械段，零 AI；按序判，任一不满足即不标记）

| 序 | 判据 | 不过时 |
| --- | --- | --- |
| 1 | 有名字 / **未标记已去世**（短路，避免反复处理） | `already-marked` |
| 2 | **没有长生者标记**（开关）且档案里**没有长生类措辞**（长生 / 不死 / 精灵 / 妖族 / 修真 / 神明 / 转世 …） | `immortal` / `long-life-words` |
| 3 | 出生日期异常**不是** `future` / `bad-format` / `after-record` | `birth-untrusted` |
| 4 | 年龄**来自真实出生日期**（`snapshotAgeInfo().basis ∈ {story, timeline}`） | `no-birth-date` / `age-not-derived` |
| 5 | **年龄 ≥ 阈值**（`cfg.repairDeceasedAge`，默认 **75**；只到「年」→ **+1**） | `below-threshold` |
| 6 | 年龄**不荒谬**（`overage` 或 ≥ 200 岁） | → **只报告不标记**（`implausible-age`） |
| ✅ | 全过 | → 写 `身份.已去世 = true`（`age-longevity`） |

**两条通道并列、互不替代**：文字证据按 v3.18.0 原口径；年龄规则补「没人写、但按剧情日期已经高寿」这一类。落同一字段、走同一条后续联动。

## 3. 联动与回报（复用既有机制）

- 标后**自动**被「出生日期校正 / 标签补充 / 年龄刷新 / 待修复名单 / AI 名单」跳过（既有 `snapshotRepairSkip`），年龄由既有机制锁定 —— 即用户要的「避免反复调取处理」；
- 机械段返回 **`ageMarked` / `ageReported` / `ageThreshold` / `deceasedByEvidence`**（文字证据与年龄**分列**）；
- 通知加「年龄规则（≥ N 岁且未标长生者）标记去世 M 名」；调试日志 kind `修复` 记逐名明细（含年龄与证据句）；
- `characterAgeScan()` 每行加 `longevity` **只读干跑**读数。

## 4. 配置

`cfg.repairDeceasedAge`：默认 **75** 岁（中文「高寿」常见门槛 70–80 的中值）；设定 → 投喂范围 → **🧑 角色修复** 组可改；**`0` = 关闭规则**。

## 5. 门禁两次抓到我（如实登记）

1. **体量棘轮**：`core/config.js` 加这一个键时**顶到上限**（+44 > +40）→ 把**角色修复族**与**履历**两组默认键外移到
   `core/config-character.js` / `core/config-resume.js`（`...CHARACTER_DEFAULTS` / `...RESUME_DEFAULTS` **原位置展开**，键/值/顺序逐字不变）→ `config.js` 回到 **+31**，**不上调基线**；
2. **V1 平价测试**：`character-repair-golden` 的 V1 场景里角色乙按锚点（2020-06-01）算出 **120 岁** → 规则**真的会标记他** → C3/P1/P2 变红。
   判定：**规则行为是对的**（120 岁 + 无长生标记 = 明确超出平均高寿），而该档职责是「V1 逐字段平价」→ 按该档既有惯例（v3.22.0 长生者 / v3.45.5 履历同款）**显式关规则**并注明「有意偏离 V1，专档覆盖」；
3. **顺带修真缺陷**：`markDeceasedByEvidence` 曾独立算阈值（`Math.max(1, …)`）→ `cfg.repairDeceasedAge = 0` 被兜回 75 = **"设定里关掉了却仍在标记"** → 统一为「`0` = 关闭」（`ageOff`）。
