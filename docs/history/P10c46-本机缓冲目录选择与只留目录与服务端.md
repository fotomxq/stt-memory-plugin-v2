## 1. 「选择目录」（原 input 原样保留）

| 入口 | 行为 | 代码 |
| --- | --- | --- |
| 📁 选择目录…（折叠块） | 候选 = **预设**（`ftt2-files` / `ftt2-local`）+ **用过的目录** + **宿主可枚举到的目录**；点一下即采用 | `localFileDirCandidates()` · `localFileDirUse` |
| ➕ 新建并使用 | 按输入框内容新建：**写探针文件 → 回读逐字节校验 → 删除探针** → 通过才落配置 | `localFileProbeDir()` · `localFileDirCreate` |
| 📂 从系统选择文件夹… | `showDirectoryPicker()` 优先（**空文件夹也能拿到名字**）；不可用则 `<input webkitdirectory>`（**只在含文件时**返回路径 → 空文件夹如实回报 `empty-folder`） | `ui/file-io.js#pickDirectoryName()` · `localFileDirSystem` |
| 🔍 扫描宿主已有目录 | **仅当**宿主 store 提供 `listNamespaces` / `listDirs` 时才渲染按钮，否则页面直接写「宿主未提供目录枚举（可手动输入）」 | `ttDirListCapability()` · `ttListNamespaces()` |
| ✅ 校验当前目录 | 对当前目录写探针并回读校验，结果带上**真实落盘位置** | `localFileDirProbe` |

### 1.1 为什么「选择目录」不能是任意磁盘路径（如实，不美化）

* `api.extension.store` 的**命名空间只允许 `[A-Za-z0-9_.-]`**（官方 Public Contract），盘符与绝对路径**传不进去**；
* 酒馆文件通道也只在 `user/files/` 之下；
* 因此「目录」= **宿主数据目录内的相对目录名**，页面上的「真实落盘」行直接写出：
  `_tauritavern/extension-store/<命名空间>/kv/local/ftt2-local-＜角色＞.json`（原生）/ `user/files/<目录>/…`（酒馆文件通道）；
* 「从系统选择文件夹」只取**文件夹名**，并在提示里写明这是宿主限制的结果（不假装能选任意路径）。

### 1.2 候选清单为什么放配置而不是 localStorage

目录模式下一旦开启，变量层**整体停用**（见 §2）。把「用过的目录」放进 `localStorage` 会出现**自相矛盾**：
候选来源依赖一个用户明确要求停用的层。故新键 `cfg.storage.localFileDirs`（上限 8，最近在前，去重），落 ST 扩展设置。

## 2. 设置了本地目录 → 不再使用内存与变量存储

| 层 | 目录模式（`storage.localFilePath` 非空） | 留空（不开启） |
| --- | --- | --- |
| 变量层（`localStorage`，键 `ftt2_state_<scope>`） | **不写也不读** | 照旧 |
| 内存库（IndexedDB / `localforage`） | **不写也不读**（保存流水线第 ⑤ 步整体跳过；载入路径不调用 `loadFromIndexedDB`） | 照旧 |
| 本地目录文件 | 本机层**唯一真相** | —— |
| 服务端记忆文件（+ 分片 / 备份 / 快照 / 清单） | 照旧（权威基准不变） | 照旧 |

三处判据（都可被测试直接观测）：

| 位置 | 改动 |
| --- | --- |
| `adapters/store.js` 保存 ④ | 目录写失败**不再回退变量层**（旧行为会把数据写回用户要求停用的层）：如实回报 `skipped:'write-failed'` + 原因「本地模式不回退变量层」 + 调试日志/读取台账留痕 |
| `adapters/store.js` 保存 ⑤ | `localViaFile` 为真 → **整段跳过** IndexedDB 写，`localStats.idbSkipped` 计数 |
| `index.js#loadMemoryState` | 目录模式 → **只读目录文件**（`loadFromLocalFile`），不调 `loadFromLocalStorage()` / `loadFromIndexedDB()`，并记一条「本机层停用」台账 |

### 2.1 迁移升级为「三层对齐」（先写后清，失败不清数据）

| 方向 | 源 | 步骤 |
| --- | --- | --- |
| 开启（路径非空） | **变量层与内存库中较新的那份**（`pickLocalSource` 按 `payload.updatedAt` 取新；坏信封不参与比较） | 写目录 → **回读逐字节校验** → 才清**两层**（变量键 + 内存库副本）→ 记住目录 |
| 关闭（路径清空） | 目录文件 | 两层都空时 → 内容**迁回变量层与内存库**（目录文件保留当备份，不删） |

`switchLocalLayer()` 的返回值新增 `from`（`variable` / `idb`）与 `idbCleared`，面板与动作提示如实展示来源。

### 2.2 连带修正

* 「校验并修复」（`adapters/sync.js#readLocalEnvelope`）在目录模式下改读**目录文件** —— 否则本机层这一份候选永远看不到；
* 新增只读调试桥方法 **`ftt.localDir`**（模式 / 目录 / 真实落盘 / 候选 / 宿主枚举能力 / 内存库是否停用 / 统计）：只读方法 46 → **47**；
* 「向量缓存」（`adapters/vector-cache.js`，IndexedDB `FTTMemoryVectorCache`）**不在本批停用范围**：它是内容哈希缓存、不属记忆存储层（用户要求的是「内存/变量存储」）；
* **停用范围**如实写进界面与文档：停的是**记忆数据**的变量层与内存库；调试日志 / 同步标记 / 版本清单缓存等辅助键体积有硬上限（调试日志 0.6M 字符），仍留浏览器本地 —— 把它们也搬进目录属另一件事，未在本批做。

## 3. 顺带修掉一个真实缺陷：命名空间碰撞

**事实**：`localFileNs()` 旧实现把非法字符一律转 `_` → 「记忆缓冲」与「剧情缓冲」**双双变成 `____`**，
两个不同目录写进**同一个命名空间**（真实后果：互相覆盖）。

**修法**：归一**丢过信息**时补一个**路径短哈希**（FNV-1a 32 位 → 6 位 36 进制，无依赖、跨会话稳定）：
`记忆缓冲` → `____` → 修剪尾下划线后 `ftt2-local-<hash>`。旧命名空间仍可**只读**命中
（`localFileNsLegacy()`；`localFileRead` 回退读一次、`localFileDelete` 两个命名空间都删），老数据不丢。
