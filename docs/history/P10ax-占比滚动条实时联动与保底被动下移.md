# P10ax · 占比滚动条实时联动 + 保底被动下移（v2.85.0）

> 文档版本：v1.0 ｜ 日期：2026-09-27 ｜ 状态：生效（v2.85.0）
> 触发（用户原话）：
> 1. 「各大类百分比滚动条**没有联动**，调节一个其他应该**等比例变化**。」
> 2. 「存储总上限的**保底数据应该被动联动**，如情节调节后，如果**保底数据高于该数字则自动下移数字**。」

## 1. 修复前的两条事实（用户为什么看到「没联动」）

| # | 现象 | 根因 |
| --- | --- | --- |
| ① | 拖动一条占比滚动条，**其余滚动条纹丝不动**，松手（`change`）后才整体跳一下 | v2.84.0 的 `input` 委托**只刷新被拖动那条的读数**（`[data-ftt-share-out]`），联动与落盘都留到松手；用户看到的是「逐帧没反应」 |
| ② | 把「情节」占比调小后，**保底数字仍然很大**，上限被保底顶住（`有效上限 = max(保底, 占比结果)`） | 上一版口径里保底**兜住**上限：占比算出 90 条、保底 500 条 → 实际上限 500 条。用户期望的是**占比推导值是权威**，保底应当跟着**降下来** |

## 2. 改动一：拖动中**实时联动**（等比、无漂移）

| 项 | 口径 |
| --- | --- |
| 纯函数 | 新增 `core/ingest.js#allotStoreShares(raw, dim, value)` —— 与提交**完全同源**的配平算法（被拖动项权威、其余按原比例缩放、四舍五入、余数给最大项），**不改任何配置** |
| 基准占比 | 本次拖动**首次** `input` 时快照（`ui/panel.js#shareDrag = { el, dim, base }`），后续每帧都以它为比例基准 → **不会**「在已改过的值上再缩放」而累计漂移；松手（`change`）或换控件即清空 |
| 联动范围 | 其余 9 条滚动条的 `value`、每行读数「`xx% · ≈N 条`」、每行「默认 x% · 保底 M 条」、合计行（`data-ftt-share-sum`）、以及上方「保底」输入框的数字，**同一帧内**一起变 |
| 落盘时机 | 拖动中**一个字节都不写配置**；松手 `change` → 面板动作 `storeShare` → 归一表写回 + 落盘 + 重绘（冒烟 BS2 断言拖动中 `cfg.storeShare` 未变） |
| 总上限同步 | 拖动「存储总上限」滚动条时，占比不变但各维**条数与保底文字**当场跟着变（`shareTotalInput`），松手后落盘并触保底夹取 |

> **踩到的坑（已修）**：首版把「被拖动项的新值」先写进基准表再调 `allotStoreShares` —— 基准表因此不足 100，
> 归一化把差额补给了最大项，比例当场失真（实测「记忆」被抬到 35%）。现在基准表**恒为合计 100 的完整表**
> （被拖项在表里留旧值），`allotStoreShares` 只按其余维度的比例缩放。

## 3. 改动二：保底**被动下移**（上限权威、只降不升）

| 项 | 口径 |
| --- | --- |
| 有效上限 | **= 四舍五入(总上限 × 占比 ÷ 100)**（不再被保底顶上去）——`storeCapRaw` / `storeCapFor` |
| 保底（对外） | `storeMinFor(dim) = min(配置保底, 有效上限)` —— 展示与「不得跌破」判定都用这个值 |
| 落盘下移 | `clampStoreFloors(shares?)`：把高于上限的保底**写回** `cfg.storeMin<Dim>`（**只降不升**），返回 `[{dim,label,from,to}]` 供 UI 如实提示 |
| 触发点 | ① 松手提交占比（`storeShare` 动作，用**新占比**判定）② 改「存储总上限」③ 手填「保底」④ **启动自愈** —— `adapters/config-store.js#loadKernelCfg` 载入后跑一次，历史存档里的越界保底自动跟到上限之下 |
| 提示 | 面板 note：「已调整「情节」占比为 3%，其余按比例联动（合计 100%）；**保底已下移：情节 5000→90**」；行尾文字标注「（已随上限下移）」 |
| 幂等 | 保底已等于上限时不再写、不再报（`clampStoreFloors` 返回空数组） |
| 兼容口径 | `storeTotalMax` 为 0 / 缺键时**完全不碰保底**，上限仍是 V1 的 `max(storeMax*, 保底)` —— 老存档与黄金样本逐字一致 |

## 5. 未做与边界

| 项 | 说明 |
| --- | --- |
| 不改裁剪算法 | `enforceDimCaps()` 的排序与保护口径（重要度保护 / 调用次数 / 新者优先）一字未动 |
| 保底**不回升** | 只降不升：占比调回原值也不会把保底自动加回去（不臆造用户没设定的值）；用户可手填恢复 |
| 无硬保底的维度 | 场景 / 计划 / 悬念 / 名册 / 传言默认保底 0，永不触发下移 |
| 其余百分比控件 | 「其余滚动条**等比**联动」只属于「各大类占比」这一组（它们之间有 100% 的合计约束）；其余 29 项百分比控件彼此独立，不参与联动 |
| 拖动中的读数口径 | 拖动中显示的条数按**预览占比**现算（与提交后一致）；拖动中不落盘，故中途关闭面板不会改配置 |
