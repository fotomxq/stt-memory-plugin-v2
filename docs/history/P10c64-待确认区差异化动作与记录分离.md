## 1. 核对出的 BUG（用户报的「点击会报错」）

| # | 缺陷 | 根因 | 修复 |
| --- | --- | --- | --- |
| ① | 点「✅ 全部已确认」→ 弹「操作未完成：unknown-action」，什么都不会发生 | `resolveConflicts`（以及总览横幅的 `goStorageConflicts`）只在**标记里**出现，**既没进 `SYNC_ACTIONS`、也没有处理分支** → 面板分发落到 `else { result = { ok:false, reason:'unknown-action' } }` → 统一收尾弹错误 | `resolveConflicts` / `conflictAct` 登记进 `SYNC_ACTIONS` 并在 `syncAction` 实现；`goStorageConflicts` 作为**面板导航**动作在 `panel.js` 实现（跳「设定 → 存储」） |
| ② | 单测 A5 是**假绿**：`await A('A5 …', (async () => {…})(), '')` 里断言条件是 Promise（`!!Promise === true`）→ 永远通过，缺陷被掩盖 | 该文件用的 `A` 没做 thenable 防呆 | 改为**真断言**（先算出布尔再断言），并覆盖四种动作路径 |

## 2. 重新设计：待确认（decide）与记录（log）分离

```text
noteConflict({kind, detail, count})
   ├─ mode:'decide'  →  待确认清单（计入徽标计数、上限 50 条、带**该类自己的动作**）
   └─ mode:'log'     →  只读记录区（**不计入**待确认计数、上限 20 条）+ 同时写一条调试日志
```

**类别登记表**（`core/conflicts.js#CONFLICT_KINDS`）：

| 类别 | 语义 | 差异化动作 |
| --- | --- | --- |
| `跨端合并冲突` | **待确认** | 🔀 重新同步（并集）· ✅ 知道了 |
| `并集自检异常` | **待确认** | 🔍 校验并修复存储 · ✅ 知道了 |
| `跨端分歧（已自动合并）` | 记录 | ——（已自动处理完，只是通知） |
| `删楼` | 记录 | ——（完成通知：备份文件名 + 保留条数） |
| `楼层收缩` | 记录 | ——（台账已归位） |
| 未登记类别 | **待确认**（保守） | ✅ 知道了（绝不静默吞掉未知情况） |

- **动作语义**：`dismiss` = 标记已确认（只清提示、不动数据）；`resync` = 走存储页「立即同步（含备份）」后再销账；
  `verify` = 走存储页「校验并修复」后再销账。动作失败 → **保留**待确认项并如实回报（不假装处理过）。
- **动作白名单**：每类只允许自己登记的动作（如「并集自检异常」不接受 `resync`）→ 请求被拒且条目保留。
- **批量**：「✅ 全部已确认（N）」只清**待确认**清单；只读记录原样保留（提示里写明）。
- **出口**：总览横幅只显示**待确认**计数（记录不打扰用户）；「去处理」跳「设定 → 存储」；记录同时进调试日志（`同步 · 记录（无需确认）`）。

## 5. 兼容与风险

- **数据零改动**：待确认项与记录都只存在 ST 扩展设置（`syncConflicts` / `syncConflictLog`），不进行李模型（`DATA_VERSION` 不变）。
- **语义变更（有意）**：删楼 / 楼层收缩 / 跨端分歧（已自动合并）从「待确认」降为「记录」→ 徽标计数会变小（用户不再被无需决策的通知打扰）；
  若某类其实需要人决定，在 `CONFLICT_KINDS` 里把 `mode` 改为 `decide` 并登记动作即可（未知类别默认仍是 `decide`，不会丢事）。
- **回退**：清空 `syncConflicts` 即清空待确认；记录可随设置自然滚动（上限 20 类）。
