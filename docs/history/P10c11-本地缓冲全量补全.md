## 1. 核对：原来漏了什么

`ui/buffer-manage.js`（v2.54.0）只列了 **3 项缓存/日志**：版本清单缓存 · 调试日志 · 交互追踪简报。
而插件在浏览器本机真正留下的东西有 **13 类**（按键前缀清点，见下）。**最关键的缺口是记忆数据自己的本机副本**：

| 缺口 | 键 | 为什么重要 |
| --- | --- | --- |
| 状态副本（浏览器本地变量） | `ftt2_state_<scope>` | 本机第一个副本；v3.1.0 起还有字符预算判定（超预算会跳过写入） |
| 内存库副本（IndexedDB） | `ftt2_state_<scope>`（`localforage`） | 本机第二个副本（v3.0.23 才被载入路径读取） |
| **其它角色的本机副本** | `ftt2_state_<其它 scope>` | 换过角色 / 用过多个存档后**会一直留在本机**，用户完全看不到 |
| 命名缓存 | `ftt2_FileSlug_*` · `ftt2_ArchiveName_*` | 文件名 / 归档名解析缓存 |
| 同步与对账标记 | `ftt2_RemoteStateHash_*` · `ftt2_RemoteSnapSig_*` · `ftt2_LastPushSig_*` · `ftt2_SyncGate_*` | 对账门控；陈旧标记会误导同步判定 |
| 同步日志（本机） | `ftt2_SyncLog_*` | 上限 30 条 |
| V1 遗留本机数据 | `SPreset_FTTMemory_char:*` / `_FileSlug_` / `_FileNames_` / `_ArchiveName_` / `Config` | **V1 导入源**：`adapters/import-v1.js` 靠它迁移 |

（另有：调试日志 `SPreset_FTTMemoryDebug`、追踪简报 `SPreset_FTTMemoryTrace`、版本清单缓存 `fttAboutJson` —— 这三项原有；
向量缓存与读取台账 / 时钟追踪在别的页面或内存里，也一并收进本分节。）

## 2. 改了什么

### 2.1 清点（单一来源）

`adapters/store.js` 新增：

- `LOCAL_KEY_GROUPS`：**插件自有本机键的前缀表**（键 → 归属模块），一个键只归一个分组；
- `localKeyStats()`：同步清点每个分组的 `{keys:[{key, chars, bytes, current}], count, bytes, chars}`，
  并把 `state` 分成 **当前作用域** 与 **其它作用域**；
- `idbCopyStats()` / `localCopyStats()`：IndexedDB 副本（`localforage.keys()`）与「当前角色本机副本」汇总
  （含 `chars` / 条数 / 信封 `updatedAt` / 预算）；
- `removeLocalKeys(keys)`：通用删除（失败不抛，返回 `{removed, failed}`）。

`ui/buffer-manage.js#bufferStats()` 把上述清点与既有三项合并，返回 `copy` + `groups`（**全部现算**，
遵守 v2.54.0「数字必须来自真实持久层」的硬要求）。

### 2.2 清理（每项独立）

| 动作 | 清理范围 | 确认 |
| --- | --- | --- |
| `localCopyClear` | 当前角色的 `localStorage` 信封 | ✅ 二次确认 |
| `idbCopyClear` | 当前角色的 `IndexedDB` 副本 | ✅ 二次确认 |
| `localCopyClearOthers` | **其它角色**的本机副本（当前角色不动） | ✅ 二次确认 |
| `nameCacheClear` | 命名缓存（文件名 / 归档名） | — |
| `syncMarkClear` | 同步与对账标记 | — |
| `v1LegacyClear` | V1 遗留本机数据（导入源） | ✅ 二次确认 |
| 复用既有 | `dbgClear` · `dbgTraceClear` · `readLedgerClear` · `clockTraceClear` · `vectorCacheClear` · `aboutClearCache` · `syncLogClear` | 按既有口径 |

三条「本机数据副本」清理都进 `DANGER_ACTION_PROMPTS`（`docs/D9` U4 / C7）：取消 = 零副作用；
文案讲清「只删本机、服务端记忆文件不受影响；若从未上传成功则等于丢弃未上传改动」。

### 2.3 呈现

数据管理页分两组渲染，每行「名称：真实统计 [🧹 清除]」（无数据禁用）：

```text
🗂 本地缓冲  共约 X
🧱 本机数据副本   记忆数据在本机的副本
  · 状态副本（浏览器本地变量）：1.0M 字符 / 1.8M（预算）· 约 1.4 MB · 12 条 · 更新 …
  · 内存库副本（IndexedDB）：约 1.4 MB
  · 其它角色的本机副本：3 个键 · 约 2.1 MB          ← 仅有其它作用域时出现
🧰 缓存与日志     排障与加速用的本机缓存
  · 调试日志 · 交互追踪简报 · 读取台账 · 时钟取值追踪 · 向量缓存 · 版本清单缓存 · 命名缓存 · 同步与对账标记 · 同步日志
🧬 V1 遗留本机数据                                 ← 仅有 V1 键时出现
  · V1 遗留数据（导入源）：3 个键 · 约 12 KB        ← 明确警告：清掉后无法再用「⬆ 导入 V1」
```

IndexedDB 统计是**异步**的（`localforage.keys()`）：页面先渲染 `[data-ftt-idb-copy]` 占位，
`refreshLocalCopy()` 取到后**就地更新占位文本**（`paintCopySpans()`；无 DOM 时只更新模块缓存，下次渲染即显示真值），
清理动作完成后也会自动再刷一次 —— 不触发整页重绘、不引入循环依赖。

## 4. 兼容与回退 / 风险

- **不改数据模型**：只新增本机键的**清点与清理**；`bufferStats()` 的既有字段（`versionList` / `debugLog` / `trace` / `totalBytes` / `any`）保持原名，旧调用点不受影响。
- **服务端安全**：所有新动作只删 `localStorage` 键与 IndexedDB 副本；服务端记忆文件 / 分片 / 快照 / 清单一律不碰（冒烟 `BH9` 显式断言）。
- **误删兜底**：三项「本机数据副本」清理都有二次确认；V1 遗留单独警示；「其它角色的本机副本」只删非当前作用域。
- **回退**：新动作是独立分支，去掉即回到 v3.2.0 的三行分节（清点函数可只读保留）。
- **未核实**：真机 `localforage.keys()` 在大库下的耗时未实测（当前实现只在页面打开 / 清理后各取一次）。
