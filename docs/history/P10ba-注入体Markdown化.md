## 1. 改了什么

| 位置 | v2.87.0（旧） | v2.88.0（新） |

| 外框（`host/inject.js#wrapInjectText`） | `【FTT记忆注入】…` + 「区块标记（[当前状态] / …）」 | `# FTT 记忆注入` + `> …` 引用行 + 「区块标题（`## 当前状态` / …）」 |

**内部逻辑键不变**：预算分配 / 排序 / 诊断 / 注入自查仍以 `[区块]` 字符串为键（`cats[].head`），渲染时才经 `mdHeadOf()` 转成 Markdown —— 这样「哪些条目进注入」的判定与 V1 完全一致，只有呈现形态变化。

## 2. 关键设计：**预算按「内容」计**（Markdown 标记不挤占预算）

Markdown 会引入额外字符（`## ` / `> 说明：` / `**` / `- ` / 二级缩进）。若按**渲染后长度**计费，同样的内容会比 V1：
① 少注入若干条目；② 约束段尾部被挤掉（实测：约束段末尾总括句 `（其余约束从略：…）` 丢失）。

因此新增 `core/recall.js#mdCostOf()`（去标记后的内容长度），**所有预算判定统一用它**：
- 条目准入：`inc = mdCostOf(标题) + 1 + mdCostOf(条目) + …`；
- 约束段留白：`room = budget - mdCostOf(bodyText) - 2`；
- 约束段裁剪：**逐行丢弃**直到 `mdCostOf ≤ room`（保留「绝不切半句」的既有语义）。

于是：**内容层面的注入集合与 V1 逐条一致**（黄金样本 `recall-golden` R10–R12 以「归一化后内容一致 + 断言 Markdown 外形」校验），渲染层面全部是 Markdown。

## 3. 提示词同步（用户强调「确保一致性」）

`PROMPT_TEMPLATES_V2.injectGuide`（记忆使用说明，注入体外框的「可配置使用说明」段）逐处同步：

| 旧写法 | 新写法 |
| --- | --- |
| 「不得输出任何 `[区块]` 标记」 | 「**不得输出任何 Markdown 标题（`## …`）或区块名**」 |
| 「一、各区块的定义…」 | 「一、各小节（Markdown 标题）的定义…（下方 `## 名称` 与注入体的小节标题一一对应）」 |
| `[当前状态]：…` … `[概念]：…`（13 条） | `## 当前状态（`- **日期** / …`）：…` … `## 概念：…`（13 条，逐条对应） |
| 「以【注入约束】段为准…」 | 「以 `## 注入约束` 小节为准…」 |
| 正文里引用 `[计划]` / `[悬念]` / `[平行事件]` / `[传言]` / `[状态记录]` / `[概念]` / `[场景地点]` / `[角色档案]` | 一律改为 `## 计划` / … （与注入体一致） |

> 一致性由新增单测 `tests/unit/inject-markdown.test.js#D1/D2` 强制：**注入体出现的小节名，必须在提示词里有对应定义**；且提示词里不得残留旧的 `[区块]` 写法。
