## 1. 问题一：货币根本没注入成功

### 1.1 核对（逐层收敛）

| # | 步骤 | 实测结果 |
| --- | --- | --- |
| 1 | 先确认「正常路径」是否可用 | **可用**：主角名下的货币会以 `## 货币` 区块恒定注入（`李瑶·黄金 120 两`） |
| 2 | 再压「预算」变量 | **不是预算问题**：`charBudget` 从 8000 压到 1200，货币区块始终在（轮转分配给每类保底） |
| 3 | 试「脏数据」 | **命中**：货币条目的 `history` 里放一个 `null` → 注入体构建抛 `TypeError: Cannot read properties of null (reading 'date')` |
| 4 | 定位抛点 | `core/recall.js` 货币区块 `hist.map(f => f.date …)` —— **直接读元素字段**，未判空 |
| 5 | 查后果为何是「全没注入」 | **整个注入体构建共用一个 `try`** → `catch (e) { warn('本地召回失败', e); return ''; }` → **返回空串**。实测：`history:[null]` → 正文长度 **0**（货币**和其它全部大类**一起消失） |
| 6 | 脏数据从哪来 | `normalizeMoneyHistory` / `mergeMoneyHistory` **本身判空** → `null` 来自**绕过归一化的路径**（导入 / 早期版本写入 / 手工编辑），一旦落库就长期存在 |

**结论**：用户看到的是「货币没注入」，实际是「**因为一条货币脏数据，整份记忆注入都没了**」—— 这也是它一直没被发现的原因（症状指向 A，根因在 B）。

### 1.2 修复（三层，缺一不可）

| # | 落点 | 改动 | 为什么必须 |
| --- | --- | --- | --- |
| ① | `core/recall.js` 货币区块 | **逐条清洗**：`filter(f => f && typeof f === 'object')`；金额/收支走 `Number(...)` 兜底 | 坏元素只影响那一条的「近期」尾注，**行本身照常注入** |
| ② | 同上 | **区块级隔离**：货币区块自兜错 + `warn('货币区块注入失败（已跳过该区块，其余照常）')` | 一条坏数据**只丢货币**，其它大类照常（此前是「一条坏 → 全没」） |
| ③ | `diagnose` 自查 | `injected.currencies` / `candidates.currencies` = 「**看到 N / 注入 M**」 | 「归属不在主角/标定名单」这种**静默跳过**从此可诊断（此前货币**不在自查表里**，用户无从核对） |

**口径未变**：「默认只记主角的货币；其他角色仅在被提及/在场时列出」**保持**（`docs/D36` 之外的既有裁决）。
变的只有两点：**坏数据不再毁掉全部**、**为什么没注入现在看得见**。

### 1.3 未做（如实登记）

* **其余大类未逐块隔离**：本轮只给「货币区块」加了 try/catch。其它大类同样存在「换个字段名就能同类触发」的风险
  —— 已登记为待办（`docs/D17` U231 的处置栏），建议后续版本做**统一的逐块隔离**（每类一个 try/catch + 计数），
  这样任何一类脏数据都只会降级它自己。

## 2. 问题二：货币融合「明明可以融合却被忽略」

### 2.1 复现（用真实内核函数）

```text
打包：金子(两) / 赤条金(条) / 黄金(两)     ← 同一物的不同叫法
AI 提议：一组 {金子, 赤条金, 黄金}          （canonical = 黄金）
旧结果：groups = 0 · rejected = [{members:[全部三条], reasons:['unit-conflict']}]
```

→ **整组被拒**，于是**同单位的金子与黄金也没合并**。用户所说的「明明可以融合却被忽略」正是这个。

### 2.2 口径修正（细化，不推翻）

| 口径 | 处理 |
| --- | --- |
| **「禁凭空换算」不变** | 不同单位**仍不合并**（不臆造「1 条 = ? 两」的换算） |
| 同单位子组 **≥2 条** | **照常合并**（求和只在同单位之间；`key` 追加单位避免与其它桶撞签名）→ `金子 + 黄金` 合成 **1 条 = 130 两** |
| 单条子组 | **只报告不合并**（进 `keep`，原因写明「同组内单位与其它条目不同（不可凭空换算）→ 只报告、不合并」） |
| 透明记账 | `reasons['unit-split']`（发生过拆分）· `reasons['unit-split-singleton']`（单条子组）→ 预览里看得见 |
| 附带 | `keep` 去重（避免与 AI 的 `keep` 列表重复登记同一条） |
