## 1. 缺陷与根因

用户点「📂 选择文件夹…」后，**文件确实写进了选中的文件夹**，但**路径框是空的** → 看起来「没选上」，只能手工把路径敲进去。

根因（两件事叠在一起）：

| # | 事实 | 后果 |
| --- | --- | --- |
| ① | 浏览器原生文件夹选择器（File System Access 的 `showDirectoryPicker`）出于隐私**不暴露绝对路径**，只给一个目录句柄 | 拿不到可写进配置的「完整路径」 |
| ② | v3.33.0 的取舍是「**只有真路径才写进路径框**」，句柄场景返回 `path:''` | 路径框空白；用户以为没选上 → **人工填写**（而插件其实已经在用那个文件夹了） |

而真路径只有在**宿主系统对话框**（TauriTavern 的 `plugin:dialog|open`）或宿主接口可用时才有 —— 纯浏览器 / 某些宿主上只能走句柄那条路。

## 2. 修复：句柄标记（`@handle/<文件夹名>`）

选中后把**句柄标记**写进路径框（也就是配置项 `storage.localDiskDir`）：

```text
📂 选择文件夹…  →  宿主系统对话框（真路径 D:\… ，跨刷新有效）
                →  浏览器原生选择器（**句柄**）→ 路径框填入 `@handle/<文件夹名>`
                     · 本插件认得它 = 「写入本会话选中的那个文件夹」（真文件，无需宿主文件 API）
                     · 框里立刻有可见、可复制的值 → **不再需要人工填写**
                     · 刷新后句柄失效 → 如实提示重选（绝不假装仍可用）
                →  宿主接口（真路径）
```

| 环节 | 口径 |
| --- | --- |
| 路径形态 | 新增形态 `handle`（与 `windows-abs` / `posix-abs` / `relative` / `empty` 并列）；**绝不**当作相对目录名解析到宿主应用数据目录 |
| 目录解析 | `localDiskResolveDir('@handle/x')` → 原样返回（`resolved:false` + `handleMode:true`）；`effectiveDir()` 因此不会把它拼成 `$APPLOCALDATA/...` |
| 开关判据 | `localDiskOn()`：句柄在 → 开启；**只有标记但句柄已失效** → 关闭（干净回退浏览器本机层，**不**每次保存都失败告警） |
| 校验 | `localDiskProbeDir('@handle/x')` 走**句柄探针**（写 → 回读逐字节 → 删自己的探针文件）；句柄失效 → `handle-lost`，如实报错 |
| 写入 | 与修复前一致：句柄可用时**句柄优先**（真文件写进该文件夹）；单文件副本 / 结构化分片 / 辅助数据都照旧 |
| 界面 | 「完整路径」行改为「路径：`@handle/<名>`（<文件夹名>（浏览器选中的文件夹 · 绝对路径不可见 · 本会话内直接写入该文件夹））」；句柄失效 → 红字「句柄已失效（刷新页面后需重新『📂 选择文件夹…』，或改成绝对路径 / 只填一个目录名）」；顶部提示写明「点『📂 选择文件夹…』会**自动把路径填进来**（无需手工输入）」 |
| 真路径优先 | 宿主系统对话框 / 宿主接口仍**优先**：能拿到绝对路径时照旧写绝对路径（跨刷新有效） |

## 4. 兼容与风险

- **兼容**：绝对路径与「只填一个目录名」两条老路径**行为完全不变**；句柄标记只由「📂 选择文件夹…」写入，用户手敲一个 `@handle/…` 也等同于「用本会话句柄」（手敲但没选过 → `localDiskOn()` 为假 → 干净回退并提示重选）。
- **跨刷新**：句柄是**会话级**的（浏览器安全限制，无法持久化）→ 刷新后必须重选；这是浏览器 API 的硬边界，界面已如实说明（不假装可用）。
- **隐私**：浏览器**不会**把绝对路径交给我们，因此 `@handle/<名>` 是能给出的最完整信息；想跨刷新请用宿主系统对话框（真路径）或只填目录名（落到宿主应用数据目录）。
- **回退**：清空路径框即关闭本机磁盘目录，回到浏览器变量层 + 内存库（与修复前一致）。
