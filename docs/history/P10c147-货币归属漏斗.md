# P10c147 · 货币归属漏斗（程序化 · 不经 AI）（v3.51.6）

> 文档版本：v1.0 ｜ 日期：2026-10-24 ｜ 状态：生效（v3.51.6）
> 用户要求（原话）：「货币需支持程序化的漏斗，AI可能将其他人的货币分析进来，但如果主体不在主角或指定人员时，应直接舍弃。」
> 关联：`core/model/money.js` · `core/ingest.js` · `core/config.js` · `ui/settings-pages.js` · `docs/D53` §3.5

## 1. 为什么需要漏斗

AI 抽取 `currencies` 时，正文里出现「谁掏出多少钱」就会被分析成一条货币记录 —— 但**主体可能是路人 / 敌方 / 群众**。
这类条目会污染货币总览（条数虚高、`storeShare` 被占、快速记账选不中主角），且**跨端**还会把别人的私房钱同步过来。

## 2. 漏斗（程序化，判定完全确定）

新增 `core/model/money.js#currencyOwnerAllowed(owner)`：主体（`owner`）满足任一条件才放行：
1. 与**主角**名相等或互相包含（`defaultCurrencyOwner()`：主角档案名 / 带「主角」标签的档案 / 宿主当前角色；都无则回落「主角」）；
2. 命中**指定人员**名单 `cfg.currencyTrackedRoles`（货币页「👥 指定角色」标定，判定与既有 `isTrackedCurrencyOwner` 同口径：去空白 + 忽略大小写 + 互相包含）。

**接入点**：`core/ingest.js` 的「AI 货币增量入库」处（`add` 与 `update` 都过）——
不合规者**直接 `continue`**（不入库、不合并、不写流水），并汇总一条调试摘要（舍弃条数 + 名单 + 主角名）便于核对。

## 3. 三个刻意的边界（fail-safe）

| # | 边界 | 理由 |
| --- | --- | --- |
| 1 | **未配置即放行**：既没有主角名、也没有指定人员时，漏斗**不武装**（`currencyFunnelArmed()` 为假）→ 全部保留 | 否则新用户第一次分析就把所有货币丢光；同时不做静默行为，调试摘要会提示去设定 |
| 2 | **只管 AI 增量**：面板 / 编辑器 / 快速记账的手工写入不受影响 | 用户手工录入即用户意志（`D28` B13 ②） |
| 3 | **不清理已有数据**：存档里"其他人"的货币**不删**（漏斗只拦新入库） | 语义数据不自动移除（`D28` B12）；要清理由用户手动删（删除会级联删流水） |

## 4. 开关

`cfg.currencyFunnel`（默认 **true**）：设定 → 存储页「货币归属漏斗：AI 抽取的货币若主体不是主角/指定人员则直接舍弃」。
关闭后行为回到 v3.51.5（全部保留），供老存档 / 特殊剧本使用。

## 5. 测试（新增 `tests/unit/currency-funnel.test.js`，8 项）

* A1 判据：主角（相等 / 包含）· 指定人员（含括注）· 路人 → false · 空归属 → false；
* B1 `add` 三人 → 只留主角与指定人员；B2 `update` 对第三人不落地（原值不动）；B3 关闭开关 → 全保留；B4 空归属回落主角后放行；
* C1 手工快速记账不受影响；D1 已有"其他人"数据不被清理；D2 `normalizeCurrency` 本身不拦（漏斗只在入库口）。

## 6. 门禁联动

新增配置键 → `check-config-decl` 控件 +1（存储页 24 项 / 总 202）、黄金样本白名单补 `currencyFunnel`；`config-clock-golden` / `settings-*` / `storage-page` 的数字口径同步。
