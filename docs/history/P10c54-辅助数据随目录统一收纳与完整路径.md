## 1. 事实（v3.26.x 之前）

目录模式只把**记忆数据**收纳到目录；**辅助数据**仍散在浏览器本机存储里：

| 数据 | 键 | 之前去处 | 体量 |
| --- | --- | --- | --- |
| 调试日志 | `SPreset_FTTMemoryDebug` | localStorage | 上限 0.6M 字符（D13 口径） |
| 交互时间线 | `SPreset_FTTMemoryTrace` | localStorage | 上限 7MB（D13 口径，最大一块） |
| 同步与对账标记 | 多个 `…MARK…` 键 | localStorage | 小 |
| 版本清单缓存 | `fttAboutJson` | localStorage | 小 |
| 快照链 / 同步日志 | `ftt2-snap-*` / `ftt2-log-*` | 服务端文件（主命名空间） | 数百 KB |

用户设了目录，却只收纳了记忆数据 → 辅助数据仍占浏览器配额、也不在同一目录里，无法统一备份/迁移。

## 2. 落点与口径（本版）

新增 `adapters/aux-store.js`（**同步门面 + 异步落盘**）：

| 情形 | 行为 |
| --- | --- |
| 路径留空 | `auxFacade()` = localStorage（行为逐字不变）；宿主无 localStorage → 返回 `null`（调用方照旧退化为纯内存） |
| 设了目录 | `auxLsGet/Set/Remove` 走内存缓存；`set` 标脏 → **防抖 1.2s** 落盘到 `<目录命名空间>/aux/aux-<键名>.json`；退出/切后台（既有 `exitFlush` 钩子）**强制落盘** |
| 启动 | `auxStoreInit()`（在 `wireDebugLog()` / `wireTraceStore()` **之前**）：目录里已有 → 载入内存并清掉同名浏览器旧键；目录里没有而浏览器有 → **先写后清**（写 → 回读逐字节校验 → 才删旧键），失败不清、下次重试 |
| 快照 / 同步日志 | 写完服务端后 `auxMirrorFile()` **额外收录一份**到同一目录（**只读路径不变** —— 权威仍在原命名空间，跨端同步语义不受影响） |
| 失败 | 只记账（`auxStoreInfo().lastError` / `failures`），内存副本仍在，下次防抖或退出前重试 —— **绝不丢** |

**完整路径**（用户第 2 点）：

* `ttLearnDataRoot()` 两条来源：① 宿主 API 的路径字段（`api.extension.store.dataRoot` / `api.dev.dataRoot` / `api.db.dataRoot` / `api.extension.paths.data`）；② **从宿主报错里学**（TauriTavern 后端错误原样带绝对路径，真机实证），学到即缓存；
* `localFileRealLocation()` 在能拿到根目录时给出 `<root>/_tauritavern/extension-store/<目录>/（blobs/local/ · kv/local/）`；拿不到则如实写「用户数据目录内…（宿主未提供绝对路径）」，绝不假装知道。

## 4. 纪律与边界（如实）

* **留空 = 不开启**：不设目录时行为逐字不变（含「无 localStorage → 退化为纯内存」的既有语义）；
* 迁移**先写后清**，任一步失败都不清浏览器旧键（下次启动重试）；
* 快照 / 同步日志的**权威副本仍在原命名空间**（参与官方同步）；目录里那份是「本机统一收纳的副本」，只读路径不变；
* 辅助键体积有硬上限（调试日志 0.6M 字符 / 时间线 cap），收纳只改**落点**，不改上限与清理入口。

## 5. 测试与门禁

## 6. 结论

「设了目录 → 本机的一切都收进这个目录」：记忆数据（v3.26.0–v3.26.5）+ 辅助数据与快照/日志副本（本版），并且**能看见在哪**（存储页完整路径 + 数据管理明细）。
