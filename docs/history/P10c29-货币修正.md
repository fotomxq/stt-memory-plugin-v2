## 1. 先看真实数据：三类问题都在

用真机落盘状态离线复算（20 条货币、5 个归属）：

| 用户说的 | 真机里的样子 |
| --- | --- |
| 不应该被记录的角色 | 归属 5 名：主角候选「李瑶」（11 条）、以及 `康泰`(5) / `孙有才`(2) / `钱大富`(1) / `孙小六`(1) —— 后四个只在正文里出现过，并非「主角 + 标定角色」；而 `钱大富`/`孙有才` 只在**状态记录主体**里出现（不在角色档案里）→ 名册口径必须含状态主体，否则会误判幽灵 |
| 错乱的单位计价 | ① `name:"贯"`（币种名写成了**单位词**）2 条；② 单位 `粒`（碎银）、`块`（碎金）非标准；③ 同一币种两种单位：`开元通宝` 既有 `枚`（-16）又有 `贯`（200）——直接相加必错；④ 6 条额度为 0 而流水有净额（-300 / -50 / 2 / 400 / -1000 …） |
| 冗余的数据合并 | 同一归属下 `金子 / 赤金 / 黄金`（3 条同物异名）、`飞钱 / 飞钱凭证`、`铜钱 / 现铜` 各成一堆 |

## 2. 设计：纯机械、零 AI、**先出计划后应用**

`core/currency-repair.js`（新增）：

```text
currencyRepairPlan(opts)   → 只读计划：{drop[], merge[], fix[], report[], counts, me, meConfirmed, roster, tracked, untrackedAvailable}
runCurrencyRepair(opts)    → 落库：剔除 + 合并 + 修正（留 id 墓碑、saveState、通知、调试日志）；幂等
```

| 类 | code | 判定 / 动作 |
| --- | --- | --- |
| ① 剔除 | `ghost-owner` | 归属不在「已知角色名册」= 角色档案 + 名册 + 状态记录主体（含 `甲·乙` 前缀）+ 记忆归属 + 主角设定 + 标定角色 |
| ① 剔除 | `untracked-owner` | 名册内但非默认归属（主角）且未标定 → **默认只报告**；勾选「同时剔除未标定角色」才剔除 |
| ① 剔除 | `name-is-unit` | 币种名就是计价单位词（贯/两/文/钱/分/厘/枚/粒/块…）且未写单位 → 提取错误 |
| ① 剔除 | `empty` | 无额度 / 单位 / 备注 / 流水的空壳 |
| ② 修正 | `unit-alias` | 单位写法归一：银圆/大洋/鹰洋→银元 · 缗/緡/串→贯 · 銀兩→两 · ＵＳＤ/rmb→美元/人民币 …（**只收无歧义写法**，不把「元/圆/块」硬归到任一边） |
| ② 修正 | `amount-from-history` | 额度缺失（0）且流水有净额 → 用净额补齐（**只补 0，绝不动非零额度**） |
| ② 报告 | `unit-nonstandard` · `amount-mismatch` · `unit-conflict` | 非标准单位（粒/块 用于金属）· 额度为负而流水净额为正 · 同币种多种单位（**绝不相加**） |
| ③ 合并 | 别名组 | 同归属 + 同规范币种名 + 单位相容 → 合 1 条：**保最新一条的 id 与额度（不累加）**、流水去重（≤12）、`uses` 累加、标签并集、备注取更长、`floorStart/floorEnd` 取 `min/max`、`date` 取最新 |

**为什么额度不累加**：货币条目的 `amount` 是「余额快照」而不是可累加的库存（物品才累加数量）——
同物异名的多条往往是**不同时间对同一个钱包的记录**，累加会凭空造钱（金子 20 + 赤金 10 + 黄金 20 = 50 两是错的）。
故取**最新一条**的额度，其余作为历史（流水去重合并），并在预览里写明「保留最新额度 X，不累加」。

**为什么单位冲突不合并**：`开元通宝` 的 `枚`（-16）与 `贯`（200）尺度不同（1 贯 = 1000 文），
在没有汇率依据时相加会得出错误金额 → 只报告，交人工。

## 3. 界面：货币页「🧹 修正货币」→ 计划预览 →「✅ 应用修正」

- 按钮加在货币页工具行（与「👥 指定角色」「✖ 清空标定」同排）；
- 点击只**出计划**（零副作用）：四段明细（将剔除 / 将合并 / 将修正 / 只报告）+ 开关「☐ 同时剔除未标定角色的货币」+「✅ 应用修正」/「取消」；
- 「✅ 应用修正」在**真实点击路径**上先过危险动作二次确认（`DANGER_ACTION_PROMPTS.currencyRepairApply`，文案讲清「删什么 / 留墓碑 / 只减不增 / 先备份」）；
  取消 = 零副作用；程序化调用（命令 / devtools / 测试）不经该闸（与既有口径一致）。

### 3.1 一处护栏（真机数据逼出来的）

真机上 `defaultCurrencyOwner()` 回落成**字面量「主角」**（存档无 `protagonist`、无「主角/玩家」标签快照、宿主身份视图为空）。
此时「未标定角色」这个判据对**所有**归属都成立 —— 若照勾选执行，会把 **20 条货币全部删光**（离线实测 20 → 0，幂等为空）。

故：**主角身份未确证（= 默认归属是兜底字面量）时，「同时剔除未标定角色」置灰不可用**
（`untrackedAvailable:false`，计划里这类条目带 `blocked:true`，只报告并提示如何让主角身份生效）。
要用这条能力，需先：① 在角色页给主角打「主角 / 玩家」标签，或用 ② 货币页「👥 指定角色」标定要跟踪的角色。

## 4. 真机数据实测（离线复算，不写回）

| 口径 | 结果 |
| --- | --- |
| 扫描 | 20 条 / 名册 44 名 / 标定 0 名 / 默认归属 `主角`（未确证 → 未标定项只报告） |
| 将剔除 | **7 条**（`name-is-unit` 2 条：「李瑶/贯 -1000」「孙有才/贯 0」；合并并入 5 条） |
| 将合并 | **4 组**：李瑶 铜钱+现铜 → 保留最新额度 1000；李瑶 金子+赤金+黄金 → 保留 20（**不累加 50**）；康泰 黄金+赤金 → 保留 50；李瑶 飞钱凭证+飞钱 → 保留 -190 |
| 将修正 | **6 处**（额度缺省 → 流水净额：-1 / -1 / -300 / 2 / 400 / -1000） |
| 只报告 | **16 条**（未标定 12 · 非标准单位 2 · 单位冲突 2） |
| 应用结果 | **20 → 13 条**，再次计算计划 **0 项**（幂等）；未标定项**一条未删**（护栏生效） |

  是否给 currencies 补哈希口径（会改变跨端合并/去重口径）**留待后续单独决定**，本次不擅自改；

  若用户语料里还有别的同物异名，可在后续批次按真实数据补充；
- 顺带观察（与本版无关）：`tests/unit/vector-parallel.test.js#P1` 是**墙钟断言**（「并行 <45ms」），
  本机满载时偶发 45ms 失败（单独重跑 12/12 通过）—— 属既有测试的环境敏感项，未改。
