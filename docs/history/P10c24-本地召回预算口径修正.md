> 相关：`host/inject.js`（预算与组装）· `ui/extract-page.js`（账目行）· `ui/settings-pages.js`（标签）

## 1. 先核对：异常长什么样

真机只读调试桥读数：

| 观测 | 值 |
| --- | --- |
| `ftt.snapshot` → `inject.length` | **8114**（`charBudget = 8000`） |
| `interceptor` | `calls: 0` / `lastPush: null`（本会话的注入由载入/楼层变化路径推送，非拦截器） |
| `settings.cfg` | `charBudget 8000` · `maxAtoms 16` · `maxMemories 8` · `useVector **false**` · `jsExtractEnabled **true**` |
| `promptTemplates.injectGuide` | **3457 字** |

`useVector=false` + `jsExtractEnabled=true` ⇒ **当前生效的就是「本地召回」（JS 层）**，
它走 `core/recall.js#buildMemoryBodyForInject`，预算由 `host/inject.js` 分配。

**离线复算**（用真实落盘状态跑同一条召回路径；情节 115 / 记忆 89 / 物品 45 / 场景 40 / 概念 66 / 关联 231）：

| 口径 | 召回正文 | 条目行 | 区块 |
| --- | --- | --- | --- |
| A 修复前（预算 8000 直接给召回体） | 8153 字 | **55 行** | 6 |
| B **v3.10.3 现行**（预算 4210 = 8000 − 框架 330 − 说明 3457） | 4317 字 | **30 行（≈ −47%）** | 6 |
| C 本版（预算 7670 = 8000 − 结构框架 330） | 7821 字 | **54 行** | 7 |

⇒ 用户的「本地召回异常」= **召回内容腰斩**（少了 25 行条目）。

## 2. 根因：两类东西混进同一个预算

v3.10.3 处置 A2（「设 8000 却注入 11955」）时，把**整个框架**都算进 `charBudget`，其中包含
**用户自己在设定里写的「使用说明」模板**（真机 3457 字，占上限 43%）。后果：

```text
用户把「使用说明」写长一点  →  记忆能召回的量被动变少
```

这不是「预算」该有的语义：预算应约束**本插件产出的内容**，而说明模板是**用户提示词**（长度由用户在设定里直接控制）。
正确的切分：

| 组成 | 归属 | 是否计入 `charBudget` |
| --- | --- | --- |
| `# FTT 记忆注入` + 区块说明行 + 日期行 + `记忆结束。`（≈330 字） | 插件结构框架（固定开销） | ✅ **计入** |
| 「使用说明」模板（`promptTemplates.injectGuide`） | **用户提示词** | ❌ **不计入**（仅如实回报长度） |
| 记忆正文（各区块条目） | 插件召回产物 | ✅ 计入 |

## 3. 修法与可见性

| 位置 | 改动 |
| --- | --- |
| `host/inject.js#planInjectBudget` | `bodyBudget = 上限 − 结构框架`；**说明不参与分配**；返回增 `guide`（仅回报）；`cap − 框架 < minBody` → 仍 `ok:false`（如实 `budget-too-small`，不注入） |
| `host/inject.js#buildAndPushInject` | 组装恢复「**始终保留**使用说明」（删除「丢说明让预算」分支）；`pushStats` 增 `lastGuide`；返回体增 `guide` |
| `ui/extract-page.js` | 「注入预算」段新增只读账目行：`上限 · 结构框架 · 使用说明（不计入）· 正文预算 · 上次实际注入`；提示语改为「预算约束记忆正文 + 结构框架」，并明写说明不占预算 |
| `ui/settings-pages.js` | 控件标签：`注入字符预算（硬上限）` → **`记忆正文预算（不含使用说明模板）`** |

> **为什么不干脆让总注入体严格 ≤ 上限**：那正是 v3.10.3 的做法，代价是「用户写长说明 = 记忆被挤掉」。
> 本版选择**语义清晰**：上限约束插件产出的记忆正文；说明模板长度单独显示，用户可自行在设定里控制它。

## 4. 验证

- 单元 **140 文件 / 2141 断言**（`inject-push` Q 组按新语义重写）：
  - `Q2` `planInjectBudget`：`bodyBudget = 上限 − 结构框架`；**同一上限下说明从 3000 变 8000 也不改变正文预算**；
    连框架都放不下 → `budget-too-small`；
  - `Q3` **真机回归**：超长「使用说明」（3000 字）不再让召回变少 —— 正文照常注入、说明保留、
    `bodyBudget === cap − overhead` 且回报 `guide` 长度；
  - `Q4` 上限足够时正文预算 = 上限 − 结构框架（记忆正文不再被说明吃掉）；`Q5` 极限上限仍如实拒绝。
- 冒烟 **204 项** · 全门禁 0 违规（`ui-wording` 门禁顺带抓到并修正了一处提示文本里的字面量 `**…**`）。
- 离线复算：召回正文 **4317 字/30 行 → 7821 字/54 行**（回到修复前量级，且说明模板照常保留）。

## 5. 部署后请这样验收（需刷新页面）

1. 刷新页面 → 设定 →「提取记忆」→ **注入预算**段：
   - 控件标签应为 **「记忆正文预算（不含使用说明模板）」**；
   - 其下应有 `注入账目：上限 … · 结构框架 … · 使用说明 …（不计入）· 正文预算 … · 上次实际注入 …` 一行；
2. `ftt.snapshot` → `inject.length` 应**明显上升**（真机预期 ≈ 7800 + 说明 3457 ≈ 1.1 万；其中记忆正文部分
   受 8000 约束、说明部分不计入）；
3. 面板总览/分类页的召回观感应恢复（不再只召回一半条目）。
