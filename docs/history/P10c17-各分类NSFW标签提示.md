## 1. 交付：把「留档等级」在界面上讲清楚

v3.8.0 已把等级写进数据，但行内只是一枚 emoji 徽标（`🔞强`），用户不易读出「这是什么级别的内容」。
本版把它改成**写明等级的文字标签**，并补齐到用户点名的每个分类与每处查看路径：

| 位置 | 呈现 |
| --- | --- |
| 各分类列表行（行首） | `NSFW·强` / `NSFW·弱`（**无 → 不显示**）；带 `data-ftt-nsfw-level` 供配色与回归断言 |
| tooltip | `NSFW 等级留档：强 —— 完全是露骨内容｜按原文判定，弱化内容不会改变该标签（永久留档）` |
| 分类页顶部 | 汇总一行：`NSFW 留档：弱 N · 强 M（按原文判定，弱化后不变；标记见每条行首）`；**该分类没有已留档条目时不显示**（不占位、不加噪声） |
| 条目编辑器（`✏️`） | 只读行「NSFW 等级留档」= 标签 + 释义 + 「永久留档：弱化内容不会改变它」 |
| 配色（`style.css`） | 强 = 警示色（`--ftt-danger`）、弱 = 中性提示色（`--ftt-warn`），标签带细边框便于扫读 |

覆盖分类（用户点名 + 同一套渲染路径的全部维度）：**情节 · 记忆 · 状态记录 · 物品 · 传言 · 计划悬念 · 概念**
（以及角色档案 / 场景 / 平行事件 / 情节分段 / 货币等等 —— 它们共用 `ui/list-rows.js` 的行渲染器，
故一并具备；货币与名册不在弱化/留档的字段白名单内，不会出现标签）。

## 2. 实现落点

| 层 | 落点 | 说明 |
| --- | --- | --- |
| 内核 | `core/nsfw-level.js#NSFW_LEVEL_HINTS` / `nsfwLevelHint(l)` | 三级释义的**单一来源**（`强 —— 完全是露骨内容`），界面各处引用同一份措辞 |
| 行渲染 | `ui/list-rows.js#nsfwBadgeHtml`（v3.9.0 改写） | 由 emoji 徽标改为文字标签 + `data-ftt-nsfw-level` + 释义 tooltip |
| 分类汇总 | `ui/list-rows.js#nsfwLegendHtml(items)` | 统计当前列表（筛选后）各等级条数，无留档时返回空串 |
| 列表页 | `ui/panel.js#listPageHtml`（通用分类页） | 行渲染已统一前置徽标；本版在列表顶部插入汇总行 |
| 状态页 | `ui/panel.js`（状态记录分页，独立渲染器） | `stateRowMainHtml(e)` 行首徽标 + 分页顶部汇总（`matched` = 当前展示） |
| 编辑器 | `ui/panel.js#editorHtml` | 只读留档行（不提供编辑：留档口径是「只升不降」，允许人工下调会破坏「永久留档」） |

## 4. 兼容与风险

- **数据零改动**：本版只改界面呈现（徽标文案、汇总行、编辑器只读行、CSS），字段与判级口径完全沿用 v3.8.0 → 无迁移、无存档风险。
- **不显示「无」**：与「缺省即无、不给数据加噪声」一致；分类汇总同样在没有弱/强条目时整行不出现。
- **风险（误读方向）**：等级是**词面判据**（弱级信号如「拥抱 / 亲近」在普通叙事里也会出现）→ 可能偏保守地记为「弱」；
  界面把「按原文判定、弱化后不变」写在 tooltip 与汇总行里，避免被误读成「当前正文的露骨程度」。
