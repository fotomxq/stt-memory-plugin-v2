# P10c2 · 导出 / 备份文件名带日期时间（v3.0.17）

> 文档版本：v1.0 ｜ 日期：2026-09-30 ｜ 状态：生效（v3.0.17）
> 触发（用户原话）：「新版本 导出json备份，文件名必须带日期和时间。」
> 相关：`docs/history/P10bg`（数据管理删楼与备份）· `docs/D12` §4 / Q5（自动备份 3 份轮转）· `docs/04-应用架构`（数据管理页）

## 1. 需求与现状

| 出口 | 改动前 | 改动后（v3.0.17） |
| --- | --- | --- |
| 数据管理「⬇ 导出 JSON」（手动备份 / 迁移） | `FTT记忆_<角色哈希>.json` —— 同一角色多次导出**同名互相覆盖**，事后也看不出是哪天的备份 | `FTT记忆_<角色哈希>_2026-09-30_14-05-22.json` |
| 删楼前的自动明文备份 | `ftt2-floor-backup-<角色>-1\|2\|3.json`（固定名 → 只能靠文件系统时间猜日期） | `ftt2-floor-backup-<角色>-s<槽位>-20260930-140522.json` |

**为什么用 `-` 而不是 `:`**：冒号在 Windows 文件名里非法、安卓与多数网盘同步也会拒绝 —— 统一用
`YYYY-MM-DD_HH-mm-ss`（可读）/ `YYYYMMDD-HHmmss`（紧凑、可直接排序），两者都是**本地时间**、个位补零。

## 2. 实现

| # | 落点 | 说明 |
| --- | --- | --- |
| ① | `core/util.js#fileStamp` / `#fileStampCompact`（新增，纯函数） | `2026-09-30_14-05-22` / `20260930-140522`；非法入参不抛 |
| ② | `index.js#exportFileName` + `ui/panel.js#defaultExportFileName` | 两处（宿主钩子与无钩子兜底）同口径，均在哈希后追加 `_<日期>_<时间>`；无作用域时退化为 `FTT记忆_<日期>_<时间>.json` |
| ③ | `adapters/floor-backup.js#floorBackupName(scope, slot, at)` | 名字改成 `…-s<槽位>-<紧凑时间戳>.json`；`at` 可注入（确定性测试） |
| ④ | `adapters/floor-backup.js#writeFloorBackup(scope, slot, text, {at, prevName})` | 上传成功后**尽力删除该槽位的上一份**（只删本插件备份前缀）→「**3 份轮转**」的上限不变，而每份备份都自带时间戳 |
| ⑤ | `host/floor-trim.js` | 删楼账本新增 `names: {槽位: 文件名}`（旧账本缺该键时按空处理）；写备份时把该槽位上一份的名字传下去供轮转删除；每次删楼的备份名照旧写入结果与人工确认项 |
