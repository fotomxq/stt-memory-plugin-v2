## 1. 怎么用

| 你想知道 | 看哪里 |
| --- | --- |
| **现在**系统是什么样 | `docs/01-业务架构` … `docs/05-开发指南` |
| 某个改动**当时**怎么做、证据在哪 | 本目录对应批次档 |
| 某条历史结论**是否已过时** | `docs/勘误-历史档过时条目.md`（只增台账） |
| 打算做什么 | `docs/D*` 设计稿 |

**阅读纪律**：本目录里的断言数 / 冒烟数 / 控件数 / 版本号都是**当时的快照**，不随版本更新。
与 `docs/README.md` §3 的「数字口径」冲突时，**以 §3 为准**。

### 2.1 `P10c<N>` 的**位数溢出规则**（v3.25.1 登记）

`P10c` 档按版本顺序递增编号，**位数不设上限**：`P10c99` 之后直接写 **`P10c100`**（不要回退成 `P10c00`、
不要另起前缀、也不要把编号挪到其它批次）——这与版本号「在 `3.XX.XX` 基础上一直追加、位数可增」同一口径
（见 `开发守则.md` §3.1）。新增批次档时同步更新本文件 §2 的区间与计数、以及 `docs/README.md` §3 的「历史批次档数」，
两者由 `scripts/check-docs-facts.js` 核对。

## 4. 新增历史档的要求

1. 文件名：`P<阶段><字母>-<主题>.md`（与已发布版本对应时，主题里带上该版本的要点）；
2. 头部元信息：`文档版本 ｜ 日期 ｜ 状态`（状态写「生效（vX.Y.Z）」）；
3. 正文口径：`用户原话 → ①②③ 改动与理由 → 门禁与回归`（与 `CHANGELOG.md` 条目同源）；
4. **只增不改**：结论变了就追加「结论变更」段落，不改旧文。
