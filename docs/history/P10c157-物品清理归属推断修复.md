# P10c157 · 物品清理漏列 / 计数为 0 修复（归属缺失 → 位置推断）（v3.52.4）

> 文档版本：v1.0 ｜ 日期：2026-10-28 ｜ 状态：生效（v3.52.4）
> 用户报告（原话）：「修复物品清理功能，角色增加关注后。是有其他人的数据，但没被列入，其次关注角色的物品数量也是0。」
> 关联：`core/items-cleanup.js` · `ui/items-cleanup-panel.js` · `ui/list-rows.js` · `docs/D59`

## 1. 根因（两个症状同一个原因）

清理计划完全依赖 `items[].owner`；而**物品抽取模板（V1 逐字符黄金样本）里没有「归属」字段** →
AI 从不产出 owner → 历史物品与 `owner` 缺失的存量数据**全部落进「未归属」**：

* 「其他人的数据没被列入」= 那些物品 owner 为空 → 按设计（未归属不动）不进候选；
* 「关注角色的物品数量是 0」= 关注角色名下物品 owner 也为空 → 不计入「保留」，显示 0。

> 为什么**不改提示词**：物品模板属 V1 黄金样本，`extract-prompt-flow` / `separate-dim-golden` 要求**逐字符一致**；
> 改模板会让两处黄金样本漂移（本轮已回滚）。

## 2. 修复：**归属推断**（确定性，不改数据、不改提示词）

`core/items-cleanup.js#effOwnerOf()`：

| 层 | 规则 |
| --- | --- |
| ① | 显式 `items[].owner`（用户在编辑器里填过 / 后续 AI 若给出）**优先** |
| ② | 否则**推断**：`carried !== false` 且 `location` 命中**已知角色名**（档案名 / 主角；精确或互相包含）→ 该角色 |
| ③ | 都不成立 → 空（未归属，仍然不动） |

依据：物品库模板的既有语义就是「**位置**写角色名或地点名 + **携带**=随身携带」——「位置是角色 + 随身」等价于「在该角色手里」。
推断**只读**（不写回数据），并在清单里标 `（…·推断）`、摘要里报「其中 N 件按位置推断归属」。

另：物品清单行新增 `· 归属：X`（有值时显示），便于用户核对清理依据。

## 3. 测试

`snapshot-watch-items-cleanup.test.js` 13 → **17 项**：
G1 位置推断 → 其他人的物品进清单；显式 owner 优先；未携带不推断 ·
G2 关注角色物品计入「保留」（不再 0）；地点位置不推断 ·
G3 清单行显示归属 · G4 **V1 提示词逐字符不变**（归属不靠改提示词）。

全量单测 **263 文件 / 3897 断言**；冒烟 224 项；`npm run gate` 全绿。

## 4. 边界

1. 推断只在**清理判定**里发生（不改物品数据）；若物品的 `location` 恰与某角色同名但实为地点，会被当作归属 —— 预览里标「推断」并要求人工确认，不会静默删除；
2. 未归属物品（位置是地点 / 无携带信息）**仍然不动**（宁可不删）；
3. `owner` 显式值的来源：编辑器字段（v3.52.2 起）+ 未来若 AI 给出（提示词未改，当前不会）。
