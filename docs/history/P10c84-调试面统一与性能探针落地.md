## 2. 为什么动了 W9 的两行（范围裁决）

用户问的是「W10 待开发事项」，但 W10 三行的**硬前置**在 W9：

- `技-42` 前置 = **`技-39` · `技-41`**；

`技-42` 是「把探针接进调试页 / 桥 / 导出」——**没有 `技-39` 的探针就没有东西可接**；而 `技-39` 此前**完全未实现**（`docs/D17` U191 仍 `⬜`，四个性能读数、`ftt.perf*` 四件套、`scripts/perf-baseline.json` **一样都没有**）。

故本批按用户确认的「**解锁链**」范围一并交付 `技-39` / `技-40`（探针 + 三处同源出口）。

## 3. 探针口径（`技-39` · `core/perf-probe.js`）

| 项 | 值 / 口径 | 为什么 |
| --- | --- | --- |
| 三级阈值 | `notice ≥ 50ms` · `stall ≥ 200ms` · `freeze ≥ 1000ms` | `docs/D31` §4.1 / Q2 |
| 采样窗口 | 环形 **200** 段（压 250 条 → 剩 200，淘汰最旧） | 探针不得成为卡顿源（`D31` R1） |
| 去重 | 同 `site` **800ms** 内合并（丢弃计 `deduped`） | 避免同一步骤连打 |
| 丢弃 | **< 50ms 直接不入环** | 「只记超阈段」的硬口径 |
| `jankRate` | **超阈条数 ÷ 200**（窗口容量） | **有意不采用** `D31` 的字面「Σ耗时 ÷ 窗口时长」——只记超阈段时分母不可自证，**不猜**（注释里写明） |
| 四类读数 | `write` / `read` / `scan` / `size`，各带 `at` / `ver` / `window` / `cause` / `site` / `u` | 追溯六字段（`D31` §3.7） |
| 优化清单 | 7 条机械判据 **T1–T7** → 现象 / 判据 / 证据 / 归因 / 建议 / **台账号或「未立项」** | 只输出候选，**不自动开单**（`D31` §4.2） |
| 基线 | `scripts/perf-baseline.json`（**70 项确定性量** · UTF-8 **无 BOM**） | 门禁只比确定性量 |
| 落盘 | `node scripts/perf-baseline.js --write`（**不带 `--write` 只打印**） | 默认只读，避免误改基线 |

**耗时为什么不进门禁**：CI / 本机的墙钟抖动与真实回归无法区分，把耗时设为判据会得到**随机红**。门禁只比**确定性量**（条数 / 字节 / 上限），耗时**照记不判**。

## 7. 一次判据收窄（有意为之，非放宽）

`tests/unit/coverage-tool.test.js#C8` 原判据是**子串**：`gate.indexOf('coverage') < 0`（意思是"覆盖率工具不许进 gate"）。
本轮新增的 `scripts/check-debug-coverage.js` 是**另一件事**（调试面完整性门禁，**故意**进 gate），文件名也含 `coverage` → 子串判据把**正确实现**判成错误。

处置：收窄为**精确脚本路径**判据（`gate` 链里不得出现 `scripts/coverage.js`）。**语义比原来更准**（原判据"任何含 coverage 的脚本都不许进 gate"本就不是原意），
且 `scripts/coverage.js` 仍**不在** gate 内 —— 「先观测不阻断」（`docs/D22` W5 `技-11`）的硬口径**未被放宽**。
