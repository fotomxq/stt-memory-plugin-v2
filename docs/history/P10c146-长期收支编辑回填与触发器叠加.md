# P10c146 · 长期收支编辑回填修复 + 触发器「抵达即触发 / 叠加执行 / 截止停止」（v3.51.5）

> 文档版本：v1.0 ｜ 日期：2026-10-24 ｜ 状态：生效（v3.51.5）
> 用户要求（原话）：「1. 核对修复长期收支编辑的错误点，尤其是信息没回填。
>   2. 核对修复长期收支，抵达剧情时间及之后日期，自动触发新增记账。如果超出多轮，则自动叠加执行，直到抵达截止日期或超过剧情日期。」
> 关联：`ui/entry-flat.js`（新）· `core/deal-triggers.js` · `ui/panel.js` · `docs/D53` §3.4/§3.9

## 1. 编辑回填（需求 1）

**根因**：`deals` 的三段 `outlook` 是**嵌套结构**，而编辑器字段表用的是扁平键（`outlookText` / `nodesText` / `forecastNextDate` / `forecastDelta` / `forecastDirection` / `forecastNote` / `forecastSource`）。
旧 `ui/panel.js#flatFor` 只做顶层拷贝 → 这些键全是 `undefined` → **编辑长期收支时表单空着**；更糟的是「直接保存」会用空值把原字段冲掉（`deconstructEntry` 生成 `outlook: {text:'', nodes:[], forecast:{nextDate:''}}` → 归一失败或丢数据）。

**修复**：把 `flatFor` 外提到新模块 `ui/entry-flat.js`（面板不再增行），并补 `deals` 分支：
* `outlookText` ← `outlook.text`
* `nodesText` ← 逐条 `日期|金额|说明`（金额 0 也照常回填；与 `deconstructEntry` **互逆**）
* `forecastNextDate` / `forecastDelta` / `forecastDirection` / `forecastNote` / `forecastSource` ← `outlook.forecast.*`

**回归锁**：`money-ledger-deals` 的 K1（互逆）/ K2（✏ 后表单带原值）/ K3（未改内容直接保存 → 不丢字段）。

## 2. 触发器（需求 2）

**旧口径的两个错误**：
1. 只有「跨度 ≥ `cfg.dealJumpMinDays`（默认 30 天）」才处置 → **「只推进 1 天就到期」的条目永远不会兑现**；
2. 「普通跳动只兑现一笔」→ **跨多个周期只补一笔**，与「自动叠加」相反。

**新口径**（`core/deal-triggers.js#runDealTriggers`）：

| 项 | 规则 |
| --- | --- |
| 触发条件 | 剧情日期**推进到/越过** `forecast.nextDate` 即兑现（不再要求 30 天跨度）；**回退**（`backward`）不处置；`prev` 脏不处置；`prev` 为空（首次运行）照常处置 |
| 叠加执行 | 每兑现一笔 → 水位 `+cycleDays` → **继续**，直到水位 > 当前剧情日期 |
| 截止日期 | 水位越过 `endDate` → **停止生成**，并把 `forecast.nextDate` 清空（本条自然结束） |
| 上限 | 每次最多 `cfg.dealCatchUpMax`（默认 24）笔，超限置 `trigger.catchUpTruncated` 并如实回报（水位停在待兑现节点，下次继续叠加） |
| 缺周期 | `cycle` 推断不出 → **只做一笔**（无法确定性推进，不猜周期） |
| 幂等 | `dealId + 节点日期` 去重（已兑现的不重复、不占上限） |
| 无 AI | 全程只做日期数学 + 写库（`noAi: true`） |

**测试**（`money-ledger-deals` J1–J5）：小步推进即触发 / 叠加到超过当前日期 / 截止日期停止并清水位 / 首次运行受上限 / 回退不处置。

## 3. 接线与失败口径

`index.js#runDealTriggersAfterExtract` 不变（`onGenEnded` → `runAutoExtract()` 之后调用；失败静默）；
只在有兑现时 `saveStateNowQuiet('deal-triggers')`。

## 4. 边界（如实登记）

1. **首次运行可能一次补多笔**（最多 24）：这是「自动叠加」的必然结果；上限与 `catchUpTruncated` 保证不静默。
2. 缺 `cycle` 的条目不叠加（只一笔）—— 需要用户在编辑器补周期。
3. 截止日期之后**清空预测水位**，若用户延长截止日期需重新填预测日期（不会自动猜）。
4. 触发器仍**不注入**、不参与正文提取（`docs/D53` Q3）。
