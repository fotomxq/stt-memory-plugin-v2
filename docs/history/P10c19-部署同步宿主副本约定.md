## 2. 判定（纯函数 · 保守优先）

`planHostSync({deployedDir, isRepo, devSha, deployedSha, sameRemote, dirtyCount, gitAvailable})`：

| 输入情形 | action | reason | 说明 |
| --- | --- | --- | --- |
| 未发现宿主扩展目录 | `none` | `no-host` | 无事可做（换台机器/纯 ST 环境） |
| 部署副本不是 git 检出 | `deploy-copy` | `not-a-git-checkout` | 改走 `npm run local -- --deploy --yes`（文件级，要求宿主退出） |
| 部署副本有本地改动 | `refuse` | `deployed-dirty` | **拒绝**，绝不覆盖（note 里给出改动数） |
| 与开发仓库不同源 | `refuse` | `remote-mismatch` | **拒绝**（`https://…` 与 `git@…` 归一后比较仓库标识） |
| 两侧已在同一提交 | `none` | `already-aligned` | 无需同步 |
| 其余（有漂移） | `ff` | `drift` | `fetch` + `merge --ff-only` |
| 本机 git 不可用 | `deploy-copy` | `git-unavailable` | 不做 git 快进，改走路文件级路径 |

**拒绝态一律 `ok:false`** —— 调用方据此**不写任何东西**（该不变量由单测 `D5b` 锁定）。

## 3. 条件探测（如实打印，不猜）

「调试端口已启动」= 下列任一成立：

| 通道 | 探测方式 | 说明 |
| --- | --- | --- |
| CDP（默认 9222，取 `local.config.json#debugPort`） | `http://127.0.0.1:<port>/json/version` | 由 `launch-debug.cmd` 起宿主时开启 |
| 只读调试桥（默认 8791） | ① 先 `connect`：已有人监听即算在线；② 连不上则**短听 2s**，收到**插件主动连入**即算在线 | 桥是**反向**的（页面无法监听端口），端口在工具这侧；插件侧「🔌 调试桥」开关无法从外部直读，短听是可靠信号 |

## 4. 本机实测记录（真实宿主）

| 步骤 | 结果 |
| --- | --- |
| 只读检查（`npm run local:sync`） | 本地运行 **是** · 调试端口 **是**（CDP 9222 ✗ / 调试桥 8791 ✓，插件确在连入） |
| 检查时的两侧状态 | 开发仓库 v3.10.0 · `5897a75d`；部署副本 v3.10.0 · `5897a75d` → `already-aligned`（判定 `none`） |
| 执行同步（`--yes`，本版发布后） | 部署副本 → v3.10.1，与开发仓库**同一提交**；两侧核对 ✅ |
| 生效 | **需刷新页面**（插件在页面加载时装配；刷新后调试桥回到关闭属设计） |
| 未触碰 | 宿主进程未重启；聊天文件 / 世界书 / 设置 / 插件用户数据（`extension-store/**`）未改；只动扩展目录下本插件自己的子目录 |

> 说明：本机的部署副本恰是**与开发仓库同源的干净 git 检出**，因此走的是「git 快进」这条路 ——
> 它也是**宿主在跑时**唯一可行的路（文件级 `--deploy` 要求宿主退出以免文件占用）。

## 5. 硬性边界（与 §6.2 同口径）

1. 只动宿主扩展目录下**本插件自己**的子目录；插件用户数据与宿主配置**一律不碰**。
2. **永不** `reset --hard` / `clean` / `checkout -f` / `push`；只 `fetch` + `merge --ff-only`
   （非快进即失败并如实报错，绝不 force）。
3. 部署副本有本地改动或异源 → **拒绝**并报告，不覆盖。
4. 入库文件不得含本机路径或主机名：脚本只经 `maskPath` 输出（`--show-paths` 才打全路径），
   由 `scripts/check-local-leak.js` 在 `npm run gate` 中强制。

## 6. 未验证事项（如实登记）

1. **`--deploy`（文件级）未在真实宿主上执行过**：其计划逻辑有单测，但「写进宿主扩展目录后宿主能否
   正常加载」未经本机实测（与 `tests/local/README.md` §9 一致）。
2. **异源 / 脏副本的拒绝路径未在真机触发过**：只有单测覆盖（`D5`），真机上当时不存在这种副本。
3. **CDP 9222 未实测可用**：本机宿主不是带 `--remote-debugging-port` 启动的（判定时 CDP ✗、调试桥 ✓），
   故「CDP 通道可用」仍属未验证（与 `README.md` §9 第 1 条一致）。
4. **手机端未纳入**：本约定只覆盖本机宿主副本；远程设备（手机）上的插件不在同步范围内。

## 7. v3.10.2：真机首跑暴露的两处缺陷（已修）

v3.10.1 发布后**第一次在真机执行** `npm run local:sync -- --yes` 即失败。记录如下 ——
它同时印证了「未实测不得写成已验证」这条纪律的价值。

| # | 现象 | 根因 | 修法 |
| --- | --- | --- | --- |
| 1 | `fetch` 报 `fatal: detected dubious ownership` | 宿主仓库属主是登录用户、进程是 `SYSTEM`；`-c safe.directory=<反斜杠路径>` **git 不认** | 路径归一为 `/` 再传（`safePath`） |
| 2 | **「查不出是否干净」被当成「干净」放行** | `git status` 同样被拒 → `dirtyCount` 落回 `null`，旧判定把 `null` 当「未检查」 | `planHostSync()`：`dirtyCount: null`（显式传入）= **拒绝** `clean-unknown`；只有键缺省（没查）才继续；单测 `D5b`/`D5c` 锁定 |
| 3 | 调试桥条件误报「未启动」 | 短听窗口 2s < 插件拨号重试间隔 | 默认 **5s**，`--bridge-wait <ms>` 可调，输出打印实际窗口 |

**修复后的真机实测（宿主在跑、调试桥在线）**：只读检查判定 `ff`（漂移，退出码 1）→ `--yes` 干净性检查
通过 → `fetch` + `merge --ff-only` 成功 → 部署副本 **v3.10.1 / `8985496a`** 与开发仓库一致（退出码 0）。

> **过程教训（已自查，未造成损害）**：修版本号时误用了 PowerShell 的
> `Get-Content -Raw | Set-Content`，导致 `manifest.json`/`package.json` 被写入 **BOM 且中文乱码**
> （`FTT记忆组件` → 乱码）——这两个文件的 JSON 当场失效。**在提交前**用文件工具重写并核对
> （`git diff --stat` 仅剩版本号一行、`JSON.parse` 通过、无 BOM）已恢复；损坏**从未进入提交**，
> 也**未同步到宿主副本**。纪律：**禁止用 Get-Content/Set-Content 处理含非 ASCII 的仓库文件**，
> 一律用读写工具。
