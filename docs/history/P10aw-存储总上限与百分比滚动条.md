## 1. 修复前的事实

| 项 | 现状 |
| --- | --- |
| 上限口径 | **逐维绝对条数**：`storeMaxAtoms`=1200 / `storeMaxMemories`=800 / … 合计 5200，且**各维互不相干** —— 没有任何「总共能存多少」的概念 |
| UI | 设定 → 遗忘 →「存储保底 / 上限」里 **10 个数字输入框**（保底 / 上限成对排），要想清楚「总共 3000 条」得自己心算 |
| 削减裁定 | `core/ingest.js#storeCapFor(dim)` 只读该维 `storeMax*`；`enforceDimCaps()` 逐维裁剪 |
| 比例类设置 | 全部是**文本输入框**（相似度 / 阈值 / 概率 / 占比共 30 项），既看不出默认值在哪，也不便拖动试算 |

## 2. 改动一：上限改「总上限 + 各大类占比」

| 项 | 新口径 |
| --- | --- |
| 配置 | 新增 `storeTotalMax`（**合计上限**，默认 **3000 条**）与 `storeShare`（各大类占比，整数百分比，**合计恒为 100**） |
| 有效上限 | `某维上限 = max(该维保底, 四舍五入(storeTotalMax × storeShare[dim] ÷ 100))`（`core/ingest.js#storeCapFor`） |
| 默认占比 | 由旧逐维上限的**相对权重**推导并配平：情节 23 / 记忆 15 / 角色档案 8 / 物品 9 / 概念 13 / 场景 8 / 计划 6 / 悬念 6 / 名册 6 / 传言 6 = **100** |
| 默认结果 | 3000 × 占比 → 690 / 450 / 240 / 270 / 390 / 240 / 180 / 180 / 180 / 180，**合计恰为 3000** |
| 兼容 | 旧的逐维 `storeMax*` **键保留**：`storeTotalMax` 有效时不再读；**显式置 0 或缺键**时回落旧口径 —— 老存档与 V1 黄金样本仍可逐字复现（见 §5 的有意偏离登记） |
| 参与维度 | 与裁剪表 `STORE_LIMITS` 一致（10 项：情节 / 记忆 / 角色档案 / 物品 / 概念 / 场景 / 计划 / 悬念 / 名册 / 传言）；`currencies` 与 `plotSegments` 不参与（前者本就是独立账本、后者只归档不入库裁剪） |

## 3. 改动二：占比用滚动条拖动，动态配平到 100%

- 界面：设定 → 遗忘 →「各大类占比」**10 条滚动条**（`data-ftt-share`，0-100、步进 1），每行右侧是实时读数「`xx% · ≈N 条`」与「默认 `yy%` · 保底 `M` 条」；
- 拖动语义（`core/ingest.js#setStoreShare`）：
  1. 被拖动项取用户值（0-100 整数）；
  2. 其余维度按**原占比比例**缩放到 `100 − 该值`，**每项四舍五入**；
  3. 四舍五入后合计若不为 100，**差额补给「除被拖动项外的最大项」**（都补不动则给被拖动项）；
  4. 于是「合计恒为 100%」始终成立（单测覆盖 0 / 100 / 全 0 / 非法输入的边界）；
- 交互：拖动中（`input`）只刷**实时读数**（不写配置、不重绘，避免抖动与频繁落盘）；**松手（`change`）**才写 `cfg.storeShare` + 落盘 + 重绘（面板动作 `storeShare`）；
- 页面顶部合计行如实显示「合计 100% · 有效上限合计 ≈ 3000 条（总上限 3000 条）」；占比合计不为 100（异常数据）时红字提示「拖动任一滚动条即会重新配平」。

## 4. 改动三：设定里所有百分比交互统一为滚动条

`ui/settings-pages.js` 新增 `RANGE_SPECS`（**30 项**）与 `rangeControlHtml()`：

| 类别 | 数量 | 例 |
| --- | --- | --- |
| 相似度 / 相关性阈值 | 9 | `conceptRepairSim`(0.1-0.95) · `vectorMinScore` · `rumorParallelLinkSim` |
| 比例 / 占比 | 7 | `atomsRecentRatio` · `lowUseForgetProtectImportance` · `atomCompactRatio` |
| 触发比例 / 阈值 | 8 | `stateDecayRatio` / `stateDecayCutoff` / `memoryForgetCutoff` / `parallelDecay*` / `rumorDecay*` |
| 概率 | 2 | `rumorFissionChance` · `rumorParallelLinkChance` |
| 重要性 | 2 | `importanceBase`(0-1) · `importancePerUse`(0-0.5) |
| 百分比刻度 / 总上限 | 2 | `storage.worldbookProbability`(0-100%) · `storeTotalMax`(300-20000 条) |

**默认值位置的三重提示**（用户要求「注意提示对应的默认值位置」）：
① 滚动条轨道上有一道**浅色刻度**（内联 `--ftt-range-def`，由渲染层按默认值算出百分比，CSS 用渐变画在轨道上）；
② 控件右侧文字「默认 X（滚动条上的浅色刻度）」；③ 文字输入被替换为 `output` 实时读数（拖动中即时更新）。

**范围与默认值来源**：区间取自各控件标签里已写明的口径（如「0.1-0.95」「0-1」「默认 0.45」），默认值直接读 `defaultCfg`（`controlDefault()`），**不重复硬编码**；
**计数类控件（条数 / 年限 / 楼层数）刻意保持数字输入** —— 拖动条不适合精确填写（单测 G3 断言其未被误改）。

## 7. 未做与边界

| 项 | 说明 |
| --- | --- |
| 不改保底语义 | `storeMin*`（保底）仍是逐维绝对条数，设定页照旧可填；有效上限恒 ≥ 保底 |
