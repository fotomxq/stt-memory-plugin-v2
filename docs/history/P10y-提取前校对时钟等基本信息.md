# P10y · 提取记忆前置校对：第一步校对时钟等基本信息（v2.61.0）

> 文档版本：v1.0 ｜ 日期：2026-09-26 ｜ 状态：生效（v2.61.0）
> 触发（用户要求）：「提取记忆优化，**第一步先校对时钟等基本信息**，然后再去提取。」

---

## 1. 问题（为什么需要前置校对）

| 环节 | 旧行为 | 后果 |
| --- | --- | --- |
| 时钟同步 | 只在楼层事件后**防抖**同步（1.8s），与提取互不等待 | 刚推进的剧情还没同步时钟就提取 → 合并时用**旧日期**给新条目补日期 |
| 提取提示词 | 只有【世界书参考】/【已有条目索引】/【货币账本】/【本轮对话】 | AI 不知道「今天」，无法把「昨天 / 三天后」折算成绝对日期，容易沿用错误日期 |
| 可见性 | 无 | 出问题时用户无法判断「提取时用的是哪个时钟」 |

## 2. 链路（先校对 → 再提取）

```text
📤 提取记忆 / ⚡ AI 摘要（单楼 analyzeFloor / 分段 analyzeSegment）
  ① 校对（host/preflight.js#calibrateBasics）
       · 从**最新一条非总结情节**解析日期 / 时间 / 地点 / 在场角色（时钟唯一可信来源，口径不变）
       · 落盘 state.state.* + clockSrc 来源 + 保留字段（第 N 天）
       · 尊重「消息后自动同步时钟」：关闭 → skipped='auto-off'，不覆盖用户时钟
       · 汇总【基本信息 · 提取前已校对】文本
  ② 前置（host/preflight.js#withBasics）
       · 把基本信息拼到提示词**最后一条 user 消息**之前
       · core/prompt.js#buildSummaryPrompt **保持 V1 逐字不动**（黄金样本 extract-prompt-flow P1 继续保护）
  ③ 提取（host/extract.js）AI 抽取 → mergeDelta 落库
       · 新条目缺日期 → 按 V1 口径用**已校对**的剧情日期补齐
  ④ 留痕
       · lastExtractRecord().calib / FTT.lastPreflightInfo()
       · 总览「📤 最后一次提取」一行：🕒 已校对 … / 时钟未变 … / 未校对（原因）
       · 调试日志独立类别「校对」（不挤占「时钟」类别的取值解析流）
```

## 3. 行为矩阵（已测）

| 场景 | 校对结果 | 基本信息是否进提示词 | 时钟是否被改 |
| --- | --- | --- | --- |
| 有最新带日期情节 | `changed=true`，note「已校对：1919-11-29 08:52 凉州卫-钟鼓楼」 | ✅ | ✅ 写入 |
| 已校对过再提取 | `changed=false`，note「时钟无变化：…」 | ✅ | 不改（幂等） |
| 完全没有情节与旧时钟 | `ok=false`，note「无可校对信息」 | ❌（无内容可前置） | 不改（不臆造） |
| 有旧时钟、无新情节 | `changed=false`，note「时钟无变化：1900-01-01」 | ✅（用当前时钟） | 不改 |
| 关闭「消息后自动同步时钟」 | `skipped='auto-off'` | ❌ | 不改（尊重用户） |
| 组件停用 | `skipped='disabled'` | ❌ | 不改 |

## 5. 未验证 / 风险

1. 真实 AI 是否**按**基本信息折算相对时间属模型行为，无法在单测中断言（仅保证信息确实进了提示词且时钟已校准）。
2. 校对仍严格遵循「时钟只取最新情节」的既定口径：**不**从正文解析日期（此前用户已明确要求去掉正文解析）。
   若新剧情尚未被提取成情节，本轮校对只会沿用旧时钟 —— 这是该口径的必然结果，已在 note 里如实标注「时钟无变化」。
3. 「发送前三层提取（向量/JS/AI）」的召回路径未加本前置（它不产出带日期的记忆条目）；如需要可复用 `calibrateBasics()`。
