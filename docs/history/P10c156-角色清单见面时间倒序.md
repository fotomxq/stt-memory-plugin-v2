# P10c156 · 角色清单默认按「见面时间」倒序（v3.52.3）

> 文档版本：v1.0 ｜ 日期：2026-10-28 ｜ 状态：生效（v3.52.3）
> 用户要求（原话）：「角色清单，默认按见面的时间倒序排列。」

## 1. 口径

* **默认排序**（角色页未显式选排序时）= 按「最近一次见面」倒序：
  `lastSeenDate`（角色最近一次在场的剧情日期）+ `lastSeenTime`（同日按 `HH:mm` 倒序）；
* **回落**：没有见面记录 → 用 `lastUpdateDate`（档案最近更新）；两者都没有 → 排**最后**（姓名稳定排序）；
* **不覆盖用户选择**：显式切「最新在前 / 最早在前 / 重要度 / 调用次数」时行为与以前一致；
* 排序下拉为角色页新增显式项 **「见面时间（近→远）」**，默认项文案改为「默认（见面时间近→远）」。

## 2. 实现

`ui/panel.js`：

* 新增 `snapshotSeenKey()` / `sortSnapshotsBySeen()`（纯函数；时间只取 `HH:mm(:ss)`，避免「傍晚」这类文案影响稳定性）；
* `listSortOf(kind, arr)`：`kind === 'snapshots'` 且排序为 `default` / `seen` / 空 → 走见面时间倒序；其余排序分支不动；
* `listFilterBarHtml`：角色页的排序下拉增加 `seen` 并改写默认项文案（其它维度选项不变）。

## 3. 测试

`tests/unit/snapshot-list-order.test.js`（**5 项**）：
A1 默认按见面日期倒序 · A2 同日按时刻倒序（无时刻排同日最后）· A3 无见面记录回落更新日期 / 全无记录排最后 ·
A4 显式「调用次数」排序不被覆盖 · A5 下拉出现「见面时间（近→远）」选项。

全量单测 **263 文件**（断言数按门禁实测）；`npm run gate` 全绿。

## 4. 边界

1. 只用**剧情时间**（`lastSeen*` / `lastUpdate*`），不掺现实墙钟；
2. 没有记录的角色不会被"编造"时间 —— 一律排最后，按姓名稳定排序；
3. 本版只改**列表默认顺序**与排序下拉，不改任何数据字段与归一/哈希。
