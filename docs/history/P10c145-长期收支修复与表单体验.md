# P10c145 · 长期收支修复（3 条/次）+ 保存失败保留草稿 + 表单美化（v3.51.4）

> 文档版本：v1.0 ｜ 日期：2026-10-24 ｜ 状态：生效（v3.51.4）
> 用户要求（原话）：「1. 长期收支添加，如果失败应停留在创建页面，而不是直接关闭。会导致所有信息被重置。
>   2. 长期收支添加窗口的输入需基于设计要求进行美化。3. 长期收支页面的添加，毫无意义请移除。
>   4. 长期收支页面，需增加修复按钮，可结合剧情修订、更正内容。注意每次抽取3个处理，不要全部丢给AI分析。」
> 关联：`core/deal-repair.js`（新）· `ui/panel.js` · `ui/money-tabs.js` · `style.css` · `docs/D53` §3.4/§3.9 · `docs/D54`

## 1. 保存失败**不再关闭**编辑器（需求 1）

旧行为：`panelAction('save')` 无论成败都 `ps.editing = null` → 失败后编辑器消失、重开后**所有已填内容被重置**。
现行为：`ps.editing = r.ok ? null : { kind, id, preset: fields }` —— 失败时**保留编辑态**，并把**本次表单值**作为伪 `preset`，
`prefillEditor` 对新建条目逐项回填 → 页面重绘后草稿原样还在，用户只需修正出错项再保存。

## 2. 分页按钮纠正（需求 3）

旧行为：两页共用一组按钮（收支记录里出现「新建标的物」、长期收支里出现「记一笔」）——**错位且无意义**。
现行为：`actBtns(which)` 分页给按钮 ——
* **收支记录**：`＋ 记一笔`；
* **长期收支**：`＋ 新建标的物` + **`🔧 修复（3 条/次）`**。

## 3. 添加窗口美化（需求 2，`style.css`）

编辑器统一为「标签左列 + 控件右列」的字段行（窄屏自动上下排），含：
输入框/下拉/文本域统一底色、圆角、内边距与聚焦光环；长文本域加高（约定 / 前景说明）；**节点文本域等宽字体**；
分节虚线分隔；保存/取消按钮区留白；整体加淡蓝渐变底与边框，突出「正在编辑」。

## 4. 长期收支修复（需求 4，`core/deal-repair.js` 新模块）

**核心口径：每批只取 3 条**（`DEAL_REPAIR_BATCH = 3`），不把全部条目丢给 AI。

| 阶段 | 做法 |
| --- | --- |
| 选取 | 打分排序后取前 3：缺现状(+25) / 缺约定(+25) / 缺前景说明(+20) / 无节点(+10) / **预测已到期未兑现(+40)** / 长期未动(每 30 天 +5，上限 +20) / 补齐被截断(+15)；**停摆（锚定货币失效）不进 AI 包**，只计数 |
| 打包 | 当前剧情日期 + 每条（id/名称/类型/约定/现状/货币/初始/最后变动/截止/周期/已发生近 3/预测/前景）+ 正文节选（`cfg.repairFloors`，截 8000 字） |
| 提示词 | **窄契约**：只回一个 JSON；id 必须来自包内；`nodes` 只追加**已发生**事实；`forecast` 是**预测**且 `source=ai`；不编造 |
| 机械校验 | 未知 id 整条跳过；节点**不得晚于当前剧情日期**、**必须晚于最后变动**、去重；预测**必须晚于最后变动**；`direction` 与 `delta` 矛盾**以符号纠正**；描述类字段截断 |
| 落库 | 只改 `desc`/`status`/`outlook.text`/`nodes`(追加)/`forecast`；**不动** `id`/`currencyId`/`trigger`；`updatedAt` 刷新（跨端取新）；`normalizeDeal` 复核后写回 |
| 失败 | AI 不可用 / 占用 / 空池 → **不改任何数据**，摘要如实说明；无自动重试 |

**安全边界**：`forecast` 始终标记 `source: 'ai'`（界面显示「AI 建议」）；预测内容**绝不写进 `nodes`**（「预测≠事实」）；
锚定货币失效的条目需要人工重指货币（AI 不改引用）。

## 6. 边界

1. 修复**不改锚定货币**（需要人工重指）：停摆条目只计数不修；
2. 修复不改 `kind`/`cycle`/`startDate`（结构性字段需人工判断）；
3. 每批 3 条是**常量**（不是配置项）：避免用户在界面调成「一次全量」而违背设计；
4. 修复**不自动定时执行**（只有用户点按钮才跑），避免与提取管线抢额度。
