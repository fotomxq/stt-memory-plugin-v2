## 1. 真正的根因：入口**自己会消失**

| 环节 | 事实（带证据） |
| --- | --- |
| 入口显隐 | `ui/resume-batch.js#resumeBatchButton()` 原判据：`if (!cands.length) return '';` |
| 候选口径 | `core/resume-batch.js#resumeBatchCandidates()`：记忆**必须有日期**，且日期落在**当前剧情日期**往前 `resumeBatchDays`（默认 30）天内；无日期的记忆**刻意不计入**（避免把远古条目当"近期"） |
| 时钟来源 | `resumeClockDate()` = 剧情日期，**回落到最新有日期条目的锚点**（`ageAnchorDate`）；两者都没有 → 空 |
| 后果 | 剧情日期空 / 记忆无日期 / 推进出窗 / 记忆被清理 / 归属名字对不上 —— **任一**即候选为空 → 入口**整块不渲染** |
| 致命处 | 空态里**写了**原因与做法（「可调大窗口天数，或先用⚡立即 AI 摘要更新记忆」），**但它在面板里，而面板要靠这个按钮才能打开** → 用户既看不到入口也看不到原因 → 体感 = **功能发版后消失** |

> 这一类缺陷的通用形态值得记下来：**「入口的显隐条件」比「入口背后的内容」更严** ——
> 于是「内容为空」时用户永远看不到「为什么为空」。凡「空态文案 + 条件性入口」的组合都要查一遍这一条。

## 2. 修法

### 2.1 入口恒显（只看开关）

```js
if (!conf.enabled) return '';                                  // 功能开关
if (cfg && cfg.snapshotResumeEnabled === false) return '';      // 隶属总开关
// 不再看候选数
let n = 0; try { n = resumeBatchCandidates({}).length; } catch (e) { n = 0; }
const badge = n ? ('（' + n + '）') : '';                        // 有候选 → 条数角标
```

* 有候选：`📜 批量完善履历（3）`，title 写「抽出 3 名相关角色…」；
* 无候选：`📜 批量完善履历`，title 写「当前**没有**落在窗口内的候选角色：点开可见原因与调法」；
* **开关关闭时仍然不渲染** —— 恒显 ≠ 无视开关（两条断言各锁一个方向）。

### 2.2 成因如实说明（内核给事实、界面写措辞）

新增 `core/resume-batch.js#resumeBatchWindowInfo(opts)`（**纯函数**，可直测）：

```js
{ days, storyDate, memories, dated, inWindow, candidates, codes: ['no-story-date', 'undated-memories', …] }
```

成因码：`no-memories` · `no-story-date` · `undated-memories` · `out-of-window` · `no-name-hit`（可多条同时成立，按「先因后果」排序）。

`ui/resume-batch.js#emptyCandsHtml()` 把码翻成人读原因 + **可执行下一步**，并给出窗口读数：

```text
窗口内没有候选角色（窗口 30 天 · 记忆 12 条 / 有日期 5 条 / 窗口内 0 条）。
有 7 条记忆没有日期（5 / 12 条有日期）—— 无日期的记忆不计入窗口；跑一次「⚡ 立即 AI 摘要」可补上日期。
本入口恒显（不再因「暂无候选」而消失）；这些参数在 设定 → 投喂范围 → 「📜 履历批量」。
```

**分层**：core 只说事实（计数 + 成因码），用户措辞留在界面层 —— 与仓内既有分层一致（core 不写 UI 文案）。

## 3. 顺带立一道兜底：功能清单基线锁

| 件 | 内容 |
| --- | --- |
| `scripts/feature-inventory.json` | 七类用户可见清单的**基线快照**（动作 / 控件 / 配置键 / 分页 / 维度 / 调试桥方法数 / 词条键） |
| `tests/unit/feature-inventory.test.js` | **只对「基线有、现状没有」判红**；新增项**不挡**（只提示跑 `--write`）；基线规模有下限（防「基线被清空 → 门禁静默全绿」）；含三条反向探针 |
| 报错形态 | `消失：resumeBatchApply ← 若确为有意移除，先在 docs/D22 登记再跑 --write 刷新基线`（**指名道姓**，不靠人去猜） |

它补的正是本轮暴露的空档：现有门禁（体量 / 静态 / 单测 / 台账）**不会**因为「少了一个按钮」而变红，除非刚好有测试覆盖它。

## 4. 测试

| 文件 | 断言 | 锁什么 |
| --- | --- | --- |
| `tests/unit/resume-batch-visible.test.js`（新） | 15 | A：四类无候选态入口都在 + 两种开关关闭才隐藏；B：有候选角标 / 无候选 title；C：成因码逐条 + 窗口读数 + 面板可读原因与下一步；D：零候选也能打开；E：反向探针 |
| `tests/unit/feature-inventory.test.js`（新） | 15 | A：基线存在与规模下限；B：七类清单无静默移除；D：用户报告的那一条在位（含「不再按候选隐藏」的源码判据）；E：基线自维护；F：三条反向探针 |

**反向探针（实跑留档）**：

* 把 `data-ftt-action="resumeBatchApply"` 改名 → 基线锁**当场报红**并指名 `resumeBatchApply`（已删回）；
* 把入口恢复成「候选为空即返回空串」→ `resume-batch-visible` A1/A3/A4 变红；
* 让 `resumeBatchWindowInfo().codes` 恒返回空数组 → C1 变红。

**测试期踩到的真实细节（留档）**：`resumeClockDate()` 会**回落到最新有日期条目的锚点** ——
所以「无剧情日期 + 有日期记忆」**仍可能有候选**；要构造「确定零候选」须用「记忆库为空」或显式传 `nowDate`。
该细节已写进测试注释与 `resumeBatchWindowInfo` 的 `opts.nowDate`（也是它存在的理由：可测性）。

## 5. 边界（如实登记）

1. **不改批量算法与候选口径**：`应-33` 的落地口径（窗口 / 命中 / 一次请求一批 / 机械复核 / 只读预览 / 确认落库）**一字未动**。
2. **不改时钟巡检与记忆日期补全链路**：它们是「没有候选」的上游成因，本轮只**讲清楚并指路**。
3. **其它条件性显隐入口保持原设计**：「🔧 修复物品」需有物品、「🧹 清理传言」需有传言、「🛠 修复角色」需有角色等 ——
   这些是「没有对象就没有动作」的合理隐显，与「开关型隐藏」不同；现已全部纳入基线锁。
4. **审计范围**：`v3.46.7 → v3.48.0`（含本仓多会话并行期间的全部发版）；更早版本不在本轮范围。
