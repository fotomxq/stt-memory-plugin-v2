# P10c158 · 角色清单排序修复：排序真正生效 + 「最近提及」优先（v3.52.5）

> 文档版本：v1.0 ｜ 日期：2026-10-28 ｜ 状态：生效（v3.52.5）
> 用户报告（原话）：「角色清单倒序，是最近提及的在前面，搞反了。」
> 关联：`ui/panel.js`（`dimBodyList` / `listSortOf` / `snapshotSeenKey`）· `docs/history/P10c156`

## 1. 根因（两处，叠加成「看起来倒过来了」）

1. **排序选项从未生效**：`listSortOf(kind, arr)` 只有**状态页**调用；列表页（含角色页）直接渲染
   `listOfInfo()` 的结果 —— 后者固定用 `sortRecentByStoryDate`，角色档案没有 `date` 字段 → 退化为
   `floorEnd` 兜底；多数档案 `floorEnd = 0` → 再退化为**容器入库顺序（最早的在前）**，即用户看到的「反了」。
   v3.52.3 新增的「见面时间倒序」因此**根本没有接上渲染路径**。
2. **只看 `lastSeenDate`**：档案**刚被更新/提及**（`lastUpdateDate` 较新）但没"见面"时，排序不动 ——
   与用户要的「**最近提及**的在前」不符。

## 2. 修复

* `ui/panel.js#dimBodyList`：对 `listOfInfo` 的结果执行 **`listSortOf(kind, …)`** —— 所有列表的
  「默认 / 最新在前 / 最早在前 / 重要度 / 调用次数」从此真正生效（非角色页的 `default` 是恒等，行为不变）；
* `snapshotSeenKey()`：取 **`lastSeen` 与 `lastUpdate` 中较晚者**（日期比较后取对应该日期的时刻），
  即「见面」或「被提及/档案更新」任一更新 → 该角色顶到前面；
* 角色页默认排序仍为「最近在前」，排序下拉仍是「默认（见面时间近→远）/ 见面时间（近→远）/ …」。

## 3. 测试

`tests/unit/snapshot-list-order.test.js` 5 → **7 项**：
A6 **排序选项真正生效**（默认 / 重要度 / 最早在前 三种结果按预期变化）·
A7 **最近提及优先**（`lastUpdateDate` 比 `lastSeenDate` 新 → 以更新时间为准）。

全量单测 **263 文件 / 3899 断言**；冒烟 224 项；`npm run gate` 全绿；体量基线 `ui/panel.js` 3752 → **3762**。

## 4. 边界

1. 时间仍只取**剧情时间**（`lastSeen*` / `lastUpdate*`），不掺现实墙钟；
2. 两者都没有的角色排最后（姓名稳定排序），不编造时间；
3. 本次把「排序选项生效」修正为**全列表通用**（此前除状态页外均无效）—— 属行为修正，`default` 对其它维度仍是恒等，不改变其默认顺序。
