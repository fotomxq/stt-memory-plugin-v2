## 1. 问题：首屏「入口已装、数据未读」的窗口

`index.js#init()` 的实际顺序：

```text
probe / cfg / 桥接 / i18n
  → 装入口（扩展菜单项 syncEntriesNow、浮层兜底、popupHooks）
  → await loadMemoryState()        ← 读本机缓冲 / 服务端文件 / 聊天元数据 + 合并 + 迁移 + 注入内核
  → 事件接线 / 启动检查
  → runtime.ready = true
```

于是从「插件在界面上可见」到「数据读完」之间存在一段窗口（慢盘 / 大存档 / 宿主 API 慢时更明显）：
此时内核 `state` 还是空的（或上一次作用域的残留），用户点开面板会看到

- **总记忆数 0、待分析 0 层**一类**残缺视图**（看起来像「数据没了」，实际只是没读完）；
- 动作（提取 / 修复 / 保存 / 清空注入 …）**基于不完整数据执行**，其中「保存」类动作有把不完整状态写回存档的风险；
- 极端情况下页面还会抛出「读 undefined 的属性」一类渲染异常。

## 2. 修法

### 2.1 内核闸门（`core/model/runtime.js`）

```text
loadGate.phase: 'idle'    默认：**未开始过载入** → 不拦截（既有行为 / 外部接口 / 既有测试口径完全不变）
              | 'loading' 首屏载入进行中 → **拦截**
              | 'ready'   载入结束 → 正常展示
              | 'failed'  载入失败 → **也放行**（绝不把用户永久挡在门外，调试页仍可查原因）
loadBlocked()   = (phase === 'loading') 且未超过超时兜底
loadGateInfo()  = { phase, blocked, startedAt, finishedAt, waitedMs, via, items, note, error, timeout }
```

`setLoadPhase('loading')` 记开始时刻；`'ready' | 'failed'` 记结束时刻与总耗时。内核零宿主依赖 —— UI 与 `index.js` 各自读它。

### 2.2 三处 UI 同源拦截

| 位置 | 表现 |
| --- | --- |
| 浮层面板正文（`ui/panel.js#panelBodyHtml` → `loadGateHtml()`） | 13 个分页**全部**只渲染：「⏳ 正在读取数据…（已等待 N 秒）」+「首屏数据尚未读完：**暂不展示内容、也不执行任何动作**，以免基于不完整数据出错」+「读完后本页会自动刷新；若长时间没有变化，请刷新页面或到『设定 → 调试』查看读取台账」 |
| 面板标题栏 | 把「总记忆数 N」换成 `⏳ 读取中…` 胶囊（此刻计数必为 0，显示出来只会误导）；标签条保留（可切页，每页都是提示） |
| 抽屉卡片（`ui/settings-panel.js#statusBlockText`） | 只报「版本 / 作用域 + ⏳ 数据读取中…」，不显示注入字数 / 待分析楼层等残缺读数 |

### 2.3 动作拦截（`ui/panel.js#panelAction`）

读取期间除 `close` / `tab`（关闭与切页）外**一律拒绝**：

```text
setNote('数据仍在读取中，请稍候…') + panelNotify('info', …)  →  done({ ok:false, reason:'loading' })
```

拒绝发生在动作分支**之前** —— 因此**不会触达任何钩子**（AI 调用 / 修复 / 保存 / 导出都碰不到），
单测用「钩子调用计数 === 0」把这一点钉死。

### 2.4 读完自动展示（`index.js`）

```text
setLoadPhase('loading')  → 同时刷新抽屉卡片状态
await loadMemoryState()
  ├─ 成功：setLoadPhase('ready', { via, items }) + 调试日志（kind='载入'，含 waitedMs 与自愈摘要）
  └─ 失败：runtime.lastError 留档 + setLoadPhase('failed', { error })
if (panelOpen()) renderPanel()      ← 把已经打开的浮层从「读取中」换成真实内容
setPanelStatus(...) + refreshPanelStatus()   ← 抽屉卡片同步
```

`teardown()` 里复位为 `idle`（避免把「读取中」带到下一次装配）。

## 3. 超时兜底（写测试时发现的真实风险）

闸门若只认「载入完成」这一个信号：宿主某个读取 API **挂起**（promise 永不 settle）时，
`phase` 永远是 `loading` → **界面被永久拦住**（比残缺视图更糟）。

故引入 `LOAD_GATE_MAX_MS = 20000`：

- 拦截期内超过 20 秒 → `loadBlocked()` **自动放行**（`phase='ready'`、`timeout=true`、`note='读取超时…'`）；
- 提示文案与调试日志如实写明「数据可能不完整」，不假装成功。

| 单元测试 | ✅ **142 文件 / 2183 断言** |
| 冒烟测试 | ✅ **206 项** |
| 内核纯净度 / 标识符 / 词条 / 版本一致 / 文档 / 本地隐私 / 变更日志 | ✅ 0 违规 |

**本版被自己的测试抓出的缺陷（如实登记）**：`init()` 里写「自愈摘要」时误引用了 `loadMemoryState()` 内的局部变量
`healInfo`（作用域错误）→ `ReferenceError` 被载入的 `catch` 吞掉，载入被判 `failed`（数据其实已注入，但闸门会走失败分支）。
冒烟 `BP1` 的 `readyOk` 断言（要求真实 `init()` 后 `phase='ready'`）当场暴露 → 改为从 `lastHealInfo()` 取值。

## 5. 未验证项（如实登记）

- **真机上「刷新后立刻点开入口」的那一瞬间未实际捕捉**：闸门逻辑由单测（10 项）+ 冒烟端到端覆盖；
  用户刷新后在读取期点开入口应能看到提示，读完自动切换（本次发版后需用户刷新页面实测一次）；
- **20 秒超时兜底未在真机触发**：需要宿主某个读取 API 真的挂起才能复现（桩环境用「把 startedAt 拨到 20 秒前」覆盖）；
- 本次**未给调试桥新增方法**（如 `ftt.loadGate`）：真机核对入口仍是面板提示 + `设定 → 调试` 的读取台账与调试日志
  （`kind='载入'` 的那条会写 `waitedMs`）；若后续需要端口级核对，再补一个只读方法。
