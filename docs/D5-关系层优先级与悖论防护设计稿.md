# D5 · 关系层优先级与悖论防护设计稿

> 文档版本：v0.1 ｜ 日期：2026-09-27 ｜ 类型：**设计稿（不发版）** ｜ 状态：草稿（待评审）
> 触发（用户原话）：「为了确保关系层不会造成紊乱悖论，如 A 变 B、B 变 A，需在设计稿中明确关系层的优先级。请设计和梳理构建。」
> 前置：`D1`（现状与缺口）、`D2`（边 + 约束的数据模型）、`D4`（联动与传播）
> 定位：**D2 定义数据、D4 定义传播、本文定义「谁说了算」** —— 即冲突与悖论出现时的**唯一裁决顺序**。

---

## 0. 一页摘要

**问题**：今天「优先级」零散存在于四处，彼此不知道对方：

| 既有裁决 | 口径 | 落点 |
| --- | --- | --- |
| 认知可靠度 | `how` 排序：策划/当事人 ≥ 亲历 > 目击 > 被告知 > 推断 > 传闻 | `core/model/rel.js:200`、`ui/rel-table.js:48` |
| 删除恒胜 | 双墓碑（id + 内容哈希）；对端条目时间 ≤ 墓碑即删 | `core/merge.js:98/110/123` |
| 跨端同 id 冲突 | 内容哈希 → 条目 `updatedAt` → **存档级时间戳** → 平局**远端优先** | `core/cross-sync.js:141-146` |
| 约束冲突（设计） | `hard > soft` → `manual > ai > mech > inferred` → 时间新 → 保守合并 | `D2` §4.3 |

**缺的是**：① 统一的**裁决链**；② **边的方向归一**（同一条关系被双向写两次）；③ **环检测**；④ 传播层的**单调性**（禁止 A→B→A 回写）；⑤ 明确的 **tie-break**（今天平局用「谁在远端」——**这不是确定性函数**）。

**主张**：给出 **五级裁决链 L0–L4 + 四类归一规则 + 六项悖论检测 + 三条单调性不变量**，并把「平局裁决」从「远端优先」改为**内容哈希字典序**（确定性、两端收敛）。

**顺带发现一处现存隐患**（`core/cross-sync.js:141-146`）：同一 id、同 `updatedAt`、内容不同且**两端都在 base 之后改动过**时，
两端各自判断「远端更新」→ **互相取对方 → 振荡不收敛**。`links` 的 `updatedAt` 归一时默认 `0`（`core/model/rel.js:38`），使平局更容易发生。**本轮只登记，不改代码**。

## 1. 紊乱的六种形态（先把问题定义清楚）

| # | 形态 | 例子 | 今天会怎样 |
| --- | --- | --- | --- |
| ① | **对称双写** | A 与 B 同时建立 `co-occur`，各自存一条 | 两条并存；去重键含方向 → 永不收敛为一条 |
| ② | **反向断言** | `A before B` 与 `B before A` 同时 active | 两条都"有效"，无人判定 |
| ③ | **有向环** | `A caused B caused C caused A` | 静默接受；因果推理失去意义 |
| ④ | **传播震荡** | D4 传播中 A 变触发 B、B 变又触发 A | 靠「已处理集合 + 上限」勉强止血，语义未定义 |
| ⑤ | **同源冲突** | 同 subject+kind 的多条约束/事实相互矛盾 | 只有 `D2` §4.3 的草案，未落地 |
| ⑥ | **跨端平局** | 同 id 同 `updatedAt`、内容不同，两端都在 base 后改过 | **互相取对方 → 振荡**（§0 隐患） |

**共同根因**：没有**全序**。只要存在「无法比较」的情形，实现就会回落到「本地优先 / 先到先得 / 数组下标 / 随机」，而这些都**破坏两端一致性**。

## 2. 优先级链（核心：L0 → L4，严格按序判定）

判定**永远从 L0 开始**，能定则止；只有上一层完全打平时才下探下一层。

| 层 | 名称 | 规则 | 说明 |
| --- | --- | --- | --- |
| **L0** | **存在性** | **删除恒胜** | 墓碑（id 墓碑优先，内容哈希墓碑次之）覆盖一切：对端条目时间 ≤ 墓碑时间即删（`core/merge.js:98/110/123`）。**唯一能压过 L1–L4 的层级** |
| **L1** | **强度 / 状态** | `hard > soft`；`confirmed/active > pending > expired > retracted` | 硬约束压软约束；有效压待生效压失效压已撤销。墓碑已由 L0 处理，本层不重复 |
| **L2** | **权威（来源 × 维度）** | 先比 `source`，再比**维度权威序** | `manual > ai(带 evidence) > mech(派生) > inferred(推测)`；`ai` **无 evidence 一律拒收**（`D2` R1）。维度序见 §2.2。**人工永远压过 AI**，哪怕维度权威更低 |
| **L3** | **事实时间** | 剧情时间**新 > 旧** | 仅在同 L0–L2 层内使用。**禁止**用时间推翻因果方向：`A caused B` 不因 B 的日期更新而反转 |
| **L4** | **确定性 tie-break** | **内容哈希字典序**（小者胜或大者胜，二者择一并全局统一） | **禁止**使用：本地优先 / 远端优先 / 先到先得 / 数组下标 / 随机 / `updatedAt` 相等时看谁先跑。这是两端收敛的唯一保证 |
| 兜底 | —— | **保留双条 + 标 `conflicted` + 按最保守口径使用** | 永不静默丢一条；冲突进 finding 清单（§4） |

### 2.1 关于 L2 的「来源」序

| source | 含义 | 是否可覆盖 |
| --- | --- | --- |
| `manual` | 用户手工建立 / 编辑 | 最高 |
| `ai` + `evidence` | AI 产出且带楼层 / 原子锚点 | 次高 |
| `mech` | 机械派生（从既有引用字段推导） | 中 |
| `ai` 无 evidence | —— | **拒收**（不入库，不是"低优先级"） |
| `inferred` | 保守推断 | 最低（可被任何来源覆盖，且优先被替换） |

### 2.2 维度权威序（跨维度同事实冲突时）

```text
事实层   atoms（情节）            ← 最高：已发生的事实
身份层   snapshots（角色档案）
状态层   currentStates（状态记录）
计划层   plans / suspense（计划与悬念）
认知层   memories / links（谁知道、认知偏差）
推演层   parallels（未发生，可被事实作废）
传言层   rumors（二手、可失真）    ← 最低
不参与   plotSegments（只归档不注入） / currencies（独立账本）
```

**组合规则**：先 `source`，后维度序，**不混合比较**（避免「人工的传言 vs AI 的情节」这种跨层比较）。
若两条断言的 `source` 相同但维度不同 → **低权威维度不得覆盖高权威维度**（如推演不得改写情节），只能**标记受影响**（对应 `D4` 的 `mark` / `dissolve`）。

### 2.3 与「认知可靠度」的关系

`REL_LINK_HOW_RANK`（`core/model/rel.js:200`）与 `HOW_ORDER`（`ui/rel-table.js:48`）是**同一维度内**的可靠度序，
用途是排序与展示 —— 它**不是** L0–L4 的替代品。本文规定：**同维度内同 source 的多条，按既有可靠度序裁决**（该序并入 L2 的维度内比较）。

## 3. 边的方向与归一（专治 A↔B）

### 3.1 三类边

| 类别 | 例 | 方向语义 | 存储规范 |
| --- | --- | --- | --- |
| **对称** | `co-occur`（同场）、`mirrors`（镜像） | 无方向 | **canonical 化**：端点排序后存一条；`id = hash(type + min + max)` |
| **有向** | `caused`、`before`、`knows`、`owns`、`located-at`、`member-of`、`derived-from` | 有方向 | `id = hash(type + from + to)`；方向不同 = 不同关系 |
| **互为反向**（反对称对） | `before` / `after`、`owns` / `owned-by` | 同一关系的两个视角 | **只存规范方向**（约定 `before`、`owns` 为规范形式）；反向写法一律归一为规范方向，**不产生第二条** |

### 3.2 归一规则（N1–N5）

| # | 规则 | 处理 |
| --- | --- | --- |
| **N1** | 同 type **反向**重复 | 对称边 → 合并为 canonical 一条；有向边 → 视为**反向断言**（§4 检测项 ②），按 L0–L4 裁决，兜底保留双条 |
| **N2** | 同 from/to、不同 type | **合法**（`A caused B` 与 `A before B` 是两条关系） |
| **N3** | 自环（`A → A`） | **非法，拒收**（`knows` 自身的"自知"由字段表达，不建边） |
| **N4** | 端点失效（被删 / 不存在） | 边保留但标 `orphan`，进死链清单（沿用 `relOrphanStats` 口径，`core/model/rel.js:96-115`） |
| **N5** | 同 id 内容不同（hash 碰撞或历史脏数据） | 不覆盖：按 L0–L4 裁决，兜底双条 + finding |

## 4. 悖论检测（六项，均为可判定子集）

| # | 检测 | 判据 | 输出 | 今天 |
| --- | --- | --- | --- | --- |
| ① | 对称双写 | 同 type 反向两条并存 | finding（可**自动归一**） | 无 |
| ② | 反向断言 | `A before B` 与 `B before A` 同时 `active` | finding（按 L0–L4 裁决；兜底双条） | 无 |
| ③ | **有向环** | `caused` / `before` / `member-of` / `derived-from` 的环（DFS，深度上限 ≤12） | finding（**只报告，不自动断环**；环上边全部标记） | 无 |
| ④ | 约束互斥 | 两条 `exclusivity` 的 subject 同时 `active`（`D2` §3.3） | finding（hard 冲突 → L2 裁决） | 无 |
| ⑤ | 时序倒挂 | `caused` / `before` 两端剧情时间与方向相反 | finding（按 L3 校正或报告） | 无 |
| ⑥ | **跨端平局** | 同 id、同 `updatedAt`、内容哈希不同 | 按 **L4 确定性键**裁决（现状是"远端优先"→ 振荡） | 有隐患 |

**统一 finding 形状**：`{ id, kind, severity, scope, subjects[], path[], message, suggestedFix }`。

**三条硬约定**：
1. **只报告不改数据**（沿用 `D2` N4）；
2. **永不抛错 / 永不阻塞**注入、生成、提取（沿用 B1 口径）；
3. 检测结果进质检报告与「设定 → 约束」的冲突面板（`D4` R4）。

## 5. 传播层的优先级与单调性（接 `D4`）

### 5.1 同一跳内多动作命中同一条目

按强度取一（强压弱），同级**合并**：

```text
dissolve（作废） > narrow（收窄） > recompute（重算） > advance（推进） > mark（标记） > annex（留痕）
```

### 5.2 单调性三律（**防「A 变 B、B 变 A」的核心**）

| # | 律 | 含义 | 违反后果 |
| --- | --- | --- | --- |
| **M1** | **权威单调** | 传播只从**高权威指向低权威**（事实 → 身份 → 状态 → 计划 → 认知 → 推演 → 传言）；**低权威不得反向改写高权威**（传言不得改情节、推演不得改事实） | 低位数据污染事实层 |
| **M2** | **时间单调** | 只沿**剧情时间向前**传播；新事件**不得改写历史事实**，只能追加或标记 | 历史被反复重写 → 振荡 |
| **M3** | **单向遍历** | 同一条边在一轮传播中**只走一次**（`D4` 的「已处理」集合）；**禁止沿反向边回写源**（A→B→A 直接禁止） | 无限往复 |

**收敛保证**：M1 + M2 + M3 与 `D4` 的有界（I3）、幂等（I1）、确定性（I2）合起来，保证**一轮传播必然终止，且两端得到同一结果**。

### 5.3 受控「晋升」（低权威 → 高权威的**唯一**合法路径）

只有两种，且都是**晋升**（产生新事实）而**不是改写**：

| 晋升 | 方向 | 条件 |
| --- | --- | --- |
| 平行转正 | 推演 → 事实 | 用户显式点击（既有 `promoteParallelEvent`，`core/parallel.js:498-548`） |
| 传言证实 | 传言 → 事实 | 由 `atoms.confirm` 触发（`D4` §4），写的是**事实条的标记**，不改传言正文 |

## 6. 速查表

**表 1 · 裁决链**：L0 删除恒胜 → L1 强度/状态 → L2 来源×维度 → L3 剧情时间 → L4 内容哈希字典序 → 兜底双条 + finding。

**表 2 · 维度权威序**：`atoms > snapshots > currentStates > plans/suspense > memories/links > parallels > rumors`（`plotSegments` / `currencies` 不参与）。

**表 3 · 动作强度序**：`dissolve > narrow > recompute > advance > mark > annex`。

**表 4 · 边类型属性**：

| 边 | 方向性 | 可成环 | 反向重复的处理 |
| --- | --- | --- | --- |
| `knows` / `knows-not` | 有向 | 否 | 不同角色 → 不同边（合法）；同角色反向 → 冲突（L1 状态裁决） |
| `caused` | 有向 | **是（重点检测）** | 反向 = 反向断言 → 冲突 |
| `before` | 有向（反对称） | **是** | 反向 = 同一关系 → 归一；与 `after` 同向 → 冲突 |
| `co-occur` | 对称 | 否 | 反向 = 同一关系 → canonical 合并 |
| `owns` / `located-at` / `member-of` | 有向 | `member-of` 可 | 反向 = 不同关系（若语义上互斥 → 冲突） |
| `derived-from` | 有向 | **是（重点检测）** | 反向 = 互为来源 → 冲突（`D2`：来源不得互为来源） |
| `mirrors` | 对称 | 否 | canonical 合并 |

## 7. 分阶段落地

| 阶段 | 范围 | 动数据模型 | 交付 | 回退 |
| --- | --- | --- | --- | --- |
| **W0** | **只读检测器**：六项检测（§4）跑通并输出 finding 清单（调试页 / 设定 → 约束） | 否 | 第一次看见「当前库里有哪些悖论」 | 关开关即消失 |
| **W1** | **归一化**：对称边 canonical 化 + 稳定 id 统一 + 自环拒收（N1/N3） | 否（仅规范化写入） | 对称双写不再产生重复 | 恢复旧写法 |
| **W2** | **裁决器**：L0–L4 落地为**单一写入/合并入口**（跨端合并、导入、AI 落库共用） | 否 | 同源冲突有唯一结果 | 逐层开关 |
| **W3** | **传播单调性**：`D4` 引擎接入 M1–M3（权威单调 / 时间单调 / 单向遍历） | 否 | A→B→A 在语义上被禁止 | 退回「已处理集合」止血 |
| **W4** | **跨端 tie-break 修正**：平局改用 L4 确定性键（**会改变既有平局行为**，需迁移说明） | 否 | 两端不再振荡 | 保留旧口径开关（短期） |
| **W5** | **UI**：冲突面板（六项检测结果 + 一键归一 + 手工覆盖） | 否 | 用户可干预 | 隐藏入口 |

> **建议起点**：**W0**（零风险、零模型改动）—— 先让悖论可见，再谈裁决。

## 8. 风险与对策

| # | 风险 | 对策 |
| --- | --- | --- |
| R1 | 优先级链被绕过（新代码直接写 `state`） | 收敛到**单一写入 / 合并入口**（`D2` §3.5），并加审计（写入路径可追踪） |
| R2 | 过度裁决导致**丢数据** | 兜底永远「保留双条 + 标记」，绝不静默丢 |
| R3 | 环检测性能 | 只对强类型边（`caused` / `before` / `member-of` / `derived-from`）；深度上限；惰性 + 缓存 |
| R4 | L4 变更影响**既有跨端行为** | 单列迁移说明 + 专测（同 id 同时间不同内容 → 两端结果一致） |
| R5 | 与 V1 口径冲突 | V1 无此模型 → 登记为**有意扩展**（`docs/勘误` 与测试显式归一） |
| R6 | 优先级链过复杂、用户不可解释 | 速查表（§6）+ UI 明示「这条为什么胜出」（finding 带裁决理由） |

## 9. 待确认（Q1–Q6）

| # | 问题 | 建议默认 |
| --- | --- | --- |
| Q1 | 维度权威序是否符合预期？尤其 `snapshots > currentStates`、`memories/links` 低于 `plans` | 按 §2.2 表；有异议只需调整该表顺序 |
| Q2 | 因果环（`caused` 成环）只报告还是**硬阻断**？ | **只报告**（不自动断环，避免误砍用户数据） |
| Q3 | 对称边是**物理归一**（只存一条）还是**逻辑归一**（存两条、读时归一）？ | **物理归一**（写入口 canonical 化），历史数据由 W1 一次性归一 |
| Q4 | L0–L4 全部打平时：**保留双条**还是**取更新者**？ | **保留双条 + 标记**（信息不丢，宁可可见冲突） |
| Q5 | 是否允许用户**手工指定优先级覆盖**（如"这条永远压过那条"）？ | 允许，但仅限 `manual` 来源，且需在 UI 明示 |
| Q6 | 跨端 tie-break 改为确定性键（W4）是否接受？它**会改变既有平局行为** | 接受；用专测锁定「两端同结果」 |
