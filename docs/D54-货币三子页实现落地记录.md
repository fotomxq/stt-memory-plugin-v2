## 2. 与 `D53` 的口径偏差（如实登记）

| # | `D53` 原文 | 实际落地 | 原因 |
| --- | --- | --- | --- |
| 1 | 账本受 `storeMaxLedger` 约束、超出进冷存 | 账本/长期收支**完全跳过按条数裁剪**（`enforceDimCaps` 显式排除），上限仅作**展示** | 冷热分层的在线切换尚未落地（`数-25` 仍 ⛔ 待裁决）；当前直接遵守 `D28`「语义数据不删」 |
| 2 | 账本/长期收支参与「总上限 × 占比」分配 | 占比 **0**（有效上限 0），占比合计仍恒 100 | 同上：不参与分配 → 不裁剪；避免凭空多出 2 条上限 |
| 3 | 界面「＋记一笔」必须先选货币 | 记账入口走既有**编辑器**（`kind=ledger`）；**v3.51.2 起货币字段是下拉选择**（选项 = 当前现存货币；无货币时如实提示「请先在货币总览新增」） | 复用既有新增/编辑/删除流程，不新造表单状态机；`currencyId` 必填由归一强制（无主流水被拒绝） |
| 4 | 长期收支详情支持编辑 | **v3.51.2 起**详情行有「✏ 编辑」入口（收支记录行同样有）→ 走既有编辑器（`kind=deals`）；节点支持 **JSON 或逐行「日期\|金额\|说明」**，解析失败/缺必填项**给出具体原因** | 同上 |

> 这四条都**不改变** `D53` 的数据契约与安全口径（必挂货币 / 级联删除 / 预测与事实分开 / 触发器无 AI），只影响「谁来做表单」与「上限如何生效」。

## 3. 关键不变量（单测锁定）

1. **记账必须挂现存货币**：不存在 → 拒绝，**不自动新建**；
2. **幂等**：`led_<hash>` 与 `dealId + 节点日期` 双重去重（重跑 / 多端不重复扣款）；
3. **级联删除**：货币消失 → 其流水逐条墓碑并移除，**不留孤儿**；`deals` 不删（触发器停摆）；
4. **预测 ≠ 事实**：`outlook.nodes` 与 `outlook.forecast` 分字段；界面分区；体检报「预测被当真」；
5. **触发器全程无 AI**：只做日期数学 + 写库，返回值显式 `noAi: true`；
6. **上限可配**：摘要 60 笔（10–200），账本长期只增。
