## 0. 一页摘要

**三域是什么、为什么它们天然互相解释**：`rumors`（传言 = 未证实信息）· `plans`（计划 = 未完成的意图）· `suspense`（悬念 = 未揭晓的疑问）
都是「**未来向 / 未决**」条目（`docs/01-业务架构.md` §2.1 的维度表把计划、悬念、传言并列归入此类）。三者互为因果是常态：
传言说的可能是某个计划，计划受阻会强化悬念，悬念揭晓会让传言被证实或证伪。

**现状 = 三域之间几乎不连通**（只读核对，逐条带证据）：

| # | 结论 | 证据 |
| --- | --- | --- |
| **①** | 关联行的**锚点维度白名单只有 4 类**（记忆 / 计划 / 悬念 / 平行），**传言不在其中** | `core/model/rel.js#REL_LINK_DIMS`、`core/entries.js#REL_LINK_DIMS`、`core/recall.js#REL_LINK_DIMS`（**同一常量三处各写一份**） |
| **②** | 因此**今天无法用一行关联表达「传言 r1 与计划 p1 相关」**；传言唯一的跨域出口是「与平行事件的标签相似度」 | `core/model/rel.js#normalizeRelLink`（dim 不合法即返回 null）· `core/rumor-evolve.js#rumorParallelLinkScore` / `#rumorParallelLink` |
| **③** | 计划 ↔ 悬念**两侧各有独立字段**（计划侧 `suspenseRefs`、悬念侧 `planRefs`），但**全仓没有任何镜像维护函数**：一侧填写不会补另一侧 | `core/model/dims.js#normalizePlan` / `#normalizeSuspense` · `core/relations.js#deriveRelations`（只读派生 `member-of`） |
| **④** | 关联（边）是**只读派生视图、不落库**：由 `state.links` 锚行与各域私有引用字段现算 → 想让「关联特性」变化，**只能写这两类载体** | `core/relations.js#deriveRelations` / `#dependents` · `core/model/relation.js#REL_TYPES`（10 类词表中 7 类 `derived: true`） |
| **⑤** | 计划 / 悬念的 `history` 与传言的 `chain` **参与内容哈希** → 联动留痕属期望的跨端更新，不是抖动 | `core/model/hashfields.js#HASH_FIELDS`（`plans` / `suspense` 含 `history`、`rumors` 含 `chain`）· `docs/D4` §6 R5 口径 |

**主张 = 三条基准对应三层设计**：

| 用户基准 | 设计层 | 落在哪一节 |
| --- | --- | --- |
| ① 三者联动，**利用原子关联构建关联特性** | **关联特性矩阵**：三域端点之间允许的边与载体（锚行结构化引用 + 人行知情 + 镜像），并补齐 `R↔P` / `R↔S` 两条**今天完全缺失**的载体 | §3.1 |
| ② 任一变化 → **符合常理的联动** | **联动规则表**（3×3 十二条 + 五条硬边界），既是提示词的判据，也是落库校验的判据 | §3.2 |
| ③ **不依赖提取记忆、不能用修复**：两页各加一个按钮 → 打包全部数据 + 提示词 → 交 AI 构建联动 | **第三条通道**「🔗 联动构建」：两个入口 · 一个动作 · 三段打包 · 一份提示词 · 窄契约 JSON · 七条机械校验 · 预览确认后才落库 | §3.3–§3.9 |

**一句话边界**：**修复管道管「同域卫生」，提取管道管「楼层 → 条目」，本功能管「条目 ↔ 条目」**（§3.8 对照表）。

## 3. 方案

### 3.1 关联特性矩阵（基准 ①：用原子关联构建三域关联）

**载体三级（今日已有，不再新造容器）**：

| 级 | 载体 | 可写性 | 说明书 |
| --- | --- | --- | --- |
| 一 | `state.links` **锚行**的结构化引用（`planRef` / `suspenseRef` / `atomRef` / `conceptRef` / `memRefs` / `sourceRefs`） | 写侧唯一目标 | 有归一、去重键、上限、跨端并集（K1/K4） |
| 二 | 关联行**人行**（`who` + `how` + `deviation` + `public`） | 写侧唯一目标 | 表达「谁知道 / 怎么知道 / 是否公开」（K1/K3） |
| 三 | 各域**私有引用字段**（`plans.suspenseRefs`、`suspense.planRefs`、`rumors.parallelRefs`、`rumors.lineage`） | **只读兼容来源** | 由提取/人工写入，本功能不写它（避免两套真相） |

**关联（边）是只读派生**（K7/K8）：写清上面三级载体，`core/relations.js#deriveRelations` 自动反映为 `member-of` / `knows` / `mirrors` 边，
反向索引 `core/relations.js#dependents` 即可回答「这条传言变化会影响谁」。

**三域关联特性矩阵（目标态）**：

| 关联特性 | 语义 | 边（既有词表） | 今天的载体 | 目标载体 | 缺口 |
| --- | --- | --- | --- | --- | --- |
| **R→P** | 这条传言说的是某个计划 | `member-of` | **无** | 传言锚行的 `planRef` | **全缺**（须扩白名单，K2/K3） |
| **R→S** | 这条传言指向某个悬念 | `member-of` | **无** | 传言锚行的 `suspenseRef` | **全缺**（同上） |
| **P↔S** | 计划与悬念互为从属 / 因果 | `member-of` | 两侧私有字段（不镜像） | 计划锚行 `suspenseRef` **与** 悬念锚行 `planRef` **同写** | 有字段、**无镜像**（K5） |
| **知情** | 谁知道这条传言 / 计划 / 悬念 | `knows` / `knows-not` | 计划 / 悬念 / 记忆 / 平行有；**传言无** | 三域人行（`who` + `how`） | 传言缺（同上） |
| **镜像** | 传言 ↔ 平行事件 | `mirrors` | `rumors.parallelRefs` | 不变 | — |
| **谱系** | 传言裂变来源 | `derived-from` | `rumors.lineage.parentId` | 不变 | — |

**扩维的最小改动面（四处同批，缺一即「写进去又被判定非法删掉」）**：

1. `core/model/rel.js#REL_LINK_DIMS` 增 `rumors`；
2. `core/model/rel.js#REL_LINK_HOW_LEGAL` 增 `rumors` 子表（建议 `heard` / `spread` / `told` / `inferred` / `rumor` / `unspecified`，并同步 `core/model/rel.js#REL_LINK_HOW_RANK` / `#REL_LINK_HOW_LABEL`）；
3. `core/model/rel.js#REL_LINK_KINDS` 视需要增 `rumor`（`kind` 只影响展示与 `require` 语义，建议加，与 `fact` / `plan` / `suspense` / `parallel` 并列）；
4. **三处重复常量同批**：`core/entries.js#REL_LINK_DIMS`、`core/recall.js#REL_LINK_DIMS`；以及维护侧 `core/rel-maint.js#cleanInvalidRelLinks` 的维白名单文案与 `core/model/rel.js#relOrphanStats` 的口径。

> **孤儿统计口径（必须显式写死，否则一夜之间冒出上百条「孤儿」）**：`core/model/rel.js#relOrphanStats` 的 `items`（条目存在但一条关联都没有）
> **维持 4 维不变**；只有 `rows`（关联行指向的条目已不存在）随白名单扩维。传言不参与「孤儿条目」计数 —— 传言本来就可能谁都不知道。

### 3.2 三域联动规则表（基准 ②：「符合常理」的可判定定义）

规则表有**两处用途**：① 写进提示词（§3.5）让 AI 按它判断；② 落库校验时按它判定「这条 op 是否有依据」（§3.6）。
`effect` 词表沿用 `docs/D4` §2.3（`recompute` / `narrow` / `mark` / `dissolve` / `advance` / `annex`）。

| # | 源变化（三域任一） | 目标 | 联动（符合常理的理由） | effect | 写在哪 |
| --- | --- | --- | --- | --- | --- |
| L1 | 传言**被证实** | 计划 | 计划的步骤 / 前提若依赖该说法 → 进度推进、阻碍解除（事实已到位，意图可前进） | `advance` | `plans.progress` / `blockers` + `plans.history` |
| L2 | 传言**被证实** | 悬念 | 该说法成为线索；若满足 `resolveCondition` → 标记可揭晓（谜题的线索又多一条） | `annex` + `mark` | `suspense.clues` + `suspense.history` |
| L3 | 传言**被证伪** | 计划 | 计划前提失效 → 记入进展并要求复核（不能继续按错前提推进） | `annex` + `mark` | `plans.history` |
| L4 | 传言**扩散 / 发酵上升** | 计划 | 计划暴露风险上升 → 记入进展（保密型计划会因此受阻） | `annex` | `plans.history` |
| L5 | 传言**扩散 / 发酵上升** | 悬念 | 话题性上升 → 悬念层级或线索推进（越多人议论，越接近揭晓） | `recompute` | `suspense.history` |
| L6 | 传言**裂变 / 演化出变体** | 计划 / 悬念 | 新说法按主体归口到相关计划 / 悬念（关联特性更新，不改任何条目正文） | `annex` | 新锚行（`planRef` / `suspenseRef`） |
| L7 | 计划**了结** | 传言 | 失去传播动力 → 客观性上调（尘埃落定）、发酵度下调 | `advance` + `recompute` | `rumors.objectivity` / `ferment` + `rumors.chain` |
| L8 | 计划**受阻 / 放弃** | 悬念 | 揭晓条件变化（延长、加条件或层级调整） | `annex` | `suspense.resolveCondition` / `clues` + `history` |
| L9 | 计划**受阻 / 放弃** | 传言 | 可能催生新说法（**只标记，不新增条目**） | `mark` | `rumors.chain`（`kind = 联动`） |
| L10 | 计划**进度推进** | 悬念 | 相关悬念的线索随之推进 | `annex` | `suspense.clues` |
| L11 | 悬念**揭晓** | 传言 | 相关传言被证实或证伪 → 客观性变化 + 传导链留痕 | `advance` | `rumors.objectivity` + `rumors.chain` |
| L12 | 悬念**揭晓** | 计划 | 阻碍解除 → 进度推进或状态备注更新 | `advance` | `plans.progress` / `phase` / `statusNote` |
| L13 | 任一域**新增 / 删除 / 编辑** | 另两域 | 仅在**确有关联**时标注受影响（不臆造因果）；删除走既有级联 `core/model/rel.js#purgeLinksForGoneEntries` | `mark` | `statusNote` / `history` |

**五条硬边界（违反即拒收该条 op，不含糊）**：

| # | 边界 | 判据 |
| --- | --- | --- |
| B1 | **不得新增 / 删除 / 合并条目**，不得改写任何正文（传言说法、计划正文、线索文本） | `patch` 字段白名单（§3.6 第 3 条） |
| B2 | **不得凭空扩散**：让「传言被更多人知道」必须要么该条目 `public = true`、要么已存在 `knows` 链 | 锚行 `public` + 人行存在性（§3.6 第 6 条） |
| B3 | **不得写历史**：留痕的 `at` 一律取**剧情当前日期**，不得早于条目现有留痕 | 单调性校验（§3.6 第 7 条） |
| B4 | **不得跨域回写事实**：情节是唯一事实锚，衍生层只追加 / 标记 / 提升（人工） | `docs/D2` §3.3b A2 · `docs/D5` §4 |
| B5 | **不得一轮递归**：一次点击 = 一轮，本轮产出不再触发下一轮 | §3.7「单轮不递归」 |

### 3.4 数据打包（基准 ③ 的第二半：**打包边界**）

**打包三段（只读快照，不改任何数据）**：

| 段 | 内容 | 上限与截断 |
| --- | --- | --- |
| ① 三域条目 | 每条的**联动相关字段**：`id` / `kind` / 标题（`subject` 或 `title`） / 正文 / 剧情日期 / `status` / `phase` / `progress` / `steps` / `blockers` / `clues` / `resolveCondition` / `level` / `objectivity` / `stage` / `ferment` / `carriers` / `media` / `chain` 尾部 / `history` 尾部 / `tags` | 每域 ≤ `cfg.triLinkMaxItems`（默认 60）；单条 ≤ 160 字（超出截断并标记）；总量 ≤ `cfg.triLinkPackMaxChars`（默认 20000 字） |
| ② 关联行 | `state.links` 中**端点或人行涉及三域**的行（锚行 + 人行），逐行给 `dim/refId/who/how/public/deviation` | 每条目 ≤ `cfg.relLinkMax`（沿用 12） |
| ③ 最小事实锚 | 已发生情节的 `{id, 标题, 日期}`（**不含正文**）+ 涉及角色名去重清单 | 情节 ≤ 60 条（按剧情日期倒序） |

**明确不打包（三条硬约束，正是「不依赖提取记忆」的落实）**：

1. **不调用** `core/ai-hooks.js#aiFeedText`（该钩子取的是**楼层正文**）→ 打包体里没有原始楼层；
2. 不打包记忆 / 物品 / 货币 / 场景 / 概念 / 平行事件的正文（只允许出现被三域直接引用的 `id` 与标题）；
3. 不打包未摘要楼层的任何内容。

**截断纪律**：超限时按「`status = open` 优先 → 剧情日期倒序 → 重要度降序」保留，并在打包报告里**如实计数**（「已截断 N 条」进预览区与调试日志），不静默丢弃。

> **配额先例**：`core/parallel.js#corpusText` / `#customSeedLines` 已有「多库 × 条数 × 每条字数 + 总字数上限」的成熟口径（自定义推演），本功能沿用同一形态、只换维度与上限值。

### 3.5 提示词（新增模板键 `triLink`，全文如下）

注册位置：`core/config.js#PROMPT_TEMPLATES_V2` 增 `triLink`，并加入 `core/config.js#PROMPT_GROUPS` 的「质检维护」组（与 `planSuspRepair` 同组）；
「设定 → 提示词」页自动列出（`ui/prompts.js#promptsPageHtml`），可编辑、可恢复默认；调用点自带兜底默认文本（同 `core/plan-repair.js#buildPlanSuspRepairPrompt` 写法）。

```text
你是「三域联动构建器」。输入是【传言】【计划】【悬念】三个库的全部条目、它们之间的原子关联、
以及一份「已发生事实锚点」。你的唯一任务是：判断哪一域发生了变化、另两域据此应当产生什么符合常理的联动，
并输出一份**只包含联动动作**的 JSON。

【绝对边界】（违反任一条即视为无效输出）
1. 不得新增、删除、合并任何条目；不得改写任何条目的正文（传言说法 / 计划正文 / 线索文本）。
2. 不得改动日期、重要度、有效性、标签、id。
3. 只允许：建立或更新关联、追加留痕、以及下表列出的受限字段。
4. 每条动作必须写 evidence，且 evidence.ref 必须是输入里**真实存在**的 id；不要写不存在的 id。
5. 不得凭空扩散信息：若某计划或悬念未公开（没有「公开」标记）且没有「谁知道」记录，
   不得让传言凭空获知它 —— 除非输入里有它已公开的证据。
6. 只做一轮：不要考虑你的输出会引发什么下一轮变化。

【联动规则表】（判断「符合常理」的依据，允许合理外推，但必须写清理由）
R = 传言，P = 计划，S = 悬念
L1  R 被证实 → P：依赖该说法的步骤/前提推进，阻碍解除；S：追加线索，满足揭晓条件则标记可揭晓
L2  R 被证伪 → P：前提失效记入进展；S：线索作废记入进展（不改正文）
L3  R 扩散或发酵上升 → P：暴露风险上升记入进展；S：话题性上升，层级或线索推进
L4  R 裂变或演化出变体 → 按主体归口到相关 P / S（只建关联）
L5  P 了结 → R：失去传播动力，客观性上调、发酵度下调；S：依赖它的揭晓条件变化
L6  P 受阻或放弃 → S：揭晓条件延长或加条件、层级调整；R：可能催生新说法（只记录，不新增）
L7  P 进度推进 → S：线索随之推进
L8  S 揭晓 → R：相关说法被证实或证伪；P：阻碍解除、进度推进或状态备注更新
L9  任一域新增/删除/编辑 → 另两域：仅在确有关联时标注受影响，不臆造因果

【受限字段白名单】（出现白名单以外的字段即整条拒收）
- 计划：progress（0-100 整数，单轮变化 ≤ 20）· phase（blocked / abandoned / 空）· statusNote（≤60 字）
        · blockers（≤8 条，每条 ≤40 字）· history（追加一条，≤60 字，带 result）
- 悬念：clues（追加一条，≤60 字，带 by）· resolveCondition（≤60 字）· level（主线 / 支线 / 彩蛋）
        · statusNote（≤60 字）· history（追加一条，≤60 字）
- 传言：objectivity（主观 ↔ 客观，单轮只改一次）· ferment（±25 以内整数，结果夹在 0-100）
        · stage（只能改到相邻档：萌芽-扩散-发酵-异变-消退-沉寂）· chain（追加一条，kind 取既有词表）
- 关联：link 动作 = 让源条目锚行指向目标条目（R→P、R→S、P↔S 双向各写一条）

【输出格式】（只输出 JSON，不要解释文字，不要 Markdown 代码块）
{
  "ops": [
    {
      "src": {"dim": "rumors", "id": "rum_xxx"},
      "dst": {"dim": "plans", "id": "pln_yyy"},
      "link": "about" | "knows",
      "effect": "annex" | "advance" | "recompute" | "mark",
      "patch": {"目标域字段名": "新值"},
      "evidence": {"ref": "输入里存在的 id", "quote": "≤40 字的依据片段"},
      "reason": "≤60 字，说明为什么这样联动才符合常理（可用 L1-L9 编号）"
    }
  ],
  "truncated": false,
  "notes": "≤120 字总述，可空"
}

【输入】
{{按 §3.4 打包的三段数据：条目 / 关联 / 事实锚点}}
```

### 3.6 输出契约与七条机械校验（AI 只提方案，结构由机械兜底）

| # | 校验 | 拒收条件 |
| --- | --- | --- |
| 1 | **端点存在性** | `src` / `dst` 的 `dim` + `id` 必须在**本次打包集合**内（id 精确匹配，不看标题） |
| 2 | **跨域性** | `src.dim` 与 `dst.dim` 必须不同（同域归既有「🔧 修复」与 `docs/D4` 的机械侧，本功能不做） |
| 3 | **字段白名单** | `patch` 只允许 §3.5 白名单字段；出现其它字段（尤其 `content` / `title` / `date` / `importance` / `validity` / `tags` / `id`）→ 整条拒收 |
| 4 | **关联特性齐备** | 每条 op 必须同时产出**至少一条关联行**（`link = about` → 锚行 `planRef` / `suspenseRef`；`link = knows` → 人行 `who` + `how`）；不产关联的 op 一律拒收（这保证「联动」与「关联特性」同源、可反查）。**注**：`mirrors`（传言 ↔ 平行事件）与 `derived-from`（传言裂变谱系）不在本功能的写入范围 —— 平行事件不属于三域，且 `rumors.parallelRefs` / `rumors.lineage` 为**只读兼容来源**（§3.1） |
| 5 | **上限与钳制** | op 总数 ≤ `cfg.triLinkMaxOps`（默认 40）；数值字段夹取（`ferment` 0–100 且单轮 Δ ≤ 25 · `progress` 0–100 且单轮 Δ ≤ 20）；留痕追加后仍守既有上限（`planHistoryMax` 30 / `cluesMax` 20 / `chain` 60 步 / `relLinkMax` 12） |
| 6 | **知情边界** | `link = knows` 新增知情者，或 `about` 让传言「扩散」到新角色时：该条目锚行必须 `public = true`，或该角色已存在 `knows` 链；否则拒收（B2） |
| 7 | **单调性** | 留痕 `at` 取剧情当前日期；不得早于该条目现有留痕日期；不得回写源条目正文（B3/B4） |

**幂等**：`linkPassSig = hash(打包指纹 + ops 规范化签名)`；同一签名重复提交 → 直接跳过并提示「本轮联动已应用」（不叠加）。
